## 2. R1（P1）：新终点仍按旧四件凭证判阶段闭环

位置：run_case.phase_evidence_complete、verifier_report/VERIFIER_REPORT_PATTERNS 与 end_target.phase_closed。

原生 3.1 的 phase-completion-probe.ts:collectCompletionEvidence 明确要求 summary.feature/phase 与调用身份一致，并说明 receipt、receipt_status 是兼容诊断，不作为当前完成观察条件。新驱动仍要求 trace/receipt/任意历史命名 verifier 文件，却不核 summary 身份与当前材料。

独立反例：plan 目录放另一 Feature、phase=spec 的 summary（PASS/closed/passed），配占位 trace、历史名 verifier.report.md 和回执；驱动返回 true，原生返回 summary=false、missing=[summary]。因此“从平铺改到 CU 目录”并没有完成闭环协议迁移。反向还会把原生允许的无 verifier/复用完成误判为缺四件套。

修正合同：终点原生观测输出 CU Feature 身份、phase 和当前原生完成事实，复用 collectCompletionEvidence；质量 verdict 与是否结束分别呈现，目标要求通过时核真实质量结论。去掉全局强制 verifier 四件套与旧文件名兜底。对终点签收/续跑核当前证据，复用 phase-evidence-manifest.ts 的 recomputePhaseEvidenceStaleness(projectRoot,feature,chain,{frameworkRoot,...})，按当前原生范围及需求绑定取参数；只消费 fresh 结果，不绕过原生陈旧判定。高频轮询使用轻量完成观察，材料有变或要认定到达终点时再核必要的当前绑定，避免每个事件全量校验。

只读原生 helper 可以复用；不运行会写回执的 check-receipt 来观测，也不为免受无关 HEAD 变化影响而跳过对象/材料绑定。保留“无关提交不必重跑”的目标，由真实材料证据达成。

测试：错 Feature、错 phase 不完成；原生身份正确的合法闭环可认；改变当前设计/阶段相关输入后旧结论不可沿用；原生合法不要求 verifier 的路径不被硬加门槛。close_phase 只写 PASS 字符串/无身份 summary 的旧正例退出，分支消费 mock 与真实原生证据用例分开标明。

## 3. R2（P1）：Story 观测会写报告；复用仍由空产出列表推断

### 3.1 观测写报告

end_target.story_delivery 调 check --deliver，后者经 reviewResult 复制原回复并再次运行原生 request 检查。独立合法已登记 Story 上，observe(kind=story) 返回 reached=true，同时 script-report.json 和 summary.json 字节改变。这是日常轮询路径，不是异常输入；观测不应参与被测模型的检查/证据生产。

修正：在现有独立审查结果消费者中分开“执行检查”和“读取已验证结果”。显式 review check 负责运行原生检查；交付观测读取现有 prepared、原始/工作报告及原生 summary/script-report，核当前 material_key、request 身份与原生绑定/摘要，不写盘、不制造新结论。共用现有解析/映射，避免另造一套交付门或把纯文件存在当通过。缺检查结果指回消费模型执行原命令；维护驱动不代它执行。

对真实已登记对象运行 observe 前后比较完整报告目录字节，必须不变；改正文/Review 后应只读返回待同步，不重写报告。普通显式 review check 的原生检查职责保持。

### 3.2 required_outputs=[] 不是复用凭证

phase_closed 当前在没有回执时用 required_outputs=[] 直接标 reused。该字段是当前阶段须生成的文件集合，不是旧结果已满足请求或阶段已获豁免的原生结论。当前合法复用用例只 mock 空列表，未证明发布件真实路径。

修正：从原生有效 scope 的 phase_chain、义务适用性与 satisfied_by 证据取得复用事实；以原生 executionScopeEvidenceIssues/Findings 核实际承接证据，整个空链复用可沿 verifyReusedExecutionScope 的适用合同校验。不能为 Plan 测试终点强制完整 Feature/Coding 完成，也不能把无需新 Markdown 等同无需阶段工作。缺明确证明报缺口，显式不适用与已验证复用分别记录。

本轮至少补一份真实原生复用输入的正例，和空 required_outputs 但仍有未满足义务的反例。这是正常目标覆盖，不能因重夹具耗时用假结果替代；可复用已有冻结工程，不另建运行器。

phase_was_reached 还以阶段目录里 reports 外有文件判断“执行过”，它仍被最终结果和 gate 选择调用。仅可作为“观察到文件”的诊断，不能用它认完成、决定合法复用或跳过本来必须的检查；这些消费者统一迁到上述原生事实，退出相应旧目录即执行断言。

## 4. 金样迁移三处裁定

正本、业务事实与效果要求保持；只在测试隔离装配层处理格式迁移，不给产品加 AR90004 特判。

1. **接口结构化来源：同意 A 的转录方向，但不批准自动补造权威字段。** SR §4 给出了接口名、输入/输出语义、调用条件与错误行为；没有给 DTO 类型、可空性、API 版本及完整 mapping。原生 blueprint-contracts.ts 要求 operation.version、字段 type/semantics/source_ref 并逐项比对，简单转录不能凭空补全这些事实。可增加带原始文档/章节定位和摘要的结构化转录附件；已有 Spec 中的已定本地设计事实明确标其出处，不能冒充 SR 原文，更不能把“新增某模块接口”塞入 nfr/errors。未知字段列为未提供，不按名字猜类型、把缺 nullable 当必填或造版本号。先交一份最小字段映射与实际原生缺口供设计者核定，不能只为金样过门创作协议；其他已能映射部分先完成。原生契约投影的真实校验用现有具有完整权威来源的 2.0 夹具保持覆盖，不拿它替换金样事实。
2. **依赖变更：采用 B，保留原节与原文，退出旧机器标记。** 在迁移副本中原 §10.1.4 作为作者区保持；同一结论在 canonical 的真实开发视图/架构影响决定中有据承载，映射表指明出处和表达位置。现行附录允许作者解释，不需为了金样加一个已退出的专用机器区，也无需删掉已认可的章节。模块归属、复用、不新增依赖分别放语义相符的设计对象，不能为塞进字段随意改决定 kind/change 的原生取值。
3. **旧 spec 图源：采用 A 的逐项映射。** 金样图的参与者/分支与内容原样保留，SR 图源不动；旧 spec 流程各分支在真实蓝图运行/场景对象中逐项可回查后，仅删除那一行失效 spec 图源标记。映射登记原位置、分支、蓝图地址与现有 Story 图内位置，缺映射明确失败。禁止通用删除任意图源或伪造一张不存在的直接上游图。

机器派生的精确字段可逐字核；图中业务分支的等价由维护设计者人工对照，不用子串全命中冒充语义不丢。4B 未完成前金样/G01 保留已知失败，不降低目标，也不把非金样工作的推进绑在这里。
