# 步骤 3 接口身份交回

> 读者：2.0.0 方案设计者。时机：复核[步骤 3 二次返修评审](../评审意见/2026-10-01-步骤3二次返修评审.md) §3 的接口身份修正之前。
> 起点：评审入库 `b25f151e`。F1–F3 与之前已通过的部分没有重做。

## 1. 按修改合同逐条落实

1. **身份在 `contracts.mjs` 里统一取。** 新增导出 `entityId(kind, item)`，按实体种类取原生身份：接口取 `class`，状态管理取 `data`，
   数据模型、组件、模块取 `name`；缺这个字段时返回空串。成员（方法、字段、状态、属性、事件）只认 `name`，子组件是字符串；
   资源条目只认 `key`，`files` 只认路径字符串。原来逐个试 `name ?? class ?? key ?? path ?? file ?? id` 的 `entityName` 退出。
2. **消费者共用 `entityId`。**
   - `obligations.mjs`：`obligationsFromContracts` 与 `patternRolesFromContracts` 按它拼地址，接口地址是 `interfaces.<class>.<method.name>`；
     成员名 `name()` 收窄为只读 `name`。
   - `resolveEntityRef` 按它找实体。
   - plan 门禁的已声明方法集合是 `<class>.<method.name>`，与逐点表的责任方法同形。
   - `statDelivery` 送出的方法地址。
   审查任务的义务表、review 复核表的落点都取 `obligationsFromContracts` 的地址，随之一致。
3. **不留宽泛回退。** 接口没有 `class` 时不拼地址，它上面的义务与角色不进下游。新增的 `unidentifiedCarriers` 点名这类实体：
   挂着 `must` 或 `pattern_roles`、却缺原生身份（接口缺 `class`，数据模型、组件缺 `name`）。plan 门禁在「契约可读与 must 挂位」组里报出。
4. **示例与夹具同步。**
   - `hooks/plan/author.md` 的 YAML 示例改为 `class: RecordStore`，方法声明那一条写明各实体按什么认、地址长什么样；
     逐点表的责任方法写「接口 class.方法 name」。作者页仍是 60 行。
   - 测试里接口只写 `name` 的契约全部改为 `class`：`test_knowledge_protocol`、`test_neutral_knowledge`、`test_contracts_single_source`、
     `test_stat_points`，以及 `test/fixtures/yaml/knowledge-contract.yaml`、P17 失效形态的正反夹具。数据模型、组件与方法的 `name` 保持不变。
   - 失效形态检查器 `_musts` 拼接口地址也改读 `class`。
5. **真实施工单位上对照。** 用 `test_cu_knowledge_chain` 同一份原生派生、冻结的契约核：
   - 义务地址是 `interfaces.HomeRepository.refreshBalance`，接口角色地址是 `interfaces.HomeRepository`，两者都能被 `resolveEntityRef` 解析；
     审查任务里的义务行也是这个地址，整份输出里没有 `interfaces..`。
   - plan.md 逐点表里 `HomeRepository.refreshBalance` 通过，`HomeRepository.saveNothing` 被报找不到。

## 3. 验证

- 受影响的十个测试文件（知识承接、门禁分组、取证送达、YAML 读取、契约单源等）：夹具改为 `class` 后 149 条全部通过。
- 全量与失效形态：见 §3.1。

### 3.1 全量与失效形态

- 全量（`pytest -n auto --dist loadscope`）：1409 通过、1 xfail；失败 4 条都是既有的（金样 3 条、`test_run_measurement` 1 条）。用时 187 秒，仍超出 120 秒目标。
- 失效形态（装开发版的隔离 template）：61 条，FAIL 1（G01，金样，步骤 4 迁移），与上轮相同。
- 夹具自检 `check_failure_modes.py --self-check`：P17 正反夹具改为 `class` 后判定照旧。自检另有 14 个形态失败（A02、R02、R04、S01 等），
  把本次改动撤掉后在 `b25f151e` 上跑结果完全相同，是既有情况，与本次无关。
