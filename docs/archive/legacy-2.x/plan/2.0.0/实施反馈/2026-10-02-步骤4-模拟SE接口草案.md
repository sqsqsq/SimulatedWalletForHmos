# 步骤 4 模拟 SE 接口草案：两个 Case 与金样输入

> 读者：2.0.0 维护设计者。时机：审定模拟 SE 接口小节、把它纳入测试基线之前。
> 依据：[二次返修评审与接口转写裁定](../评审意见/2026-10-02-步骤4二次返修评审与接口转写裁定.md) §3.3、§5。
> 本页是草案，三份 SR 都还没改。逐接口审定后，实施者按定稿写进材料并更新指纹。

## 0. 写法约定

- **原文不动**：草案只在已有接口段之后补「接口明细」，现有句子一字不改，业务事实（调用时机、幂等、失败收敛）不变。
- **三种写法**，避免模型只会认一种版式：

  | 材料 | 写法 |
  |---|---|
  | 金样 AR90004 | 每个接口一张「字段 / 方向 / 类型 / 必填 / 可为空 / 说明」表 |
  | auto-topup | 「请求参数 / 返回参数」两张表，表头措辞不同（「是否必须」「能否为空」），金额单位写在说明里 |
  | car-key-sharing | 不用表，逐条列「入参 / 出参」；编号沿用原文的 `4.1b` 这类非整齐编号；版本写成「车云开放接口 2.1」 |

- **新增标记**：下面「来源对照」表逐字段标出哪些是原文已有、哪些是本次模拟新增（类型、版本、可空性、新字段名）。新增的是模拟 SE 补的协议事实，不是从旧材料推出来的。
- **各 Case 只放 SE 原文**：消费模型拿到的只有这些原文，转写、映射、审查结论一概不预置。

## 1. 金样 AR90004：`test/fixtures/golden/AR90004/SR/design.md` §4

在 §4 三个接口原段落之后各补一段（下面是要插入的原文）：

````markdown
### 4.1 `queryLossEligibility`

（原段落不变）

接口版本 v1，钱包调用交通卡云。

| 字段 | 方向 | 类型 | 必填 | 可为空 | 说明 |
|---|---|---|---|---|---|
| `cardId` | 入参 | string | 是 | 否 | 脱敏映射后的卡片标识 |
| `accountScope` | 入参 | string | 是 | 否 | 账号范围摘要 |
| `eligible` | 出参 | boolean | 是 | 否 | 是否可以挂失 |
| `identityRequired` | 出参 | boolean | 是 | 否 | 是否需要先完成身份 |
| `cardState` | 出参 | string | 是 | 否 | `normal` / `frozen` / `conflict` |
| `existingApplication` | 出参 | object | 否 | 是 | 已有申请；没有时为空。含 `applicationId`（string）与 `status`（`submitted` / `processing` / `frozen` / `failed`） |
| `reason` | 出参 | string | 否 | 是 | 可读原因，`eligible` 为 false 时给出 |

调用失败（网络、超时、服务端错误）沿用卡云既有错误码，不新增。只读查询，可以重复调用。

### 4.2 `createOrReuseLossApplication`

（原段落不变）

接口版本 v1，钱包调用交通卡云。

| 字段 | 方向 | 类型 | 必填 | 可为空 | 说明 |
|---|---|---|---|---|---|
| `cardId` | 入参 | string | 是 | 否 | 脱敏映射后的卡片标识 |
| `accountScope` | 入参 | string | 是 | 否 | 账号范围摘要 |
| `userConfirmed` | 入参 | boolean | 是 | 否 | 用户已确认冻结风险，必须为 true |
| `idempotencyKey` | 入参 | string | 是 | 否 | 稳定幂等键，同一次挂失流程内不变 |
| `applicationId` | 出参 | string | 是 | 否 | 申请标识 |
| `status` | 出参 | string | 是 | 否 | 固定为 `submitted` |
| `reused` | 出参 | boolean | 是 | 否 | 是否复用了已有的有效申请 |

同一 `idempotencyKey`，或该卡已有有效申请时，返回原 `applicationId` 且 `reused` 为 true，不新建。失败沿用既有错误码；响应丢失后用同一 `idempotencyKey` 重调。

### 4.3 `queryFreezeResult`

（原段落不变）

接口版本 v1，钱包调用交通卡云。

| 字段 | 方向 | 类型 | 必填 | 可为空 | 说明 |
|---|---|---|---|---|---|
| `applicationId` | 入参 | string | 是 | 否 | 申请标识 |
| `result` | 出参 | string | 是 | 否 | `frozen` / `processing` / `failed` |
| `freezeTicketId` | 出参 | string | 否 | 是 | 冻结凭证，只在 `result` 为 `frozen` 时给出，交给补卡单 |
| `reason` | 出参 | string | 否 | 是 | 可读原因 |

只读查询，可以重复调用。失败沿用既有错误码。
````

**来源对照**

| 接口 | 原文已有 | 本次新增 |
|---|---|---|
| queryLossEligibility | 字段名 `cardId`、`accountScope`、`eligible`、`identityRequired`、`cardState`、`existingApplication`；「可读原因」；调用时机、无轮询 | 版本 v1、方向、全部类型与必填/可空；`cardState` 取值；`existingApplication` 的内部字段；字段名 `reason`；「沿用既有错误码」 |
| createOrReuseLossApplication | 「卡片标识、账号范围、用户确认、稳定幂等键」的含义；`applicationId`；`submitted`；不建第二份申请 | 字段名 `userConfirmed`、`idempotencyKey`（原文只有中文含义）；`status`、`reused`；版本、类型、可空性 |
| queryFreezeResult | `applicationId`；`frozen` / `processing` / `failed`；可读原因；只有 frozen 驱动成功；`freezeTicketId` 出自 §5 交接 | `freezeTicketId` 作为本接口出参；字段名 `result`、`reason`；版本、类型、可空性 |

**对金样正本的影响**：业务叙事不动。附录「技术契约·端云接口」改由蓝图契约重投，表头变成现行的字段表；映射表核的是接口名等旧事实。

## 2. auto-topup：`test/cases/auto-topup/system/SR90006/design.md` §3

在 §3 四条要点之后、「创建签约之前…」一段之前插入：

````markdown
### 接口明细

四个接口均由钱包调用交通卡云，接口版本 1.0。金额一律以「分」为单位的整数。

**getAutoTopupPolicy**

请求参数：

| 参数名 | 类型 | 是否必须 | 含义 |
|---|---|---|---|
| accountId | string | 必须 | 去标识账号 |
| cardId | string | 必须 | 卡片标识 |

返回参数：

| 参数名 | 类型 | 能否为空 | 含义 |
|---|---|---|---|
| signable | boolean | 不能 | 是否可签约 |
| unsignableReason | string | 能 | 不可签约的原因（如未实名），可签约时为空 |
| thresholdOptions | int[] | 不能 | 门限档位 |
| amountOptions | int[] | 不能 | 面额档位 |
| dailyLimit | int | 不能 | 单日限额 |
| agreementText | string | 不能 | 协议文案 |

**createAutoTopupContract**

请求参数：accountId（string，必须）、cardId（string，必须）、agreementNo（string，必须，支付部件返回的协议号）、threshold（int，必须）、amount（int，必须）。

返回参数：

| 参数名 | 类型 | 能否为空 | 含义 |
|---|---|---|---|
| contractNo | string | 不能 | 签约号 |
| existed | boolean | 不能 | 是否为既有生效签约（true 时没有新建） |

**getAutoTopupStatus**

请求参数：accountId（string，必须）、cardId（string，必须）。

| 参数名 | 类型 | 能否为空 | 含义 |
|---|---|---|---|
| contractStatus | string | 不能 | `none` / `active` / `disabled` |
| contractNo | string | 能 | 未签约时为空 |
| threshold | int | 能 | 当前门限，未签约时为空 |
| amount | int | 能 | 当前面额，未签约时为空 |
| recentRecords | object[] | 不能 | 最近记录，可以是空列表；每项含 time、amount、result |
| consecutiveFailures | int | 不能 | 连续扣款失败次数 |
| disabledReason | string | 能 | 停用原因，未停用时为空 |

**cancelAutoTopupContract**

请求参数：contractNo（string，必须）。返回参数：cancelled（boolean，不能为空）。解约不回滚进行中的订单。

各接口失败时返回卡云统一错误结构（错误码 + 可读信息），本需求不新增错误码。创建签约以「卡片 + 生效状态」判重：已有生效签约时返回既有 `contractNo`。
````

**来源对照**

| 接口 | 原文已有 | 本次新增 |
|---|---|---|
| getAutoTopupPolicy | 返回可签约性、门限档位、面额档位、单日限额、协议文案；不可签约不拉起免密 | 请求参数 accountId、cardId；全部字段名、类型、可空；`unsignableReason`；金额单位「分」；版本 1.0 |
| createAutoTopupContract | 入参账号、卡片、`agreementNo`、门限、面额；已有生效签约返回既有 `contractNo` | 字段名 accountId、cardId、threshold、amount；`existed`；类型；版本 |
| getAutoTopupStatus | 返回签约状态、当前门限与面额、最近记录、连续失败次数、停用状态 | 请求参数；全部字段名与类型；`contractStatus` 取值；`disabledReason`；`contractNo` 出参 |
| cancelAutoTopupContract | 解除后不回滚、不撤销已完成订单 | 请求参数 `contractNo`、出参 `cancelled`；版本 |

## 3. car-key-sharing：`test/cases/car-key-sharing/workspace/SR/design.md` §4

在每个接口原段落之后补一段「字段」列表，不用表。以 4.1 为例，其余同样写法：

````markdown
### 4.1 `queryKeySharingQuota`

（原段落不变）

字段（车云开放接口 2.1，钱包调用车云）：
- 入参 `vehicleId`：字符串，必传。
- 出参 `canShare`：布尔，必有。
- 出参 `remaining`：整数，必有，剩余可分享数。
- 出参 `reason`：字符串，可能为空；满额时给出原因。
- 出参 `shares`：列表，必有，可以是空列表；每项含 `shareId`（字符串）与 `status`（字符串）。
````

其余接口的字段：

| 接口 | 入参 | 出参 |
|---|---|---|
| 4.1b `queryGranteePermission` | `vehicleId` 必传；`granteeId` 必传（对方账号标识） | `shareable` 布尔必有；`permissionLevels` 字符串列表必有，不可分享时为空列表；`reason` 可能为空 |
| 4.2 `createKeySharing` | `vehicleId`、`granteeId`、`permissionLevel`（字符串）、`validUntil`（ISO 8601 时间）、`idempotencyKey`，全部必传 | `shareId` 必有；`status` 必有，固定为 `pending` |
| 4.3 `acceptKeySharing` | `shareId` 必传 | `credentialStatus` 必有（`issued` / `failed`）；`status` 必有（`active` / `pending`） |
| 4.4 `revokeKeySharing` | `shareId` 必传 | `status` 必有（`revoked` / `revoking`）；`graceHours` 整数可能为空，`revoking` 时为 48 |
| 4.5 `queryKeySharingList` | `vehicleId` 必传 | `items` 列表必有；每项含 `shareId`、`status`、`permissionLevel`、`validUntil`、`granteeMasked`（脱敏后的对方标识） |

失败时返回车云错误码与可读信息，本需求不新增错误码。

**来源对照**：
- 原文已有：六个接口名；入参的中文含义（车辆标识、分享对象、权限档、有效期、幂等标识、分享标识）；配额、权限、状态、宽限 48 小时等语义。
- 本次新增：全部英文字段名、类型、必传/可空、状态取值的英文写法、版本「车云开放接口 2.1」。

## 4. 模型拿到的指引（草案，随知识任务送达）

**`extensions/hooks/blueprint/author.md` 新增一节「接口协议的转写」**：
- 读本次冻结的 SE 原文接口小节，写 `<features_dir>/<蓝图 id>/blueprint/contracts/se-interfaces.yaml`：
  - 结构按原生 operation、request_dto、response_dto、errors（`items`）、idempotency（`rule`）、nfr（`requirements`）；
  - 每段的 provenance 写冻结原文路径与章节；
  - 原文写的照写，原文没写的不补。
- 本部件的字段映射写同目录 `mappings.yaml`，那是本部件的设计决定。
- 蓝图 `contracts` 的各段 `source_ref` 用 `#/…` 指向这两份文件的对应段落。
- 原文缺类型、版本、可空性，或意思自相矛盾：登记缺口，写明向谁取得。当前切片要用的，设为 blocker。不要把未知的可空当成不可空。
- 修订时保留旧版本引用的文件，新版本用新文件名。

**`extensions/hooks/blueprint/reviewer.md` 新增一条质询要求**：同时读冻结的 SE 原文、转写、映射和蓝图，逐接口核：
- 字段、类型、必填与可空、版本、错误、幂等是否和原文一致，有没有遗漏；
- 哪些是 SE 给的事实，哪些是本部件新加的设计；
- 来源不明的，交人决定。
