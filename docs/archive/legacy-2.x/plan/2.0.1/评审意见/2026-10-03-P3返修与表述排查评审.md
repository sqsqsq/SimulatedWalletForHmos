## 2. 剩余必改

### S1 [P1] 报告目录改变仍会丢失同一对象的 BLOCKER

位置：independent-review.mjs 的 prepareReview / earlierConclusion。

当前把“同一材料”视作“同一报告目录”。反例沿实际命令：报告已有 fail/BLOCKER → 同材料 prepare --report-dir doc/reports/alternate-neutral → material_key 不变，结果却变成 report_missing → unreviewed 授权成功 → 再准备、登记和交付均退出 0。

这是已有 --report-dir 参数的合法输入变化，不能用“默认目录没变”的用例代替对象身份保护。目录是存放位置，不是业务对象身份。

**本轮定案最小修法：同一 material_key 复用首次准备确定的 report_dir。后续显式指定不同目录时返回目录冲突，保持原准备记录和历史结果，不写新状态。** 不增加跨目录扫描器、报告登记中心或结论锁定；材料变成新对象后可以重新指定目录，原件保持。原始目录内实际复审的新报告仍能更新结论。

验收：同材料换目录不消除 fail、不生成未审查资格；同目录复审的新 pass 可消费；冲突调用不改文件。

### S2 [P2] 材料路径按空白切词，误拒合法文件名

位置：independent-review.mjs 的 cells / locations。

实际存在且已进入本次材料集合的 meetings/neutral meeting/v1/raw.md，以反引号整体引用，仍被判 report_invalid。table 先剥掉反引号，locations 再按空白拆开，破坏了原本完整的路径。这是对当前无空格样例的结构假定。

裁定：保留材料位置单元格的引用边界。单个位置可直接使用完整单元格中的路径（含空格）；多文件或混有说明时用反引号逐个标注，派审前在报告合同说明。先取得完整路径，再处理 #定位/:行号，按本次集合精确比对；不退回 includes 或按词命中。保留 .bak 和无关路径拒绝。

验收包含空格/中文文件名、定位片段、多个明确引用，以及不存在路径。不扩展成任意 Markdown 链接解析器。

### S3 [P2] 投影缺口给出的 story_details 恢复方式不起作用

位置：appendix-readers.mjs 的 gapAt/readable，appendix.mjs 的 appendixSourceProblems。

当前提示把结构写入 story_details，但追加带同一设计对象引用的人读明细后，原字段依旧进入 readable 并产生同一缺口；前后 gaps 相同，明细虽能渲染，整次投影仍被阻断。实际可行的路反而只剩改写/删除 canonical 原字段，容易引导消费模型为通过工具改变设计结构。

**本轮定案：未支持的合法结构属于 Extension 投影适配缺口，报告具体字段并交扩展维护者补人读映射，保留 canonical。撤下“追加 story_details 就能解除该缺口”的无效指引。** 已有精确明细继续正常投影；不新增覆盖原字段的私有协议，不要求消费模型读 checker 或修改机制，不以把对象改成字符串消除报错。维护者有实际结构来源后再补相应映射，禁止为单个金样添加放行分支。

这是对前轮“交设计/作者处理”过宽裁定的收紧：缺业务事实回设计，工具尚无合法结构的人读写法回维护层，责任不能混淆。

## 4. 表述排查：范围与批次裁定

排查表是候选清单，不把“如实、不是、不再、原生”等词的出现当作错误，也不引入禁词测试。注释可以解释算法和职责理由；消费者动作页应提供目标、输入、动作、产物和恢复责任。真实业务历史与维护失败故事分开。

### 随 P3 收敛的内容

1. **失效报告字段**：reader-review-task 的 blocking_findings 和旧“审查方法一节”退出，按当前判据核对后的方法说明及发现表写；SKIP 退出。准备期输入不可读就报 input_invalid；派审中发现缺输入，按相关判据记录阻断缺口和未核范围，不伪装“不适用”，也不一概宣称所有业务判据都已失败。
2. **可执行恢复提示**：report_invalid 给出 prepare 取得新位置、把当前合同交 reviewer 重给原回复的下一动作；与 S1 的对象/目录规则一致。
3. **阶段审查表的对象**：pre_verifier 的判据汇总表与知识逐条裁决表不是同一对象，不能仅凭“表”字认定逻辑矛盾。改成“逐项核审查判据并给汇总；知识审查解释问题和依据，保留判断覆盖”，移除 Story open 议题的专属例外，不删有效知识审查职责。
4. **UT 与实机**：不采纳“ut 不是实机，所以从实机可选去向删除 ut”的结论。本仓原生 HMOS UT 可经 Hypium、安装、aa test 在设备上运行（request-harness.md）。ut/device/both 是验证责任，实际是否在设备执行由运行证据证明；修正把阶段等同环境的注释与话术，本轮不更改合法枚举或弱化实机证据要求。
5. **来源命名与原件去向**：逐引用核对象；指派生提取稿的改为 AR/story-src/design-draft.md，指上游原件的仍是 AR/design.md，不能全文替换名称。收件箱说明明确被替代原件的备份位置和追溯方式，不承诺文件永远不移动。
6. **本包新增话术与人机受众**：将回评式辩解改为当前执行步骤与必要边界。交付选项只呈现业务含义，范围准备参数移到执行方法页；实际调用必需的原生名称/字段保留。读者任务与主执行者派遣步骤按受众分开，不靠删执行信息变简短。

上述与 P3 同包交回，逐项给改前/改后和职责保持依据。判据含义、严重程度、ID 与报告结构保持，不借文案修改拆判据或重构机制。
