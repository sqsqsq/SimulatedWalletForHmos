# S2：新版Framework核实与适配定案

新版合同调查以前置为Framework正式发布件；1.9.9发布核实、[成果保全准备](01-成果保全与基线切换.md)与调查可以独立推进，不要求先替换源码。产品实施定案须两份发布身份、完整保全覆盖及必要依赖齐备。维护设计者负责分析定案，实施者提供源码事实；本文件不给尚未交付接口虚构接线。

## 1. 收件与正式接入

记录发布zip来源、摘要、RELEASE-MANIFEST的版本/source_commit/built_at及MIGRATION。即使仍叫3.1.0，也按构建身份区分，不能只比较版本字符串。先在scratch解压只读核文件、合同和样例，确认Framework作者的“完成”包含哪些修复。

正式替换demo/framework时按根AGENTS §6逐项执行：demo先干净，核迁移diff，重加两处本地定制，framework-init UPDATE，保护已装Story入口，根verifier同步，执行原生harness及相关离线验证，登记EVOLUTION。若新版改变这些接口，先形成具名接入差异裁定再执行，不能旧模板整文件覆盖新模板。

接入Framework与正式发布Story是两件事：允许按§6更新demo Framework，不提前把开发源安装到demo/doc/extensions。需要测试时用一次性template；恢复的1.9.9与新Framework并不自动兼容。Framework自身问题回上游，当前不代用户发送外部消息。

## 2. 必须定案的职责与接口

| 面 | 必须从实际生产者和消费者核实的决定 |
|---|---|
| 设计权威 | YAML/blueprint.md分别编辑什么、谁维护决定、如何准入/修订、表达变化与业务变化如何区分、下游引用哪个身份 |
| 人读产物 | 目标读者、完整需求叙事是否成立、技术精确内容如何查阅；Story合并、独立或交付裁剪的实际价值与代价 |
| Extension参与 | 作者与质询要求何时进入实际模型上下文，是否允许整体表达组织，直接设计入口及Story入口是否同样有效 |
| 知识链 | 三类知识激活、适用判断、契约实体义务/模式角色、CU责任与Spec/Plan证据，不退化为列名称或孤立附录 |
| 流程状态 | 材料和范围确认、蓝图、CU准备、Spec/Plan的权威及可恢复入口；消除旧1.x自有编排与原生阶段的同责路径 |
| 意见与更新 | Review人工区、事实/建议/授权决定、送审/恢复、重新设计与投影更新、既有稿件手改和同名材料换版 |
| 独立审查 | 实际派发、原件首次消费保护、生产者边界、格式恢复、warn、无视觉能力时的停留与恢复；不将作者自改报告判可信 |
| 安装与宿主 | manifest/overlay/hooks/Skill物化、发布安装器、目录所有权、适配入口；与2.1.0未实现需求的边界 |
| 1.9.9能力保持 | 逐项消费04的继承及新增能力清单，给出新承担者、入口和验收；依赖旧Spec/阶段的知识、usage、独审和状态不能因正文迁移而丢失 |
| 最小可用装配 | 03的安装器/entries、template、manifest与宿主发现、公共夹具及定向测试形成首包，完整对外adapt增强按版本边界另处理 |
| 金样与来源 | 正本及审定/来源/模拟前提可追溯；新blueprint布局另定期望，不改写1.x正本冒充已审新版 |

旧U01/U02、FW-01/02/04/05及术语interactive问题按实际新版逐一复核，分类为已接替且证据充分、部分解决、仍阻塞或本轮不适用并给理由。旧报告既不能证明新版仍缺，也不能被作者的完成反馈直接关闭。

## 3. 正常、变化与失败推演

设计者沿两条正常入口推演：系统单取材至送审再update；本地单至蓝图、合法CU准备及Spec/Plan。另核直接Framework入口能否得到需要的Extension知识；没有业务编号或需求系统时不强迫制造系统单状态。多CU时共同设计不重复作、责任不漏传，无关联须有实际依据。

再核同名材料换版/撤回、未决影响准入、已有CU修订复用、正文表达修改、人工意见未接受、归档授权范围、报告无效后被原位编辑、视觉工具不可用、有效warn和重复调用。每条明确输入、权威决定、写入、下游消费、失败返回和恢复入口；推演不冒充行为证据。

合并选择引用[讨论](../../spec/2.0.5/01-蓝图与Story职责讨论.md)，不预定必须保留十章或独立Story。若合并，逐项接替成文/Review/归档/update能力并退出旧消费者；若独立，明确新增的阅读任务、设计事实来源及同步方式，不维护第二份独立设计权威。新版只解决通用设计时，Extension的业务交付职责仍需真实承担者。

## 4. S3开工前的交付

形成一套可直接实施的当前方案：逐能力新旧责任与唯一真源；Framework正式接口、版本和必读材料；extensions、test、配置与文档逐文件动作；删除、保留和保护清单；错误与恢复；定向/组合验收及预期；各实现步骤预计绝对G、X、净增、峰值和最终量。以[04](04-旧成果与能力承接清单.md)标记每项旧成果复用方式和证据边界。

逐项补全S1中“已保全、复用去向待新版”的最终承担者和处置；1.9.9发布后变化补到能力/测试对应中。未发布承诺及既有缺陷明确留原版、经用户定范围迁入或后续处理，不依靠更新版本号关闭。首包同时确定源码切换、版本升为2.0.5、最小适配、安装/物化及相应测试；其后各包仍需可独立检查，不先交无法装配的纯恢复版本。

Framework未交付必要接口时只阻受影响动作，保留准确复现与所需交付，不在Extension实现通用框架旁路。不能将未定关键设计留给实施者猜。新增通用框架或生成器先按用户级约定说明必要性、成本及简单替代并取得确认。

S2通过条件是实施者仅凭本版当前方案及列明合同即可实施，且关键架构、预算及需用户取舍的决定已确认；未来接口待决的部分明确不具开工条件。本次初步方案未达到该产品开工状态。
