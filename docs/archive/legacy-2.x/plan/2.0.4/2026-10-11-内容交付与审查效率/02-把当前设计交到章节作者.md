# 步骤2：把当前设计交到章节作者

## 1. 现有入口及新增行为

修改既有`story-inputs.mjs`、`chapter.mjs::nextSteps`、`story-build.mjs::cmdSkeleton`、`writing-plan.mjs`及其当前方法页。复用已有`basisSections(plan)`、`designSource(ctx)`与Framework `blueprint-addressing.ts::stableAddressIndex`，不要按名称相似度找关系，不创建designContent中间模型。

默认skeleton的起手/恢复行为保持。写作设计成立后，skeleton和chapter成功后的NEXT指向下一章时，在同一输出中交该章输入。增加现有skeleton的`--chapter <既有章名>`使用方式，用于读取任意已存在章节的当前输入：该分支在任何写盘前分流：选唯一章、读取已有Story/写作设计/当前来源并组装，成功仅输出，不进入writeDrafts或默认骨架写入。它只读，不覆盖草稿/正文、不重建写作设计；尚未起skeleton或无该章时报缺口。chapter参数沿原命令的唯一章名规则，不新造编号。

```powershell
node doc/extensions/skills/story/scripts/core/story-build.mjs skeleton --feature <需求> --chapter <章名> --project-root <工程根>
```

`basis`是成文登记机器JSON入口，保持原协议，不将它改成人读章节任务。

## 2. 即时章节输入

生成Markdown输出，内容只从当前已校验对象投影，不持久化一份可编辑的设计副本：

1. 需求/章身份、蓝图revision及来源摘要；章节读者问题与现有写作设计片段。
2. 本章`依据`里的原生地址对应对象完整内容：用已校验蓝图的stableAddressIndex精确取对象，保留条件、结果与未决字段，不再由脚本摘要。相同地址只出现一次；父对象已经完整含子对象时只输出父全文并列明子地址的包含关系。
3. 明确引用的决定、缺口及相关story_details原文。只沿现行原生引用字段和已解析地址取关系，不能按段落关键词或相近ID推断。
4. 全局未决索引只含status为open_decision/blocker的决定与gap，固定列真实ID、status、owner和蓝图JSON位置；决定逐字附实际存在的rationale/knowledge.requirement，gap逐字附needed_by/unlock_condition。不要求原生不存在的question字段，无说明时明示“原生对象未提供问题说明”，不编摘要；not_applicable不进未决索引但保留在被选对象全文中。本章未关联的只标“需作者判断关联”，不能宣称不适用。已关联的提供完整原文。语义上遗漏关联仍由作者及独立审查发现。
5. 本章依据写到的原件路径/定位和本次冻结版本；文字依据原样保留。背景等合法章节可以仅依据原材料，不强迫每句话加蓝图地址。没有可解析地址只说明没有机器关联，不能据此认定没有设计责任；原件确实缺席则报输入缺口。

关联范围定为一次有界取用，不做任意递归图搜索：起始集合S是本章basisSections解析出的稳定地址；同一已选父对象实际包含的稳定子对象可算入S，包含按原生对象结构/身份判断，不按地址字符串前缀猜。

| 关联方向 | 明确读取字段 | 行为 |
|---|---|---|
| 本章→对象 | 本章依据的完整稳定地址 | 从原生stableAddressIndex取完整对象 |
| 已选对象→决定/缺口 | 对象现有verification_refs中精确可解析的decision:/gap:地址 | 取一层完整对象；其它验收编号/自由文本原样保留，不猜成坏事实 |
| 决定→本章对象 | 顶层decision的target_ref、affected_items、verification_refs，以及知识决定knowledge.target_refs/roles[].target_ref | 任一精确地址命中S则取完整决定；不因新增决定再递归扩大S |
| 专项→本章对象 | story_details[].evidence_refs | 精确命中S则取原始明细；它不在stableAddressIndex，沿现有数组读取，不新造原生地址 |
| 未定归属 | 所有open_decision/blocker决定及原生gaps | 已关联给全文，其余列全局待判断索引；gap.needed_by等自由文字不被猜成关联 |

原件路径校验只针对已登记/冻结清单和已存在的机器引用合同。写作设计的自由文字依据原样交出，不用路径正则猜它已定位到哪份原件，也不宣称脚本验证了所有自然语言引文。文本依据的忠实性归作者与独立审查。

首次写作设计之前仍须取得整体设计与全局来源；本章输入不是整体理解的替代，也不是正文内容上限。裸原生地址不存在、revision过期或声明来源不可读时，沿现有错误出口一次报全输入缺口，回写作设计或设计责任方，正文与草稿不写。选择什么图、如何叙事归作者；提交继续用chapter原子替换，机器只核结构/引用，不用关键字判是否讲清。

## 3. 替换与性能边界

当前storyInputs只交图与材料清单，本章缺少对象事实；本步骤增加的是动作前实际输入。图源/原件清单现有实现保留，按本次动作需要引用，不在每个章输入后再次倾倒全套图体和全篇来源内容。默认整篇起手仍能取得完整索引，不靠减少事实省token。

同一命令内复用已经校验的blueprint、写作设计及对象索引，不重复启动原生读取。跨命令不新增已读缓存或阅读完成状态。旧NEXT里要求每章回读“当前Story所有已写章”改为交写作设计中共享S地址的其它章/节定位，由已有Story分节解析器定位正文。它是确定相关位置索引，不穷尽语义关联；没有共享地址不表示无跨章关系，作者仍按实际关系补读。最终全篇一致性审查仍保持；不得由脚本猜无关章即可免审。

drafts仍只管草稿及骨架，不能将动态对象全文塞回可编辑草稿造成第二权威。作者需要返修已写章时用上述只读入口取当前依据，再改草稿提交；不重写整篇。

## 4. 验收

机械：章节对象与原生字段逐字对应；未决状态保留；一个对象用于多个章节/父子包含/不同合法章安排；纯原材料背景；坏地址/来源/过期版本失败无写入；无关对象正文变动不使该章输出混入无关大块（全局未决索引真实变化除外）；章提交不改其它章、已有草稿不覆盖。独立只读skeleton --chapter组装失败非零退出且全盘不变；chapter已经原子写入后若下一章输入组装失败，必须沿既有nextSteps异常出口报告“本章已落盘、下一输入缺口”，不回滚、不改提交为失败、不诱导重交。分别测这两个时点。复用`test_writing_flow.py`、`test_story_build.py`、`test_knowledge_task.py`，不用业务专名匹配断言。

语义：超时未知不变成确定无记录，验收保留未决前提；原本存在却漏写依据的业务责任仍能被全篇独立审查指出，不能以“本章输入没给”豁免。同一关系分布于不同章节可采用不同表达但结论一致。脚本输出正确只是必要条件，实际首次质量由步骤4签。

命令：`python test/scripts/verify.py affected test/tests/test_writing_flow.py test/tests/test_story_build.py test/tests/test_knowledge_task.py`。预计G150/X35；成本收益主要期待减少重复找依据和局部返修，不能在未运行前宣称提效比例。
