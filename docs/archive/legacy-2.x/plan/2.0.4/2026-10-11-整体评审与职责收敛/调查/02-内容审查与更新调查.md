## 2. 原材料到成文：最早失真位置不同

### C-01 有效来源中的入口条件，在提取后向设计承接时漏掉

`A/checkpoints/initial/SR/design.md:137` 明确写支付部件能力不可用时隐藏新签约入口；`AR/story-src/init-analysis.md:126` 已登记此项。它不是新建议、不是必须等待人重新纳入的范围。`design-draft.md:32,67` 只承接功能开关关闭后新用户隐藏、已签约入口保留；`:96` 只承接运营配置不可用按关闭处理，支付能力条件已漏。保留的 initial.blueprint 中亦未找到该条件，第二轮原始审查直接指出初析已登记、蓝图与正文未落。

最早可指认的遗漏是初析到设计提取稿；设计作者仍有冻结 SR 原文可读，不能认定冻结机制没有交付来源。遗漏随后穿过蓝图准入与首稿。设计承接不是“读取摘要即完整覆盖”：要按有效来源中的对象、条件、行为、异常与责任核对当前设计，发现未覆盖项在设计完成前解释去向。不能把无疑点的来源初筛行当成已设计证明。

第二轮 task 原始事件 `A/events.jsonl:967` 把此项列 MINOR，理由是“无对应 AC”，并要求人确认是否纳入。现行 `extensions/rules/story-reader-rules.yaml:46–60` 已明确漏掉已确认范围、两层一致性任一层不成立须阻断。规则存在而实际严重性判断错误；再追加“无 AC 也要检查”同义句不能证明解决。

### C-02 已进入蓝图的未知结果与未决前提，在首稿丢失

首稿真实写入见 `A/events.jsonl:774`：异常表把“创建签约调用失败或超时”合并，影响写为“云侧没有产生签约记录”。会议 T6 尚未确认超时是否已建约、协议号能否复用，这个确定结论无来源。首审 `events.jsonl:909` 的 task_result 正确指出 SR 只保证验证取消/失败无记录，不覆盖创建超时。

蓝图保留了 T6 未定：`A/checkpoints/initial.blueprint/blueprint/component-blueprint.yaml:1870,3206–3220`；面额上调重验待 T2 已写在 `:1418` 的 sc-ac-r6。首稿验收 AC-R6 却丢掉未决注，首审原始报告发现2明确指认。这一类最早错误在蓝图到 Story 表达，不能修改蓝图迁就首稿。

修复后 initial checkpoint 的 `AR/story.md:276–277` 区分明确失败与超时未知，`:302` 的 AC-R6 保留面额上调待定边界。这证明本轮纠偏发生，不证明首次成文能力成立。initial checkpoint 是初段完成后的快照，不能把它误称首稿；首稿应回 events 的写入与首审原始回复。

`extensions/skills/story/phases/story-write.md:238–257,369–404` 已要求按关系同步受影响位置并回看原材料。首审仍有错误说明作者执行不足。修正必须把正常成文动作变成以一条关系为单位组织，再投向相关章节，而不是再叠一个自报核对表或固定“四处”规则。不同需求涉及哪些章节应由当前关系决定。

### C-03 原样专项投影保留了上游含混，而审查建议误交 Story 改设计

首审原始回复 `A/events.jsonl:909` 发现3指出蓝图专项写“验证结果决定 create/update 分支”，但管理路径的 update 与签约路径 create 不同。initial.blueprint `:3613` 仍保留该原句。`extensions/hooks/blueprint/author.md:46–59` 与 `phases/design.md` 成文段要求专项内容逐字呈现，Story 作者补解释不能改变专项原意。

合理保留精确专项投影，但蓝图作者须在准入前讲清分支来源；改变决定回蓝图修订。独立审查把此问题交 Story 改句或留 CU 定，责任不够准确。不能把“按上游原文复制”作为整体正确性豁免，也不能让 CU 定已经影响整体流程的共同承诺。

## 3. 独立审查原件实际上被作者改写

现行 `extensions/skills/story/phases/design.md` 五节派审要求 dispatch_text 原样交子代理，原回复原样保存。`independent-review.mjs:150–176` 的 dispatch 明确“只写上面这一份回复，其余文件保持原样”。本轮 `A/checkpoints/initial/AR/story-src/review/dispatch.md:6–10` 同样给出了报告路径和写入权限。

实际首审 prompt `A/events.jsonl:909` 自行重组任务，尾句改成“你只读文件、做判断，绝不修改任何文件”。第二轮 `:967` 也如此。它否定了产品给审查者写报告的具体权限，于是报告先返回 task 文本，由作者重新写盘。最早失效是派审输入被主作者改造，不是报告格式检查器没有理解语义。

该问题不能只解释为“宿主包装导致字节不同”：上表已取 task_result 正文，长度和具体段落均有实质编辑。格式检查只证明作者缩写件符合报告合同。当前 `independent-review.mjs:130–145,181–199` 的原样摘要保护在报告被引入返修上下文后才保存指纹，不能追溯证明首份落盘是否对应宿主原输出。

最简单修正是使用现有隔离 task 按 dispatch 直接写唯一报告文件，作者只读消费。已有写文件能力的子代理不再被加“绝不修改任何文件”。宿主确只能返回文本时才由宿主保存 task_result 正文原字节，格式问题交原审查者再给新回复，不让作者摘要修格式。独立语义仍由模型负责；原始输出保存是机械责任，不能用模型自报“原样”替代。

## 4. 九轮原因、复用和上下文

本轮九次 Story task 在 `A/events.jsonl:909,967,993,1022,1065,1078,1099,1115,1126`，从 11:42 到 13:04，首末约83分钟。首轮两项真实 MAJOR；第二轮实际遗漏被低估；以后表达调整持续产生新的重复、错误来源、缓存措辞、观察口径与验收差异，最终追到 pass。既有真实必须修的问题，又有建议清零式反复成文，不能一律免审或一律重复全改。

例如第二轮补入口条件后下一轮指出重复句；`events.jsonl:1065` 的 prompt 仍主动邀请未采纳 INFO “如果你认为确实需要可以提出”；`:1078` 表明三条 INFO 又被全部采纳并改材料。`phases/design.md` warn 行已经允许不采纳并记录理由、不因建议反复重审。因此优先修作者交付动作与非阻断建议处置，不能加固定轮数上限。

`independent-review.mjs:101–125` 正确在同键 pass/warn 时复用；fail 同键重新派审；材料改变没有 review_context。本轮键确实改变，缓存无失效证据。变化需新结论是合理保护，旧发现仍有返修参考价值，不应和旧结论一起消失。

本轮作者实际在 `events.jsonl:967,993,1065,1078` 自行附上上轮发现与“已修正”摘要。不能说九轮都因审查者不知道前轮；问题是背景由作者选择性转述，dispatch 未实现正常变化后的原报告交接。修复复用现有 prepared、report_file、原件指纹和 dispatch，跨版本把上一份原报告作为待核参考，明确结论仍只针对当前材料；不用新增审查账本，也不将旧 pass 迁给新版本。

`extensions/hooks/shared/reader-review-task.mjs:258–270` 每次要求来源、人签、蓝图与全交付完整读；同字节设计附件与评审投影只读一次合理。当前没有证据证明可安全仅审 diff。完整范围保留，避免本次省时掩盖此前遗漏；先消除原件改写、反复成文与责任误交，再测成本。

`review-object.mjs:58–65,72–78` 同时枚举历史会议 raw 与冻结采用文件，按路径去重（`:101–102`）。历史证据应当区分当前采用依据与历史裁决对照，但本轮尚无证据把它认成九轮的直接原因。暂不加内容去重缓存或更改材料键算法。

冻结外部原件另有边界待验：`materials/frozen.py:193–200` 的 origins 为 inbox 原件登记路径与采用时摘要；`:209–221` 冻结 adopted_files 的字节，未把 origins 引用的全部外部 docx 再冻结一份。`story/sources.mjs:220–244` 从活 inbox 路径读原件、摘要不同或缺席时报缺口。update 方法允许把旧同名原件移入 `.backups/local` 再放新版本，故合法触发是“旧快照仍为当前绑定，旧原件已备份、新原件正在导入”；该过渡期间旧来源核缺口符合显式失效，不宜自动降级。新 complete 是否重建当前 origins、restore 回旧 Story 后原件能否沿备份恢复，需用现有离线更新入口验证。当前本轮没有这条真实变化证据，不裁定必须新增永久原件存储，也不能把‘能报缺口’称作长期可恢复成立。

## 8. 上游依赖与未验证

直接报告保存可先使用现有 task 写文件能力，未发现必须先加 Framework 能力的证据。若具体宿主无法让隔离执行者写唯一报告，需上游提供原始输出稳定落盘及绑定，Extension 不复制通用调用或报告调度器。不同宿主能力须实际核定，不能把本轮 general task 行为推给所有宿主。

未验证：本轮审查子代理内部究竟读了哪些文件没有独立内部事件，任务要求与报告自述不等于读完证据；图片像素审查缺失；其他合法业务首次成文改善；变化后原报告交接的成本效果；update真实业务与人工保护完整链；Spec独立审查与Plan。本报告没有把门禁、字段齐或摘要一致当这些行为成立。
