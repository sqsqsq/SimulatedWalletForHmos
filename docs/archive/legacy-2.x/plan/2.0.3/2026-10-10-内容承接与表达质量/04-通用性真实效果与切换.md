# 步骤4：通用性、真实效果与正式切换

## 验证与证据

先离线与维护内容走查，再获授权的独立评价及正常CLI。复用现有专项夹具和verify.py，不新增完整Case或评测平台。

| 输入 | 预期 |
|---|---|
| 中性业务替换 | 不依赖Case名词、数值、对象数或图数 |
| 无云/无图/无模式/无待决 | 不强迫编造内容，空合法与输入损坏分开 |
| 名称/组织/图型/合理CU划分变化 | 语义成立不因形式差异误拒 |
| 错主体查询/漏恢复/单位变义/未决写定案 | 独立内容评价指出实际错误及最早责任 |
| 引用失效/材料变化/报告失效/人工区覆盖 | 机械检查正确失败且给恢复方向 |

专项测试覆盖story_build、writing_plan/flow、verifier_report_protocol、knowledge_task、cu_knowledge_chain及现有原生派审材料用例。只跑相关affected，最后handback；无新改动不反复全量。语义反例不变成产品关键词判定器；指令、注释、测试和实际生成内容都核过拟合。

## 正常双Case与成本

保持自动充值初段送审+update、车钥匙止于Plan+update。按实际索材与提问回答，不预告答案，金样/维护判据不进消费工作区。输入采用本轮已记账版本，不能把改了立场的运行与旧输入直接比成本。

五个问题分别给可定位证据：产物达到读者效果；信息先于行动实际送达；已定表达复用/局部细化有真实增量；独立审查发现真实问题并回正确责任；重复读取/派审/返修有无信息增量。

质量先达标后比较同输入/终点配对的token、有效处理时间与人工操作。遵循R3既有非增长签收条件，原始usage/未知统计如实披露；失败基线只证明恢复，不作为提效基线。没有模型或CLI授权不得启动；未验Coding/设备/内网不扩称完成。

## 正式切换与退出

用户审定后切test/golden新情景正本，核枚举、指纹、_golden_titles、knowledge_forms、唯一副本与旧覆盖迁移。历史原件保留，新旧稿不同时维护为正式权威。退出旧图标记及旧生成/check消费者；无消费者代码/配置/说明和专用测试清理，正常覆盖有接替才删除。

审查建议、异常场景、原生接口缺口分别交回，不因个别上游问题挡住所有维护工作，也不以CLI能启动宣布全部依赖解决。发布/demo更新、提交推送按实际授权。

完成分别报告金样效果、机制正确与通用性、真实过程与成本。本轮交回带单步和累计G/X、退出对象、证据、剩余事项；不能以测试总数、图数或一份候选修好宣告整个2.x适配完成。
