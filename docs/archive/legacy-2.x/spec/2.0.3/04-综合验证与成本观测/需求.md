# R4 质量与需求执行成本的综合验收

承接原 2.1.0 R4 的 G1/G2/Q1 及 P1 中需求执行成本；安装 A1–A6、图形 V1–V3 与相应成本留 2.1.0。操作、评分与机械计量按 test/TEST.md，不新增评测平台。

## 1. 证据与场景

输入为本次实际 Framework/Extension 组合、产品 diff、R1 审定修订稿、对应材料/真实决定和实际运行。金样与维护分析不能进入消费模型工作区。不同模型/输入/终点/版本的结果不能混算收益。

| 组 | 场景 | 完成证据 |
|---|---|---|
| G1 | 两 Case 来源、G01–G09、待决与按立场定案的情景 | 原件、宿主立场与工程事实可追，修订贯穿 Story、Review 与必要的 Spec、Plan；立场注明是构造预期的输入，不写成已发生的人签 |
| G2 | 金样正本替换及消费者迁移 | 用户审定目标金样；确定性机制改由专项夹具验证；旧有效场景有承接，只有一份正式效果正本 |
| Q1 | 内容与表达 | 同事实/决定贯穿正文、图、验收和工程接入；摘要不漏关键约束，合法差异不误伤 |
| Q2 | 独立审查 | 实际输入、读取范围、原始回复及发现与当前对象对应，未由作者加工结论 |
| P1 | 需求执行成本 | 同输入/质量/终点的 token、时间、人工操作和真实返修；收益/代价均披露 |
| K1 | 原能力保持 | 2.0.2 冻结、恢复、派审、发布和原生阶段接缝保持；无 Coding/设备证据不扩称完成 |

结构检查只证格式/引用/状态；独立语义核真实内容；效果由读者判断；成本以完成正确工作的代价计。既有异常/保护用相关回归核保持，不扩新异常状态矩阵。

## 2. 正式 Case 与诊断

沿现有自动充值系统单和车钥匙本地单，命令起手、按实际索材/提问回答、不预告答案，本版正式安排是自动充值首段送审及 update、车钥匙实现方案止于 Plan 及其现有 update，均在实际运行前取得授权；缺真实裁决按 R1 情景处理。直接 Framework、多 CU、复用按本次适用范围列明；未覆盖记未验证，不为填表强拆需求。

审查发生真实错判时先读现有主/子会话和产物；需要定向诊断则使用当前 Story 审查合同与保留的中性材料，模型调用另获授权。已经退出的 spec overlay/旧报告资格驱动不恢复，不将通用代码审查重新包装为 Story 审查。

### 2.1 通用性验收

| 验证方式 | 输入安排 | 成立条件 |
|---|---|---|
| 业务替换 | 预约、文档协作等中性业务表达相同责任关系 | 不依赖Case名词、数字或固定对象 |
| 不适用 | 无云服务、个人身份、埋点、待决或适用模式 | 不强迫编造内容或流程 |
| 合法变形 | 名称、章节组织、图型、参与方数量、合理CU划分变化 | 语义成立就不因形式不同误拒 |
| 真实反例 | 漏恢复入口、超时当失败、掩码代身份、未决写定案 | 独立内容评价指出问题及最早责任 |
| 机制反例 | 引用不存在、材料变化、报告失效、人工区覆盖 | 确定性检查准确失败并给恢复方向 |

覆盖作者任务、脚本、判据、注释、测试和实际生成内容；零专名命中只是其中一项。复用现有专项输入，不新建完整CLI Case或评测平台。机械证据、维护语义走查、授权独立模型评价分别登记。

正式双Case同时核结果与金样的读者效果、任务/知识/决定的送达时机、独立审查实际发现与修复责任、重复读取/派审/返修的原因，以及原能力保持和旧职责退出。不同输入时不混算性能收益。

## 3. 切换、失败与完成

R1 修订稿先在方案工作区审定，不提前替换 test/golden。独立内容复核与用户效果审定成立、消费者迁移通过后，一次切换正式效果正本与枚举、指纹等实际消费者；金样不经生产链装配，旧整链装配与专用断言退出，有效业务覆盖保留或迁移。新旧候选不得都称正式金样。

源材料/人签不足回权威；产品缺陷回现有责任；上游能力缺失保持依赖。2.0.2 未完成项继续归原版收口，本版保持性不代签原版。上游、真实 CLI、内网、设备、发布分别按实际授权和证据报告。

## 4. 统一签收

当前四步实施以10-10方案为准。验证已定内容是否实际取得、已有表达是否正确复用、局部细化是否有据、共同变更是否回责任方；明确检查单一图源协议及旧消费者退出。原生lifecycle/extension摘要接缝已有，不再预设为上游待交付接口。FW-04/05及术语模式问题按真实交付状态分别报告。


人读质量按 R2 §1.1 的读者问题和 TEST 三轴，不因原生附件存在而签收；效率严格按 R3 §3 的配对条件，token/时间相互抵消不算整体改善。当前金样只在内容通过、用户审定及旧覆盖迁移全部成立后切换；真实 CLI 与成本验收仍是版本完成条件，但不是编写期望稿的前置。正常 Case 未完成、上游依赖未到位或成本不可比的能力明确未完成，不用版本迁移降低目标。
