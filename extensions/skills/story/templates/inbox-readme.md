# 上游材料收件箱

需求系统里 PRD / SE 设计还没归档，或者手上有补充说明、界面设计图、澄清会议记录时，把文件放进**本目录**（整个文件夹放进来也行），
然后在对话里说一句「材料放好了」。AI 会读内容判断每份是什么、转换并接进流程；你也可以顺带说明某份是什么
（例如「这份只是补图」「这是周二澄清会的记录」），AI 按你的说明取用；一份稿件的正文里有别的材料没写到的内容时，AI 会保留正文并告诉你为什么。

## 放什么

| 材料 | 格式 | 去向 |
|---|---|---|
| 产品需求、系统设计、本部件补充说明 | `.docx`，或 `.md` `.txt` 等文本文件 | 成为对应的上游正文（`RR/prd.md`、`SR/design.md` 等）；`.docx` 里的表格与图片一并保留 |
| 正文已由其他材料完整写到、只需要里面图片的稿件 | `.docx` | 只抽出图片，正文不作依据 |
| 界面设计图、视觉稿、交互说明 | 图片（`.png` `.jpg` `.jpeg` `.webp` `.bmp`）或文档 | 进 `assets/ux/`，每张图带一句说明 |
| 需求澄清会议记录 | 原始 `.docx` | 按版本存档；AI 读会后把要定的事摆给你确认 |

其他格式（如 `.pdf`）AI 读得懂就自己转写后再导入，读不了会告诉你需要什么版本。

## 几条约定

- **路径即章节标题**：转换后每份材料成为正文里的一节，标题就是它在本目录下的相对路径；
- **同类多份按所在路径排序拼接**（先比子目录名，再比文件名）：想控制先后就加数字前缀（`1-总体.docx`、`2-补充.docx`）；
- **不同文件夹里可以有同名文件**：按所在路径区分，各自导入、互不覆盖，不用改名；
- 以 `.` 开头的文件和文件夹、各层的 `README.md` 不当材料；
- **原文件留在这里存档**，不会被移走或删除；已经导入过的原样文件再导一次不会重复导入；
- **改了重放即可**：更新文件内容后再导一次，对应正文重新生成；每一版的原件与转换结果另存在 `../.backups/local/`，
  被换掉的旧版仍可回查，已经依据旧版的设计与审查也指得回原来的字节。
