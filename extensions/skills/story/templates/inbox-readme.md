# 来源收件箱

需求系统里 PRD / SE 设计还没归档，或者手上有补充说明、界面设计图、澄清会议记录时，把文件放进**本目录**（整个文件夹放进来也行），
然后在对话里说一句「材料放好了」。AI 会读内容判断每份是什么，导入后接进流程；你也可以顺带说明某份是什么
（例如「这份只是补图」「这是周二澄清会的记录」），AI 以你的说明为准。

## 放什么

| 材料 | 格式 | 导入后 |
|---|---|---|
| 产品需求、系统设计、本部件补充说明 | `.docx`，或 `.md` `.txt` 等文本文件 | 原件与转换出的正文一起存成一个材料版本；`.docx` 里的表格与图片一并保留 |
| 为了补图的原稿或参考稿 | `.docx` | 只取其中的图，正文不作依据 |
| 界面设计图、视觉稿、交互说明 | 图片（`.png` `.jpg` `.jpeg` `.webp` `.bmp`）或文档 | 存成材料版本，每张图带一句说明 |
| 需求澄清会议记录 | 原始 `.docx` | 按会议版本存档；AI 读会后把要定的事摆给你确认 |

其他格式（如 `.pdf`）AI 读得懂就自己转写后再导入，读不了会告诉你需要什么版本。

## 导入之后

- 每份原件导成上一级目录里的一个材料版本（`<名称>-v1/`），原文件名不改；导入成功的文件从本目录移走，这里只剩还没导入的；
- **不同文件夹里可以有同名文件**：按所在路径区分，各自成为一份材料，不用改名；
- **改了重放即可**：同一位置放入改过的文件再导一次，存成新版本，旧版本留着可查；内容没变就沿用原版本；
- 有哪些材料、各自最新是哪一版，看上一级目录的 `README.md`；
- 以 `.` 开头的文件和文件夹、各层的 `README.md` 不当材料。
