# 增强阅读 SVG：正式图的同图阅读形态

> 读者：做增强阅读 SVG 的作者，以及做它验收的独立审查者。时机：story 业务登记与审查成立之后，
> `story_flow.py status` 报「完成本地阅读」时。正式登记、审查、update 比较与归档一律在 Mermaid 形态做，SVG 不改变它们的对象。

## 一张图、一个 ID、两种形态

- **正式图**是正文的一部分：Mermaid 写在正文里，`story-build view --mode prepare` 给它加 `<!-- story-figure:<ID>:begin/end -->` 标记并首次写源
  `AR/story-src/figures/<ID>.mmd`。源一建成就是唯一语义真源：改图义改 `.mmd`，再跑 `view --mode mermaid` 让正文跟上，随后照常重新登记与审查。
  块结构坏了而边界还认得出、源还在，`prepare --id <ID>` 从源重建这一块；源丢了从备份或真实依据恢复，不从正文或 SVG 反写。
- **增强阅读 SVG** 是同一张图的另一种形态：`AR/figures/<ID>.svg`，ID 与正式图相同。同样的事实，把布局、分组、角色或层次、
  标注与连线做得更清楚；不追加业务关系，不删条件与异常。与 Mermaid 表达相同事实是本来要求，不是不做的理由；
  要改的是图的意思时回 `.mmd` 与它的业务依据，再按新源重做 SVG。每张正式图都要做，没有正式图就没有要做的。
- **原位切换**：图块里一次只放一种形态——Mermaid 围栏，或一行 `![<ID>](figures/<ID>.svg)`。`view --mode svg` 只把验收成立的图换成 SVG，
  其余保持 Mermaid 并说明原因；`view --mode mermaid` 全部换回；`view --mode toggle` 来回切（AR 目录下的 `切换视图.cmd` 双击就是它），
  带 `--id <ID>` 只动这一张。正式命令动手前自动回到 Mermaid，结束或失败后恢复当前可用的 SVG。图块之外不写指向 `AR/figures/` 的引用，`check` 会逐处点名。

## 按图的用途组织

| 图在讲什么 | SVG 怎么组织 | 中性示例 | 必须保住（审查也核这些） |
|---|---|---|---|
| 流程与分支 | 主线清楚，复杂分支分区，多责任时用泳道 | 资料申请、补件、批准或退回 | 每个分支的条件与去向，回流接回正确位置；不凭布局多出分支 |
| 时序交互 | 参与方横排、时间纵向，调用与返回一眼分得开 | 预约请求、名额确认、通知结果 | 消息起止方、先后、等待、响应与失败处理；不把不同执行方混成一条线 |
| 状态与动作 | 状态节点 + 带触发条件的迁移箭头，必要时分组 | 申请草稿、待审、通过、撤回 | 初始与终止、合法迁移；动作不画成状态，终态不多出无依据的出口 |
| 对象关系 | 对象卡片 + 命名清楚的关系连线 | 场馆、房间、预约记录 | 名称、方向与源里已有的数量约束；不补造基数或字段 |
| 架构与责任边界 | 按真实边界分区，突出跨区连接 | 前台、审批、通知服务 | 所有权、依赖方向与数据交接；分区好看不能掩盖真实责任 |
| 依赖与开放顺序 | 前置到后继排列，可并行的并排 | 基础能力、业务接入、开放验证 | 依赖与并行关系；不因排版制造先后，不虚构日期 |

按实际图型用，不要求一单遍历六类；不固定坐标、颜色或节点数。

## 做一张

1. 按 `AR/story-src/figures/<ID>.mmd` 做，根元素是带 `xmlns="http://www.w3.org/2000/svg"` 的 `<svg>`，资源用内嵌或 `AR/` 下的本地文件
   （样式里的 `url(...)`、`@import` 也算），`viewBox` 写四个有限数。手边有能出 SVG 的现成工具可以先生成再整理；没有就按源手写。
   把 `.mmd` 改个后缀不是 SVG，Mermaid 文本也不是增强。
2. **结构检查**：`python doc/extensions/skills/story/scripts/core/story/figure-check.py AR/figures/<ID>.svg --id <ID>`。
   它只核 XML、根元素、viewBox、文件名与引用（href 与样式里的 `url(...)`、`@import`，递归跟进），不判可读。
3. **验收请求**：`story-build view --mode review-request --id <ID>` 绑定这张图的 `.mmd` 内容、SVG、它用到的本地资源与审查方法生成请求，
   并给出交给独立审查者的任务（图源原文放进任务，SVG 与资源给路径由审查者自己打开）。不需要渲染图。
4. **独立审查**：按任务开头写的方式，用宿主现有的专用独立只读审查入口同步调用一次，把【交给审查者】一段原样作为完整任务交给它，
   不传你的结论；审查者读 SVG 源码里实际的文字、图元与连线，对照图源判事实与关系一致、增强后是否更好读，把报告 JSON 作为最终回复返回。
   你按【作者收尾】把回复原样存到 `AR/story-src/figures/<ID>.reading/report.json`，只把 executor 填成宿主返回的这次审查执行或会话引用。
   同一上下文的自查不能代签。没有回复、格式不合或调用中断：保留请求与原回复，修好调用条件后把同一任务完整再交一次，不替审查者补结论。
   宿主没有可用的独立审查入口就如实报「独立审查入口缺失」——这和没有看图能力不是一回事，看不了图不妨碍这一步。
5. `story-build view --mode review-check --id <ID>` 核报告绑定当前请求、结论成立，再跑 `view --mode svg`。
   这个结论只证明源码与图源一致；实际显示有没有裁切、遮挡，需要时用浏览器或人看一眼，发现缺陷照常改图重审，不要求每张图存截图。

## 改了之后怎么恢复

`view --mode status` 与 `review-check` 报出每张图的当前状态和最小恢复动作，按这张表做：

| 变了什么 | 恢复 |
|---|---|
| 图源 `.mmd`、SVG、它用到的本地资源变了，或请求被改坏 | 重新生成请求 → 独立审查 |
| 请求有效，只缺报告或报告不合规 | 把同一请求交独立审查，回复原样存为 `report.json`；不重建输入，作者不改结论 |
| 旧版补充阅读图的请求或报告 | 不能当这张图的验收：按当前图源与 SVG 重新生成请求、重审；旧证据留在原处 |
| 别的章节、编号、注释分隔空行，或只显示、隐藏 | 验收不变 |

报告结构核得过只说明它对得上这一份请求，不证明审查真的独立发生——交回时写清每张图由谁、在哪个会话审的。
