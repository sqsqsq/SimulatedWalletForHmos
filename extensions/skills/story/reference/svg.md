# 阅读图：写作设计选中的补充 SVG

> 读者：做本地阅读图的作者，以及做阅读图验收的独立审查者。时机：写作设计「## 阅读图选择」选了候选、story 业务登记与审查成立之后，
> `story_flow.py status` 报「完成本地阅读」时。正式登记、审查、update 比较与归档一律在正式形态做，阅读图不改变它们的对象。

## 正式图与阅读图

- **正式图**是正文的一部分：Mermaid 写在正文里，`story-build view --mode prepare` 给它加 `<!-- story-figure:<ID>:begin/end -->` 标记并首次写源
  `AR/story-src/figures/<ID>.mmd`。源一建成就是唯一语义真源：改图义改 `.mmd`，再跑 `view --mode mermaid` 让正文跟上，随后照常重新登记与审查。
  块结构坏了而边界还认得出、源还在，`prepare --id <ID>` 从源重建这一块；源丢了从备份或真实依据恢复，不从正文反写。正式图不需要 SVG。
- **阅读图**只为写作设计里选中的候选做：`AR/figures/<ID>.svg`，ID 是候选的 ID，不必对应哪张 Mermaid。它回答候选写的阅读问题，
  可以综合多段文字、表与图，补出依据里已有、但分散或隐含的关系；不编造依据里没有的规则，不作业务决定的来源，不上传。
- **阅读槽**：每个候选在放置小节末尾有一对 `<!-- story-reading:<ID>:begin/end -->`，同一处多张按写作设计顺序排。
  正式形态槽是空的；显示时槽里只有一行 `![<阅读问题>](figures/<ID>.svg)`。改了选择、放置或顺序就跑一次 `view --mode prepare`：
  它按当前选择移除旧槽、在新位置重建空槽；槽里有别的文字、标记坏了或放置小节找不到时整次不写。
  已取消候选的 SVG 与验收证据留在原处，不参与完成判定，不再用由作者清理。槽外不写指向 `AR/figures/` 的引用，`check` 会逐处点名。
- **显示与隐藏**：`view --mode svg` 只把验收成立的候选放进自己的槽，其余槽保持空并说明原因；`view --mode mermaid` 把全部槽置空；
  `view --mode toggle` 来回切（AR 目录下的 `切换视图.cmd` 双击就是它），带 `--id <ID>` 只动这一张。
  正式命令动手前自动回到正式形态，结束或失败后恢复当前可用的阅读图；阶段审查期间保持正式形态。

## 什么样的阅读图成立

| 图要讲的 | 可以 | 必须保住 |
|---|---|---|
| 流程与分支 | 主线横排、分支纵排，按角色分泳道，把散在几节的分支收到一处 | 每个分支的条件、终点（正常与异常各到哪）、谁做的这一步 |
| 时序 | 按参与方分列，把重复的请求与返回收成一组并注明次数 | 先后、谁调谁、谁返回、失败时谁负责补救 |
| 状态 | 按生命周期从左到右排，终态集中 | 每条迁移的触发条件，不可逆的那几条 |
| 对象关系 | 按归属分组，数量关系写在连线上 | 一对多、多对多与可空 |
| 架构责任 | 按责任方分区，跨区的线只保留交接 | 每个交接点两边的责任，数据从哪来到哪去 |
| 依赖与边界 | 按阶段分列，可并行的放同一列；已定与未决分区 | 阻塞关系与先后，未决项标成未决 |

不固定图数、节点数或坐标。读者看完能比只读这一节的文字、表与 Mermaid 更快地回答阅读问题，才算有增益——把已有但分散的关系放到一处也算，
只换颜色或方向不算；怎样选候选见 [`story-write.md`](../phases/story-write.md)「阅读图选择」。做出来发现没有增益，回写作设计把候选改成不采用，再走正式内容审查。

## 做一张阅读图

1. 按候选的阅读问题与全部依据画，根元素是带 `xmlns="http://www.w3.org/2000/svg"` 的 `<svg>`，资源用内嵌或 `AR/` 下的本地文件
   （样式里的 `url(...)`、`@import` 也算），`viewBox` 写四个有限数。`<metadata>` 可以写一句依据说明，权威绑定是验收请求里实际读取的依据。
2. **结构检查**：`python doc/extensions/skills/story/scripts/core/story/figure-check.py AR/figures/<ID>.svg --id <ID>`。
   它只核 XML、根元素、viewBox、文件名与引用（href 与样式里的 `url(...)`、`@import`，递归跟进），不判可读。
3. **验收请求**：`story-build view --mode review-request --id <ID>` 按写作设计逐条读取依据的实际内容
   （整份文件绑定全文，`> 标题` 指到的一节连同子节；原件按它导入的阅读稿取，原件、阅读稿与抽出的图按字节一起绑定；图片按字节绑定），
   连同放置小节正文、槽的顺序、SVG 与本地资源生成请求，并给出交给独立审查者的任务：按小节取的依据原文放进任务，
   整份文件、图片与只抽图原件的原图给路径由审查者自己打开，原件只作身份。不需要渲染图。
   依据取不到、标题有歧义、实际位置在需求目录外（目录联接与链接按真实位置判）、登记过的材料在登记之后变了，
   或依据里的正式图与 `.mmd` 不一致（先跑 `view --mode mermaid`）时不出请求；重验时同样按这些重新判。
4. **独立审查**：按任务开头写的方式，用宿主现有的专用独立只读审查入口同步调用一次，把【交给审查者】一段原样作为完整任务交给它，
   不传你的结论；审查者读 SVG 源码里实际的文字、图元与连线，对照依据判事实与关系忠实、阅读增益与位置相称，把报告 JSON 作为最终回复返回。
   你按【作者收尾】把回复原样存到 `AR/story-src/figures/<ID>.reading/report.json`，只把 executor 填成宿主返回的这次审查执行或会话引用。
   同一上下文的自查不能代签。没有回复、格式不合或调用中断：保留请求与原回复，修好调用条件后把同一任务完整再交一次，不替审查者补结论。
   宿主没有可用的独立审查入口就如实报「独立审查入口缺失」——这和没有看图能力不是一回事，看不了图不妨碍这一步。
5. `story-build view --mode review-check --id <ID>` 核报告绑定当前请求、结论成立，再跑 `view --mode svg`。
   这个结论只证明源码语义；实际显示有没有裁切、遮挡，需要时用浏览器或人看一眼，发现缺陷照常改图重审，不要求每张图存截图。

## 改了之后怎么恢复

`view --mode status` 与 `review-check` 报出每张图的当前状态和最小恢复动作，按这张表做：

| 变了什么 | 恢复 |
|---|---|
| SVG、它用到的本地资源、依据内容、候选的问题/增益/放置/顺序或放置小节正文变了，或请求被改坏 | 重新生成请求 → 独立审查 |
| 请求有效，只缺报告或报告不合规 | 把同一请求交独立审查，回复原样存为 `report.json`；不重建输入，作者不改结论 |
| 阅读槽缺失或错位 | `view --mode prepare` 同步槽；放置真的变了，按第一行重审 |
| 与这张图的依据和放置小节无关的章节，或只显示、隐藏 | 验收不变 |

报告结构核得过只说明它对得上这一份请求，不证明审查真的独立发生——交回时写清每张图由谁、在哪个会话审的。
