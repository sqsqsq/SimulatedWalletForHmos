# 阅读图：把 Mermaid 图重述成 SVG

> 读者：story 写完、要给评审人一份更好读的本地视图时的作者，以及做对照审的独立审查者。时机：story 已登记、正式检查过之后；
> 正式登记、审查、update 比较与归档一律在 Mermaid 形态做，阅读图不改变它们的对象。

## 一份文档，两种形态

- **Mermaid 是图的唯一语义真源**：`AR/story-src/figures/<ID>.mmd`。改图义改它，再跑 `story-build view --mode mermaid` 让正文跟上，
  随后照常重新登记与审查。
- **SVG 是同一张图的重述**：`AR/figures/<ID>.svg`。可以换布局、换方向、拆泳道、合并表达上的冗余；
  不增删关系、条件、责任与结果。它不上传、不作业务决定的来源。
- **管理块**：`story-build view --mode prepare` 给还没管理的 Mermaid 图加 `<!-- story-figure:<ID>:begin/end -->` 标记并首次写源；
  源一建成，正文块只按它派生：块里的图与源不同时，切换按源重铺并说明，块里的改动不保留。
  块结构坏了而边界还认得出、源还在，`--id <ID>` 从源重建这一块；源丢了从备份或真实依据恢复 `.mmd`，不从正文反写。
  标记之间是脚本管理区，不要手改；块外的正文照常改。
- **切换**：`view --mode svg` 只把有阅读图、结构检查过、来源快照就是当前源的块切过去，其余保持 Mermaid 并说明原因；已经显示的阅读图每次也重核，不合格就切回；
  `view --mode mermaid` 精确还原。正式命令与阶段开始前会自动切回 Mermaid，`story_flow.py archived` 登记完会切回 SVG。

## 六类图怎样重述

| 图讲的是 | 重述时可以 | 必须保住 |
|---|---|---|
| 流程与分支 | 主线横排、分支纵排，按角色分泳道，汇合点合并画 | 每个分支的条件、终点（正常与异常各到哪）、谁做的这一步 |
| 时序 | 按参与方分列，把重复的请求与返回收成一组并注明次数 | 先后、谁调谁、谁返回、失败时谁负责补救 |
| 状态 | 按生命周期从左到右排，终态集中 | 每条迁移的触发条件，不可逆的那几条 |
| 对象关系 | 按归属分组，数量关系写在连线上 | 一对多、多对多与可空 |
| 架构责任 | 按责任方分区，跨区的线只保留交接 | 每个交接点两边的责任，数据从哪来到哪去 |
| 依赖顺序 | 按阶段分列，可并行的放同一列 | 阻塞关系与先后，不能为对齐而改顺序 |

不固定图数、节点数或坐标；读者看完能比读 Mermaid 更快地回答同样的问题，才算重述成立。

## 写一张阅读图

1. 按上表重述，根元素是带 `xmlns="http://www.w3.org/2000/svg"` 的 `<svg>`，资源用内嵌或 `AR/` 下的本地文件（样式里的 `url(...)`、`@import` 也算），`viewBox` 写四个有限数；`<metadata>` 里原样放这次采用的 `.mmd` 全文（可包在 CDATA 里）——
   切换按它认「这张图对应的是不是当前源」，源一改就要重做。
2. **结构检查**：`python doc/extensions/skills/story/scripts/core/story/figure-check.py AR/figures/<ID>.svg --id <ID>`。
   它只核 XML、根元素、viewBox、来源快照、文件名与引用（href 与样式里的 `url(...)`、`@import`），不判可读。
3. **渲染核**：用宿主能用的预览工具真正打开看，核文字、裁切、遮挡与连线；临时截图放工作件位置。没有看图证据的视图算没做完，
   结构检查通过不能代签。
4. **对照审**：交给不是作者的审查者，同时读 `.mmd` 与渲染出来的 SVG，逐条核分支条件、正常与异常终点、先后、状态迁移、数量与责任；
   多画的分支、漏掉的去向、混了的责任都是问题。它与正式的需求审查分开，不把 SVG 交给正式审查。
5. 三件都过了再跑 `view --mode svg`。只改了 SVG 布局，重做这一张的三件即可，正式审查不重派；改了 `.mmd`，三件全部重做。

元数据相同只说明来源版本相同，不说明语义等值；有一份审查报告文件也不说明对照审做过——交回时写清每张图三件各自的实际结果。
