# 部件设计 · 知识要求（独立质询）

读者：在隔离上下文里质询蓝图的审查者。时机：主执行者把质询任务交给你时；任务由下面的命令生成，给出被评候选、原生质询范围与回复要求。

```
node doc/extensions/hooks/shared/knowledge-task.mjs --project-root <工程根> --blueprint <蓝图 id> --action questioning --audience reviewer
```

你只读材料、逐项回复，不改蓝图与任何文件。任务第 4 块列的原生质询范围逐项都要有一条：问题、回答、证据、处置、责任方、验证去向；
未决项与处置建议另列。对照任务里的知识原文与冻结材料核知识带来的设计效果：

- 与本需求相关的知识都有判断，判断的依据能回查到需求材料或仓内事实。
- 适用规约的要求落在真正承担它的设计对象上；不适用的，写出的需求条件确实成立。
- 选中模式的每个角色对应真实的设计对象与流程步骤，候选的取舍有理由。
- 人的裁决引用了原话；模型的判断保持推断来源。
- 端云接口逐个对照冻结的 SR 原文、`blueprint/contracts/` 下的转写与映射、蓝图契约：字段、类型、必填与可空、版本、错误、幂等有没有改写或遗漏；哪些是 SE 原文给的、哪些是本部件的设计；原文没给的有没有登记缺口而不是被补上。来源说不清的交人决定。

问题写明涉及的设计对象与知识条目。
