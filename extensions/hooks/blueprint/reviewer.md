# 部件设计 · 知识要求（独立质询）

读者：在隔离上下文里质询蓝图的审查者。时机：质询开始前取一次知识任务。

```
node doc/extensions/hooks/shared/knowledge-task.mjs --project-root <工程根> --blueprint <蓝图 id> --action questioning --audience reviewer
```

在原生质询范围（视图、关系、流程、应用镜头、术语）里核知识带来的设计效果，对照任务里的知识原文：

- 与本需求相关的知识都有判断，判断的依据能回查到需求材料或仓内事实。
- 适用规约的要求落在真正承担它的设计对象上；不适用的，写出的需求条件确实成立。
- 选中模式的每个角色对应真实的设计对象与流程步骤，候选的取舍有理由。
- 人的裁决引用了原话；模型的判断保持推断来源。

问题按原生质询结论记录，写明涉及的设计对象与知识条目。
