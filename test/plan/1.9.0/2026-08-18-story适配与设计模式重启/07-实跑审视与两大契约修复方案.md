## 2. 根因：两个系统性契约缺口 + 三个独立缺口

**缺口一：「登记-投影」体系没有形态契约。** 设计假设是「登记原子值、投影即引用」，但
「原子值」从未定义——登记表长成了第二正文：整句论证进 `conclusion`（每处引用展开 ×6）、
整句验收标准进 `ids.json`（附录与正文两处）、作者正文自抄值再挂引用（嵌套渲染）。
症状族：长值 ×6、同短语 ×10、嵌套、附录重列。

**缺口二：章节合同的镜头纪律只落到章级。** boundary 定了每章镜头，但**必答**还是旧镜头
（12 章问「各自负责什么」= 03 的镜头，必答自己逼出职责表重述）、**取材**有静默路径
（`section: []` 被赋予整篇语义，06-pages 守恒基准膨胀至 ~100 行）、**形态**零指引
（旅程该用什么形态、什么该强调，合同不置一词）。
症状族：变形矩阵重述、不做清单两处、旅程堆砌、零强调、基准膨胀。

**缺口三：受控值（外键）语义缺位。** §10 第四列是指向路由表主键的外键，约束未声明，
模型当自由文本填。

**缺口四：ADAPTATION 场景框架视角错位。** 主场景（适配执行者在目标仓内改写知识）被写成
复制视角；演示载体与能力文件未区分。根源是把能力开发环境的措施与面向适配执行者的指南混写。

**缺口五：机械判散落语义层 + 观测不完备。** facts 上游覆盖该归 post_check；门禁 fail
无诊断（本轮 merge_story_check 偶发 fail、日志 0 字节、无从归因）。

## 3. 正向设计与严格验收

### 3.1 契约一：登记-投影形态契约

| 设计 | 落点 |
|---|---|
| 登记值形态：`conclusion`/`proposal`/`ids.title` 是**可嵌入的原子短值**（能放进一格表格的单句）；论证归 `rationale`（只在决策件渲染） | `rules.md` 红线 3、scaffold `_example` 两处 |
| 登记范围：业务编号（匹配 `spec_shape.identifier_pattern`）定义权在正文各章，**不进 ids.json**；附录只收外部规约编号 | `rules.md` 红线 4 |
| 正文引用纪律：值由渲染供给，作者正文只写 `{{DEC-X}}` **不自抄值**（治嵌套） | `rules.md` 红线 3 |
| 机械裁判：值含多句（句号/分号后仍有正文）→ build fail；ids 含业务编号 → build fail | `story-build.mjs` validateDecisions / validateIds |

**验收**：
- V1.1 单测正反例：多句 conclusion → build 退出码≠0 且报错指明「多句」「移 rationale」；单句短值 → 0
- V1.2 单测正反例：ids.json 含 `AC-1` → fail；含 `UX-01` → 通过
- V1.3 复跑量化：story.md 每个决策括注前的展开值 **≤40 字**（脚本逐个提取判定，0 例外）；「（…（决策」嵌套 = **0**
- V1.4 复跑量化：附录内匹配 `spec_shape.identifier_pattern` 的编号行 = **0**

### 3.2 契约二：合同镜头完整性（必答/取材/形态与 boundary 同镜头）

| 设计 | 落点 |
|---|---|

### 3.3 缺口三：§10 外键语义

第四列语义重定义为「**命中路由表行**」（事实陈述：信号对上了哪一行，填该行 pattern_id 或「无」）；overlay `spec_pattern_signals` 补外键判据（值 ∉ 路由表 ∧ ≠「无」→ FAIL）；路由表头注声明主键性质。

**plan 应用表给模板锚点**：plan 撰写模型没有可靠注入，唯一到达通路是 spec 产物——把 §10 章末的下游义务句从一句话展开为**带表头的应用表模板**（适用单元 / pattern_id / 实例名 / 选型理由 / 知识文件 / 契约锚点），上游产物携带下游的表结构，plan 照填。

落点：`story_on_context_load.md`、`spec-sections.md`、`spec-rules.overlay.yaml`、`design-patterns/README.md`。机制层保持模式无关。

**验收**：
- V3.1 断言：overlay 判据含外键规则文本；机制层文件仍零具体 pattern_id（既有看护保持绿）
- V3.2 复跑量化：spec §10 第四列每个值 ∈ {路由表在册 pattern_id} ∪ {「无」}，**0 例外**

### 3.6 设计模式有效性验证设计（怎么测）
