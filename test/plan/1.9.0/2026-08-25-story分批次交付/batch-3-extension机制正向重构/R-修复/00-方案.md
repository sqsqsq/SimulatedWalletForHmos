## 2. R1 · 三态每一种都有判据面

### 2.1 `audit.json` 形态（替代现三态记录；作者不加任何自证字段）
```json
{ "records": [
  { "key": "PRD:17:ab12cd34", "at": "场景与功能", "by": "machine" },
  { "key": "PRD:31:…",        "at": "完整用户旅程", "by": "author" },
  { "key": "SE:18:…",         "covered_by": "PRD:21:…" },
  { "key": "SPEC:58:…",       "machine_facing": true }
] }
```
- `by: machine`：`audit` 命令写；条件 = 该章含单元 ≥1 token，或（无 token 单元）含其正文规范化后 ≥8 字连续片段（现 `autoPlace` 的两条路径，**只保留这两条**，删「old.at 保留」分支）。机器每次重算，作者改不了。
- `by: author`：机器定不了时作者填章名。机器只核标题在合同里；**讲没讲清由 2.3 的 verifier 裁**。
- `covered_by`：目标须 `at` 已核实且（共享 ≥1 token ｜ 同 `also_in` 组 ｜ 两者正文规范化后一方是另一方子串）。
- `machine_facing`：枚举器打标；作者写此键 → FAIL（现有）。
- 三态之外、`at` 标题不在合同 → 点名 FAIL。

### 2.2 落点域与 token 排除

框架每个阶段都有 verifier 子 agent，S5 没有——机器定不了落点的单元本来就只有模型能判，这是缺口，不是围栏。

- `SKILL.md` S5 三步：writer 子 agent → verifier 子 agent → `story_flow.py story` 登记（已自带 `check`）。主 agent 不读材料。
