## 三、设计（假设：十章 + 附录；机制零改动，只换数据与判据面）
### M0 骨架与读者问题成为合同数据
- `story-chapters.json` 换为用户 08-21 §2 的十章：背景 / 术语 / 范围（当前特性·相关特性）/ 业务方案 / 业务流程 / 功能说明 / 异常与恢复 / 验收（场景·整体质量）/ 交付与上线 / 附录（接口·数据配置事件·工程范围·规约判定·追溯·来源）。每章 `questions[]`（从 2026-08-21 十章合同的必答问题 + 冻结 1-C3 导出，≈30 问），**无 `inputs` 路由**。
- 14 章内容归宿：页面组件状态 → 功能说明；方案取舍 → 业务方案；影响面合规 → 验收·整体质量 + 附录规约判定表；上线协同 → 交付与上线；技术与数据约定 → 附录。
- 模板 `story-template.md` 按十章重写；逐章渲染输入 = 本章分配单元 + 本章 questions + 上一章结尾。
### M1 附录是工程标识的唯一落点（解泄漏，不是排除）
- 接口、字段、存储键、配置项、事件、错误码、工程范围、规约编号判定表只在附录成表；主叙事写中文业务名与中文规约名。守恒 token 在附录表里可核（机器），主叙事不再被迫写标识。
- 语言红线（lint，作用域 = 附录外主叙事）：仓内标识、规约编号、检索措辞、「（本工程设定…）」来源括注、文档坐标、模板占位/机械分类词/AI 腔标题。批次 3 的 `token_exclusions` 词表删除（不再需要）。
### M2 十三条人读要求进判据面
- 进 lint（机械）：背景先术语后（章序）；标题非模板占位/非提问/非 AI 腔词表；验收每个原始编号独立一行；未确认事项不出现「待确认/评审导读」段。
- 进 verifier 逐问维度：业务过程与本特性功能分开；正常受限结果与真正异常分开；取舍有被否方案与理由；三四级标题按真实从属；第一次接触者读完能答四问。
### M3 不重复 / 不丢
- 分配恰好一处（已有）+ `check`「规范化相同段落 = 0」；验收把批次 1 story 当第五份材料跑 audit：基线单元 100% 落点，人核 ≥90%；删事实对抗测试常驻。
### M4 形态守恒（md 表达形式诉求之一：不降级）
历史出处：08-21 原始需求 §1「去重不能以文档变短、标题减少或表格减少证明优化成功」、§2「表格、流程图、状态图、时序图和图片按实际表达需要使用」；1.0 `rules.md` 第 2 条「源材料用流程图、状态机或表格表达的内容，对应章节必须保持同类形态，且图的数量不少于源」；踩坑 #2「形态判据管语义 → 换皮四次」。实证：AR90005 术语成列表、流程图未进 story。
- **判的是形态不是语义**：`diagram` 单元的落点章须含围栏图（mermaid）；`image` 单元须以图片引用落点；story 的图数、表数 ≥ 源；`list_item` 不约束（列表转散文合法）。
- `table_row` **与 M5 的「一行不成表」对齐**：该章分到 ≥2 个 `table_row` 时才要求成表且这些行 ≥1 格原文在表内（术语 / 异常 / 验收表自然成表）；只分到 1 个时不要求成表，只要求该行原文在该章出现。M4 防的是「把表压成散文」这种降级，而一行本来就不构成表（§2.7 Google 风格指南），不存在降级——不写明就会出现机器要建表、模型判不该建表的相斥。
- 不设「每章必须有表/图」配额；形态判据**不作为「讲清」的证据**（语义归 verifier 逐问）。实现落 `story-build check`（单元 `kind` 已有）；台账加正反夹具（流程图压成 `A → B → C` 箭头文字 = FAIL）。
- **替代**：批次 3 check ④ 只判 diagram「有落点」不判「以图落点」。

### M5 表达形式：充分而合理使用，避免长文（md 表达形式诉求之二：用得对）
历史出处：冻结 02-C2 形式清单（正文、有序/无序列表、任务列表、强调、引用、表格、代码、流程图、状态图、时序图、图片、链接按内容实际关系自然使用；不设配额）；08-21 成文方案 §2 选择规则；原始需求 §2「连贯的原因、方案、取舍用自然叙述；标题短、真实业务名」；**批次 3 删 overlay 时一并删掉的 `story_reader_fitness (3)`「表达贴合内容」——唯一判『用得合不合理』的判据，删后无替代**。外部印证：Google 开发者文档风格指南（tables/lists）——表只用于二维数据、每项 ≥3 个相关属性，只有一列的表改成列表、只有一行不成表；Microsoft 写作风格——短句短段、每段结论先行、步骤超过 12 步拆节、复杂段落换成列表或表格。
- **选择规则表**（进 writer 作业书与模板注释；是数据不是判据）：

| 内容 | 形态 |
|---|---|
| 原因、方案、取舍、影响 | 正文，结论先行 |
| 有真实先后的步骤 | 有序列表（>12 步拆节） |
| 并列项 | 无序列表 |
| ≥3 个属性逐项比对 | 表（一列的改列表，一行的不成表） |
| 流程 / 状态流转 / 多方交互 | flowchart / 状态图 / 时序图 |
| 界面 | 图片 + 一句说明它画的是什么 |
| 关键结论、硬约束 | 强调 |
| 上游原话、裁定原话 | 引用 |
| 接口、字段、存储键、配置、事件 | 附录表（不进主叙事） |
| 标题 | 短、真实业务名；H3/H4 只反映真实从属 |
- **长文红线**（lint，机械且不可被换皮受益——拆长段、拆长章只会更可读）：段落 ≤ 200 字；一章正文 > 600 字须有 H3 或列表/表；有序列表 > 12 项拆节；夹具：一段 400 字散文 = FAIL。
- **不设句长红线**（用户 2026-08-29 裁定）：中文里 45–60 字的完整复句很常见，逼着断句会写出半截话和断裂的指代，而 writer 最省力的做法正是在逗号处一刀切——形式过了、读起来更差，与踩坑 #2「形态判据管语义 → 换皮四次」同形。
- **合理性**（verifier 逐章维度，恢复被删的那条）：能一句话说清的成了表、该成图的写成文、通篇是表而叙述只做连接词、并列内容写成长句、**句子啰嗦该断不断**——各判「表达不贴合」并点名。句长归这里不归 lint：它是语义问题，机器判不了。
- 不设数量配额；M4 守不降级，M5 守用得对。
- **替代**：`story_reader_fitness (3)`；写作书里泛泛的「表达贴合内容」一句。
