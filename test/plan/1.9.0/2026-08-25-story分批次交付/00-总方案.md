## 4. 交付协议（每批一致）

1. 读 [01](01-全批次需求记录.md) 中本批需求节 → **从 0 立目标契约**（参考 02、避开 03，均非依据）；
2. **判据先行**：验收判据从冻结 C 条款独立重推，带口径与责任层（机械/语义/行为），先于实现定稿；
3. 实现 → 离线全绿（语法/单测/负面扫描）；
4. 历史回归（台账全量 + 既有产物）+ 对抗夹具；
5. **冻结清单**：记录本批脚本/阈值/提示词/夹具指纹（**一次冻死，不重出**）；
6. 用户手动 CLI **揭盲 holdout**（冻结后由用户提供未参与设计的新材料；失败即本批泛化失败；
   用后作废，下批换新）；
7. 按**总判定规则**出批次验收结论（任一机械 BLOCKER 或语义 FAIL → 失败；WARN 未逐条裁决 →
   闭环失败；未到达阶段不得称已验证；守恒/SHA 类只报基线完整性）；
8. 结论回写本批 `STATUS.md`，并把新验证的机制入册 02、新坑入册 03——作为下一批设计的输入。
