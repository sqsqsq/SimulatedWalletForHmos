### 1.1 钩子配置按用途归属

上表四份配置为消费工程的 Framework 钩子接入，不适用“个人配置留根”。当前 Claude/CAC 挂 PreToolUse 与 Stop，Cursor 挂 preToolUse；Codex 只有 Stop，且当前 framework codex adapter 未声明生成这份历史 hooks.json，故分类为“消费钩子接入配置”，不声称它由当前 adapter 物化。

迁移后 Claude/CAC 的 `${CLAUDE_PROJECT_DIR}` / `${CODEAGENT3_PROJECT_DIR}` 须指向实际 demo 或隔离 workspace 工程根；Cursor 的相对 framework 路径以同一工程根为 cwd。Codex 把唯一 Stop command 改为下列 JSON 字符串，消费会话/装配验证以消费工程根为 cwd：

```json
{"command": "node \".codex/hooks/check-phase-completion.mjs\""}
```

只替换旧 `D:\\1.code\\SimulatedWalletForHmos` command 值，其他键和钩子脚本保持原内容；记为 AC03 的“迁移必需配置”例外。实际脚本的项目根解析仍沿原行为（CLAUDE_PROJECT_DIR 优先，否则 payload.cwd/process.cwd），消费启动不得带指向维护根/其他工程的旧环境值。不在本版扩大宿主钩子协议或补 Codex PreToolUse。

### 1.2 根维护会话的边界

迁走消费配置后根不保留失效的 Framework Stop/PreToolUse 接线，也不把 demo 的阶段闭环钩子用于维护任务。P1 在旧入口迁出时同步建立根 AGENTS 最小入口及 CLAUDE 指针，明确根为维护仓、先读 test/AGENTS、`demo/framework/` 为只读发布件，改动走正式接入；P3 在同一文件补齐操作协议，无第二份过渡契约。

维护者承担遵守发布件只读边界的职责，维护设计者以本次迁移 diff/字节保持证据复核 AC03。根会话不声称有已迁走的 hook 物理保护；现有 hook 本来也不覆盖 shell/脚本等全部写入。宿主若具备任务沙箱/只读挂载则由该宿主执行实际隔离，本版不新增维护守卫、不修改 framework、不把一次迁移比对做成长期防护机制。

## 2. 迁移后形态

根保留 extensions、test、tools、output、scratch、忽略/换行规则及维护装置；demo 持有业务和 framework。根 doc、framework、消费配置及业务目录完成迁出。个人宿主目录若仍有本地设置可保留，不以目录存在判迁移失败；核其中 tracked Story/Framework 物化是否正确归位。

根 AGENTS 最小维护入口和 CLAUDE 指针在 P1 就位，P3 完善操作协议和 README；旧 demo 入口仅存在于 demo。维护模型从根入口取得实际只读边界和 test/AGENTS。
