# 工作分册 02：引用清点与脚本适配

属于 [总览 P1](00-总览.md#2-三个实施包)，承接范围 #3/#5/#6 和 AC07。先按实际生产者/消费者分类，再修改；目录字符串本身不能决定改法。

## 1. 路径责任表

| 角色 | 目标基点 | 典型消费者 |
|---|---|---|
| 维护开发仓 | 仓根；源码在 extensions，工具在 test | 预算、源码扫描、fixture 取源、宿主装置 |
| demo 消费工程 | 仓根/demo | 默认本地试用、发布基线、宿主依赖取用、回灌 |
| 隔离消费工程 | 环境变量或显式传入的 workspace | run_case、产品 gate、Framework、知识及需求产物 |

清点输出文件×位置×角色×现读/写对象×改法。搜索 test/story、doc/extensions、framework/config、REPO_ROOT/HOST_ROOT、parents[n]、relative_to、快照及回灌目标。业务知识相对路径和 fixture 消费目录形态保持。

## 2. 文件动作

1. run_case.py：调整维护脚本自身 HOST_ROOT 的层数；运行 REPO_ROOT 仍优先使用显式 workspace，缺省消费目标才设为 demo。harness cwd 保持运行根/framework/harness，config 保持运行根/framework.config.json。不能在隔离 workspace 下再加 demo。
2. config/test.yaml：gates.post_check 和 story_build 在 run_case 中按运行根解析，保持 doc/extensions/...；静态源码扫描或取源键才指 extensions。逐键核消费者，不批量替换。
3. run_multi_case.py：修维护根层数，区分 DEMO_ROOT 和每个 Case workspace；复制相对路径按复制源计算，不按维护仓固定根计算。FEATURES_ROOT/回灌目标按 demo 消费配置解析，输出证据仍在维护仓 output/story。
4. 源码快照和 finalize 回灌：隔离端按消费相对路径记录，回灌端映射到 demo；冲突比较的前后基线使用同一对象，不把消费路径直接写回维护仓根。保护其他任务修改及已有回灌冲突处理。
5. ext_workspace.py、test_yaml_reader.py、verifier-smoke：维护端取 framework 依赖改为 demo/framework/harness；临时测试目标内仍为 framework/harness。修各自 parents[n]。
6. bootstrap_local_story.py：默认目标为 demo，维护需求系统数据仍属于维护域，消费配置按 demo 读取；同步 TEST §0.3。
7. golden_workspace.py 和 fixture builders：源改 extensions，临时目标保留 doc/extensions；不改业务答案。
8. test_mechanism_budget.py：扫描根改 extensions，计量口径保持；安装器仍单独计，不混入运行机制。
9. check_failure_modes.py：源码扫描继续接收 --extension-dir；增加明确的 --project-root 消费目标参数（默认 demo），退出无 config 即回退维护根。开发版集成检查显式给 P2 装配的 template；fixture 自检使用 fixture 自己的目标，不能悄悄读 demo。
10. adapt 检查调用：执行被指定源扩展内的 adapt-scan，自身定位源，传 --target；退出测试中的旧 --package 源仓推断，配合 03。

## 3. 忽略规则

根保留维护缓存、output/scratch、个人设置、extensions 的适配运行态以及 test/requirement-system 等；demo/.gitignore 承接业务构建、依赖、Framework 状态/报告和需求本地运行态。相对锚定路径与例外同时迁移。根 .gitattributes 保持，对 demo 仍有效。

不复制依赖到版本控制；迁移已有依赖或按既有 package 安装。定向测试所需依赖在测试前具备，不等 P2 才解决。

## 4. 验证

- 清点复扫逐条解释剩余命中；合法 doc/extensions 消费路径应保留，不追求字符串零命中。
- P1 跑实际存在的 yaml/harness/adapt/author-task 相关定向测试；完整 multi-case 装配测试到 P2 接线后执行。
- 覆盖自定义消费 extension_dir、独立 fixture 根、环境指定 workspace、demo 默认目标、回灌冲突及恶意/错误路径越界。
- checker 的源码检查与消费检查分别有证据；不能把 demo 1.9.7 的通过算作开发 1.9.8 的通过。
