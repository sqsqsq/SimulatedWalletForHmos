## 3. 总结、问题与反思

### 3.1 总体结果

**Story 的写作链换掉了。** 旧链是「一个渲染器把七类输入拼成一段文字写进每份草稿的头部，逐章刷新，末尾统稿」；新链是「原材料切成可引用的内容单元 → 进 spec 前留下稀疏初筛 → Spec 后一次形成整篇写作设计 → 按它铺材料视图与草稿 → 逐章写 → 回到来源核落点」。对使用者的实际差别：每一章的输入是一份持久文件而不是一段会被截断的 stdout；哪一件事讲在哪一章由本需求的编排决定而不是由合同预先规定；作者选定的形式（表头、图类型、图片位置）成为机器能在声明位置核的事实。

**v3 那条链退干净了。** 19 个标识符在交付面零命中，`context_chapters` 字段与说明键一并退场，落地之后不存在两条正式写作链。

**行为一次也没验过。** 这是 2.3 最大的未知。全部证据都是结构与连接层的：命令跑得通、判据拦得住、退出项归零。**它不证明模型在真实需求上会走这条路，更不证明产物质量变好了。** 03 分册 §7 的三次同条件重复与两类场景泛化，需要用户按 `TEST.md` 启动。

**规模是净增，超出方案估算。** 9942 → 11210（+1268），而总方案 §7 的完成估算是 9772–10432。专项审视四问逐条核过：旧职责真退了、无同一判据两处维护、无保留旧链再加分支、每一块都追得到分册明写条款；第四问（是否换来更少的重复理解与返修）静态证明不了。评审判断是估算与实际形态的差距，不是叠加补丁。**待用户裁定**：按现值重定 target 并移除预算例外，还是把「机制变小」另开一轮。

### 3.3 反思

**有效机制**

- **拆步的粒度决定评审能不能对着合同逐条核。** 3a/3b 的拆法（先做函数、再接线）让 3a 那轮四条返修全部由「对着分册逐函数对照」查出；相比之下 3b 是一笔 878 行的 diff，同类问题只查出三条，其中两条靠机械扫描而非阅读。
- **突变核对。** step-01 用旧实现跑新用例、step-04 把删掉的句子塞回去——两次都当场确认了用例的区分力。「用例绿」与「用例能红」是两件事。
- **端到端探针胜过读代码。** 02-R1、3a-R1、3b-R1 三条 P2 全部是拿真实工作区跑出来的，读代码时它们都「看起来对」。
- **既有用例接住了返修带走的东西。** step-04 剪那一段时把十章读者问题一并带走，被 3b-R3 补回的那条守恒断言当场接住。守恒断言的价值在它拦下第一次意外时才兑现。

**无效或低效行为**

- **只核「退出清单归零」。** 三轮都做了，三轮都是绿的，而残留一直在增加——因为清单是按文件名与函数名列的，残留在字段、段落、判据这三层。
- **按类名判用例去留。** 退 v3 用例时以「这个类叫什么」为准，把两条与 v3 无关的断言一起退了。
- **规模自审只对着预算数字。** 预算不设上限之后，「+1268 合不合理」这个问题只能靠专项审视回答，而专项审视的四问里最要紧的第四问静态答不了。

**下次改进**

1. **改动的影响面要反向查，不能只查清单。** 三个问题机制上可查：本次改动之后谁失去了唯一调用者、这个字段/段落现在还有谁需要它、新接手的那件事旧的承担者退了吗。前两个可以进失效形态检查，第三个只能靠人。
2. **改完一处交付面文字，拿它的特征句反向搜全仓。** executor 自己提的，直接可执行。
3. **验收表里凡是有「同类对象」的维度，先列 ≥2 的反例再动手。** 02 与 3a 各栽一次之后 executor 开始这样做，3b 与 step-04 的返修都不再出在这一维。
4. **拆步时问「这一刀落下之后，还剩几条链」**，而不是「这两块工作量差不多」。

**未解决风险**

- **真实运行未验。** 新链没有被真的作者走过。已知的行为风险（模型主动截断输出、统稿只改表面、verifier 漏报）在 2.2 的实测里都出现过，2.3 是针对它们的重设计，但重设计有没有解决它们，只有真实运行能回答。
- **跨 extension 的历史残留。** 评审侧另做了一次全量清点（`test/story/plan/2026-09-10-extension历史残留清点/00-审计报告.md`）：四层共 62 条候选，不需裁定就能退约 350 行，另有五件待用户裁定，还有一个活的缺陷（`hooks/spec/author.mjs:40` 路径少一层 `core/`，任务包「你现在在哪」从来没工作过）。step-04 的 04-R1 就是那份报告 B 类在本 loop 内的一个实例。这份清单不在本 loop 的范围内。
- **`FINAL_REVIEW.md` 的提交方式待裁定。** 本目录在 `.gitignore` 内（`test/story/plan/`），与「设计件不入库、评审会话不提交」的既有裁定冲突。
