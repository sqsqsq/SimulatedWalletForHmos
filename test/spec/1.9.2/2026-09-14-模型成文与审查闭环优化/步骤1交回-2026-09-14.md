## 3. 授权内的局部选择

评审已复核 1、3：严格拒绝未知字段等未见导致合法输入失败，暂不另做泛化。

1. **设计进 JS 存在性台账**。`test_negative_guards` 锁着「冻结清单、存在性台账、ctx 路径三处同一批文件」，设计既然随稿冻结就一并进台账：在线 check 缺设计时在台账这一步点名并堵「删掉设计让报错变少」这条路。代价：几个自己搭工作区的测试补一份设计（见 §4）。
2. **自动补选定结构只换未写、且内容（行尾归一后）仍是起点的草稿**。判据是现有草稿等于按合同最小结构、当前输入重渲染的起点；不等（作者动过、或 Spec 术语变了）一律不改，只输出起点。没有保存「上一次选择」的状态。
3. **协议从严**：协议外字段、图带 `columns`、附录 `at` 不在合同五节内都报；占位符行算没写完。
4. **`storyInputs` 放在 `hooks/spec/author.mjs`**（分册原文），由 `story-build.mjs` 导入；这是 core 导入 hooks 的第二处（第一处是既有的 `reader-review-task`）。
5. 空壳首次建出时不逐条报占位（下一步就是写它）；已存在的设计读不了才把问题列进「记一笔」。
6. **重合的表合成一个槽位，而不是两个槽位各核一次**（`c9ce889a`）：两个槽位时一个缺口会报两条、打两份底；合成后锚列取「合同要求 ∪ 作者补列」，合同要求不因作者换列名而丢（作者列里已含合同锚的不重复加）。

## 6. 自查：正常与异常路径

| 路径 | 覆盖 |
|---|---|
| 正常 | 空壳 → 写设计 → skeleton 给第一章 → 按设计提交 → check |
| 缺失/坏输入 | 设计不在（台账点名）、空文件、空壳、12 种坏形状 |
| 不适用 | 离线 check 不读设计（金样零 FAIL）；结构选择为 `[]` 合法；无选择的空章合法、只有合同要求的空章照原语义；本地单无系统设计不算丢件；Spec 未写成不算丢件 |
| 声明冲突 | 选定表/图（含与合同要求重合）与「不涉及」冲突时章提交与 check 同报，撤回选择后放行（R1） |
| 重合结构 | 同一个缺口只报一次、草稿只打一次底、已动过的草稿只给一次起点 |
| 写前失败 | 设计读不了或声明冲突时章不落盘、Story 与候选字节不变；skeleton 预检失败时空壳不建 |

| 恢复 | 坏设计重跑 skeleton 列出问题；未写且未动的草稿自动补选定结构；已写/动过/补回的草稿不改但给当前缺的起点（R2）；登记后改设计被点名；reopen 后放行 |
