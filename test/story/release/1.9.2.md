# Story Extension 1.9.2 发布说明（草稿）

> 本版在推进中，当前登记已完成的步骤；其余新增与优化随后续步骤补写。上一版见 [1.9.1](1.9.1.md)，本版在它之上做增量。

## 本版新增与优化

### 1. 写作设计是一份骨架，草稿照它铺好

写作设计不再是每章一段说明加一段结构选择：作者写阅读主线，再为每章写骨架——正文将要有的小节标题、
每节要回答什么、依据在哪、要一张什么表或图。起手命令把骨架铺进还没动过的章草稿，章提交与全篇检查
核骨架里的小节、表与图在正文里都有；正文可以多写，要删骨架里的一节就先删骨架那一行。骨架里的图按要解释的关系判定种类，流程图、时序图、状态图等都能点名，点名了哪种正文就用哪种。
旧形态的写作设计会被指出来，按骨架重写。

### 2. 十章齐后按回看清单逐条处置

十章写完，起手命令给出一张回看清单：需求分析里还要核实的疑点、未决与已定的决策、骨架里留着的待核问题、
正文里每张图所在的位置。作者对每一条问「这句话材料里有吗、材料给的靠得住吗」，有问题回它的真源改；
独立审查拿同一张清单核每一条的去向。

### 3. 评审议题的选项写后果，依据写撞点

「可选的做法」每一项写成「做法——选它会怎样」，缺后果的会被指出来；写不出后果差别的改成请人复核结论。
议题的依据要说清是在哪一章、哪份材料的哪一处撞出来的。

### 4. 规约声明强制力与验法，各阶段照它执行

规约表里的强制力、验证（执行体）与探针三列现在由各阶段读取，知识写什么，门禁就照什么执行：

| 阶段 | 现在 |
|---|---|
| 载入知识 | 强制力、执行体、探针写法与协议版本不合的，一次全部列出并说明改哪边；模式文件缺上篇或下篇也会指出 |
| spec | 判断骨架每条带上强制力、要求、命中条件与验法；§10 多出「强制力」「验法」两列。命中但这一轮不做可以登记豁免：红线不许，基线要写补偿，由评审人表态。项目事实按面登记用途，未确认的面要写核实时看的位置 |
| plan | 每处落点的 `verify` 要与规约声明的执行体相符，要实机证据的不能只标 `review`；不是规约要求的业务规则写进实体说明或设计章，不借编号挂。契约里用 `- { … }` 流式写法的字段会被指出 |
| coding | 规约自带的探针对形态匹配的每处落点自动跑：标了「阻断：」的形态不符按强制力处理（红线拦下），其余只记证据缺口；只写在注释里的实体不算；注释里写了规约编号的报到行号 |
| review | 复核表一处落点一行、按列读结论；红线的落点「未落实」会拦下，基线「未落实」要写依据 |

### 5. 会议转写进需求输入

需求澄清会议的语音转写 docx 放进收件箱、归类为 `MEETING`，导入把它解析成按议题分节、逐条编号的发言，
一个源版本一个目录，同名文件换了内容存成新版本，旧版本的原文与结论照旧可查。

| 环节 | 现在 |
|---|---|
| 读会 | 按 `phases/meeting-read.md` 纠偏（只改字面，每处留痕）、切话题、写会议结论：每个话题的变化、结论、遗留问题都指回发言编号；判不准归属、没收敛、推翻旧决定的摆给人，每个选项写清选完的结果 |
| 自检 | 发言编号守恒、纠偏留痕解释全部改动、登记的话题都有去向、选项带完整结果——不合的逐条点名，不摆关卡 |
| 人裁决 | 与第一级材料关卡同一轮，不新增停等点：要问的逐条 `decide --gate meeting`，人对第一级表态即确认其余条目 |
| 生效 | 人签的选项与第一级确认过的条目合起来生效，写成 `AR/story-src/doc-refresh.md`：提取稿据它修正，也是给人的文档刷新清单；旧决定只被签过的替代选项撤销 |
| 下游 | 需求分析 ⑥ 按话题登记会议，未决的遗留进回看清单；写作设计的依据可以指向它；独立审查逐话题核去向 |
| 收口之后才到的会议 | 先 `reopen`，一场会一轮 |

## 修复

| 问题 | 现在 |
|---|---|
| 列表项里一句带冒号的话被读成键值，渲染出 `[object Object]` | 按一整句读，原样渲染 |
| 同一章里两个同名小节、只有标题没有正文的小节会进入交付件 | 章提交与全篇检查点名，给出合并、改名或补正文的出口 |
| 还没收口就登记成文时，计算下一步失败会盖掉「还没收口」这句提示 | 先说还没收口，下一步算不出来的原因附在后面 |
| 审查复核表里写「未落实」会被读成「落实」；同一条规约挂在两处时只认最后一行 | 结论按「结论」列的原值读；每处落点各认一行 |

## 退出项

下列能力或约定在本版退出。每一项写明由谁接替，以及使用者会看到什么不同。

| 退出 | 由谁接替 | 使用者会看到的不同 |
|---|---|---|
| 收口提交时把被覆盖的上游 AR 按轮次留存到过程目录，并作为一份独立材料进入作者任务、材料清单与审查任务 | 覆盖前把上游那一份备份进需求目录的 `.backup/`，与导入覆盖正文走同一条退路；上游预填的每一条由提取稿承接；审查回查上游原话看 RR、SR 原文与 `.backup/` | 附录·材料清单不再要求列「上游原件」一行；作者任务不再有「上游原 AR」一节；1.9.1 功能清单里的「上游原件留存」不再提供 |
| 关卡决策命令的 `--by` 参数 | 关卡记录固定记为人签 | 带 `--by` 的旧写法会被拒绝，去掉该参数即可 |
| `story-build review-task` 子命令 | 审查任务只随独立审查装配，审查方法只在规则里维护一份 | 该命令不再可用 |
| 界面参考说明文件（`ux-reference/README.md`）在来源表里的登记 | 界面参考目录下的文件逐个登记为材料 | 没有这份说明文件时不再提示「来源不存在」 |
| 来源路径在章节合同与材料脚本里各登记一份 | 章节合同的来源表是唯一登记，材料清单与导入落点都从它取 | 无 |
| 附录·材料清单按目录范围粗判链接 | 按材料清单逐份核对列到的材料 | 没有材料清单时，这一项与图片身份检查一样记为「未执行」 |
| 评审回流时「AR 根下旧台账挪进过程目录」的迁移说明与专门检查 | AR 根下出现过程件时按通用规则报出，挪进 `AR/story-src/` | 无 |
| 流程契约里没有读者的记录：需求名、每轮分析件摘要、归档时的产物摘要，以及章节合同里没有读者的逐问、逐章判词表 | 需求名就是需求目录名；归档记录只留时间；成文登记时间由 `status` 输出 | 无 |
| 契约义务的 `verify: probe` 取值 | 探针随规约走，coding 对形态匹配的每处落点自动跑 | 写 `verify: probe` 会被拒，按规约声明的执行体改成 `ut` / `device` / `both` / `review` |
| `knowledge-use.yaml` 里项目事实按文件写一句 `used_for` | `facts[].used` 逐面登记 `facet` / `used_for`，未确认的面加 `verified` | 旧写法会被指出，改成按面登记 |
| 审查复核表按编号认行的四列表 | 按 rule + 落点认行，多一列「落点（契约实体）」 | 没有落点列的旧表对不上落点，补上这一列 |
| coding 作者页「每条义务都要有个说法」 | 证据就是挂着义务的实体的代码，注释只写代码意图 | 无 |
