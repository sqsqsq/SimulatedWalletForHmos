# Story Extension 1.9.0 发布说明

Story Extension 面向需求开发与评审，提供材料整理、范围确认、规格与评审文档生成、评审意见回流，以及工程知识在开发各阶段的应用能力。

**1.9.0 重点优化文档展示与跨工程复用**：Story 各章按内容关系组织表达，减少固定排版限制；安装升级明确区分公共机制、业务对接与目标知识；需求过程文件保留，便于后续排障与返修。

本版基于 **Framework 3.0.0**，支持有人参与的交互式流程。本文说明发布能力与版本变化；命令、操作步骤和常见问题见[《story 使用指南》](story使用指南.md)，整体协作方式见[《需求交付流程》](需求交付流程.md)。

## 本版新增与优化

### 1. Story 展示形式按内容组织

十章的阅读职责保持稳定，具体小节与展示形式由内容决定：属性与约束、条件组合适合表格；过程与分支适合流程图；多方交互适合时序或泳道；状态变化适合状态图；原因和取舍用叙述解释。

本次调整覆盖全部章节：

- 取消固定段数、固定分支标签、预设页面槽位等排版要求，支持有页面与无页面能力的说明。
- 多个独立的入口、功能或数据对象可以分别说明管控与恢复措施，避免整项需求只套一份回退描述。
- 章草稿提供读者问题、组织提示和必要表头；按实际业务生成二、三级小节，不预填整套可选目录。
- 图、表、文字可以互补，章节间按内容职责衔接；保留流程总览、源图对应、验收追溯和附录契约投影。
- 附录允许在契约投影之外补充必要的单位说明与格式样例，投影仍以原始契约为准。

### 2. 安装升级与业务仓复用简化

公共流程脚本与业务对接实现分目录管理。正常升级按明确范围更新文件并检查安装结果，不重新分析目标业务或合并知识正文。

| 复用场景 | 本版行为 |
|---|---|
| Demo 仓向业务仓提供扩展 | 更新公共机制与指定入口，保留目标已有对接实现，不复制 Demo 替身 |
| 内网业务仓之间复用扩展 | 公共机制与共用对接实现一并更新，保留目标已有知识 |
| 目标首次接入 | 创建知识说明骨架，扫描目标仓形成部件画像，不复制来源仓业务知识 |
| 目标已有知识 | 保留知识正文、说明、画像及激活清单，升级不重新扫描画像 |

目标工程身份与无关配置保留。安装检查覆盖公共文件、指定入口和清单，允许目标采用自己的需求目录忽略策略及宿主入口文件。

### 3. 交付目录与过程文件职责分离

AR 根目录集中放置 `design.md`、`story.md`、`review.md`，以及需求系统对接层的 `detail.json`。流程记录、材料分析与其他辅助文件放入 `story-src/`。

成文登记保留章草稿和其他过程文件，便于核查文档生成过程与返修。需求系统归档仍只传需求叙事与评审记录，过程文件不随这条归档路径上传。

### 4. 公共指引与检查规则收敛

删除无消费者的旧适配模板和重复规则文件；移除部分固定业务例子及失效维护说明。作者与审查者从当前需求提取关键对象、条件和依据，减少对熟悉场景的依赖。

脚本保留结构、引用、编号与投影等确定性检查，展示是否清楚、内容是否遗漏或矛盾由独立 AI 检视。能力描述同时允许有工程依据的既有能力和有需求依据的计划新增能力。

## 1.9.0 功能清单

以下为本版包含的完整功能，涵盖既有能力及上述优化。

| 功能 | 提供的能力 |
|---|---|
| 需求系统取材 | 获取 AR 及其上游 RR、SR 材料，建立本次需求的输入基础 |
| 本地需求接入 | 支持问题单、工单等非 AR 需求，使用本地提供的材料形成规格与评审文档 |
| 补充材料导入 | 接收 DOCX、文本与界面图片，保留原件，登记材料与图片来源；不支持的格式明确报出 |
| 范围分析与拆分 | 提出整体承载或拆分方案，记录用户选择、各方责任、交接依赖与决定依据 |
| 规格与验收生成 | 形成需求范围、功能行为、业务规则、技术契约及可观察的验收条件，供后续设计实现使用 |
| Story 成文 | 按章编写、落盘与统稿，形成面向评审者的完整需求叙事；附录契约从规格与知识判断中投影 |
| 决策与评审记录 | 呈现已定判断和待定事项，说明依据、建议与影响，并保留人工表态区 |
| 归档与恢复 | 将需求叙事及评审记录送入需求系统，备份被覆盖的正文，支持恢复上次归档前的内容 |
| 评审意见回流 | 获取评审意见，逐条处置并修订相关规格；保留评审时点文档及意见处理记录 |
| 工程知识应用 | 使用项目事实、工程规约和设计模式，支持适用判断、设计落点、验证分派及后续阶段检查 |
| 开发阶段协作 | 向规格、计划、编码、代码检视、单元测试、实机测试提供对应的作者要求与扩展检查；阶段执行由 Framework 承接 |
| 中断恢复 | 根据需求目录中的流程记录恢复进度，支持更换会话后接续 |
| 跨工程安装与升级 | 按来源更新公共机制及相应对接实现，保留目标知识和工程身份 |

## 主要产物

| 产物 | 职责 |
|---|---|
| `AR/design.md` | 经范围确认形成的需求输入 |
| `spec/spec.md` 与验收材料 | 后续设计、实现和验证的依据 |
| `AR/story.md` | 面向评审者解释完整需求、方案、行为与交付安排 |
| `AR/review.md` | 承载需要审核的判断、待定事项及人工意见 |
| 需求过程记录 | 保存材料、范围决定、成文过程和评审处置的可追溯信息 |

Story 正文由 AI 根据材料、规格与已确认判断编写，附录的部分内容由脚本投影；整篇文档并非规格的确定性转换。评审回流保留评审时点的 Story，规格变更通过处置记录追溯。

## 依赖与发布范围

- **Framework**：基于 3.0.0 的扩展能力接入，安装本扩展无需修改 Framework。
- **需求系统**：业务工程需具备真实对接实现与访问配置；Demo 对接脚本用于本地模拟。
- **知识维护**：项目事实、规约与设计模式由目标工程核实并维护，公共机制按激活清单使用。
- **运行范围**：交互式需求开发；本地非 AR 需求保留仓内产物，不执行 AR 的系统归档与恢复。
- **能力边界**：本版不包含会议转写的专门语义纠偏与结论提取。结构检查和独立 AI 检视辅助质量把关，需求取舍与最终评审仍由人负责。
