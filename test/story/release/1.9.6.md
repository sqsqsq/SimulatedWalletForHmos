## 本版新增与优化

### 1. 知识靠自己描述自己

- **frontmatter 自描述**：每份知识写 `name`、`kind`、`applies_when`（非空文字），机制按 `applies_when` 把它交给当前阶段；知识有几份、叫什么由目标仓定。
- **读写规则归机制**：三类知识怎样写给模型用，统一在 `skills/story/reference/knowledge/protocol.md`；`knowledge/` 只放目标自己的内容，四份 `README` 并入各知识文件。
- **adapt 按消费任务适配**：方法页交给模型——定决定、取证、写、走查；只读检查在内网工程根可跑。内网从 1.9.3 升级见 [内网适配指南（1.9.3 → 1.9.6）](内网适配指南-1.9.3升级1.9.6.md)。

### 2. 埋点：指标为单位，spec 设计打点，plan 实现打点

- **埋点知识分篇**：`knowledge/facts/event-tracking.md` 与设计模式同形——上篇（读者 spec）讲指标、统计点与边界，下篇（读者 plan、coding、review）讲 SDK 行为、角色、结构骨架、使用约定与完成判断。
- **指标是比率**：由事件结果算出，如成功率；失败原因这类分析信息作为事件字段随每次上报带上；耗时只在时延类指标里带。
- **spec §9.1.4 设计打点**：总述一段，每个指标一个小节、标题写指标名；小节下先写定义段（衡量什么、怎么算、每次上报带什么、在哪打点），再放带「统计点」「所在流程」列的表。spec 任务包专设统计设计一节，门禁核每个指标有定义段与统计点。
- **plan §9.2 实现打点**：9.2.1 共同约定、9.2.2 逐点实现（每个统计点每种结果一行，带责任方法）、9.2.3 待登记与缺依据；指标口径以 spec 为准。plan 门禁核每个统计点有行、责任方法在契约里。
- **样稿**：`golden/bank-card-opening-reporting-candidate/` 按上述形状给出 spec、story、plan 的埋点样稿，只作形状参照。

### 3. 扩展章挂到 framework 预留的宿主扩展锚点下

- **spec**：「9. 宿主扩展治理项」下是 9.1 技术契约（9.1.1–9.1.5）、9.2 规约约束要求、9.3 设计模式候选登记，锚点表逐行写承载位置；附录是全文最后一章。
- **plan**：「9. 宿主扩展」下是 9.1 知识决策（设计模式选型、规约义务、项目知识影响）与 9.2 埋点；任务包要求先写 9.1、再写设计章。
- 门禁核锚点位置与附录最后；解析按章名与相对层级定位。

### 4. 1.9.5 遗留收口

- 统计设计按指标与业务结果组织，plan 逐结果落实。
- 决策原文送达作者与审查；审查按影响定级。
- 上报知识分清业务语义与协议映射。
- 图与附录的指引只说内容。

### 5. 全量自检

- 机制与知识里与测试用例同形的例子、号段、样本原话和叙述历史的注释改为通用写法。
- 旧格式兼容分支、静默兜底与死代码退出。
- 修正中文单位匹配与命中编号串读；命中集合收成一处定义。
- 失效形态检查全部通过：错误消息分行 CRLF 安全；知识引用按整条路径判；夹具与现行协议一致。

### 6. 测试域

- 双检查点：配了 `after_initial: update` 的 Case 在第一段到目标后固定快照、评测、回流，再在同一会话里跑 update 第二段。
- 过程件入库：`test/story/spec/`（需求）与 `test/story/plan/`（方案、评审、交回，原 `design/`）含历史版本全部入库；实跑运行证据放 `output/story/`。

- 知识能力台账与登记机制、知识确认标记、`knowledge/` 下四份 `README`；知识名 `reporting` 改为 `event-tracking`。
- spec 在锚点之外另起的 §9–§11 三章；plan 设计章之前的独立「知识决策」章与「服务层接口定义」下的埋点小节；按行号判「知识决策在设计章之前」的门禁。
- 指标标题「指标名（流程名）」写法与把失败原因、耗时单列成指标的写法。
- 失效形态 P06「知识决策在设计之后」由「知识决策不在锚点下」接替。
- 内网适配指南（1.9.3 → 1.9.5）由 1.9.3 → 1.9.6 指南替代。

## 未达成与移交 1.9.7

以上两个用例对 extension 全量功能的分析（含过拟合与打补丁、测试资产本身、运作效率与一次成文质量），及其正向优化方案，全部纳入 1.9.7 整体方案：[`plan/1.9.7/2026-09-25-整体设计/00-总览.md`](../plan/1.9.7/2026-09-25-整体设计/00-总览.md)。要点：

- plan 埋点的必须设计项（事件 ID、内码、结果分类）要有具体候选值；plan 写作时送达知识下篇。
- 审查判据全量下发，定级与阻断一致；WARN 处置规则一处定义，交付门与规则一致。
- 人签只来自人的回话；update 统一承接依据变化；退出交付门口头评审入口。
- 测试用例、测试方法、金样与检查器按现行设计修正。
