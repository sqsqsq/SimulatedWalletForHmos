## 1. 为什么是机制级三分法，不是再补一步

1.9.2 两轮实跑（suite 20260915-154711、20260916-130054）六项分从 82/72/80、82/64/80 到 88/75/86、83/70/85，都没到 90。对 `doc/extensions` 约 14000 行逐条盘点（四份，见 §5）并统计两 Case 事件流后，结论是三类结构问题，不是缺几条规则：

| 问题形态 | 事实 | 分数上的表现 |
|---|---|---|
| 扩展自造了比 framework 更严的读法与判据 | 217 行 `yaml-lite` 拒收流式 YAML 而 framework 用 `yaml` 包接受；`resource_keys` framework 是两层对象、扩展按平铺数组读；spec post_check 14 类判据合一条 status 且逐层早退 | car 一轮 harness 22 次、11 次带 FAIL；contracts.yaml 编辑 18 次；性能 70 |
| 机器用形态代语义、同一件事多处各判一次 | 6 套标题定位、5 套围栏扫描、2 套表解析；语言红线 8 类里 4 类两轮零命中且词表含工具链自己的词；Python 与 JS 各存契约常量并各判一遍，JS 侧约 12 条只有手改文件才可达 | 修一轴破另一轴（auto：红线报机器区，改机器区又被投影一致性打回） |
| 模型做关键判断时拿不到原义，之后各件一致继承错误；提示层用解释代送达 | 作者判规约适用只见「强制力·约束·命中条件·验法」，处置列不送达；会议、图、知识给 verifier 的是路径不是内容；提示层约 200 个指令簇动作类不到四成，同一件事最多六处说；三个产物完全没有判据 | 未决写成已定、时序压成流程、DFX/RES/COMPAT 适用判断轮间摇摆；产物 83–88、知识 85–86 |

洋葱式暴露不是新问题：`test/story/EVOLUTION.md` 在批次 3 之前就记着「`lifecycle_hook_post_check_extension` 洋葱式暴露五层」；金样 README 记着 2026-08 「判据逐条教模型抄 token、23 次 check 循环、修一轴破另一轴」。同一形态换了位置反复出现，是机制层的问题。

| 步 | 内容 | 独立验收 |
|---|---|---|
| 1 | 读法与门禁：R1 → R2 → R3 → R5 → E10 | 离线全量绿；四类 YAML 样本与 framework 解析深相等；spec/plan 各自的独立问题同轮同现、依赖组标前置；junction helper 后六个套件全绿 |

| 3 | 送达与登记：E1 → E2 → E3 → E4 → E5 → E6 → E8 → E9 | 真实产物副本上 author.mjs / pre_verifier 装配输出原义与判断并列；夹具逐条；E3 体积在上界内 |
