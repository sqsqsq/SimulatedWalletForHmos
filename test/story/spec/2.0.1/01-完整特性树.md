# Extension 完整特性树

本树从产品结果定义能力，不指定已有目录、命令、阶段或字段。共同目标和词义见 [总览](00-版本需求与结论.md)。编号仅用于维护文档间覆盖核对，不引入运行期登记或要求消费模型回显。

每行同时规定正向结果及重要异常边界。特性应在实际行为中组合成立，不以独立文件或检查数代替。

## A. 取得并澄清需求

组合结果：外部描述成为来源可靠、边界明确、可供开发使用的需求依据，由人确定业务责任，交给设计执行者。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| A1 | 系统与本地来源接入 | 有系统单可取关联材料，无系统单可用本地材料；缺权限、查无此单、无关联材料分别报告 |
| A2 | 材料读取与转换 | 正文、表格、图片及其关联可读，保留原件；不能读取时明确缺口，不丢内容报成功 |
| A3 | 来源、版本与采用关系 | 知道材料来自谁、采用哪版、取代什么；新旧不混拼，时间新不自动覆盖权威 |
| A4 | 图片与视觉依据 | 图有稳定来源、含义、用途与取舍；界面参考和业务关系图分别使用，改名不重复认图 |
| A5 | 材料充分性确认 | 模型先盘点实际缺口，人决定本轮补料；不把未取得的材料当成已理解 |
| A6 | 会议理解与澄清 | 逐话题保留观点、建议、未决及决定依据；讨论、转述与真实表态有区别 |
| A7 | 业务分析与承载范围 | 讲清本单、兄弟单、协作方及不做的边界；人决定业务分单，执行拆分不冒充业务分单 |
| A8 | 形成开发输入 | 原始依据、已确认目标、约束、验收意图与未决一起交设计方；不只交模型摘要，不夹带未授权设计 |

## B. 形成面向人的完整说明

组合结果：读者无需拼接施工单元，就能理解整项需求、有效设计、风险与交付要求，并追查精确依据。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| B1 | 阅读组织与材料定位 | 写作前明确读者问题及材料用途；写到相关内容时取得必要原文，不把初筛当完成判断 |
| B2 | 完整业务叙事 | 背景、术语、范围、场景、行为、方案理由、异常、非功能、验收和交付均有适用落点 |
| B3 | 图表与文字协作 | 总览与局部合起来讲全关系，图表互补；承接图不丢角色和失败责任，不用装饰填量 |
| B4 | 精确内容与来源查阅 | 接口、数据、配置、事件、依赖、知识判断及来源可定位，正文解释不能替代技术事实 |
| B5 | 专项方案说明 | 适用要求需要单独讲清时，业务目的、条件、边界、变化和设计可被读者找到；无要求不造空章 |
| B6 | 可靠写入与整体验证 | 分次写作不丢既有正确内容；整篇核遗漏、矛盾和表达质量，结构检查不能冒充理解正确 |
| B7 | 需求级统一交付 | 一个需求的一套有效 Story/Review 覆盖整体设计；施工拆成多份不导致重复成文或遗漏共享关系 |

## C. 支持真实的人工决定

组合结果：人审的是有依据的具体问题，决定保留对象、语义、身份和适用范围，并进入正确责任方。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| C1 | 发现与解释议题 | 提出影响产物的取舍、冲突、未决与跨方确认，给依据、选项和后果；纯事实不凑议题 |
| C2 | 人工表态与保护 | 人填写或给出原话，模型不代填；人工已编辑内容不被重新生成覆盖 |
| C3 | 已定与未定有据 | 能指认谁对哪件事作何决定；计划、转述及默认推荐不能当已定 |
| C4 | 表态版本适用性 | 问题变义不沿用旧答案；旧版本反馈须核对适用性，不仅凭编号或勾选迁移 |
| C5 | 反馈分类与结果 | 意见、事实、建议、授权裁决分别处理；取得意见、具备资格、被采纳和同步完成分别可见 |

## D. 知识看到、理解、应用、传递

组合结果：知识在相关动作之前到达适当执行者，对具体需求产生有依据的作用，并完整进入后续实现与验证。是否先使用 Story 不影响知识能力。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| D1 | 目标知识激活与读取 | 只采用目标启用内容；空集合合法，已登记文件缺失响亮报告；正文及附注在判断前可取 |
| D2 | 项目事实与画像 | 根据真实工程识别能力、接口、位置与惯例；冲突核事实，不把未确认能力当现成实现 |
| D3 | 规约适用与冲突处理 | 结合实际需求判断适用、不适用及依据，形成具体要求；不以条目名称代替判断 |
| D4 | 模式理解与选择 | 根据条件、反证、角色和骨架选择、拒绝或调整模式；模式不是固定业务答案 |
| D5 | 对决定与实体产生作用 | 知识改变实际业务要求、设计关系、接口/数据/文件职责；自指声明不算应用 |
| D6 | 跨执行者传递 | 后续得到已成立的决定、相关来源、具体义务与验证要求；拆分或复用不重猜、不漏共享约束 |
| D7 | 实现及代码审查 | 核具体行为和角色协作；调用形态只作取证线索，不证明运行正确 |
| D8 | 验证与整体责任 | 单元、设备、人工或组合证据按义务取得；多个局部通过不证明跨部分要求已满足 |
| D9 | 维护解耦与通用性 | 目标维护知识，机制不含目标专名或样例答案；改变知识无需增加业务分支，事实不写流程落点 |

## E. 处理变化并保持一致

组合结果：变化被理解并交给正确责任人，已有工作尽量保留，当前有效结果与剩余工作可以解释。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| E1 | 取得本轮变化 | 取上游、询问补料、接收反馈/新决定/直接编辑；区分内容相同、原本缺席与读取失败 |
| E2 | 比较与未完成识别 | 无变化、已有更新待续、无法比较、确有变化分别处理；没有基准不声称历史未变 |
| E3 | 理解影响与保留项 | 解释变化涉及的业务关系及不变原因；需求、设计、实现影响分别交责任方，不只替换文字 |
| E4 | 最早责任处修订 | 修正有效依据，再同步派生结果；范围变化回人，不手改投影消报错 |
| E5 | 增量同步与交回 | 只改必要的已有结果，显式留下未决/未验证/后续责任；文档更新不自动授权实施 |
| E6 | 本地撤回与现场保护 | 撤回前保留后续人工工作，恢复对象明确；不通过复制旧文件伪造设计或施工回滚 |

## F. 对外发布与恢复

组合结果：人能将审阅材料正确交给外部系统，知道发布了哪一版，并能处理失败与恢复。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| F1 | 交付选择与授权 | 区分送审、实施、先发布再实施和暂不推进；选择针对实际结果，不重复请求已有授权 |
| F2 | 归档发布 | 展示当前内容及缺口后按授权发布，正文/评审/素材可读；本地需求不调用远端 |
| F3 | 失败与外部冲突 | 发布失败保留本地正确结果，重试核外部新变化；不覆盖他人新意见 |
| F4 | 远程恢复 | 恢复外部被覆盖版本，可说明内外差异；不等于撤回本地设计或代码 |

## G. 可继续、可核查的协作

组合结果：模型知道下一步，人知道当前边界；失败不会被状态字样掩盖。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| G1 | 动作前信息送达 | 目标、输入、知识、完成条件和恢复方式在行动前到达作者及相应独立审查者 |
| G2 | 状态查询与续行 | 从实际依据继续同一工作，不凭会话记忆重建；只读不触发设计修订或施工 |
| G3 | 检查、独立审查与返修 | 脚本查确定事实，独立模型查语义；真实阻断回责任处修复，建议不导致无限再审 |
| G4 | 有效证据与完成表达 | 证据对应当前对象；文件在、命令成功、旧 PASS 各有边界，未审未测明确披露 |
| G5 | 需求级进展与成本 | 呈现材料、设计、人读交付、发布、施工的实际结果与必要缺口；不要求用户管理 CU 才能理解进展 |

## H. 安装到真实目标工程

组合结果：目标取得可用机制及入口，保有自己的知识、身份和业务对接；升级不破坏目标工作。

| ID | 子特性 | 可观察结果与边界 |
|---|---|---|
| H1 | 首次接入与画像 | 建立必要知识骨架并核实目标事实，由人核对身份和画像；不带入 Demo 业务知识 |
| H2 | 升级与旧内容退出 | 新机制可用，被替代内容退出；既有目标知识、身份与不属于包的工作受保护 |
| H3 | 来源与业务对接所有权 | Demo 替身不进入业务仓；业务仓之间按明确来源规则复用对接，不靠目录猜 |
| H4 | 兼容、重复执行与自检 | 不支持的环境写入前说明；覆盖冲突可见；无变化不重复写；部分失败不报整体成功 |

## 能力组合与边界

A 提供可靠的需求依据，B 形成完整的人读说明，C 保持人工决定真实有效，D 贯穿理解、设计、实现与验证，E 使变化后的结果保持一致，F 负责外部交付，G 保证各项工作可继续、可核查，H 将整套能力安装到目标工程。各组共同服务同一需求，不按开发阶段或发布批次划分。

知识原文、骨架参考、专项说明、精确技术定义、实体义务和验证责任共同组成知识应用链。目标工程的上报渠道与 SDK 属于项目事实和业务能力；通用机制依据这些事实工作，不将其固化为跨工程规则。

路径解析、文件操作、检查结果复用和环境诊断是实现与验证支撑，不增加用户需要管理的流程。特性成立取决于表中结果与异常保证，具体目录、字段、命令和执行步骤由设计选择。
