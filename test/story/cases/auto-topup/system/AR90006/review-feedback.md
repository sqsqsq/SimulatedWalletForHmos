# AR90006 评审记录（评审人批注版）

> 评审人直接在归档件上批注后回传。以下是逐条意见，编号只表顺序。

**总体表态**：方向同意，签约与管理一并交付的范围也认可；第 2 条改完再往下走。

1. 判定与扣款全在服务端、端侧只做签约与展示——同意，按现在写的做。

2. **要改**：功能开关关闭后，已签约用户的「管理」能力写漏了。现在只写了
   「已签约用户的自动充值照常发生」，但这些用户还能不能进管理页看记录、改档位、解约，
   没有交代。请明确：**开关只管新签约入口，已签约用户的记录查看、档位修改与解约不受影响**。
   这条影响验收——不改的话，关开关那天已签约用户想解约都找不到入口，投诉会直接打到客服。

3. 免密额度随面额走、不设固定值——同意，协议文案里记得把单日 200 元上限也写给用户看。

4. 单日达到上限不计入连续失败——同意，这条别丢，丢了会把正常用户停用掉。

5. **暂缓**：充值发票的开具入口这次先不做，税务侧的口径还没回来；责任人是运营接口人，
   下个迭代给结论。不阻塞本单。

6. 计划外的一条：管理页的充值记录，运营侧希望能按月份筛选，说是客诉核对要用。
   这条产品还没走流程，你先记着，别直接写进这轮的方案。
