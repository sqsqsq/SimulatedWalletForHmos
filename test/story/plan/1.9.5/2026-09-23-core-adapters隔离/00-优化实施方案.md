# core / adapters 隔离优化实施方案

2026-09-23，维护设计者。依据[用户确认的范围](../../../spec/1.9.5/2026-09-23-core-adapters隔离/00-需求.md)。本文交执行者实施前评审，未修改产品。当前55cbd05f上还有已评审的第二步未提交改动，开工先核归属，不覆盖或重做它们。

## 1. 目标与现状

core内外网一样，adapters内外网实现不同；SKILL指导模型组合调用，数据/文件合同把两者接起来。隔离不等于取消数据合同，也不要求把Python改写为JS。

已核现状：update.py::_fetch_command硬编码SKILL_ROOT/scripts/adapters/story.js并拼CLI；cmd_update_inputs/status将它作为fetch返回，phases/update.md与SKILL指示模型照回执执行。core未直接spawn该adapter，但仍拥有其路径和调用协议，属于命令耦合。adapter story.js成功日志又提示运行story_flow.py init，反向承担流程指导。

保护项：core内的flow/client.mjs调用story_flow.py、lifecycle协调其他core脚本、hooks导入解析/材料模块、delivery调用Framework回执，这些是同一通用机制的内部协作，不在本次退出范围。

## 2. 最终分工

| 责任 | 承担者 | 消费者 |
|---|---|---|
| 何时取系统材料、取token、归档/恢复 | SKILL及对应方法页中的顺序与既有确认 | 执行流程的模型 |
| 具体需求系统/MCP/鉴权/富文本/图片处理 | 目标adapters公共入口及其内部模块 | 模型调用；材料/回执供后续本地处理 |
| 工作区定位、状态、变化比较、导入、产物生成和检查 | core | 模型及现有hooks/core内部消费者 |
| 公共参数、stdout、材料和回执形态 | scripts/README的数据合同，入口说明随之同步 | 两侧实现者及模型 |

core返回工作区事实，不返回任何对接命令；adapters返回执行结果，不返回core下一步命令。统一合同保留，但不能要求core为适配器生成参数字符串或要求目标改core接内网。

## 3. 第一步：退出跨边界命令，迁移编排

### 3.1 core只返回数据

在flow/update.py删除_fetch_command及仅为它存在的import/局部量，inputs/status删除fetch命令字段，不保留空字段或旧命令兼容分支。两个命令保留已有状态、阶段、差异、材料与upstream回执内容。

为了替代旧命令中承载的可靠目录信息，两个返回中增加同一形态的只读paths：project_root、feature_root、inbox，均从现有已解析参数派生为绝对路径。实现可用本文件小辅助函数复用，不建立路径服务或配置项。这些是本地数据，不含adapters目录、程序名、token或shell命令。

inputs中是否展示upstream仍按已有系统/本地来源事实判断，不再用“有没有fetch字符串”间接判断。action中删除“先跑fetch字段”之类指令；本地流程动作保留。是否已经执行本轮外部取材，由SKILL对应步骤结合本次工具结果和已有回执确认，不新增epoch/ticket来记录。

原_fetch_command的两个职责由不同位置接替：本地目录解析留core的paths；adapter命令选择及参数绑定归SKILL。不能仅删函数后让模型自己猜收件目录。

### 3.2 SKILL拥有系统调用顺序

SKILL.md的update入口正向替换为：

1. 执行core update status，读取续行状态和paths。若已有未完成更新，按其状态恢复；是否重新取材仍沿当前update方法的有效分支，不擅自每次resume都重复fetch。
2. 本次需要取材且是AR系统需求时，按token规则取得token，调用目标adapters/story.js的fetch。命令形态在SKILL维护，project-root与out分别绑定paths.project_root/paths.inbox；路径按当前shell正确引用，不拼进core输出。
3. 命令成功且当前回执有效后运行core update inputs，呈现当前材料、询问本次补料，之后沿原round/prepare/修订/close。adapter失败停在取材环节，不以旧回执或无变化替代成功。
4. 非AR本地需求跳过token和adapter，直接沿本地inputs材料流程。不能因无fetch字段把AR误判成本地。

phases/update.md只引用SKILL的取材调用步骤，负责输入解释、补料、更新行为及恢复，不再另定义一套adapter命令生成规则。SKILL已有init/archive/restore分别调用两侧的方式保持，核参数定位与失败处理不退化。

init：系统取材成功再建本地骨架；本地单直接建骨架。archive：已有校验/确认→系统写入成功→现有本地登记；失败不登记成功。restore：区分系统归档回退与core本地更新恢复，不因名字相同互相调用。保留既有授权语义，不增加确认关卡。

### 3.3 adapters只表达对接结果

外网story.js不再输出story_flow.py、story-build或其他core命令。成功日志改为取回/归档/恢复的事实及位置，命令后下一步由SKILL提供。文件头中描述工作区职责可以概述数据接收者，不能指示执行core脚本。

不改变四条CLI及stdout JSON、fetch四态、材料/评审回稿/回执落点；不增加next_command字段替代旧日志。内网story.js仍唯一系统命令入口，init由fetch.js实现、新fetch由fetch-upstream.js实现，MCP/转换/图片/token按既有模块复用；通用core不认识这些模块名。

### 3.4 文件动作

| 文件 | 动作 |
|---|---|
| core/flow/update.py | 删除adapter命令构造与fetch字段；返回paths；upstream直接按来源选择 |
| story/SKILL.md | 编排adapter调用，使用core路径数据，处理失败与本地跳过 |
| story/phases/update.md | 改为调用入口的引用及数据解释，退出读fetch命令字段的要求 |
| adapters/story.js | 清理core命令日志及跨层作业说明；保留数据输出及失败语义 |
| scripts/README.md | 正向写两侧隔离与数据合同；core不“调用入口”，模型按SKILL调用；记录fetch命令字段退出与paths接替 |
| story-adaptation/SKILL.md、release内网对接指南 | 明确本次增量及目标维护动作；不要求内网改变core或适配复制策略 |
| 相关调用说明/测试 | 搜实际fetch字段消费者和跨层命令依赖，逐个迁移，不批量删一切名为fetch的变量 |

此步完成条件：公开作业入口已有完整顺序；core和adapters不再认识对方可执行路径或给出对方命令；同一数据/文件合同仍可接通。改README而未改实际消费者不算完成。

## 4. 第二步：验证隔离与现有行为

复用现有requirement_source、story_update、adapter合同、适配所有权和update_dispatch测试；必要时在这些文件中加有区分力的用例，不新增通用测试引擎。

| 场景 | 预期 |
|---|---|
| 项目没有adapters目录 | core status/inputs仍能处理本地工作区并返回paths，不因缺对接脚本失效 |
| 内外网替换adapter内部模块而公共合同一致 | 同一份core无需改动；测试显式分别调用公共入口和core，不测试core执行adapter |
| AR取材成功/全相同/评审缺席/读取失败 | 回执四态保持；失败不能被当无变化，旧回执不能冒充本次取材 |
| 非AR多种名称 | 不取token、不执行adapter，本地材料流程正常 |
| 配置不同features_dir、根目录/需求目录含空格 | paths按配置正确，按SKILL参数位置调用可到达同一需求；不泄漏或误写其他目录 |
| 已开更新续行、补料关卡、无变化、restore | 原阶段语义与数据保留，移除fetch字符串不损坏恢复路径 |
| archive失败/restore无历史 | 明确失败，不修改本地成功状态；不会从adapter内部进入core |
| adapt升级 | 机制复制与adapter所有权不变，目标实现不被Demo替身覆盖 |

测试同时核静态边界与行为：core不存在adapter路径导入、进程执行或命令生成；adapter不存在core命令调度/下一步输出。注释中的职责说明与数据合同名称不应仅因提及另一层就判失败，静态扫描不能代替调用链判断。

旧_fetch_command专用字符串断言退出，迁移为路径正确性及分步数据消费验证。不保留只为通过旧测试而存在的fetch:null。项目AR协议和四态结果是已确认业务合同，不因防过拟合而删除。

这里只做离线合同验证，不运行内网MCP、不执行真实系统归档/恢复、不自动启动额外CLI模型轮次。后续已规划的CLI使用完成隔离的版本，记录新基线；真实内网实现由目标维护方验证。

## 5. 适配交接必须说明的增量

本次公共adapter命令/结果不变；变化是由core生成fetch命令改为SKILL指导模型调用，core回执的fetch命令字段退出，新增本地paths数据。内网需核story.js及其内部模块没有调用core/提示core下一步，保持材料/回执合同即可，无需把内网HTTP逻辑复制进core。

发布/适配说明分别列：机制更新、目标对接需检查/修改事项、已有行为保护、离线与真实验证状态。不能只说“adapters不覆盖”而不交代新功能需要目标落实什么；也不能把安装检查通过写成内网联调通过。
