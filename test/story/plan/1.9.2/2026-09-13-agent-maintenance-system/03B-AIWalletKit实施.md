## 操作顺序与验收

1. 在本项目根运行 `git status --short -- AGENTS.md README.md task/README.md test/walletkit/AGENTS.md test/walletkit/TEST.md`，再读取这些正文及本步具名事实入口。
2. 核对用户级入口和原资产清单，再修改项目根/README，最后同步 task 和测试入口。
3. 逐项检查通用内容承接与项目差异保留，特别区分协议已确认、实现已完成、测试已通过。
4. `git diff --check -- <本步路径>`；验证资产链接及维护/消费的不同读取路径。
5. 以一项当前维护任务核查目标、协议事实、实施状态与测试入口是否可直接取得。

完成证据为具名文件 diff、内容去向和读取路径。提交按已有用户授权，仅含本步实际修改。新协议裁决、资产变更或产品范围调整不由本步顺手处理。

本次审查确认越界删除的迁移桥、阶段自检与测试义务已恢复，不再删除。当前 README 的精确资产集合去重可保留；它有同读者可达的原资产清单和用途摘要，不推广为删其他能力说明。
