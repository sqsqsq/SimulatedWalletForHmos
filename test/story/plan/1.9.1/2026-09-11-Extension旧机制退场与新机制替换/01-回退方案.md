## 2. 先保现场，后回退

1. 停止旧实施loop及其写入者，重新检查实际工作树，不沿用“只有三文件”的旧数量。
2. 保存HEAD保护tag；未提交的tracked与untracked由stash保存；被忽略的本轮/冻结设计及spec目录另存到仓库外的唯一临时恢复目录。tag不包含工作区，stash -u不包含ignored，两者不能互相替代。
3. 记录保护tag、原HEAD、原分支、stash对象ID、保护路径和状态清单。保护内容读得回且完整才允许reset。
4. 不自动stash pop，避免把待撤销的2.4代码带回。用户AGENTS入口改动单独取回后改指本目录；旧实现/测试改动留在stash。

以下为PowerShell执行骨架，实施者必须逐段检查退出码；不是可不看现场一次粘贴的清理脚本：

```powershell
$repoRoot = (git rev-parse --show-toplevel).Trim()
Set-Location -LiteralPath $repoRoot
$beforeHead = (git rev-parse HEAD).Trim()
$beforeBranch = (git branch --show-current).Trim()
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$guardTag = 'story-before-rebuild-' + $stamp
$recoveryDir = Join-Path ([System.IO.Path]::GetTempPath()) ('story-recovery-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $recoveryDir -ErrorAction Stop | Out-Null
git status --porcelain=v1 --untracked-files=all | Set-Content -LiteralPath (Join-Path $recoveryDir 'status-before.txt') -Encoding utf8
git tag $guardTag $beforeHead
if ($LASTEXITCODE -ne 0) { throw '保护tag失败，停止' }
Copy-Item -LiteralPath (Join-Path $repoRoot 'test/story/plan') -Destination (Join-Path $recoveryDir 'design') -Recurse -ErrorAction Stop
Copy-Item -LiteralPath (Join-Path $repoRoot 'test/story/spec') -Destination (Join-Path $recoveryDir 'spec') -Recurse -ErrorAction Stop
```

先确认上述备份可读，再根据实际工作树执行：

```powershell
$pending = @(git status --porcelain=v1 --untracked-files=all)
if ($LASTEXITCODE -ne 0) { throw '读取工作区状态失败' }
$stashObject = $null
if ($pending.Count -gt 0) {
    $oldStash = git rev-parse --verify refs/stash 2>$null
    git stash push --include-untracked -m ('回退前现场 ' + $stamp)
    if ($LASTEXITCODE -ne 0) { throw 'stash失败，停止' }
    $stashObject = (git rev-parse refs/stash).Trim()
    if ($LASTEXITCODE -ne 0 -or $stashObject -eq $oldStash) { throw '未取得本次stash身份，停止' }
}
@{ head=$beforeHead; branch=$beforeBranch; tag=$guardTag; stash=$stashObject; backup=$recoveryDir } |
    ConvertTo-Json | Set-Content -LiteralPath (Join-Path $recoveryDir 'recovery.json') -Encoding utf8
# 读回recovery.json及备份，并核tag/stash确可取回后，才进入回退。
git reset --hard 33dd9123
if ($LASTEXITCODE -ne 0) { throw '回退失败，保留现场，不清理保护件' }
```

reset前检查目标会覆盖的路径与被忽略内容是否冲突；有冲突先完整备份。不要执行git clean，不删除用户的output、inbox或历史需求。A段不带任何自动force-push；远端历史是否同步属于独立动作，需明确授权及远端预期提交核对。
