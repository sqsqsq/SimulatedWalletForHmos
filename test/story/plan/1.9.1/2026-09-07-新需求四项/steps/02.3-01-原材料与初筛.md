# Step2.3-01 · 原材料与初筛

> 依赖与范围见 [总方案](02.3-Story写作流程重设计.md)。本步修改S4提交与原材料准备，不实施最终作者入口切换。完成后交回评审；新流程整体尚不可发布。

## 1. S4先分清输入与输出

当前AR/design.md既是外部预填输入，又在S4被模型覆盖成提取稿；覆盖后complete检测到材料变化而要求重开。不能用永久忽略AR/design的方法修复，否则外部真实更新也会失去检测。

改为以下确定顺序：

1. 原导入和范围确认继续处理RR、SR、外部AR预填及补充材料。
2. 模型将S4提取结果写入 `AR/story-src/design-draft.md`，不覆盖输入AR/design.md。它按原提取目标写内容，不生成新的业务决策。
3. `story_flow.py complete --feature <名> --from <候选稿>` 先按原流程核范围与材料是否仍允许收口；核候选存在、可读及原S4必要结构。
4. 在 `AR/story-src/sources/ar/r<当前轮次>.md` 留存本轮外部AR输入，然后将候选提交为AR/design.md。若当前AR等于既有流程登记的派生稿，则沿用该派生稿所指原输入，不把派生稿再标成外部证据；当前AR与已登记派生稿不同则按原材料变更路径处理，不自动认作自己的输出。
5. 更新现有materials清单与当前轮材料基准，再记录design摘要、原输入定位、design_generated_at和complete状态。新增的是当前轮来源定位，不是另一份范围/决策状态。

旧的直接覆盖AR/design再complete入口随本步退出，SKILL、ar_design_init.md、next_step和测试调用同时改。脚本仅提交模型已写好的内容，不替模型写AR需求。

预检失败不改原输入、材料基准或流程状态，候选保留。提交按“留存原输入→覆盖AR/design→刷新materials与当前轮基准→记录complete”顺序执行，complete最后写。留存文件已存在时不得覆盖，须与该轮原输入摘要一致。

中途失败报出已完成的文件动作及未收口状态，保留来源与候选，重试同一条complete命令。仅当当前AR等于本次候选且已留存来源与原轮基准一致，才将这个AR差异认作本命令自己的写入；其余来源仍按原材料检查。当前AR既非原输入也非候选、候选发生变化、轮次不同或来源身份不能证明时停止，不重置基准放行。重复成功命令返回已完成，不再留存一份派生稿作为原输入。

不新增三文件回滚副本、通用事务或强杀恢复状态机。以上顺序与重试判据共同构成幂等提交；它不承诺跨文件原子性。离线测试覆盖各写入边界失败后重试及外部同时修改。

S4作为本步骤第一个独立实施提交，相关调用与回归一起交回评审；通过后才实现来源索引。本次规模政策按总方案§7：用户已授权暂不限制数值峰值，记录增删与实测，以最终总量下降为期望。

## 2. 文件所有权

路径均相对feature根目录。

| 文件 | 写入者 | 内容与消费者 |
|---|---|---|
| AR/story-src/source-index.json | 脚本 | 来源身份、性质、版本、内容单元范围；初筛、编排与材料视图共同读取 |
| AR/story-src/source-selection.json | 模型填取舍；脚本填版本与首次骨架 | Spec前稀疏初筛；后续编排继承未覆盖的取舍，仍是有效输入，不重复抄全量台账 |
| AR/story-src/chapters/*.md | 脚本 | 仅编排成立后生成的材料视图；模型读，不在这里修改业务事实 |
| AR/story-src/sources/ar/rN.md | S4提交脚本 | 被覆盖前的外部AR输入，按已存在轮次保存，只用于来源追溯 |
| AR/story-src/design-draft.md | 模型 | S4提交候选；成功后保留过程证据，不加入原始材料集合 |

sources/只保存本次确实会被覆盖的原AR，不复制RR/SR/所有knowledge做另一份数据库。chapters视图不进入materials原始输入集合，不因重建视图开新材料轮次。

现有decisions空容器初始化前移到初筛开始前，供真实冲突即时落盘；复用原初始化职责，不创建第二份早期决策文件。此时不要求Spec或knowledge-use已经存在，后续原init不得清空已有判断。已成文冻结后的初始化保护保持。

## 3. 内容单元怎样切

入口：`story-build sources --feature <名> --stage before-spec`。脚本读取当前材料清单、原AR来源定位、已收口AR提取稿和当前范围，生成source-index；after-spec行为见步骤02。

只索引实际存在并适用于当前入口的来源，不硬要求本地问题单有远程RR/SR。必需来源缺失、坏清单、缺原AR来源且不能判明输入身份时明确失败，不用空数组冒充没有材料。

来源集合从既有章节合同sources、materials已登记的Markdown正文以及S4原AR来源定位合并；相同规范路径只登记一次。已知来源沿用合同key（当前PRD、SE、DESIGN、SPEC等）；S4留存原AR使用AR_ORIGINAL，以区别DESIGN派生稿；其它正文以规范相对路径作为key，不从业务词猜类型。before-spec包含原始来源与AR派生稿，after-spec再加入当前Spec；knowledge-use/decisions仅作判断入口，不参加Markdown分段。没有自身正文的目录索引不作为独立业务证据。

Markdown只做已有场景所需的确定性定位，优先复用现有围栏/标题能力：

- 仅识别代码围栏外的ATX标题H1–H6；代码里的标题不切分。
- 最小章节正文是一个默认单元；父章节在第一个子章节前的正文另成一个单元，不能丢掉父级前提与表格。
- 每个单元保存祖先标题路径、正文起止行。context只列各祖先在其第一个子标题之前的正文范围，按由外到内排序；不含标题行、当前单元或兄弟正文，空范围省略。标题已由heading表达，不重复收进context。行号为原文件的一基、闭区间。
- 只有标题而没有自身正文的父节只作定位上下文，不生成需要模型裁决的空内容单元；父级确有正文才单独登记。
- 表、列表和图的围栏保持整体。本期只引用完整单元，不支持子范围对象，也不做setext专门解析；未识别为标题的文本留在所在单元中，不丢弃、不自动摘要。
- 无标题文件作为整份文档单元；不做逐句切分。无法支持的特殊Markdown结构保留整块并提示，不静默丢内容。
- 链接和图片按原文件位置解析。生成视图时由脚本改成相对视图的可访问路径，保持原引用的身份与标题；图片身份沿用materials现有登记，不再让模型复制、命名或手算路径。

目录、标题只有定位用途，不能只因一个单元叫“失败与恢复”就把里面的用户取消都归为系统异常。脚本不得判定哪些句子是业务事实。

## 4. source-index合同

字段由脚本填；示意值不是本用例答案：

```json
{
  "schema": 1,
  "feature": "<feature>",
  "scope_round": 3,
  "sources": [
    {"key": "SE", "path": "SR/design.md", "kind": "original", "digest": "sha256:<现有file_digest值>"}
  ],
  "units": [
    {"id": "SE#7", "source": "SE", "heading": ["整体方案", "异常处理"], "start": 40, "end": 58, "context": [{"start": 3, "end": 8}]}
  ]
}
```

source.kind取original或derived，AR提取稿与Spec为derived，不能提升原来源的权威性。已定决策与knowledge-use作为独立权威引用路径随视图给出，不把YAML/JSON硬切成Markdown单元。Knowledge激活和缺件沿用现有能力，不在本步重写适用协议。

source-index另含images数组，由现有materials图片登记派生：`{id, path, source}`。id取既有图片内容摘要并加image前缀，path是可访问的代表路径，source指其首次出现的已索引原文单元；独立登记而未被Markdown引用的图为null，不能编造正文来源；同一图片的多个路径保留在原materials中，不另维护图片取舍台账。模型在编排中按id选图，脚本解析位置，不让模型重抄文件名或手算相对路径；无图片时为空数组。

ID采用`<source-key>#<文件内序号>`，从1开始，不附摘要；包含特殊字符的source-key按整体字符串处理，以最后一个#分隔序号。文件版本只存在sources[].digest及选择/编排的basis中，不让模型逐个重抄摘要。

source-selection和template JSON都含脚本维护的`basis`对象：`{sourceKey: digest}`，记录该产物使用的文件版本。sources首次创建骨架时填入；after-spec只给当前template补新增来源，不要求初筛追记尚未参与初筛的Spec；已有basis项逐项核对，不替旧来源更新basis。源变化时更新索引，并在错误输出逐项列出变更文件、旧/新摘要、受影响的选择和编排坐标；原文件和旧basis保留，不新增“待处理”状态文件。重建索引前读取旧索引，在变更报告中按同一来源的完整标题路径列“旧ID/旧范围→新候选ID/新范围”；同名路径列全部候选，标题改变或无匹配明确写未找到。只做确定性候选定位，不按相似度猜语义、不自动修改selection/template引用；模型据新旧原文确认取舍，accept-source仍只刷新版本。短ID即使仍存在，只要对应basis不一致也不能用于生成视图或登记。

模型重看变更来源并修正受影响判断后，运行同一sources命令加`--accept-source <source-key>`，脚本核当前来源与索引一致后，只更新现存selection/template中该源的basis；删除源则核已无引用后移除该basis项。该动作确认引用坐标重新建立，不能证明模型理解正确，来源义务仍由语义审查核对。不得把它塞进自动修复循环或静默更新所有basis。无源变化的正常链不需要此参数，也没有逐章版本票据。

## 5. 模型初筛合同

sources首次提供如下骨架，basis由脚本填。模型读索引及对应原文，记录已有的初步归章、排除理由或疑点，不逐单元填“已用”。空items合法，只表示没有显式取舍；不证明已读或已完成语义初筛。初筛动作由进入Spec之前的作者指令送达，不能用文件存在证明执行过。

```json
{
  "schema": 1,
  "feature": "<feature>",
  "scope_round": 3,
  "basis": {"SE": "sha256:<当前文件摘要>"},
  "items": [
    {"unit": "SE#7", "disposition": "keep", "chapters": ["05-flow", "07-exceptions"], "note": "含过程去向与恢复条件，分别解释"},
    {"unit": "SE#8", "disposition": "defer", "note": "接口返回条件有冲突", "decisions": ["<已有未决ID>"]}
  ]
}
```

默认keep表示原文可参考，不能解释为“已采用、已覆盖或已审查”。items仅写需要记录的取舍：keep可给暂定chapters或混合用途note；omit须给具体排除理由；defer须说明待处理问题，涉及真实业务未决时先登记decisions并引用其ID。单纯归章尚未决定可暂不填写，不制造业务未决。decisions如有是非空、无重复的真实条目ID数组，允许同一单元涉及多项问题，关闭与否以原decisions文件为准。

每个显式unit只能出现一次；chapters如有须为合法章ID且无重复。脚本检查类型、引用和理由，不强求每个单元或每章一项。一个混合单元可以多章参考；note只保存已有理解，不要求拆成原子事实台账。小节可参考不等于其中各项义务都保留。

## 6. 初筛之后与命令输出

Spec前不生成chapters视图，不实现collect命令；Spec作者读取原材料、索引和稀疏初筛。保留当前上下文的可靠判断，处理真实冲突与缺口，不再为生成第一版目录重复搬运原文。

正式视图只在Spec后编排可装配时由skeleton生成，落盘规则见02§3。这样没有“初筛视图覆盖最终视图”的第二条写入路径。

sources、skeleton、prepare统一按NEXT、INPUT、RESULT顺序输出短摘要，NEXT先说当前动作，INPUT给本次必须读取的实际文件位置，RESULT列保存/保留内容。sources指索引、初筛或编排；skeleton指编排、shared及目标章；不在stdout展开材料。预检失败用非零退出码列完整定位，不输出成功。发生写入后的错误如S4须先明确已写与未收口，不能套用“失败无修改”。

## 7. 修改清单与验收

改动：core/materials.py（来源角色及摘要复用）、core/story_flow.py（S4候选提交/来源定位/接续）、ar_design_init.md、SKILL与相关S4提示；来源定位与材料视图放`core/story-sources.mjs`，只提供解析、引用解析与视图构建函数；`story-build.mjs`持有命令、文件写入和写作步骤派生。Python仍负责材料轮次与S4，不启动Node查询写作子步骤。摘要在MJS使用原始文件字节SHA-256前16位，输出加sha256前缀；与materials.file_digest做普通UTF-8、BOM、CRLF一致性测试，不复制Python的材料判断算法。

验证：

1. 按原S1–S4授权走完，候选生成不会触发自己的新材料轮次；真正的RR/SR/外部AR变化仍被发现。S4预检失败不改输入与状态。
2. 有标题、父级前导内容、无标题、嵌套标题、同名标题、围栏内假标题、表格/列表/图均不丢；边界与原件可逐行核对。
3. 稀疏/空初筛合法；未知ID、重复项、非法章名、无理由omit/defer被拒；多章参考合法。通过只证明映射结构，不证明语义取舍。
4. 视图构建函数的相对链接和图片可读，公共材料只有一份正文；正式命令接线在02验收，不提前生成Spec前视图。
5. 只改一个源，旧短ID不能因重新编号而静默重绑；basis差异及受影响引用可定位，显式刷新只改变指定源。原selection和草稿保留。
6. 不使用AR90006金额、接口、特定章节措辞来切材料或判归属；按总方案及03做过拟合自查。

测试复用material_rounds、writing_flow、image_registration等现有测试域的临时夹具。允许补本成文能力的独立测试文件，不创建新测试平台。交回实际文件、函数责任、退出旧调用、规模估算/实测及上述正常和失败路径。
