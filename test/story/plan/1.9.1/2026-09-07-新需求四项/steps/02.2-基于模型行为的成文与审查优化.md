## 1. 先说明这次为什么没有达到目标

执行者是非确定性模型。脚本可以把内容摆到它面前，不能替它完成理解、比较和取舍。此次不能再把“有提示、有脚本、有独立审查”当作设计已经可靠的充分理由。

### 已观察到的行为与证据

样本为 `story-suite-20260908-2115 / auto-topup / 20260908-191333-23392-f5996e3f`。案例细节只留维护域，不进入通用执行提示。

| 观察事实 | 证据 | 对设计的含义 |
|---|---|---|
| 模型能在首稿采用不同形式 | events 的首次 write 已有规则表、取舍叙述、多对象管控表 | 保留 Step2.1 的选择方法，不恢复固定排版 |
| 多章完整复述同一过程 | 最终 Story 的 4.3、5.1、6.3，以及缓存恢复的多处叙述 | 仅说“避免重复”不足；作者需要在写此章时判断它相对已写内容增加什么 |
| 统稿把重复合理化 | copyedit.md 称“各章必要落点、无冗余”，仍以措辞不同支持去重结论 | 自问“是否重复”很容易得到自我肯定；必须比较具体内容的差异与独有信息 |
| 图的源标记修好了，关键关系仍未补齐 | 首稿两张图；后续修标记和编号；最终五方交互仍未展开 | 来源对应与过程正确是不同问题，不能将前者的通过当后者答案 |
| 排版调整后错误语义留存 | 表后“最后两种”错指；可恢复的入口关闭被写成不可逆 | 需要沿改变后的对象和结果回查语义，而不只检查文案流畅 |
| 独立审查同样漏报 | verifier 总体 PASS，声称参与方次序和分支完好 | 独立身份不是有效判断的保证；应规定它实际重建和对照什么 |
| 返修集中于机械问题 | 原始记录显示编号、引用、禁用词和图源标记修正 | 应减少不产生阅读收益的修正，同时保留真正确定的保护 |

### 已核实的输入，尚不能确认的事实

作者逐章读取了带 questions/form.note 的草稿；说明不是所有要求都未送达。现有“每章输入”仅要求看上一章结尾，却没有明确在写局部能力前如何核对相关已写内容，这是可确认的任务定义缺口。

本轮 verifier request 指向实际 ai-prompt；该 prompt 中 Spec 已内联，Story 以路径给出，读者审查的六项要求也确实存在。task 记录返回审查报告，但现有导出中没有足够的子代理逐次读取轨迹，不能断言“它没有读全文”。可以确认的是其判断未得到内容充分支持，报告没有呈现能解释本次错误的实际比较。

因此，本步针对已知的任务与输入缺口设计；不把全部问题归咎于遗忘，不声称改好提示就能消除模型能力差异。

## 2. 目标、保持与不采用的做法

目标是：模型首次写作就能按内容职责组织相互衔接的章节；统稿实际修正重复、断链和矛盾；独立审查能发现剩余的关键错误；最后交付的内容与依据一致。

保留十章及 Step2.1 的三级展示方法、按章落盘、主流程总览、上游图对应、必要表和验收追溯、材料与契约单源、归档边界和过程件保留。正文的目标是清楚、完整，不能为了减少重复把关键事实删掉。

不新增 Agent 层级、另一轮完整审查、展示状态机、逐事实分配表、全量裁决表、相似度门禁或模板分类器。不把“写一份证明自己认真做过的记录”变成新的任务。模型的主要产出仍是 Story 的正确内容与独立审查的可靠结论。

## 3. 作者怎样工作：写当前章之前先明确它增加什么

### 3.1 用已有上下文建立整篇理解

开始成文时，作者先结合已确认范围、材料、Spec 和现有判断理解整体过程与交付结果，再使用已有十章骨架。章节职责来自同一份合同，不再凭某个例子的目录套本需求。

这一动作不要求另落“全文规划”或“事实归属清单”。执行者可在现有章草稿中直接整理真实的小节标题；不先输出十份章节摘要再各写一遍正文。

### 3.2 将章节之间的分工送到写作位置

在现有章节 questions/form.note 中明确本章的主要问题及与邻接职责的边界，替换重复的概括性说明；不新增字段体系。已有章草稿继续由同份合同生成。

| 章节 | 写本章时真正要新增的信息 | 需要回看的相关内容 |
|---|---|---|
| 背景 | 现状问题、影响与有依据的目标 | 原始需求，不提前展开完整方案 |
| 术语 | 理解需求必需的概念与真实歧义 | 统一后文命名，不把规则表提前复制到词义表 |
| 范围 | 本单责任、明确不负责项及交接边界 | 已确认范围，不重复背景的问题论证 |
| 业务方案 | 总体解决机制、真源、关键依据与取舍 | 范围和目标；不逐步讲完整执行过程 |
| 业务流程 | 谁在何条件下做什么、各阶段怎样相接、何时结束 | 方案的参与方/真源，材料与 Spec 中的过程；不重复完整取舍论证 |
| 功能说明 | 单项能力内部的输入、规则、状态与结果 | 已写流程及全局规则；只展开尚未解释清的局部行为 |
| 异常与恢复 | 各失败的影响、处置及恢复条件 | 已写流程/能力；不重复正常过程，必要分支出口不能消失 |
| 验收 | 能够验证既定行为的条件与结果 | 范围、功能、异常；必要重现预期值，不重写完整过程 |
| 交付与上线 | 交付依赖、控制对象、存量/在途影响及恢复条件 | 范围、方案和异常；控制与恢复能力均须有依据 |
| 附录 | 精确契约与来源的可查信息 | 保持原有投影，正文中的行为解释不再整段搬入 |

作者写某章前，使用当前上下文中已经读到的相关内容；不足或压缩后不确定时，用现有 Read 按实际标题读取相关已写片段，不能只靠记得上一章结尾。只补读相关内容，不规定每写一章都重新读全篇。

写作判断是：“此处读者还不知道什么？已经讲全的部分，在这里最少需要重现什么才能接得上？”答案直接体现在正文。能一段讲清的短写，不强行增加小节或表格。

### 3.3 图从要解释的过程出发，不能从选一张源图出发

画总览前，作者根据当前需求确认过程的起点、参与方、关键交接、分支和结果；再判断已有图是否已经准确承载这些内容。能用就用，需合并或改画则据实际过程处理。

先完成“要解释的过程是什么”这一判断，再加来源标记。没有新建图文件、第二份图目录或逐节点台账；判断直接落实在章草稿里的图与必要说明中。

图需同时满足：覆盖当前特性的完整过程；局部复杂过程明确接在总览；各分支可继续或终止；多方调用/返回按已确认要求可见。来源标记只证明图的对应身份，不证明这些语义已经满足。

## 4. 统稿怎样工作：比较对象，修改结果，不写自我保证

保留一次作者统稿，替换当前七项“核过没有”的自查写法。先通读最终合成稿，再做下列实际比较；发现问题就回责任产物修改，不先写 PASS 式结论。

### 4.1 比较信息，而不是比较措辞

找到多处描述的同一过程、规则或对象，把相关片段对着看：每处独有的信息是什么？删除其中一处后读者具体少知道什么？若没有独有信息，只保留主要落点，其他位置改为必要的连接说明。

若确实互补，保留独有部分：图讲关系、表讲属性、正文讲原因、验收给通过条件。不能用“这是不同章节”作为保留完整重复的理由，也不能把“字面不同”作为已经去重的理由。

### 4.2 沿过程推演，不以“图在”作为完成

从触发走到结果，用当前材料的实际条件沿图和正文核对：每次交接由谁发起、谁处理、结果回谁；条件改变时走向哪里；后续处理有无遗漏。简单分支不必写长报告，但图与正文必须能支持这次推演。

### 4.3 对重组处检查指代与后果

移动、合并表格或段落后，回看“上述、最后一种、这一步”等指代是否仍指向正确对象。说明启停、恢复、不可逆影响时，核对动作前后实际改变了什么，而不是为了回应提示把“不可逆”写进每项措施。

### 4.4 取消七行留痕作为完成凭据

本轮已证明 copyedit.md 的七行可以全部写得像通过，却没有修正文问题。因此新流程不再要求生成该文件，不再将其存在或行数作为成文前置；不换成十行、另一张表或另一个确认字段。

统稿的结果是修正后的正文；重要的上游矛盾按既有 decisions/notes 路径记录，未决事项不替人定。没有问题时不制造修改，也不强制另写一份“没有问题”的说明。

移除 COPYEDIT_ROWS、copyeditPath 的强制消费者、check 的七行项及 copyedit 的冻结登记；decisions.json 的冻结和人工反馈保护继续。已有 copyedit 文件作为历史过程件保留，不清扫、不迁移、不兼容重算。

这项删除不意味着“统稿可以跳过”：作者任务仍明确要求实际通读和比较，独立审查仍对最终内容负责。它承认脚本无法通过计数证明模型做过语义工作，而不是宣称换一个记录形态就能强制模型认真。

## 5. 独立审查怎样工作：用来源校验结果，不接续作者的自评

沿用一次现有 verifier，不增加同质审查轮次。重点改变它的输入和判断动作。

### 5.1 审查对象完整送达，要求不重复堆叠

当前 ai-prompt 内联 Spec，但 Story 只列路径。本步通过既有 reader-review-task → pre_verifier 的 promptFragments 路径，将当前最终 Story 作为只读原文上下文送入同一个 verifier；这份原文就是审查对象，不先由作者摘要或抽取。

不再要求该 verifier 因为任务书只有路径而重复寻找同一份 Story；原文附来源路径，必要时可回文件核实。材料清单、已确认范围与决策仍走原有文件入口，按本次核对需要读取；不把原始材料全部复制成新的常驻上下文。

实现前核当前宿主最终 prompt：若它已通过原生路径内联同一份 Story，则直接复用，不再追加第二份。以既有输入装配责任确定唯一生产者，不增加文本相似度去重。内容超过宿主可承载范围时如实说明并按现有读取工具完整分页，不能静默截断后判完整通过。

原文是必须读的对象，增加内联字符只能以减少查找和遗漏风险解释，不能称为减少 token。验收同时观察实际输入成本。删除任务书中重复的通用判据，规则只在 overlay 维护；不把本方案或测试答案放进任务包。

### 5.2 审查动作先于结论

verifier 从已确认范围和相关来源建立对关键过程及结果的理解，再对 Story 核查，不以作者分了哪些小节或 copyedit 自评作为完整性答案。

它要实际完成三类判断：

- **覆盖与关系**：需求要求的过程、重要条件和结果，在文稿/图中是否都有去向；源码或材料缺席不能被误报成已核实。
- **独有信息与一致性**：同一事项在多处出现时，各处究竟增加什么信息；图、表、文字和验收是否互补且同义。
- **主张与依据**：设计、回退和可观察效果是否由当前事实支持；重组后的指代、状态与因果是否成立。

这些是全篇审查中的比较动作，不是只挑三个例子就代表整篇已审。模型按实际需要选择比较对象，遇到疑点继续查其直接依据；不规定必须找到若干错误，不按业务类别生成固定“问题清单”。

### 5.3 报告呈现判断依据，不呈现全部思考过程

沿用原有汇总行与 blocking_findings/advisories。汇总证据说明实际核对的关键关系与产物位置，避免只罗列十章名称、写“均一致”。有问题时给出对应内容、冲突/遗漏及影响；没有问题时用必要的对照结果支持结论。

取消“PASS 到此为止，不写明细”对必要证据的压制；允许在同一份报告中用简短说明补足汇总格装不下的依据，不新增逐事实裁决表，也不要求公开逐步思考过程。脚本不按字数、引文长度或证据条数判语义质量。

框架的 subject、报告身份和闭环检查继续复用。check-receipt/PASS 只说明框架定义的闭环条件，不自动证明作者和审查者在未知任务上判断准确。读者审查无法完成关键核对时，按既有结果结构如实报未完成的阻断项，不编一个肯定结论。

## 6. 脚本只处理能可靠完成的部分

保留章节、材料/图路径、源图对应、验收编号、附录投影与冻结一致性等检查。删除七行自述检查，不以更复杂的自述结构补回。

本轮已有两种无阅读收益的返修，限定修正其作用域：

- 工作编号检查针对读者阅读的正文与表格，不把 Mermaid 内部节点 ID 当业务编号；图标签是否夹带无意义标识由既有图语义审查判断。源图对应及验收表编号检查不变，不为此新写 Mermaid 解析器。
- 数据/状态的回滚含义与客户端发布用词分清。复用现有语境处理，将可确认的业务语义放行；语境无法可靠区分时给明确提示交既有语义审查，不因为命中一个词就强迫改掉正确业务描述。禁用词范围不扩张，不按当前案例字符串加豁免。

修法须以真实错误作用域为单位，不修改业务结论迎合脚本。单次局部修正后重跑受影响的确定性检查；语义审查返修按原有 subject/重验路径处理，不新增全流程重跑规则。

## 8. 实施与验证

### 实施顺序

1. 同步作者任务与章节职责，移除自相矛盾的旧指令；使实际章草稿拿到本步定义的输入。
2. 同步统稿及 copyedit 的全部直接消费者，保持冻结与归档行为正确。
3. 调整现有审查输入及任务，检查最终 prompt 中 Story 完整、只出现一份；报告格式仍与 Framework 兼容。
4. 校正两种已观测的机械误判，补结构回归，完成本轮要求的离线检查与实施评审。
5. 用户启动真实 CLI 后，依据实际产物与行为收口；不在本步自动启动新测试任务。

### 确定性验收

| 项 | 可检查结果 |
|---|---|
| 作者输入 | 实际草稿包含本章职责和必要边界，公共执行内容不引用维护方案，不预生成另一份逐事实计划 |
| 统稿凭据退场 | 正常成文不要求 copyedit.md，历史过程文件不被删除；决策冻结、人工意见保护仍通过 |
| 审查对象 | 通过实际 pre_verifier 装配检查，最终 Story 的首尾及全文正确送达且只一份；缺件/不可读如实出声，不静默用空串 |
| 检查边界 | Mermaid 节点 ID 不再触发正文工作编号错误；有效业务回滚表述不因关键词误拒；正文无意义工作编号、必需图/验收/投影缺失仍按责任发现 |
| 报告兼容 | 实际对照说明可正常落盘并被现有读者审查结果检查读取；报告缺失、subject 不符等既有保护不被绕过 |

构造件只证明这些确定性能力，不用删几段造出的坏稿证明模型判断力。

### 真实行为验收

复用 runlog/events、实际草稿、最终产物与独立报告，不新增评测平台。以本步前的真实结果为问题证据，但不把案例词、金额、接口名或预期答案写入执行提示。

- **首次成文**：查看首次 write/落盘的内容，主要过程关系与章节分工是否在首稿成立。区分本轮确实新增的能力与偶然换措辞；不要求绝对零编辑。
- **统稿**：本轮真实出现重复或矛盾时，作者是否实际比较并修正；如果保留多处，读者能指出各自独有信息。没有缺陷时不强迫制造修改。
- **独立审查**：维护者/用户在真实产物中发现的关键问题，verifier 报了没有、依据对不对；不能拿“报告有三个引用”判有效。任务装配可查，子代理实际阅读轨迹取得不到时如实记缺口，不声称已经证明完整执行。
- **完整性与可读性**：多方过程、必要分支、关键约束、验收与源图有去向；重组后的指代和结果一致。去重不能删掉唯一的条件、例外或业务结果。
- **成本**：分别列材料准备、成文、机械返修、语义返修和人工等待；首次章稿与最终稿的差异说明用途。不要用全程时长单独断言本步好坏，也不把增加内联内容的成本藏起来。
- **泛化范围**：已有 UI 场景之外，无页面数据管理场景仍需用户真实材料验证；暂缺则保持待验，不声称本步已覆盖全部业务。

### 不达标时如何处理

先分清：输入未送达、任务没执行、比较做错、语义能力不足、机械误判。修在相应责任位置，不统一追加“务必仔细”。如果输入和动作已经明确，真实执行仍重复漏掉同类关键问题，应向用户报告该模型/配置的能力缺口，讨论适用配置或人工复核范围；不得继续用提示长度掩盖，也不擅自换模型或增加 Agent。

## 9. 规模与收口

本步允许必要的输入成本，但必须说明它如何帮助模型完成任务。预计作者任务文字以替换为主；移除七行凭据减少脚本与冻结关联；审查输入装配只扩已有函数。不开新的长期运行文件、轮次或状态。

实施前按实际基线统计两种成本：除 knowledge/adapt 外的完整字符，以及现有分类代码行预算；同时测实际生成的作者/审查输入字符。静态文件变短不代表运行上下文变短。

量级预估：scripts_mjs/scripts_py 合计净减约 15–40 行，hooks_mjs 增约 10–30 行，提示与合同以职责替换预计净增 0–50 行；不是已签配额。继续按当前已批准预算及用户“允许合理增加”的约定登记，超出已批准边界再具名确认，不削减内容与验证凑数。

实施完成、离线和独立实施评审通过，可以标“实施评审通过，行为待验”接续后续步骤；本步行为目标仍须上述真实证据。Step2.1 已证明形式可变，本步必须进一步证明模型实际会组织、比较并纠错，才算完成本轮优化目标。
