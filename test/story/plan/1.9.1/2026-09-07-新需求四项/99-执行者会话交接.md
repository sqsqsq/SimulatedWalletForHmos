## 5. 只在对话里存在的事

**`gate_failed` 不一定是判据红。** 撞到过一次：终态 `gate_failed`，查下来是
`story-build check` 那一刻进程没起来（`returncode 3221225794` = `0xC0000142`，
stdout / stderr **全空**）；同一条命令手工跑退出 0、通过 10 章。
诊断在 `output/story/<suite>/cases/<case>/<run>/gate_diagnostics.json`——
**先看那份的 `returncode` 与 `stdout_tail`**，全空就是环境，不是机制。

**预算口径有个反直觉的地方。** `skills/story-adaptation/**` 整个不占配额
（`mechanism-budget.yaml` 的「范围」段），`.js` 也不入任何类别（后缀表只认
`.mjs / .py / .md / .json / .yaml`）。所以重写 `adapt-scan.mjs`、移动三个对接脚本，
配额上都是 **0**。早期方案把步骤 2 写成「大幅净减」，据此定的上限会不够用。

**这个 shell 会吃反斜杠。** 用 `bash` 的 heredoc（连 `<<'PY'` 带引号的也一样）写
Python / JS 时，字符串里的 `\n`、`\r?\n`、`\\` 会被吞成真换行或单个反斜杠，
把代码写坏而语法检查未必当场报。**写含转义序列的代码用 Write / Edit 工具**，
或者先把补丁写成 `.py` 文件再执行。本轮在这上面折过四次。

**改 `story-build.mjs` 与 `story_flow.py` 之后别忘了失效形态。** 它比单测更严：
交付面不许有历史叙述（「曾经」「退场」「此前」都会被判）、按 `\n` 分行要写成 `\r?\n`、
adapt 交付件不许出现 hook 阶段名与知识文件名。`PYTHONIOENCODING=utf-8` 跑，
否则输出会在中文上崩。

**起跑被一份几天前的 suite 挡住，那是 PID 复用。** 历史现场清理预检拿终态 Case 记着的
`worker_pid` 去问「还活着吗」，而旧记录多半没有 `started_at`、创建时间比不了，
`_pid_alive` 只能「宁可判活」——于是系统把号发给别的程序之后，那份 suite 永久挡路
（连着两轮起跑都撞上）。修在 `run_multi_case.py` 的清理预检：**已终态的 Case 不再有 worker，
它记着的 pid 今天在谁手上都与本轮无关**，只对非终态的记录去问。
「宁可判活」那条退让对非终态仍成立（误判成死会删掉正在跑的现场）。
**这个修改还在工作区，没提交**——它属测试域，等你确认后随下一个提交带走。

**suite-id 不要互为前缀。** 装置按名字前缀找历史现场，`...step21` 会被 `...step21b` 撞上。
另外：`start` 失败会留下一个只有 `previous-run-cleanup.json` 的空壳目录，同名重起会被
「结果目录已存在，拒绝覆盖」挡住——换个 id 重起，空壳留给下一轮统一清理。

**heartbeat 会被系统按内存压力杀掉。** 实跑期间连着杀了三次（被测 worker 一次没受影响）。
**被杀会通知你**，所以不会失明，但每次都要重新架上；把逐轮快照写进日志文件、
stdout 只在该叫人时说话，能少一分被挑中的理由。代跑脚本必须在
`next_action != poll_after_interval` 时**退出**（TEST.md §3.1）——退出即唤醒，
自己续睡就会重演那次 45 分钟空等。
