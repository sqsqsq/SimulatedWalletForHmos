## 2. 评审判据

设计者独立读成品与 runlog，不以门禁 PASS 或 verifier PASS 代替。四项判据都在成品上核，缺一项即本轮目标未达成：

| # | 判据 | 看什么 |
|---|---|---|
| J1 | Spec §9.4 的每个 H4 是指标 | 标题「指标名（流程名）」；第一段能读成「X 率或分布由下表结果算出」；材料里的事件分类或业务目标被翻成了指标并说明关系；表里无实现名 |
| J2 | Plan 每个结果有具体候选值 | 流程号、步骤号、十位内码是数字并标候选与登记文件；尝试持有者与结算方法有名字并在 contracts 里；写不出的行有「缺哪一项」 |
| J3 | 只计一次 | 跨流程或跨端共用的事实只在一张表里出现；远端状态回显按首次得知计，不按查询或进页次数计 |
| J4 | 审查报了什么 | spec 与 plan 的 verifier 报告对 J1–J3 的缺陷有没有指认；把占位当「待登记」放行的写法不再出现；交回写明哪些阶段是 `completed_with_prior_review`、最终材料是否再审 |

附带观察，不作为通过条件：runlog 里 spec 作者在写 §9.4 前有没有重读知识上篇、plan 作者有没有读下篇；knowledge-use 骨架的「何时读」是否让作者跳过了不相关的事实；面改为九个节名后作者在 `facts[].used.facet` 填了什么、审查用不用得上；模型停摆与上轮比是否变化（模型因素，只记录）。

## 3. 判定与发布

- J1–J4 成立：实施者升 `manifest.yaml` version 到 1.9.6，写 `test/story/release/1.9.6.md`，分开列机制、知识、离线、正常模型任务结果、内网待验证（adapt、coding 后行为）与用户成品评价；预算台账按实测重签 target、status 改 closed；使用指南同步；提交带版本号。
- 任一不成立：停在评审，写诊断进本目录 `评审意见/`，按 08 §8 的四问归因（送达、知识、模型应用、审查）。不在实跑后追加第三轮小改；诊断若指向知识或机制，回到本目录改分册后再谈下一次实跑；若只剩模型因素，如实写入发布说明的未达成项，由用户决定是否换模型验证。
