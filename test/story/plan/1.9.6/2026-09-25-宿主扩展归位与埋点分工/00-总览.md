## 1. 问题

### 1.1 spec 的扩展章没有挂在 framework 预留的锚点下

framework 两份 spec 模板结构一致：

- 文件：`framework/profiles/{generic,hmos-app}/skills/spec/templates/spec-template.md`；
- 核心章编号 0–8，「Scope 声明」不编号；
- §8 之后是两章：不编号的「## 宿主扩展治理项」（258 行）和「## 附录」（270 行）。

`framework/docs/concepts/phase-terminology.md:25–35` 的规定：宿主细则经 extension 模板与 overlay 叠加，「模板末尾锚点：宿主扩展治理项」。

extension 没有用这个锚点：

- `skills/story/phases/spec.md:102` 写的是「§8 验收标准之后追加一章」，另起 `## 9. 技术契约`、`## 10. 规约约束要求`、`## 11. 设计模式候选登记`；
- 锚点被降成一句固定套话（`templates/spec-sections.md:89`、`phases/spec.md:122`），里面还带着「TA 联调 / Demo」。

结果是扩展章的位置全靠模型猜：

| 产物 | §8 之后的章序 |
|---|---|
| car-key 本轮（`doc/features/ISSUE-206-update/spec/spec.md`） | 宿主扩展治理项 → **附录** → §9 → §10 → §11 |
| auto-topup 本轮（`AR90006-update`） | §9 → §10 → §11 → 宿主扩展治理项（自填 6 行表）→ 附录 |
| auto-topup 上一轮 | 宿主扩展治理项 → §9 → §10 → §11 → 附录 |
| 夹具 `fixtures/golden/AR90004/spec/spec.md` | §9 → §10 → §11 → **附录（336）→ 宿主扩展治理项（355）** |

同一模型三次放了三种位置，car 这次把附录夹进了正文中间。门禁不核章序：

- framework 的 `check-spec.ts:614–634` 只按名字核必需章；
- extension 的 `hooks/spec/post_check.mjs` 只核扩展章在不在。

### 1.2 plan 的扩展内容同样没有挂在锚点下

framework 两份 plan 模板的结构：

- 文件：`framework/profiles/*/skills/plan/templates/plan-template.md`；
- 「Scope 声明与继承」不编号，§1 模块架构图到 §8 spec 功能映射表；
- 末尾是不编号的锚点「## 宿主扩展（可选）」（150 行）。

extension 没有用这个锚点：

- 「## 知识决策（设计输入）」插在 §1 之前（`templates/plan-sections.md:6`）；门禁还强制这个位置（`hooks/plan/post_check.mjs:37–58、266–272`）。
- 「### 埋点」塞进 core 章「## 6. 服务层接口定义」（`plan-sections.md:106–111`）。
- 锚点在 extension 里从未被提及。framework 的 `check-plan.ts` 只按名字核必需章，不核章序。

### 1.3 埋点：指标标题带流程说明，spec 与 plan 重心重叠（金样反馈）

- **指标标题带流程或阶段说明**：
  - spec 模板写「`#### { 指标名 }（{ 流程名 }）`」（`spec-sections.md:48`）；
  - spec 任务包写「标题写『指标名（流程名）』」（`hooks/spec/author.mjs` 第 5 节）；
  - 知识示例是「服务开通成功率与失败原因（服务开通流程）」（`knowledge/facts/event-tracking.md`）；
  - 金样是「开卡成功率、步骤耗时与失败原因（开卡办理·运维）」。

  用户要求：标题只写指标名（「开卡成功率」「查询成功率」），正文以指标展开，讲清怎么算、在哪些业务流程打点。
- **story 投影照搬 spec 标题**：story 是投影，同样整改。
- **plan 与 spec 同构**：plan 埋点小节也按指标分节，重抄业务结果。见 `plan-sections.md:113–127` 的「指标（流程）」列与「提交成功率（下单流程）」H4，以及金样 plan 的每指标一个 H4。

  用户要求：**spec 的重心是如何设计打点，plan 的重心是如何实现打点**。
