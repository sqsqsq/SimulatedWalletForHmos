## 5. 读法偏差（交评审裁）

1. **测试域只链接 `yaml` 包，不链接整个 `framework/harness`**（03 §6 写的是「`framework/harness` 指向真实目录的 junction」）。第一版按整目录做，`test_verifier_report_protocol` 里放替身 runner 的用例（`_stub_receipt` 往 `<根>/framework/harness/node_modules/ts-node/dist/bin.js` 与 `scripts/check-receipt.ts` 写替身）经 junction 写进了真实 harness：ts-node 被换成替身、`check-receipt.ts` 被清空。已恢复（`git checkout` 回 check-receipt.ts，`npm install` 重装 ts-node 10.9.2，framework 零差异）。改为只链 `node_modules/yaml` 一个目录后套件各自的替身仍落在临时根里。
2. **helper 顺手写空 `framework.config.json`**：`yaml.mjs` 以它定根，多数临时根没有它；空配置对扩展等于取默认路径（`paths.mjs::readConfig` 缺键即默认），不改任何套件的行为。
3. **安装期检查只在目标有 harness 时才 die**：目标连 `framework/harness/package.json` 都没有时（失效形态 A02 与 `fixtures/adapt` 的目标树都是这种最小树）只在 stderr 提一句。理由：没有 harness 是 framework 还没接入，归 framework-init；adapt 只核已接入 harness 的依赖。整目录 die 会让 A02 的 good 夹具也失败，而在夹具里补假 node_modules 是按解析器形态造夹具。
4. **`FLOW_FILE / FLOW_FIX / FLOW_STATES` 三个常量保留**：方案「`FLOW_*` 字面常量退出」我读成「与合同重复的三个」（schema、gates、carry_all）；这三个分别是契约路径、处置句、状态机顺序，合同里没有对应键，Python 侧 `after_complete` 也只写状态名不写顺序。要不要把 `FLOW_STATES` 也入合同，交评审定。
5. **与 framework 同一读法带来的两处语义变化**（`test_yaml_reader` 锁定）：值里带「`: `」的句子（`reason: 命中条件: 事实`）现在是解析错误，要加引号；列表项写成 `- 键: 值` 现在读成映射。两处都与 framework 对 contracts / acceptance 的读法一致，报错带行列。`knowledge-use.yaml` 骨架的 `reason` 填法说明在步骤 3 E1 改时顺带写一句「带冒号加引号」，本步没动提示层。
6. **`test_yaml_lite_scalars.py` 改名为 `test_yaml_reader.py`**：保留原七种写法同值与引号内 `#` 的用例，把「引号没收尾原样留着」「句中冒号当字符串」两条改成与 framework 同一判法，新增深相等与缺 harness 两类。
7. **R3 的 `gate.mjs` 渲染**：组名用「【组名】N 处」一行，编号跨组连续；没有 problems 只有 skipped 时的输出不变。
