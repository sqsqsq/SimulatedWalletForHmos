# Review 决策项精简与计划外意见模板（需求2 关联）

> 状态：已实现（实施完成，回归全绿） · 日期：2026-08-23
> 同一批待优化方案之一（与 `00-图片引用`、`01-知识应用`、`02-人读成文闭环` 并列）。
> 本方案处理 review.md 两个问题：①决策项表述冗杂、机械化；②计划外意见区无模板、AI 回流难处置。
> 核心认知：review.md 经 `/story review` 喂给 AI、按 `review_reflow.md` 修正 spec——**是"AI 可处置的决策说明"，不是"人工跟踪表单"**。
> 实施事实与行为验证结论分局记录，禁止写"已实施"。

## 一、现状（已核实）

### 1.1 review 的本质（修正理解）

`/story review` 工作流：AI 读 `AR/review.md`（唯一输入）→ 对每个决策项表态+处置 → 按 `impact` 指向的编号**改 spec**（correction 闭环）→ 落 `AR/review-disposition.json` 台账。

所以 review 决策项服务于两个读者：
- **AI（主要消费者）**：需要知道"这个议题改不改、改哪里（impact）、改什么（当前结论）"——可处置；
- **人（触发者/复核者）**：快速读懂"决策是什么、为什么、改哪"——可读。

### 1.2 现状问题

每个决策项由两区拼成（`story-build.mjs` 渲染）：

**机器区 `renderMachineZone`**（L470-485）：`### question` + 6 个 `- **标签**：`（当前建议/结论、为什么这样建议/定、同意或修改后会影响什么、结论来源、请谁确认）——decisions.json 的 `proposal/rationale/impact/source/decider` **全独立成机器标签**。

**人工区 `renderHumanZone`**（L488-510）：`#### 审核结果（由评审人填写）` + 4 checkbox（同意/修改/暂缓）+ 5 子字段（修改意见/暂缓责任人/期限/是否阻塞/后续动作）+ 确认人/日期/依据。

**问题**：一个决策项 = 1 标题 + 5 机器标签 + 1 人工表单（含 5 子字段）——**像任务跟踪表单，机器感强**。责任/期限/阻塞/动作/确认人是"任务跟踪"语义，review 不是跟踪工具（跟踪归 `review-disposition.json` 台账 + 下游 plan 参考），这些字段是**错误方向**。

**计划外意见区 `renderFreeformSection`**（L544-556）：只有一句引导语（"一条一段，写清是什么与影响哪里；不必套用上面的表单"），无条目模板；空态显示 `（暂无）`。AI 回流要判类型（需求类→改 spec / 叙述类→记台账）+ 落台账（原话摘录），无模板时人写"这里好像有问题"，AI 判不出"改哪、影响哪"。

## 二、目标

1. **决策项**：从"标签清单"→"叙述段落"，5 个语义块（本问题/背景/决策/评审意见），删一切任务跟踪字段；
2. **计划外意见**：提供极简可选模板（意见/影响两字段），对齐 reflow 判类型落台账，不破坏自由意见本质。

## 三、决策项新形态（叙述段落，非标签清单）

```markdown
### 离线时是否允许打开已保存的交易凭证？

**背景**：上游 PRD 与 SE 设计原存在直接冲突（PRD 要求断网可查看，SE 原文「断网一律阻止查看」）；
经产品裁决以 PRD 为准，SE 已按裁决修正并留痕（来源：产品裁决，本地问题单材料）。

**决策**：允许——网络不可用但有通过校验的可用缓存时即可打开凭证正文；缓存缺失或校验失败
才引导重新生成。影响：AC-1、AC-2、S1。

**评审意见**：
- [ ] 同意（不改 spec）
- [ ] 需修改（按影响 AC-1/AC-2/S1 改 spec）
- [ ] 暂缓（记台账，不改产物）
```

### 语义映射与合并

| 语义 | 现字段 | 现渲染（错：标签堆） | 新渲染（对：叙述段） |
|---|---|---|---|
| 本问题 | `question` | `### question` | `### question`（保留，人话标题） |
| 背景 | `rationale` + `source` | `为什么这样定` + `结论来源` 两标签 | `**背景**`：rationale（来源并入尾注） |
| 决策点 | `proposal`/`conclusion` + `impact` | `当前建议/结论` + `会影响什么` + `请谁确认` 三标签 | `**决策**`：proposal/conclusion（影响并入一句；`decider` 渲染侧删除） |
| 评审意见 | 人工 checkbox（错：任务表单） | 4 checkbox + 责任/期限/阻塞/动作/确认人/日期/依据 | `**评审意见**`：3 checkbox，各带处置语义（对齐 reflow §1 三态处置） |
| 结论 | 确认人/日期/依据（错：跟踪） | 3 空行 | **删除**——评审后 AI 落 `review-disposition.json` 台账，不在此填"结论" |

### 关键决断

1. **机器区 5 标签 → 2 段**（`背景`/`决策`）：合并不是删信息——`source` 并入背景尾注、`impact` 并入决策一句。评审者判断所需依据（理由/影响/来源）一条不少，不再各自顶标签行。
2. **人工区 4 checkbox+5 子字段 → 3 checkbox**（各带处置语义）：删责任/期限/阻塞/动作/确认人/日期/依据——**无责任人、无期限**，review 是一次性"评审→处置"输入，跟踪归 `review-disposition.json`。checkbox 标签直接对齐 reflow §1 三态处置表（同意不动 / 需修改按 impact 改 / 暂缓记台账），AI 看到「需修改（按影响改 spec）」即知动作。
3. **`decider`（请谁确认）**：**渲染侧删除、登记层保留**（不动 decisions.json schema，历史兼容 + 人可能需知谁定的）。
4. **`HUMAN_ZONE_MARK`**：`#### 审核结果（由评审人填写）` → `#### 评审意见（由评审人填写）`。需兼容评估：`extractHumanZone`（L517-524）按此 MARK + `<!-- decision: id -->` 定位、逐字节保留已填内容。本轮四 Case 的 review 均新生成、无已填历史 → 直接改；真实环境升级时需保留旧 MARK 兼容读（方案标注）。

## 四、计划外意见模板（极简、可选、非强制）

```markdown
## 计划外意见（不属于以上任何议题）

起草方没登记成议题、而你认为该说的事写在这里——缺的分支、该复用的既有能力、遗漏的埋点都算。
可选按下面骨架写，一条一段；不按骨架也可以，写清楚就行。

> 模板（可选用，不强制）：
> 1. **意见**：<缺了什么 / 该做什么>
> 2. **影响**：<影响哪个功能/验收编号，或哪段叙述不清>
> （例：意见——离线场景还有"弱网"档没覆盖；影响——AC-1 只写了断网，建议补弱网分支）

<!-- freeform-zone -->
（暂无）
<!-- /freeform-zone -->
```

**设计理由**：
- **意见/影响两字段** = reflow §1 判需求类（有 impact 指向）vs 叙述类（叙述不清）的最小判据——AI 见"影响：AC-1"判需求类去改 spec；见"影响：背景段落没说清"判叙述类记台账；
- **模板 + 示例 + 非强制声明**：既给 AI 可处置的最小结构，又不破坏"自由意见"本质（模板是引导不是约束）；
- **空态（暂无）保留**：无意见时不产生模板占位，避免"无意见"被误读成"必须填"。

## 六、边界（明确不做）

- `decisions.json` 字段**不改**（登记层语义不变），只改渲染形态；
- 定位机制（`<!-- decision: id -->` + MARK 切分 + 已填逐字节保留 + `freeform-zone` 逐字节保留）保留；
- 不改 `framework/`；
- 「是否阻塞执行/后续动作」删除（跟踪语义归 `review-disposition.json` 台账）。
