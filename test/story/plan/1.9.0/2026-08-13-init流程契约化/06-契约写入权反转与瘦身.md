## 二、根因（两条，非五条）

### 2.1 我违反了自己定的边界，且 01 的一条裁决被实测证伪

[01 §3.5](01-init流程契约方案.md) 写「**契约由 AI 写、脚本只校验**——判断留 AI，执行归
脚本」。前半句与后半句自相矛盾而当时没有察觉：**写契约本身就是执行**——算 sha256、
盖时间戳、判断轮次边界、维护数组结构，没有一样是判断。真正的判断只有两样：
人选了哪一项、依据是什么。

于是 Q1/Q3/Q4/Q5 是同一件事的四种表现：**让执行者记忆并复现机械事实，它就会漏记
（Q1、Q5）、编造（Q3）、结构错乱（Q4）**。仓内正例就在隔壁：`import_sources.py
--classify`——归类（判断）由 AI 传参，**脚本是唯一写入者**，从未出过这类问题。

> **正式推翻 01 的「契约由 AI 写」**：依据即 Q1/Q3/Q4/Q5 四条实证。
> 曾考虑的替代修法（schema 加 outcome 字段 + post_check 逐类加断言）被否——
> 那是把「AI 会写错」当常态去枚举，失败模式无穷，下一轮必出第 6 种。
> 正解：**审计记录应当是动作发生的副产品，不是要求行动者事后另行填写的文档。**

### 2.2 SKILL.md 装了不属于它的东西（Q6、Q7 的根因是同一个）

按章统计（总 540 行）：最大的一章「spec 阶段的三份产物」**166 行 / 30.7%**，而它自己的
标题就写着「适用于所有 feature，**与是否走 /story 无关**」。逐段比对：
`hooks/spec/on_context_load.md`（110 行）**已完整覆盖**它且更细（防重复规则、两张术语表
分工、数值来源、闭环下一步提示）。钩子才是正确落点——spec 阶段自动注入、所有 feature
都吃到；SKILL.md 只有走 /story 才读。

同病还有第三个落点：两个 adapter 跳板的 `/spec` 行整段复述 spec 作业（三份产物 / §9 /
scaffold→转写→build / decisions.json 渲染），并带一个**与 SKILL 矛盾**的括号——
「决策件未确认时另读 SKILL 的决策件定稿 Step 4」，而 SKILL 归档章明写草稿态是
「常态路径」「**不停等确认**」。跳板的本分是它自己第一句：「按用户指令**只读所需章节**」
——一张命令→章节路由表，不该知道 SKILL 内部小节编号，更不该复述别的阶段的作业。

## 三、设计

### 3.1 删（Q6/Q7 主体动作，净 −约 210 行 / −38%）

| 动作 | 量 | 去向 |
|---|---|---|
| **整章删除**「spec 阶段的三份产物」 | −166 行 | 与钩子重复的部分直接消失；**三小块不重复内容移入 `rules/rules.md`**（spec 钩子已引用它，条件加载）：①Step 3.2 逐章转写细则 ②Step 4 决策收集（五类来源表、准入判据、字段、question 写法）③完成标准四条 |
| **缩减**「初析与流程契约」 | 73 → ~25 行 | 手写 schema、哈希命令、时间命令、轮次语义推理全删——AI 不再有这些义务（见 3.2）；只留：调什么命令、`--basis` 写人的原话、`by:"ai"` 须带 policy 与授权原话 |
| **跳板归位**（两个 adapter） | 各 −约 4 行 | 删「另读 SKILL 的决策件定稿 Step 4」括号（越权 + 与 SKILL 矛盾）；`/spec` 行压成一句「需求规格阶段：一次 pass 产出三份产物并过门禁」 |

**自检修正 ①（rules.md 兼容）**：`rules.md` 既有断言
`test_every_rule_declares_an_execution_channel` 要求红线条目标执行通道——三小块移入时
作为**独立章节**追加（非红线条目格式），实施前先核对该断言的扫描范围只覆盖红线表格；
若全表扫描则调整断言的定位方式，不迁就格式硬套「执行通道」标签。

**`AR/template.md` 不动**（裁决 2026-08-13）：我一度判它为死产物（本地字节等同
design.md、零消费者）——**判错**：内网它是 story.js 从需求系统拉取的平台模板，本地
mock 用同一个 `emptyArTemplate()` 生成才造成重复表象。契约章与 init 输出表保持原样。

### 3.2 反转：契约唯一写入者 = `scripts/story_flow.py`（治 Q1/Q3/Q4/Q5）

新增脚本（标准库，形态同 `import_sources.py`：`--feature`/`--project-root`、stdout 单行
JSON、stderr 人类日志、Windows 下 reconfigure utf-8、可预期失败给补救动作）。
**这不是新增功能**——不带来任何新能力，只是把执行动作从 AI 手里拿走，3.1 的缩减才成立。

| 子命令 | AI 传入（判断） | 脚本自己做（执行） |
|---|---|---|
| `round` | 无（可选：import_sources 输出 JSON，脚本从中提取 `imported`） | 算四源+初析件 sha256；**按初析件哈希判定新轮/同轮**：与末轮 `analysis.sha256` 相同→幂等更新不新建（Q4 假轮次按构造不可能）；无契约文件则创建 |
| `decide` | `--chosen` `--by` `--policy` `--basis` `--scope-text` | 盖真实时间戳（Q3 按构造消除）；参数校验：`by=ai` 缺 policy/basis 直接拒绝；**`chosen=supplement` 时自己判定 inbox**（见下）；追加进当前轮 `decisions[]`；无轮次报错「先跑 round」 |
| `complete` | 无 | 校验：`AR/design.md` 存在、末条决策为 `proceed` 且 accepted、`split.decided=split` 则 `scope_text` 非空；盖 `design_generated_at`；置 `status="complete"` |

**自检修正 ②（「未导入」判定精确化）**：SKILL 现写「除 README.md 外没有未导入文件」，
但「未导入」AI 其实无从准确判断。脚本有账本：**inbox 现存文件 − 历史各轮 `imported`
并集 = 未导入集合**。非空 → `outcome:"accepted"`（继续导入流程）；空 →
记 `outcome:"rejected"` + reason 并**非零退出**提示重新放料——校验与记录是同一次调用，
Q1 的「忘了记」不存在。

**自检修正 ③（complete 不做过度校验）**：曾考虑用「design.md ≠ template.md 字节」判定
「确实重新生成过」——否。template.md 在内网语义刚被我判错过一次，不对它做第二个假设；
「确实生成过」由调用时机（S4 生成后调）+ 时间戳承担，脚本只查存在性。

schema 定为 v2：`rounds[].decisions[]`（一轮可含多条决策：拆分定案→再选进 spec）、
每条带 `outcome`（accepted/rejected）与 `at`、`analysis` 记 `{path, sha256}`。
**这是脚本模型的自然形状**：一轮=一次初析，一次关卡交互=一条决策，含未生效的。

`post_check.mjs` 的 `storyFlowProblems` 角色变小：从「抓 AI 健忘」变为**防手工编辑与
文件损坏的最后防线**。跟随 v2 调整字段名；`schema !== 2` 报单独一条明确错误；
保留 rejected-须有-reason、ai-须有-policy/basis、complete 前置、相邻轮哈希不同等轻量校验
（成本低，防手工改坏）。

### 3.3 收口后直接进 spec（治 Q2，+6 行）

「生成design.md」章末尾改为**具体动作 + 边界澄清**：

> 收口后**直接读 `framework/skills/feature/spec/SKILL.md` 并从 Step 1 开始执行**，
> 不再询问。授权来自 S3 关卡那次「进入 /spec」的选择。这不违反 `user-confirmation-ux`
> §8——那条治的是 **framework 阶段之间**的推进（四件套 PASS 后→下一 phase）；
> story 的 S1–S4 不是 framework 阶段、没有四件套，它与 spec 的关系是
> 「同一次需求开发的前置准备 → 第一个阶段」。进入 spec 后，spec 自身的确认点
> （术语映射 `[x]`、`spec.freeze` 等）照常生效，本条只豁免「进入」这一步。

实测模型停下来是对的：SKILL 说「自动进入」、框架说「禁止自动读下一 Skill」，
它选了保守一边——**规约没说清这次推进为什么不归那条管**。

## 四、机械断言

- **新增 `test_story_flow_script.py`**（驱动真实脚本，正反例都要）：
  同轮多决策落一个数组 / 空 inbox 被拒且留痕（exit≠0 且契约有 rejected 记录）/
  初析哈希未变时 round 幂等不新建 / `by=ai` 缺 basis 被参数校验拒绝 /
  complete 前置不满足拒绝收口 / 无轮次时 decide 报错 / 中文文件名 imported 不乱码；
- `test_flow_contract_gate.py`：夹具升 v2（含 rejected 记录的合法契约放行）；
- `test_story_template_consistency.py`：FlowContractTest 的 13 项手写 schema 字段断言
  **替换**为「契约章指向 story_flow.py 三子命令 + basis 义务」；新增反重复落点断言：
  ①SKILL.md 不含 spec 作业指导（三份产物表 / §9 / 合规判定三出口）
  ②两个跳板不含 SKILL 内部小节编号（`Step N`）③收口段点名 spec skill 路径与 §8 边界；
  `test_entries_describe_the_current_production_flow`（要求四入口都提 story-build）
  缩到 skill + spec hook——这条断言正是把跳板复述锁死的钉子。
