# 批次 5 · 独立评审报告约定

每个步骤通过或不通过都建立一份独立报告：`NN-<步骤短名>.md`。返修继续写在同一报告的新轮次小节，不另建“最终版”文件。

报告由方案维护者填写，实施者不得代写评审结论。最小结构如下：

```markdown
# 步骤 N · <名称> · 独立评审

## 1. 结论
- 状态：通过 / 不通过 / 阻塞
- 审查基线：<开始 HEAD>
- 审查对象：<实际 diff 文件>

## 2. 行为重建
- 输入生产者：
- 处理与所有者：
- 输出及消费者：
- 失败路径：

## 3. 验收证据
| 判据 | 证据 | 结果 |

## 4. 问题
- blocker：
- advisory：

## 5. 范围与回归
- 允许范围：
- 保护区差异：
- 预算变化：对照步骤文件《预算》节与 `mechanism-budget.yaml` 的 diff——预计与实际各类别增减、新增脚本行各归 D2 §4 哪一类、抬高的 reason 是否成立、有没有为过门禁砍方案：
- 未运行的高成本测试及原因：

## 6. 后续
- 允许提交：是 / 否
- 下一步是否可开始：是 / 否
```

“测试通过”“字段存在”和实施者自述不能单独作为通过依据。评审必须从实际文件重建行为，并明确未运行真实 Story 时仍缺少什么证据。
