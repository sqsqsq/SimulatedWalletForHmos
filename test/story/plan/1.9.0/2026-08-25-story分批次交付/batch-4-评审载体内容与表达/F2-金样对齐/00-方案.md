## 2. 改动（每项：现状 → 目标形态 → 自验；受影响文本按目标形态整段重写，不逐行删改）

### D1 · 模板按金样对齐——「形」的第一载体一次修全（含用户点名两条）

**现状**：`doc/extensions/skills/story/templates/story-template.md`——`:34 # {{需求名称}}`、`:36` 登记 blockquote、章标题无编号、附录注释「小节可以带 A.–E. 序号」、材料清单注释只有「一行一份，一句话说清贡献」。

**目标形态**（模板骨架与注释重写为）：

1. H1：`# {{AR编号}} {{需求名称}}`；**删除头部登记 blockquote**（单据与来源信息的落点是附录材料清单；「文档状态」是流程信息，不进归档件）；
2. 章标题带编号：`## 1. 背景` … `## 10. 附录`；正文小节 `### <章号>.<序> <业务名>`；附录小节**必带** `### A.`–`### E.`（「可以带」改「须带」）；
3. **材料清单行形态**（注释给中性模板）：`- **<材料类别>**——<来源：需求系统 <单号> / 随归档附件>《<文件名>》（<提供方>，<提供方式或版本口径>）：<内容贡献>；`——读者据此能定位那份材料；仓内路径仍属红线；
4. 模板头注释新增「**全篇样式约定**」一节（中性描述，不含任何业务示例）：图题 = 图片 alt 带题 + 图后一句说明它画的是什么，全篇一种样式；表前一句引导（这张表给你看什么）；单元格 1–3 个短项，超长改列表或拆行；同列头的表连排时各自说明差别；小节名 2–6 字常规业务名；每章小节颗粒度一致（要么分节要么不分，不混）；同一主题只占一个结构位置；
5. 各章注释补金样定稿的形态要点（中性措辞）：业务方案章注释加「关键取舍成表：选了什么 / 否了什么 / 为什么被否的不行——写不出被否方案的不算取舍」；异常章注释加「设计内的受限结果与真正异常**分两张表**，异常表带『守住什么』列」；验收章注释加「原始意图、本轮细化、通用质量**三层编号全收**，按要验的事分组」；功能说明章注释加「页面用『区域｜用户看到什么｜能做什么』的读者语言表，不用组件实现表」。

**同步**：check ① 增加一条硬事实判据——H1 含本 feature 编号（机器可核，金样有此形）；`story-build check` 对附录小节字母的规范化已在（F 修复②），无需再动。

**自验**：① 金样对更新后判据零 FAIL（G01）；② 模板与金样并排人读——每条样式约定都能在金样找到对应实例、且注释里无业务字面；③ 夹具 story 的 H1 加编号后台账全绿。

### D2 · 机器面列与红线作用域——两处合同数据修死视角回滑

**现状**：`story-chapters.json` 的 `machine_facing.table_columns = [所属模块, 所属层, 置信度, 本流程消费步骤, SR 章节, 链接]`；`language_redline = { scope: "non_appendix", kinds: [repo_identifier, rule_id, search_phrase, source_tag, doc_coordinate, placeholder_heading, ai_heading] }`。

**目标形态**：

1. `table_columns` 增补 spec 模板的工具面列：「权威模块」「代码现状」（依据是 spec 模板的列约定——§0 术语映射表的权威模块列、§9 各表的代码现状列是给门禁与编码看的登记项，不是给评审读者的事实；列名变了改这行数据，机制不动）。增补后这两列的内容不再成为守恒对象，模型不再有把类名与取证语句写进产物的落点义务；
2. `language_redline.kinds` 数据结构升级为「字符串（默认作用域 = 附录之外）或对象 `{kind, scope}`」：`search_phrase`（检索措辞）改 `{"kind":"search_phrase","scope":"all"}`——取证语言在附录同样不该有；新增 `{"kind":"harness_artifact","scope":"all"}`（装置词类：测试装置与流程机构的词表放合同数据，词表内容执行者从差距清单 A19/B3/B12/A6 的**类别**归纳成中性词表，不含业务词）；`lint-rules.mjs scanLanguageRedline` 按 per-kind scope 判。

**自验**：① 用金样同轮材料重枚举：权威模块列与代码现状列的单元格不再产出 token（单测）；② 金样零 FAIL 不变；③ 附录含检索措辞 / 装置词的副本 → ⑩ 报（正反夹具）；④ 第二 Case 材料（业务域不同）同判据通过——防过拟合。

### D3 · 取舍进内容源——决策件成为第六类材料

**现状**：`story-chapters.json.sources` 五份（PRD/SE/SPEC/DESIGN/UPSTREAM）；`AR/story-src/decisions.json` 是分配作业书列出的输入但**不在枚举内**——它的内容没有落点义务，取舍理由不会被守恒链要求出现（差距 A8/B5 的结构性根源）。

**目标形态**：`sources` 增加决策件（`DECISIONS: AR/story-src/decisions.json`，枚举器为 json 决策件实现专用切分：每条决策一个单元，kind = `decision`，正文 = 结论 + 理由 + 影响，`status: settled` 与 open 都枚举——settled 的落点在业务方案的取舍位置，open 的落点是「不进正文」（machine_facing 或专有态，由执行者按三态语义定，口径：open 议题不得在 story 出现为结论）。作业书分配段同步一句：决策单元的落点即取舍表。

**自验**：① 单测：含 2 条 settled + 1 条 open 的决策件枚举出 3 个单元、open 的不要求正文落点；② 副本删掉取舍表 → audit 报 settled 决策单元无落点；③ 金样锚不受影响（金样轮的决策件 4 条 settled，金样 4.4 取舍表可承载——用金样同轮材料跑通）。

### D4 · 成文流程补「统稿」一步——重复与样式的收口人

**现状**：`phases/spec.md` §二流程 ①init → ②分配 → ③逐章渲染 → ④裁决 → ⑤登记 → ⑥harness；`phases/story-write.md` 十三条最后一条有「再次核对全部事实」，但没有可操作的统稿步骤——逐章各写各的，没有任何一步通读全篇（差距 A9/A12/B8/R 系列的结构性根源）。

**目标形态**：③ 与 ④ 之间插入「**③b 统稿**」，`story-write.md` 增补对应作业段（中性自查清单，全篇通读一遍逐项过）：

1. 同一件事在全篇出现几处？多于一处的，留在最该讲它的位置，其余删除或改写成一句承接（表 / 文 / 图是三种形态不是三次机会）；
2. 有没有两句逐字或近乎逐字相同的话？
3. 每张表前有一句引导吗？同列头的表连排各自说明差别了吗？
4. 每张图有正文承接吗？图在它内容所属的章吗？
5. 样式约定过一遍：图题一种样式、单元格短项、小节命名与颗粒度、编号体系完整；
6. 读者视角扫一遍：有没有写给流程或门禁看的话（登记、回写、守恒、按类别可回查这类句子）？有没有给实现者的指令混进来？

统稿改动后重跑一次 `audit` 与 `check`（既有能力，无新机制）。**不加相似度判据、不加重复率指标**——多形态重复只有通读的人能判，机器只守既有的 `duplicate_paragraph` 与跨章同引文两条。

**自验**：① `phases/spec.md` 流程含 ③b 且 `story_flow.py next_step` 文案同步；② 作业书统稿段无业务字面；③ 注入体积仍在既有口径内（`--phase extensions` 过）。

### D5 · 逐章维度补一维 + 裁决面遗留一并收口

**现状**：合同 `verdicts.chapter_dimensions` 六维已含取舍与表达贴合；缺「重复」维。F 修复轮遗留：抽样人核判裁决面无效后按用户裁定「跑完即停」，KG-5 删事实对抗未跑。

**目标形态**：`chapter_dimensions` 增一维（中性措辞）：「同一件事只在一处完整表述——本章内容与其他章无成段重复，也没有同一事实的表、文、图三种形态各讲一遍」。裁决面修复延续 F 修复 D5 的既定路径：`story-verify.md` 逐单元任务的良定性不动，本轮收口时**抽样人核（10 行、种子入报告）与删事实对抗（每 Case 删 5 须 ≥5 未讲清）都必须跑出数**——两道一起过，裁决面才算恢复有效。

**自验**：单测核合同维度数；收口两道对抗数字进 03-交付报告。
