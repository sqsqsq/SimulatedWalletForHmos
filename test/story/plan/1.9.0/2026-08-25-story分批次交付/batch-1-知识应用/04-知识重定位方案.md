第二个结构问题：**三类知识的组织不对称**。规约有目录 + README + 内容单元（条目表：固定列、编号）；
模式有目录 + README + 内容单元（角色、上篇/下篇）；facts 是根目录下两个散文件，无 README，**无内容单元**——
没有单元，改写时就在段落和表格之间漂。

第三个问题：**两个 README 里混装了维护信息**（`constraints/README.md` :8,17-18,54-57,72-74,97-98；
`design-patterns/README.md` :12-13,77-79；`component-profile.md` :12）——「新增域改这张表并在 manifest 加一行」
「修订走评审」「第二份真源迟早对不上」。README 在激活清单里，这些话被原样送进了被测模型的 prompt。
知识是给模型消费用于实现需求的，不承载维护信息。

## 一、三类知识的定位（本轮唯一真源，落 `knowledge/README.md`）

**尺度（用户裁定）**：知识只给关键信息或规则。日志接口怎么用——给类名就行，模型知道怎么用。
这条尺度适用于三类知识和所有索引文件。

根 README 给模型的全部内容（≤15 行）：

```
# 知识
三类，各在一个目录：
- 规约 constraints/：必须做或禁止做的事。逐条判命中；命中即义务，落实并验证。
- 项目知识 facts/：这个仓的惯例与已有能力。直接复用，不自己造；与规约冲突时以规约为准。
- 设计模式 design-patterns/：复杂实现的写法。spec 只登记候选，plan 决定用不用；允许一个都不用。
需要具体封装看 facts；需要时机与要求看 constraints；需要代码结构看 design-patterns。
```

**给维护者的写法判据（进 AGENTS.md §2.2，不进知识）**：

| 类 | 写 | 不写 |
|---|---|---|
| 规约 | 要求、命中条件、判定边界、平台隐性例外 | 类名/路径/API、消费方落点坐标、论证 |
| facts | 真实路径、类名、API 名、封装形态一句、「无（已核对）」+ 零命中检索项（1.0 形态） | 调用点、字段逐项、内部实现、时机、理由、维护规则 |
| 模式 | 适用/不适用、角色、骨架、约定、验证清单 | 目标工程是否采用（那是 facts 的事） |

判据一句话：**模型认识这个名字就知道怎么用的，只给名字。**

## 二、目录组织（三类对称）

```
knowledge/
  README.md                       kind: index    ← 第一节那 ≤15 行
  facts/
    README.md                     kind: index    ← 面表三列含义、「无」的含义。≤10 行
    component-profile.md          kind: facts    ← 部件是谁（原位移入，内容只删 :12 维护句）
    codebase-facts.md             kind: facts    ← 仓里怎么做（按第三节重写）
  constraints/
    README.md                     kind: index    ← 只留读法：列语义、强制力含义、执行体、空缺登记、域清单
    *.md                          kind: constraints
  design-patterns/
    README.md                     kind: index    ← 只留读法：粒度、路由表、组合合同、模式清单、文档结构
    *.md                          kind: patterns   ← 正文不动（B1-5 冻结为原件逐字节）
```

**子 README 的分工规则**：只写「本类怎么读」（列是什么意思、表怎么查）和「本类有哪些」（清单）；
**不写定位**（是什么、为什么这样分）、**不写维护**（怎么新增、改哪几处、走什么评审）。

`manifest.yaml > provides.knowledge` 同步：两个 facts 文件改路径，新增 `knowledge/README.md`、`knowledge/facts/README.md`。
`kind: index` 已被 `knowledge.mjs` 支持；目录移动本身不需要改机制（路径全部来自清单）。

## 五、知识如何被 extension/story 应用（应用链一处成文 + 消费侧只引用）

### 5.1 应用链（写进 `04-知识重定位方案.md` 作设计说明；模型侧见根 README 的生命周期行与各阶段 hook）

manifest.provides.knowledge（确定性激活；kind 随文件）
  │
