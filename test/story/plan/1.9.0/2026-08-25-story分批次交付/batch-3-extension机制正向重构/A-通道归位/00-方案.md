## 1. 现在为什么不行（实测，不是推断）

扩展想让主 agent 做的每件事，现在都写在 `hooks/<phase>/on_context_load.md` 里。但这些文件**只进 `ai-prompt.md`、只给 verifier 看**（`harness-runner.ts:765-768` 四个 hook 事件连排在 verifier 前，片段唯一去处是 `report-generator.ts:311-318` 的 ai-prompt 尾部）。写产物的那个 agent 从头到尾读不到。

证据摆在文件里：`hooks/spec/on_context_load.md` 98 行，通篇是「spec 是什么（写作前必须理解）」「§10 怎么写」「写每一行前的三个自问」「不写文档坐标」——**全是作者向**，却只送给了审查者。六份合计 400 行，加 `story_on_context_load.md/.mjs` 183 行，共 **583 行送错对象**。

后果是内网实跑的三段式结论：spec 生效（`/story` 链恰好有一句指路）、plan 仅展示、coding 完全失效。作者只能靠门禁报错反推要求——这就是「回环占全程 49.3%」的来源。

同时暴露的三个附带缺陷：

| 缺陷 | 实测 |
|---|---|
| 通过与没跑同形 | 六个 post_check 只有 `spec`、`plan` import `evidence.mjs`；`doc/features/AR90004/coding/reports/` 里**没有** `ext-post-check.json` |
| verifier 注入超载 | `pre_verifier.mjs` 注入知识判定**全集**（251 行脚本），spec 阶段扩展占 prompt 44.3% |
| overlay 判据发散 | `spec-rules.overlay.yaml` **7 条** semantic_checks（124 行），plan 3 条，其余各 1 条 |

### 与 03 §3 的三处偏差（登记，不静默）

**偏差三 · `SKILL.md` 不从 0 重写。** 判据③ 的前提是「承载**被替换的**机制」。01 §9 给
`SKILL.md` 写的替代物是「`phases/{spec,story-write}.md` ← `SKILL.md` 中的**写作/命令段**」，
但基线 `e96e90fc` 上这个文件里**没有写作段**——写作指令一直在 `hooks/spec/story_on_context_load.md`
（本子批已删，内容进了 `phases/spec.md`）；剩下的命令段是 `/story` 自己的
（`story.js` / `story_flow.py`），`phases/` 替代不了它们。它承载的机制是 `/story` 流程编排，
**01 设计没有替换这个机制**，只让它「压到链条 + 关卡语义 + 产物定位」并加一句指路。

处置：本子批只加那句指路（已做）；`SKILL.md` 从判据③ 移交子批 C——那时 S5 挂点会真正重组链条章，
重写才有替代对象。

**判据③ 清单的整体复核**：13 项里 10 项在 01 §9 有明确替代物（story-build / merge-story /
三个 post_check / pre_verifier / adjudication / freeze / downstream / story-chapters.json /
六份 on_context_load / story_on_context_load），**3 项没有**——`SKILL.md`、`rules.md`、
`evidence-rules.md`。三项的共同来源是把「文件大、文本旧」当成了「承载被替换的机制」。

## 7. 风险与已知偏差

1. **`spec/post_check.mjs` 的 story-flow 三级关卡校验近 400 行**（`storyFlowProblems`，`:490-887`）。它是 `/story` 收口的唯一门禁，重写时必须保留全部判据能力，否则关卡形同虚设。重写前先把它现有的判据逐条列成清单，重写后逐条对照——这是本子批最大的风险点。
2. **`author.md` 60 行装不下现有 98 行的 spec 作者向内容**。分流原则：**结构判据进模板的 HTML 注释**（`spec-sections.md` 各节顶部），**门禁会拦的进 author.md 第四段**（一句一条），**语义裁决进 overlay**。分流后 author.md 只做索引，不做教材。
3. `constraint-usage.md` 被 `skills/story/reference/` 内其它文件引用时须同步改指向 `hooks/spec/author.md`——删除前先 grep 全域引用。
