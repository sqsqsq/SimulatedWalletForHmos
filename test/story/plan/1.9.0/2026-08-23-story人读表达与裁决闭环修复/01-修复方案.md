## 0. 本轮四条纪律(用户 2026-08-23 追加诉求,贯穿全部修复项)

1. **重写优先,不打补丁**:专项检查判为结构不合理的构件(4a-4d 兜底族、消费矩阵、落法附注制度),重写该构件本身,不在其上叠判据、加行、修字。
2. **零过拟合**:机制层与注入件不得含测试需求特征——示例一律用中性题材,约定形态(编号、单号前缀)一律声明为**数据**而非固化进代码。
3. **知识不进机制**:域清单、编号前缀、域专属动作只在 knowledge 内维护;机制层按规则消费(manifest 派生、形态解析),新增/改名一份知识**不改一行机制代码**。
4. **知识描述规则与特征,不穷举实现**:落法附注只写平台隐性例外、边界与决策理由;封装/类名/路径指向 codebase-facts(设计模式的代码结构除外)。

以上四条在 §D 固化为**每轮提交前的机械扫描断言**,不靠自觉。

## A. 机制修复(doc/extensions,8 项)

### ①【最高优先级】裁决机械闭环:`hooks/shared/post_verifier.mjs`(新)

**目标契约**:注册六阶段 `post_verifier` 事件。读本阶段扩展 overlay 的 semantic_checks id 清单(复用 pre_verifier 的解析),再读本次 verifier 产物(ctx 提供的报告路径;拿不到路径时按 feature 的 reports 目录内最新 verifier 产物定位),校验**每个 id 在产物文本中出现且带有 PASS/FAIL/SKIP 字样的裁决**。任一缺失 → `ok:false, severityOverride:'BLOCKER'`,message 列出缺了哪几条并写明「verifier 未执行扩展判据,裁决无效,须重跑 verifier」。产物完全找不到时同样 FAIL(宁可误拦,不可漏放——本判据防的就是静默漏裁)。
**验证**:冒烟——伪造一份缺 3 条 id 的报告须 FAIL 并点名 3 条;完整报告 PASS;AR90006 现有产物输入应 FAIL(0/8)。

### ②【高】写作指引层重写:注入件按"给模型的方案文件"标准

**落点**:`hooks/spec/story_on_context_load.md`(表 B/C/D 整体重写)+ `story-build.mjs` 的 `WRITING_CRITERION`(同源修订)+ `skills/story/rules/rules.md`(对应红线同步)。

**目标契约(内容要求,五件套缺一不可)**:

1. **形式选择表补全**(回收被否档案中验证过的表述,palette 十形态):

   | 内容形态 | 用什么 | 反例(一句) |
   |---|---|---|
   | 连续因果、判断与理由 | 正文段落 | 写成表格会把"为什么"切碎 |
   | 有真实先后顺序的步骤 | **有序列表** | 写成长段读者要自己数步骤 |
   | 并列相关项(≥3 且无需逐列对比) | 无序列表 | 塞进一句话用顿号连 5 项 |
   | 多项且需逐列比对(职责/字段/验收) | 表格 | 能用列表说清的别建表 |
   | 有分支的过程、状态迁移 | **流程图(mermaid)** | 压成「A → B → C」箭头文字即信息降级 |
   | 界面外观与布局 | 图片引用 + 文字转写 | 只引图不转写,归档断链后信息丢失 |
   | 待办/勾选状态 | 任务列表 | 用在非待办内容上是装饰 |
   | 术语、原文约束的引用 | 引用块 | — |
   | 命令、键名、代码形态标识 | 行内代码 | — |
   | 改变句子含义的关键限定 | **加粗** | 通段加粗等于没加粗 |

2. **段落纪律**:一段只讲一件事;段落超过约 5 行(≈150-200 字)就拆;句子超过约 25 词/40 字拆句;每章开头一两句说明本章要讲什么;刻意变化句长——连续多段等长句是机器节律。
3. **AI 味负面清单**:禁止模板句跨章复用(同一句式一篇内至多出现一次);禁止无据判断词(「显然」「毫无疑问」「至关重要」);禁止空过渡(「综上所述」「值得注意的是」);判断必须跟着理由或代价。
4. **内置范例**(调研结论:范例 > 抽象指令):给一个 6-10 行的「好的章节片段」——含一段先说结论的正文 + 一个有序列表 + 一处加粗限定;并列一个「同内容的坏写法」(一整段 200 字长句流)。范例用与业务无关的中性题材(如"图书馆预约"),避免被当事实抄。
5. **厚度基准**:明示「story 是 spec 的超集叙事:spec 有的事实之外,story 还要有 PRD 的业务语境、SE 的方案理由与你的判断。**成文后正文明显薄于 spec,通常说明语境与判断层没写够**——统稿时自查」。

**结构要求**:重写后的表 B/C/D 总长受控(注入件不因求全变成第二篇论文):形式选择用一张表,纪律与负面清单各一组短列表,范例一处。删除现版分散重复的表述。

### ③【高】流程图空档三补(不恢复数量配额——冻结需求2 C2 红线)
