## 六、这一轮踩过的坑

| 坑 | 教训 |
|---|---|
| 拿「与上游的 diff」当我们的改动清单 | 里面混着**上游新增的功能**（`--report-reconcile-only`、Native evidence gate）。要以我们自己那两笔提交为准 |
| `git checkout main -- framework/` 以为就干净了 | 它**不删** story 独有的新增文件（`author-context.ts` 等三个），要手工删 |
| 断言「codex 的 verifier 机制有问题」 | 错的。framework 对无能力声明的 adapter 判 `blocked` 并如实报 `verifier_provider_unavailable`，那是设计内的三态，不是故障 |
| 以为「没有发布器就认执行方自写的报告」 | framework 从不认这条路。扩展原来那四种自写文件名一直是**扩展自己造的旁路** |
| 只在候选版上验补丁 | main 实际升到的是更新的 `85e266f`，结论会变（opencode 那份就打不上了）。**要在真正的目标树上验** |
| heredoc 里写 `\n` 之类的转义 | 反复被 shell 吃掉。改用 Write 工具写脚本文件再执行 |
| 跑 `adapt-scan --scan` 后忘了清 `.adapt-<版本>/` | 它是 `.json`，会被预算统计算进 `data`（曾让 data 从 745 跳到 1701）。跑完 `rm -rf` |
