## 五、跑 CLI 的完整操作

### 5.1 硬条件（评审定的，不满足就停）

> verifier 证据 JSON 必须**由插件发布**——`agent_id` 不是 stub、`state: published` 来自
> `record-verifier-report.js`。首个 verifier 完成事件后插件未触发，**当场停，不修不重试**，
> 写总结回开步骤 1。

起跑后第一次 verifier 跑完就去查：

```bash
ls output/story/<suite-id>/cases/auto-topup/<run-id>/artifact/spec/reports/
python -c "import json,glob;print([json.load(open(f,encoding='utf-8')).get('agent_id') for f in glob.glob('output/story/<suite-id>/**/verifier.report.*.json',recursive=True)])"
```

### 5.2 命令

```bash
# 1. 只读确认（Case、feature、终点、交互规划、cli 配置顺序）
python test/story/scripts/run_multi_case.py plan auto-topup --jobs 1

# 2. 起跑（suite-id 自取，形如 story-suite-<YYYYmmdd-HHMMSS>）
python test/story/scripts/run_multi_case.py start auto-topup --jobs 1 \
  --suite-id <suite-id> --authorize-non-sandbox

# 3. 循环 poll（15 秒一次），要回话时以需求方身份回
python test/story/scripts/run_multi_case.py poll --suite-id <suite-id> --wait-sec 0
python test/story/scripts/run_multi_case.py reply --suite-id <suite-id> --case auto-topup \
  --text "<需求方的话>" --reply-mode adaptive --reply-kind planned --step <规划条目 id> \
  [--deliver 交通卡自动充值.docx]

# 4. 终态后回灌
python test/story/scripts/run_multi_case.py finalize --suite-id <suite-id> --promote
```

代跑 heartbeat 的循环脚本可参考上一轮的写法：每 15 秒 poll 一次，
出现 `adaptive_reply_requests`、终态、`stalled` 或 `last_error` 就退出叫人；
顺带把 `raw.jsonl` 里模型的说话与工具调用写进日志——只看 `status=running` 看不出它在干什么。
