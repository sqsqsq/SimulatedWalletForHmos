## 来源与假设

用户提供：五步开卡流程；事件身份由模板/流程/步骤组成；结果由内码、外码、分类等字段表示；十位内码五段语义，BankCard_001_001 与 1001010101 的解释例子。

候选假设：为展示多流程增加独立的结果查询；子点拆分、重试/待确认边界、其他 Chart 编号均是本例拟定，尚未由真实业务材料确认。已撤下自行补充的运营诉求、查询补记开卡终态、本地同步和跨流程联合指标。它们不自动扩展 1.9.5 Case 或成为通用知识硬规则。

按用户明确的目标项目约束：页面/点击等已有自动运维上报，本例复用其覆盖；没有明确独立运营需求，不新增 BI。后续明确需求的运营与运维共用语义相同的事件常量，参数按项目协议使用。已删除自行拟定的 BI 事件名和默认运营点表。目标项目已有自动能力来自用户确认，不宣称当前 Demo 代码已实现。

## 使用边界

多流程先给指标对应，再在同一小节内逐流程展开。开卡和查询分别说明自身结果，不为展示“多流程”而设计二者的补偿/同步关系或额外联合指标；同一流程的多个指标使用需要的原始事实。查询成功与开卡成功分别定义。

Spec 9.4 的丰富表达是用户期望效果；当前生产约束仍有短表/表外文字限制，Story 投影也需相应承接。本文不声称这些机制已经实现，后续按设计裁定改模板、检查与投影。参考位置与实现动作见本轮设计《06-埋点单处承载裁定》。
