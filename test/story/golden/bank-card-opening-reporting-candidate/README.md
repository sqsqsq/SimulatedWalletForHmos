## 来源与假设

- **用户提供**：五步开卡流程；事件身份由模板 / 流程 / 步骤组成；结果由内码、外码、分类表示；十位内码五段语义，以及 `BankCard_001_001` 与 `1001010101` 的解释例子。
- **样稿拟定**：
  - 为展示多流程增加的结果查询；
  - 子点拆分、重试与待确认的边界；
  - 查询流程号 `002` 与其余编号；
  - Plan 里的责任方法名。

  这些用于展示形状，未经真实业务材料确认；实施时，责任方法以 `contracts.yaml` 声明的方法为准，编码以目标仓登记为准。
- **目标项目约束**（用户确认）：页面、点击已有自动运维上报，复用其覆盖；没有明确的独立运营需求，不新增运营事件。不宣称当前 Demo 代码已实现这些能力。

## 使用边界

- 开卡与查询各自定义成功：查询成功与开卡成功分开，两者不设补偿、同步或联合指标。
- 一个指标一个子节，标题写指标名；失败原因是成功率事件的字段，写在定义段的「每次上报带」。
- 这些形状不自动扩展 1.9.5 的 Case，也不成为通用知识的硬规则。
