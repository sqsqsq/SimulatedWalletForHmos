# AR90001 甲需求

## 背景

用户在闸机前才发现余额不足，这时候只能当场掏出手机充值，而闸机前的信号往往不好，充值页面要转很久才打得开，后面排队的人越来越多，用户的压力也就越来越大，这个场景是当前投诉量最高的一个，产品希望把它彻底解决掉，办法是让用户提前签约一次，之后由系统在余额低于门限时自动完成充值，把「想起来充值」这件事从用户身上移走，用户不必再在闸机前手忙脚乱，也不必在每次刷卡之前先打开钱包确认一遍余额还够不够，而这件事之所以一直没被解决，是因为触发时机很难判断：端侧看到的余额在离线刷卡之后会失真，按它去扣款会扣出用户预期之外的钱，所以判定必须放在云侧，等余额上报之后由云侧决定要不要触发，端侧只负责签约入口、状态展示和记录查询这三件事，既不判断该不该扣款，也不保存任何支付凭据，这样一来责任边界是清楚的，出了问题也知道该找谁查。
