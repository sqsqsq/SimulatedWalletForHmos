# 交易凭证下载简报（RCPT-1001）

## 现状与问题

用户完成一笔交易后常常需要留存凭据：报销要交给财务，纠纷时要提供给客服，个人记账也需要
一份可以离线查看的记录。目前他只能在交易详情页截图——截图既没有完整的交易要素，
又带着与凭据无关的界面元素，财务经常要求重新提供。受影响的是所有需要留存交易记录的个人用户，
业务上表现为客服重复答复「请提供正式凭据」，而钱包侧一直给不出。

本需求要让用户在交易详情页直接得到一份规整的凭证文件。做成的标志是：完成态交易能拿到凭证，
且凭证与详情页所列的交易要素一致。

## 要求

用户要在无网络或不愿额外上传交易信息时，从交易详情保存已经完成的交易凭证。只有 `COMPLETED`
交易展示入口，`PENDING` 和 `FAILED` 不展示——它们的结果还可能变化，定格出来的凭证会与
后来的事实矛盾。用户选择 `PDF` 或 `PNG`，并通过 `maskCounterparty` 决定是否隐藏对方账号；
隐藏生效时只保留账号首尾，中间以掩码代替；不隐藏时凭证上的账号与详情页所见一致——
凭证不扩大用户当前已经看得到的信息范围。

端侧渲染采用固定版式与内置字体，避免设备差异影响排版。

凭证的内容真源是详情页当前展示的那份交易要素——页面进入时由
`GET /wallet/transactions/{transactionId}` 取得，生成凭证时**不再额外请求**，在端侧渲染，
不采用服务端生成。因此详情页已经打开的情况下，无网络也能生成凭证。
交易要素由交易域提供，钱包侧不重新计算金额与手续费，也不另存一份。
详情页要素尚未加载完成时不展示凭证入口。
任务状态为 `IDLE → RENDERING → READY`，失败进入 `ERROR`，离开页面进入 `CANCELLED`。失败和取消都删除
`wallet_receipt_temp`，不显示分享入口；成功文件分享完成或离开后删除。渲染期间可以取消。
渲染失败时页面提示可以重试，用户可以重新发起或换一种格式；失败分类只进埋点，不展示给用户。

记录 `receipt_render_start`、`receipt_render_success`、`receipt_render_fail`，只带不可逆交易摘要、格式和失败分类；
上报失败不影响业务结果。不新增远程开关，沿用详情页兼容范围和中英文资源。

产品另附一张凭证预览界面图（`assets/receipt-preview.png`），图上给出凭证的三段版式——
页眉的交易结果与时间、中部的要素清单、页脚的凭据编号与生成时间，以及隐藏对方账号时
掩码在版式中的位置。版式细节以图为准，正文不逐项复述。

本次不做凭证的云端归档，也不做批量导出。渲染依赖端侧已有的文件写入与分享能力，不新增系统权限——
这些能力都是现成的，没有阻塞本需求的外部依赖，也不需要与其它特性对齐排期。
界面文案沿用详情页现有资源，没有面向用户的资料或帮助文档要交付。
出现问题时隐藏详情页入口即可回退。常见要素规模下渲染应在数秒内完成——这一条是工程设定，
不是上游约束。

## 验收意图

- `RECEIPT-001`：完成交易可选择 PDF 或 PNG，凭证与详情一致。
- `RECEIPT-002`：隐藏选项生效，不泄露完整账号。
- `RECEIPT-003`：非完成交易无入口，失败或离开不留下文件和分享动作。
