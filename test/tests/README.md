# test/tests 编写纪律

默认并行跑，入口是 `test/scripts/verify.py`（[../TEST.md §5](../TEST.md)）。测试彼此隔离是本域的既有约束，不是并行带来的新要求：并行只是让违反它的地方
立刻现形（写到共享路径的那条会当场撞车，串行下它一直是绿的）。

- **每条测试只写自己的临时目录**。落到 `%TEMP%` 下固定名字的路径不算「自己的」，几个 worker 会撞同一条；要带上进程号或用
  `TemporaryDirectory`。
- **重夹具一个类建一次**（`setUpClass`）。工作区模板这类要复制整棵工程树的夹具，一条用例建一次就够整轮跑的时间翻倍。`verify.py` 固定带
  `--dist loadscope`：同一个类的用例落到同一个 worker，那份夹具才真的只建一次（默认的 `load` 按用例散开，拿到该类用例的每个 worker
  都会各建一份）。
- **慢的要报出来**：`verify.py full` 带 `--durations 10` 报最慢十条；单条超过 5 秒，要么让它快，要么在测试文档字符串里写明它为什么必须慢。
- `-p no:randomly` 与 `-n auto` 不冲突；要固定顺序就两个都写，不要为让输出好读而连带丢掉并行。

## 用时预算

全量通道的原2分钟及类45秒预算是定位信号；完整必需handback目标为 **120—180秒**，以[TEST §5](../TEST.md#5-离线验证)为准，均不作为功能标准或开发测试阻断。整轮用时由两件事定：总工作量除以整机吞吐，与最慢的那个类
（loadscope 把一个类整个交给一个 worker）。`conftest.py` 每轮按类汇总用时与子进程数，末尾点名超过类预算（45 秒）的类与超过
2 分钟的整轮；点名后先按真实职责与成本判断，不要求每次同一改动强行提速（要全部类的用时，设 `STORY_TEST_TIMING_JSON=<文件>` 跑一轮，按用时排序写出每个类的用时、条数与子进程数）：

- **重状态整轮只造一次**：要走真实流程造的状态（准入蓝图、登记好的 Story）用 `shared_state.shared_tree`，键是输入内容的摘要，
  各进程与之后各轮共用；只在一个类里用的，至少 `setUpClass` 造一次、每条用例复制。共享只到**被测动作之前**：
  设计已准入用 `designed_fixture.designed_copy`，被测动作在起骨架之后的用 `designed_fixture.skeleton_copy`（真实 skeleton 跑一次、交回那次结果；
  `skeleton=False` 停在走完流程）；造前态时会写时刻的导入也放进共享前态里，否则按内容取的键每例都不同、永远不命中。
- **不为每条用例重复起进程**：同一输入的派生结果（激活知识、原生读取）按内容缓存；能在进程内调的不另起 node 或 Python。
- **复制工程跳过 Framework 链接**：临时工程的 `framework/` 是指向被测 Framework 的 junction，`shutil.copytree` 会顺着它把整个 Framework
  连依赖复制一遍（几千个文件）；复制工程根一律用 `shared_state.copy_tree`，复制后 `link_framework` 重接。
- **按职责减重复**：先分局部规则与真实组合链，复用同输入前态、各用例私有写入；不能仅拆类把重复准备分散到更多worker。报告身份与更新恢复的被测步骤仍真实执行，不跨根缓存已派审/登记态。
- **产品命令本身慢的改产品**：命令为一件小事去算整条下一步、嵌套再起一层进程的，改成只问要问的那一件——模型实际使用同样在付这份开销。
