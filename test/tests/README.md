# test/tests 编写纪律

默认并行跑，命令见 [../TEST.md §5](../TEST.md)。测试彼此隔离是本域的既有约束，不是并行带来的新要求：并行只是让违反它的地方
立刻现形（写到共享路径的那条会当场撞车，串行下它一直是绿的）。

- **每条测试只写自己的临时目录**。落到 `%TEMP%` 下固定名字的路径不算「自己的」，几个 worker 会撞同一条；要带上进程号或用
  `TemporaryDirectory`。
- **重夹具一个类建一次**（`setUpClass`）。工作区模板这类要复制整棵工程树的夹具，一条用例建一次就够整轮跑的时间翻倍。并行时加
  `--dist loadscope`：同一个类的用例落到同一个 worker，那份夹具才真的只建一次（默认的 `load` 按用例散开，拿到该类用例的每个 worker
  都会各建一份）。
- **慢的要报出来**：`--durations 10` 看最慢十条；单条超过 5 秒，要么让它快，要么在测试文档字符串里写明它为什么必须慢。
- `-p no:randomly` 与 `-n auto` 不冲突；要固定顺序就两个都写，不要为让输出好读而连带丢掉并行。

## 用时预算

全量（`-n auto --dist loadscope`）目标 **2 分钟以内**。整轮用时由两件事定：总工作量除以整机吞吐，与最慢的那个类
（loadscope 把一个类整个交给一个 worker）。`conftest.py` 每轮按类汇总用时与子进程数，末尾点名超过类预算（45 秒）的类与超过
2 分钟的整轮；点名的在同一次改动里处置：

- **重状态整轮只造一次**：要走真实流程造的状态（准入蓝图、登记好的 Story）用 `shared_state.shared_tree`，键是输入内容的摘要，
  各进程与之后各轮共用；只在一个类里用的，至少 `setUpClass` 造一次、每条用例复制。
- **不为每条用例重复起进程**：同一输入的派生结果（激活知识、原生读取）按内容缓存；能在进程内调的不另起 node 或 Python。
- **大类拆小**：用例彼此独立、却都挤在一个类里的，按主题拆成几个类（共用的 setUp 放父类），让 loadscope 分散开。
- **产品命令本身慢的改产品**：命令为一件小事去算整条下一步、嵌套再起一层进程的，改成只问要问的那一件——模型实际使用同样在付这份开销。
