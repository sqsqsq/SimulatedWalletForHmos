# 完整交付初建与设计修订子契约（沿用既有路径）

原目标内设计/CU与必要架构修订按共同授权策略由 runtime 交设计 owner 草稿、独立质询、检查、发布和重绑；detached 保留既有完整交付授权，attended 由主 Agent 从可信原全权授权在每次控制调用重传 --authorize-autonomy。未授权会话沿原确认；默认 never/goal_mode、日志或 Agent 自写记录不授设计权。plan/coding 不就地自授，改变原目标/实质验收、真实秘密/不可逆外部动作、用户总上限或明确禁止仍按实际授权处理。

尚无 canonical CU 的正式完整请求先以既有 Goal manifest 的 `initial_design` 输入变体受管；路径键定位本次蓝图工作区，不伪造 Feature 施工范围、阶段 PASS 或产品完成。初建与修订共用调用、写前快照、报告、质询、原检查和发布接缝，只在真实基线/revision 差异处分支。初建作者仅写本次签发指令允许的需求物化、蓝图草稿、候选与设计报告；修订已有 admitted 设计仍走正式候选/发布/重绑，不能以初建覆盖旧权威。

## 编写者

- 读取原始请求、有效人工裁决、修复简报及已有工程事实；必要时只读调研补证据。
- 修订已有 admitted 设计时，只修改本次报告区提供的 component-blueprint.yaml、change-unit.yaml 和 architecture.json 候选，不直接覆盖 canonical 设计/DSL/需求。初建按本次 instruction 指定的草稿、来源物化与候选路径执行；两者都不得写产品源码、测试、个人配置或运行记录。
- 可以在原需求内补节点、关系、选型和 architecture_impact 决定，不能删除明示需求、降低实质验收、伪造已获人签或扩大明确禁止的范围。
- 架构变化仍按已有六类记录。先换合法候选，再考虑组件下沉，最后才增加依赖边/调整模块。模块迁移或退役不授权丢失用户数据。
- 不手算 revision、来源/决定指纹或 CU 引用身份；不写 review_summary.admission，不填写自己的质询结果。
- 施工映射由权威投影生成；已有决定能唯一派生时不重复手填，存在实质冲突时由设计责任方统一决定。

## 独立质询

只写本次指定蓝图草稿/候选的 review_summary.questioning。按 P1 的先正文八问、后核原请求/来源/YAML顺序读取本轮实际材料，核验未超范围、未降验收、架构配置与决定相符、依赖和写集闭合。必须由真实独立上下文/provider 执行；不同 role/provider 名本身不证明独立，缺必需能力须如实报告。真实否决保留，不沿用旧报告，不以无人值守作豁免。

## 框架发布与恢复

框架在既有锁与写入核对下签发新 revision、重算派生准入，校验候选目标 DSL 与完整设计。CU 内容走原 consumer，架构配置走原 init writer，原始运行记录和历史证据不原地改写。

发布后必须重新绑定并通过原门才算恢复。当前绑定有效就继续本 run；实际失效由原接续入口自动承接后继，累计消耗不清零。编写与质询均计入原预算，重复无进展按既有规则停止；不同有效输入不能因检查编号相同就永远不再尝试。

初稿缺失、格式/schema/来源或设计缺口在原职责内可修时，把原检查定位、当前原件与复验命令交回作者；缺独立质询时直接派原独立责任方，不让作者自签，也不先要求含质询的总检查通过。作者 exit 0 或报告 passed 只证明本次调用事实，不替代准入、CU readiness 或产品完成。报告已接受后中断先消费已有结果和必要机器检查，不无条件重做设计。

初建作者必须实际交出签发路径的 `component-blueprint.yaml`；发现笔记只是中间材料。每次续作先读已有材料、前次同职责真实正文与当前全部机器问题和独立质询否定，补齐本职产物，不重复冷探索。admission 整块（含 current_slice 和编号）由机器维护，新请求在作者动笔前提供技术编号，作者仅在业务 gap.needed_by 引用；已有编号保持，旧有 gap 缺编号时机器分配标签但不改原 needed_by/status，作废旧质询并重新独立核实归属；歧义或真实 blocker 交作者修业务 gap，不猜当前/远期。

初建与设计修订不再以局部 max_retries_per_phase 次数终止；只守原请求总预算和既有无进展规则。同一组当前问题且实际候选可比内容确无变化时，沿 no_progress_guard 暂停；只改机器元数据不算业务进展，读失败或无基线不冒称无变化。暂停后时间经过不自动重拉；用户沿既有 force-takeover/force-resume 明确继续，或真实条件变化再沿公开 next/resume 接回，累计 turns 与活动时间保留。机械缺口由机器修复，不要求人为起后继；更正原请求仍保留原审计后继、存活执行者、未报告请求、真实授权及总预算边界。

准入后由既有 CU consumer 与 P2 推进正常 CU run；child 的不可变 `delivery_origin` 只定位原请求，不授予权限。原需求/来源、adapter、模型与视觉钉、fidelity、超时及其它原限制从原请求继承；当前有效总预算只认原请求的合法值，设计、质询、返修、各 CU 和后继累计，真实活动区间合并后计墙钟，不嵌套双计或换 run 清零。child 正式结束后回原请求重读 P2，全部适用 CU 正式完成即到本批请求终点；部件闭环只按原口径只读检查一次并披露，不自动派修或改变结论。

自动决议沿已有阶段账本和 goal-report 展示，记录决定、CU和架构改动的依据；账本只留痕。展示文档失败不回滚有效设计，也不构成产品验收通过；指引沿原 renderer 定向补齐。

旧 B1 单字段入口只用于无原始任务的兼容调用；当前正式完整交付按共同原请求授权，不要求 personal opt-in。attended 未取得本次全权输入时保持原确认，先恢复已有可信授权而不重复询问。设计作者/独立质询经同一 next/report 用途交接，跨命令保留原草稿/依据，不运行普通阶段 harness，不把报告 passed 当 published。
