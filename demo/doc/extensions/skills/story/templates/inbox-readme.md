# 上游材料收件箱

需求系统里 PRD / SE 设计还没归档，或者手上有补充说明、界面设计图、澄清会议记录时，把文件放进**本目录**，
然后在对话里说一句「材料放好了」。AI 会读内容判断每份是什么、转换并接进流程；你也可以顺带说明某份是什么
（例如「这份只是补图」「这是周二澄清会的记录」），AI 以你的说明为准。

## 放什么

| 材料 | 格式 | 去向 |
|---|---|---|
| 产品需求、系统设计、本部件补充说明 | `.docx`，或 `.md` `.txt` 等文本文件 | 成为对应的上游正文；`.docx` 里的表格与图片一并保留 |
| 为了补图的原稿或参考稿 | `.docx` | 只抽出图片，正文不动 |
| 界面设计图、视觉稿、交互说明 | 图片（`.png` `.jpg` `.jpeg` `.webp` `.bmp`）或文档 | 进界面参考目录，每张图带一句说明 |
| 需求澄清会议记录 | 原始 `.docx` | 按版本存档；AI 读会后把要定的事摆给你确认，确认后的结论才进上游提取稿 |

其他格式（如 `.pdf`）AI 读得懂就自己转写后再导入，读不了会告诉你需要什么版本。

## 几条约定

- **文件名即章节标题**：转换后每份材料成为正文里的一节，标题就是文件名（不含扩展名）；
- **同类多份按文件名排序拼接**：想控制先后就加数字前缀（`1-总体.docx`、`2-补充.docx`）；
- **原文件留在这里存档**，不会被移走或删除；
- **改了重放即可**：更新文件内容后再导一次，对应内容整体重转；同名会议记录换了内容存成新版本，旧版本留着；
- 本 `README.md` 不会被当成材料。

> 文档类材料导入会**整体覆盖**对应的上游正文（人工放的材料视为权威版本）；被覆盖的旧内容
> 自动存入 `../.backups/local/`，需要时可取回。
