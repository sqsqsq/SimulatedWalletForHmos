# Maison 调查问卷 v2：设计说明

2026-11-03。状态：按已确认方案形成 v2 文档，待小范围试填；尚未发布或收集本版答卷。

本文件供组织者使用，记录调查决定、题目依据、分流及分析口径。可交给填写者的正文见 [填写者版](01-Maison调查问卷v2-填写者版.md)。本文“问卷正文”与填写者版内容保持一致；组织者说明不展示给填写者。

## 一、设计起点与交付边界

v2 从“调查结果需要支持什么决定”出发重新设计。原问卷仅作为已发现问题的记录，不作为题目底稿；不沿用原题号，也不以压缩到某个题数为目标。

本版独立保存在本目录。原 [设计稿](../00-Maison使用与改进需求调查问卷.md) 与 [填写者版](../01-Maison使用与改进需求调查问卷-填写者版.md) 保持不变。本轮只新增两份 v2 文档，不发布、不收集答卷、不提交 Git。

## 二、需要支持的决定与证据

| 要支持的决定 | 问卷需要取得的证据 | 不做的推断 |
|---|---|---|
| 优先解决推广、接入还是产品能力问题 | 接触程度、实际使用、未开始的阻碍 | 不把所有未使用者归为“不认可产品” |
| Maison 适合承担哪些工作 | 实际使用环节、使用效果、有价值或失败的例子 | 不由总体好评推出所有能力有效 |
| 应先解决哪些使用问题 | 遇到的问题、最影响的一项、造成的后果 | 不把问题勾选数量直接当优先级 |
| 应改善效率、人工投入还是结果质量 | 同一个比较对象下的三个独立评价 | 不把 AI 执行更快等同于开发者更省事 |
| 现有路线是否遗漏真实需求 | 提示列表之前的开放需求、其他方式的优势 | 不预设 lite、review 是大家最需要的方向 |
| 哪些能力应保持 | 正向效果和实际案例 | 不让路线只由抱怨驱动 |

### 设计取舍

- 不要求所有人回忆并填写一份完整任务复盘。问卷负责定位问题；具体根因和复现信息由后续调查取得。
- 使用场景、工具方式和实际问题允许多选；状态、评价及最重要的问题单选。
- 开放需求只问一次，替代方式只问一次，问题列表只展示一次。Q3 收集常用方式，Q6 的比较对象仅用于明确评价基准，不要求再次勾选工具列表。
- 身份信息仅保留可解释工程差异的平台；删除职责、任务数量和共建招募。
- 问卷平台按回答显示相应部分；Markdown 版使用分节提示，不让填写者计算多个题号条件。
- 不设固定填写分钟数。主问题为 11 个，仍有比较矩阵和条件追问，不能据此宣称已减负。

## 三、分流与展示规则

所有人先答第一部分 Q1—Q3，再按 Q2 进入相应部分，最终到第四部分 Q10—Q11。

| Q2 的接触程度 | 填写路径 | 不展示的内容 |
|---|---|---|
| 之前没听说过 | 第一部分 → 第四部分 | 使用评价、效果比较、问题列表和未用原因 |
| 了解过，含介绍、演示、练习，未实际使用 | 第一部分 → 第三部分 → 第四部分 | 第二部分 |
| 实际接入尝试未成功，尚未处理工作 | 第一部分 → 第三部分 → 第四部分 | 第二部分 |
| 已处理过实际工作，含未完成或失败的尝试 | 第一部分 → 第二部分 → 第四部分 | 第三部分；停用者也不重复回答未用原因列表 |

| 条件 | 展示与处理 |
|---|---|
| Q6 没有可比经历 | 允许各行选择“无法比较”，不要求编造比较对象 |
| Q6 给出实质比较 | 明确一个实际用过的方式或组合，三行共用；未知维度仍可选“无法比较” |
| Q6 没有完成过可比工作 | 总时间与最终结果选“无法比较”；不推断已完成任务的效果 |
| Q7 选择多个具体问题 | 从已选问题中标出最影响的一项，再填写其后果 |
| Q7 只选一个具体问题，包括“其他” | 直接把该问题作为后果追问对象，不重复选择 |
| Q7 没有明显问题／暂时说不清 | 二者各自与其他选项互斥，不展示追问 |
| Q7 后果选择“影响不大” | 与其他后果互斥 |
| Q9 选择“没有特别原因／说不清” | 与其他原因互斥；具体原因最多三项 |

Q1、Q10、Q11 及标注选填的说明框可以不填。无经历者不评价功能，无可比经历者不估算提效。正式发布前核实平台的数据记录与访问安排，并落实非绩效用途；本版不收姓名、工号、联系方式或内部原件。

## 五、分析口径

- Q2 区分接触、接入与实际工作；Q8 区分持续使用、场景限定、缺少机会和主动停用。两者共同解释采用情况。
- Q4 是使用范围，Q5 是整体评价，Q6 是自报效果，三者不能互相替代。Q4 的多个环节不能与 Q5、Q6 的整体评价逐项绑定，据此断言某一环节有效或失效。
- Q7 的多选记录遇到过的问题；标出的关键问题和对应后果用于识别调查优先级。它不衡量故障频率，也不保证所有问题来自同一次任务。后果只归到填写者明确选出的关键问题。
- Q7 未列出的环境适配、业务扩展等问题可通过“其他”、Q1 和 Q10 表达。首轮试填后检查遗漏，不预先塞入全部候选功能。
- Q9 仅用于未进入实际工作的人。实际使用后的问题不再用另一张原因清单重复询问；不能仅将 Q8 的停用状态与 Q7 的所有问题关联为停用原因。明确选择“因此减少或停止使用”的后果，才是对应关键问题的自报关联。
- Q1 的未来需求与 Q7 的既有缺陷分别分析；低频但后果严重的问题单列，不按总票数直接排序。本版不量化发生频率，低频判断需案例或后续取证，不从少量勾选倒推。
- Q10 的案例用于解释现象和寻找后续取证方向，不凭个案断定 Framework、Extension 或模型根因；案例与某个关键问题的关系未说明时，不自动合并。
- 未收集版本和使用时间，不将结果宣称为某一发布版本或近四周的效果评价。
- 未用者的期望与实际使用者的效果分开分析；各分流题注明实际答题人数，多选百分比不能相加当作整体分布。
- 未填写案例不等于没有真实问题。保持正向效果和成功案例的独立记录，不让改进路线只由抱怨数量驱动。

整理结果时，分别呈现采用障碍、实际效果、关键问题与后果、开放需求以及值得保持的能力；每项路线建议注明支持答案、证据不足和需进一步调查之处，不设置未经确认的加权总分。

## 六、讨论与修订依据

### 试填反馈与原设计差距

来源：用户在本会话转述原问卷试用反馈。反馈包括：许多单选应允许多选；题目相似；部分选项超过十项；应参考公开 Agent 工具调查；关联逻辑不严谨、措辞难懂。上述是用户转述的反馈，本轮未取得原始答卷或计时记录。

此前设计曾以减少主问题数量、细化分类和跨题关联来兼顾分析完整性，仍留下较多子题、长选项和填写者需要自行判断的条件。用户反馈说明不能仅以主问题数判断减负。原稿保留在上级目录，v2 不覆盖或改写它。

### 用户纠正与本版决定

用户明确要求：“不要基于原有问卷题目改，用分析的角度整体重新设计问卷；不要覆盖原版，重新生成v2版本文档。”

此前围绕原题进行的重新编排不再作为本版施工依据。本版采用用户随后明确要求实施的“Maison 调查问卷 v2：从演进决策重新设计”方案：先明确需要支持的决定及证据，再建立共同入口、实际使用、未用阻碍和补充四部分。保留开放需求、真实效果与严重问题的证据，取消职责、任务量、共建招募及重复原因清单。

题目及选项按已确认方案落盘。设计说明补充平台展示、互斥规则和解释边界，使组织者不会把整体评价误归到某一能力，或把同时出现的问题误认作停用原因。文档完成不等于减负或路线判断效果已经成立。

## 七、检查与试填

### 文档自查范围

- 核对 Q1—Q11 连续且唯一，设计说明的问卷正文与填写者版一致。
- 核对四个部分及分流：未用者不进入效果评价，实际使用者不重复回答未用原因。
- 核对问题多选、关键问题、对应后果和互斥选项的关系。
- 核对填写者版仅含开场说明、题目、选项和必要提示。
- 核对本地文档链接及原版两份文件内容未改动。

以上属于文档自查，不是独立评审、问卷平台验证或实际试填。

### 后续试填场景

| 场景 | 需要观察的填写行为 |
|---|---|
| 持续使用 | 能表达正负效果；没有明显问题时不被迫填写问题后果 |
| 限定场景使用 | 能选出多个实际环节，说明其他方式或组合，不被误分为全面采用 |
| 主动停用 | 仍能报告实际体验和当前停用状态，不再填写未开始使用的原因列表 |
| 缺少任务机会 | 能与主动停用区分，保留此前体验 |
| 安装失败 | 直接表达接入阻碍，不评价未用功能 |
| 仅了解或演示练习 | 不被当作实际工作使用者，可表达不尝试的原因 |
| 完全不了解 | 不回答使用效果和问题清单，仍可提供 AI 需求及常用方式 |

试填还需观察混合工具使用、不同场景效果不一致、仅有未完成任务、多个问题、没有问题等情况。

验收重点是：填写者能否自行理解问题、能否表达混合工具使用和多种问题、是否仍需重复回答，以及组织者能否从答案中区分采用障碍、实际效果、严重问题和新增需求。记录实际填写时间、犹豫位置、理解歧义、错选和跳题问题，不以题数代替减负结论。

当前尚未开展 v2 试填、平台配置或正式发布；这些事项不属于本轮文档落盘的完成声明。
