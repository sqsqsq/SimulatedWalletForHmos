# Maison 使用与改进需求调查问卷

2026-11-02。状态：问卷设计稿，尚未发布或收集答案。面向内网开发相关人员，用于判断 Maison 的实际价值、问题与未满足需求，修正演进路线。

本文包含设计依据、可配置到问卷平台的正文、分流规则及答案分析方法。组织者说明不展示给填写者；开放题不要求提交代码、日志或其他内部原件。

## 一、调查目标与设计依据

调查需要回答三个问题：

1. 大家是否使用 Maison、用于什么任务、结果如何；相较其他实际采用的方式有何差距；不用或放弃的原因和场景是什么。
2. 对 Maison 或 AI 辅助开发还有哪些具体诉求，哪些应优先投入，怎样才算问题得到解决。
3. 使用中出现过什么问题、造成什么影响、最后如何处理，哪些需要进一步调查。

目的不是获取赞扬，也不预设 lite、review 增强或更多自动化必然是正确路线。有效体验同样用于识别应保持的能力，但总体评分不能代替具体事实。

## 二、发布与填写约定（组织者使用）

### 2.1 人群与基本原则

- 面向全体内网开发相关人员，包含继续使用、暂停或放弃、历史使用、仅演示、未尝试及不了解的人。
- 过去四周为主要窗口；历史使用保留时点，不当作当前版本或近期活跃情况。
- 先问开放诉求，再展示问题和改进列表。不把“未展示候选列表前的回答”称为完全不受提示影响的自发需求。
- 不要求未使用者评分；不知道版本、名称或技术原因不影响填写。填写者描述现象，维护者承担后续归因。
- 建议匿名，不收姓名、工号、职级或团队细分身份；如需业务差异，只自愿收集宽泛类别，避免小群体交叉识别。
- 发布前确认平台身份记录、访问权限和非绩效用途，才采用对应说明。联系方式通过独立自愿入口收集，不直接关联匿名答卷、不使用隐藏关联键。
- 采用十四个主问题及条件追问，不把主问题数量当作实际负担。填写时间与理解难度在试填中核实，不提前承诺分钟数。

### 2.2 主路径与条件分流

所有人先答 Q1—Q4。以下分类由 Q3 确定，题号均指新版；旧题号只在 §五的修订映射中出现。

| Q3 人群 | 使用经历部分 | 后续路径 |
|---|---|---|
| A 近期尝试/使用，仍继续 | Q5—Q9；Q3 附近期任务量 | Q10，再按替代信息决定是否展示 Q11，最后 Q12—Q14 |
| B 近期尝试/使用，已决定暂停或放弃 | Q5—Q9；Q3 附近期任务量 | 同 A；不因曾成功就强制归 A |
| C 以前实际用过，近期未用 | Q3 附最后使用时间；Q5—Q9 按最后经历，Q8 按最后使用时期 | 同 A；无任务机会与主动停用在 Q10 区分 |
| D 仅介绍/演示/练习 | 跳过 Q5—Q9 | Q10、Q11、Q12—Q14 |
| E 听说但未尝试 | 跳过 Q5—Q9 | 同 D |
| F 此前不了解 | 跳过 Q5—Q10 | Q11、Q12—Q14 |

过去四周仅为真实工作尝试安装、没有进入功能使用，也可属于 A/B。历史实际接入尝试计入 C；纯演示和练习归 D。A 指当前仍选择继续使用，不要求每天或每个任务都使用。

| 条件 | 展示与处理 |
|---|---|
| Q6 尚在进行或外部暂停 | 不选择最终采用结果；Q7 总时间与最终质量选无法判断，可评价已发生的人工投入 |
| Q6 安装/环境受阻、未进入有效工作 | Q7 可提供替代方式，但不展示效果矩阵；Q8 可描述阻碍，Q9 可按接入体验评价或选体验不足 |
| Q7 有具体替代方式且有可比经历 | 展示三行矩阵；各行可单独选无法判断 |
| Q7 无可比方式 | 不展示矩阵；尚未提供具体替代方式，后续展示 Q11 |
| Q7 已提供具体替代方式 | Q11 不再展示，即使矩阵各项均无法判断，也不重复询问 |
| Q8 选具体问题或“其他问题” | 展示案例关系、发生情况、主要后果及选填案例 |
| Q8 选没有明显问题或无法判断 | 不展示问题追问 |
| Q10 选择速度、质量或人工负担原因 | 对每个命中的理由显示来源追问，最多两项，不将两个不同理由合成一个来源 |
| Q10 选没有主动避用或无法判断 | 与具体理由互斥，不显示来源追问 |
| Q12 有明确选择 | 至多三项，再从已选项指定第一优先；显示 Q13 |
| Q12 无明确诉求或无法判断 | 与具体选择互斥，跳过 Q13 |
| Q14 选不参与/暂时只想使用 | 与主动参与选项互斥；其他意见仍可填 |

Q1、Q4、名称/类别、案例和文字补充选填；Q13 可跳过或填“不清楚，需要讨论”。其他题有明确的无法判断出口，不能为了完整回收强迫猜测。Q6 环境失败和 Q9 接入评价不等于对未用功能评分。

Q8 可能描述不同于 Q5 的任务，两者只有在填写者明确选择“刚才那次任务”时才作为同一案例关联。Q12 候选结果顺序随机，“其他”“无明确诉求/无法判断”置底；程度、时间及自然顺序选项不随机。

## 四、答案分析与路线决策（组织者使用）

### 4.1 三条证据链

| 证据链 | 对应题目 | 可以支持的判断与限制 |
|---|---|---|
| 实际使用 | Q3 → Q5/Q6 → Q7 | 当前采用状态、最近任务与目标、结果及相对体验；历史、未完成和环境受阻分别分析 |
| 问题 | Q8 的问题 → 发生情况 → 后果 → 案例关系与描述 | 主要阻碍、主观发生情况与实际影响；只有明确关联才与 Q5/Q6/Q7 串成同一案例 |
| 需求 | Q4 → Q12 → Q13 | 候选列表展示前的开放诉求、提示后的第一优先结果及具体成功条件，不将两者混称完全自发需求 |

Q10 解释避用和暂停，区分实际经历、预期担忧及无机会。Q11 补全未在 Q7 给出的替代方式；同一填写者不因两个题入口被重复计数。

### 4.2 统计与解释口径

- 分别呈现 A—F，B 为当前暂停或放弃，不自动认定由产品造成；C 为近期未用，不直接称流失。
- 安装接入失败者是有效反馈来源。Q9 可以反映接入体验，不作为其未用功能的满意度；D/E/F 不进入满意度和效果比较。
- 总体评分与具体经历分开。分母说明回答人数及无法判断人数，不用平均分代替问题分析。
- Q8 只选最影响使用的一项，统计为“首要问题被选人数”，不是全部问题发生率；未选到的问题不等于没有发生。
- 问题频率为受访者报告，不是系统故障率；只有一次经历和无法判断分别列出，不强行归为高频或低频。
- 后果中返工、接手、受阻和后续发现错误是不同风险，结合案例解释，不自行赋一个未经确认的权重总分。
- 多选平台的占比可重叠，不能相加当作整体分布；小样本不做过细交叉统计或个人识别。
- Q7 是同一指定替代方式下的主观比较，不是随机对照实验；环境、模型和版本未控制，不能从问卷直接计算客观提效比例。
- 进行中任务和外部暂停不算最终失败或完整提效。目标不同的任务不能把“达到目标”合并成同一种工程完成率。
- 不把未填写案例或成功条件解释为没有真实问题。Q4 与 Q13 分别是开放诉求和优先项具体化，不把后者覆盖前者。
- 未使用者的期望与使用者的实际效果分开呈现；共建意愿不改变问题权重。
- 问卷定位现象、场景及下一步调查方向。Framework、Extension、模型或环境的根因由后续取证确认，不要求填写者诊断。
- 识别值得保持的能力及适用条件，防止路线只由抱怨数量驱动。

### 4.3 从答案到候选路线

| 答案组合 | 候选调查方向 | 需要避免的推断 |
|---|---|---|
| 不知道如何开始、不了解用途，无实际任务失败 | 接入说明、示例与支持 | 产品能力必然差 |
| 实际尝试在安装或环境阶段受阻 | 平台、工具条件和接入可用性 | 必须新增业务功能 |
| 小任务频繁避用，单任务耗时或人工负担突出 | 核 lite 场景及成本构成 | 并行更多任务即可替代单任务减负 |
| 检视/测试结论错误或必要检查未执行 | 区分判断质量与执行缺口 | 多接 Skill 或多写报告一定有效 |
| 业务规则难以应用，现有替代更合适 | 知识消费、专项能力复用及接入 | 应直接复制内部 Skill 或另造业务框架 |
| 文档修改负担大，影响理解和评审 | 内容、表达与交付组织 | 越短越好 |
| 多平台出现相近问题 | 核共同机制与共同输入条件 | 问卷已证明 Framework 根因 |
| 某能力被采用且结果有价值 | 固定保持项与适用范围 | 所有任务都应采用相同流程 |

### 4.4 调查报告交付内容

1. 邀请范围、回复覆盖、各使用状态人数和无法判断情况，说明选择偏差。
2. 使用、暂停、放弃和替代场景，区分无机会、条件受阻、实际不适用及体验后避用。
3. 主要问题的首选人数、发生情况、后果、案例及可进一步核实的线索。
4. 未展示候选列表前的诉求、第一优先结果及成功条件，分别呈现。
5. 有效能力的保持建议，以及修复、增强、暂缓或继续调查的路线建议和证据强度。

优先级综合受影响人群、反复程度、后果、替代方式和期望效果，不只按票数，也不用未经确认的加权总分。路线建议不等于已批准实现方案。
