# Maison 使用与改进需求调查问卷

2026-11-02。状态：问卷设计稿，尚未发布或收集答案。面向内网开发相关人员，用于判断 Maison 的实际价值、问题与未满足需求，修正演进路线。

本文包含设计依据、可配置到问卷平台的正文、分流规则及答案分析方法。组织者说明不展示给填写者；开放题不要求提交代码、日志或其他内部原件。

## 一、调查目标与设计依据

调查需要回答三个问题：

1. 大家是否使用 Maison、用于什么任务、结果如何；相较其他实际采用的方式有何差距；不用或放弃的原因和场景是什么。
2. 对 Maison 或 AI 辅助开发还有哪些具体诉求，哪些应优先投入，怎样才算问题得到解决。
3. 使用中出现过什么问题、造成什么影响、最后如何处理，哪些需要进一步调查。

目的不是获取赞扬，也不预设 lite、review 增强或更多自动化必然是正确路线。有效体验同样用于识别应保持的能力，但总体评分不能代替具体事实。

## 二、发布与填写约定（组织者使用）

### 2.1 人群与基本原则

- 面向全体内网开发相关人员，包含经常使用、偶尔使用、尝试失败、停止使用和从未使用的人。
- 以过去四周为主要窗口；超过四周的最近经历明确标记为历史体验，不混算近期活跃使用。
- 先问真实工作和最近经历，再问满意度及改进方向；不先展示宣传材料、预期收益或 lite/review 推荐结论。
- 未使用过的能力不评分；不知道名称、版本或技术原因不影响填写。填写者描述现象，维护者承担后续归因。
- 建议匿名、不收姓名和工号。联系方式由独立自愿入口收集，不直接关联匿名答案，不使用隐藏关联键。
- 发布前核实平台是否记录身份及访问权限，确认实际数据用途，才使用对应匿名和“非绩效评价”说明。
- 不收团队细分身份；如确需分业务分析，只增加自愿填写的宽泛业务类别，并避免小群体交叉识别。

### 2.2 题目与分流

Q1—Q4 用于分流；Q5、Q6、Q7 是使用者分支的关键事实；Q10 保留“无法判断”；Q12、Q14、Q17 用于非使用原因、现有替代和优先级。开放题允许跳过，不为提高必答率强迫猜测。

| Q4 人群 | 进入的题目 | 特殊处理 |
|---|---|---|
| A 近期实际使用并推进任务 | Q5—Q14、Q16—Q20 | Q15 满足比较条件才显示 |
| B 近期尝试但放弃/未成功 | Q5—Q14、Q16—Q20 | 安装失败也是有效经历；未进入功能使用时 Q9 不显示相应能力 |
| C 以前实际使用，近期未用 | Q5—Q14、Q16—Q20 | Q5 改为最后使用时间；Q6—Q11 按最后实际经历；Q15 明确比较时点差异 |
| D 仅介绍/演示/练习 | Q12—Q14、Q16—Q20 | 不要求实际工作效果评分 |
| E 听说但未尝试 | Q12—Q14、Q16—Q20 | 不展示基于实际使用的比较题 |
| F 此前不了解 | Q12—Q14、Q16—Q20 | 可以选“不了解/无法判断”，不迫使其归责产品质量 |

Q8：任务未结束或没有可比经历时可选无法判断，不能据进行中耗时计算完整提效。Q9：只显示 Q6 实际用过的能力，且允许未完成/无法判断。Q11：“没有明显问题”与其他项互斥，案例框仅对选择问题者展示。Q12：“没有主动避开的场景”“无法判断”与具体原因互斥。

Q15：仅 A/B/C 且 Q14 有实际替代方式、能确认自己做过类似任务比较时显示；演示印象不进入比较。Q17 选至多三项，并从中指定第一优先；选“没有明确诉求/无法判断”则不再要求排名。Q18 仅在 Q17 有明确第一优先时展示。Q19 的“暂时只希望使用”“暂无意愿”与主动参与项互斥。

候选问题和改进方向选项可随机排序，“其他”“不清楚”“不适用”等置底；有自然时间或程度顺序的选项不随机。

## 四、答案分析与路线决策（组织者使用）

### 4.1 分组和证据口径

- 按 Q4 的 A—F 分组呈现，尝试失败者纳入问题分析；不要只看成功完成者。
- 分开报告近期使用、历史使用、仅演示、未尝试及不了解，整体满意度的分母仅为有实际体验且能判断者；同时披露无法判断人数。
- 分析平台、任务、频次、实际使用能力的差异。小样本不做过细交叉统计，更不据此推断整个内网群体。
- Q7 区分采用、人工接手、换工具、环境受阻、仍在进行和外部中止；不能统一压成一个“成功/失败率”。
- Q8/Q15 是填写者的主观对比，有版本、环境、模型和任务差异；不得直接换算客观提效比例或因果结论。
- 具体案例按“任务—期望—实际—影响—处理”整理，保留未知；由维护者进一步查证机制、输入、模型执行或环境责任。
- Q16 的自发诉求与 Q17 的提示后选择分开统计，保留候选列表之外的方向。
- Q17 同时呈现被选次数和第一优先次数，并结合影响、频率、替代方式及 Q18 的成功条件判断；不能只按票数排研发顺序。
- Q19 仅用于组织自愿参与，不以是否愿意贡献改变问题优先级，也不将回答作为工作承诺。

### 4.2 从答案到候选路线

| 答案信号 | 优先考虑的调查或改进方向 | 不能直接得出的结论 |
|---|---|---|
| 大量人员不了解或不会开始 | 接入、说明、示例与支持 | 产品能力一定差 |
| 已尝试但环境阶段失败 | 安装、平台和工具链可用性 | 应立即增加业务功能 |
| 小任务、紧急修复频繁避用且人工负担高 | 核 lite 的实际场景与单任务成本 | 所有小需求都需要固定轻量轨 |
| review 被采用但漏检、误报或复核成本高 | 检视方法、业务依据与处理闭环 | 多接几个 Skill 就会更好 |
| 专项工具更有效且使用广泛 | 比较复用、接入或方法吸收价值 | 应全文复制内部 Skill |
| Story／方案修改量高、评审难理解 | 内容正确性、表达与交付组织 | 文档越短越好 |
| 多平台出现相同问题 | 调查公共机制及共同输入条件 | 未调查就归因 Framework |
| 仅在特定业务环境出现 | 调查业务知识、工具条件和适配 | 该业务需要独立框架 |
| 某项能力效果稳定且持续使用 | 识别保持项及适用条件 | 所有业务场景都适用 |

### 4.3 调查报告交付内容

1. 邀请范围、回复人数及使用人群覆盖，说明选择偏差和缺口。
2. 使用、放弃和替代方案的具体场景分布。
3. 已有效、值得保持的能力及适用条件。
4. 主要问题的影响、案例、涉及人群和当前应对方式，归因不足的标待调查。
5. 需求优先级与期望效果，区分自发诉求和提示后选择。
6. 路线建议：保持、修复、增强、暂缓或进一步调查，并说明证据强度；不将问卷选择直接变成已批准实现方案。

## 五、发布前验证与当前状态

先请少量近期使用者、尝试失败者和未使用者试填，核对分支、术语理解、填写耗时及敏感信息要求，再删减重复问题。检查 A/B/C 的历史口径、D/E/F 的免评分、Q9 动态行、Q15 比较资格、Q17/Q18 联动和各互斥选项。

发布时记录邀请范围与回收覆盖。主动反馈可能偏向特别满意或特别不满意的人；呈现人数和实际案例，不用低覆盖样本代表所有开发者。

当前仅完成设计和本地文档整理，尚未试填、发布、收集、联系受访者或作统计结论。匿名、非绩效用途及自愿回访方式须在实际发布环境落实。历史背景仅用于设计调查维度，不作为对填写者的能力承诺。
