# maintain 正向优化

2026-11-11。这是用户级维护能力任务，不属于 Extension 产品版本，也不占预算包。本页保存依据、八处设计、退出表和验证；实施结果见[实施反馈](实施反馈/)。

## 依据与授权

依据是[维护自检](../../diagnosis/2026-11-11-140110-维护自检.md)（含 §6a）。自 11-08 起，Skill 改为步骤卡结构，规定的产出基本都交了，但同类错误仍在复发：

- 没读到真实行为；
- 删检查后，它原来拦的错没人接；
- 测试条件被当成产品需求；
- 分不清步骤和批次；
- 效果退化靠用户发现；
- 修订一层层叠加；
- 非阻塞返修被单独开成一轮。

**用户原话**（11-11）：

1. “根据目前的分析，给出maintain这个skill的正向优化方案，不要打补丁或防御性描述”；
2. “还有一个问题，模型总是搞不清步骤和批次的区别”；
3. “还有一个关于评审的问题，当进入评审时，如果需要返修，会要求执行者只做返修动作，没有考虑或许步骤或批次是否可以继续执行，否则会因为一个非阻塞的小问题带来多轮返修，浪费时间。我希望skill能指导模型合理判断，非阻塞的返修和后续步骤，按批次统一执行”。

用户批准了方案（Claude 计划文件 `~/.claude/plans/maintain-skill-pure-mochi.md`，本仓外；八处设计已整理在下文），并选择“逐条盘点 Claude 项目记忆后迁移”。写进项目 AGENTS 或 TEST 的长期规则，逐条请用户确认后再写。

**不在本次范围**：不运行模型、设备或正式 Case；不推送；不改公共 Skill 原件；不改 Extension 产品；2.0.4 在原目录接续，历史需求目录不迁移。
