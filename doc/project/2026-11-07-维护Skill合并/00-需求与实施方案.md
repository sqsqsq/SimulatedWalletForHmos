# 维护 Skill 合并为 maintain 与公共 Skill 清理

2026-11-07。用户级维护能力任务，不属于 Extension 产品版本或预算包。本页保存用户决定、工程事实、实施方案及接续；实施结果见[实施反馈](实施反馈/)。

## 目标与授权边界

- 把 maintenance-designer、maintenance-executor 合并为一个 Skill `maintain`。角色保留，改为按会话绑定。执行子命令 `implement` 改名 `exec`，同义词 `handover` 退出。
- 删除没有任何入口到达的公共 Skill：prototype、implement、grill-with-docs。grill-me 保留。
- setup-matt-pocock-skills 与 codebase-design 不安装，由用户级规约里的一句映射承接。
- 受影响的现行入口、规约和其他项目文档一起改；历史原件不动。

本轮只做结构合并与清理，方法正文的语义不动。不推送，不运行模型/设备/正式 Case；新入口的宿主实测由用户开新会话执行。

## 讨论与修订依据

- **起因**：用户读 [11-07 维护自检](../../diagnosis/2026-11-07-084052-维护自检.md) 后，要求了解两个维护 Skill 的设计，然后说「我准备把maintenance的2个skill进行整合，你有什么好的建议？包括新skill的名字和子命令」。设计者建议：新名 `maintain`；子命令取两边的并集；角色改为会话绑定；先做结构合并，内容修订另起一轮。
- **用户四点回复**（原话）：
  1. 「基本认同」。
  2. 「implement这个子命令太长了，能优化下吗」。改名候选为 exec、do、build，用户选 **exec**；它与公共 implement 不撞名。
  3. 「diagnoise里保留的本skill的问题，以及对公共skill的判定是否分析了？是否存在无用的公共skill？」。设计者核查：历次 doctor 只核「本次是否适用」与链接是否存在，没审过 Skill 正文；没有跨历史的公共 Skill 使用统计。
  4. 「本次2个skill修改后对其他项目文档或skill内容有影响的要一起改」。
- **公共 Skill 处理**：
  - 设计者先建议本轮只记候选。用户答：「你要了解公共skill它们的内部依赖关系，有的子skill可能我们是没用到的，grill-me肯定是用的」。
  - 摸清依赖后，用户勾选删除 prototype、implement、grill-with-docs；handoff 未勾，保留。
  - Claude 插件 mattpocock-skills 1.2.3 的副本：用户选「保持现状，只记录」。
- **setup 与 codebase-design**：
  - 第一版方案只记录 setup-matt-pocock-skills 未安装。用户拒绝该版方案：「setup-matt-pocock-skills 没安装的问题要一起解决」。
  - 设计者给出三个选项：用户级映射、安装、各项目运行。用户追问「究竟有没有必要安装它」「tdd当前有用到吗？」。
  - 设计者查证后的结论见下节。依据补齐后，方案改为映射、不安装，用户批准。

## 设计

```
~/.agents/skills/maintain/            ← git mv 自 maintenance-designer/
├─ SKILL.md            角色绑定 + 子命令表 + 共同准备（替代两个入口）
├─ agents/openai.yaml
├─ references/  documents method-use dependencies doctor doctor-env doctor-analysis
│               clarify spec plan(原 design.md) review exec(原 executor implement.md) handback
├─ scripts/read_reference.py   tests/test_read_reference.py
```

**子命令**：help、doctor [关注点]、doctor env、clarify、spec、plan、review、exec、handback。文件名与子命令对应。

**角色绑定**：
- 角色由用户在本会话指定；没有指定时按子命令推定，并在第一句回复里说明推定结果。
- 跨角色调用要用户在本任务里授权；执行者会话做 review 只能叫自查，不得自批评审。
- doctor 两个角色都能调用，行为相同。
- 其余入口内容取自两个原入口的现有句子。`read_reference.py` 的 `--role designer|executor` 不变。

**映射句**：放在 `~/.agents/AGENTS.md`「工具使用」节，所有会话都能读到。内容：公共 engineering Skill 所说的 issue tracker/工单对应项目的 Spec/Plan 目录，domain docs/ADR 对应项目的术语与决定真源；setup-matt-pocock-skills 与 codebase-design 不安装。
