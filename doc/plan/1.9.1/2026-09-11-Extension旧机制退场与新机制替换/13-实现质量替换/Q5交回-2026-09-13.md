## 2. 写前核：判据只有一份

`chapterProblems(ctx, chapter, candidateBody, getView?)`，返回 `string[]`：

- 剥指导后**非空**；正文恰为「本需求不涉及。」时到此为止（那一章没有结构可言）；
- **围栏闭合**（同种、不短于开启标记、标记后到行末只有空白）；
- **模板占位符** `{{…}}`；**待写 marker** 还在；
- **必要 H3/表/图**：`chapterStructureProblems`，不另写一份；
- **仓内工作编号**：按合同 `id_shapes.drop`，**画图围栏内部挖空**——上游那张图是原样搬来的，
  里头的节点名不是作者写的字，让他改只能改坏图（这是本包的一处行为纠正，分册 §1 点名）；
- **本地图片断链**：`scanBrokenImages`。⑨ 里 story 那一份随之退场，review 那一份留着。

全篇 check 的 ⑪ 与 ⑫a 合成一条 `⑪ 章内必要项`，逐章调同一个函数；章之外那一段（大标题与前言）的
占位符由同一个 `placeholderProblems` 扫，**不是第二份规则**。`getView` 传的是 check 自己那份记忆化取法，
**要用时才算**：空章不解析，一次 check 仍是「有正文的章各解析一次」（`test_chapter_view` 守着这条）。

## 3. 章提交：顺序与两条新拒绝

冻结守卫 → 读候选与 Story → **唯一章锚** → 剥指导 → 剥自己的标题（**异名 H2 拒绝**）→
**附录候选在内存投影** → 写前核对 → 替换目标区 → 接续。

- **判不过时 story.md 与候选文件都不动**，exit 1；作者只改草稿，不必同时改已经落盘的正文。
- **同名章锚两处**：替换按锚定位只替得掉第一处，另一处仍是旧的而读者读到两遍——现在拒绝并点名。
- **开头是别的章的 H2**：从前剥标题那一步遇到它就停手，于是别的章的标题进了这一章正文，
  `## ` 又成了一个章锚，下一次替换切错的就是它——现在拒绝。
- **附录先投后核**：那四节本就不该由作者写，不投的话写前核对会因为它们空着而拦下一份合法的附录。
  投的是**内存里的候选全文**，投完再核再写盘。
- 非目标区按原文区间拼接，字节不变（含 BOM/CRLF/空白），既有用例照旧守着。
- **落盘成立之后不反报失败**：接续算不出来也不说提交失败——说失败他会把这一章重写一遍。

## 4. 首屏接续：一处，三行

`nextSteps(ctx, storyText, result, warnings)`，前三行固定：

- 仍有待写章：`NEXT` 给下一章、还剩几章、完整命令（带实际 `--project-root` 与本工程的引用规则）；
  `INPUT` 给本章草稿、当前 Story 已写的章、`story-write.md` 第五节；
- 十章齐：`NEXT` 直接要求通读当前 Story（比较跨章独有信息 / 推演关键条件下四处说的是不是同一件事 /
  核指代与单位与可逆后果），改哪章改哪章的草稿再提交，收口跑 `story_flow.py story`；
  `INPUT` 给全文、草稿目录、`story-write.md` 第四节。
- `RESULT` **只写真做过的事**：skeleton 写「骨架 + 几份草稿」或「已存在，未改动」，不说提交过一章。
- 完整三动作只在作业书维护，stdout 只给短动作与当前数据；记一笔与统计放三行之后。

Python 侧 `spec_stage_step` 按分册分出两步：`story_chapters`（还有 N 章带待写标记）与
`register_story`（十章齐、先写后核再登记）。待写记号进合同 `pending_mark`，Python 读合同、
document 侧留字面并注明真源——**状态查询仍只读**，没有在 Python 重做章级检查，也没有起 Node 查询。

## 5. copyedit 七行自证退场（同包，四处一起）

`COPYEDIT_ROWS`、check ⑫d、`STORY_SRC_LEDGERS` 的 `copyeditPath`、Python `STORY_SRC_FROZEN` 的
`copyedit.md`、作业书那一段与阶段页那一行、`review_reflow.md` 的「那两件」——全退。
七行是「做过没做」的代理，它只证明有人写了七行；统稿真正的痕迹是**被替换的那几章**与
提交时那一次核对。**写后核对的七条作者清单原样留着**，没有新建记录、没有加「已读/已统稿」字段。
`story_flow.py story` 的登记接口不变：complete 前提、project→number→build→check 全过才 `story_written`，
失败不登记；decisions 的存在/形态/冻结与人工区保护不动。
