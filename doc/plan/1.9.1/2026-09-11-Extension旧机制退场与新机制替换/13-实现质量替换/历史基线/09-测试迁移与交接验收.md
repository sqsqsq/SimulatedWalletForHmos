## 2. init测试如何迁，避免再次“引用多所以不退”

用 `rg -n 'init_audit|story-build|"init"|\x27init\x27' test/story/tests test/story/scripts/check_failure_modes.py` 定位后读每个调用上下文。名字命中不是直接删除指令，knowledge-use/flow/adapter的init不在删除范围。

逐处分类并在本包交回表写最终落点：

1. 仅为旧起手建decisions：改到当前合法skeleton起手；若测试本来仅测纯解析，直接创建它所需的合法输入，不跑完整流程造昂贵夹具。
2. 真测材料齐备/可选缺失/坏决策/不覆盖：迁到skeleton或check，对应正反结果仍守。
3. 真测来源索引/audit文件：回退基线已无该机制时删除该专属断言；不能顺带删除同测试里的图片身份、冻结或内容保持断言。
4. helper结果未使用且不产生后续所需状态：删空转调用，保留测试主体。必要时一次定点替换验证判断，不建立全仓函数置空平台。

不能用“改空后160条绿”证明所有调用都无效；必须核它们各自的生产输出与下游读取。迁完跑真实起手正向例，避免全是负例通过、第一次正常使用反而卡死。

## 5. 全部最小章节的行为验收

评价真实CLI产物时，将Story所有H2、H3、H4建阅读清单；父节自己有正文/表格也单列，不能只评叶子而漏父级。02的十章方法覆盖所有章；原2.1三级细则是比较参考，不把它的所有示例标题强加给业务作者。

每个最小单元记录五项：它回答什么读者问题；依据和该处独有信息；形式为何适合关系；是否遗漏/重复/矛盾；从上一轮或金样保留/改善/劣化了什么。可在同一评测表短写，不另加业务运行期台账。

| 章 | 本轮重点核对的真实效果；不是强制所有场景出现 |
|---|---|
| 背景 | 因果与目标可读，没提前完整重讲方案；未知指标不编造 |
| 术语 | 概念能消歧，词典不成为唯一规则落点；完整字段不重复进正文 |
| 范围 | 完整需求不做与本部件不负责分开；依赖提供方、阻塞和交付边界明确；父子标题含义一致 |
| 业务方案 | 全局规则/真源/实际取舍有主要落点；已否方案指代准确；没有虚构备选 |
| 业务流程 | 顺图能追实际参与方交接、主分支、回跳和终态；源图标记齐不能替代内容核对 |
| 功能说明 | 按能力；数据属性/对象关系/生命周期选合适形式；有图处就地解释，无页面不造页面；不重讲整条流程 |
| 异常与恢复 | 正常受限/主动取消/故障区分；可观察影响、数据与在途结果清楚；缓存不同对象不混用 |
| 验收 | 原编号独立、条件/结果/主责可执行；工程阈值有来源与口径；重复预期属于必要重现 |
| 交付与上线 | 对各实际控制对象说明措施、存量/在途/恢复；业务自动停用不冒充发布回退；依赖未就绪不称可上线 |
| 附录 | 五节与精确投影可信；作者解释不被清除；业务含义在正文，材料贡献不变倾倒区 |

## 6. 模型行为与失败归因

按TEST §8.1还原首稿、提交、整稿、返修和verifier收到的对象。read次数、文件存在、ai-prompt生成、作者自称已核都不能互相替代。尤其读取完整tool_input、head/分页和真实tool_output，不只看命令第一项。

| 现象 | 回查与修复责任 |
|---|---|
| 首次不知道必须形态，研究源码才写 | 核章头/任务包是否在动作前送达、是否给精确形状；回C01/C02 |
| 第一屏仍无下一动作、恢复只说继续 | 回C03真实输出和spec_stage_step，不加已读字段 |
| 能拿到当前正文但仍全程重复/漏关系 | 核C08工作方法是否实际执行；看独立审查是否发现；输入正确后仍失败要披露模型表现边界，不再归因为文件缺失 |
| 已修内容又坏 | 核这次改的是草稿还是真源、是否被projection覆盖、实际提交对象与版本；不能仅凭context_total高断言遗忘 |
| 为过词面检查删事实 | 回语言判据作用域，不加案例原句豁免；在真实稿中恢复事实 |
| verifier全文已到但漏重大问题 | 核当前规则与报告依据；承认语义未达，不用结构PASS或增加同义提示解释为完成 |

报告初稿质量、确定性返修、语义返修、工具/输入成本、总耗时与人工等待。扣除已知故障的数只能叫估算，不能写成修复后实测。无记录的子代理内部行为标未知。真实CLI仍由用户按TEST启动，本方案不附自动测试命令。
