**正常路径**：第 5 条证明依据成立时照写不误；`check ⑯` 的既有 20 条用例一条未改。

## 返修 2 · UX 交互正文在成文链上没有落点

**走的哪条路**：方案给的最小改法，一个字没多改。合同加

```json
"UX": { "path": "ux-reference/README.md", "required": false, "label": "界面参考" }
```

于是它走 `indexSources` 的第一支（遍历合同 `sources`），`material_dirs` 那一支的过滤规则、导入端、清单端**都不动**。合同版本 4.3 → 4.4，`sources_note` 里「README 不是登记，也不是来源」那句改成正文是来源、图片仍走 `materials.json`。

**反例与正常路径**（`test_entry_switch.py::TheInterfaceReferenceIsAnInput`，4 条）：inbox 放一份 UX 类文档 → 真的跑 `import_sources.py` → `sources --stage before-spec` 之后索引里有 `UX` 且切出了内容单元；编排引用它的单元，正文进这一章的材料视图；没有 UX 材料时 `sources` 仍退出 0 且不当缺件；图片数目不因为加了正文 key 而变化，`UX` 只有 README 一条路径。

**两条既有用例被推翻了一半，我按「这条断言守的是什么」逐条判的**：

| 用例 | 原来守什么 | 现在 |
|---|---|---|
| `test_the_contract_no_longer_declares_a_readme_source` | 合同不把 README 当来源 | 裁定推翻。它真正保护的是**图片登记只有一处**——改成守「正文是可选来源 + 图片仍在 materials.json」 |
| `test_init_passes_without_mentioning_the_readme` | 有图无 README 不拦、不提起 | 「不拦」保留（`required: false`）；「不提起」改成**要当场说清缺席是正常的** |

第二条的改法有实测依据，写在那个类的注释里：首跑 `init` 被 README 缺失拦下 → 补 README → 材料指纹变 → 契约开新一轮 → 轮次死锁 18 分钟；二跑降成记一笔仍出现两次，作者两次停下处理，其中一次顺手删了附录材料清单里的那一行。所以那一笔必须自带「缺了是正常的」——不说的话，下一个作者还会去手造那个文件。

**方案让确认的那件事**：`ux-reference/` 也是 framework 像素保真链扫图的目录。已确认不受影响——`fidelity-shared.ts:463` 只收 `jpe?g|png|webp|bmp`，README.md 不在其中。

## 返修 3 · 父级上下文进了索引却没有送达

**选第 1 条：接上消费者。** 理由是分册给切法的理由是「不能丢掉父级前提与表格」，而这个理由现在**只在切法里兑现、没在送达里兑现**——`context` 一路记着位置，没有人把它送到作者手上。

**做法**：`story-sources.mjs` 新增 `contextRefs(index, ids)`，把 `context` 记的行范围**认回那个父单元**（父节在第一个子节之前的正文本来就自成一个单元，所以上级前提有身份），材料视图新增一段「上级前提（在原件里，按位置读）」，给 `ID` + 标题路径 + `文件:行范围`，**不复制正文**——送全文就是第二份原文，而要不要用得由编排来引。

已经在本章材料里的父单元不列（全文就在上面）。

**实施中弄清的一件事**：有正文的祖先都会被切成单元，所以 `context` 的每个范围**必然**对应某个单元。原先我按防御写的「认不回就不列」只在索引被外部改过时成立，注释已按这个事实写准，不留一句让人以为常见的话。

**反例**（`test_entry_switch.py::TheParentPremiseIsLocatable`，2 条）：只引子节时视图给出父单元的 ID 与 `upstream.md:行范围`，且**父节正文不出现在视图里**；父节也被引时不再列第二遍。

**突变核对**：把 `context: contextRefs(...)` 换成 `context: []`，第一条当场红。
