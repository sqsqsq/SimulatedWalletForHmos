# 探索报告审视与 Step2.2 可靠性建议

> 2026-09-09；评阅 [模型在什么条件下遵循](../steps/02.2-方案分析·模型在什么条件下遵循.md)，对照 [Step2.2 草案](../steps/02.2-基于模型行为的成文与审查优化.md)、当前代码及 reviews/13 的真实运行证据。本报告提出方案调整建议，未实施、未重写步骤主方案。

## 1. 总体判断与对原方案的反思

报告的重要贡献是把“模型需要理解什么”与“模型实际上倾向做什么”分开，并揭示报错清零不等于质量提高、填写自述不等于完成比较。我原 Step2.2 的写前回看、动作式统稿，仍主要描述模型应该做什么，缺少足够明确的工作材料与任务交付方式变化。若只是把整张十章边界表灌进提示，就仍是同一路径加文字，不能宣称更可靠。

下一步应改变的是模型当前任务：从凭记忆生成另一章，变成对照已经写出的相关内容完成当前章的独有问题；从勾选自查清单，变成在实际文稿上消除已识别的问题；从汇总“均通过”，变成以可核查的内容比较支撑结论。脚本辅助准备与保存这些材料，不能替模型裁定语义。

报告的若干绝对结论则不能直接进入设计前提，否则容易重新滑向“凡不能写成门禁就取消要求”。可靠性是降低任务歧义、减少不必要选择、提供实际材料并验证结果，不是保证所有语义都可以程序化。

## 2. 哪些结论成立，哪些需要收窄

| 报告主张 | 评阅意见 |
|---|---|
| 确定性排版交给脚本更稳定 | 成立。编号、投影、固定表头不应要求模型重算。但“100%”不能作为工程保证；移除一项任务或判据后该类报错为零，也不证明原语义目标仍被满足 |
| 错误应定位到实际编辑对象，下一步明确 | 成立。减少模型猜命令、找文件和反复试探。不能把“给具体替换”一概当正确修法，替换必须保持原业务含义 |
| 关键确定性检查应嵌入生产动作 | 成立。记录只有在对应检查通过后生成，比可跳过的自助 lint 更可靠；它仍只保证该检查实际证明的性质 |
| 只写提示基本无效 | 证据不足。最近一次真实首稿已采用 Step2.1 放开的表格/叙述形式，说明模型并非不受指引影响。真正失败的是若干未被有效执行的比较任务，不能外推为所有指引无用 |
| verifier 不适合查重复与形态 | 当前样本只支持“现有任务和配置没有可靠发现这些问题”。报告自述新版可核产物只有一份、正面报告也不齐，不能推成固定能力边界 |
| 14 字重合可证明重复规模 | 可作候选线索，不能当语义重复真值；术语、数值、必要验收重现也会重合。已有人工确认的完整过程复述才是本步的直接证据 |
| 读 checker 说明送达不足 | 是调查信号，不是唯一原因。还可能查调用方式、调查真实脚本故障或因旧指令冲突而求证；必须看读了什么及随后怎样使用 |
| 唯一 NEXT 有效 | 是有价值的执行引导，但现有观察不能单独证明与其它机制变化的因果。应复用确定流程中的下一步，不把真实的人类选择也强行变成唯一命令 |
| 无法消除重复就降为 advisory | 不应整体采纳。轻微文字冗余可以是建议；妨碍理解、制造冲突或遮蔽独有信息的重复仍是质量问题，不能因为难检就降低用户目标 |

报告 §9 的不确定性限制应同样约束 §1/2/6/8 的强结论，不能在末尾承认样本不足，在前面仍写“只有四种”“已证无效”。

## 3. 现场与代码核对补充

1. 当前目录能枚举到 **63 份 runlog、21 份最终 Story**，与报告的留存规模一致。它不等于 63 次同版本、同配置、同输入的独立试验，不能直接用于评估遵循率。
2. “作者任务包 12288 字节”来自 `test_author_task_package.py` 的测试约束；`author.mjs` 当前直接输出完整任务包，没有运行时截断。它是体量控制依据，不是宿主只能接收 12KB 的事实。
3. `flow-check` 确实主要核 key 等记录结构，但 `story_flow.read_gate_options` 已按合同回填第一级 label。若人实际看到的消息仍被模型改写，缺口在展示消息与选项记录的关联，给磁盘记录再加 label 相等检查也不能证明显示内容一致。这不适合成为“再加记录判据就解决”的论据。
4. Framework 的“WARN 记 notes 不修”出现在具体 NEXT 分支中，不能推出“所有非 BLOCKER 内容错误在所有路径都不修”。当前 Story 读者审查本身已经是 BLOCKER，却仍漏报；提升它的 severity 不能解决没发现的问题。
5. 报告不同段落的 14/20 次源码读取、与先前度量的 44 次不是同一统计面。此前度量含 bash 和 Framework 读取；报告复现说明主要取 read/grep、Extension 路径，并把 JSON 合同也纳入一部分统计。需要统一定义后才能比较，不宜用这些数直接证明读取大幅改善或恶化。
6. 原始统计脚本没有随报告保留，仅有复现要点。1.38 轮等精确均值可作为报告提供的线索，本次未复算为自己的结论。方案优先依据已定位的真实错误与操作链，避免先扩大为历史测量工程。

## 4. Step2.2 应怎样调整才能更可靠

### 4.1 从“再记住一条规则”转为“拿着明确材料完成当前任务”

保留共用方法和每章少量非显然边界，不把十章表整份重复进入每一章。

当前任务应明确四件事：当前章草稿、相关已写内容、当前需要新增的信息、这次写入位置。已有相关正文应直接作为当前比较对象，不能只给一句“必要时回看”。优先利用现有按章命令的结果和原文读取能力，在接续下一章时给出明确的相关片段位置；若装配原文，取真实正文、不由模型再写摘要，不构建全量事实分配台账。

例如写局部能力时，任务是“结合已有整体过程，完成该能力尚未交代的输入约束、规则和结果”，而不是再次生成完整旅程。最后仍按章落盘，保留独立可读的最少承接，不能把整章压成“见前文”。

这里的可验证变化是实际任务材料与提交动作，不是提示多了几个动词。它降低凭记忆重复生成的机会，仍不能保证语义重复不可能；必须用真实首稿验证。

### 4.2 把动作与局部确定性保护连接，错误回到最近的工作对象

借鉴 Framework 的 NEXT，但使用既有流程真源，不另建 next 状态：

- 章落盘成功后，明确剩余章与当前下一项工作，指到实际草稿；已经有下一步的地方只统一文案，不另维护第二套顺序。
- 章正文中可独立判定的必需结构，尽量在同一落盘动作前用现有检查逻辑核实，失败保留旧章，错误指向本次草稿。不能每写一章跑一次全书检查，把未写的章也报一遍。
- 跨章完整性与最终投影仍在登记/交付位置核；不会因局部结构通过就绕过全篇检查。
- 报错末尾给当前唯一可执行的接续动作，例如修改本次草稿后重试原命令。需要多处编辑时一次列清，不能伪造一条能够自动解决语义问题的命令。

这是对既有 chapter/status/check 的整合方向，不应再加一套必须手动调用的审稿工具。共享同一检查实现，不在写前、写后各复制一份规则。

### 4.3 统稿交付的是文稿改动，不是完成声明

七行凭据应删除，报告对此方向的认可成立。不能因为想保留“机械触点”而换成必须写一句修改说明，否则还是自证。

统稿的当前工作材料必须是实际合成稿和需要比较的相关内容。重点在原稿上完成合并、保留独有信息、连接图的分支、修正指代与后果；已有章草稿是编辑落点。真实运行中通过 edit/chapter 与最终内容观察结果，不强制每轮一定有修改，不产生另一份全量报告。

如需提出候选重复，可以在维护诊断时借助字符串定位，但不将重合度写成生产门禁或自动删除依据。语义层面的重复不能靠限制下游章“只能引用”来保证消失，那还可能损害 Story 自包含。

### 4.4 将图的语法与内容完整性分开，不从表行数猜真实参与方

报告提出“参与方表≥3 行就强制图种”，看似结构化，但 Step2.1 已允许参与方通过非表格形式表达；表行也可能是角色类别、分组或重复对象。该来源由模型编写，少写一行即可改变触发条件，不能称为删除句子也绕不过的结构锚。

已确认的多方交互要求继续成立。可可靠取得的图代码类型、语法和引用关系由脚本检查；实际有多少参与方、是否覆盖完整交互及分支，需要对照来源与范围。只有参与方条件来自可靠的既有结构源时，才将对应图种要求接成硬检查，不能为加这一条先造一份模型自填的参与方声明。

图种正确仍不是完整性证明。作者任务应先处理“源材料要求的过程与当前图差在哪”，编辑图本身；缺标记只修身份问题，不能作为图内容通过的证据。

### 4.5 独立审查的输入改进保留，但按风险试证而不预设有效

完整 Story 通过现有 pre_verifier 送达，能消除一次额外定位/读取需求，值得保留。它解决的是输入可达性，不保证模型正确比较；增加的实际上下文成本须明示。

审查问题改成具体关系核对，避免输出“十章过了、均一致”；结论以实际内容和位置为依据，但不强制 PASS 报告变长。对历史上漏掉的重复与多方关系，本轮必须用真实结果观察，不能先承诺换一套措辞后审查必然可靠。

若输入与动作已明确，同一配置仍反复漏报关键问题，应披露此范围的能力不足，讨论可用配置或人工复核边界。不是默认追加一个同质 reviewer，也不是擅自将要求降为 advisory。

### 4.6 严重度按结果影响，措辞要求按实际可读性

内容缺失、矛盾、无依据承诺等会改变交付理解的错误应在现有内容审查规则中明确阻断；不把所有 MAJOR 批量升成 BLOCKER。已有 blocker 漏报先修判断任务，不能用 severity 掩盖。

“每表一句引导”应直接改为：标题或邻接文字是否已经解释表的用途、对象与条件；已经解释就不重复补一句，没有解释且妨碍理解才处理。这是读者目标，不新增基于空行、字数或段数的引导句门禁。

编号和回滚的机械误判继续按原计划修作用域。报告建议给所有模式匹配都加结构锚不宜整体采纳：必须先证明锚代表真实对象，不能只另添一个模型可填写或删除的字段。

## 5. 建议采纳次序与判断标准

先将 Step2.2 的投入收敛到三项实际变化：

1. 当前写作任务具备明确的相关原文、增量目标和编辑落点，降低默认重新生成整套内容的倾向。
2. 确定性保护嵌入最近的原子动作，接续动作来自现有流程；移除无效自证与机械误判。
3. 最终 Story 的完整审查输入与具体比较任务，实际结果决定是否有效，不再以报告结构存在推断质量。

评审时先验这三项是否真实改变执行材料与动作，再看首稿、实际修改、独立审查和最终结果。不能只 grep 提示里出现“比较”“独有信息”“完整过程”就宣告机制已闭合。

继续保留不重复、不丢失、可靠展示和合理成本的目标。历史已知失败用于检验诊断是否有解释，不进入交付提示；用正常真实需求验证，不先造覆盖所有可能行为的大型测评系统。

本次未直接改写 Step2.2：其中局部结构检查的前移与当前任务材料准备需要在方案中明确消费者和边界后实施。本报告给出取舍依据，不把探索报告的所有建议自动变成新增需求或已批准机制。
