# S2—S3 维护流程与评价方法验证

2026-10-21，维护设计者建设并试用，性质为自查/方法走读。采用`extension-acceptance@1`；标准、入口和输入原件已固定，逐文件摘要及副本映射见`output/evidence/1.10.0-evaluation-20261021/frozen-inputs.json`。本报告验证维护方法的可执行性和区分力，不宣称独立评审或未知需求上的统计可靠性。

## 1. S2实际入口与演进规则

项目[AGENTS §0](../../../../AGENTS.md)在维护任务入口直接要求：方案制定/修改、开工、评审前读取[TEST §6.5](../../../../test/TEST.md#65-维护标准与评审)、[标准](../../../../test/regression/extension-acceptance.md)、本版变更。TEST的按任务读取表也有对应分支，§6.5包含版本演进、开工条件、身份、四类任务、结论和报告。入口在动作前出现，不要求维护者先读1.10.0调查史。

角色走读结果：

| 执行者/时机 | 实际能取得的输入 | 决定/产物与完成条件 |
|---|---|---|
| 设计者定需求/改方案 | AGENTS→TEST§6.5→标准条目及有效需求 | 判新增/修改/退出/保持，写本版变更；目标和判法覆盖后才交实施 |
| 实施者开工/需求中途变化 | 本版变更中的标准修订、保持集合和证据安排 | 固定实际工作区身份；标准缺口只停依赖项，目标变化先改标准再实现 |
| reviewer审方案/实现 | 同版标准、原件、实际diff和消费者 | 目标对齐、实现符合、退场、证据分开核；旧方案即使实现正确也能判目标偏离 |
| 真实运行评审 | 固定运行输入/产物/宿主/配置/阶段及标准 | 只判已运行范围及副作用，其余未覆盖，不能以initial签update/设备 |
| 版本验收 | 固定标准全量适用集合 | 逐条列已改/保持/未覆盖，不因父组绿而省子条件；用户评分和发布另有确认 |

全局Skill/用户AGENTS未改。旧调查00—04加历史定位，05的旧待澄清、旧视觉前置/版本依赖已同步为当前定案入口。1.9.9统一接续加入新标准链接，并建立其首次核对记录，避免首次应用还缺“本版变更”。普通评审不再靠00—04里历史现状猜目标。

## 3. 正反结果、缺证据与合法变体

复用现有`test/scripts/make_narrative_variants.py`，输出在本题`variants/`。它只按精确差异生成14份文本及两份材料和索引（共17文件），不调用模型。生成成功只证明输入构造成立，以下结论由维护模型对材料与全文核读给出；不拿夹具自带的expect当答案。

| 对象/对应条件 | 核读事实与结果 | 结论及边界 |
|---|---|---|
| receipt.good，B2的入口/正常/失败/清理 | 简报要求完成态且要素加载后入口，端侧复用当前数据，失败/取消删临时件；全文的流程、功能、异常、AC均有落点 | 对这些文本条件符合；图片实际显示与全产品运行未覆盖 |
| queue.good，B2的入口/免打扰/失败/清理 | 等待态可订阅、已办理/过号无入口；免打扰不推送但留记录；取消/失败删除、失败不重试在全文一致 | 同上，符合指定文本条件，不签隐藏工程事实/设备行为 |
| fabricated_receipt，B2/C3 | 新增“生成7天后自动失效”不在原始需求、已知决定或原方案，凭证是一次性定格文件 | 偏离；不能因AC或章节仍完整而放行 |
| fabricated_queue，B2/C3 | 新增“失败自动重发三次、间隔三十秒”与原件“不再重试”直接相反 | 偏离；关键行为矛盾，与另一题材的7天错误均由原件核而非数字黑名单发现 |
| chapter_hollow_receipt，B2/B6 | 整个业务流程章换为“按标准流程执行”，原件从入口到分享/取消的主线在该章不可读 | 偏离该读者主线条件；其他章节仍有事实不意味着空泛主线足够 |
| chapter_hollow_queue，B2/A4 | 整个功能说明改为空泛一句，页面状态/免打扰操作说明及原图承接被删除 | 偏离相应读者操作与原图承接；不是因字数短而判错 |
| image_dropped_receipt/queue，A4/B3 | 原件指定图承载版式/状态位置；正文采用关系与图引用被删，仅附录仍列图不能代替正文使用 | 对实际承接条件偏离；图内像素事实未在此次判断中核验，不编造视觉结论 |
| same_meaning_receipt，B2/B6 | 异常表改为列表，失败删临时件、不分享、提示重试/可换格式、离开取消、埋点不影响业务均保留 | 符合该表达变更的语义保持条件；不因不是金样表格判错 |
| same_meaning_queue，B2/B6 | 术语表改为段落，号三状态、订阅和提醒区别、免打扰条件均保持 | 符合同一条件；允许另一业务及组织形式 |
| fact_deleted_receipt/queue，B2 | 被删的是功能章入口说明，但凭证流程仍写“完成态且要素已加载”，排队流程仍写“等待中”，AC第三行仍明确非完成态/已办理已过号无入口 | 不能跟随夹具“fact_deleted=blocking”就判整篇遗漏；入口条件仍可由流程+AC共同取得，指定事实覆盖符合。其余质量另核 |
| knowledge_echo_receipt/queue，D3/D5 | 规约依据格变成名称回显，但正文、事件表与清理规则仍有具体字段和行为，不能只读这格就说整个知识未应用 | 该依据格回查性偏离；文中具体应用落点仍可查；完整激活规约/Spec/Plan链未在这组文本中取得，完整知识链未覆盖。不能把声明弱化自动升级成“实现缺失” |

另一个缺证据例：当前R4要求正常入口取得独立源码语义原回复。历史run的PNG/请求存在但无有效独立原报告时，B3该子条件未覆盖，不能因XML合法标符合；无页面的纯后台中性例只使B2的页面子条件不适用，来源、失败和验收仍适用。这三种状态与上表的符合/偏离能明确区分。

已有变体的expect与当前语义判断不一致处，仅作为测试域材料局限登记，不修改夹具/产品或让标准迎合其标签。它验证了方法必须看全文与实际职责，不能只搜索被删原句、关键数字或规约名称。

## 5. 必要性与实际使用

同名材料本来是合法输入，路径安全与身份唯一性需要保护；按短名拒收或请人改名增加无依据人工中断，A2能将两者分开。SVG源码语义与位图独占事实不同：无视觉不自动阻断文字型SVG，也不能把未看过的像素事实判符合。

清理范围按当前接续§4及既有第二批评审§5：只处理临时sw-story，保活动现场/路径边界，output/story永不清理；构造的归属冲突不是恢复已撤销登记/认领平台的理由。现有实施交回承认未在真实临时现场清理，因此这里只核当前目标和必要性，不替其真实副作用签通过。

对一份真实实施交回实际按新方法形成完整报告，见[03实际回查](03-实际交回按新标准回查.md)。它能支持“不能按旧R8放行V5、保留机械保护、真实行为与在途新实现分别待核”的推进决定；没有把未来新交回不存在作为无限延期理由。
