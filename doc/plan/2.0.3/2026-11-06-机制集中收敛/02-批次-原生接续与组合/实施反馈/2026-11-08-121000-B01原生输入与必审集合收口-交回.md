## 3. 方案外决定

- **只派生、本阶段契约没写出时门禁读不到契约**：退出 `chosen` 后，`TheDerivedUnitWithItsRole`、`AMissingOwnRoleIsNamed`、`NoPatternIsACandidate` 依赖「没写出的契约当成本阶段已有」的旧行为。探针（`output/evidence/2.0.3-B01-R02/20261108/probe_r02_spec.py`）确认原生同一状态下 SpecLoader 给 null、原生 plan 检查把 contracts.yaml 当不存在。三类改为先物化（与 prepare-blueprint-design 同函数）再冻结，是第六节第 3 步的正常顺序；另加 `ADerivedContractIsAnInputUntilThePlanWritesIt` 锁「作者看得到选中输入上的义务、门禁不当作已交」。
- **作者任务按选中输入列义务**：03 §2.1 只说「缺口文案区分」，没说没写出时作者看什么。若按 spec 为 null 处理，作者会丢掉写契约要落的 must 与相关知识正文。改为按选中输入列，并明写还没写出；必审集合与门禁仍以产物为准。请设计者复核这一取舍。
- **成功链的 harness 不带 NODE_OPTIONS**：测试进程的转译缓存钩子被原生 harness 判 `node_options_injection` BLOCKER；`native_cli` 去掉它（真实宿主没有）。
- **覆盖合同用例的夹具没冻结**：`test_review_closure::ThePlanReviewUsesTheSameCoverageContract` 的 AR90006 没有执行范围，「完整报告收下」在新规则下应拒收。改为核拒收原因（缺口没清零）；完整报告收下由成功组合核。`ext_workspace.required_inputs/cover_report` 改返回核查标识、退出补占位。

**全量里的失败**：`test_adapt_ownership::TheStatusViewOnlyReads` 判「--status 写了文件」，并耗时 1479 秒。原因在本步新加的用例：跑真实 harness 的两类（`TheRequestChainFromANewlyAcceptedUnit`、`APlanClosesThroughTheNativeRequest`）的工程把整个 framework 接成共享被测副本的链接，原生 harness 把运行状态写进共享副本的 `framework/harness/state/.current-phase.json`；那个只读用例的快照顺着链接读到它在变，失败时 difflib 对一亿多字符的快照做差异，拖成 25 分钟。修法：两类用例的工程改用自己的 `framework/harness/state` 与 `reports`（`private_harness_state`，其余照旧链接或复制自被测副本），并删掉本轮写进共享副本的那份状态文件。修后 `test_blueprint_case_closure` 25 passed，共享副本的 state 只剩原有 `.gitkeep`；与 `test_adapt_ownership` 并发跑 71 passed（`output/verify/20261108-121146-affected`）。

全量对象：本交回所列产品改动加修前的测试；最终对象：同一产品改动，测试多了 `private_harness_state`（只改测试夹具）。差异的补测是上面两次定向运行，没有重刷全量。

结构：上面各项。语义：替身只证明确定性消费，没证明审查者读懂了。真实行为：DSH 作者与独审、完整 phase:plan 效果留 C02。

未覆盖：同一工程里的最终 Story 依据（施工单位链的夹具没有 Story 流程，建 Story 要改蓝图需求条目，会让 CU 引用过期；Story 依据失效与恢复由 Part4 两例在另一夹具核）；use_cases 有投影或要求时的必审只由代码路径承接，没有专门正例。
