## 2. 原生输入与阶段产物的接口决定

### 2.1 readFeature只补全真实事实

在framework-access.mjs::resolveFeature中，对当前已消费的acceptance/contracts保：

~~~text
inputs[input_id] = {
  state, detail/attempts（原生实际给出时保留）,
  value（resolved时取本次原生选中值）,
  binding: {
    input_id, source, dependencies, source_refs, content_fingerprint
  }
}
spec = SpecLoader给出的本阶段规范结果（contracts/acceptance/useCases）
required_outputs = 本次原生context.required_outputs
~~~

binding整对象直接复用原生InputBinding，不再截成source，也不并存native_binding旧新两份。source形态为artifact/artifact id或derive/provider_id；dependencies的path/exists/sha256/role、source_refs、content_fingerprint不本地重算或修剪。input state为resolved/absent/invalid/not_applicable；capability的pruned/blocked是另一个层次，按原生assurance/issues说明，不把absent改名pruned。

inputs.value与spec分清：前者不再被SpecLoader本阶段结果覆盖；后者只取SpecLoader规范结果，退出chosen fallback。原生resolver在成功选择时已把artifact/派生值放进resolved.artifacts，SpecLoader可正确读它；本阶段required_outputs同名产物则以本地产物为准，缺了保持null，不能用上游选中输入回填为“已经完成”。不改原生loader或复制其选择规则。

同步knowledge-task中唯一直接旧binding.kind/artifact读法为binding.source.kind/artifact，并说明输入来源与本阶段产物各自位置；缺口文案也区分“原生输入已resolved”和“本阶段必交产物尚未生成”，不能拿前者表示后者已经在盘。其它使用f.spec的phaseArtifacts及阶段checker保持当前语义，不为本步广改其签名。use_cases不是此版固定input_id：继续消费spec.useCases及原生required_outputs/产物映射，不编造inputs.use_cases。

### 2.2 正式阶段与缺口

reviewInputs读同次readFeature(plan)。status非ok、范围未冻结、原生blocked/invalid、规范值shape错误或required_outputs不能取得时，原issues进入现basis.gaps，明确该输入准备未成立，不能用空集合/本地文件存在降级成PASS。这里不冻结、不写summary/receipt，不把真实失败吞成not_applicable。

已resolved的原生输入需核其实际选中内容；absent/not_applicable按原生实际必需性与issues处理，不给已被原生裁剪的增强输入强造本地文件。必交输出缺失仍missing并作为gaps，不能以缺文件为由声明本阶段整体SKIP。当前对象上的必要输入未核，仍须按原生阶段/扩展判据报告失败或未完成，不增加豁免。

## 3. 一份当前basis，两个最终消费者

### 3.1 reviewInputs与覆盖标识

保reviewInputs(root, feature, purpose='plan')入口及inputs/update/gaps/alias/visual返回结构；临时持有native（本次readFeature结果）和knowledgeTask（本次knowledgeTaskData结果），不落盘、不复制真源。输入行如下：

| 项 | 行的标识与数据 | 实际内容在哪里 |
|---|---|---|
| 原生逻辑输入 | input_id取真实binding.input_id，保binding/required/missing及用途；没有虚构path。digest展示原生content_fingerprint | 当前harness签发主prompt的(resolved input <id>)块；真实source_refs按问题回查 |
| 本阶段真实输出/仍有效文件依据 | path为原生解析的工程相对实际路径，沿现required/missing/原字节摘要 | 原生主prompt已有产物块或实际文件 |
| 本阶段必需知识正文 | path为共享选择给出的真实知识路径，purpose写明本次全文/上篇/下篇范围 | 同一次知识任务text中的对应正文；其它知识只在完整索引中 |

inputs中原生input_id与文件path各是自身核查标识；键选择为input_id存在则用它，否则用规范化path。原生输入即使来自本地artifact也按input_id声明；不新增“路径等于派生值”的alias或等值引擎。额外读取canonical/来源文件不能替代该原生选中输入的覆盖，已有图面纯文件basis的alias规则不变。

本阶段required_outputs逐项经已有loadNative().module('config.ts').resolveFeatureArtifact取得真实路径，存在性/缺件沿现add机制核；不能手拼逻辑CU路径或扫描父view猜来源。inputs与同名产物是两种责任，分别以原生input_id和实际输出路径核：允许读者一次对照完成，不要求重复论证；输入binding不能给当前产物字节背书，读过上游不等于审了本地输出。

保现有效决定、人答、Story/update依据与旧现场保护的规则，直接Spec/Plan没有走Story不强造三件套。退出固定必需的本地spec/spec.md与acceptance.yaml；存在但不是原生选中来源的文件只可作有理由回查，不能替换当前输入。其它required输出仍真实必审，scope/来源异常照原生报告。

### 3.2 模型看到什么，脚本检查什么

inputRows对原生项给input_id、source/provider或artifact、原生fingerprint及主prompt承载位置，明确“核主prompt当前解析值，按该input_id声明”。source_refs/dependencies保完整身份，不逐个提升为必读正文，不重新输出typed value。实际独立verifier收到的是原生完整ai-prompt，不是孤立的Extension片段；测试必须检查真实request.prompt_path中的正文与扩展核查标识同对象。

扩展Plan判据仍用blocking_findings/advisories/examined_inputs/unreviewed四键，值类型不变。examined_inputs的字符串现在可写任务明确列出的原生input_id或真实文件路径；unreviewed沿现字符串“键：原因”或现映射形态给理由。inputRows、detailProblems及其合同文字同步从“每份路径”改为“每个本次核查标识及范围”。这不是Framework全局报告格式变化；原生汇总、request、subject、终态、receipt和Story两行报告不改。

detailProblems的table/seen/skipped/silent均用同一键规则，missing对原生项表示本次值未成立、对文件项表示真实缺件；必要项不允许伪称已读、缺核或用extra顶替。Plan basis.native所示本阶段required_outputs有真实交付职责时，不能因输出还没写就用SKIP规避；输入/输出缺口按原生问题与本判据必审规则处理。图面等没有此原生阶段上下文的纯文件basis保持自身既有适用规则，不把合法无图场景改成业务阻断。extra真实取证仍可声明，不能因当前表没有该路径就禁止核源。

pre_verifier在Plan只取一次basis，把其中同一次knowledgeTaskData.text作为reviewerKnowledge片段，并从这个basis生成必审行；不能先写一份任务、再按另一套范围建表。verifier-report::reportProblems/coveredProblems在post_check消费时用当前同一reviewInputs规则重建basis，不读取上轮缓存文件或让模型提交新资格上下文。原生当前性/subject决定旧回复能否用，Extension不另建状态机。

## 4. 复用A05知识选择，完整退掉全量枚举

将knowledge-task现buildTask开放为knowledgeTaskData(root,args)，返回仅{text, preview, documents:[{path,part}], gaps}。documents就在现knowledgeBlock的sent/bodyFor循环生成；part取全文/上篇/下篇，path为实际工程相对路径。完整正文和全局索引已经在text，不另导出一份正文副本。knowledgeTask(root,args)返回data.text的薄包装；CLI仍沿同入口，只有原有author正式调用才记usage，审查或纯数据函数不记开始。

relatedFiles/bodyFor及完整激活/selfCheck/knowledgeContext保持唯一；reviewInputs通过data.documents加入相关知识，不再knowledgeRegistrations全量add，也不解析任务Markdown反推选择。保common评审动作/pending、本单位事实、实际must/pattern_roles与验收knowledge_refs、flat起步/无相关CU及audience冲突。全局索引仍供发现漏判，登记本身不等于正文必审。

调用依赖保持单向：pre_verifier/verifier-report→review-inputs→knowledge-task→现knowledge/application/contracts/framework-access。knowledge-task不反导报告模块。readFeature既有同命令缓存承担同一原生对象取得；不新增全局cache，不广改phaseArtifacts或其他阶段取数接口。

主文规则不能只依字符串机械省承诺：用户自然语言已要求“可读实施方案/Plan正文”时，模型负责在原请求结果里明确原生产物名，不要求用户懂文件协议，也不追加重复确认。未要求主文的原生合法路线仍保留。

最小成功组合沿B批01分册§2.2继续：真实CU接受→request范围→当前作者产物→harness签发→完整ai-prompt中的原生值/知识任务/必审键一致→测试替身仅在独审外部边界回真实subject与按该任务完成的四键→真实receipt/finalizer产closed→observer达phase:plan→同工程最后Story依据。只证明确定性消费，不证明替身有真实业务理解；不手造closed/receipt、不关闭policy、不写假的本地Spec。修后的新对象重新由原生生成，旧失败现场保留。
