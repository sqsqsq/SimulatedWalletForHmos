## 2. 关键调查与被撤回方案

原生InputBinding已含input_id/source/dependencies/source_refs/content_fingerprint，hook ctx却没有resolved inputs，因此继续现readFeature解析。现场完整ai-prompt已有(resolved input acceptance)/(resolved input contracts)和真实产物正文；固定harness-runner::collectContextFiles就是其生产者。原先调查考虑Extension再serialize typed值，核实后撤回：本层只补标识/绑定/用途与覆盖，不增加inliner、虚拟文件、快照或同值alias。

SpecLoader对本阶段required_outputs优先读自身产物，缺失保持null。故inputs保原生raw selected与完整binding、spec保规范结果，chosen fallback退场；上游值不可替本地产物。完整source_refs含知识依赖不等于正文全部必审，A05 relatedFiles/bodyFor的结果成为最终必审消费者的唯一知识范围。

覆盖选择已定：原生逻辑输入以本次input_id、真实文件以path声明；二者不互相冒充。报告四键及原生subject/终态保持，图面纯文件basis不被套新阶段规则；当前required产物缺失不可用SKIP规避。actual主prompt才是模型输入，不以单独hook片段缺正文为由另造一份。
