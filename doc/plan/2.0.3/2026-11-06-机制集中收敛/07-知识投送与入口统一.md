# 知识投送与入口统一

2026-11-07。A05的唯一详细设计，承接本轮静态审计；未实施。依据当前manifest/knowledge.mjs/knowledge-application.mjs及固定原生CU身份；不扩知识schema、不增加持久阅读状态或片段平台。

## 1. 生产与消费

完整activeKnowledge加载、自检和knowledgeContext摘要保持。buildTask先加载一次知识并取得blueprintTask/featureTask已使用的judged，在同一调用内传给knowledgeBlock；不重复读蓝图，不把这个临时选择结果写成第二真源。

第四块改为全局发现索引＋本动作必要正文。索引由manifest/frontmatter及已有解析结果派生，每份一行path/source_ref、name、kind/form、applies_when和可用篇/单元；当前13份只是样板事实，不写死数量/域名。已有不适用、未选和公共理由仍可定位；未选正文不等于不适用。索引只渲染一次，审查者同样取得，允许直接按路径取完整原文，不加expand命令。

CU相关文件集合由unitContext的mine/facts及unitDuties/rolesOf取得：applied规约（包括reviewAction）、本单位selected模式角色、原生事实provenance.source_ref；与本单位相关pending知识仍送。common中applied的reviewAction（可合法仅指decision或需求级地址）以及尚未确定承担单位的pending也作为公共上下文送对应文件，由模型判断当前动作，不强造代码must/验收；不能因unitDuties排除reviewAction而漏送。并入本阶段实际contracts实体must/pattern_roles、acceptance.knowledge_refs所引文件，避免把已存在的错误引用过滤掉；现有对齐检查仍报错，不能由输入收缩掩盖来源不一致。路径按现knowledgeSource解析和去重，不用裸ID猜文件。

非spec/plan阶段第二、三块也改为本单位义务与必要公共依据，不再列他单位全套applied为当前任务。完整全局结论通过既有蓝图定位取得，审查者能发现漏判，但不重做共同选型。

## 2. 正文粒度与动作

| 动作 | 直接送达 | 决定责任 |
|---|---|---|
| 蓝图设计/质询 | 全局事实（facets全文、halves上篇）、全部规约全文、模式上篇 | 全局发现、适用性与角色；质询先原生正文首读，再读知识材料 |
| CU Spec作者/审查者 | 本CU相关规约文件全文、事实与模式上篇（facets全文） | 行为/验收承接；不是共同设计重判 |
| CU Plan及coding/review/ut/testing | 本CU相关规约文件全文、事实与模式下篇（facets全文） | 结构、角色、方法与验证；reviewAction不能因无代码must漏送 |

复用knowledge.mjs现有halvesOf与解析产物，不另写切篇正则。规约以相关文件全文保通则/附注，事实facets也保文件前言与跨面说明；模式不按角色名切碎方法。需要另一篇或其它文件时按索引核源。受众只决定任务责任，不授权作者替审查者删不适用依据。

manifest audience继续作为显式路由；实际契约必用引用若被audience排除，沿现有输入诊断指出登记与消费者冲突、交知识所有者修正，不静默少送或自动改清单。坏清单/空派生/缺篇继续由完整加载器报错，不作正常零相关正文。合法无相关正文仍给索引与本单位未承接说明。

非CU的既有维护Feature按现knowledge_facts/context取判断；无可承接判断时保全局发现材料并如实说明，不将CU算法强套到未知路径、不在本轮新增平铺Feature状态流程。
