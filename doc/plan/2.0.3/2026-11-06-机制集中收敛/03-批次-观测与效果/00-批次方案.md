## C02 固定组合、获准CLI与集中效果评审

1. 固定Extension源摘要、实际安装件、Framework release/source、patch、CLI版本/模型配置、Case原料/人答与目标；组合不混不同revision。
2. 一次完整必要handback；装配输入变则assembly，Case/编排变则cases。必要验证失败定位修复，准备不等于模型已验证；120—180秒是成本目标，不为凑时长删覆盖。
3. 用户明确启动后走现有run_multi_case两例流程：auto到story:submitted，car到phase:plan。按真实合法输入继续，不新增第三Case、默认update、设备、内网或编码。真实接口外部条件仍按原输入，不能把金样的额外模拟前提当答案。
4. 保全同一对象原生父子会话/完成回复/实际写入/读回/最终组合，语义评审并排材料、当前产物及参照。一次效果不推稳定成功率，不因不满意无限重跑求绿。
5. 按@26逐项核来源分类/转写方向、蓝图与Story分工、实际派审/首读范围、原读者按影响复核、最小证据接入及旧资格机制退出；报告准确性（业务/身份/来源/终点）、性能（总耗时/工作/等待/结构与协议成本）、返工（实质修复/格式补核/无变化复用/影响面遗漏）及全部58项适用结论；三轴评分按TEST提议、用户确认，当前无分数重签。
