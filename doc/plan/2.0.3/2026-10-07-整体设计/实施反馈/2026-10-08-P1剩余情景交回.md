## 3. 需要设计者定的事

1. **未准入蓝图与附录投影的两难**：按 R2，修订后的蓝图在独立质询前不能记为准入；但附录机器区的投影（`project`、附录的 `chapter`）要求蓝图已准入。auto-topup/update 的附录因此还是实跑时的旧版，其中的旧 SEC-01 判断、「单日最多充 200 元」与修订后的蓝图不一致，修订后的作者区只能作为草稿另交。可选做法：
   - 授权一次独立质询让蓝图真实准入，然后正常重投；
   - 接受「旧附录 + 草稿」的阅读形态，在 README 里标明。

   我不会为了投影临时恢复通过。
2. **待裁定 update 的流程轮次**：开轮要过材料关卡、记一次人的回答，car-key 这一段只有预置台词「不补」。我没有开轮，也没有跑 `decide`，本轮记录作为候选文件交出。这样交是否可以？还是要用标明为测试输入的方式开轮？
3. **car-key D2 合并了两件事**：用例里两条「暂缓」意见本来分别针对再转分享和强制下线，现在都落在合并后的 D2 上。是否要求把 D2 拆成两条议题？
4. **plan-ready 只交缺口清单**，不在实跑的 FAIL 产物上做修补，这样是否可以？
5. **草稿介质的推断**：plan-ready §2 从「退出登录清除」推出草稿要扛过杀进程，所以选本地持久化。这个推断是否成立？
6. **车钥匙底稿的术语记录**：人确认过术语，蓝图却记成 `headless_assumed`（reviewable README §4）。是在候选里改成确认状态，还是作为底稿缺陷只记录不改？
7. **需要用户回答的两件**：Q1（auto-topup update 里那句 200 元的回答是否在授权内）和 T6 澄清，仍按复核裁定交给用户；它们分别决定 D11 和 D4 能否定案。
