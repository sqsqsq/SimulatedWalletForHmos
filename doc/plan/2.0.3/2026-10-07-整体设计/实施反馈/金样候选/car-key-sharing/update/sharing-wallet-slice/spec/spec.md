## 1. 功能概述

车主在钱包卡包里的车钥匙卡片上发起分享：选对象、权限与有效期后发出，对方钱包收到待接受的钥匙，72 小时内接受后生效，并作为车钥匙卡片出现在对方卡包里；推送没送到时，对方进入卡包也能看到待接受的钥匙，点它进入接受页。车主在分享管理页查看每条分享的状态，可以随时撤销生效中的分享。

本工程还没有车钥匙卡片，本单元一并补上卡包里的车钥匙卡片（车主本人的钥匙与接受成功的钥匙）和卡片上的分享入口。车云开放接口在工程里还不可用，车主本人钥匙信息、车辆标识与分享关系都先由可替换的模拟数据承接；被分享人一侧按账号查收到的分享，六个车云接口里没有对应接口，同样由模拟数据承接；与车云的真实联调另列依赖，不算本单元验过。真车开锁、凭据签发与设备能力不在本单元。

被分享人能否再转给第三人、撤销后极端断网是否强制下线，上游仍未定，本单元不承载。

## 2. 目标用户与使用场景

| 用户角色 | 描述 |
|----------|------|
| 车主 | 持有车钥匙，想把钥匙临时给家人或联系人用的钱包用户 |
| 被分享人 | 收到待接受钥匙、把钥匙加进钱包的家人或联系人 |

| 场景 | 名称 | 描述 | 前置条件 |
|------|------|------|----------|
| S1 | 车主发起分享 | 卡包车钥匙卡片点「分享」→ 选对象、权限、有效期 → 发出，对方收到待接受的钥匙 | 已登录、持有车钥匙、功能开关开启、配额未满 |
| S2 | 被分享人接受 | 收到推送进接受页，或推送没到时在卡包点待接受的钥匙进接受页 → 添加到钱包 → 钥匙生效，作为车钥匙卡片出现在卡包 | 分享为待接受且未逾期 |
| S3 | 车主管理与撤销 | 从车钥匙卡片进分享管理页，查看每条状态，撤销生效中的某一条 | 至少有一条生效的分享 |
| S4 | 发起被打断后续办 | 退出页面、断网或关掉应用后回来，接着上次的选择发出 | 有未发出的草稿，且仍是同一账号 |
| S5 | 被分享人查看收到的钥匙 | 进入卡包看到待接受与可用的钥匙；车主撤销后，撤销中显示「正在收回」，收回完成后移除 | 已登录 |

| 编号 | 功能 | 优先级 | 描述 | 场景 |
|------|------|--------|------|------|
| F0 | 卡包车钥匙卡片 | P0 | 卡包里展示车钥匙卡片：车主本人的钥匙（来自模拟的本人钥匙数据，含车辆标识与车型）与接受成功的钥匙；点卡片进钥匙卡片详情 | S1, S2, S3 |
| F1 | 分享入口与门槛 | P0 | 车主本人钥匙的卡片上有「分享」和「分享管理」入口；未登录或没有车钥匙的用户看不到；功能开关关闭时不能发起新分享，已生效的分享不受影响 | S1, S3 |
| F2 | 分享设置 | P0 | 三段：给谁、权限、有效期。选定对象后查该对象可用的权限档位；换对象重查，旧档位不可用时请车主重选；三项选齐且配额未满才能发出 | S1 |

| F4 | 分享管理与撤销 | P0 | 顶部车辆与剩余可分享数；逐条列出对象（打码）、权限、有效期、状态；只有生效的条目可撤销，待接受、撤销中与已结束的条目只展示状态，已作废与已到期的可重新发起 | S3 |
| F5 | 接受页 | P0 | 车辆信息卡（车型、车主昵称、权限、有效期）与「添加到钱包」；不设拒绝按钮，72 小时未接受自动作废 | S2 |
| F6 | 钥匙卡片详情 | P1 | 显示权限范围与有效期；权限之外的功能不出现，而不是置灰 | S2 |
| F7 | 状态、身份与隐私 | P0 | 六态与车云返回一致；页面与记录只显示对方昵称与打码账号；业务请求用可识别的对方账号标识 | S1, S3 |
| F8 | 被分享人收到的钥匙 | P0 | 进入卡包时按当前账号取收到的分享：待接受的显示为待添加，点它进接受页；生效的显示为钥匙卡片，撤销中显示「正在收回」，撤销完成、到期或作废的从卡包移除；从旧入口打开不可用钥匙的详情时提示已不可用；换账号重新获取 | S2, S5 |

## 4. 页面与界面

| 页面 | 内容 | 交互 |
|------|------|------|
| 卡包页（修改） | 新增车钥匙卡片分区：本人钥匙卡片（车型、车辆）、发给当前账号的待接受钥匙与接受成功的钥匙卡片 | 本人钥匙卡片上「分享」进分享设置页、「分享管理」进分享管理页；点待接受的钥匙进接受页；点钥匙卡片进钥匙卡片详情；每次进入或回到卡包重新获取 |
| 分享设置页 | 给谁（通讯录选择或输入对方账号，展示昵称与打码账号）、权限（档位单选）、有效期（7 天 / 30 天 / 自定义至多 180 天）、发出 | 选定对象后查权限档位；对象不可分享时不呈现档位并给原因；满额时发出置灰并给原因 |
| 分享管理页 | 顶部车辆与剩余可分享数；分享列表 | 每次进页拉取；只有生效的条目有「撤销」，已作废、已到期的条目有「重新发起」（进分享设置页新建一条），其余只展示状态；断网给网络失败态，不展示陈旧列表 |
| 接受页 | 车辆信息卡与「添加到钱包」 | 按分享标识取这条分享展示；添加成功回到卡包；添加失败保持待接受、可重试 |
| 钥匙卡片详情 | 权限范围、有效期（只读） | 进入时按分享标识取当前状态；已撤销、已到期或找不到时提示这把钥匙已不可用并回到卡包 |

| 状态 | 页面表现 |
|------|----------|
| 加载中 | 进页拉取时显示加载 |
| 空数据 | 管理页没有分享时给空态 |
| 网络失败 | 管理页给网络失败态，可重试 |
| 满额 | 设置页发出置灰，显示配额接口给的原因 |
| 待接受（被分享人） | 卡包里显示为待添加的钥匙，点它进接受页 |
| 撤销中 | 车主侧显示撤销中；被分享人卡包里的这把钥匙与详情显示「正在收回」 |

## 5. 业务流程

### 5.1 发起与接受

```mermaid
flowchart TD
    A[卡包车钥匙卡片点分享] --> B[分享设置：给谁]
    B --> C[查该对象可用的权限档位]
    C -->|对象可分享| D[选权限与有效期]
    C -->|对象不可分享| E[给原因，不呈现档位]
    D --> F[三项齐且配额未满，点发出]
    F --> G[带幂等标识创建分享]
    G --> H{车厂云签发}
    H -->|成功| I[待接受，推送对方]
    I -->|推送未达| P2[对方进入卡包，按当前账号补拉到待接受的钥匙]
    P2 --> K
    H -->|失败| J[不留关系，提示可重试]
    I --> K{对方 72 小时内接受}
    K -->|接受且凭据下发成功| L[生效，钥匙出现在对方卡包]
    K -->|凭据下发失败| M[保持待接受，可重试]
    K -->|72 小时未接受| N[自动作废，列表可见，可重新发起]
```

本单元里「车厂云签发」「凭据下发」的结果都来自模拟的车云返回，用来验证钱包端在各分支下的表现。

### 5.2 管理与撤销

```mermaid
flowchart TD
    A[分享管理页] --> B[查看每条状态]
    B --> S{这条的状态}
    S -->|待接受、撤销中或已结束| N[只展示，不发撤销请求]
    S -->|生效| C{撤销}
    C -->|对方在线| D[立即失效，已撤销]
    C -->|对方离线| E[撤销中：对方卡片最长 36 小时内收回，被分享人一侧提示正在收回]
    E --> F[对方回网或 36 小时到，已撤销]
```

车辆侧从撤销发起那一刻起就拒绝这把钥匙；36 小时只影响对方设备上卡片的收回时间。车云接口现在返回的宽限值是 48 小时，要由车云调整为 36 小时，调整前联调口径不一致。

## 6. 异常与边界

| 编号 | 场景 | 触发条件 | 处理 | 用户看到 |
|------|------|----------|------|----------|
| E1 | 配额已满 | 生效加待接受合计到 5 | 不发请求 | 发出置灰，显示原因 |
| E2 | 待接受逾期 | 72 小时未接受 | 自动作废 | 列表可见作废条目，可重新发起 |
| E3 | 车厂云签发失败 | 创建时签发失败 | 不留关系 | 发出失败，可重试 |
| E4 | 接受时凭据下发失败 | 接受时下发失败 | 保持待接受 | 可重试，重试不产生新分享 |
| E5 | 撤销时对方离线 | 撤销请求时对方离线 | 进入撤销中，对方卡片最长 36 小时内收回 | 车主侧显示撤销中，被分享人一侧显示「正在收回」 |
| E6 | 发起被打断 | 退出页面、断网或应用关闭 | 草稿保留，续办沿用同一幂等标识 | 回来接着办，不发出第二条 |
| E7 | 断网进管理页 | 无网络 | 不展示陈旧列表 | 网络失败态，可重试 |
| E8 | 退出登录或切换账号 | 账号变化 | 清除草稿；列表与收到的分享按新账号获取 | 不带出上一个账号的草稿、列表或收到的钥匙 |
| E9 | 清除应用数据 | 本地数据被清除 | 草稿丢失不崩溃，从头选 | 回到未选状态 |
| E10 | 推送未达 | 推送没送到被分享人 | 不改变分享关系；对方进入卡包时按当前账号补拉 | 卡包里看到待接受的钥匙，点它进接受页 |
| E11 | 对非生效条目撤销 | 条目为待接受、撤销中、已作废、已到期或已撤销 | 不提供撤销，不发撤销请求 | 只看到状态；已作废、已到期的可重新发起 |
| E12 | 打开已不可用的钥匙 | 从旧入口打开已撤销、已到期或已作废的钥匙详情 | 按当前状态处理 | 提示这把钥匙已不可用，回到卡包 |

## 7. 非功能性需求

### 7.1 数据与存储

| 数据 | 要求 |
|------|------|
| 发起草稿（对方账号标识、权限档位、有效期、幂等标识） | 本地保存，扛过应用关闭；按账号隔离；发出成功、退出登录、切换账号时清除 |
| 分享列表与配额 | 不落地缓存，每次进页从（模拟的）车云拉取 |
| 被分享人收到的分享 | 不落地缓存，每次进入卡包按当前账号从（模拟的）数据源获取；真实查询接口不在六个车云接口内，另列依赖 |
| 本人钥匙信息、车辆标识 | 本单元由模拟数据提供；真实来源与车云联调另列依赖 |

### 7.2 安全与隐私

| 要求 | 说明 |
|------|------|
| 输出面脱敏 | 页面与记录只显示对方昵称与打码账号；打码在生成展示内容处做（`CommFunc` 的 `MaskUtil`），列表用车云返回的打码标识；日志与事件不带账号 |
| 业务身份 | 查权限与创建分享传可识别的对方账号标识；展示用的打码值不承担业务身份；打码后相同的两个账号仍要能区分 |
| 草稿中的身份 | 草稿里的对方账号标识只用于续办请求，不进入页面、日志与事件 |
| 事件字段 | 发起、接受、撤销、失效四类事件只带车型类别、阶段与结果分类，不带车牌、账号、位置 |

### 7.3 兼容性

| 维度 | 要求 |
|------|------|
| 设备 | 手机 |
| 深色与大字 | 车辆信息与主按钮可读可点 |
| 错误码 | 沿用车云既有错误码，不新增 |

## 8. 验收标准

AC-1–AC-11 承接产品稿验收意图 AC-K1–AC-K11。所有结论只到本地模拟数据；与车云的真实联调不在本单元验收内。

### P0

- [ ] **AC-1**（F2/F3）：卡包车钥匙卡片点分享，对象、权限、有效期三项都选齐前不能发出；选齐后发出，对方收到待接受的钥匙
- [ ] **AC-2**（F5/F6）：对方接受后钥匙可用，权限与车主所选一致，钥匙作为车钥匙卡片出现在对方卡包
- [ ] **AC-4**（F2/F4）：生效加待接受合计到 5 后不能再发起，能看到原因
- [ ] **AC-5**（F4）：撤销时对方在线立即失效；对方离线进入撤销中，对方设备上的卡片最长 36 小时内收回，被分享人一侧显示「正在收回」；撤销起车辆侧就不认这把钥匙
- [ ] **AC-6**（F3）：发起途中退出页面、断网或关掉应用再打开，回来接着上次的选择发出，沿用同一幂等标识，不发出第二条
- [ ] **AC-7**（F4）：管理列表的状态与车云返回一致：待接受、生效、已作废、已到期、撤销中、已撤销
- [ ] **AC-9**（F1）：未登录或没有车钥匙的用户看不到分享入口
- [ ] **AC-10**（F1）：开关关闭后不能发起新分享，已生效的分享不受影响
- [ ] **AC-11**（F2）：选家庭成员时全功能可选；换成其他联系人后全功能不可选，已选的全功能请车主重选；换回家庭成员又可选
- [ ] **AC-12**（F0）：卡包展示车主本人的车钥匙卡片与接受成功的钥匙卡片，本人钥匙卡片上有分享与分享管理入口
- [ ] **AC-13**（F3/F7）：发出成功、退出登录或切换账号后草稿被清除，换账号后看不到上一个账号的草稿或列表
- [ ] **AC-14**（F7）：两个打码后相同的合法账号，查权限与创建分享时各自拿到正确的对象
- [ ] **AC-24**（F8）：推送没送到时，对方进入卡包能看到待接受的钥匙，点它进入接受页并能添加
- [ ] **AC-25**（F8）：接受成功后，卡包里的待接受项变为可用的钥匙卡片；接受失败仍保持待接受
- [ ] **AC-26**（F8）：车主撤销且对方离线时，被分享人卡包里的钥匙与详情显示「正在收回」；收回完成后卡片移除
- [ ] **AC-27**（F8）：撤销完成、到期或作废的钥匙从卡包移除；从旧入口打开它的详情时提示已不可用并回到卡包
- [ ] **AC-28**（F7/F8）：切换账号后，卡包只显示新账号收到的待接受与可用钥匙
- [ ] **AC-29**（F4）：只有生效的分享显示撤销；待接受、撤销中、已作废、已到期、已撤销的条目不显示撤销，也不发撤销请求

## 9. 不承载与依赖

| 项 | 说明 |
|------|------|
| 被分享人再转给第三人 | 上游待安全评审，不承载（D2） |
| 撤销后极端断网强制下线 | 上游在和车厂谈，不承载（D6） |
| 车云真实接口与本人钥匙真实来源 | 本单元用模拟数据，真实联调另列依赖（D3） |
| 被分享人一侧的钥匙查询 | 六个车云接口没有按接受方账号查待接受与已接受钥匙的接口；本单元由模拟数据提供，真实接口由车云提供（D3） |
| 推送点击进入接受页 | 工程里没有推送通道接入，宿主入口也不读分享参数；本单元的接受入口是卡包里待添加的钥匙，推送通道与点击跳转另列依赖 |
| 车云接口宽限值 48 → 36 | 由车云调整接口返回值；调整前与车云的联调口径不一致（D1、D8） |
| 真车开锁、凭据签发与设备能力 | 不在本单元（D5） |
