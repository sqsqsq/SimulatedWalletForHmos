- 情景终点：需求级完整评审。
- 目标产物：`AR/story.md`、`AR/review.md`、`assets/` 配图（取自《数字车钥匙分享》与《车钥匙接受侧界面说明》抽出的界面图）。
- 输入：`test/cases/car-key-sharing`（基底 `15844e09`；交互脚本 10-09 补立场后为 `0d48bdfea52c1989`，`case.yaml` 为 `720a0293704355c6`，评审回稿 `ebbad8571f846f95`，记账见 `test/EVOLUTION.md` §7）。目标工程 demo 与知识取 `15844e09`。
- 有效宿主立场：补料一次交齐；不拆单；`grace-window-initial`（宽限 48 小时指卡片收回，车辆侧即拒绝，D1）；`car-key-card-scope`（一并补卡包车钥匙卡片与分享入口，D5）；`no-real-interface`（模拟数据验证钱包端，真实联调另算，D3）；`draft-resume-boundary`（退出页面、断网、应用关闭都能续办，D7）；`terms-confirmed`；交付选实现方案。
- 设计选择：车主本人钥匙信息、车辆标识与分享关系都先用模拟数据（并入 D3），真实来源另列依赖；被分享人一侧按账号查收到的分享也先用模拟数据（六个接口里没有对应接口）；对方账号在业务请求里传可识别值，展示用打码值；再转第三人（D2）与强制下线（D6）不承载。
- 相对旧稿的具体优化：按修订合同改正 G04 业务身份与打码值分开、G05 草稿边界与模拟承载按立场定案、G06 卡片入口落到卡包页、G07 撤销只从生效态、G09 示范回填不当人签；补上被分享人补拉待接受、收回中与终态移除；流程章讲跨能力链条、功能章只讲页面规则，「撤销中不等于还能用」只在术语与撤销链条讲；删去指着文档说话的句子。
- 可参考的表达位置：分享生命周期的状态图与逐条迁移条件；接受链条里推送未达的补拉；附录端云接口的业务摘要。
- 这是期望结果：人的回答取自 Case 设计的宿主立场，是构造预期的输入，不是已发生的人签；它不证明产品已能产出这份结果。
