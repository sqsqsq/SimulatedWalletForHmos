## 4. 术语确认按真实证据

10-03 实跑的车钥匙段只发生过三次提问：材料、范围、交付门。流程契约里没有术语关卡。交互脚本里的「术语确认，按你列的定」从来没有被问到，也就没有送出过。所以三条术语都**没有被人确认过**：

- 车钥匙分享
- 权限档位
- 分享状态

它们不能记为 `user_confirmed`。实跑是交互运行，也不是 headless，所以原来的 `headless_assumed` 同样不对。按原生术语检查（`framework/harness/scripts/utils/blueprint-discovery.ts` 193–209 行），这三条现在如实记为 `inferred_by_designer`。原生检查器据此报三条阻断：交互态须当场确认并记 `user_confirmed`。

这是真实缺口：要等生产入口真实走到术语确认、人回答之后，才能按回答逐条记 `user_confirmed`。本候选不会借术语更正恢复准入，旧质询里提到 `headless_assumed` 的那条历史回答也不改。
