## 2. 议题与依据

| 议题 | 状态 | 依据 |
|---|---|---|
| D1 撤销宽限 | 已定：对方设备上的卡片最长 48 小时内收回，车辆侧撤销即拒绝 | 产品稿 24h 与系统设计 48h 冲突，问需求方；答复取自立场 `grace-window-initial` |
| D2 再转给第三人 | 待定 | 产品稿「还没定的两件事」第 1 条 |
| D3 接口未就绪时的承载 | 已定：按冻结契约用模拟数据验证钱包端，真实联调另行验收、不算验过 | 立场 `no-real-interface` |
| D4 功能开关 | 已定 | 产品稿 AC-K10 与系统设计一致 |
| D5 入口与卡包展示 | 已定：钱包端一并补卡包车钥匙卡片展示与分享入口，接受成功的钥匙也在卡包；真车开锁、凭据与设备能力不做 | 产品稿假设车钥匙卡片已上线，工程里没有（有意保留的工程事实探针）；答复取自立场 `car-key-card-scope` |
| D6 强制下线 | 待定 | 产品稿「还没定的两件事」第 2 条 |
| D7 草稿续办边界 | 已定：退出页面、断网、应用关闭后重开都能续办；发出成功、退出登录、切换账号后清除 | 材料没写「退出」包不包括应用关闭，问需求方；答复取自立场 `draft-resume-boundary` |
| D8 车主本人钥匙的来源 | 待定（建议由车云提供接口），蓝图登记阻断缺口 `owner-key-source` | D5 定案后的直接后果：材料只约定了分享六个接口。Case 设计里**没有**对应立场，已交设计者（第三轮交回 §3） |

术语：车钥匙分享（产品稿标题）、权限档位（产品稿规则表）、分享状态（系统设计「分享状态机」、AC-K7）三条都出自材料，映射到 WalletMain。按立场 `terms-confirmed` 记为 `user_confirmed`。这是构造预期；10-03 实跑里术语关卡没出现，原因在第三轮交回 §4 调查。

## 3. 生成方式

| 步骤 | 做法 |
|---|---|
| 底稿 | 10-03 实跑工作区 `car-key-sharing` 的副本 `output/scratch/2.0.3-p1/ck-review`，换装当前开发版扩展 |
| 修订 | 蓝图：`revise_ck_bp.py`、`split_d2.py`、`settle_ck_initial.py` 做文本修订。新增开发节点 `car-key-card`；两条待定决定改为人已定；宽限缺口撤下，入口缺口换成 `owner-key-source`；草稿明细补上应用关闭；术语确认。决定指纹与来源指纹按原生算法重算（`decision_fp.py`、`source_fp.py`），原生 renderer 重渲投影 |
| 审查状态 | `questioning.status: pending`，`admission` 派生为 `blocker`（`mark_unadmitted.py`）；原生检查只剩缺独立质询一项 |
| 人读件 | 第 1–9 章经 `chapter` 提交，Review 经 `build` 渲染，编号经 `number`；附录 `chapter` 在未准入时被拒，当前稿由 `assemble_story.py` 组装 |
| 未做 | 独立质询、准入、附录重投、独立审查、成文登记 |
