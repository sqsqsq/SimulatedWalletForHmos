## 2. 草稿保存方式：设计选型，不交人拍板

按复核 Q3 裁定，先确定草稿要扛过哪些中断，再据约束选介质：

- **约束**：产品稿 AC-K6「发起途中退出或断网，回来接着办，不会发出第二条」；系统设计「发起途中退出或断网，回来凭它接着办；发出成功即清除；按账号隔离，退出登录清除」。
- **推断**：「退出登录清除」只有在草稿能跨过应用进程存活时才有意义；「退出」也没有限定为只退出页面。要承接的中断应当包括退出页面、应用被关闭或杀进程、断网。
- **选型建议**：用按账号隔离的本地持久化保存草稿；发出成功、退出登录、切换账号时清除。草稿里的对方账号标识只用于续办请求，不进入页面、日志与事件。
- **与实跑产物的差别**：实跑 Plan 第 163 行写「会话本地」，杀进程就会丢失，扛不住上面的中断，要改。

这是由约束推出的设计结论。如果设计者认为「退出」只指退出页面，介质可以降为内存，并在 Spec 里写明边界。
