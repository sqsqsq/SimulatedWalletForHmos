## 2. 草稿保存方式：已知约束与待澄清的边界

已知约束：

- 产品稿 AC-K6：「发起途中退出或断网，回来接着办，不会发出第二条」；
- 系统设计：「发起途中退出或断网，回来凭它接着办；发出成功即清除；按账号隔离，退出登录清除」。

也就是说，草稿要能续办、按账号隔离、发出成功后清除、退出登录时清除。

**未知**：应用被关闭或杀进程之后，用户回来还要不要接着办。上一版从「退出登录清除」推出「必须跨进程保存」，这个推断不成立：放在内存里的草稿，同样需要在切换账号或退出登录时清除。所以撤下这条推断，也不反过来默认「退出」只指离开页面。

这条边界要请需求负责人澄清，介质由设计者据此选：

| 澄清结果 | 设计建议 | 利 | 弊与安全约束 |
|---|---|---|---|
| 杀进程后也要能续办 | 按账号隔离的本地持久化；发出成功、退出登录、切换账号时清除 | 满足最宽的中断边界 | 草稿里有可识别的对方账号标识，落盘要按隐私规约处理（不进日志与事件，按账号隔离，及时清除） |
| 只要求页面退出与断网后能续办 | 进程内保存，切换账号或退出登录时清除 | 不落盘，隐私面更小 | 应用被关闭后草稿丢失，要在 Spec 里写明这条边界 |

实跑 Plan 第 163 行写的「会话本地」，相当于第二种做法，但 Spec 里没有写明这条边界。
