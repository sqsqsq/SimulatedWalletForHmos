# auto-topup/initial

- 情景终点：系统送审，零施工单位。
- 目标产物：`AR/story.md`、`AR/review.md`、`assets/` 配图（取自产品原稿《交通卡自动充值》抽出的界面图）。
- 输入：`test/cases/auto-topup`（基底 `15844e09`；交互脚本 10-09 补立场后为 `91d5d59473d57dee`，答案卷 `999e5cc4b578744d`，记账见 `test/EVOLUTION.md` §7）。目标工程 demo 与知识取 `15844e09`。
- 有效宿主立场：会议各话题按 `meeting-*`（加更新接口；AC-R1 与开关按会上改；充值记录按月筛选不属本单；调高面额是否重验、授权后建约失败保持待定）；范围不拆；术语确认；送审。
- 设计选择：授权后创建失败分「明确失败」与「结果未知」，结果未知以状态查询确认、不当成没签成；面额调整（调高、调低）的验证待定，只改门限不验证已定；缓存缺失与查询失败不推断未签约；「创建签约成功率」与业务目标「签约转化率」分开。
- 这是期望结果：人的回答取自 Case 设计的宿主立场，是构造预期的输入，不是已发生的人签；它不证明产品已能产出这份结果。
