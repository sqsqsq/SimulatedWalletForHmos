## 1. 生成方式

| 步骤 | 做法 |
|---|---|
| 底稿 | 10-03 实跑初段快照 `doc/features/{AR90006,bp-AR90006}`，放回实跑保留的工作区副本 `output/scratch/2.0.3-p1/at-initial`，换装当前开发版扩展 |
| 蓝图 | 用实跑作者的蓝图生成器重跑（先验证能逐字节复现原蓝图），修订脚本 `output/scratch/2.0.3-p1/revise_at_gen.py`、`revise_at_details.py`；原生 `check:component-blueprint` PASS，原生 renderer 重渲投影 |
| 人读件 | 改章草稿后逐章 `chapter` 提交；决定登记、会议结果、写作设计由 `revise_at_story.py` 修订；`review --action prepare` 重投附录、编号、渲染 Review、生成设计附件，结构检查通过 |
| 未做 | 独立审查（要调用模型，需要授权）；成文重新登记（要在审查之后） |

导出内容：`AR/` 下的三件，加上修订过的决定登记、会议结果和写作设计；`bp-AR90006/blueprint/` 下的原生蓝图、投影和契约来源。图片与冻结输入仍在底稿里，没有复制。

## 3. 一处人签的承接方式

会议关卡给人的 T6 选项 a 写的是「保持待定：等卡云与支付对齐协议号有效期，端侧暂定复用同一协议号重试并标未决」，实跑里人选了 a。宿主立场（交互脚本 `meeting-failed-contract`）和答案卷都是「授权后建约失败怎么处理，保持待定」。

这条选项把一个临时做法捆进了「保持待定」，候选按「保持待定」承接，不采用捆进去的「暂定复用」。人签原件保持原样。产品侧的问法已经在 2.0.2 P1 改为一项一决定、临时做法单列。如果审定时认为这一选择本身批准了「暂定复用」，就需要改回，请用户裁定。
