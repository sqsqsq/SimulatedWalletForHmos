## 1. 阅读入口

在 output 下保留了同字节的阅读副本，路径是 `output/story/2.0.3-p1-candidates/auto-topup/initial/`。它保留了需求目录的相对布局，正文图片、冻结来源与原件都在原位置，可以直接打开阅读：

| 读什么 | 打开 |
|---|---|
| Story | `output/story/2.0.3-p1-candidates/auto-topup/initial/doc/features/AR90006/AR/story.md` |
| Review | 同目录 `review.md` |
| 设计附件 | 同目录 `design-review.md` |
| 冻结来源 | `doc/features/AR90006/AR/story-src/inputs/0ac5c65d…/files/`（附录「本次冻结材料」逐份链接到这里） |

本目录（doc/plan）是唯一可编辑的候选，阅读副本由 `output/scratch/2.0.3-p1/export_candidate.py` 从生成工作区重建。导出时会核两件事：人读三件与蓝图跟本目录逐字节相同；三件里的 20 个本地链接全部指得到文件。

## 2. 生成方式

| 步骤 | 做法 |
|---|---|
| 底稿 | 10-03 实跑初段快照 `doc/features/{AR90006,bp-AR90006}`，放回实跑保留的工作区副本 `output/scratch/2.0.3-p1/at-initial`，换装当前开发版扩展 |
| 蓝图 | 用实跑作者的蓝图生成器重跑（先验证能逐字节复现原蓝图），修订脚本 `revise_at_gen.py`、`revise_at_details.py`；原生 renderer 重渲投影 |
| 审查状态 | 内容修订之后，旧的独立质询不再是当前内容的审查证据：`review_summary.questioning.status` 记为 `pending`，`admission` 按原生检查器派生为 `blocker`、`root_questions_complete: false`（`mark_unadmitted.py`）。旧质询的逐项记录保留，作为上一轮的历史来源。原生检查只报 `blueprint_questioning_provider_missing` 一项 |
| 人读件 | 改章草稿后逐章 `chapter` 提交；决定登记、会议结果、写作设计由 `revise_at_story.py` 修订；附录机器区、编号与 Review 由此前的 prepare 生成。R1 返修在未准入状态下经 `chapter` 和 `number` 提交 |
| 设计附件 | 设计附件的定义是原生投影的逐字节副本。蓝图未准入时 prepare 不会生成它，这里按同一定义从重渲的投影复制，所以附件里显示的是质询 `status=pending` |
| 未做 | 独立质询、准入、独立审查、成文重新登记（都要等授权的模型调用） |

## 4. T6 按 Case 立场保持待定

会议话题 T6（授权后建约失败怎么处理）在 Case 设计里的宿主立场是「保持待定」（交互脚本 `meeting-failed-contract`，答案卷「端侧处理待定，不能按十分钟写」）。所以候选里的 D4 保持 open，不批准协议号复用，也不批准十分钟期限；「保持待定」这一结论不写成处理方案已定。

10-03 实跑里，模型给出的选项 a 把「保持待定」和「端侧暂定复用」捆在了一起，宿主选了 a。这是会议问法的产品缺陷，2.0.2 P1 已改为一项一决定、临时做法单列。这条历史回答原样保留，不改。
