# auto-topup/update 候选：来源与语义差异

> 情景终点：在初段之上承接产品需求 v1.1 与评审回稿，完成更新交付。单日上限 200/300 的冲突没有取得有效裁决，所以本候选是**待裁定候选**：D11 摆给产品负责人，正文不写死数值。来源锁定见 [00-来源与决定核对](../../00-来源与决定核对.md)。
> 状态：**待裁定候选，附录未重投**。蓝图未准入（修订后还没有重新做独立质询）。附录的机器区要等准入后才能投影，见 §4。这份候选不是正式金样。

## 1. 阅读入口

| 读什么 | 打开 |
|---|---|
| Story | `output/story/2.0.3-p1-candidates/auto-topup/update/doc/features/AR90006/AR/story.md`（附录是实跑 update 段的旧版，见 §4） |

| Review、设计附件 | 阅读副本同目录的 `review.md`、`design-review.md` |

导出时核两件事：人读三件与蓝图跟本目录逐字节相同；三件里的 10 个本地链接全部可达。

## 2. 生成方式

| 步骤 | 做法 |
|---|---|
| 底稿 | 10-03 实跑 update 段之后的工作区副本 `output/scratch/2.0.3-p1/at-update`。实跑已经完成新输入冻结（`12f4a1ea…`，含 v1.1 与评审回稿）、update 记录、蓝图 r2 与决定 D9–D11 |
| 蓝图 | r2 生成器先验证能逐字节复现，再套用与初段相同的修订（`revise_at_gen.py`），加上配置与埋点明细（单日上限写成待裁定），并修改字段映射里写死的「单日最多充 200 元」（`revise_atu_bp.py`）；原生 renderer 重渲投影；审查状态如实标为未准入（`mark_unadmitted.py`） |
| 人读件 | 先套用初段的正文与决定修订（`revise_at_story.py`），再做 update 专属修订（`revise_atu_story.py`，包括 R1 签约链与充值链分开）。第 3–9 章经 `chapter` 提交，Review 经 `build` 渲染（标题带 D 编号），编号经 `number` 处理 |
| 设计附件 | 按原生投影逐字节副本的定义，从重渲的投影复制 |

## 3. 语义差异（相对实跑 update 段）

| 项 | 实跑 update 段 | 候选 | 依据 |
|---|---|---|---|
| D11 单日上限 | settled「本期维持 200 元」，依据写「人确认按会上定的，本期 200 元」 | open 选择题：200（澄清会）或 300（v1.1），建议 200；业务方案只写「协议文案写明单日上限，取值待 D11 裁定」；配置明细、字段映射、update 记录同步 | 10-03 那句回答不在授权的需求方立场之内，复核 Q1 裁定不能凭「已发送」推定它有效 |
| D9 停用横幅重签入口 | 已采纳 | 保持 | 评审回稿第 3 条「要改」 |
| D10 发票开具入口 | 本期不做 | 保持 | 评审回稿第 4 条「这次先不做」 |
| 初段的 G01/G02/G03/G08、R1、范围矛盾、SEC-01 | 未修 | 与初段候选同样修订 | 见 [initial README](../initial/README.md) §3 |
| 附录采用说明 | 旧格式作者列表 | 草稿里写明 v1.1 采用了什么、哪处冲突，以及评审回稿四条各自的去向（作者区，见 §4） | v1.1 原文；评审回稿 |

保持不变的部分：冻结输入、人签记录（含 update 段那条回答的原始记录，只是不再当作裁决）、D2/D5–D10 的结论。

## 4. 附录没有重投（问题已交设计者）

实跑的 update 段附录还是 2.0.1 的旧格式。按当前合同重投附录的机器区，需要蓝图先准入；而按复核 R2，修订后的蓝图在独立质询之前不能记为准入。所以：

- `story.md` 的附录仍是实跑时的旧版：旧版 SEC-01 判断、字段映射里的「单日最多充 200 元」都还在，与修订后的蓝图不一致；
- 修订后的附录作者区（端云接口、数据存储、规约的业务摘要，采用与取舍说明）在 `AR/story-src/drafts/10-附录.md`。`chapter` 提交时拒绝了这份草稿，原因是机器区投不出来；
- 准入之后跑一次 `chapter`（附录），再 `review --action prepare`，附录就会按新蓝图生成。

auto-topup/initial 没有这个问题：它的附录是在 R2 之前就投好的，机器区内容只取自蓝图正文，不受审查状态影响。
