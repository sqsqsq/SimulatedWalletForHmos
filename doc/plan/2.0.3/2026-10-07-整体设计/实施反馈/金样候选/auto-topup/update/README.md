## 3. 语义差异（相对实跑 update 段）

| 项 | 实跑 update 段 | 候选 | 依据 |
|---|---|---|---|
| D11 单日上限 | settled「本期维持 200 元」 | 结论相同（200 元、300 不采纳）；依据改写为「登记成议题问需求方，需求方答复…」，update 记录注明答复取自 Case 立场的构造预期 | 交互脚本 `update-daily-limit-conflict`；答案卷「上调到 300 的提议被否决」 |
| D9 停用横幅重签入口 | 已采纳 | 保持 | 评审回稿第 3 条「要改」 |
| D10 发票开具入口 | 本期不做 | 保持 | 评审回稿第 4 条「这次先不做」 |
| 初段的 G01/G02/G03/G08、R1、范围矛盾、SEC-01 | 未修 | 与初段候选同样修订 | 见 [initial README](../initial/README.md) §3 |
| 附录采用说明 | 旧格式作者列表 | 草稿里写明 v1.1 采用了什么、哪处冲突，以及评审回稿四条各自的去向（作者区，见 §4） | v1.1 原文；评审回稿 |

保持不变的部分：冻结输入、人签记录（含 update 段那条回答的原始记录，只是不再当作裁决）、D2/D5–D10 的结论。

## 4. 当前稿怎样组成（按 10-08 设计者裁定）

实跑 update 段的附录还是 2.0.1 的旧格式，内容与修订后的蓝图相反。附录机器区的投影要求蓝图已准入；而按复核 R2，修订后的蓝图在独立质询前不能记为准入。设计者裁定：旧附录不能作为当前稿的一部分；候选可以停在未准入；能同步的正文与作者草稿可审；投不出的机器投影标为缺件；旧的完整产物只作独立的历史对照。

所以当前稿 `AR/story.md` 不是由脚本一次生成的完整成品，而是这样组成的（`output/scratch/2.0.3-p1/assemble_update_story.py`）：

- 第 1–9 章：取工作区里经 `chapter` 提交、`number` 编号后的 story.md，逐字节照搬；
- 附录：取修订后的作者区草稿 `AR/story-src/drafts/10-附录.md`（本目录保留了原件），去掉草稿指引行，按章节编号补上标题号；
- 配置项、埋点、改动边界、本次冻结材料四节：写明缺件，蓝图准入后经 `project` 生成。

蓝图准入要等用户授权的独立质询及其处理。准入之后经原入口重投：先跑附录的 `chapter`，再 `review --action prepare`，最后登记。不改生产准入门，也不新增草稿投影器。
