# P4 综合验证、金样切换与完成

需求：[R4](../../../spec/2.0.3/04-综合验证与成本观测/需求.md)；金样消费者迁移按 [05 金样职责修正与执行合同](05-金样职责修正与执行合同.md) §4。本步承接 G1/G2/Q1、审查有效性和需求执行成本；安装与 SVG 增强不混入本轮变量。

## 三类证据分开签收

| 证据 | 证明什么 | 怎样取得 |
|---|---|---|
| 金样 | 给定输入下期望的交付结果已明确 | P1 候选经独立内容评价与用户审定 |
| 专项回归 | 确定性机制（章节写入、机器投影、附件同源、编号、人工区保护、来源与审查对象绑定）正确 | 现有 verify.py，用专项夹具 |
| 授权的真实 CLI | 消费模型的实际过程、结果与成本 | 用户授权后跑两个正常 Case |

三者共享需求依据，不互相冒充完成。真实 CLI 与成本验收是版本完成条件，不是编写期望稿的前置。

## 验证顺序

1. 每包定向自验后核实际源版本，最终跑现有 `verify.py handback`，已知历史失败单列，不用全绿替代内容评审。
2. 按 R4 场景核 P1 候选与原始来源、宿主立场，核正常与相关异常、不同合法输入。
3. 获授权后跑两个正常 Case，按实际索材与问题回答：自动充值按初段 submitted＋update，车钥匙按 plan 上限＋update；金样和维护答案不进入消费工作区。实跑产物与金样按语义与读者效果比对，允许合理的组织、图形、设计与施工单位划分差异，不比内部状态或中间路径。
4. 依规格 R3 §3 的配对与非增长条件评价成本；用户按 TEST 三轴确认消费效果，Coding、设备、内网无证据的保留未验证。

## 通用性与正常行为的交回

执行规格R4 §2.1的五类验证：业务替换、不适用、合法变形、真实反例、机制反例。复用test_writing_flow、test_writing_plan、test_review_render、test_verifier_report_protocol、test_neutral_knowledge及原生CU专项夹具；相关输入由现有夹具派生，不另造完整Case或通用评测平台。

机械回归检验身份、引用、装配与保护；维护语义走查给实际材料/结果和理由；授权独立评价给原始输入与回复。合法变形不要求与金样逐字、同图或同CU；无相应业务不强迫编内容。审提示、注释和测试断言是否仍隐含某个Case的对象数量、固定数值、词条或路径，不能只报专名搜索零命中。

正式双Case按同一有效输入审五项：内容/表达是否达金样效果；知识与决定是否先于行动送达；独立审查是否抓到真实错误并回最早责任修复；重复读取/派审/返修有无信息增量；原能力保持与旧职责是否退出。交回可定位原始证据，未发生的行为明确未验证。

## 消费者迁移与正本切换

不新增框架、运行器或金样生成器。先登记实际消费者与有效覆盖，再迁移，不能只换名搬走整套旧装配。

| 当前对象 | 动作 | 必须保持 |
|---|---|---|
| `golden_workspace.py`、`golden_design.py` 及蓝图夹具 | 退出效果金样的整链装配、旧格式映射与重投；消费者迁完后删除失效实现 | 有效的机制场景改用 `design_fixture` 等现有专项夹具 |
| `test_golden_sample.py` | 检查目标文件、配图、链接与审定版本；退出要求金样拥有准入现场的断言 | 金样完整性；业务质量由语义评价核 |
| `test_review_render.py`、`test_review_modes.py` | 用小型明确输入与确定性预期，不从整份业务金样反推登记状态 | 编号、分组、人工区保护、重复渲染 |
| `test_story_build.py`、`test_verifier_report_protocol.py` | 用既有专项夹具验证生产入口 | 章节写入、机器投影、附件同源、来源与审查对象绑定 |
| `check_failure_modes.py` | 把对整份金样装配的依赖迁为对应机制的正反例，同步台账引用 | 正常输入不误拒、错误能发现、判据实际执行 |
| `test/golden/README`、指纹、枚举与唯一副本检查 | 消费新路径与职责；删除「拦金样必然是判据错」的说明 | 已审结果唯一、变化可追溯 |

字节比较只用于确定性渲染、审定文件保护与副本一致性。用户审定目标金样、覆盖迁移通过后，一次把两 Case 的正式正本切到 `test/golden/<case>/<情景>/`；方案候选退为审定证据，不继续双份编辑。旧样本独有的有效场景逐项指出新承接或保留为小型专项输入，不随旧正本误删。

切换未获审定或迁移失败时，旧正本继续供既有回归，新候选只供审核。审定金样与原始来源都是复核依据：失败先定位来源、样本或当前规则是否真实变化，再回责任方修，不以金样名义豁免有效约束；指纹只保护已审字节，不证明业务永远正确。

## 1.x分析的逐项承接与退出核对

事实输入为本目录实施反馈/2026-10-09-1.x分析承接核对.md及其原始分析链接；本表是当前责任分配。旧报告的“当时存在”不代表当前仍存在，也不以缺专用脚本判定能力缺失。

| 历史项 | 当前归属与交回证据 |
|---|---|
| 数值单位、来源名粒度、自设阈值漂移 | P2数值/来源合同，交作者送达位置、真实决定落点及合法/错误内容走查；不恢复单位白名单 |
| 说明性引用块、H1与格式 | P2区分模板残文和业务引文；H1沿当前章节合同与既有结构检查，核不同合法标题；不恢复旧Spec规则 |
| 承接两式、指标粒度、统计点列集、术语列序、来源名形态 | P2五项定案；逐项核当前合同与产物，允许表达差异，不制造五个新checker |

| 审查自激与同材料反复派审 | P3保持现有materialKey与复用；test_verifier_report_protocol已有相同/变化/原回复损坏用例；CLI核实际派审原因 |
| 终检过晚、环境堆栈、缺恢复出口 | P3入口三类负例，交调用方看到的输出和成功状态未写证据 |
| 218条裁决与反复检索 | P3现有任务和章级读取，机械完整性与真实执行成本分别核，不以减条目获得减载 |
| reopen/update冲突 | P3现有状态与范围/表达/恢复回归，CLI观察update正常收口 |
| 本地单 | car-key-sharing即本地入口，test_multi_scenario_cases/test_material_delivery与真实Case核；不是覆盖空白 |
| 无埋点、不适用、空章 | test_story_build已有无设计对象、作者区为空与“不涉及”路径；合法不适用通过，必需内容缺失失败，不因没有表强造内容 |
| 无待决Review | test_story_build的empty register及test_review_render/test_review_modes核无待决与已有决定；不补示范人签 |
| 多流程/多指标、状态图/依赖顺序图 | 用现有writing_plan/writing_flow/Story夹具核来源及合法形态；独立内容评价核指标/事件区别与关系完整，不要求每份金样各放一张图 |
| 接口复用/变更、新错误码/依赖新增 | test_knowledge_task/test_cu_knowledge_chain与原生设计夹具核引用、义务传递；语义核变更范围与兼容责任，不要求Case虚构新增接口或错误码 |
| 模式零候选、选择与不选择 | test_knowledge_application/test_neutral_knowledge/test_cu_knowledge_chain核激活、适用判断、角色与实体；没有适用模式不得造角色，坏激活登记不能作为零候选 |
| 兄弟单与跨CU责任 | 现有范围/蓝图夹具中核各自承担对象、共同依赖及顺序；语义核不遗漏与不重复。不要求实际CU数量与金样相等 |
| 原始验收编号、显式不适用、Review建议理由 | 当前story-write、story-chapters及review渲染已承担；回归保持编号来源、理由与人工区，模板形态不代替内容 |
| 历史README批注与“数量少即缩水” | P2/P4同步当前合同；旧绝对裁定与数量质量阈值退出，已审字节保护保留 |

执行者逐项给出现有具体用例/产物位置和结果；表中测试文件名是归属入口，不声称每一行已有完整覆盖。确有机械缺口在对应现有文件补最小正反例；语义项交实际内容走查，授权后再核独立执行效果。不存在生产消费者的历史项记录已退出依据，不重建功能。只为补覆盖表而新增完整CLI Case不在本轮范围。

消费者切换同时核新case/情景/AR目录的_golden_titles与test_knowledge_forms枚举、金样来源链接和候选图片边界；旧说明指纹更新须记录实际理由。通过不能只看总测试数不变，应核每项原有效覆盖由谁接替。
