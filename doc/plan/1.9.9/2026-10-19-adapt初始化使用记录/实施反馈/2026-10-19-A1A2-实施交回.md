## 1. A1：记录器与适配接线

**记录器**：`skills/story/scripts/core/usage.py` 新增两个动作，走原有 stdin JSON 入口，不要 feature 与 step。

- `ensure`：
  - 在已有锁内重判文件在不在；
  - 缺了，就用 `load` 给出的空表（schema 取自合同）经原子 `save` 建立；
  - 在了，只按合同解析校验，一个字节不改，也不对账、不建需求节点；
  - 输出沿用 `{ok, changed, errors, requirement, pending_init}`。
- `inspect`：只读，缺失时明说，不建目录、锁或临时文件。

`reconcile` 缺文件不建表的原义不变，旧格式照旧拒绝。

**适配接线**：`skills/story-adaptation/scripts/adapt-scan.mjs` 经扩展自带的桥接 `hooks/shared/usage.mjs::recordUsage` 调记录器，不复制校验器，也不写 JSON 模板。

| 环节 | 做法 |
|---|---|
| `--apply` 前置 | 目标已有 `doc/usage.json` 时，先用**包**的记录器 inspect。不合法（坏 JSON、冲突标记、旧 schema、节点不合合同）就在写任何机制文件之前停下，退出 2，原文件保留。usage 不在写入面里，它有未提交改动不会挡升级，也不会被覆盖 |
| `--apply` 收尾 | 机制、manifest、跳板、入口、`.gitignore`、首装配置都写完之后，经**目标已装**的桥接 ensure。首装、升级、同版本补文件三条路径都走这里，包括原来「没有机制文件要写」那条提前返回 |
| 建立后的提示 | 建立时提示「已建立使用记录 doc/usage.json（schema 1，还没有需求）：它归目标，与这次升级改动一起提交」；已在时提示「已在且合法，保留未动」 |
| 建不起来时 | 写明机制文件已写完、不用重跑 --apply，给出只补这一份的命令：`echo '{"action":"ensure"}' \| python doc/extensions/skills/story/scripts/core/usage.py --project-root '<目标根>'`，再跑 --check；整体退出 1，不说「升级完成」 |
| 仍被忽略规则挡住 | 同样退出 1，并说明「未解决前适配不算完成」。原来这里只打一句警告、退出 0，这条警告已并入同一处 |
| `--check` ④ | 用 inspect 只读核：缺失时提示「缺了跑 --apply 建立」，坏了提示修好后重验、不重置成空表 |
| `--status` | 不变，不建文件 |

本次发现并已处理一处副作用：adapt 调目标里的 Python 记录器，会在目标的 `doc/extensions` 下留 `__pycache__`。目标仓没有忽略字节码时，下一次 `--apply` 会因为写入面有未提交文件而停下。现在桥接调用前设 `PYTHONDONTWRITEBYTECODE=1`，不再留字节码。
