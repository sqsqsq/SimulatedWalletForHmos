# 1.9.9：可核验的完整交付与稳定执行

2026-10-14，维护设计者。按用户本轮“综合问题、从 Extension 能力正向实现、可靠 harness、整体重新方案”的要求重写。本套五份正文为当前实施合同，历史分析与交回只供追溯。只制定方案，不修改产品、测试装置或 demo，不启动模型测试。

## 1. 重新诊断后的目标

用户需要消费模型取得真实输入，作出有依据的决定，交付完整、正确、可读的需求成果，并以合理成本完成更新与归档。此前方案把新增指引、局部门禁和最终行为混在一起，无法说明模型漏做某件事时谁会发现，也没有证明现有独审能识别关键错误。

本轮改造现有作者、检查、独审和操作入口的协作，不建设新框架。以实际输入推导必须处理的对象；脚本控制可计算的完成条件、顺序、身份和副作用；独立模型判断业务含义；隔离测试验证这套分工能否抵抗漏做、误解、编造与跳步。语义结果仍有不确定性，不能因套上 harness 就宣称正确。

| 已核现象 | 最早失效的能力 | 本套解决方式 |
|---|---|---|
| 两 Case 都读到可选阅读图指引，却没有 mmd/SVG | 必交视图变成可选动作，后续检查只枚举已登记对象 | 从 Story 实际图块派生工作；缺生成、质量证据或有效视图均不能算阅读完成 |
| 超时写成远端无记录，待定实际选边，update 改错权限仍通过 | 决策输入和审查范围不足，独审区分能力未经验证 | 原件、现行决定、工程事实、before 先送达；独审反查遗漏和权限，并实测正确/错误稿 |
| 知识 ID 齐全而 AC 义务错配被判 WARN | 结构存在代替语义应用，分级未服务交付后果 | 结构门保引用；独审核实体与实际义务，必要行为错误阻断 |
| 会议无法用原名引用，真实决定被写成无上游依据 | 作者和检查器没有共享来源合同 | 一个解析供作者、检查、投影使用，决定沿用已有账本 |
| 重跑 harness 只是为了截另一段输出 | 可执行恢复路径及报告消费不完整 | 一次给完整诊断，区分读报告、修报告、重审与同步闭环 |
| 检查点吞归档回复，closed 当完整，dirty 当污染 | 测试完成定义和对象身份错误 | 安装基线比较；业务、审查、阅读、归档分别取证，按实际目标结束 |

依据是当前源码、story-suite-20261013-201213 原始事件和产物。可定位原文及历史映射见 [SVG 与历史复核](CLI测试分析/2026-10-14-SVG缺产与历史性能稳定性复核.md)。两 Case 不生成 SVG 的共同主因不是切换失灵；当前 OpenCode 适配声明 image_input:none，视觉执行能力也是起跑前必须解决的独立缺口。

本地存在可用历史证据，不能笼统写“无法比较”。78 条两 Case 原始运行已用同版 measure 重算。同模型、同 Case、同 initial 终点最近参照如下；当前 Extension 与该 CLI template 同源。

| initial | 最近 1.9.8 样本 | 当前 1.9.9 | 可观察差距 |
|---|---:|---:|---|
| auto-topup 时长 / harness | 48.9 分 / 6 次 | 71.2 分 / 18 次 | 时长约 +45.6%，更多检查未消除业务错误 |
| car-key-sharing 时长 / harness | 75.8 分 / 9 次 | 101.3 分 / 28 次 | 时长约 +33.6%，仍错改有效约束 |

## 3. 统一能力合同

| 环节 | 输入与责任 | 确定性保证 | 必须由模型或人判断 |
|---|---|---|---|
| 工作范围 | 材料、原件、知识清单、决定、当前 before、实际图块 | 枚举对象、版本与缺件；在行动前送达 | 原文业务义务、冲突与适用性 |
| 作者产出 | 作者理解、选择、叙述与绘图 | 结构、来源、投影、登记检查 | 假设是否成立、方案是否正确 |
| 独立审查 | 原件反查成果，新稿对照有效旧依据 | 当前请求绑定、声明覆盖完整、报告自洽 | 遗漏、越权、知识错用、图义与视觉质量 |
| 交付操作 | 使用已验证的当前成果 | 前置、Mermaid 操作范围、失败恢复、副作用交回 | 有权人裁决真实冲突 |
| 效果验证 | 事件、原件、历史正确/错误稿 | 同口径采数、身份对应、完整分母 | 质量、根因与评分 |

沿用 Framework 请求、subject、回执和闭环，不复制阶段状态或调度。沿用 materials、decisions、update、图源和原生报告作为真源，完成情况从证据计算，不另存可被作者填成“完成”的总状态。

用户本轮已确认增加**局部阅读验收合同**：绑定 Mermaid、SVG、渲染结果和独立对照结论，复用宿主独立执行能力；不改变 Framework 正式业务 subject，不新增阶段或通用状态机。S3 明确该合同的生产者、消费者、失败出口及能力缺口。

脚本通过只允许进入依赖它的下一动作；业务审查通过不等于阅读完成；远端归档成功不等于本地恢复成功；目标阶段闭环不等于全功能已验证。按本次请求的适用结果合取整体完成，不能用一个 PASS 覆盖其它维度。

## 5. 有效决定与保护项

保持 1.x interactive 协议、Framework 3.0.0 只读和现有阶段所有权。承接已确认业务补充，宿主按实际立场在模型问到后回答，不灌金样答案。知识来自目标仓事实，adapters 仅负责外部访问。

Mermaid 是图义真源；SVG 为模型重述，允许重组布局，不改成机械转换。正式业务材料使用 Mermaid；本地默认可用 SVG。自动恢复只覆盖 Extension 自己的 archive/update/生成/检查/状态命令；Framework post_phase 早于审查装配，不能在那里恢复。原生 harness/独审期间保持 Mermaid。AR 一键入口纳入精确白名单、生成和验收。

金样仅两组七件：auto-topup 的 Story/Review/Spec，car-key-sharing 的 Story/Review/Spec/Plan；必要原图保留，不增加 update 金样。两 Case 既定终点不擅改。真实视觉、跨业务 adapt、六阶段后段效果分别取得前置和 CLI 授权。发布另行决定。

金样是否可转正另按 [当前准备度评估](评审意见/2026-10-14-两Case金样转正评估.md) 判断：两组暂不直接转正，先修候选自身内容、取得当前版本审查并交具体稿审定。正确期望的定案不以产品先达到该期望为前置，具体流程见 S4 §6。
