# S3 本地阅读与操作：生成、验收、使用、恢复

必读 [总览](00-实施总览.md)、[S2](02-来源合同与稳定执行.md)。预计 G310/X75。本步交付“正常任务产出可用 SVG，正式操作自动使用 Mermaid 并恢复”的完整能力，不以切换成功代替图已生成、质量合格。

## 1. 一个图源与实际工作集合

同一 AR/story.md 维护一套正文。稳定 ID 管理块对应 AR/story-src/figures/ID.mmd，SVG 在 AR/figures/ID.svg；图序/章节不作身份。mmd 是唯一图义真源，正文按源派生，不从 SVG 反写。

复用 figure-view 的围栏/管理块解析，每次从 Story 实际内容派生适用图与未管理围栏，而不是只看已登记 ID。无图可不适用；有图却 managed=0 必须报告未准备，不能“零项全通过”。六类图的义务是忠实表达实际关系，不固定图数、节点、坐标或 Case 布局。超出既定支持范围明确种类和影响，不以“不适用”免除已支持图的生成。

成文链 story 在 project/number 之后、最终 check 和摘要登记之前，调用同一个 prepare 提取首次源、加稳定标记；已存在同 ID 源内容不同则拒绝覆盖。初次结构变化随本轮正式登记/审查，不在归档后补标记。动作前序已发生的写入如实交回。

prepare --id 仅从已有源重建可唯一定位的块。源缺失、重复 ID、边界错、块夹正文/多个围栏整次视图零写入；合法单围栏与源不同则按源刷新并说明差异。图块外字节保留。

成文结果、作者任务包、routing.next_step 和 status 使用同一派生工作集合，列 ID/位置、mmd/SVG 路径及待准备/待生成/待渲染/待独审/过期/失败。集合不持久化为新流程状态。story-write 中“可以做阅读图”退出，svg.md 在执行生成前进入实际任务。正常模型无需额外得到“请画 SVG”指令。

正常顺序是先准备图源并完成正式业务登记/审查，再补当前有效源的阅读图，减少错误业务图的无效重绘。next_step 在 story_written/archived 原分支中先保持已有登记和业务闭环要求；这些满足而 reading 未完成时返回“完成本地阅读”的实际入口和待办，不能返回 done。update_open 先沿已有更新动作推进，close 后仍按当前源检查阅读缺口。status 只计算业务是否可交付、reading 是否完成及下一动作，不能靠一句模型“完成了”消待办，也不把这个动作新增成持久阶段。读取失败明确报未知及原因，不按空集合完成。

## 2. 局部阅读验收合同

这是用户本轮明确确认的最小新增：现有快照只能判断图源是否变过，不能证明当前 SVG 经过渲染和对照。复用现有图解析、结构检查、hash 和宿主独立执行，增加当前对象的请求/结果绑定。替代仅靠作者自述三道核已完成；不改 Framework 正式业务 subject，不增加阶段、通用调度或持久批准状态。

### 2.1 文件与生产者

沿既有图目录，在 AR/story-src/figures/ID.reading/ 放 request.json、render.png、report.json 和必要原始执行输出。它们是派生阅读证据，不是材料原件。每图只维护当前可用证据，历史运行原件由测试装置另存 output。重复 prepare/status 不重写有效证据；新内容只有实际发起验收时才替换当前请求。

| 对象 | 生产者 | 最小内容及消费者 |
|---|---|---|
| mmd | 作者的业务设计，经现有正式链验证 | 真实图义；绘图与独审消费 |
| svg | 作者按 mmd 重述 | metadata 含所用 Mermaid 全文；结构检查、渲染器、独审消费 |
| render.png | 当前宿主已有浏览器/渲染能力 | 实际打开当前 SVG 的完整图像；独审看图，不用作者描述替代 |
| request.json | 核心图工具 | 版本1、图 ID、源/SVG/本地资源/渲染图的相对路径和 SHA256、验收方法版本、必核项、内容派生 request_id |
| report.json | 独立执行体返回，作者原样留存 | 同 request_id、逐项结论和证据、blocking_findings、advisories、未核原因、真实执行引用 |
| 派生 reading 结果 | 核心图工具 | 每图状态/原因/下一动作，供 view、status、交付结果、测试终检消费 |

request 不带时间戳或作者结论参与身份；同输入同请求，不为重复检查重派审。request_id 对规范序列化的输入字段算 hash，路径以需求相对形式规范化；源/SVG/渲染和资源按实际文件字节取 hash。业务身份算法保持不变，局部证据失效允许保守地重新核验。

SVG 引用的本地资源一并纳入请求输入；复用 figure-check 的引用规则枚举，若合法 CSS/SVG 再引用资源，递归解析、去重并防循环。缺件、越界或不能完整确定依赖时不发有效请求；不能只 hash SVG 后忽略字体/图片变化。内嵌资源已由 SVG 字节覆盖。保持现有本地资源合法能力，不用一律禁资源缩小范围。

### 2.2 入口及顺序

在现有 story-build view 命令增加局部动作：--mode review-request --id ID --render <图像路径> 生成请求，--mode review-check --id ID 校验结果。继续由现有分派和 figure-view/figure-check 承担；必要时在同目录拆一个局部阅读证据模块，不建设独立系统。

1. 作者依据当前 mmd 生成 SVG，metadata 保存真实源，结构检查通过。
2. 用宿主现有工具实际渲染 SVG 到指定图像，保存原始工具结果；无渲染或看图能力时报告缺口，不能用 SVG XML 或文字总结冒充视觉验证。
3. 核心生成绑定源、SVG、资源及渲染图的只读请求，同时给出独审任务：核语义对应、渲染可读性和图与业务位置是否合适。
4. 作者通过宿主已有独立只读执行体或独立会话发起任务，只交请求、必要业务上下文及判据，不交作者的“已正确”结论。审查者自己打开 mmd、SVG 和真实渲染图。
5. 返回报告原样留存，review-check 核当前请求、所有输入 hash、结构、必核项、结论自洽及未核项；通过后才成为可用 SVG。修改图或资源后重走受影响部分，不复用旧结论。

请求生成可在结构检查成功后写局部证据，不替作者绘图、不假装自动调用一个不存在的视觉模型。切换、status 和归档只消费检查结果，不启动模型或重绘。

### 2.3 独立执行与能力边界

复用 adapt/knowledge-review 已有的“宿主独立只读子代理或独立会话”方式。当前阶段 verifier 模板只接 Framework 原生 request JSON，不能把本请求塞给它冒充合法调用，也不新增一个通用 Agent 层。

独立上下文和实际调用由宿主提供；JSON 中写 reviewer_name 或 independent:true 不证明独立。报告记录宿主实际返回的执行/会话引用并保留原始返回；作者负责传输而不改写结论。机器可核文件及绑定，不能仅凭引用字符串认证一段对话确实发生，真实调用与隔离由 S4 的宿主事件/会话证据核实。交回明确区分“报告结构与对象绑定已核”和“独立执行来源已核”，不能对后者给虚假自动认证承诺。

起跑前核实际工具和模型是否具备渲染、图像输入、独立执行能力；CLI 名称不是能力证明。当前 OpenCode image_input:none 的配置不能承担视觉通过。缺能力则该图保持未验证，说明需要在已授权宿主配置具有该能力的独立执行体或交有能力的独立会话；同一作者自查不能代签。S4 若拿不到真实独立视觉证据，本功能不能验收完成，不能只改 adapter 声明伪造支持。

### 2.4 通过条件及恢复

结构核有效 XML、命名空间、viewBox、源快照、资源范围和可读性；局部合同核当前输入、必核项及结论自洽。独审分别判断语义等值（角色、关系、方向、条件、状态、去向、顺序）、实际视觉（裁切、遮挡、连接辨识、文字可读）、位置与说明。六类图按实际关系核，不用字符数、节点数或关键词替代。

必核项未执行、结论 FAIL、阻断项非空、输入变更、报告/图像缺失或绑定不一致，阅读均不完成。非阻断建议可保留但不冒充已修。脚本无法证明语义正确或图片真的由该 SVG 渲染；渲染工具来源和独审核对是这部分证据，S4 要挑战错配图像、漏关系及假声明。

源变化回正式业务登记/审查并重做该图；只改 SVG 布局/资源则局部证据失效，不使业务 subject 失效。重新渲染或修改报告不触发业务重审；质量结论不通过时修对应源/图，不改 metadata、hash 或报告求过。

## 3. 操作切换由 Extension 持有

最外层 Extension 命令执行“进入 Mermaid→业务动作→finally 恢复操作后的可用 SVG”。依据操作后的当前源，不保存并写回旧全文。切入失败零业务动作；业务失败也恢复可用视图。坏/缺/过期/未验证图保留 Mermaid，明确原因和只修图入口，不能显示成已满足本地 SVG 目标。

| 入口 | 结束边界 |
|---|---|
| story-build skeleton/chapter/project/number/build/check | 当前命令所有业务处理结束或异常 |
| story_flow story/status/round/reopen/complete/archived | 含内部检查和登记的外层动作结束 |
| update inputs/prepare/status/close/restore | 本次比较、before/after 快照或还原结束，不等整轮 close |
| 核心 archive | 交付门、上传核读回、本地登记全部结束或失败 |
| 显式 view prepare/mermaid/svg/toggle/review-request/review-check | 保持显式动作结果，不由自动恢复抵消人工选择 |
| 原生 harness/pre_verifier/正式作者读取 | 保持 Mermaid，不能 post_phase 提前恢复 |

Framework 3.0.0 post_phase 先于审查装配；本版不承诺其退出即恢复。Extension 子调用的恢复归最外层持有，用私有参数/环境传递工程根、需求范围和所有权，不写盘、不要求模型填写、不因当前已是 Mermaid 猜嵌套。hooks 的内部 status 查询也保持正式读取形态。操作串行，正式独审期间不并发点切换，不另建锁服务。

context.mjs::fail 当前直接 process.exit，相关命令须把失败带到外层 finally 之后才退出，保留原码/原诊断；Python 同样处理。强杀/断电无法保证 finally，下次正常命令或显式 view 按当前源恢复，不新增恢复状态机。

## 4. 归档一个核心入口

正常命令为：

    node doc/extensions/skills/story/scripts/core/story-build.mjs archive --feature <AR> --mcp-token <token> [--project-root <root>]

核心依次核参数/系统单适用性→Mermaid→现有业务交付门→adapter archive→核回执→core archived 登记→finally 恢复。adapter 仍按现有 story.js archive <AR> <token> --project-root <root> 协议访问系统；参数数组传递，不拼 shell、不打印 token。

退出0且 JSON 的 mode/reqNo 匹配、success/verified/archived/reviewArchived 全为 true 才登记。交付门失败零系统调用；坏回执/核读回失败不登记。adapter 不增加任何切换、恢复或 core 调用。模型三步编排指引退出，底层 archived 仅保留登记及失败后补登记能力。

远端核验成功而本地登记失败，明确已成功的副作用，提供补本地登记入口，不自动重传。视图恢复失败只补视图；不得把一个 resume 参数当远端成功证据，不自动回滚系统。系统 restore 使用 adapter 原备份。

保留业务结果及退出码，另返 reading/view 结果：恢复 ID、留 Mermaid 的 ID/原因、视图错误。业务错误优先，恢复错误附加；业务成功但图未恢复不诱发重传，整体任务仍按 S2 判未完全完成。stderr 与 JSON 均可取得恢复缺口，不能藏日志尾部。

## 5. AR 一键切换、白名单与派生证据边界

story-chapters.json 唯一登记 local_reading_entry 为“切换视图.cmd”，生成、白名单、update 排除共用同值。脚本只定位工程、调 core view --mode toggle、保留结果窗口：任何管理块为 SVG（含混合）则全 Mermaid；全 Mermaid 则尝试已验可用 SVG。无管理图说明 prepare 入口，不自动生成；坏块整次拒绝。

从脚本所在 AR 向上找最近 framework.config.json，按 features_dir 核需求位置、extension_dir 找核心；坏配置不越过猜另一工程。可用 Windows PowerShell 读配置，参数安全传递；不写绝对机器路径/生成时需求名，不依赖 cwd，不要求管理员或全局策略变更。显式选择保持到下次正式操作。

同一生成函数供成功的 build 与 view prepare 调用；相同内容不改写，同名用户文件保留并报冲突，只覆盖有生成标记的文件。check/status/toggle 不补写启动器。context.mjs 仅放行该精确文件名，不豁免任意 cmd/ps1/js。

新增局部证据目录只在图路径允许 ID.reading 下的合同文件，拒绝未知任意过程件。派生 SVG、局部请求/渲染/报告、启动器均不入材料原件、story_digests、正式业务审查和上传；mmd 图义必须通过 Mermaid 正文参与正式身份。update mirror/restore 对启动器与局部派生证据作精确排除；restore 后按恢复的实际源重新核已有 SVG/证据，匹配可复用，不匹配标过期，不恢复旧“已通过”。source 备份仍按既有业务规则保留。

这次仅新增局部阅读证据的排除规则，不能排除全部 story-src 或 figures 而漏掉原材料图/业务图源。材料图片继续遵循自身身份和取舍，不能混成派生阅读视图。

## 6. 文件动作与验收

| 位置 | 动作 |
|---|---|
| core/story/figure-view.mjs、figure-check.py | 实际图集合、证据请求/核对、资源依赖、有效视图、toggle；可拆局部阅读证据函数 |
| core/story-build.mjs、context.mjs、story-chapters.json | 命令、finally、核心 archive、精确白名单及入口生成 |
| core/story_flow.py、flow/lifecycle.py、routing.py、update.py、client.mjs | 生成任务、父子边界、分离结果、每次 update 恢复、精确排除 |
| core/flow/state.py、story/delivery.mjs 及正式材料枚举消费者 | 核登记/审查/上传不意外收进局部证据；实际业务图源仍被登记和更新覆盖 |
| hooks/shared/story-view.mjs、author/pre_verifier/内部状态读取 | 动作前送达方法与图工作，原生读取期间不提前恢复 |
| SKILL、spec/story-write/update、reference/svg.md、upgrade-changes | 必交阅读、局部验收、自动操作与一键入口，退出旧可选/三步说明 |
| figure_view/story_build/story_update/material_rounds/verifier 相关测试 | 真实入口、失效、身份、恢复及副作用回归 |

core 路径指 extensions/skills/story/scripts/core，hooks/合同均在 extensions 内。复用现有检查和安装机制；不在 adapters 放阅读行为。

离线必须覆盖：普通无 mmd/SVG 的 Story 自动派生工作；合法无图；未管理图不能空通过；同源错 SVG/漏报告不能可用；源、SVG、资源、渲染图分别改动只使对应证据失效；请求不因检查变化；未知/旧局部合同明确拒绝。绑定正确的语义错误图仍交独审，脚本不冒称能辨。

操作覆盖成功/异常/嵌套/强杀后重入，上传、摘要、before/after 的真实字节为 Mermaid；图外不变，原异常不被 finally 遮蔽。远端成功本地失败、坏回执、恢复失败均不重复上传。restore 保人工区且不把旧证据当当前批准。

一键入口覆盖中文/空格/特殊字符、自定义目录、搬迁、多个需求、坏配置/缺依赖、同名冲突、重复生成及无关 cwd。启动器/局部证据变化不改业务身份，真正文/mmd 变化仍失效。

真实生成、六类渲染/独审、错图检出、独立执行来源、Windows 双击和开销由 S4 的授权 CLI 取证。没有能力或真实证据明确未完成，不由维护者手工摆 SVG 代替正常链。
