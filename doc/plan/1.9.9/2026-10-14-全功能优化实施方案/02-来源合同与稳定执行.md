# S2 完成门禁、独立审查与稳定执行

必读 [总览](00-实施总览.md)、[S1](01-事实决定与语义质量.md)。预计 G125/X35。修现有 harness 的责任连接，不建设新工作流、通用校验框架、语义规则引擎或重试调度。

## 1. 从真实对象计算完成条件

复用 story-build check、原生阶段 harness、verifier-report、Framework 回执/closure、delivery.mjs 和 update close。组合现有结果到对应出口，删除同职责重复实现，不让检查工具生成业务结论。

| 出口 | 确定性前置 | 缺口处理 |
|---|---|---|
| 提交、登记 | 当前材料/结构/来源/投影/决定引用完整，实际图块可枚举 | 一次列全可计算问题及缺前置而未执行项 |
| 原生独审 | 脚本通过，必审输入及判项装配成功，当前 request 可读 | 缺请求/装配失败不派伪任务，缺依据明示 |
| 业务交付、update close、归档前 | 有效登记、原生回执/closure、报告绑定自洽、业务必审通过 | 缺审、失效、未采纳、必要 FAIL 不当已审通过 |
| 本地阅读交付 | 当前适用图全部完成 S3 生成和局部验收 | 单列缺图、过期和未验证 |
| adapt 知识交回 | 本次知识适配义务对应的当前知识和独立报告 | 加载通过不代替语义完成，缺审明确未完成 |
| 最终交回、测试终检 | 上述适用结果及所选操作都有真实证据 | 按任务范围合取整体完成，不另存总批准状态 |

check --deliver 保持业务门含义，同时交回阅读结果。核心 archive 用业务门，阅读待补不能伪造远端失败；要求本地 SVG 的完整任务仍须阅读完成才可报整体完成。合法无图不适用，实际有图但未管理不是不适用。

## 2. 独审与可机械核对的报告

复用原生 verifier，不新增多层 Agent。Spec 的 story_reader_review/知识判项、Plan 的义务判项沿 S1 取得依据。按“原件义务/未决→作者遗漏与选择→变化权限→知识落实→表达与跨件一致”审查，不能仅在作者登记表里找错。

错误授权、错误外部状态、未决选边、遗漏必须由人决定的事项、必要知识义务错配、核心实现仍需业务裁决，归对应 BLOCKER 判项 FAIL。保持正确性的表达改善才可 WARN，不一刀切升级，不把 notes 记录当修复。

当前 verifier-report.mjs::judgeReport 对 PASS 可跳过两类明细。改为 Extension 的 story_reader_review 无论结论都使用同一明细合同，保留 blocking_findings、advisories，增加 examined_inputs 和 unreviewed。原生汇总表、request、最终结论及 Framework 协议不变。

- examined_inputs：当前任务必审输入的相对路径集合，是审查者覆盖声明，不是已理解正确的机器证明。
- unreviewed：未核输入或判项及原因，没有时为空；缺文件也须如实列出。
- blocking_findings/advisories：沿既有格式给问题、位置、影响和恢复责任，不要求无意义的通过长文。

任务生成与报告检查消费同一派生集合及明细定义，放在现有 shared 合同位置，不另存静态文件清单。脚本核集合遗漏/多报、重复/不可定位路径、缺必审项、类型错误及结论矛盾。PASS 带非空阻断项或必审 unreviewed 必须拒绝；advisories 沿现有 WARN/处置语义处理。虚假声明全核而实际没理解，脚本不能识别，必须由 S4 验审查区分能力。

不为这份局部明细修改 Framework 全局报告格式。其它扩展项沿现有汇总与绑定合同，结构明确的 FAIL/最终 PASS 冲突应拒绝，不能靠自然语言关键词推断结论。原生缺口给上游证据，不仿造新已审状态。

### adapt 沿同一完成原则补齐现有出口

当前 knowledge-review.md 只要求交回说明独审，--mark-adapted 只核知识加载。这留下与 SVG 同类的空隙：模型省略独审仍可能把适配版本记完。本轮直接修该出口，不再加一句“记得审查”。

复用已经允许的 .adapt/knowledge-review.md，在其中约定可解析的 YAML 证据块：当前 knowledge.digest、逐份激活知识路径、已有四个质量维度的结论/证据、未核范围、阻断项和独立执行引用。来源与范围仍用既有适配交回，不另建 request、审查状态或通用报告系统。--status 只读派生报告缺失、过期、未核、失败或结构有效；结构有效不自动证明实际独立语义审查发生。

--mark-adapted 在现有 followUp 确认本次有知识适配义务时，除加载外还核当前 digest 对应报告、激活集合/四维完整、无必修失败/未核，未满足不写 adapted_for。无知识演进义务的机制升级保持自动完成、不新增问人；已有报告匹配则直接复用。知识文件或激活集合改变，旧报告不覆盖新内容。独立调用原始证据与报告真实性由宿主能力和 S4 核验，作者不能用自述身份代签。

同步 knowledge-review.md、knowledge-adaptation.md、adapt SKILL、adapt-scan.mjs 的 status/mark 消费与输出，退出“版本已记即知识适配完成”以及“mark 只核加载”的失效说明。保留脚本不写知识、首装范围由人决定、升级按演进主题、status 零写入和历史未知，不新增历史状态补洞。缺独立能力时允许机制已安装，知识适配明确未完成。

## 3. 身份和恢复只走已有协议

subject/request/回执/closure 由 Framework 负责。Extension 的审前依赖含真实输入，before 或有效依据变化应失效；报告、notes 和本地派生视图不制造业务自激。本轮十次派审 subject 实际不同，不能仅凭次数认定同对象重审。

| 状态 | 正确路径 |
|---|---|
| 脚本失败 | 读完整报告，修真源后重验，说明未执行项 |
| 当前请求审完、产物未变、尚未闭环 | 原样落报告→核报告→回执→sync-closure→交付门，不重跑审前链找输出 |
| 报告格式/覆盖/自洽错 | 独审基于同一有效 request 重投，作者不改结论，坏稿不占首份合规结论 |
| 业务依据或产物改变 | 正常登记/阶段/当前请求，不能沿旧语义 PASS |
| 原生允许修正重验沿用 | 核真实历史报告与 reviewed_subject_id，说明沿用范围 |
| 已闭环后补当前审查 | 完整 harness 采纳报告再 close，sync 不改闭环绑定 |
| 非阻断建议暂缓 | notes 记有效报告及处置，沿已有机制收敛 |

不设置固定返修次数或语义缓存制造性能收益。成本下降来自输入正确、少走错路、一次报告完整问题和复用有效证明；真实变化必须支付必要检查成本。

## 4. 失败说明原因、机制和下一动作

每个 Extension 失败集中给实际对象/位置、期望条件、判定机制、恢复真源与真实入口、已完成/中断/未执行动作、恢复后预期。子进程保留 stdout/stderr 和退出码；校验失败、工具异常、外部环境失败分开，不能笼统要求读源码。

给实际 summary/script-report/log 路径，已有完整输出就读文件。退出反复 harness 截取片段的指引；不禁止读 checker 来掩盖缺信息。调查工具内部错误的源码读取与猜隐含判据迎合产物分开评价。

复用当前错误收集器和结果结构，不新建错误框架，不重写已经充分的报错。Framework 原生诊断缺口保留输入/输出/责任函数上报，Extension 只补掌握的上下文，不仿写其判据。

路径相对 extensions；core/flow 是 skills/story/scripts 下简写。

| 位置 | 动作/消费者 |

## 6. 验收

从真实入口核 PASS 带阻断项、漏输入/判项、未审而 PASS、过期请求、假沿用、缺报告、未启用 verifier、闭环补审、单纯报告落盘、真依据变更及 WARN 暂缓。正常完整报告和真实不适用必须通过，不能只证明更严会拒绝。

六阶段各用已有失败 fixture 核首次结果足够定位与恢复，含前置缺失、长双路输出、内部异常、环境缺口；不只断言几个字段存在。复用 review-closure、verifier-report、各 phase、story-update 测试。

S4 必须让实际配置独审区分好坏业务稿，维护者核命中真正原因。区分失败先查送达、任务和能力，再回责任位置处理；不能继续塞语义关键词、添加审查层或降分求过。没有效果证据，只签结构可验证，不签语义可靠。
