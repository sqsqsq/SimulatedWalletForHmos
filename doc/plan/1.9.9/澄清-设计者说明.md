## 4. R7：失败解释的边界裁定（用户 2026-10-12）

脚本职责止于告诉模型**错在哪里、什么事实违反哪条判据、恢复的类别与入口**；推导具体修法是消费模型的职责——场景复杂，脚本不按场景给「具体解决方案」，不写会过期的处方模板库。两条红线：

1. **脚本不开处方**：失败合同第 3 件「恢复动作」止于类别 + 真实可执行入口/落点，不延伸到具体场景的修法内容；
2. **模型不靠读 checker 源码理解失败**（既有目标维持）：错误中的判据解释须达到「不读源码即可定位并理解」的门槛。

**实现落点**：P7 §2「原因和机制」只陈述判定所依据的计算规则（依据哪条合同、如何取身份/集合/状态、为何不通过），不延伸修法；「恢复动作」按上述边界收窄表述。

**验证口径相应调整**：维护者用缺陷输入只读错误与公开规则，验证「能定位 + 判据可理解 + 恢复类别/入口清楚」；「修法是否正确、是否发生走读源码」由授权后的真实实跑观察。plan §2「不新增通用错误翻译服务或判据解释字典」在本裁定下重申有效。

## 6. R4 重设计：单文档双形态（用户 2026-10-12，替代 plan 05 分册冲突部分）

**方案**：Mermaid 是唯一语义真源（上传、归档、审查、update 比较一律 Mermaid 形态）；SVG 是对同一流程的**重述视图**——按六类指导重新组织表达（拆泳道、换方向、合并冗余），不是机械转换。story.md 默认呈现 SVG 引用形态；本地同时保留每张图的 Mermaid 源与 SVG 文件；一键脚本按图块 ID 双向切换（确定性、幂等）。

**三条纪律（用户确认）**：
1. **形态纪律**：update 比较、登记、独立审查、归档一律在 Mermaid 形态执行（入口钩子确保切回）；SVG 形态只存在于本地阅读窗口期。不引入形态归一化指纹机器；
2. **图引用块为脚本管理区**，禁止手改；手改正文段落不受影响，破坏图块对应时只能重新生成；
3. **归档后自动切回 SVG 默认态**（adapters 归档脚本调用切换，adapters 不计预算）。

**质量三件套**：结构检查器（XML/viewBox/引用）+ 渲染核（人看）+ 对照审（SVG 与其 Mermaid 源语义等值，重述多画分支/漏异常去向在此拦）。Mermaid 源兼作切换备胎与对照物。

**范围**：仅 story.md 的流程图类（Mermaid 可表达的图型）；Mermaid 表达不了的图不在本版。zip/打包整体退出（用户裁定：在线 md 无法引用 zip，不考虑该归档形态）。

**预算修正**：R4 分册由 650/55 修正为 **G≤430 / X≤40**（构成：重排任务页与指导 ~100–140、结构检查器 ~100–120、切换脚本 ~80–120、对照审与渲染核接线 ~30–50，以实施分册定案）；总账由 G2000/X430 修正为 **约 G1780/X415、净增约 1365**，峰值上限相应下调（精确值随实施分册签认，台账开工时更新）。plan 05 分册中与本文冲突的部分（派生图身份/digest 登记/重审接线/打包/预审资源接线/schema 迁移）不再执行。

**与 2.x 关系**：外部行为合同自此分叉（2.x：SVG 为交付物；1.x：SVG 为本地阅读视图）——并行构建原则允许，过渡方式由用户后续裁。验证：定向链简化为「完成的 story → SVG 重述 → 结构检查 → 渲染核 → 对照审 → 一键切换双向走通」，在每个 Case 上可验，与生成时选型无关。
