# S2：现有入口自动采集与入库

> 历史方案：本文件的usage字段、起点、Git归属及统计口径已由用户指定的V5替代，不再执行。当前只读[统一接续](../2026-10-21-需求确认与执行接续.md)和其中usage纠正包；保留本文用于追溯当时实施与预算，不将历史通过结论当V5验收。

依赖S1和总览中的返修/预算前置。本步G330/X0估计，以实际差额为准。目标是进入正常产品入口就执行记录，不由测试或模型额外补调用usage脚本来证明成功。

## 1. 一处桥接

新增 `extensions/hooks/shared/usage.mjs`：默认导出作为Framework pre_phase hook，具名函数供既有MJS入口调用。内部只用Node已有child_process启动S1 Python入口，stdin传结构化上下文；结果原样归一返回。不读写第二份usage，不依赖Agent运行事件。

manifest在spec/plan/coding/review/ut/testing的现有pre_phase列表各登记同一文件，保留story-view及现有顺序约束。只对有feature的六阶段请求生效；全局维护阶段、help、安装和报告重放不冒充新需求使用。正常返回ok，不把计数、当前时间或usage摘要放进promptFragments，避免统计写入改变verifier对象。

错误沿Framework现有dispatcher处理，不另写闭环规则。hook被禁用或登记缺件时adapt明确提示该安装不能保证阶段采集，不擅自改用户禁用决定；启用与依赖恢复走既有适配确认流程。

## 2. 身份和初始化输入

需求编号取明确的本次输入；已有usage.features包含本feature时复用该关联；标准AR/DTS需求的同名feature可按完整值关联。其它本地编号沿原产品语义保留，不从名称子串猜AR/DTS。非同名feature需当前任务明确提供requirement，冲突时拒绝跨需求覆写。

所有六阶段统一消费本feature根的 `.usage-input.json`（S1 §2），不再只给Story init/round或Spec/Plan增加一条专属填写路径。模型在原任务工作区写此语义输入，pre_phase、已有作者包和Story命令在内部读取；直接Coding/Review/UT/Testing无需创建Story flow。

名称候选可来自detail.title，版本须按需求优先、工程配置其次完成首份判断；模型提交完整name/version后才一起冻结。不能先凭title锁死未知版本。name为null的暂存节点已经保留实际使用，原post_check报告同一输入路径与字段合同，修复仍走原阶段操作。可空业务版本、agent/model不产生额外人签。

首次环境由第一次采集调用取得。若首次观察没有可靠agent/model就保留null，补业务元信息不改初始环境。所有输入消费与清理走同一记录器；解析错误保留输入原件，便于修复，不写出半份初始化数据。

## 3. 触发点与事实

| 既有入口/文件 | 调用 | 记录的事实 |
|---|---|---|
| 六阶段Framework pre_phase | 桥接先reconcile当前已登记需求，再observe本phase | 确实进入该阶段检查；没有工作起点时耗时未知 |
| `hooks/spec/author.mjs`、`hooks/plan/author.mjs` | 在实际作者任务包入口接初始化与begin；模块被其它脚本导入时不触发 | 本轮作者取得任务包的可观察起点；不把任意文件读取当工作开始 |
| `story_flow.py` 的init/round | 在原有输入取得和正常流程操作内部observe，接收初始化信息 | Story需求使用，不把usage错误伪装成业务未初始化 |
| `story-build.mjs` 的实际skeleton/chapter写作入口 | 首次真实写作时begin story；纯check/status不begin | Story写作的可信工作区间 |
| `flow/lifecycle.py::cmd_story`、公开status及archive交付路径 | 业务成功后或状态观察时reconcile | 登记状态与必要原生闭环已成立则补完成；公开status不创造新节点/步骤 |
| `flow/update.py` 的inputs/prepare/close/restore | 实际开轮begin；close finish-own；restore abort-own；重复调用幂等 | 使用既有轮次id、opened_at/closed_at，不另建update统计轮次 |
| 独立stats脚本 | 对全部已有需求/steps有限reconcile，然后固定数据快照统计 | 补本地已成立而漏刷的结果；不回扫未知需求目录 |

原生结果通过S1共享reader取得。`pre_phase/post_phase`不是正式闭环后事件，当前调用中不能读取尚未生成的新summary；待后续入口读取。`check-receipt`/`sync-closure`仍由Framework负责，不包一层替代它们，不改Framework源码。

Story完成按现有登记指纹与交付条件读取，不重建成文判据；结束为当前登记和必要原生闭环时刻的较晚值。仅Story登记、Spec尚未闭环时保留待对账，不能先填完成。update结束直接使用本轮closed记录；restore结束已知活动但不增加完成。

### 最终闭环的时效

下一阶段、Story状态/交付/归档或stats会自动对账；补采结束时间取真实闭环，不把等待下次调用的时间计入spent。只有首次检查才被观察到的coding等步骤，完成可成立但耗时未知。

原生最后一次闭环后没有任何上述入口时，usage仍可能是闭环前快照。原工作区执行正常stats即可补齐；更新的usage需随下次正常提交保存。只保留usage/Git的克隆没有未归档原生事实时，只报告归档状态。不得承诺无后续操作的即时完整性，也不为此增加后台轮询或Agent hook。

若实际验收必须要求这一性质，记录具体不可接受后果并交最小上游接缝需求；不把未验证能力写成已有，不让执行者私改vendored Framework。

## 4. 失败与恢复

- 记录器写失败：hook返回实际失败；Extension操作已经成功时保留原result，另列采集错误。不能让作者因此再执行一次归档/业务更新。
- 后续既有status/交付/stats入口会重试采纳仍可读取的结果，不依赖模型自行记得运行sync。
- 证据不存在：保留usage已知事实。证据存在但损坏/配置无法解析：明确报告，不以空目录替代。旧闭环不能结束新的可信start。
- 统计自己的调用不算story、review或任何研发步骤；内部嵌套查询不重复采集，守卫在最外层入口，S1无变化则零写。

## 5. 安装与归档保护

修改现有adapt-scan及方法说明：usage归目标数据，安装整体替换doc/extensions不能碰它。用 `git check-ignore --no-index` 检查doc/usage.json可通过普通git add纳入；不能依靠每次add -f，也不能只写一条在父目录排除下无效的白名单。

若被目标ignore挡住，在原适配确认边界内作最小规则调整，仅开放所需父路径与usage文件，其它过程文件继续忽略。配置更改必须以真实git行为复查。非项目ignore来源点明责任，未解决不报安装统计能力已完成。

`<features_dir>/.usage-stats/`与锁/临时文件忽略；features_dir自定义只影响原生证据和统计输出，不移动doc/usage.json。继续复用发布安装函数，测试期只装template。声明新增维护Skill的manifest及六桥接由S3统一完成。

## 6. 自验

用真实Harness执行触发pre_phase，核实际usage；测试不得先手工调用记录器给入口垫好统计状态。覆盖从Coding/Review/UT/Testing直接起手、无Story/Spec/Plan目录、待补元信息后恢复、title先取得但version键尚缺、显式null版本合法且只冻结一次、正常任务包起点、Story/update操作、末段闭环后stats补采、无原生材料克隆、不同配置路径、记录失败恢复。

单测正反例同时核usage变化与原业务产物/结果不变；验证正常hook输出不把统计内容注入审查材料。初次/升级/重复adapt、父目录ignore和普通add均用隔离Git工程验证。T03原矩阵保持，不产生第二套路径fallback。

交回实际调用者、生产者、结果消费和已知时效限制；所有缺口按真实原因分类，不把未采集或未知时长冒充通过。
