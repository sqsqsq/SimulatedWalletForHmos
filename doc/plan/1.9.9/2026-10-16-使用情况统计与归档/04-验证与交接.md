# S4：验证与交接

依赖S1–S3自验；本步复用现有测试与装配，无产品新增预算。返修产生的新实现仍计入R8和整版累计，不能藏到验证包。

## 1. 验证顺序

1. 在新隔离template装本轮extensions，确认源/安装面同源、demo未被写入。装配按 [TEST §5](../../../../test/TEST.md)，不从维护仓根直接模拟已安装入口。
2. 先跑新增test_usage/test_usage_stats及受影响flow、update、适配、入口回归；保持 `-n auto --dist loadscope`。定向通过后执行TEST §5要求的收口检查，不无理由反复全量。
3. 调现有measure及有效行diff，记录从R8开工基点起的G/X和原累计，核实际退出；原初始G2000与前置关闭记录保留。按用户实际签认的新额度核台账，不能只看pytest预算测试变绿。
4. 真实模型采集和stats成文只有在用户授权里程碑、宿主能力和旧方案起跑条件满足后执行；当前先准备输入与证据清单，不启动CLI。

参考命令（仓根）：

```powershell
python -m pytest test/tests/test_usage.py test/tests/test_usage_stats.py -n auto --dist loadscope
python -m pytest test/tests -n auto --dist loadscope
python -m pytest tools/cli/tests -n auto --dist loadscope
python test/scripts/check_failure_modes.py --project-root <本轮隔离template>
```

其余语法/装配命令沿TEST，不复制一套新测试协议。失效形态用开发版template，不拿demo旧版结果证明新实现。

## 2. 必须取得的证据

| 层 | 证据 | 不能代替什么 |
|---|---|---|
| 确定性 | 记录幂等/并发/失败保护；不同路径与原生闭环；真实Git关联/去重/时间；比例与均值；安装入库 | 不证明模型会找对业务版本或遵循采集动作 |
| 提示送达 | 六宿主入口指向stats；AGENTS扩展段与六阶段作者页在动作前可读；正常收口提供sync动作 | 磁盘存在不等于模型实际执行 |
| 真实使用 | 一次Story起手、一次不经Story的Framework起手；最后阶段独立闭环后确实sync；名称/版本优先级；重进与初始化不变；模型从facts成文 | 不把构造报告或替身调用记成行为通过 |
| 归档消费 | usage按普通git add可提交；新克隆不带feature原件时统计仍工作；适配升级不抹数据 | 不需要对真实业务仓提交测试数据 |
| 原能力 | 旧评审T01–T03反例保持关闭；更新/阅读/归档/恢复和未解决项保持原口径 | R8离线全绿不关闭旧视觉/设备/金样问题 |

真实运行的需求、期望与停止条件由现有Case/TEST承载。优先在下一次已经授权的里程碑附带观测usage，所需直接Framework场景另由同一授权明确；不因采集测试再建无关业务用例或给消费模型看维护样例。评估unknown/null时检查真实来源，不能教模型按样例填身份或版本。

## 3. 交回内容

本目录每步交回说明：所用HEAD/在途文件身份、生产者→消费者、当前修改与退出、定向结果、实际G/X/总量、已实现与未验。S4最终交回还应包含：

- 最新T01–T03关闭交回及预算确认记录，不复制旧口头“已完成”。
- 生成的usage、stats事实JSON和模型报告；日志在output/story，敏感凭据不入统计记录。
- 8个功能步骤使用与完成口径，步骤完成率的正确分母、初始化环境均值、版本标题时间范围。
- 新克隆和ignore正反例、改动仅在授权安装范围的证明。
- 实际全量失败清单。此前1749 passed/6 failed是旧记录，不能原样当本轮结果；既有失败与新增失败各自给证据。
- 保留的真实视觉/独立执行、G04、金样、系统/设备验收及R8行为待验项，说明下一动作与责任人。

未获真实CLI授权时交“实现与离线验证完成，真实采集/模型报告未验”，等待设计者集中复核；不发布、不写demo、不推送。用户后续批准发布时再按AGENTS §7同步README当前能力与1.9.9发布说明，不能提前把未验能力写成已发布。
