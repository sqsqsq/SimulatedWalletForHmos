# S3：Git统计与报告

依赖S1记录合同；S2接线完成后用于端到端装配。预算G300/X10，按 [总览](00-实施总览与接续条件.md)累计。

## 1. 单一事实生产者

新增 `extensions/skills/story/scripts/core/usage_stats.py`，调用S1加载/校验usage；接受 `--project-root` 与可选 `--version`。stats不要求`--feature`，不进入story_flow的业务视图切换，不要求原始需求或阶段报告在盘。

读Git用subprocess参数数组、不拼shell命令。先固定一次HEAD，读取该提交可达普通提交集合，输出的事实JSON记这个观察点；不取所有远端分支、不自动fetch。可读usage但Git命令运行错误须明确失败，不当成零提交。合法无关联提交时照常给usage统计，不加缺失分析。

提交字段：SHA、完整提交正文、author姓名/邮箱、committer ISO时间、numstat。使用NUL或已有Git机器协议解析，不能按文件名里的空格/制表符拆错。TicketNo从独立行读取，恰好一个AR或DTS标识才关联，比较完整值；Description里出现其它编号不影响。编号内部合法形态以实际输入约定为准，不从示例XXXX推出固定长度。坏/多TicketNo不猜配，跳过该提交的业务关联，计算规则有单测。

SHA去重，merge commit不重复父分支量，二进制`-`不转数值。姓名展示、邮箱身份，按记录邮箱去重，不擅自合并不同邮箱。只将对应usage需求的提交带入聚合；修改usage文件本身不参与推断归属。

## 2. 聚合合同

| 输出 | 算法 |
|---|---|
| 全版本需求数 | usage所有需求键计数，包括没有coding或没有提交的节点 |
| 分组 | 按初始化version精确值；null归未知版本；`--version 未知`筛null；未知具体版本筛选返回空结果说明，不退回全版本 |
| 开发人数 | 相关提交author邮箱集合大小，跨版本重新并集，不加各组人数 |
| 代码量 | 相关SHA普通提交的numstat增加/删除各自相加；名称为关联提交变更量 |
| 时间范围 | 同一提交集合的committer时间min/max，按带时区时刻比较；仅在相应全版本/版本标题展示起止，不显示天数差；无提交不编时间 |
| 使用数/使用率 | steps中有该步骤的需求数 / 当前范围全部usage需求数 |
| 步骤完成率 | completed=true的需求数 / 使用过该步骤的需求数；零分母显示—，不能误除全部需求数 |
| 环境组 | version、fw、ext、agent、model五元组；保留null，不把字符串“未知”混为版本；组号仅报告内标记 |
| 平均耗时 | 每组每步筛completed=true且spent是合法数值的需求，spent合计除这些需求数，再从秒转分钟；零值合法，null/未完成不纳入；无样本显示— |

步骤顺序来自S1合同，不在stats另写第二套。总体需求/提交/代码量可跨版本核加和，开发人数须并集；功能使用与完成数可按版本核加和。平均值必须按有效需求样本重算，不对各组平均值再做简单平均。

报告时间与统计时间范围分开，默认使用执行环境时区并标注；不新增跨项目时区配置。不得把spent称为AI活动时间或模型能力排名，不跨步骤相加总耗时。需求级数据只在usage和内部计算，不输出逐需求统计表。

## 3. 入口、报告与输出

- 修改 `skills/story/SKILL.md` 命令路由，新增 `phases/stats.md`：先运行确定性脚本，再读取事实JSON按预期报告结构成文。
- 同步 `skills/story/AGENTS.section.md` 和 manifest已登记的六份 `extensions/bridges/*` 的命令枚举/路由/help，stats不需要需求编号或需求系统token。不新增宿主入口或第二个Skill。
- `phases/stats.md`包含简短报告骨架与列合同，不另造完整渲染器。脚本提供所有数字、已格式化的比例/时间与分母；模型不自由重算或补额外指标。
- 默认写 `<features_dir>/.usage-stats/facts.json`、`report.md`；指定版本使用同一输出位置覆盖本次统计结果，返回明确路径与筛选范围，不累积无消费者的历史目录。本地文件写失败显式报错。
- facts写当前scope和固定HEAD；模型生成报告前确认所读facts仍为同次结果。并行stats写同一输出位置时明确提示占用/重试，不合并两次报告；不新建持久会话注册表。

报告正文按样例四部分：全版本总览、业务版本统计、初始化环境与步骤平均耗时、简短口径。指定版本只写相应范围；版本周期写标题；使用率/完成率与平均时长分母分别说明一次；没有逐需求明细、独立周期表、缺失数据分析。模型看不到数字的推测不进入报告。

输出facts为聚合事实，包含每项分子/分母和有效耗时样本数供复算，不要求报告新增样本覆盖分析。必要的需求与Git关联可留内存，不复制一份长期需求明细台账。所有事实来源仍是usage+Git。

## 4. 验收

`test/tests/test_usage_stats.py`用隔离真实Git仓构造AR与DTS、两版本和未知组、跨版本同人、同需求多作者、统计记录晚于代码提交、Description附带编号、单提交、merge及二进制。通过实际CLI读取，核数字与筛选，不能只验证自造JSON聚合函数。

换一组中性需求名称、不同编号长度、不同业务版本字符串，仍应成立。步骤使用率和完成率分母故意取不同数；平均耗时用不同有效样本数，含0/null/未完成，证明不是除全环境人数或执行次数。

仅保留usage及Git的新克隆能算同一报告事实，不依赖feature原件、金样或当前框架运行产物。Markdown样例仍是阅读示意；结构验收核表头/分隔行/数据列数，语义由模型核数字与口径，不用固定样例句子检验“好报告”。

X10仅来自stats路由整合时被替换的旧命令描述，若原内容仍有效就保持，不为预算删掉。交回实际G/X、Git真实用例与facts/report对应证据。
