# S3：独立统计 Skill 与报告模板

依赖S1数据合同和S2对账入口。本步G340/X0估计；属于随Extension交付的维护能力，计量按既有AGENTS范围，不因独立Skill而移出产品预算。

## 1. 文件与路由

| 文件 | 职责 |
|---|---|
| `extensions/skills/story-stats/SKILL.md` | 接受当前仓/指定目标与可选业务版本，执行脚本、读取facts、按模板成文、处理失败 |
| `extensions/skills/story-stats/scripts/stats.py` | 调用同包S1对账/读取模块，确定性读取Git和聚合事实；不复制usage写入逻辑 |
| `extensions/skills/story-stats/templates/report.md` | 唯一报告模板，对齐spec样例；包括全版本与指定版本两种组织条件 |
| `extensions/skills/story/SKILL.md` | `/story stats`直接路由到同包story-stats，不承载统计实现或报告骨架 |
| `extensions/manifest.yaml`、六份已登记bridges、AGENTS.section | 增加stats命令路由与story-stats Skill登记；用法/help同步；不新增第二套宿主命令 |
| `test/tests/test_usage_stats.py` | 真实临时Git仓、聚合、模板列合同与stats入口回归 |

与adapt一样，独立Skill随extensions整体分发。`/story stats`不要求需求编号、系统token、Story flow或模型手动同步数据；不是需求执行阶段，也不触发新的使用记录。安装后从Skill自身路径定位脚本与共享合同，不能硬编码维护仓路径。

## 2. 执行链与快照

内部命令分为 `python <已安装Skill>/scripts/stats.py collect --project-root <目标仓> [--version <业务版本>]` 与 `python <已安装Skill>/scripts/stats.py publish --project-root <目标仓> --analysis-id <collect返回值>`，由独立Skill按顺序调用，用户入口仍只有 `/story stats`。未给版本输出全版本总览及分组；`--version 未知`筛usage.version=null。没有指定版本数据时报告空范围，不退回全版本。

脚本先通过S1对已有需求做有限对账，再取得usage的完整字节快照和一次固定Git HEAD，后续所有数字只基于这两个快照。目标没有Framework/原生材料时保留已归档usage；存在坏配置/坏证据时报告真实错误，不当成无数据。只需usage/Git的新克隆可统计已有归档事实。

Git命令用参数数组执行，取固定HEAD可达普通提交，不fetch。完整提交正文只从独立 `[TicketNo:]` 行取唯一AR/DTS编号；Description里其它编号不参与。SHA去重，author邮箱作为开发人身份，committer带时区时间用于标题起止；merge不重复父分支，二进制numstat不当行数。无对应usage的提交不创造需求节点。

事实JSON记录分析范围、HEAD、usage快照摘要及各聚合的原始分子/分母。摘要只绑定这次计算输入，不参与业务门禁，不建立统计历史登记中心。模型从同次facts取数，不重读变化中的Git后自行改数。

## 3. 聚合合同

| 指标 | 算法 |
|---|---|
| 需求数 | 当前范围usage需求键数；只要有记录即计为使用框架编码 |
| 业务版本 | 用初始化version精确分组；null为未知组，不取当前AppVersion覆写 |
| 开发人数 | 关联提交author邮箱并集；全版本重新去重，不能累加版本人数 |
| 代码量 | 关联普通提交numstat加/减分别求和，按SHA去重；名称为关联提交变更量 |
| 标题时间 | 同一提交集合committer时间min/max；显示开始—结束，不显示几天几小时；无关联提交不编时间 |
| 步骤使用数/占比 | 有该步骤节点的需求数 / 当前范围全部usage需求数 |
| 步骤完成率 | completed=true需求数 / 使用该步骤的需求数；零分母显示— |
| 初始化环境 | version/fw/ext/agent/model组合；组号仅用于报告内两表对应，不写usage |
| 平均耗时 | 每环境每步骤只取completed=true且spent为可核实数值的需求；spent合计 / 这些需求数，秒转分钟；没有样本显示— |

steps顺序读共享合同。零秒是有效值，null和未完成不当0；不对多个组的均值再做简单平均，不跨步骤求总耗时。不同步骤占比不相加。平均时长包含可观察区间内等待与中断，不是AI纯工作时间或模型排名。

## 4. 模板与成文

模板与 [spec样例](../../../spec/1.9.9/11-使用情况统计与归档-预期统计报告样例.md) 保持下面的节与列合同，不复制样例业务名或数字：

1. 报告信息：项目、范围、报告生成时间、统一时区。全版本总览标题带关联提交起止时间。
2. 总览指标表，以及功能使用表：功能步骤、使用需求数、使用占比、步骤完成过的需求数、步骤完成率。
3. 业务版本汇总：版本、使用需求数、开发人数、提交数、新增/删除行数；每个版本标题带起止时间，下面同一功能使用表。
4. 初始化环境表：环境组、业务版本、Framework、Extension、agent、模型、需求数；步骤均值表以步骤为行、环境组为列，单位分钟/需求。
5. 简短统计口径，只解释分母、完成过、初始化快照、Git时间和spent含义一次，不复述全部表格数字。

指定版本报告只保留该版本的指标/步骤/环境表，报告标题带该版本起止，不混入全版本总量。没有逐需求明细、独立周期时长表、版本总需求数/全员分母或缺失数据专题；样例最后的命令说明不作为生产报告正文。

模板使用占位和条件说明，模型只组织表达，脚本提供数值、已格式化比例/时间。输出前核对每张表的表头、分隔行和数据列数一致，数字与facts一致；该机械检查复用测试域现有Markdown解析能力，生产脚本不因此新增库。生产发布前由统计脚本核表头/数据列数、范围、时间标题及表中数值与facts一致；比较的是模板已定义的结构和聚合值，不引入语义关键词评分。模型语义说明仍按事实核对。

## 5. 候选与正式报告发布

输出根为 `<features_dir>/.usage-stats/`，目标目录按既有配置解析且不入库。每次脚本计算生成唯一analysis_id，在本次子目录保存不可变的facts.json；模型按脚本返回路径写同目录report.draft.md，不能直接覆盖正式报告。

根目录仅有一个 `current.json` 输出索引，包含pending与published两个analysis_id。它只选择当前统计候选/已发布报告，不管理需求或执行阶段，也不进入usage。更新索引使用短文件互斥和原子替换，不在模型生成期间持锁。

操作顺序：

1. **collect**：先完成对账和数据快照，写 `<analysis_id>/facts.json`；成功后原子设置pending=本次id，保留published不变。返回facts路径、候选路径和id，不返回旧报告冒充本次结果。
2. **成文**：独立Skill让模型读取该份facts和模板，仅写该次report.draft.md；模型失败时，上一份published报告保持可用，本次明确未发布。
3. **publish**：脚本接收analysis_id，不接收任意项目外路径。核pending仍是本次id、facts字节摘要/范围一致、候选结构与数值通过；不满足则拒绝，不更改published。
4. **原子可见**：先将本次候选原子改名为同目录report.md，再原子更新published=本次id、pending=null。只有索引更新成功才返回正式报告路径。若在两步之间中断，旧published仍有效；重试publish可根据本次facts/完整报告继续完成，不重跑统计或业务。
5. **并发**：后发collect更换pending，旧请求的publish明确返回“已被新统计请求替代”；不能发布旧scope覆盖新请求。已发布的同一id重复publish返回原结果，幂等不重复发布。

统计事实JSON与报告永远从同一个analysis_id目录读取；根目录不再并排放容易混用的latest facts.json与report.md。每次成功输出带明确范围、时间和实际报告路径，不把统计目录里存在旧report当本次成功。

这些子目录是运行输出，不要求历史归档。成功发布后可按本工具生成的清单清理已不被pending/published引用的旧输出；仅清理自身目录并验证实际路径在输出根内，不扫描删除需求产物。不增加长驻服务、后台任务、依赖库或永久统计台账。

新增发布动作仍属于stats维护Skill内部流程，用户入口保持 `/story stats`；初始化采集、业务操作和Git提交不因发布失败重做。

## 6. 自验

隔离Git仓覆盖两种TicketNo、不同合法编号长度、不同业务版本、同需求多作者、跨版本同人、统计文件晚于代码提交、Description附带其它编号、单提交/merge/二进制/空范围。测试从真实CLI读取，不只测手填事实对象。

特意使使用率、完成率和均值分母不同；核默认全版本与分组的加和/并集关系，指定版本和未知组，标题时间跨时区正确。模板以不同环境组数量渲染检查列数；核安装后路由真实进入独立Skill、stats不建需求/步骤、正常对账可以更新已有结果。

增加四组发布反例：旧报告有效时新模型生成失败；两个不同version请求交错；候选列数/数值/范围不符；report改名后索引更新中断再重试。必须断言旧published仍可读，错误候选不成为当前结果。

结构检查不能证明模型总结准确；模型报告与facts、模板的完整一致性在S4验证。实际G/X按diff交回，旧提示仍有效就保持，不预认删除量，更不为预算硬删。
