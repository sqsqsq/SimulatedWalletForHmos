### 关键规则落点

- **初始化（D01）**：
  - 读 `<需求目录>/.usage-input.json`，requirement / name / version 三键齐全才接收，version 可为显式 null；
  - name 为 null 时整组接收一次，之后相同输入幂等清理，不同输入报「已固定」、保留文件；
  - 坏输入保留原件，完整诊断一次给出；
  - agent / model 只在首次创建节点时进入；
  - fw 取框架根的 `package.json`，ext 取已安装扩展的 `manifest.yaml`。
- **身份**：显式 requirement → 已关联本 feature 的需求 → 输入文件里的 requirement → 同名 feature。feature 已属于别的需求时拒绝跨需求改写。
- **终态游标（D02）**：
  - 终态只来自三类：原生闭环、Story 成文登记且 spec 闭环（结束取两者较晚的时刻）、update 关轮（完成）或撤回（终止）；
  - 指纹由来源、终态类型、原生对象身份与结束时刻组成；
  - 中间结论只更新 verdict，不推进游标；
  - 同 id、或早于游标的旧快照不采纳；
  - 同时刻不同身份或一次出现多个新终态，按「归属证明不了」处理，记耗时未知；
  - 早于本轮起点的旧终态只补历史，不结束本轮；
  - 有完成没起点，耗时未知，之后不回填精确值；
  - 撤回只结算已知区间，不增加完成。
- **单文件事务**：
  - OS 互斥锁（Windows 用 msvcrt，其它系统用 fcntl），等锁上限 10 秒，超时报「稍后重跑原操作」；
  - 锁后重读；坏 JSON、冲突标记、不支持的 schema 都拒绝覆盖；
  - 同目录临时文件 `os.replace`，失败时原字节保留；
  - 没有新事实时不写文件；初始化输入在写成功之后才清理。
