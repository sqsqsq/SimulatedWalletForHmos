## 1. 正式图与阅读图

**正式图**：story-figure 块与独立 `.mmd` 的建源、按源重铺、坏块诊断都保留。它不再意味着要做 SVG。

**阅读图**：工作集合只取 P2 的 `plan.reading.items`。
- 每个候选在放置小节末尾（最后一行非空内容之后、同级下一节之前）有一对 `<!-- story-reading:<ID>:begin/end -->`。同一处的多张按写作设计顺序排列。
- 正式形态槽是空的。阅读形态槽里只有一行 `![<阅读问题>](figures/<ID>.svg)`。alt 里的 `\`、`` ` ``、`*`、`_`、`[`、`]`、`<`、`>` 逐个转义。
- 正文与 Mermaid 始终保留。

### 1.1 槽解析与规范布局

`story/document.mjs`：
- 新增 `FIGURE_MARK`、`markPairs(lines, mark, noun)`。成对标记的配对、唯一（不分大小写）与围栏豁免只在这一处实现，正式图块与阅读槽共用。原来 `figure-view.mjs::figureBlocks` 退出。
- `readingSlots(lines)` 在 `markPairs` 之上再核内容：只认空，或本 ID 的一行引用。别的内容属于作者，报错，不清除。
- `withoutReadingSlots(text)` 是请求身份的唯一剥槽算法：内存里去掉整个槽，正文与 Mermaid 一个字不动。

`story/figure-view.mjs::layout`：
- 先移除全部合法槽（连同紧挨在前的一个空行）。
- 再按选择把槽放回各自放置小节末尾。
- 放置按 P2 的 `headingPath` 逐层精确定位，找不到或同名有歧义时一次报全。
- 同一份文本重排得到同一结果。prepare 由它实现；status 与 svg 用它判错位（规范布局里该在的行与现在不同）。

### 1.2 view 各命令

| 命令 | 现在做什么 |
|---|---|
| prepare（不带 id） | 正式图建源；阅读槽整体同步：移除已取消的合法槽，迁移位置，按顺序重排，补建缺的空槽。槽结构坏、槽里有作者文字、放置找不到或有歧义、写作设计的阅读图选择有问题时，整次零写 |
| prepare --id | 正式图 ID：从源重建这一块（原行为）。阅读图 ID：整体同步阅读槽。一个 ID 同时属于两类时，要求不带 id 执行 |
| mermaid | 正式块按源还原；全部合法阅读槽置空。不读写作设计，首次起稿不会被阅读声明锁死 |
| svg | 正式块不动；只把验收成立的选中图放进自己的槽，其余槽置空并说原因。孤立槽、错位或放置问题时拒绝写 |
| toggle | 有任一槽展开就全部隐藏，否则执行 svg。既无选择也无槽时，说明不需要 SVG，不做任何操作 |
| svg / mermaid / toggle --id | 只操作这一张阅读图；正式图 ID 被拒绝 |
| status | 只读，返回 `readingWork` |
| review-request / review-check | 只认当前选择里的 ID；不在选择里的明确拒绝 |

**旧格式**：story-figure 块里只有一行 SVG 引用时，报「旧版阅读形态，本版不再读它」，并指向旧版切回或从 init 重起。源还在时，`prepare --id` 从源重建这一块。

### 1.3 验收请求 v2

`story/figure-reading.mjs`：
- 请求固定为 `version: 2`、`method: story-reading-review/2`。
- 四个必核项：`semantic_fidelity`、`reading_gain`、`visual_readability`、`placement`。
- 原请求文件、request_id 派生、报告四键与状态分类都沿用。

`inputs` 的组成：

| 字段 | 内容 |
|---|---|
| `selection` | 问题、增益、放置、全部依据写法 |
| `basis[]` | 每条依据的规范化路径、标题路径、内容摘要与 `from`（对应的依据写法） |
| `context` | 放置小节的标题路径、正文摘要，以及同一处的槽顺序 `order` |
| `svg`、`resources`、`render` | 字节摘要，与原来相同 |

**依据的读取**：
- 逐条实际读取。整份文件绑定全文；`> 标题` 指到的那一节连同子节一起绑定。
- 同一路径与标题路径只绑定一次，多种写法记在 `from`。
- Story 依据取 `withoutReadingSlots` 之后的正式文本。只显示或隐藏不改身份。
- Story 内容的摘要先做稳定化：标题序号与「图 n ·」不计。
- Story 依据或放置小节里，正式图块与 `.mmd` 不一致（含源缺失）时，报「依据未同步」，不出请求，旧图不能 ready。
- 读不到、越界、标题有歧义、放置找不到，都明确失败。

**审查任务**：
- 给出阅读问题、增益、放置与顺序，以及 SVG、渲染图和资源路径。
- 按小节取的依据，原文用围栏放进任务（围栏长度随原文里的反引号自适应）；整份文件给路径。
- 放置小节的正文与正式 Mermaid 也在任务里。
- 写明四项各判什么，包括「只换颜色或方向不算增益，没有增益判 FAIL，建议回写作设计取消」与「亲自看渲染图，看不了判 UNKNOWN」。

**旧请求**：version 1 或旧 method 判 `invalid`，原因里写明当前方法是 `story-reading-review/2`，要求按当前选择重新生成。没有保留 v1 分支。

### 1.4 `readingWork`

| 选择与证据 | 结果 |
|---|---|
| 明确不采用、理由非空，且声明、槽、正式块结构都没有问题 | `applicable=false, complete=true`，items、unmanaged、problems 为空，`next=null`，有 Mermaid 也一样 |
| 选了 n 张，全部 ready | `applicable=true, complete=true` |
| 选中项缺槽、错位、缺 SVG、渲染、请求或报告，或审查失败、过期 | `applicable=true, complete=false`，逐项给 state、reason，`next` 非空 |
| 缺选择节、仍是占位、坏声明、依据或放置问题、标记或源结构坏、孤立槽 | `applicable=true, complete=false`，problems 与 `next` 点明修复入口；items 只列已能确定的候选 |
| 没有 story | `applicable=true, complete=false`，problems 为「AR/story.md 不在」，不推出「无须阅读」 |

- `unmanaged`（未建源的 Mermaid 行号）只在选了阅读图时列出，并计入待办，因为同步槽的 prepare 会一并建源。不采用时，按 03 §4 表第一行给空。
- `reviewCheck` 与 `readingWork` 用同一判定 `evidenceGap`（先核 SVG 结构，再核验收状态）。

## 5. 未验证与边界

- 四项审查的**语义效果**（关系忠实、增益判断、真的看图）只在任务与报告合同里送达，没有真实独立审查实跑。真实宿主能否完成渲染与独审、模型是否自然少选图却表达更好，留给 P4 之后的真实里程碑。
