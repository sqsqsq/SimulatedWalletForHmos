# P5 / R5 adapt 的起步质量、状态与独立审查

必读：[总览](01-实施总览.md)、[R5 spec](../../../spec/1.9.9/09-adapt移植能力.md)、[澄清 §1](../澄清-设计者说明.md)、现行 `story-adaptation/SKILL.md`、`reference/knowledge-adaptation.md` 与 `reference/knowledge-topics.md`。旧 03 知识范围稿不覆盖当前准入规则。当前分额 G140/X55（初始G230保留，自动恢复70及一键入口20转P4，见总览） 已纳入批准总账；用户正在真实仓使用 1.9.8 适配，本包保留本版，不延后。

## 1. 两类适配与知识范围

首装仍先完成机制安装、自检和画像确认，再按基线演进主题与目标仓实际决定列知识范围。首跑集用于发现最早缺口；每项结论为适用且有文件、有据不适用、缺口。盘点写入现有知识交回，不新建知识状态台账。

起步每份最多三项、编码规范不入知识、模式按已登记主题与相同依赖准入均保留。无法支撑首个真实需求的关键决定，明确缺哪项、影响哪一步、由目标维护者补什么；不能以“清单有文件”宣布就绪，也不能为填满四格扩大适配范围。

升级只处理晚于 adapted_for 的知识主题及加载问题。无知识变化且加载正常，不全量重盘点、不重复语义审查；机制一致性、知识结构、内容审查、对接完成分别交回。

## 2. status 输入输出

新增 `adapt-scan.mjs --status --target <目标根> --package <包根>`；沿既有根目录与 extension_dir 解析，读取包/目标 manifest、演进记录、目标激活知识。复用 `knowledgeCheck` 与 followUp 的纯计算，不能调用 `printFollowUp` 或任何 mark/apply 分支。

输出 JSON：包版本，目标 installed/version 与 name/description/adapters/adapted_for，按当前游标可推导的 knowledge/adapters/in-flight 条目，知识 PASS/FAIL 及 kind×form 数量或具体问题。补 `history: unknown` 说明独立进程无法恢复升级前版本和历史已完成事项，不能把空列表解释成历史无待办。

未安装返回明确 not_installed 事实；坏配置/manifest、依赖缺失、坏知识清单分别给错误类别、路径、判定机制和恢复入口；具体修法由消费模型判断。退出 0 为事实读取成功（含未安装），1 为已读到结构自检不通过，2 为输入/运行前置读不出。数量为空与加载失败不同，错误不能被转成空成功。

状态聚合不写 adapted_for、不刷新版本、不生成缓存或自动修知识。输出当前激活知识的内容摘要可复用 `knowledge-use/document.mjs::manifestDigest`，用于交回和审查绑定，不另存摘要状态文件。

## 3. 独立内容审查

知识产物完成后、宣告适配完成前，用宿主当前可用的独立只读子代理/独立会话审查；不复用作者上下文，不用阶段 verifier 的 request JSON 协议冒充独立 adapt 审查。已核 codex/opencode adapter 有阶段 verifier 能力声明，但那并不等于可在无需求编号时运行阶段 verifier。

独立审查任务直接提供：目标根、激活清单及当前内容摘要、已定适配范围、演进主题、对应源码/规范位置、一个正常需求的检查输入、本次质量判据。审查者独立读取事实，按决定支撑、有据性、项目级边界、不适用理由和未完成缺口给结论，不只看作者自评。

`reference/knowledge-review.md` 必须显式交付以下四个审查维度，并在当前知识范围内给出有依据的结论：

| 维度 | 独立核验内容 |
|---|---|
| 条目粒度与归类 | 是否过多过细、未先归类再归纳；首批每份最多三项的判据是否遵守；结构计数不能代替粒度判断 |
| 项目事实的用途 | 是否讲目标仓有什么、在哪里、通常怎么用；是否混入实现推导或代码内部解释，导致消费模型难以使用 |
| 跨文件重复 | 同一事实/约束/方法是否在多个文件重复维护；区分有来源引用、合理互补与内容重复，点名权威位置及合并/引用方向 |
| 编码规范边界 | 是否把已有编码规范改写成项目知识；内容应留在其现有责任来源，不以多写知识替代引用 |

机械参考在 `adapt-scan.mjs` 的 status/审查输入聚合中实现，复用 `activeKnowledge` 的文件名、kind/form、name 和 `appliesWhen`。源码没有独立的“主题 ID”字段，因此只按去首尾空白后的 `appliesWhen` 完全相同分组，列出多文件声明同一用途的原文及路径，标题明确“同用途声明候选，须语义核对”；全量知识索引仍交给审查者。不得从相似度推断主题相同，也不得因候选为空宣称无重复；异名同义仍由审查发现，不新增 topic 字段或另一份主题清单。此提示不影响 PASS/FAIL，不自动删改知识。

任务正文落 `reference/knowledge-review.md`，由适配模型通过宿主原生独立任务能力完整交付。宿主不具备该能力时交给独立会话/维护者审阅并明确未审状态，不能同上下文代签。该能力不需要新增 adapter 文件、平台调度器或 Framework 阶段。

审查结果回到既有适配交回，记录审查执行体、采用知识摘要、发现、修正后的复核结果。实现时允许把实际报告保留在目标扩展 `.adapt/knowledge-review.md`（点目录不随机制复制），它是证据不是状态真源；没有额外的“approved=true”字段。适配内容变了须复核受影响知识，旧报告不可继续声称覆盖当前版本。

`--mark-adapted` 保持“各块已交回后由脚本写包版本”的已有责任。脚本结构 PASS 不代表内容审查已完成；SKILL 在发起 mark 之前必须交回独立结果及未做项，不改脚本去机械判断知识质量。真实独立调用和输入摘要匹配由维护验证核，不能仅以作者填了审查者名字证明独立。

## 4. 两步实施

| 步 | 文件动作 | G/X | 完成条件 |
|---|---|---:|---|
| S1 方法和只读聚合 | SKILL.md、knowledge-adaptation.md、adapt-scan.mjs；退出方法页手写 knowledgeCheck 片段 | 90/40 | fresh、upgrade、same-version、无知识变化、未安装、坏清单各有正确事实；前后文件集合与内容一致 |
| S2 独审与成本观测 | knowledge-review.md 四维任务、新任务入口、交回要求；adapt-scan 复用已解析元数据列机械候选；upgrade-changes 按主题登记 | 50/15 | 独立上下文核四个维度；同用途候选仅供参考；发现虚构事实/错误不适用/跨文件重复并回作者；机制已装与内容未审分别交回 |

回归扩展 `test_adapt_ownership.py`、`test_adapt_source_kinds.py`。独立语义验证包含一个正常目标和一个有真实知识缺口的目标，不修改 Demo 发布件；真实移植及首个 spec 成本只在用户授权时记录。

同用途提示预计≤15行，包含在 S2 的 G50 内。正反例覆盖“同用途但内容互补”和“用途表述不同但正文重复”，证明脚本不把候选当语义结论；独立审查另覆盖条目过细、实现解释、编码规范越界，检查结果回到各自知识真源，不增加知识状态文件。

观测实际人工决策次数、作者轮次与返修；两个计划确认点不构成次数门槛。被替换的重复自检代码退出，安装所有权和升级复制范围不变；业务仓知识不跨仓照抄。
