## 1. 有效决定与交付目标

1. 金样只维护两个现有测试 Case：auto-topup、car-key-sharing，按后续裁定采用两组七件，不含 update 金样；update 测试输入与回归保留。退出 AR90004、银行卡专项等无关效果金样的维护及专用消费者；仍有效的通用机制回归用小型 fixture 承接，不保留第三套业务金样。用户已确认承接 2.x 补齐的业务输入与宿主立场，保留 1.x 阶段/投放协议，具体差异见 P6。
2. 性能优化先消除无效工作：不让报告写入反过来改变被审业务对象，不重复处理已明确去向的提醒，不恢复已退出的逐行裁决机制。
3. 所有本版涉及的 harness 失败都须向模型交付：失败位置与实际事实、判定机制、恢复类别与真实入口、何时算恢复。具体场景的修法由消费模型推导，脚本不开处方。原始诊断不得在调用链中丢失；不能要求消费模型走读 checker 源码才能理解失败。
4. 材料作者表与机器事实分责；递归收料统一相对路径；页面交互进入既有流程章；Mermaid 是图义真源，SVG 只作 Story 本地阅读重述；正式登记、审查、update 比较与归档先实际切回 Mermaid。按用户2026-10-13新裁定，Extension拥有的归档、update、Story生成/检查/状态命令结束后自动恢复可用SVG，过期逐图提示；归档由一个core命令编排，切换与恢复不在adapters、不依赖模型排列步骤。原生harness/独立审查期间仍保持Mermaid，本次不接其结束自动恢复。
5. 沿用 interactive、Framework 只读、1.x 独立实现、不预埋 2.x 过渡机制的边界。金样按 1.x 的单份 Spec/Plan 组织，不引入 CU、蓝图或 design-review。

## 2. 调查后的设计取舍

| 事项 | 已核事实 | 本方案决定 |
|---|---|---|
| 审查身份 | Framework `verifier-material.ts` 已排除 reports 与回执，但包含 lifecycle fragments 和检查状态投影；Extension spec/plan post_check 仍调用 `reportProblems` | 拆开审前产物检查与审后报告校验，报告校验复用现有模块和交付门；不重写 Framework subject 算法 |
| sync-closure | `phase-state.ts::runSyncClosureDetailed` 校验回执后收口；`phase-closure-finalizer.ts` 对已提交闭环保留既有绑定 | 当前对象未闭环、仅落报告时走同步收口；已闭环后补新对象审查仍须完整 harness 采纳，不能统一替成 sync |
| MINOR | 高频术语告警由 Framework `check-spec.ts` 产生，已有修法是改置信度或维护 glossary | 修实际事实或明确暂缓去向；不在 Extension 屏蔽 Framework 真实 WARN，不把“处置过”伪装为 PASS |
| 大任务 | `test_verifier_report_protocol.py` 与 `pre_verifier.mjs` 明确旧逐行裁决已退场；当前仍有正文、写作设计、会议和议题的较大审查输入 | 用现有文件分节阅读、任务顺序与最终跨节核对减载；不新增分批调度器、分批状态或逐条引文门禁 |
| 数值 | 已有项目知识及 decisions 登记，本工程设定数值原本就要登记议题；分析未核各轮是否履行 | 优先复用已确认项目约束；本需求新设值沿既有决定登记、update 承接。禁止从另一条测试运行自动学习业务阈值 |
| 单文档双形态 | 当前 adapters 只上传 Markdown，原生 pre_phase 在 Story 读审装配前可执行 | 上传归档用 Mermaid，本地默认可用 SVG；Extension命令负责切入/业务/finally恢复，归档由单个core入口执行。post_phase早于审查材料装配，不用它提前恢复。zip/打包及派生图指纹重审整体退出 |

以上取舍修正 spec 中基于历史分析的实现假设，保留其目标。R7 的 O9 验收按“同一已处置问题不再要求重复处理，底层诊断如实保留”执行；O12 按当前审查对象减载验证，不复活历史任务。用户的新金样裁定替代 spec 中仍保留的 AR90004 锚步骤。报告/检查状态/片段对身份的局部关系已调用当前 Framework 生产函数验证，四项预期成立，证据见 P7；这不等于完整闭环已实跑通过。

每步交回实际文件动作、验收证据、G/X 与保留/退出核对；未通过不得进入依赖它的下一步。完整需求收口才跑必要全量，细则统一引用 [TEST §5](../../../../test/TEST.md)，不在各分册复制运行器命令协议。

## 5. 保持、退出与完成边界

保留材料 digest/轮次、远端与本地输入、会议原件版本、UX 取舍、十章结构、人工评审区、update 备份恢复、Mermaid-only 与无图路径、知识所有权及原有通用回归。旧运行数据格式不双轨读取；需改格式时升级 schema，并在演进记录中说明旧版收口或从 init 重起。

发布前核七包全部证据、旧承担者已退出、作者及审查者能收到当前规则、README 与版本一致。测试源装一次性 template；正式发布前不写 Demo。需要模型产出或独立审查的验证按用户后续裁定统一进入CLI阶段；确定性离线验证仍由实施者完成，具体安排及授权边界见09。本次只改plan，不修改产品、测试或demo。首个改 extensions 的提交升 manifest 为 1.9.9；正式发布按 AGENTS §7 单独授权执行。

本次CLI除业务验收外，必须交稳定性与性能观察，具体记录项与结论边界单源见[P7 §6.1](../2026-10-14-CLI验证与优化/02-CLI验证与稳定性性能观察.md#2-本次-cli-必须记录的稳定性与性能观察项)。初始阶段和update分别记录；没有可比基线不宣称效率提升，未触发路径保留未覆盖。

结构和行为分开签：格式/链接检查证明文档可读；离线证明机制输入输出与错误路径；独立审查证明内容；两个 Case 的授权实跑观察一次成文、重审、读源码排障次数和人工操作，不预先宣称效率提升。R4 以两个 Case 完成稿上的指定载体定向链为主要证据，不再要求自然生成 SVG；图义等值与双向切换分别取证。

1.x 的 SVG 是本地阅读视图，2.x 的 SVG 是交付物，外部行为合同按用户裁定分叉；本版无系统二进制交付依赖、不为过渡留桩。Framework 自身诊断若需改动，按 P7 输出可复现上游问题，不在只读副本补逻辑。存在该类未解决失败时不得声称“所有 harness 失败均已解释充分”，但可交回已完成的 Extension 范围。
