## 1. 实际改动

### S1 管理块与入口

| 文件 | 动作 |
|---|---|
| `core/story/figure-view.mjs`（新增） | 切换合同的唯一实现，模式有三种：<br>• `prepare`：给未管理的 Mermaid 围栏加 `<!-- story-figure:<ID>:begin/end -->`，写 `AR/story-src/figures/<ID>.mmd`。ID 取首次准备时内容摘要的前 8 位，之后不随内容变。带 `--id` 时以正文那一块为准重建源。<br>• `mermaid`：精确还原。<br>• `svg`：只切有阅读图、来源快照等于当前源、结构检查过的块；其余保持 Mermaid 并逐块说明原因。<br>孤立标记、重复 ID、块内既非源也非引用、源缺失、手改等问题一次列全，整次零写入并给恢复入口。块外正文不动；源与快照按内容比较，不受行尾影响。不建状态文件，形态直接读管理块。 |
| `core/story-build.mjs` | 新增 `view --mode prepare\|mermaid\|svg [--id]`；其余命令读写 story 之前先自动切回 Mermaid，切不回就停。 |
| `core/flow/client.mjs` | 抽出 `runPython`（解释器选择与两路输出合并），状态查询与结构检查共用。 |
| `core/story_flow.py`、`core/flow/lifecycle.py` | `status/story/archived/update/round/reopen/complete` 动手前调用 `ensure_mermaid`：story 里有管理块时经同一个 JS 入口切回，没有管理块不起进程。`archived` 登记完切回 SVG，结果放在 `view` 字段，与归档登记分开；切不过去时如实说「本地 SVG 没有恢复」，登记不受影响。 |
| `hooks/shared/story-view.mjs`（新增）、`manifest.yaml` | 六个阶段都登记 `pre_phase`：原生检查与读审装配之前切回 Mermaid；切不回报 BLOCKER。已核 Framework `hooks-dispatcher.ts` 按 `hooks[phase][event]` 派发 `pre_phase`。 |
| `hooks/shared/pre_verifier.mjs`、`hooks/spec/author.mjs` | 单独调用时同样先切回。 |
| `SKILL.md` 归档段、`phases/spec.md` 闭环表 | 归档链：① 交付门切回 Mermaid，② 上传与读回同一份 Mermaid，③ 登记后切回 SVG；读回核验不成立不算成功。独立跑回执或收口前先 `view --mode mermaid`。 |
| `adapters/story.js`（对接层，不计量） | archive 与 restore 的 `verified` 不成立时输出 `success: false` 并非零退出。升级演进记录 1.9.9 节加了对应的 `[对接层]` 条目。 |

## 4. 与方案的出入和未做项

1. **对接层没有调用切换（与分册 §3 表最后两行不同）**：仓里有既有不变量 `test_requirement_source.py::test_the_adapter_names_no_core_command`，规定对接脚本不认识核心命令。归档链的实际顺序本来就是「① 交付门（自动切回 Mermaid）→ ② 对接层上传 → ③ `archived` 登记（再过门禁，然后切回 SVG）」，所以切换放在 ① 与 ③ 两个核心入口里，对接层只保留「读回核验不成立按失败退出」。这样各部署环境的自备对接层不用跟着改。请设计者确认这一取舍；如果仍要对接层自己切换，需要先改这条不变量。
2. **两个 Case 完成稿上的定向链（源 → 重述 → 结构 → 渲染 → 对照 → 双向切换）未做**：它需要两个 Case 的完成稿、真实的 SVG 重述、看图与独立对照审，依赖 P6 候选稿和独立执行体，放在 P6 之后连同评审一起做。在此之前，「SVG 语义等值」没有证据。
3. **阅读图题**：SVG 引用的 alt 从块所在小节名派生（`<小节名>（阅读图）`），不写回 Mermaid 源。
