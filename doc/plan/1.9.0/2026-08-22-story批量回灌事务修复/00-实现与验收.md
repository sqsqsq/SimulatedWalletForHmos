# Story 批量回灌事务修复

## 问题

旧 finalize 每处理一个 Case 都拿主工程与 suite 初始整体源码摘要比较。首个 Case 写入源码后，后续
Case 全部被误判为 `main_workspace_drift`，Feature 文档也在检查前被跳过。

## 修复

- 每个终态 Case 的 Feature 文档独立回灌，不受源码检查影响。
- 源码按文件比较 suite 基线、当前目标和 Case 结果；只拒绝真实三方冲突。
- 已存在且内容相同的 Feature 或源码记为 `already_promoted`，重复 finalize 可安全重入。
- Feature 目标内容不同则不覆盖，保留现场并记录冲突。

## 验收

- 同批首个 Case 写源码后，后续 Case 文档仍全部回灌。
- 重复 finalize 不重复覆盖、不产生虚假漂移。
- 真实目标冲突只阻止冲突项，promotion manifest 记录 promoted、already_promoted 和 conflicts。
