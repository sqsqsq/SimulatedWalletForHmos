# W12 方案：平台绑定拆离 story——事实归数据侧，规则与脚本零占位

> 背景：内网把 story 复制到**安卓项目**，反馈除 knowledge 外还有四个文件绑着鸿蒙/钱包特征：
> `reference/evidence-rules.md`、`scripts/merge-story.mjs`、`scripts/lint-rules.mjs`、
> `scripts/story-build.mjs`。
> Human 裁决：平台内容拆到 knowledge 可以，但**不要「占位符 + 脚本替换」**——那种机制脆，
> 且会让 story 后续迭代受限。
> 本文是方案，**未经确认不实施**。

## 一、绑定清点（逐处核实过）

| 文件 | 绑定 | 换平台的后果 |
|---|---|---|
| `evidence-rules.md` | 六个取证面的「现状」检索式全是鸿蒙 API 与工程文件名（`module.json5`、`preferences\|relationalStore`、`shared/constant/*Constants.ets`、`hiAnalytics\|hiAppEvent`、`oh-package.json5`、`route_map.json`…） | 检索式全部落空，取证降级链失真 |
| `lint-rules.mjs` 42 行 | `LOCAL_PATH_RE` 的 `\b0\d-[A-Za-z]…/` 段是本工程分层目录形态（`01-Product/`…`05-SystemBase/`） | **最严重**：安卓模块目录（`app/`、`feature-*/`）扫不到，归档件自包含红线**静默失效** |
| `lint-rules.mjs` 99 行 | 裸文件名清单是 `knowledge/constraints/` 的**手工快照**，且已过期（含退役的 `run-modes`、`telemetry`、`app-lifecycle-config`） | 换项目后约束文件名变了就漏检 |
| `lint-rules.mjs` 32 行 | 豁免模式 `story-template-hmos-v1` | 死规则（无害，但该清） |
| `story-build.mjs` 225 行 | `isPath` 扩展名白名单 `\.(md\|ya?ml\|json\|ts\|ets\|mjs\|js\|py)$`，无 `kt/java/gradle/kts/xml` | `` `MainActivity.kt` `` 不被判为路径 → 被当「待覆盖技术标识」要求写进 story，而红线又禁止仓内路径——**复发 W10 撞过的规则互斥** |
| `merge-story.mjs` | **自身零平台绑定**：三项文本校验全部委托 lint-rules（207-209 行）。内网报它是继承所致 | 修 lint-rules 即修它 |

**不算绑定、明确不动的**：`BANNED_TERMS`（灰度/回滚/部署/QPS…守「客户端 vs 服务器」语境，
安卓同样适用）；`merge-story` 59 行编号形态与 71 行术语表列名（spec 模板/glossary 绑定，
同框架沿用）；lint-rules 103 行 framework 字段名；story-build 的 `MEASURED` 量纲表；
evidence-rules §81 的 `architecture can_depend_on`（framework 概念，跨平台成立）。

## 二、取法：按消费者分流，零占位

被否掉的方案是「规则/脚本里留占位符，复用时由脚本替换注入」。替代取法——**平台事实
按消费者分三条路，story 本体里不存在任何待替换物**：

| 消费者 | 取法 | 依据 |
|---|---|---|
| **模型**读的取证方法 | 拆成 knowledge 下独立画像文档，规则文件**引用**它 | `component-profile.md` 被 `ar_design_init.md` §1 引用是同一个已验证模式：规则说怎么判，画像说工程长什么样，两边各自演进 |
| **脚本**读的工程形态 | **运行时从已有配置与目录事实推导**（`framework.config.json` 的 `outer_layers`、`constraints/` 目录列举） | 不新造维护面；99 行快照已过期，正是硬编码方式的失败证据 |
| 推导不出的少量形态 | **通用化判据**，不维护清单 | 清单漏一个平台就复发一次规则互斥；宽松方向误差无害 |

效果：story 后续优化随便改规则与脚本；换平台 = 重写两份 knowledge 画像 +
目标工程自己的 `framework.config.json`，**脚本零改**。

## 三、改动明细

### 1. 新建 `doc/extensions/knowledge/codebase-probes.md`（工程取证探针画像）

按 evidence-rules 现有六个面组织：**对外暴露面 / 端云接口 / 数据存储 / 配置项 / 埋点 /
依赖变更**。每面登记本工程的检索式与文件名——内容就是从 evidence-rules 平移出来的那些
鸿蒙检索式。头注写明：换平台/换工程**整篇重写本文件**，不动 evidence-rules；
权威在本仓，对端不本地改（与 component-profile 同款提示）。

### 2. `reference/evidence-rules.md`：检索式出、结构留

- 各节「现状」行改为指向 probes 对应面（例：「现状：按 codebase-probes §数据存储 的
  检索式扫 in_scope 模块」）；
- 「降级」行的平台词一并通用化（「现状仅内存态 `AppStorage`」→「现状无持久化封装
  （检索零命中）」）；
- 核心公式、六面结构、意图/现状/降级三段式、§81 的 `can_depend_on` 全部保留。

### 3. `scripts/lint-rules.mjs`：推导替代硬编码

- **模块目录段**：`scanLocalPaths(text)` 改为 `scanLocalPaths(text, projectRoot)`
  （或导出 `buildScanners(projectRoot)`），`0\d-…/` 段**运行时从
  `framework.config.json` 的 `architecture.outer_layers[].id` 构造**（escape 后拼
  `\b(?:01-Product|02-Feature|…)\/[\w./-]+`）。通用段（`doc/(extensions|features)/`、
  `framework/`、`RR|SR|AR` 文件坐标）保留硬编码——那是 framework 结构，不随平台变。
  config 读不到时退回只用通用段。两个调用方手上都有 projectRoot（已核实：
  `post_check.mjs` 走 `ctx.projectRoot`，`merge-story.mjs` 有 `--project-root`）；
- **裸文件名清单**：拆两半——框架产物名（`spec|impact|review|acceptance`）保留；
  约束文件名**运行时列举 `knowledge/constraints/*.md` 生成**，从此不过期；
- 删 32 行 `story-template-hmos-v1` 死豁免。

### 4. `scripts/story-build.mjs`：扩展名清单换通用判据

225 行 `isPath` 的扩展名段改为 `/\.[a-z][a-z0-9]{0,4}$/i`（含分隔符判断不变）。
该判据的用途是「文件名形态的 token 不进待覆盖事实」——宽松方向误差无害
（顶多少要求覆盖一个像文件名的词），清单方向漏检才是复发互斥的根源。

### 5. `scripts/merge-story.mjs`：只跟签名

按第 3 条把 projectRoot 传给新签名，其余不动。

### 6. 交付边界与 manifest

- `export_delivery_patch.py` 的 `INCLUDE` 加
  `doc/extensions/knowledge/codebase-probes.md`（knowledge 现在只单列了
  component-profile 与 constraints 目录，新文件不加就不进 patch）；
- `manifest.yaml` 的 `provides.knowledge` 声明它（否则对端 `--phase extensions` 报
  `knowledge_missing`，本仓 `ManifestCoverageTest` 也会拦）；
- patch 前言 CAVEAT 加一句：安卓等异构工程复用时，`codebase-probes.md` 与
  `component-profile.md` 两份画像整篇重写（《story使用指南》复用章的清单顺延，
  指南文档本轮不动）。

## 四、看护（新增）

| # | 看护 | 判据 |
|---|---|---|
| 1 | 规则纯净度 | `reference/` 与 `rules/` 不含平台 API 词（`\.ets\b`、`oh-package`、`hiAnalytics`、`relationalStore`、`module.json5`…——测试域硬编码词表可接受，它不交付）。防检索式回流 |
| 2 | 模块目录段是真推导 | 临时工程配自定义 `outer_layers`（如 `10-Custom`）：`10-Custom/x/y.ets` 被拦，未配置的 `01-Product/...` 不拦 |
| 3 | 约束清单不过期 | 往临时 constraints 目录放一个新 `.md`，其裸文件名即被悬空引用扫描覆盖 |
| 4 | 通用扩展名 | `` `MainActivity.kt` ``、`` `build.gradle` `` 判为路径形态、不进待覆盖事实；`getAutoTopupStatus` 照常进 |
| 5 | 既有行为不回归 | `05-SystemBase/...` 仍拦、禁用词仍拦；63 条 build/merge 用例全绿 |

- 不提交 git。
