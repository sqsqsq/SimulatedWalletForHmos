> 状态：**分析定稿**。本文回答一个问题：三个评审维度已优化五轮，为什么同族问题一直换皮复现。

## 0. 三个维度是什么（本项目的常驻验收标准）

| 维度 | 出处（冻结需求） | 一句话 |
|---|---|---|

## 2. 不收敛的根因

### R1 形态判据必然被"形式满足"——同一失效模式已换皮四次

| 我定义的形态判据 | 结果 | 模型换成的新形态 |
|---|---|---|
| 流程图不能丢 → 给清单 + WARN | 流程图恢复 ✅ | 纯编号清单段（为满足编号守恒凑数） |
| 守恒改按名 + 禁纯编号段 | 纯编号段消失 ✅ | **N3** 编号索引句（加中文名绕过） |
| 决策引用不再截断 | 截断消失 ✅ | **N2** 作者复述 + 占位符双写 |
| 附录收敛单表 + 逐条目 + 结论非空 | 结构去重 ✅ | **N8** 结论列变规约原文复述 |

**规律**：每次定义"不该出现的形态"，模型就用**满足该判据的最省力形态**去填。
形态判据只能判「写没写」，判不了「写的是不是本需求的东西」。
**这是判据层级的错，不是执行问题。**

### R2 没有回归——每轮只验新增判据

上一轮验收判据是 B1–B15，本轮 `02-行为验证计划.md` 从 **B16** 起，B1–B15 **一条都没重跑**。
于是「修好的东西换个形态回来了」结构上不可能被发现——N2、N3 正是这么漏掉的。

### R3 验收判据由实现者自拟，且每轮重拟

实际顺序是「实现 → 拟判据 → 验证」，判据天然对着我做过的事。
每轮"通过"的都是我做过的，漏的都是我没想到的——**而我没想到的那批就是下一轮的新问题**。
「判据从冻结需求独立重推」这条纪律早已存在，但没落成可执行、可追溯的文件。

### R4 内容自检标准只给了维护者，没给被测模型

`AGENTS.md §2` 给维护者写了判据「换一个业务域，这段文字还成立吗」；
而被测模型看到的 `WRITING_CRITERION`（15 条）与注入件表 B/C/D **全是形态要求**，
**没有一条内容自检问句**。模型写作时没有「这是规约原话、不是本需求」的判断工具，
只能事后被门禁拦——而门禁又是形态判据（R1）。闭环从一开始就不成立。

### R5（元层）评审工具本身有口径缺陷，导致维护者误判

见 §1.4 两例。计数类指标必须声明「计什么、不计什么」，否则错口径会直接变成错结论。

## 3. 与冻结需求的对照

| 失效形态 | 违反的冻结条款 |
|---|---|
| N1、N2、N4 | 01-C2「多处都完整复述同一事实…选择一处保留完整主叙述」；01-C3「一项事实同时影响多个问题时，只在主要位置完整表述」 |
| N3 | 01-C1「不预先使用筛选…不能因为判断某项内容『无关』而删除事实」的反面——代理门禁制造了非事实内容 |
| N5、N7 | 02-C2「可以在固定顶层骨架内…合并或拆分三级和四级章节」（能力在，未被用起来）；02-C3「全文统稿处理章节承接与跨章重复」 |
| N6 | 01-C4「Story 附录中的追溯只保留人类评审需要的信息」的同源要求：归档件面向评审人，不承载仓内标识 |
| N8 | 03-C6「适用规约必须落实为具体设计约束、处理方式和验证义务；只列『已命中』不算应用」——**复述规约原文与"只列已命中"是同一类失效** |
| N9 | 03-C1「规约：启用 → 判断是否适用 → 落实 → 验证」，判定粒度必须与规约条目粒度一致 |

## 4. 结论

三个维度上一轮的**结构性修复大部分见效**（附录收敛、图片唯一、编号对照恢复、命中条目 100% 到达 spec）。
但**内容层的失效原封不动地换皮存活**：该写本需求设计的地方写了规约原文（N8，占比 73%–90%），
该只说一次的地方说了两次（N1/N2/N4），该切小节的地方没切（N5）。

根因不在模型，在判据：**五轮下来我加的全是形态判据，而形态判据必然被形式满足**。
下一轮如果继续加形态判据，可以预期同族问题第六次换皮。

方案见 `01-正向方案.md`：把判据从形态升级为内容，并让判据自己不退化。
