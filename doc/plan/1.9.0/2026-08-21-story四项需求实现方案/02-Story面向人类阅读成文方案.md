# 02 · Story 面向人类阅读成文

## 1. 成文顺序

模型先通读全部材料并理解十章职责，再按十章顺序逐章写作。每章写作时仍可读取全部材料和此前完成的章节，不使用结构化事实分配表。

十章完成后：

1. 装配全文预览；
2. 通读全文并回到章节源文件调整叙述顺序、承接、标题和重复；
3. 重新装配；
4. 生成最终内容审计并完成全量复核。

`story.md` 始终由章节源文件装配，不直接编辑，也不整篇重新生成。

## 2. 人读表达

- 先说明本段要解决的问题或结论，再解释原因、参与者、条件、过程和结果。
- 标题使用真实业务名称，H3/H4 只反映真实从属关系。
- 连续因果使用正文；有真实顺序时用有序列表；并列内容用无序列表；横向比较才用表格。
- 强调、引用、代码、图、图片和链接只在能改善理解时使用。
- 接口、字段、错误码、配置和事件放在其影响的功能、异常、验收或附录中，不打断主叙述。

## 3. 内容保护

- 人读改写不能新增、删除或改变需求事实。
- 每章完成后核对本章职责，但不把局部核对当全文完成。
- 全文统稿后以全部来源重新核对，不能用“更自然”或“更短”解释事实减少。
- 图片保留可读替代文本和图中有效信息；链接保留说明文字和原始目标。

## 4. 验收

- 第一次接触需求的评审者无需外查即可理解目标、范围、方案、流程、功能、异常、验收和交付。
- Markdown 形式与内容关系匹配，不存在固定数量配额。
- 统稿前后事实集合一致，跨章完整复述被消除。
