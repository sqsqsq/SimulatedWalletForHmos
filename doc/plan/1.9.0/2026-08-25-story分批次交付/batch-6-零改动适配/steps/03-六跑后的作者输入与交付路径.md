### R46 · S7 单向，机械与语义各补一层

六跑的事实：E 只有三份文档三行，`materialListSkeleton`（`story-build.mjs` 第 2232 行）只种文档；④ 的报错（第 1327 行）与 `story-write.md` 都是「要么引，要么在清单那一行写理由」；作者选了「引」并把理由写进图题；⑫c 零命中；读者审查只问「用了没有、没用的理由成不成立」（`reader-review-task.mjs` 第 83 行），用了不该用的图它不追问。四处一起改：

- **E 种子逐张列图，E 的允许集合同步改**：对 `materials.json` 里每个 image 各出一行 `- 界面图：[名](链接)——{{这张图讲了什么 / 未引用：理由}}`；文档行不变。现在 `materialListTargets`（`story-build.mjs` 第 514–535 行）按设计**排除图片**（「图随材料走，单列会把清单变成文件列表」），⑫c 据它把图片链接判成「不是材料」——只改种子会撞旧门。这条设计被用户的 S7 裁定改写：E 逐张写图的去向就是要单列。所以 `must` 集合加进 `materials.json` 里的每个 image（范围仍从清单派生，不是作者自由列），头注改成「图逐张列，因为不引用的图要在这里说理由」，⑫c 的报错与夹具随之改。
- **规则单向**：`story-write.md` 图那一段改成「不属于本需求的图**不进正文**，只在附录 E 那一行写『未引用：<理由>』；进正文的是本需求的界面，图前一句、图后接着讲」。任务包 §4 同句。
- **④ 加一条机械事实**：E 标了「未引用」而正文引用同一张 → 报「E 说不引，正文却引了：二者取其一」。报错文案单向。机械门证明的只是 E 与正文一致，不证明作者判得对。
- **读者审查加一问**：材料里的图逐张三问——story 用了没有；**用了的，这张图属不属于本需求、有没有必要进正文**（陪衬、旧稿、他单的页面进了正文就是 finding）；没用的，理由成不成立。判得对不对归这一层。
- 装置不动：5 张陪衬正是为这条造的。

夹具三条：E 种子有与 image 数相等的行；E 标未引用而正文引用被拦；只在 E 写未引用、正文不引通过。审查那一问在任务书里。

### R47 · 登记只有一种语义

`story_flow.py` 的 `SPEC_STAGE_ORDER`（第 791–792 行）与 `run_archived` 的下一步文本写「登记 → build → harness」，`phases/spec.md` 写 ④ build → ⑤ 登记。模型照 status 走，⑤ 时 review.md 不存在，`check` 对不在的 review 不判，⑨ 到交付门才报，reopen 一轮。改成**一个动作**：

- `story_flow.py story` 登记 = **`project`**（附录机器区按当前真源重投，现有第一步，保留）→ `number` → `build`（`review-render` 机器区按当前 `decisions.json` 重算，人工区逐字节保留，与现在 `build` 的语义相同）→ `check`（review 在，⑨ 一并核）→ 写登记。现在的顺序是 project → number → check，只是在中间插入 build，不动 project。作者不需要在登记前自己 build；先 build 了也不碍事（幂等）。
- 两处顺序文本改成「④ 逐章落盘与统稿 → ⑤ `story` 登记（自动 number / build / check）」；`phases/spec.md` 里单列的 ④ build 步骤删掉。
- 交付门不变：那时人工区可能已有内容，⑨ 仍要核。

夹具一条：登记后 review 与 decisions 同代且人工区保留；review 有 ⑨ 违规时登记被拒。
