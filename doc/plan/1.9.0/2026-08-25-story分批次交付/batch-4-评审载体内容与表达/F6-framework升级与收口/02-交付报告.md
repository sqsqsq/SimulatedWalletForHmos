## 四、本轮暴露的三件事

### 1. 子 agent 两次空返回，且退回后仍未产出裁决台账（最重）

时序（`events.jsonl`）：起子 agent → 返回空 → 「给它明确的可执行指令＋对模板，让它重写」→
再起 → **又返回空** → 「子 agent 两次均未产出，改为自行裁决」。此后 34 分钟绕在 audit 分配
（`machine_facing` 标记、`covered_by` 需要共享 token）上，`story-verdicts.md` 至今未落盘。

这个失败形态早有台账：`03-踩坑记录.md` 第 62 条「opencode Task 上游已知，无超时参数；
**4 次 3 空**」。批次 3 当时的处置是把 writer 拆成有界步骤并声明「机制不依赖子 agent」，
但那句话把选择权交给了模型——它不知道这条路有已知失败率。

**已处置（`0800e0f0`）**：子 agent 那条路整条退场，四处删除，不加护栏也不改说「主 agent
自己做」（后者仍在暗示另有选项）。作业书内容一字未改。理由：起另一个 agent 想买的是独立性，
而这里买不到——子 agent 由主 agent 启动、prompt 由主 agent 写、读同一批文件；F4/F5 已证明
「独立的」子 agent 照样把清单里的字抄进证据列（272 行证据只有 14 种字符串）。真正的独立性
由机器判据提供（逐字子串、句边界、复用上限、缺什么要写明），不由 agent 身份提供。

### 2. `verifier_provider_unavailable` 在 opencode 上的真实影响面

spec harness 50 项 3 FAIL，其一是它。查证结论：

- 影响的是 **framework 的阶段闭环审查**（`<phase>/reports/` 下的 verifier 报告），
  `blocked` 状态下框架**不生成 `ai-prompt.md`**（本轮实证：该目录只有
  `capability-snapshot` / `ext-post-check` / `fidelity-intent` / `merged-report` / `script-report`，
  对照 F4 轮同目录有 `ai-prompt.md` / `summary.json` / `trace.json`）；
- **不影响** story 成文环节扩展自有的裁决（`story-verdicts.md`）——那条链路由作业书驱动，
  与 framework verifier 同名不同物。批次 4 的两道硬指标测的是后者。
- `balanced_verifier_retained_phases` 可覆写，但 `disabled` 同样不生成 `ai-prompt.md`，
  对 framework 侧那半没有帮助。
- **补齐 opencode 能力不可行**：`adapter-schema.yaml` 的 `publisher` enum 只有
  `subagent_stop`，且其实现是 claude-kernel 家族共享的 hook；schema 明文禁止
  「另建 adapter 白名单 / 按内核家族推断 / 以有 hooks 目录推断」；入册纪律更写明虚标会
  「让 runner 生成一份永远没人发布的 request」。**这是 framework 上游的能力缺口，
  应作为升级反馈提出**：3.0.0 把 spec/coding 的 verifier 设为 required，而只有一个内核
  家族能满足它。

### 3. 产物目录被模型的中间件污染

`ISSUE-206/AR/story-src/` 下有 **21 个模型自造的临时文件**（`_chapter_*.txt`、`_pool_*.txt`、

分不清哪些是交付物。**未处置，留待裁定。**

## 九、结论与建议

1. **本轮不构成批次 4 验收**。硬指标缺数据的直接原因是裁决台账没产出，根因是子 agent 那条
   已知不可靠的路还留在作业书里（已于 `0800e0f0` 退场）。**下一轮起跑即可验证该删除是否奏效。**
2. **AR90006 需重跑**：本轮它死于 provider 内容审查，与被测对象无关。重现概率不明，
   这是第一次遇到 `DataInspectionFailed`。
3. **待裁定三项**：① `DESIGN_HEADING_RE` 静默失效（§七）；② 模型中间件污染产物目录（§四3）；
   ③ 宿主 `conclude` 后终态被 `gate_failed` 盖过——F6 前半 E2 的归因表本意是记
   `concluded_by_host`，实际 gate 判定优先，「这是宿主收工的」这个信息丢了。
4. **升级反馈**（提给 framework 上游）：verifier 的发布机制只有 `subagent_stop` 一种实现，
   而 3.0.0 把 spec/coding 的 verifier 设为 required——非 claude-kernel 宿主在 full track 上
   一律拿不到闭环，且 `evidence_profile=balanced` 对这两个 phase 无效。
