## 1. 为什么会重复（源头），以及为什么之前两版都是补丁

### 1.1 源头

1.0 把一份给人读的文档拆成 **14 个互相看不见的写作任务**：`scaffold` 为每章生成任务书（`story-build.mjs:845-968`），作者逐章写章文件，`assemble`（`:973-1115`）拼回。每个任务从**互相重叠**的来源节取材（合同 `contracts/story-chapters.json` 的 `inputs`：03 旅程 ← PRD 旅程、06 场景 ← SPEC 场景/功能表、08 流程 ← SPEC 流程、11 异常 ← SPEC+SE 异常、13 验收 ← SPEC 验收——同一台状态机的五个视图；SPEC 自己已把同一批事实写了四遍），再用**逐章守恒门禁** `findMissingFacts`（`:247-277`，在 `:1040` 逐章调用）要求每章把自己取材节里的每一行表格、每个数值、每个反引号词都写进本章。

同一事实在 PRD/SE/SPEC/DESIGN 各出现一次、又被四个章节合同各指到一次，门禁就逼作者写四遍。编号守恒（`findMissingIdentifiers :432-444`、`merge-story.mjs:153`）再逼出「场景索引：S1、S2、S3」，`{{ID:}}` 渲染（`:526-543`）与「附录：编号速查」（`:549-559`）把 S/F/AC 三张表凑成第四份。`{{DEC}}` 渲染成 `《决策与评审记录》——"…"`（`:516`）让每次提及都复制一段 30 字引用。

**作者不是不会去重，是被结构禁止去重。**

### 1.2 前两版为什么是补丁

第一版：保留生产线，写完再让作者给每个来源单元登记「去向」，再用门禁核对——量的是「落地了没」，不是「重复了没」。第二版：把登记提前到写作之前当分配表——但这违反冻结 02-C3（核对记录**只用于审计，不参与来源选择、分章或正文装配**；每章**不能只接收预先分配的事实**），而且又加了任务书生成器、白名单门禁、围栏 8 条。两版都没碰生产线本身。

### 1.3 治理

删掉生产线：没有任务书、没有章文件、没有装配器、没有逐章守恒、没有编号守恒、没有占位符渲染、没有附录。一个作者拿全部材料写一份文档，一件事自然只讲一遍——这是人写文档的常态，不是需要机制保证的奇迹。剩下的检查全是**整篇级、已存在**的（`merge-story` 的术语与契约名守恒、四条归档红线、数值溯源），外加冻结 01-C4 要求的**成文后审计**。

## 2. 用户的两点关注：内容会不会丢、模型会不会略写

### 2.1 内容丢失的防线（三层，全是闭环 BLOCKER）

| 层 | 守什么 | 谁判 | 丢了会怎样 |
|---|---|---|---|
| 机械·整篇 | spec 术语表首列、技术契约五表首列（既有 `merge-story`）；PRD/SE 每个带量纲数值在 story 或 decisions 有落点（新，整篇搜）；每个图片单元的文件名、每个链接单元的 URL 在 story 出现 | `merge-story --check`、`story-build check` | 点名缺哪个，spec 闭不了 |
| 机械·逐单元 | 核对记录集合 == 来源单元全集；每条要么 `at` 指向 story 真实标题（可检索单元由机器重算一致），要么 `reason` 非空 | `story-build audit` / `check` | 一个单元没交代即 BLOCKER——丢内容从「静默」变成「必须写理由」 |
| 语义·逐单元 | 每条记录裁「落点成立 / 落点错 / 漏了 / 不进理由成立」，全集无条件，写进报告文件 | verifier + post_check 落盘核对（批次 1 机制复用） | 理由站不住即 FAIL |

比 1.0 强：1.0 守的是「章 × 数量」（表格行数、数值个数），丢一行换一行看不出；本版守到单元、理由成文、verifier 全集复核。第一版实跑证明被测模型能填完 239 行且不拿「不进」逃避（27 条不进全是表头/纯链接）。

### 2.2 模型跳过或略写的防线（三道，都绕不开）

1. **写作指令在它必读的注入件里**（`hooks/spec/story_on_context_load.md`，spec 阶段 hook 注入），且 spec `post_check` 的 `STORY_CHECKS` 把 `story-build check` + `story-build audit --verify` + `merge-story --check` 作为 BLOCKER 跑——写薄、漏、跳，spec 闭不了。执行点与今天完全一样；1.0 那句「模型跳过 scaffold 自己写了一份」的风险来自**有装配器可绕**，没有装配器，检查直接对着它写的文件。
2. **略写在核对记录里现形**：写得薄 → 大量单元落不到任何标题 → 要么回去写全，要么逐条写「不进」理由 → 理由进 verifier 全集裁决 + 测量报告分类计数。「本需求不涉及。」的章同理：该章问题对应的单元若被标不进，verifier 按理由裁。
3. **结构与实质由既有语义判据守**：14 个 `## ` 齐全、顺序一致（机械）；`story_reader_fitness`（叙述能否支撑四问、不能通篇是表）、`story_decision_substance`（取舍有被否方案）保留。不设篇幅配额（G8）。

「一份文档写成」指**一个作者拿全部材料写一份文档**，不是一次工具调用：允许分多次写入同一文件，写完通读一遍统稿。写作指令里明写这句（§7），避免模型为凑单次输出长度而缩写。
