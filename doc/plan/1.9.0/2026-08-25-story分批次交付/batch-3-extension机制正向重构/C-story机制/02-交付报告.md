### ① 为什么是 9589 而不是 ≤7500

参考估算（03 §0）算的是「删旧 + 重写」，**没有把新增的执行器算进去**：

| 新增件 | 行 | 它替代了什么 |

| `probes.mjs` | 198 | `coding/post_check` 里那**一行** `\b名\b` 存在性探针 |
| `obligations.mjs` | 119 | `knowledge_freeze` 账本 + `downstream.loadLedger` |
| `gate.mjs` | 108 | 六份 post_check 各写一遍的入口守卫 + 报错拼装 + 留痕 |
| `source-units.mjs` | 232 | `story-build` 里的取材与逐章守恒函数 |
| `review-render.mjs` | 128 | 从 `story-build` 拆出（保留能力，不是新增） |
| 六份 `author.md` + 两份作业包 + 两份模板 | ≈ 700 | 送错对象的 583 行 hook 文本 |
| **合计** | **≈ 1485** | |

基线态这些能力**大部分不存在**：没有作者面通道、没有探针执行器、没有崩栈兜底、
没有留痕、没有引文核实。把它们建起来必然是净增，而被它们替代的旧实现只有寥寥数行
（一行存在性探针、一本没人读的账本）。

**剩下最大的三块**：`hooks/spec/post_check.mjs` 795（其中 `/story` 三级关卡逐字段校验近 400 行，
是关卡的唯一门禁，逐字段判本来就那么长）、`hooks/shared/knowledge.mjs` 441（三类知识的派生）、
`story-build.mjs` 455。要压到 7500 得从这三块里再砍 2000 行——那只能靠**减判据**，
不是靠更好的实现。

这一条留给你裁定：接受 9589 并把 ≤7500 改成「较基线净减」，或指出该砍哪些判据。
