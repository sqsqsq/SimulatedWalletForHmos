3. **§3 兼容锁核查**：逐条对上了 `test_knowledge_purity.py` 的测试锁（9 文件、frontmatter 两键、

## P1〔须改〕方案自违它新立的原则

**事实**：R-1（§4.0）把 README 原则改为——

> 不写消费方文件的**内部坐标**（章节号/表名/流程环节）

而同一份方案的 §4.1 给出的落法是：

> UX-01 落法=**指针→coding-standards §6.2**（不复制细节,消除重复）
> UX-05 落法=**指针→coding-standards §6.1**

`§6.1`/`§6.2` 正是「章节号」,即 R-1 明令不写的内部坐标。**方案在同一份文档里自违。**

**更硬的理由（不止是自洽问题）**：被指向的
`framework/profiles/hmos-app/skills/coding/templates/coding-standards.md` 位于
**`framework/` 之下——vendored 发布件**,升级唯一途径是 framework-init UPDATE
（`CLAUDE.md` 红线 9）。上游一次改版就可能让 `§6.2` 指向别的内容,而**没有任何机械看护
会发现**——这与本轮正在根治的「文档描述一个不存在的消费方」是同一个病（design-patterns
的废 hook、constraints 矩阵的五个空阶段）。

**建议改法**（三选一,倾向前两者）：

1. 指**规范名 + 主题**：「hmos-app coding-standards 的资源管理章（字符串/颜色资源化）」
   ——升级后仍可定位,不依赖编号;
2. **内联一句事实**：「色值走 `$r('app.color.*')`,base 与 dark 各配一份」
   ——规约本就是权威（`README.md:3-4`）,一句话不算重复,且自包含;
3. 若坚持用编号,须同时在机制侧加一条看护断言（指向的章节号存在）——**但这会让规约内容
   依赖 framework 的内部结构,不推荐**。

## P2〔须改或须等〕「执行体=脚本」目前没有运行位

**方案的判断**（§4.1 UX-01）：

> 验证=脚本（正则扩为 `#[0-9A-Fa-f]{3,8}` 语境匹配 + `0x` 色值数值形式 + base/dark key
> 成对比对）+ 实机深色走查。**执行体真实存在,红线成立。**

**事实核查**——今天**没有任何环节会真的跑这段脚本**：

| 环节 | 现状 | 能否跑脚本 |
|---|---|---|
| spec 撰写期 | 模型自查 + hook 注入指引 | 模型可自行检索,但那是「模型执行体」不是「脚本执行体」 |
| spec 语义复核 | verifier 子 agent | **不能**——`.claude/agents/verifier.md:4` 声明 `tools: Read, Glob, Grep`,无 Bash |
| plan/coding/review/ut/testing | **规约尚未挂载**（本轮 W3 才做） | 无消费方 |

按方案自己在 §1 立的规则——「**仅当验证执行体真实存在时才可标红线**」——UX-01 目前标红线
**不成立**。§5 的结论「每条红线均有真实执行体（脚本或 verifier）支撑」在此点修正前也不成立。

**出路二选一：**

- **A（内容会话自行处置,不依赖机制侧）**：把这类验证诚实标为
  **「模型（按条目内检索式执行）」**——检索式照写（它有价值,是给模型的可操作判据）,
  但不宣称脚本执行体存在。红线可保留,因为 verifier 能判「有没有按检索式给出结论」。
- **B（等机制侧建运行位,W3 承接）**：由 W3 为脚本执行体建真实落点——
  instance 的 phase `post_check` hook。**先例已存在且正是同类工作**：
  `doc/extensions/hooks/spec/post_check.mjs` 已在做「数值来源回查：标『上游约束』时
  读 SR/RR 原文核对该数值是否真实存在」（见其文件头注释第 4 条）——
  这就是「脚本执行体」的现成范式,dispatcher 机制对所有 phase 通用
  （`extension-loader.ts:182-202`）。

**机制侧承诺**：W3 已把「为脚本执行体建运行位」纳入范围,并把机械断言从
「矩阵格子 → 挂载」延伸到「条目声明的验证执行体 → 真实落点」
（脚本=post_check hook / 模型=overlay 或 hook / 实机、人工=豁免）。
**建议内容会话按 A 先行**（不阻塞落地）,W3 运行位就位后,再把确有脚本判据的条目
从「模型」升级为「脚本」——升级是加强,不返工。
