# 分步实施与需求追踪

## 实施顺序

1. 回退并验证稳定基线。
2. 实现来源单元、事实合同和守恒校验。
3. 实现业务标题、章节消费和附录。
4. 实现 Knowledge 分类与 Spec 交接。
5. 实现 Plan 冻结、Story 结论消费和 Extension 适配。
6. 同步四宿主入口并清除废弃路径。
7. 运行正向及故障注入测试。
8. 用当前全部 Case 进行新 suite 验证。

每一步的退出条件均取自 `implementation-contract.yaml`。未满足当前步骤时不得提前修改下一步，也不得用“后续补齐”关闭步骤。

## 追踪纪律

每项 requirement 必须同时具有：生产实现位置、正常行为证据、负向故障证据和真实 Story 位置。文件存在、脚本 exit 0 或模型口头说明均不能单独作为完成证据。

若冻结方案缺少必要决定，停止受影响部分，向用户说明缺口；经确认后另建修订文件和 commit。原方案与验收合同保持不变。
