## 1. 原生观测

**采集**：`test/scripts/dsh_session.mjs`仍是唯一的原生会话读取器。原有`header/children/lines`保持，另输出三项：
- `calls`：原生`tool/call`按`callId`归并它的`tool/result`。同内容的重复结果只留一份，内容不同的都留着给读者判冲突；结果正文只为会派生子会话或跑命令的工具保留。
- `children`：补上原生登记时间。
- `settled`：子会话收尾通知（`subagent-settled`）。

没有另建采集器。

**归并与角色**：`measure_run.native_delegations`按`(原生会话, callId)`看每次委派，按实际派出去的东西与子会话实际产出认角色，label只用来定位：

| 依据 | 角色 |
|---|---|
| 派出去的是产品生成的Story派审载体、蓝图质询载体、阅读图任务 | `story_review` / `questioning` / `figure_review` |
| 子会话写了需求`blueprint/`下的设计产物（canonical或契约转写） | `blueprint_author` |
| 专用`verifier`工具 | `stage_verifier` |
| 其余 | `unresolved`，带label交人判 |

每个子会话给出从原生登记到收尾通知的**观察跨度**（明确含等待，不是纯推理时间）和收尾状态（finished/failed/unknown）。没有收尾通知时跨度为unknown，不按0算；没有保全原件时整项为null。

**失败分类**：门禁种类在harness、story_register之外，另分`story_check`、`review_check`、`deliver`；审查结论按值另计`review_results`。交付门一次过，不抹掉此前的检查、审查结论与返修。

## 2. 必需证据保全

**捕获**：`run_case._freeze_dependencies`经工作区里装好的`framework-access.mjs --action blueprint`取得同一份`source_index`，不在runner里重新解释`source_ref`。
- 范围：契约权威文件与设计依据引用的工程文件中，位于需求目录以外的那些，写入`<point>.dependencies/{manifest.json, project/<工程相对路径>}`；需求目录里的已随需求树保全，不重复复制。
- `manifest.json`记录：case、时点、需求树摘要、蓝图引用（还没有蓝图时记原因）、来源索引原样，以及逐份的原路径、用途、期望与实际摘要、副本位置和状态。读不到、摘要对不上或越出工程根时标`incomplete`。
- 保护：复制前后核原件字节；先在`.building`里写，成功后再改名；同一时点同内容复用，内容不同不覆盖。

**接线**：

| 位置 | 改动 |
|---|---|
| `cmd_checkpoint` | 需求树、报告、依赖在同一个等待窗口固定；依赖没固定成功时，整个检查点命令失败，原件保留，重跑时需求树复用、依赖重试 |
| 初段补答替代 | `initial`、`initial.reports`、`initial.dependencies`作为一组换成同一个`initial.superseded-*`名；回话入队失败时整组回到原位 |
| 终态 | 每次重写`artifact/`时，同一窗口写`artifact.dependencies/`；worker丢失或外部停止仍按原流程，不新增恢复前扫描 |
| `run_multi_case.command_checkpoint` | 记下依赖清单的位置、摘要和状态 |
| `promote-checkpoint` | 核清单在且摘要与记录一致才回流，回流记录带上这组引用 |
| `finalize`终态回流 | 改取本run固定的`artifact/`及其依赖清单，不取后来的工作区；没有固定终态时退回工作区并标`terminal: incomplete` |

源码差异三方回灌的职责不变。
