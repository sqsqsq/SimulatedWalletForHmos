## 2. 完整协作设计

正常链为：

`材料/人答版本 → 原生范围与共同设计 → 按对象语义读取原料/authority/工程事实 → 蓝图实体义务与原生质询 → Story/Review → 专用独审者原件 → 登记/实际交付 → 按授权CU Spec/Plan或update`

测试域只观察、保存和评价这条链，不替作者补实体/报告，不向Case注入维护答案。

1. **来源由真实合同分责。** scope仍走原生current-scope协议；contract authority由原生完整契约validator核Pointer与内容；原始出处、工程文件和人答按用途交给读者。去掉混合support一律文本includes/材料登记的路径。派生契约不新增为材料版本，也不搬出需求目录。
2. **一条命令读取一份当前来源。** 退出不完整目录stat驱动的跨调用来源缓存；复用现有命令ctx，不另造缓存/状态服务。下一命令重新读取，写入后不得复用旧ctx。模块loader缓存与D08版本生产保持。
3. **独审者返回完整原文，调用方原样保存再消费。** 统一首审/格式返修、宿主三类只读任务及作者接收职责；权威完成回复与进度/外层通知分开，调用方不补正文或覆盖声明。保现有prepared/originals、原生生成和阶段/SVG合同，缺交接保持受阻；不用权限升级、generic或未审降级代替。
4. **知识在两个粒度落实。** 蓝图作者写真实实体义务/角色；原生只投影目标内部已有精确机器内容。合法phase absent由Spec/Plan形成自己的产物，invalid/真实权威冲突按原因回owner；不强制蓝图预写全部机器产物。外层must不自动投影，CU仍须真实落实与消费，不新增映射账或投影器。
5. **语义收敛回原责任。** 蓝图负责目标/接口/状态/数据生产消费/恢复；Story负责独立业务阅读；Review只收真裁决。把长散规则重组到这些职责，退出重复、冲突和“缺文件就问人”的解释，不按auto/car追加特例。
6. **工作少做重复，证据不减。** 采用既有L1–L4分工；旧E批的明确重复准备在本版C批落实。观测修在现有采集/解析/度量，报告零值不能掩盖未识别/未覆盖。

精确接口、正常/异常处理、状态与消费者见[原生合同与职责](参考/01-原生合同与职责.md)。该分册是工程决定，不把关键接口选择留给执行者。
