## 2. 生产者、消费者与退出

**生产者**：`hooks/shared/framework-access.mjs`。
- `readBlueprint`：在原生检查前后各取一次契约权威文件的字节，前后不同报`contract_authority_changed_while_reading`（stale），然后按`consume ?? blueprintId`产生`source_index`。
- `authorityRefs`：契约段的位置与原生`validateBlueprintContracts`逐段核对的位置一致。
- `authorityOf`：原生检查结果里`blueprint_contract_authority_*`为空时，给出每份文件的摘要；不为空时整组incomplete，`sha256`置null，原生问题原样放进`authorityIssues`和`problems`。
- `sourcesOf`：依据或冲突引用与某段引用完全相同时，记进那份权威文件的`refs`；同文件的其它位置（父子指针、整文件）逐条报“不是原生核过的那一段”；其余引用的处理不变。
- `refsOf`：只收各集合的provenance，契约段的`source_ref`退出。

**消费者**（同一步切换）：

| 读者 | 改动 |
|---|---|
| `scopeConsumption` | 吃同次索引，不再重算 |
| `storyReviewVisual` | 收可选的`read`；`sources_sha256`并入`authorityFiles` |
| `relatedStories`/`unitSources` | 收`{blueprint, source_index}`，不再给了蓝图又重算一遍来源 |
| `design-source.mjs` | `designSource`保留`read`和`answers`，`sourcesOf`身份并入`authorityFiles` |
| `review-object.mjs` | 收`source`（同命令的`designSource`）；契约文件行由`authorityFiles`给出，退出私有的`contractSources` |

| `knowledge-task.mjs` | 质询/设计任务读`bp.source_index`，并列出契约权威文件；施工单位的Story来源带上同次索引 |

## 3. 局部选择与偏离（交reviewer核）

- **撤掉裸`adoptedSources`**：方案§1.2写的是“裸`adoptedSources`自己调公开validator”。切换以后，产品里已经没有调用方，只剩测试在用。`test_product_exports`要求每个导出都有产品消费者，所以没有保留这个入口；来源索引只经`readBlueprint`和原生完整检查产生。这比方案更严：不存在不经原生检查的来源入口。原来直接调它的三处测试探针，改为把蓝图对象放到canonical位置后走`readBlueprint`，读完撤掉。
- **契约权威问题进`problems`**：它们同时是原生issues。进`problems`后，依赖来源身份的动作（质询任务、Story成文和审查对象）会停在“契约权威不完整”，并给出原生原因；`routing`的提示文字仍是通用的“同步来源”说法，本步没有改。
