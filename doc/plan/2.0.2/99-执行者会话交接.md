## 允许连续推进，最终集中评审

1. 每步先按方案完成定向验证，写出实际改动、结果、失败/依赖、退出项和 G/X/净增后再继续。明确标记“自验完成，待集中评审”，不冒称维护设计者已通过。
2. 满足下一步依赖时直接继续，不逐步停等设计者。全部当前可执行范围完成后一次提交集中评审，设计者仍逐步核证并评估整体链路。
3. 关键设计冲突、必须上游接通的能力缺失、需人工裁定的预算或授权边界，停止相关依赖工作并报告；其余独立工作可继续。不得临时补 Framework、副作用放行或用夹具冒充真实接通。
4. 新 CLI、demo 发布仍单独授权。本次决定没有新增 Git 提交/推送授权；已有用户约定照其适用范围执行。“集中提交评审”不等于自动提交 Git。
5. P4 的真实行为未验证或上游尚未就绪时，如实交回剩余范围，不宣告四步或整版完成。
