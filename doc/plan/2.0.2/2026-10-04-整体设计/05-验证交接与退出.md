每包先经 `python test/scripts/verify.py affected <实际测试文件> [-k <组>]`。每包自验通过并写交回后保留结果，可按总览连续推进，不为计数重复全跑；最终 `python test/scripts/verify.py handback` 沿现有并行通道。原生发布接入验证按根 AGENTS §6。既有 PNG 索引历史失败单列，不能写全量 PASS。

## 2. 授权后的正常 Case

主请求仅 `/story init <需求>`，实际索材时投材料，按模型真实问题回答，不固定回选项号，不提前泄露会议/冲突/解决方式。允许合并合理问题，已有授权不重复问。

自动充值：初段实际送审三件→检查点→`/story update`→取得反馈与新材料→有效人签→更新交付；车钥匙：本地 Story 三件→选择实现方案→原生认可的适用 Spec/Plan 或合法复用，止于 Plan。车钥匙 update 作为授权选项单列，未授权不要求执行；历史本轮没有车钥匙 update 不算产品失败。

真实业务未决未裁定时应正确停在责任方，不给模型标准答案强行跑完；此时只证明正确交互，不能把它计作“Plan 完成”。完成能力需需求方给出所缺输入后正常续行。直接 Framework 入口、单/多 CU、无新 Spec/Plan 以适用需求安排验证，不为覆盖而强拆业务，额外模型调用另获授权。

初段与 update 分别保存原件、人签、冻结输入、被质询候选与回复、当前蓝图、三件交付、dispatch/task/原始报告、CU/阶段证据、原生身份及宿主全部子任务记录。当前 SQLite 和 events 保留；部分运行失败也回流真实产物，不只留最终成功稿。

## 3. 内容、过程和成本如何判

结果：评审者能读懂并决定需求，关键行为/异常/未决/验收完整；图与文相互支撑，技术详情附件可取得；整体设计与施工输入同义，不能靠缩范围得通过。抽查一个决定从原话至所有受影响产物，不是每条写一份重复对账稿。

过程：看原始 task prompt 是否等于派审载体、谁写了原始报告、修改了什么、何时取得知识、人是否实际决定；看失败是否回真实责任。隔离 task 存在不能单独证明结论独立。发现作者改报告即该次证据不签收，保留历史再由独立执行者重审，不能事后覆盖原件补证。

知识：按“看到→理解→应用→传递”看具体设计/实体，不以 ID 和原文回显给分。图片能力不足、色块素材不支持视觉细节、Coding/设备未做，均明确未验证。

性能：首段/update、人工等待/外部故障分别计；用现有 measure_run 的可信读数，未知/合并不可归属不算零失败。看反复读大块材料、错误返修与实际交接成本，不设产品正文长度或固定重审次数。三轴按 TEST §6.4 提议并由用户确认，结构全绿不代替真实行为目标。

## 4. 退出核对

| 退出职责 | 接替者 | 同步退出 |
|---|---|---|
| Story 展开 canonical 全字段/内部映射 | 原生设计附件＋业务摘要 | 全量 contract/data 转储读取器、只证明 Story 全字段相等的测试、相关提示/注释 |
| task 嵌作者全文又另读机器区 | 同一文件索引、完整阅读与实际读取证据 | 双版本嵌入逻辑及专用断言；保留图/会议/决定比较能力 |
| 主模型手拼审查身份与合同 | prepare 的确定性 dispatch、单一报告合同模块 | 重复格式说明、短键推断、作者改原件指引及专用测试 |
| 手写当前采用摘要 | 当前冻结输入派生材料清单 | 旧材料版本手填逻辑；保留模型对采用理由的说明 |
| 业务未知用标签规避施工门 | 原生 review_readiness 与 CU/readiness | 本地猜 admission、把 draft 当交付的旁路，不建 Extension 平行状态 |
| 多文件各修一个局部结论 | 按决定影响修真源、重新派生 | 遗留相反业务结论及把 canonical 矛盾当 INFO 的话术 |

代码审查 request、首份结论锁、旧 Spec 知识真源已退出的保持退出，不重新引入。正常验收、身份/摘要/引用、人工保护、原生施工与合法复用测试保留。2.0.2 不兼容旧在途运行结构，升级说明让旧单在旧版收口或新版本重新 init；adapt 升级保护不是运行时 fallback。
