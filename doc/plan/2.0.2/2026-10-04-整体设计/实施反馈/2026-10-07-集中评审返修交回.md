### 3.3 原生代码里的原因（Framework 3.1.0）

- `capability-resolution-entry-input.ts:279`：没有 run 的 feature，facts 身份是 `executionScopeFingerprint(有效范围)`，有效范围就是冻结范围加上各次修订。
- `blueprint-skill-projection.ts:102`：Spec 产出合格的验收、后面还有阶段时，`design_scope_facts` 一定会提出范围修订。`applyFeatureScopeRevisionsThenMaybeComplete` 在阶段末尾把它写进 revisions。
- `context-facts.ts:212`：feature 载体的身份校验「与 baseline 无关」，代码注释写明了这一点（第一轮阻断 5）。
- `factsBaselineFingerprint`：哈希范围是 `## phase_delta:` 之前的全部内容，包括 frontmatter。

这几条放在一起：正常路径上 Spec 一闭环，有效指纹就变；Plan 要求 facts 绑定新指纹，又要求基线字节不变，两条不可能同时满足。结果只能在 Plan 重做全量探索，这和原生自己的设计说明「后续阶段以 phase_delta 增量追加，不重做全量探索」相矛盾。

## 4. 容量：opencode 的实际压缩触发规则

| 项 | 证据 |
|---|---|
| 版本 | `opencode --version` → 1.18.32；run.json 里实际启动的是 `npm/node_modules/opencode-ai/bin/opencode.EXE` |
| 触发条件 | 二进制内 `SessionCompaction.isOverflow` 调用的函数：`compaction.auto` 不为 false，且 `limit.context ≠ 0`，且 tokens（total，或 input + output + cache.read + cache.write）≥ `vn()` |
| 阈值 `vn()` | 声明了 `limit.input` 时取 `limit.input − (compaction.reserved ?? min(20000, maxOutputTokens))`；没声明时取 `limit.context − maxOutputTokens` |
| `maxOutputTokens` | `min(limit.output, OUTPUT_TOKEN_MAX)`，`OUTPUT_TOKEN_MAX` 默认是 32,000（可用 `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX` 覆盖） |
| 生效配置 | 运行时 `OPENCODE_CONFIG` 指向 `~/.config/opencode/opencode.jsonc`，模型 `bailian/deepseek-v4-flash-0731` 声明 `limit.context 1,048,576`、`output 131,072`，没有 `limit.input` 和 `compaction` 配置 |
| 阈值结果 | 1,048,576 − 32,000 = **1,016,576** |
| 车钥匙会话 | 最后一次成功的 step：input + cache.read 为 998,544，加 output 243，约 998,787，低于阈值，所以没有压缩；下一次请求越过服务端的 `[1, 1000000]` 被拒 |

阈值和计数都用 opencode 自己统计的 token，服务端的上限也在同一量级，这一组数能解释「到上限之前一直没压缩」。服务端报错没写单位，这一点仍然如实保留。

**请用户决定**（我没有改全局配置）：在这个模型的配置里加 `"limit": {"context": 1048576, "input": 1000000, "output": 131072}`。按上面的规则，阈值会变成 1,000,000 − 20,000 = 980,000，在服务端上限之前触发压缩。不需要新的配置框架。

> 更正（复核后，2026-10-07）：交回原先另列「对全局配置设置 `compaction.reserved`」为等效做法，这是错的。`reserved` 只用在声明了 `limit.input` 的分支，没有 `limit.input` 时阈值是 context − maxOutputTokens，单独设 `reserved` 不会提前压缩。服务端报错没写单位，`limit.input` 取多少要先核实服务端的计量口径和实际生效的输入，再给出具体改动。
