# S05 独立读稿及报告接收

[本批安排](00-批次方案.md) · [总方案三表](../00-实施方案.md) · [计量真源](../01-计量基线与投入.md)

**必读输入与前置**　读者协议和发布前登记。对应 R06/R10/R11，AC06–08/12/13。核心为 rules/story-reader-rules.yaml、reader-review-task.mjs、review-object.mjs、review-report-contract.mjs、independent-review.mjs、phases/design.md、flow/check.mjs。 可先改派审及接收；组合待 S03、S04。

**责任、文件动作与退场**　把首次待审对象限定为当前 Story。先读业务稿，再核承诺所需的蓝图、固定人答及必要来源；允许发现明确上游冲突并交回。退出“核设计为何引用或不用”“两层各自成立才一致”及任一层普遍阻断。区分材料身份绑定与必须逐份阅读：精确保存本轮来源索引和不可缺的人答/改稿原件，技术参考按问题回查。变更影响小沿原报告；新材料或全局变化扩大核查。生成任务、报告覆盖判法、接收和交付门同步，避免换提示但仍要求全量核源。

**已定设计与合法分流**　独立读者收到：“先说明单凭稿件能读懂的行为，再核它与有效事实、授权和目标的一致性。指出具体错句、影响和修正责任。设计自身的实质冲突给出出处；已审取舍不例行重开。”父作者仅按现行有权调用回收同一次完成结果，不代写、改键或直接读取宿主会话库。原件单份替换双全文只在宿主公开能力能证明当前读者、该文件及已结束时采用；900c/现行 DSH 未证，默认保留现有可信双全文。

**验证入口与通过条件**　从 prepare 打开完整 dispatch/task，再走读者→接收→登记→交付：正常完整 vs 截断、错键、未结束、历史件残缺、已有 fail；正确稿依据真实待定可交，未答写成承诺须返；同段只改表述 vs 变更权威人答须重新绑定。核 file、真实 final、报告 verdict 和下一动作，不能以父作者自述补证。

**交回**　按材料键逐轮对照不同发现、真实返修及登记；批末组合 S03→S04→S05。 本步预估 G54/X108，按 AGENTS §5 报实际新增/退出、旧职责接替及未取得的证据。交付物的结构、语义和真实运行分别下结论。

**从任务到下游的判法。** 以 `review-object.mjs` 的当轮材料集合绑定不可变对象，把“供回查”和“本文结论所需必读”分开；前者留索引和固定版本，后者取不到必须披露影响。报告生成器只要求说明实际读取范围及对本稿的影响；报告接收器继续按同一对象、当前调用及原件完整性决策，缺源不能沿用原件已变的 PASS。原生蓝图质询的首读与核源不复用这一缩减后的报告合同。凡因工具裁切、调用未结束或引用材料失踪而缺证，返回原读者和本轮固定输入恢复；实际文件本身坏了就明示缺口，不指向最新 inbox 凑齐。
