# S04 整稿表达及改稿同步

[本批安排](00-批次方案.md) · [总方案三表](../00-实施方案.md) · [计量真源](../01-计量基线与投入.md)

**必读输入与前置**　成文与 update。对应 R04/R05/R10，AC05–07/11–13。读 phases/story-write.md、phases/update.md、writing-plan.mjs、chapter.mjs、story-inputs.mjs 和 flow/update.py。 S03 提供原话、蓝图及受影响对象；独立写作样例可先准备。

**责任、文件动作与退场**　蓝图是共同决定真源，写作设计按真实旅程组织，多章可共享一项事实，不在各章节重新定值。最早在写作设计与全文回看处核条件→行为→中间态→恢复→验收及负责方，保留原始验收映射、可选 SVG、原图可读性和恰当的精确查阅。原生字段已有内容就读取，story_details 只补能力缺口。取消让作者以新问询弥补普通写作问题的指路。

**已定设计与合法分流**　给作者：“把同一已定条件落到受影响的正文、图和验收。已有设计明确而稿子漏写，直接改稿；依据确实互斥，标明原文、责任和受影响承诺，回到作决定的位置。”update 首次写入前保存共同底稿、人工稿与本地稿；不同段合并，同段互斥按原话和权限解决，缺底稿留两份和待裁部分。仅有意见按意见处理。

**验证入口与通过条件**　从 story-build skeleton/chapter/check、/story update 的实际问法到登记及送审：已扣款未写卡 vs 交易已完成、已答 48 小时 vs 仍待定、字段缺失 vs 完整显示。覆盖异段、互斥、无共同稿、只有意见以及迟到的人答；检查版本指纹随实际语义改变重绑。对照两个金样，合法表现变化保留，示例数字不进入通用指令。

**交回**　带版本原件、全稿和图/验收差分、人答同步和交付 readback。 本步预估 G46/X68，按 AGENTS §5 报实际新增/退出、旧职责接替及未取得的证据。交付物的结构、语义和真实运行分别下结论。
