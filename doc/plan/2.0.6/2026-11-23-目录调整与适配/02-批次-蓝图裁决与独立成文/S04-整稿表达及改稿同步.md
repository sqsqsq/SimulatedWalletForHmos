# S04 整稿表达及改稿同步

[本批安排](00-批次方案.md) · [总方案三表](../00-实施方案.md) · [计量真源](../01-计量基线与投入.md)

**必读输入与前置**　成文与 update。对应 R04/R05/R10，AC05–07/11–13。读 phases/story-write.md、phases/update.md、writing-plan.mjs、chapter.mjs、story-inputs.mjs 和 flow/update.py。 S03 提供原话、蓝图及受影响对象；独立写作样例可先准备。

**责任、文件动作与退场**　蓝图是共同决定真源，写作设计按真实旅程组织，多章可共享一项事实，不在各章节重新定值。最早在写作设计与全文回看处核条件→行为→中间态→恢复→验收及负责方，保留原始验收映射、可选 SVG、原图可读性和恰当的精确查阅。原生字段已有内容就读取，story_details 只补能力缺口。取消让作者以新问询弥补普通写作问题的指路。

**已定设计与合法分流**　给作者：“把同一已定条件落到受影响的正文、图和验收。已有设计明确而稿子漏写，直接改稿；依据确实互斥，标明原文、责任和受影响承诺，回到作决定的位置。”update 首次写入前保存共同底稿、人工稿与本地稿；不同段合并，同段互斥按原话和权限解决，缺底稿留两份和待裁部分。仅有意见按意见处理。

**验证入口与通过条件**　从 story-build skeleton/chapter/check、/story update 的实际问法到登记及送审：已扣款未写卡 vs 交易已完成、已答 48 小时 vs 仍待定、字段缺失 vs 完整显示。覆盖异段、互斥、无共同稿、只有意见以及迟到的人答；检查版本指纹随实际语义改变重绑。对照两个金样，合法表现变化保留，示例数字不进入通用指令。

**交回**　带版本原件、全稿和图/验收差分、人答同步和交付 readback。 本步修订 4 预估 G78/X128，按 AGENTS §5 报实际新增/退出、旧职责接替及未取得的证据。交付物的结构、语义和真实运行分别下结论。

## 修订 4：章节合同及图文写作

**已定输入。** 正式 Spec R05/AC06 和 @36。H1 是需求总标题；章节合同中的十个 ID 与中文名是 H2 的唯一来源。只在确须成文的路径建稿。作者为 H3 及下层选择业务主题并组织内容，工具负责各级展示编号。

**改最早的生产者。** 在 `contracts/story-chapters.json` 保留十章名称、职责和读者问题，退出章级可省略语义。在 `writing-plan.mjs` 的 shell、骨架解析和有效章表退出“展示标题”、依提纲重排、省略章的操作与指令，改为按合同 ID 检查十章；缺章、重名、换序清楚指出章位置。保留逐章任务、小节树、图的来源与精确引用。在 `story-build.mjs`、`story/chapter.mjs`、`story/check.mjs` 和实际帮助输出撤掉 `--omit` 删章与“只给在场章编号”的退路；不适用章在原位简述本需求依据，避免给不适用章强造表、图或待填占位。新规则覆盖全部实际生成的 Story。

**定稿身份。** 复用 `document.mjs` 的围栏识别、标题树、重编号以及既有 prepare/登记/交付摘要；区分比较业务章名时归一化标题与检查最终文件时核字面编号。定稿只处理可生成区域，保人工区、实际项目名和正文里的业务编号。先统一编号、检查、生成审稿对象，再绑定现版报告和登记。登记后改文或丢号，在发布与回流之前留住修改，返回既有定稿、按影响复核、登记流程；读出产物和已登记字节必须一致。机器投影长段从源或渲染器（如 `story/appendix.mjs`）处理，人工正文不覆盖机器区。

**作者在提纲、逐章写入和全篇回看时收到的关键句。** “一级章沿合同。小节标题写成读者找得到的业务对象、状态、条件、责任或关系；提纲里的读者问题用来组织答案。先确定读者要判断什么，再看现有图表是否已经讲清。关系交给图，条件组合交给表，单一理由用短段。图前一段只交代场景、参与方与看图目的；图中讲清主关系；图后用简洁列表补图外且影响判断的条件、责任和例外。没有额外信息时自然结束。”保留真实动作名、正常图注和必要重复；缺关键分支先修图或其投影源。正文在投影之外可以补一张业务状态图或决策表；图数、表数、字数和列表项数均不定义达标。

**正反对照（仅维护域）。** 将“钱包端承担哪一段”改为“钱包端职责边界”，“申请撤销”作为真实动作可以保留。自动充值 §5.3 图后约 283 字符把实名、支付能力、入口和查询失败混在一起：用既有 §6.1 入口表查全条件，图后只留真正图外的前提。车钥匙 §7 把同身份重试和条件变化后重新发起分清；附录投影的混装信息从相应源修。只拆换行或把相同流程逐箭头转为项目符号，仍须改稿。业务专名和示例答案留在维护材料。

**交回证据。** 从公开 `skeleton → chapter → prepare → 登记 → 送审/回流` 保留实际提示和文件身份。覆盖章标题改名、重排、缺章、不适用章、登记后第 6/8 章及小节失号、再定稿、免写路径、真实动作名、投影足够/投影有缺口、必要例外/冗余复述。替换 `test_writing_plan.py` 中把换名换序省章判成功的旧例；保留人工稿、正常层级、引用和读回回归。
