## 实现边界与交接

- 蓝图作者和原生质询决定事实、权限、共同设计与真实缺口；Story 作者和独立读者负责将有效内容写全、读懂和纠正表达。直接进入施工阶段也要取得本单位义务；批准到 Plan 的工作不得修改业务代码。
- 工程根 manifest 原位保留，知识按根寻址。S09 已用正式 900c 和 f894 在 Codex 首装、升级触发根清单的 docs 钩子，用原生生成器把桥指向 base 内唯一 Story 源。S10/S11 直接按本仓方案实施。[S09 正式接点](04-批次-三方发行与就地适配/S09-核定宿主首装的正式接点.md)
- **强化档。** 实施者按步骤中指定的实际角色、触发时机、关键句和输入对照接手；可自行决定局部函数划分、措辞顺序和符合现有风格的实现。设计者对照真实生成正文、独立语义、下游状态与旧路径退出分别复评。执行者若发现照做仍失败，保原件、报告冲突位置并继续其他独立部分。[2.0.5 真实偏差与成因](../../2.0.5/2026-11-12-蓝图下的人工确认与范围收敛/评审意见/2026-11-23-223900-两例初段基线效果独立复评.md)
- 首次获准修改 extensions 的提交升至 2.0.6。表中源码坐标默认为移动前位置，S10 迁移后后续在 base 真源改；适配/运行与验证禁止再向旧位置同步一份。每轮 CLI 前更新仓内 demo，发布取最后通过测试的同一份外网交付。资料阅读覆盖上述 Spec、两份 draft、2.0.5 两例原件、两组金样、TEST §0–6.5、全量标准和现有源码/测试。编辑范围由步骤点名，不动历史评审、金样模拟前提、用户未提交资料和现有运行记录。
- 产品工程与测试装置分工：主体在行动前收到正向输入；机器判结构/绑定，模型判含义；测试观测与保留异常归维护域。每步以“未问到/未收到/未运行”表达缺证。正常错误优先；假想损坏无实际消费者时结束，不扩大兼容或构造流程。方法取用按[参考读取回执](../../../../output/evidence/2.0.6-plan/methods/reference-read-20261124T070735Z-d0a6bb2755474dc3a24485910d98899b/read.json)。

## 验证与版本收口

每次先核正式 Spec/标准、输入原件、候选身份、受影响生产者与消费者。批内走目标测试或 `python test/scripts/verify.py affected`；批末按 TEST §5 和实际对象执行 handback 及必要 assembly。改测试准备、装配或适配目录须连安装后的宿主实际入口确认。S12 用 `cases`、`assembly`、`handback` 的真实规定组合，不把不同 checkout 拼成一笔全绿。S13 是最终一轮真实模型测试，修改中途不插模型试跑。标准、金样、Case、生成结果分别留身份。结构对照不能代签真实理解，实跑两例不能代签内网系统或未到阶段。三轴分别呈现，达到 90 且用户确认才记达标；限制发布另由人决定。
