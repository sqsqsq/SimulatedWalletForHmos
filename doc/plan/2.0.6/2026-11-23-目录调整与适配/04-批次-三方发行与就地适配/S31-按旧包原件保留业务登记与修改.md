# S31 按旧包原件保留业务登记与修改

承接[联合复评 R1/R2](../评审意见/2026-11-25-164500-S29与S30联合复评.md)，S29 的一次限定返修。以 7b117923 为基线，预算 G20/X12（目标清单保留 G8/X5、旧文件归属与同一写前核 G12/X7）。旧实现与方案的关键偏差是从白名单重建目标清单、从同名路径直接认领已提交文件。

1. 在原位合并入口以目标的有效登记为底，保业务 capabilities、mcp_actions 及其引用，也保其余合法业务登记；同键相冲时按真实所有者处理。只退出明确由旧包换版接替的绑定。以原生 loader 在导入前、第一次 init 后和 adapt 后的实际输出核同一组业务能力、动作、hook 与其实体。
2. 在第一次导入写入前核旧根实际将退出的全部文件。路径同名不能证明内容仍归包。能与受支持旧版的可信前像对上的旧件可退；已有已提交的业务字节或归属未明时保文件和登记，提出具体冲突。未知归属且需要人决策时，在覆盖 base 或写根 manifest 前提示。共用现有 dry-run／apply 归属结果；不要向消费项目增加一个通用状态管理层。对现有“内容明确属于新版发行包”的 base 更新按既定合同处理。
3. 复验固定 2.0.5 原件、1.9.8 对照及三种单差异（另一个有效 capability/MCP action、已登记旧路径改为业务字节、未登记未知旧件），捕获导入、根清单、宿主检查、apply 前后文件与 loader。保住已通过的脏 base、桥冲突、样例、替身缺件及正常旧绑定退出。本步与 S32 同期，在一份新候选交回并复核暂缓额度。
