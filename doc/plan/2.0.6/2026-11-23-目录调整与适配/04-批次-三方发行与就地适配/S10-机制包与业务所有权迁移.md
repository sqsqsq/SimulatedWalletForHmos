# S10 机制包与业务所有权迁移

[本批安排](00-批次方案.md) · [总方案三表](../00-实施方案.md) · [计量真源](../01-计量基线与投入.md)

**必读输入与前置**　源布局、包和装配。R01–R02、R11，AC01/03/14。读外网包和内网组装所有权决定、manifest 实际全部引用、publish_to_demo.py 与测试装配。 S01 计量校准；物料清单可先做，大迁移等 02、03 内容合流。

**责任、文件动作与退场**　外网源交付面迁到 extensions/base；只带通用机制、适配说明、base/examples/knowledge/ 和 base/.gitignore 中 /examples/。用已有 demo 项目知识和替身作测试输入，不把二者当 base 同级发行项。包元数据提供版本及本版机制声明，业务根 manifest 仍为运行时唯一清单；任何随包的机制声明只用于安装合并。安装时的路径均按真实位置调整：技能互引、命令、hooks、rules、资产、文档、测试注入及 adapters 定位。隔离 template 以外网 base、测试用 demo adapters 与目标知识组合。

**已定设计与合法分流**　将大搬迁按同源内容识别，在同一整合提交改生产路径与使用者；并行内容分支先在旧坐标完成，S10 合并时迁其最终内容。外网发行包显式纳入 .gitignore 与 examples；业务侧知识及替身只来自 demo/目标。内网导入覆盖 base，adapter 文件清单与内容保持；业务升级从同一发行取 base 和 adapters。内网不能操作时交相同目录合同、清单和应由内网验的断点。

**验证入口与通过条件**　核外网包解压真实列表、旧机制位置消失、样例实际在包、demo 内容不漏进交付；两次内网式导入比较适配器摘要，业务安装对照来自内网包。目录源迁移与验收规则同时改 test/scripts/publish_to_demo.py、run_multi_case.py 的模板装配和对应检查。将完整根 manifest 装入正式 Framework，验证 init 从 base 启动 Story，以及涉及的原生阶段仍收到各自任务。

**交回**　包清单、地址命中与退出对照、组装实例和一次纯搬迁预算对账。 本步预估 G132/X176，按 AGENTS §5 报实际新增/退出、旧职责接替及未取得的证据。交付物的结构、语义和真实运行分别下结论。

**集成边界。** 源码迁移用独立候选组装，留住已能跑的开发基线；S09 输入已就绪，隔离候选同时验证物料、宿主入口与原有阶段消费者。按实际目录所有者拆现有 `extensions/manifest.yaml` 的条目：包版本、Skill/阶段绑定、钩子/规约等机制声明随 base；项目名称、已激活知识等字段在业务根清单原位承接。包内供适配合并的机制元数据不得被运行时当成第二个项目 manifest。源文件间相对引用在 base 内保持一致；模型示例里以业务工程根为起点的命令改到实际 base，正式知识/适配游标从业务扩展根读，系统调用统一落业务 adapters；没有真实对接时明确缺输入。发布脚本仅显式选取 base 的发行文件。已退旧角标、旧服务脚本或兼容转发件不进包。

**A7　物料与隔离范围（11-24 生效）**　固定包内机制元数据 `base/package-manifest.yaml`，路径字段以业务扩展根为基准保留 `base/` 前缀，供 adapt 合并。名称、机制声明与项目根下唯一运行时 manifest 职责分开。未发布到 demo 前，测试样板知识、替身 adapters 暂放 `test/fixtures/`，不进外网包。可在独立候选推进物料、搬迁与计量；根 manifest 按 [S09](S09-核定宿主首装的正式接点.md) 登记 docs 钩子；包元数据列实际交付的 Skill ID。修正在 base 启动后仍从旧根读取 usage.json 的资源路径。保护 Feature 阶段绑定、项目原有登记及其他所有者的入口；首装与升级分别交生成桥及实际目标。 [裁定与复验](../评审意见/2026-11-24-000641-开工疑问裁定.md)
