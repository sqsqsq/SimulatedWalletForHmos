# S11 就地适配及安装后清理

[本批安排](00-批次方案.md) · [总方案三表](../00-实施方案.md) · [计量真源](../01-计量基线与投入.md)

**必读输入与前置**　就地安装、升级、状态及使用者入口。R01/R02/R10–R11，AC01–03/12/13。仅对需要正式入口的整合依赖 S09；独立的读写逻辑可先做。 S10 提供物料；需要宿主的部分另等 S09 正向签发。

**责任、文件动作与退场**　adapt-scan.mjs 从已安装脚本定位本工程 framework.config.json，仓内子工程用 Git 顶层+工程相对写面核改动；退出跨工程 package→target 应用和同树一律拒绝。读新 base 的机制版本、业务根 manifest/knowledge 和 adaptation.yaml；只合并机制拥有的登记，保目标激活项、人工稿、身份、usage 与合法空清单。首装读 base/examples/knowledge 参考形状，由模型从项目证据写起步知识，包内写前核与就地操作按各自真实时点负责。

**已定设计与合法分流**　适配作者读：“从正在运行 adapt 的业务工程定位目标。用项目实际文件决定哪些知识成立并登记；示例只说明写法。已有知识保留有依据的差异。只有目标知识能被实际入口取得且对接已核，再完成本次适配。”核准后清理本次装入的 base/examples/，保留 .gitignore；清理或版本落盘中断按已完成事实重入，最后写 adapted_for。只处理本次安装包自有临时样例；清理失败不报适配完成。

**验证入口与通过条件**　首装/旧混装升级分别在根、repo/apps/pay 子工程试用，改动覆盖未跟踪文件与已跟踪人工文件须在复制动作前阻止；兄弟工程脏文件不挡。旧游标、激活清单、替身隔离、真实 adapters、同版再跑、失败重入、无需迁在途需求均分别核。原生 init/真正 Story 登录入口及清理后重启需同一正式装配证明。

**交回**　真实入口、清理前后与再次升级三组清单；内网负责方的真实对接报告或明确未验证。 本步预估 G110/X164，按 AGENTS §5 报实际新增/退出、旧职责接替及未取得的证据。交付物的结构、语义和真实运行分别下结论。

**写入时序。** 旧混装首升先读旧 manifest、入口所有权、适配游标和现有激活知识，按真实目标路径保住项目知识及配置，再替换发行目录。覆盖前比较实际将删除及写入的路径与 `git status --porcelain -uall`，归一为同一工作树坐标；发现会覆盖未提交内容则报告具体路径，其他子工程的改动不参与。正式发行说明必须把检查放在解包覆盖之前；不宣称事后运行的 adapt 能恢复被手工覆盖的文件。新版同版重入还要核入口、知识可读与对接状态，不能仅凭版本号宣布完成。额外预算只在定位到具体消费缺口后计入原包。
