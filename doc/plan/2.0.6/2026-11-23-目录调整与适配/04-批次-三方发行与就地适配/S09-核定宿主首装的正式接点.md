# S09 核定宿主首装的正式接点

[本批安排](00-批次方案.md) · [总方案三表](../00-实施方案.md) · [计量真源](../01-计量基线与投入.md)

**必读输入与前置**　设计者拥有外部接点。对应 R02、AC02/03，不把调查派给 Neon。读 Spec A02、目录草案实装与两次 CREATE 的原件、正式 manifest 和本地 Maison 来源。 设计者现在核已有证据；缺正式接点时仅挂起相关验收。

**责任、文件动作与退场**　已核 900c 的 loader 读取根清单，provides.skills 只收 ID 且到根 skills/<id>/SKILL.md 校验；公开 materialize 先验 bundle 再写桥。有效旧布局两次 CREATE 成功但无 Story 跳板；随后物化成功。父根+base 源得到 skill_missing。当前本机 Maison 242f6b1d 对该源位置仍同形。旧地址、第二根 manifest、符号链接、常驻转发件或直读源码均不满足本版。

**已定设计与合法分流**　正式接点的验收输入仅是根处的项目清单、安装到 base 的机制源和已选宿主；输出是 init 返回时宿主原生桥指向唯一真实源。知识保持按根解析。接口语法以正式所有者的发行合同为准，不能先向人提供未经接受的 YAML。无正式材料时状态为待外部合同；若须对外沟通由用户转交，不代发。

**验证入口与通过条件**　到件时核发布提交/树/版本、安装器说明；同一候选干净 CREATE 和已有工程 UPDATE 后直接调用 /story adapt，核宿主实际转向 base 中唯一源。仅显式另跑物化、AGENTS 可见或直接脚本读到知识不通过。已有反例保留，不循环重试同一 pin。

**交回**　当前正式版不满足；已用隔离候选取得 CREATE 和 UPDATE 的正向证据。设计者负责与正式发行合同核对，只有受支持的正式对象满足下列条件才签发 S11 的宿主入口输入。G0/X0 仅指本仓交付面；上游改动未计入、未获准在其仓实施。

**供接口所有者核对的最小合同。** 同一业务根清单声明项目身份、激活知识与包机制来源。注册的 Skill ID 是宿主名称，已安装的 `base/skills/<id>/SKILL.md` 是该 ID 的唯一源；加载检查、桥生成和后续宿主打开的地址须一致。项目 init 在所选宿主确定且有效清单可读后，复用已有扩展物化，CREATE 和 UPDATE 都涵盖新增、改源及已退受管入口；不触发项目知识写作。由本仓提供干净首装、同一项目替换包、另一个宿主、旧引用缺失的输入与期望；正式接口未说明时不发明 schema 字段。若正式版本尚未支持，保持 AC02 未达；本版交付目标和其它独立步骤照原方案执行。

## 技术定案与隔离原型（Plan 修订 2）

**结论。** 在未修改的 900c 公开接口下，根 manifest + base 唯一源 + init 返回即有宿主跳板，这个组合不可用。保持三项约束，可以用下面两处职责改动实现。根外知识寻址、额外人工命令或恢复旧 Skill 源都无须引入。用户未同意拆版，拆版不作为推进分支。

1. **统一 Skill 注册与真实源。** 隔离原型在根 manifest 为 Skills 登记一次包内相对清单 `base/skills/registered.yaml`，知识仍按根处 `knowledge/…` 登记。清单只列 Skill ID，由包维护；加载器与扫描器使用同一解析规则，将每个 ID 定位到该清单同目录下的 `<id>/SKILL.md`。保留原数组登记的既有语义和工程内相对路径校验。上游可以选用等价正式表达，原型字段不能作为 900c 的配置示例。生成包和 S11 消费的具体登记语法必须使用同一个获接纳接口。
2. **在 init 收尾消费注册结果。** 在项目级 CREATE 与 UPDATE 成功完成必要任务后，为已选宿主复用已有受管桥写入和退出逻辑。更新包内清单后，用户无需再编辑根清单。正式实现须沿 init 的原有报告与错误合同表达无效来源、人工冲突及未完成项；不动用户手写入口，不把失败报成就绪。
3. **正向证据。** 在 900c 的独立副本上改变上述两处职责，直接执行项目 init，而非在 init 后补跑物化命令。干净 Codex 工程 CREATE 退出 0，桥的所有权标记和正文指向 `doc/extensions/base/skills/story/SKILL.md`，其中 adapt 路由能解析到同包真实文件；旧地址始终不存在。再仅把包清单中的 stats 换为 knowledge，UPDATE 退出 0，新桥出现、旧桥消失。两轮业务根 manifest 与项目知识文件的 SHA 各自相同。[两轮结果](../../../../../output/evidence/2.0.6-s09-feasibility/result.json) · [CREATE 日志](../../../../../output/evidence/2.0.6-s09-feasibility/create.log) · [UPDATE 日志](../../../../../output/evidence/2.0.6-s09-feasibility/update.log) · [隔离原型复现脚本](../../../../../output/evidence/2.0.6-s09-feasibility/probe.py)
4. **签收边界。** 正向证据覆盖桥生成、更新与 adapt 指令文件可达，仅用 Codex 和隔离修改过的 Framework；没有验证人手实际输入 slash、完整 2.0.6 adapt、所有宿主、内网发行或正式上游接纳。原型脚本不进发行包，也不用于替代 S12 正式候选。若项目坚持使用未改 900c，S09 的正式签收明确为不通过。设计者交付可复现合同与证据，不向执行者转嫁方案选择。

**Q1　开工裁定（11-24 生效）**　依赖仅在当前正式 Framework 的 Skill 源定位与 init 收尾物化。现有 900c 读 manifest，知识注册可用；隔离原型尚不能签正式采用。目录目标完整保留，设计者跟进正式接点。01–03 按依赖在原坐标合入；04 的独立物料、路径准备与写面核查继续，正式语法消费和新目录主线切换见本次评审。 [裁定与复验](../评审意见/2026-11-24-000641-开工疑问裁定.md)
