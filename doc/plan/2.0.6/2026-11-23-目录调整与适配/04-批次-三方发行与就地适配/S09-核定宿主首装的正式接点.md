# S09 核定宿主首装的正式接点

[本批安排](00-批次方案.md) · [总方案三表](../00-实施方案.md) · [计量真源](../01-计量基线与投入.md)

**必读输入与前置**　设计者拥有外部接点。对应 R02、AC02/03，不把调查派给 Neon。读 Spec A02、目录草案实装与两次 CREATE 的原件、正式 manifest 和本地 Maison 来源。 设计者现在核已有证据；缺正式接点时仅挂起相关验收。

**责任、文件动作与退场**　已核 900c 的 loader 读取根清单，provides.skills 只收 ID 且到根 skills/<id>/SKILL.md 校验；公开 materialize 先验 bundle 再写桥。有效旧布局两次 CREATE 成功但无 Story 跳板；随后物化成功。父根+base 源得到 skill_missing。当前本机 Maison 242f6b1d 对该源位置仍同形。旧地址、第二根 manifest、符号链接、常驻转发件或直读源码均不满足本版。

**已定设计与合法分流**　正式接点的验收输入仅是根处的项目清单、安装到 base 的机制源和已选宿主；输出是 init 返回时宿主原生桥指向唯一真实源。知识保持按根解析。接口语法以正式所有者的发行合同为准，不能先向人提供未经接受的 YAML。无正式材料时状态为待外部合同；若须对外沟通由用户转交，不代发。

**验证入口与通过条件**　到件时核发布提交/树/版本、安装器说明；同一候选干净 CREATE 和已有工程 UPDATE 后直接调用 /story adapt，核宿主实际转向 base 中唯一源。仅显式另跑物化、AGENTS 可见或直接脚本读到知识不通过。已有反例保留，不循环重试同一 pin。

**交回**　当前负向裁定已具备；正式正向接点到件后由设计者签发 S11 输入。 本步预估 G0/X0，按 AGENTS §5 报实际新增/退出、旧职责接替及未取得的证据。交付物的结构、语义和真实运行分别下结论。

**供接口所有者核对的最小合同。** 同一业务根清单声明项目身份、激活知识与包机制来源。注册的 Skill ID 是宿主名称，已安装的 `base/skills/<id>/SKILL.md` 是该 ID 的唯一源；加载检查、桥生成和后续宿主打开的地址须一致。项目 init 在所选宿主确定且有效清单可读后，复用已有扩展物化，CREATE 和 UPDATE 都涵盖新增、改源及已退受管入口；不触发项目知识写作。由本仓提供干净首装、同一项目替换包、另一个宿主、旧引用缺失的输入与期望；正式接口未说明时不发明 schema 字段。若正式版本仍不足，设计者只把具体能力缺口与版本取舍交用户，不让执行者改上游、手建桥或私改 demo。
