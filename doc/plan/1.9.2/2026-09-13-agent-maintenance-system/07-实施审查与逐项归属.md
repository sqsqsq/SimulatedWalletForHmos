## 2. 已闭合的问题与修法

### R1：用户级“项目只写实际差异”给出了错误的删除依据

位置：用户 `.agents/AGENTS.md` 当前“表达与验证”第3条，两个宿主副本相同。

现句“每项事实、规则和当前决定只在一处完整定义，项目只写实际差异”没有限定读者。用户级规约约束当前用户的维护会话；产品消费者和隔离测试模型不能被假设会读它。把项目中的产品要求删掉，即使用户级出现同义句，也不构成迁移完成。

**修复**：三入口同步替换为：“事实、规则和决定在明确的责任来源维护；各入口按其读者和使用时机交付必要内容。跨文件摘要或提醒标明来源，修改时同步，确保相关读者能取得完整要求。”

不再要求所有项目只留下与用户规则不同的句子。是否可删必须先核完整语义、适用对象与实际可达性。

### R2：用户级角色把项目身份和一般工作阶段混在一起

位置：用户入口“角色与工作对象”第1–4条。实际正文使用裸称“设计者、实施者”，并声明覆盖所有任务；没有保留用户明确的维护设计者只做方案及评审的边界。

**修复**：通用工作要求继续适用于所有任务；这段明确以“维护 Agent 产品时”为适用条件，使用“维护设计者、维护实施者、消费模型”。维护设计者交付方案和评审、不代实施者改产品；消费模型即使执行产品内部的 spec/plan 阶段，仍是产品使用方。当前任务角色由用户指定。

这只修该角色段，不改用户现有授权、设计文档处理及工作约定。

### R3：Defect 的失效对象清理范围被抽象句替代，项目落点变窄

位置：`docs/PROJECT.md` §8 末尾，原句“删除失效功能、契约、fixture 和测试时同步关闭其引用”已删除。用户级现句强调“被替代”的指令/实现/状态，没有明确覆盖单独废弃的 fixture 和测试；原项目测试规约又对回归删除有特定边界，不能依靠读者自己补出对应关系。

**修复**：在 PROJECT §8 原位置恢复该句。它说明本项目清理对象与直接引用责任，不放到用户级列举。测试 baseline/回归的现有冻结与废弃条件继续适用，不扩大删除权限。

### R4：WalletKit 的具体载体清单应恢复在项目定位中

根 AGENTS §2 删除了项目的具体载体，用户级“指令、知识、代码和工具”不完整包含官方资产、Truth、Case 与报告的职责语境。

**修复**：将 §2 当前“评价对象是消费模型在未知目标工程中的完整行为：”替换为：“Skill、引用资料、官方资产、脚本、Truth、Case 和报告都是载体；评价对象是消费模型在未知目标工程中的完整行为：”。后续行为链和局部证据边界保持不变。

## 3. 哪些是用户级，哪些是项目级

| 内容 | 归属与动作 | 原因 |
|---|---|---|
| 维护设计者/实施者的责任、事实核实、方案交付、修改与验证习惯 | 用户级；项目可简要引用共同方法 | 约束当前用户的维护工作，不定义某个产品行为 |
| 消费模型要完成什么、从哪里读、禁止接触哪些测试材料 | 项目及产品正常入口完整保留 | 是产品输入与隔离合同，使用方未必读取用户级规约 |
| Defect 十二理念、app 特点、定界顺序、日志/代码/经验边界 | 根 AGENTS 和 PROJECT 的现行有效内容保留，本轮不再压缩 | 产品领域要求；根入口与 PROJECT 的读者/加载不能视作等价 |
| Defect 根“app package”关联、补齐动作、测试域门禁 | 根 AGENTS 保留 | PROJECT 未逐项完整承接，不能删原入口后要求读者自行推导 |
| Wallet 协议事实来源、加载链、接口精确性、Truth/Case 裁决、端云与资产边界 | 根 AGENTS/测试 AGENTS/TEST 各自保留 | 产品及测试系统合同；通用词汇不改变其项目归属 |
| Wallet/Story 中间态、迁移桥所有者/用途/退出条件/删除步骤、完成检查 | 项目原处保留 | 项目运行与验收义务，用户“处理旧内容”不能替代具体条件 |
| Story Framework/Extension/Knowledge/Adaptation 分工，信息送达、verifier、知识链、预算、真实 Case | 项目原处保留，当前只做具名角色消歧和必要引用同步 | 描述被维护系统如何工作，不是要求维护模型个人更认真 |
| 用户级“行动前具备信息”和项目级“消费模型在某分支必须取得协议/守卫” | 两处均有作用，各自保留其对象和含义 | 相似措辞对应两个不同合同，不能按字符串同义删除 |
| README 构件表、公开产物列，STATUS 进度和图 | 保留使用者需要的视图，与权威来源核对一致 | 视图/摘要不等于第二套产品决定；单一真源不要求删掉人读信息 |

具体改动应该是“删除这句，因为同一读者在动作前能从某节取得完整等义要求”，而不是“§4 是通用原则，整段上移”。找不到这样的承接证据就保留项目内容。
