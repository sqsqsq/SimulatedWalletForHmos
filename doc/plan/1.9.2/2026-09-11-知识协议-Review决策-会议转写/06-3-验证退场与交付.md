# 步骤6 · 工作包3：验证效果与完成替换

依赖工作包1、2的完整实现。按[总览](06-步骤6-有效结果保真与模型协作收敛.md)交回，不因本分册自动获得真实CLI授权。

## 1. 验证

### 离线（实施者执行）

优先扩已有test_meeting_transcript、test_recheck_list、test_writing_plan、test_author_task_package/入口与verifier协议测试，不新建测试平台。

1. 公共转换：正文/软换行/制表符/超链接混排保持顺序；多列会议表保留单元格与内容；透明内容控件内文字不丢；未知含正文结构明确报缺口。既有RR/SR/UX导入和图片引用回归保持。转换不生成发言人/议题推断。
2. 同一业务内容用姓名时间同一行、分行、表格、时间在前、无时间等中性格式：均能转换并定位。测试不要求脚本产生同样语义切分；模型理解须真实行为验证。原件相同重复导入不改旧raw，原件变化新版本，解析器变化不伪装新会议；原文损坏不静默重建。
3. 任意姓名/术语/时间所在行纠偏：仅差异由模型给出，生成件未改行原样；行号错、原文错、重复行、换行注入、空依据一次报全且不覆盖已有有效件。无纠偏空数组生成原样件。所有引用在对应原始版本可查。
4. topics/notes的重复ID、未知话题、非法范围、未知keep_open/resolves、冲突解决/保留、无效替代目标/环均报到字段；允许多话题共引与原文不全覆盖。无变化但有未决不冒充已收敛；选项拒绝变化不采纳旧conclusion；同话题采纳一变化并保留遗留完整投影。
5. status全部话题出现，包括非本需求和归属不明；派生引用是真实路径且原话与raw一致；多场按文件名排序不能改变有效结论。没会议保持原路径；gates不增加effect副本。
6. 作者/审查对象清单含Spec、Story、Review/decisions及条件会议原件/差异/有效结果；核实际输出，不只搜索提示。正常续写、已写草稿不覆盖、冻结/reopen、人工区保护保持。
7. 相关验证通过后按TEST完成必需全量、failure-modes/adapt检查；framework零diff。核新行为成立及旧正则/旧引用/整份重抄要求与专用测试已退出。过拟合自查覆盖提示、注释、脚本、合同与夹具，不以搜不到Case名代替格式适应性审查。

### 四交付件离线与语义交回

在现有作者输出/审查任务包测试中核：Plan起手给出当前Spec、Review及有才读的review-disposition；不存在Plan时不要求提前制造Plan；送审快照保持与当前决定同步的两种分支有明确出口。测试只证明送达与结构，不证明模型已正确推演。

语义交回由reviewer核三个中性设计片段的处理方向：条件例外合并后是否仍成立、输出是否足够支持后续恢复、已送审快照与本轮批准变更如何共同供下游使用。这是维护方案/提示审视，不运行构造材料的模型评测，不要求产品增加对应判据关键词。现有历史缺陷仅作维护侧对照，不能写入消费提示。

### 模板形成与实际消费

沿现有writing-plan/chapter/drafts测试核替换合同：不同中性主题声明表格均只铺表达意图、不预定列；两组不同但合法列均通过，固定合同所需锚列不能绕过；具名图及有序/无序列表在对应节落实，围栏中示例不充当列表；叙述无字数门。旧表头/图声明给修正出口，解析器没有并行旧协议。已写草稿不覆盖、重合结构不重复报错、待核进原清单保持。

核作者正常入口实际输出：template任务要求设计章节/形式/解释关系，写章任务要求决定列/节点/项目并成文。结构测试不证明这两种工作状态被正确执行。无偏离不制造记录；实际调整文件位于story-src，存在时审查任务给出路径，不参与业务决定或新增冻结门。

真实评价同时看template、写章事件/草稿、最终Story与实际调整：模板是否帮助直接开写、是否提前代写答案；成文是否利用意图并保留条件；具体内容决策是否留在成文；修改模板的原因是材料变化、认识深化、组织改善、原设计有误，还是无依据偏离。分类由维护评价完成，不要求运行模型填写分类枚举。正常列/节点选择不是偏离，合理调整不是失败，作者写了理由也不证明调整正确。

历史金样与template-gap-analysis仅作维护对照，不注入消费上下文。验收不看长度或与金样的字面一致；不恢复JSON编排/source-index，不新增模板审查Agent。

### 两种写作任务的交接验收表

下列在已有writing-plan、chapter-view、writing-flow与任务书测试中扩展，输入用中性题材，不向产品提示复制用例。

| 输入/动作 | 应观察到的结果 |
|---|---|
| 合法十章模板中某节选表格，只写描述不列列名 | 可解析，草稿有标题与可剥除指引，没有模板造出的占位表头 |
| 同一模板，正文分别用两套有意义但不同列名的表 | 均通过模板形式门；若该节有固定合同，仍须满足合同锚列 |
| 固定合同表缺列且模板同位置选表格 | 一项合同问题，不生成两张表、不退化成只核表存在 |
| H3甲/H4结果选表，只有H3乙/H4结果有表 | 甲处仍报缺失，不能借同名节通过 |
| 节选有序列表，只有无序列表或围栏里的有序示例 | 拒绝缺有序列表；真实范围内有非空有序项则通过，不设项目数 |
| 同位置重复形式/通用图与具名图 | 合并相同要求；具名图不能被其它图种替代；只报一处缺口 |
| 形式为空/未知、旧表头/图声明、带列表前缀的形式声明 | 报具体位置与当前写法；不静默当成合法结构选择 |
| 正文比模板多解释一个有依据的分支 | 结构门不因多内容拒绝；语义由审查判，正常深化不强制调整记录 |
| 已动草稿后修改模板形式 | 原稿字节不被skeleton覆盖；返回缺失指引，由模型作有依据调整 |
| 提交剥guide | Story不留下“此处写什么”的操作指令，实际内容仍受结构核对 |
| 调整文件存在/不存在 | 前者在原verifier对象里真实可达，后者不假造空文件/不拦交付 |

reviewer交回时看实现是否仍通过模板columns或旧图声明接线，防止表面改了用语、实际上仍提前约束成文内容。上述离线通过只证明接线成立；是否按两种任务思考，须看真实作者编辑与产物。

### 真实行为（待用户按TEST授权）

真实会议样本由用户提供后验证；当前构造DOCX仅证明转换与引用合同，不证明真实会议理解。样本未到不阻塞本步设计与离线实施，但交回明确真实格式与内容理解未验。不得照新转换器的假设编一个“真实会议”当行为证据。

不以离线绿宣告模型可靠。后续测试至少区分：确定性输入是否完整送达；作者是否实际按关系回看；verifier是否发现真实遗漏；最终业务条件/未决/知识义务是否正确；相关能力有无劣化。原两例作历史定位，中性离线反例不作为模型测试答案。稳定性需同材料、范围、配置的独立重复；若只跑一次，明确未验证稳定性，不推成功率。会议原话中的不同确定程度分别核，知识应用同时核业务可实现性；不要求与历史同小节/同图数。

跨轮评价沿用evaluation/history-comparison.md的来源清单与已核实的义务，维护侧分别列“改善/退化/合法变更/未验证”，不取平均分抵消退化。保留历史正确关系：配置失效与恢复边界、按业务与责任组织验收、按步骤承担知识义务、业务身份与展示信息分工、已批准范围同步；按新材料失效的旧结论不继承。每条先核材料、人工决定、产物时点及版本，缺可比证据就不声称退化。

真实运行成功条件：四交付件在各自阶段保持有效义务、关系与未决；核心历史正确项没有无依据退化；新增设计能满足业务且符合知识；变更按快照规则可追溯并送达。若只跑到Spec，只评价前三件，不能宣告Plan质量达成。相同条件两次可以观察保持性，不能据少量样本保证确定性。需要返修时核首稿/修订稿/最终稿，不能只看最终门禁绿。

交回写当前提交、生产者→消费者、删除/替换清单、实际预算、离线结果、尚未实跑项；只声明已实施等待评审。一次提交统一审，不用本步命令进入被维护业务流程验证它自身。

## 3. 联合验收

沿总览两条完整路径，用现有临时夹具与实际入口核确定性接线。必须覆盖：先刷新阅读件再写notes没有循环依赖；变化与未决共同进入作者输入；模板改变形式时既有草稿不被覆盖；当前人工决定传给Plan而归档快照保持。复用已有用例组合，新增只补连接点缺口，不重复造测试平台。

各包单测通过不能代替联合接线；离线联合通过仍不证明模型理解正确。最终交回一次，真实行为验证边界按§1。

## 4. 全量退场与交付检查

按两个实施包的替换清单核产品、提示、配置、入口和专用测试：没有固定会议语义解析/S#双读，没有模型整份重抄要求，没有无变化即已确认的推断，没有open绝对不进正文或verifier后绝对不修正的矛盾规则，没有模板预定表头及旧图声明双协议，没有措辞专属性判知识正确的代理判据。仍有效的公共转换、知识结构、裁决、冻结、人工区和正常阶段能力保持。

报告分开列机制合同已验证、消费模型实际行为、未验证环境和问题归因。对仍发生的错误区分确定性遗漏、未送达、指令冲突、理解/判断偏离与外部问题；已有充分指引的一次语义失误不自动变成新规则。过拟合检查同时看业务答案与输入格式，不能只搜专名。

交回至少列提交与基线、实际新增/删除/结构成本/字符总量、生产者到消费者路径、必要回归结果、旧路径退出证据、真实样本与稳定性验证状态。未跑到Plan不能宣布四件达标；没有真实会议不能宣布真实格式适应性达标。局部检查通过后不无理由重复全套，真实效果缺口回职责所有者处理。
