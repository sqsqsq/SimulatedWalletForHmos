## 4. 文件所有权与旧机制交接

S3的源码起点是锁定发布源的完整extensions树，包含知识样板和adapters；先在scratch证明同源，再按获批清单进入story并实施首包。旧2.x独有文件不作为隐式混合版本保留。知识、adapters不计机制预算但仍须核来源与业务有效性，真实目标仓知识保护沿原所有权执行。

保留story提交祖先关系、doc/release、运行证据和业务工程。旧2.x的spec/plan现归档于docs/archive/legacy-2.x，当前doc/spec、doc/plan从新2.0.0继续；历史版本号与评审结论保持。1.9.9的需求、发布说明和必要来源文档以锁定提交为依据，后续采用非冲突路径带入；重名文件逐项裁定，不整仓合并。旧产品机制随实际替换退出运行树，历史代码由Git保存，不另挂一套备份Extension让宿主加载。

测试、Case、金样、发布安装器、运行配置和CLI工具按职责选择来源，不能随extensions一键替换，也不能原样保留即宣称可用。根AGENTS与demo Framework沿现行维护契约；确需修订其所有权条款时单列决定，不能让恢复旧源绕过安装安全边界。
