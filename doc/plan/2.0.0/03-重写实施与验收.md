# S3–S4：实现、组合验收与交付

实施前必须完成[新版合同定案](02-新版合同与适配定案.md)。本页确定推进与验收原则；具体接口、文件和预算由S2补齐，不凭本页提前编码。

当前原生接口已按[10](10-Framework-main新版核对与方案调整.md)核实：初次CU接受/readiness、原生@12文档/说明摘要和可选设计知识资产可用于首包定案。首包复用这些公开能力，不新增自有blueprint.md、原生文档renderer或CU接受脚本。1.9.9正式发布身份、能力落点及预算未齐前仍不实施。

## 1. S3实施顺序

首包先将基线切换、升版、最小适配、安装物化和对应测试装配一起打通，按S1保留发布源同源证明，核空白template安装、宿主入口/引用及定向回归。首包不宣称整条业务链完成，但必须能验证其承担的职责；不把安装装配拖到业务实现之后。首包具体接口、文件、范围和预算由S2定案，不在未知新版时猜实现。

新增版专属验证对象：无CU也生成当前人读稿；guide缺失/过期如实诊断；纯guide润色不改变施工业务摘要，真实设计变化正确过期；接受成功而readiness/文档失败时不重复接受；设计知识未声明、可读、声明不可读及直接/Story入口；阅读先后与原件写入者；FW-04当前一般gap、FW-05无run阶段接续。按10中已交合同设预期，仍待复验的旧问题不写成已通过fixture。

随后打通真实材料、设计输入、知识送达和原生蓝图/CU消费，再完成选定的人读交付、意见回灌与更新恢复，收口完整安装/adapt、统计与文档。各能力测试随所在包迁移，最终再核全量覆盖。按最终合同可合并局部动作，不把所有保留代码重写一遍。

每个职责沿生产者、实际上下文、决定、产物、消费者和验证位置完整替换。旧1.x的阶段编排、knowledge-use或自有报告机制并非恢复后永久保留项；若新版原生能力接替，其状态、入口、指令与专用测试同包退出。有效业务覆盖迁移到新消费者。未发布的旧2.x状态不建兼容读取；发现旧格式按项目约定明确报错，指引在旧版本收口或从init重起。真实目标仓1.9.9升级路径是否纳入本版须S2明确，不自动承诺迁移已有需求实例。

旧代码片段只有在新输入输出与失败语义相符时复用，连同依赖和定向测试一起迁移。必要缺陷回最早责任位置，不叠业务关键词判据、重复指纹或旁路CU创建。实际G超估或退出不足按根AGENTS §5解释并复核。

## 2. 测试与底座来源

实施前先按[TEST §5](../../../test/TEST.md#5-离线验证)核当前命令及装配，以下只规定验收对象，运行命令与评分真源仍在TEST。

| 对象 | 处理与证据 |
|---|---|
| 1.9.9回归 | 从锁定发布源引入其新增能力、真实反例及合同；旧Spec等假设按新责任改消费者，不能删除仍有效业务断言 |
| 旧2.x回归 | 保留有效来源/知识/CU/报告/恢复反例，核新版合同后迁移；固定旧文件名、章节或错误API的断言退出并说明新覆盖 |
| 金样及Case | 以1.9.9已审定正本及来源决定为质量起点，保留其有效事实与页面叙事；新版产物布局单独审定，不机械改名Spec为blueprint；旧2.x候选不覆盖新正本 |
| CLI与装置 | 当前tools/cli同步身份、tools/SYNC及中央契约测试独立核实；不被1.9.9回灌降级。宿主输入保留忠实投递、幂等、整批冲突写前拒绝及部分写入可观察语义 |
| 配置与环境 | 不覆盖用户全局配置，不从另一分支带入密钥/绝对环境路径；模型生效limit与压缩/视觉能力起跑前核，旧容量证据只保留适用版本边界 |
| 证据与预算 | 运行证据留output；保留历史failure-modes与EVOLUTION的规则来源，现行台账只登记新实现适用项；预算同源算法与累计账不能被旧分支台账覆盖 |

测试源按三套组合分别登记，不能拿混合组合的通过数解释保持效果：

| 组合 | 固定身份与用途 |
|---|---|
| 1.9.9发布参照 | 正式发布源码、原配Framework、安装器、该发布TEST及测试/Case/金样/配置；复核来源自洽和原有验收边界，不依赖新Framework |
| 旧2.x历史证据 | 固定story提交、当时Framework、测试装置与输入/报告；用于选反例及保留失败事实，不算新版通过 |
| 新2.x目标 | 锁定1.9.9起点、新Framework构建、获批适配与迁移测试/装置；先验装配，再验局部和完整行为 |

每套组合记录源码完整SHA及实际在途差异、Framework构建身份、测试装置来源、Case输入/立场/终点、金样/资源身份及非秘密环境/模型配置。不同组合通过数不相加，测试数量相等不代表断言保持；环境不同比较成本需说明限制。

今天先按实际引用列依赖及拟选来源，S2再定与新版接口有关的迁移动作。每个原业务断言记录旧来源、要保护的结果、新消费者/测试和处置依据；允许改文件布局，不静默删除有效业务覆盖。

| 依赖面 | 首包/迁移必须核的闭合关系 |
|---|---|
| 安装与发现 | publish_to_demo、entries、manifest/schema、overlay、hook、Skill物化及支持宿主入口共同成立；旧bridge由原生接替时核实际发现 |
| template与运行 | workspace复制/排除、原配Framework配置、本地需求系统、adapters、Case规划及终点；开发源确实装入template且无额外旧源 |
| 测试入口与公共设施 | 各组合自身TEST/执行脚本、pytest配置、shared helper/fixtures、进程隔离和ts转译缓存；f5972a82未含story的verify.py/shared_state/conftest，不能假定发布源原生具有它们 |
| CLI与环境 | tools/cli及中央契约测试同源，宿主/模型配置和插件/依赖按各组合身份核，既有同步成果不降级，不复制密钥 |
| 检查与金样 | failure-modes checker/夹具/clause、正本登记与消费者、来源图及审定文档一起迁移；不复制旧专用判据来限制合法新表达 |
| 预算与记录 | 计量算法、适用台账及历史累计一致，证据路径/回流范围符合当前TEST，状态摘要不覆盖实际交回 |

金样先锁定原1.9.9正本及批准对象，逐文件登记正文、Review、Spec/Plan、Mermaid、SVG、界面参考图、README与必要审定/来源材料。审定/来源文档按固定提交在非冲突路径引入或提供可解析的准确引用，核正文及图像链接、来源映射和人工区。模拟建设前提与业务未决原样保持；没有业务裁定的不借金样审定转成已定。发布产品对SVG等能力的实现成熟度单独核。

新版产物组织变更在新目标组合形成待审结果与覆盖对应，不覆盖1.x已审正本；正式切换由用户审定后按项目规则执行。若新旧目录冲突，在S2确定各自消费者和唯一有效入口，再精确迁移，不能把两套正本留成无归属候选。原Spec内容仅供核有效事实/关系，不机械当蓝图答案。

离线逐步跑定向，交回跑适用全量及失效形态；改Framework另跑原生harness。发现失败先辨发布基线缺陷、装配错配、新适配问题或外部限制，不先放宽合同。语法、文件和链接通过只签结构；行为结论引用实际轨迹。

收集错误、跳过、预期失败与尚未迁完覆盖须逐项说明。首包范围之外的未完成适配有明确去向，不能通过排除失败宣称整版全绿；正式整版验收核全部有效范围。原生harness通过不代替Extension业务回归，最终PASS不代替原始审查过程。

## 3. S4组合验收

真实CLI只在用户启动的里程碑运行，使用隔离template，不向消费模型提供本版方案、历史失败答案、checker或金样。宿主只按测试协议代理需求方，不能为跑通补实现指令。

| 链路 | 必须观察到的结果 |
|---|---|
| 系统单与更新 | 真实材料/图片与人签进入设计；首稿讲全条件与边界；Review可裁决；归档字节与授权一致；新材料/评审update完成且旧原件保留 |
| 本地单与CU | 不依赖系统单模拟；整体设计和知识义务进入合法CU，Spec/Plan在原生阶段闭环，多个单位共同与各自责任可核 |
| 直接入口 | 原生蓝图设计入口实际取得Extension需要的作者/质询输入，不能用Story入口成功代签 |
| 人读与知识效果 | 未参与设计的评审者能理解业务、操作、异常和验收；项目事实正确、规约命中和模式角色有实体落点，下游确有应用 |
| 独立审查 | 原始prompt、执行者、读取/写入及报告版本可核；原位改无效报告不能转可信pass；格式新编号恢复正常；无视觉能力有明确范围和恢复；有效warn不强制清空建议 |
| 失败与重复 | 材料冲突先拒绝不部分冒写；失败区分已完成与未执行；重入/重复回复不重复副作用；设计修订与纯表达变化按各自合同同步 |
| 保持与成本 | 1.9.9发布能力和旧2.x仍有效业务覆盖保持；语义、首稿质量与运行/人工等待/异常耗时分别核，条件不同时不宣称提效 |

既有两个Case覆盖业务主链；其不能自然触发的直接入口、多CU、报告篡改/视觉缺口等按风险定向取证，不强迫给业务Case塞测试答案。每个必要终点均须有实际结果；BLOCKER未解决、人工代实现或只有最终PASS时不能签完成。

## 4. 退出与正式交付

检查新旧全部可达入口、manifest、hooks、overlay、命令、状态、安装器、测试和README：开发树只运行一套有效合同，历史记录仍可查。临时1.9.9源码状态和混合装配明确已退出；旧2.x候选片段留维护材料，不作为消费者备用路径。若Framework接替原Extension职责，核其实际消费而非只看声明。

最终交回本轮与累计G/X、净增、峰值及总量，核完成目标而非仅峰值；列真实保持能力、已关闭与未关闭问题、金样审定身份、每层证据和外部限制。用户评分/审定按TEST，未取得的证据标未验证。

2.0.0是临时版，不由本方案自动发布。用户决定正式版本和发布后，按根AGENTS §7更新manifest、README、对应release、demo安装同源及EVOLUTION；1.x发布说明不充作新2.x发布说明。1.9.9→新2.x升级支持范围必须与S2决定一致，不能因全新安装通过便宣称升级支持。
