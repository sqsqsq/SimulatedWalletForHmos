### 正常链与对象合同

1. 先读当前materials.json和已登记冻结快照。保留现有Story、Review、设计附件、写作设计、决定、蓝图、知识、update-before及task绑定。材料清单缺失/坏形状和pending按现有缺口/导入恢复处理，不静默缩成空集。
2. 除冻结采用文件外，组装全部origins.path原件及origins.readable_paths、每个登记图片对象（含unused理由者）、每版会议raw/corrections/evidence，以及materials.json自身。原件按第3条分配只绑定/来源核验或必读角色。范围依据当前材料清单及已有meetingVersions，不扫描全工程找“可能相关”文件。
3. 原始二进制与阅读稿分工保持B：普通原件核存在/来源摘要和与阅读稿的关系，不强迫模型全文阅读DOCX/PDF等二进制。只取图的原件核在场，抽出的图片承担必审；真实文本原件有阅读角色时列入。对象可给绑定行增加`required_read`（缺省true）和`kind: image|text|metadata`，仅用于现有消费者；纯存在/来源核验的原件用false，仍纳入字节绑定。禁止把“不必直接读二进制”变成免核原件身份或免读图片。
4. 冻结files中已采用的逻辑路径以冻结字节为设计权威；用已有readFrozenInputs校验，不复制另一套快照算法。当前同逻辑路径只有字节同源才作为alias；不同版本独立列出“当前对照，仅核取舍，不替代采用版”。材料清单登记的原件关系沿其现有hash格式核，不能用当前新字节冒充旧原件；找不到旧版保留缺口及恢复位置。
5. 图片按imagesIn的对象及明确别名关系合并阅读义务，逐路径绑定实际字节；不因readablePaths过滤空结果而变成“无图”。同一图片已知别名可统一核源，内容不同不互相顶替。reviewObject返回现有rows/problems/design，并增加内存alias供任务和检查共用；不持久化第二个图片登记。覆盖义务按canonical去重，同一canonical的required_read取各成员OR，原件只绑定行不能消掉图片/文本必读义务；覆盖、发现定位和图片延期共用同一alias归一，避免别名被重复判漏审。
6. 任务的材料表从同一对象输出阅读义务和来源检查说明；originRows/imageRows/会议逐话题内容继续解释caption、unused、冲突与纠偏，但不另定义成员集合。完整核源仍在首读之后；context.md的旧报告/诊断继续单独由prepared派生，不重新塞进参与材料键的task。
7. materialKey继续按rows实际路径及字节散列，无需新算法。覆盖声明用required_read非false的行（排除task本身）；来源存在/摘要检查由对象problems先拦。发现定位先按同一alias归一，接受本次完整材料集合的有效来源；另按现有G3允许引用报告examined_inputs已声明的实际额外取证，不能用它顶替必审。额外取证真实性由报告、原始调用及语义核验承担，不新增“只能工程内现存文件”的来源白名单或路径存在性门。额外依据如需改变业务决定或成为新的采用设计输入，再回既有材料/设计修订及prepare，不把其自动升为已授权事实。
8. coverageBasis按kind识别图片，退出label后缀判断；全部必审图片使用同一个既有Story视觉裁定。裁定的需求依据仍取已授权、冻结的需求与人签，未采用提案不变成设计权威。只有既定semantic_layout/best_effort且允许延期的真实图片可unreviewed且最高WARN；文本/纠偏缺审、图缺失和hard/defer边界仍按原合同处理。

### 验证与退场

在test_verifier_report_protocol及现有材料/会议回归中用合法输入验证：采用稿+未采用冲突阅读稿+未用图片+会议纠偏一并送达；漏任一适用核源项不能PASS/WARN；引用这些实际来源的发现可被消费。复用现有图缺件/无视觉、原件换版、别名与subject_stale用例，核同字节别名合法、不同版本不替代、核源文件变化令旧报告失效。二进制只做来源核验的正常情况不制造必读义务。

## 2. F2：仅核本文编号与本文引用

当前parseDocument保留heading.raw/name/level/at，无number字段；直接从raw取号，不改所有解析消费者。恢复小型`hooks/shared/chapters.mjs`，只承担两项纯函数：

- `chapterNumberProblems(text)`：用实际Markdown层级确定父节，核带号父子节的数字前缀与层级关系、重复编号造成的歧义；不要求所有标题编号、序号连续或从1开始。不替无号Scope/宿主章造号，围栏内容沿parseDocument排除。
- `chapterRefProblems(text, column)`：只核明确“号＋章名”的本文引用，数字和经既有normalizeHeading规范化的名称必须指向同一实际H2，不用双向startsWith；纯章名或Markdown链接沿现有语义处理，不扩大为跨文件解析器。

spec/post_check取得实际spec.md时独立加编号检查；plan/post_check对plan.md同样检查，并核`承载设计章`这一已在B真实调用的本文映射列。当前N映射表并不保证含此列：列不存在就没有该项引用义务，不另造表；`spec章节`等指向另一文档的列不拿plan本文比较。缺Markdown沿既有skipped记录，不造新的必产物要求。两份author.md补充编号及本文引用随正文同步的结果要求。

不恢复B的profile模板加载、固定主章号、宿主第9章、锚点末尾或模板格式套件；hostChapterProblems继续承担现有知识章责任。N的Spec Skill和hmos模板对Scope编号有不同表达，本项只核本文自洽，不选择一套固定编号，不改vendored Framework，也不宣称解决了其全部模板问题。

恢复test_chapter_numbers中内部关系正反例，与test_cu_knowledge_chain真实spec/plan hook调用一起验；合法自由编号、无号父章、无映射列及围栏标题不误拒。test_host_extension_anchor的知识章存在/适用小节等有效回归由现有CU链承接，旧位置/固定号断言列明退出，不恢复为安装器测试。预计G120/X0；测试不计机制预算。
