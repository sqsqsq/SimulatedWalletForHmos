## 5. 只在对话里出现过的事实与坑

- **测试接 Framework 的方式**：`test/tests/ext_workspace.link_framework(root)` 用 junction 把 demo 的 `framework/` 接进临时工程；`git_init_excluding_framework` 必须把 `/framework/` 写进 `.git/info/exclude`，否则 git 会顺着 junction 收录约 3700 个文件。
- **junction 的删除**：Python 的 `shutil.rmtree` 不会跟进 junction，但 Git Bash 的 `rm -rf` 会。`output/scratch/s1/mkws.sh <名>` 会建一份 demo 的隔离副本，并把 node_modules 用 junction 接过来；它在删除前先 `rmdir` 掉 junction。如果当前 shell 的 cwd 在副本里，删除会报 busy。
- **蓝图夹具**：`test/fixtures/blueprint/wallet-balance-refresh` 需要 demo 的 `doc/module-catalog.yaml`。换用自定义 features_dir 时，夹具 CU 的 `source_ref` 也要改成对应路径。
- **测试状态只能用原生入口制造**：prepare-scope、`ensureFeatureExecutionScopeFrozen`、`materializeBlueprintSkillInputs`，写法见 `test_knowledge_task.py` 的 `PREPARE`。另外两个原生行为：
  - 冻结之后再物化本地文件，原生会判绑定过期；
  - 只加 YAML 注释不算改动契约，要做语义改动原生才判过期。
- **原生 hook 的 ctx**：只带 `projectRoot`、`phase`、`feature`，不带已解析的输入。
- **原生无 Feature review request 的坑**（探针在 `output/scratch/s2r/`）：
  - 事实记录 `exploration_mode` 只收 subagent 或 sequential，`searches_performed_estimate` 至少 3；
  - 问题编号必须是 `CR-数字`，否则计数对不上；
  - 有条件通过而 MAJOR 未标关闭，原生直接判阻断；
  - 问题只指向 `.md` 时 `issue_to_file` 判 SKIP BLOCKER，原生 verdict 因此是 FAIL；
  - 需求目录里同时有 `blueprint/` 与 `ux-reference/`、`spec/`、`context/` 时，原生 `enumerateFeatures` 按歧义拒绝；所以蓝图工作区用异名 `bp-<需求>`，bind-design 拒绝同名。
- **A02 失效形态**：夹具已改成 2.0 形态，并在检查时按被查工程的 Framework 当场物化。所以对 demo（仍是 1.9.8）跑失效形态时 A02 会失败，这不算回归。开发期要对装了开发版的隔离 template 跑：`python test/scripts/check_failure_modes.py --project-root <template>`，命令前加 `PYTHONIOENCODING=utf-8`，否则 GBK 控制台会报编码错误。
- **命令环境的坑**：
  - Bash 的 heredoc 会把 `\\n` 等转义吞掉。改文件的脚本先用 Write 写到 `output/scratch/`，再执行。
  - Git Bash 的 `/tmp` 和 Windows 上的 Python 不是同一个目录，中间文件放在仓内的 `output/scratch/`。
  - 解包发布件要用 `git -c core.autocrlf=false archive`，或直接按 blob 取内容，否则换行会被改掉，摘要对不上。
- **预算核算**：用 `output/scratch/s1/budget_delta2.py <基点> <终点|WT>`：逐文件取台账 `code_lines` 同一剥法的有效行再做差分，新增−退出恒等于规模差。旧的 `budget_delta.py` 按比例折算，会差几行，别再用。`output/scratch` 不入库，需要时照这个思路重写。
- **测试夹具的需求文件也是蓝图来源**：改 `doc/requirements/wallet-balance-refresh.md` 会先让蓝图失效；要测需求来源变化，另拷一份只给请求用的文件（见 `prepare(..., requirement=...)`）。
- **设计夹具**：`test/scripts/design_fixture.py` 由测试和失效形态运行器共用，负责接 Framework、准入蓝图与投影，并建立真实的交给设计状态。`test/tests/designed_fixture.designed_copy` 按进程缓存做好的工程；`design_kit.registered_basis` 造登记依据。
- **失效形态的 template**：`WS=$(bash output/scratch/s1/mkws.sh <名>)` 建副本，`python output/scratch/s1/try_install.py "$WS"` 装开发版，再跑 `check_failure_modes.py --project-root "$WS"`。作者页 `author.md` 超 60 行会被 A03 拦下；脚本提示复述 phase 文档里的规则会被 M19 拦下，提示改为指路。
- **证据位置**：能力核对的证据在 `output/story/2.0.0/fw31-capability/`，基线接入的证据在 `output/story/2.0.0/fw31-baseline/`，设计者复核的证据在 `output/story/2.0.0/review-step1/` 等目录，都不入库。
