## 4. CLI：car-key-sharing（ISSUE-206，终点 phase:plan）——没有进入 Story

### 4.1 现象

1. 首轮读完上下文，反问「这轮要我做什么」。宿主一句话重申需求意图（写需求说明，定稿后做实现方案，到方案为止）。
2. 第二轮读 AGENTS 后：
   - 按 `spec 动笔前先处理 skill:story-knowledge` 领知识任务；
   - 用原生 `goal-mode-entry --prepare-scope` 生成并冻结 spec→plan 执行范围；
   - 自己跑了一次诊断门禁，留下没有归属的 spec 报告；被这些报告挡住后，去找 `--clear-state` 清理。
3. 最后停在原生 spec 的术语映射确认（用英文提问）。
4. 全程没有调用 `story_flow.py`，没有材料关卡、蓝图或 Story。

用户决定收工留证据，终态 `gate_failed`。工作区保留在 `%TEMP%/sw-story/story-suite-20261002-101032/car-key-sharing`。

### 4.2 根因

2.0 里，模型拿不到「需求材料起手 → /story」的路由：

- 1.9.8 的工程 AGENTS 有扩展段写入的一行（`demo/AGENTS.md:107`）：「需求流程入口：`/story <init|…>`——从材料导入到归档的完整链条由它承载」。
- 2.0 按步骤 1 退出了自有段生成，入口改由原生物化。原生 AGENTS 只在「实例扩展 Skill」表里列出 `story` 的路径。§4.0 的需求路由把正式需求指向 `component-design`。
- opencode 的 Skill 清单里，story 跳板的描述是原生写死的「实例扩展 Skill：story」（`instance-skill-bridge.ts:338`、`renderClaudeSlashMarkdown`），扩展 SKILL.md 自己的 description 没有带过去。相比之下，原生 `spec` 的描述是「spec 撰写」，正好对上「需求说明」。
- auto-topup 进了 Story，可能是 prompt 里「从这张单开始」对上了 init，但这不可靠。

### 4.3 修法方向（请定）

1. **上游**：原生桥接用源 SKILL.md 的 description 生成跳板描述，或在 manifest `provides.skills[]` 支持写一句用途、渲染进 AGENTS 的实例 Skill 表。写进 Framework 问题反馈，由用户转交。
2. **本仓**：在模型实际会走到的原生入口上接住它。`spec 动笔前` 绑定的 `story-knowledge` Skill 里加一条：需求来自材料、需求目录里还没有 Story 流程契约时，先走 `/story`，定稿交给设计后再进施工阶段。只用现有绑定，不新增入口机制。
3. 修好后单独补跑 car-key。auto-topup 这次的结果可以复用。
