## 2. F1：只读查询认被检查的那两份字节

改动在 `independent-review.mjs`。

**显式检查 `reviewResult`**：
1. 先从准备记录里去掉上次的原回复摘要；
2. 把原回复交入工作报告，跑原生检查；
3. 检查成功后，核两件事：summary → script-report 摘要链成立；工作报告与原生 `input_bindings.review_report` 一致；
4. 两件都成立，才把这次交入的原回复 SHA-256 写进既有的 `prepared.json`（字段 `original_sha256`）。

**只读查询 `verifiedReviewResult`** 依次核：
- 原回复的当前字节等于 `original_sha256`；
- summary → script-report 摘要链成立；
- summary 与 script-report 记的 `review_report` 绑定相同，并且用原生 `readBoundInput` 按这份绑定重读当前工作报告，没有判为陈旧。

不要求原回复与工作报告字节相等；不重跑检查；不写盘。三项任一不成立，都返回 `report_unchecked`，指回显式 check。执行检查与只读查询仍共用 `classify`。

**一处实现选择，请确认**：原生绑定里的依赖路径是检查时的绝对路径。工程整体搬到别的根目录后，`readBoundInput` 会把它判为陈旧。`test_story_update` 的已登记夹具就是复制到新目录用的，第一版因此有 5 条交付门失败。现在按 summary 自己记的 `project_root` 作为原生 `readBoundInput` 的 `legacyRoot` 重定位，用的是原生已有的「记录写于另一个工程根」参数。不用原生 `inferLegacyProjectRoot` 的原因：它只认 `doc/features/` 下的路径，而审查报告在 `doc/reports/`。

**新增用例 `TheReadOnlyResultIsBoundToTheCheckedBytes`**（每条都断言只读查询前后整棵 `doc/` 字节不变）：

| 用例 | 内容 | 旧实现上 |
|---|---|---|
| 原生修正统计数 | 合法 MINOR、来源指向真实 `snapshot.json`、统计误写 9；显式 check 返回 warn，工作报告被原生改写、与原回复不同；只读查询返回同一个 warn | 失败（`report_unchecked`） |
| 检查后换回复 | 检查通过后，把原回复和工作报告一起换成「不通过」，不重验；只读查询返回 `report_unchecked` | 失败（仍返回 pass） |
| 检查后改工作报告 | 只读查询返回 `report_unchecked`；显式 check 重做后恢复 pass | 通过（守住恢复路径） |
