# 02 主链组合核验与批次交回

输入：M固定产品对象、01交回、第一批标准/Case/金样来源、参考12/14。目标是集中核首条主链的消费者与保持边界，避免只安装成功就进入后续。

动作：核系统材料或本地材料、已定/未决人答、三类知识、正文独立可读要求、独审首读/核源及原件、上传读回恢复、合法CU到Spec/Plan和首链usage是否在同一组合中成立。用既有相关模块组合验证；不在此重复整版full，也不先把第三批所有复杂恢复分支跑完。发现本步职责内实现错误集中修正、必要验证、交回并提交普通后续提交，预算继续累计M之后的投入。

若用户已启动本阶段真实CLI里程碑，按现有DSH协议取一次真实主链证据；没有授权则只交离线/设计核对及未覆盖，不自行调用模型，也不拿金样或预写稿签真实效果。首稿语义和独审效果未验时明确标出，不强制增加一个专门CLI批次。

验收：M和后续修正对象固定；首链结构/公共流程的适用检查有结果；真实证据与未覆盖分开；第三批剩余能力和阻塞条件可执行；当前README/维护指南准确反映开发状态和demo发布版。仅验证工作G0/X0，实际修正按所属责任进入原预算，不额外给额度。

本步交回并提交，末尾汇总批次二的提交、证据、问题和第三批条件，集中送审等待评审。评审根据后续契约依赖决定可进入第三批哪些实施；不把未获CLI授权本身当成所有后续实现停工理由，也不把已证契约缺陷留给第三批猜。
