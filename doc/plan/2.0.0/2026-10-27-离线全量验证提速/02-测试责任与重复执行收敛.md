# 02 局部规则与真实集成各归其位

输入：01的显式准备及四层合同。目的不是降低测试数量，而是同一个有效职责只由合适层次证明。全部有效断言保留或给出明确退出依据；先对应生产者义务再移走隐式准备。

## 1. 各族具体落点

| 现有族 | L1：真实函数/明确输入 | L2：必须保留的具名责任 |
|---|---|---|
| test_story_build / writing_plan / figure_view | chapterStructureProblems、parseChapter、chapterProblems中纯规则、renumberStory/normalizeHeading、readWritingPlan；同输入一次导入、多独立预期 | ChaptersLandOneAtATime：真实skeleton→写章→check/统稿，章外字节、失败不写、pending、无旧台账；投影冲突与图视图切换/失败恢复仍真执行 |
| verifier_report_protocol / review_closure | reportProblems、reviewResult等规则使用明确报告和必审文件；不自动补缺，不把构造PASS算语义 | 原样回复接收、绑定、新编号、A→B→A、FAIL后新回复、人签、登记交付；每根真实prepare，避免复制prepared身份 |
| story_update / usage / stats | cmd_update_*的文件分类/比较/反馈、usage纯时间字段函数；每例私有输入，实际异常断言 | update正常轮及恢复、同名原件换版、远端成功本地失败、读取视图与usage入口副作用；真实锁、原子写、Git历史/clone继续 |
| knowledge_task / cu_knowledge_chain等 | 明确契约实体、义务/角色与任务结构的真实函数观察；可用固定合法对象作消费者输入，不为每个措辞变体冻结新CU | 原生候选→冻结→物化→作者/门禁，完整知识生产消费链；真实身份变更/兄弟CU/本地契约边界。模型适用判断质量归L4 |
| adapt / publish | YAML等价来源输入均经已有status正常路径观察相同来源判定；entries现有局部导出核所有权计划 | 每类来源至少保真实apply→物化→字节；脏写前拒绝、adapter/knowledge/usage保护、旧入口撤下、交替来源、真实Shell修复保持 |
| material_rounds / meeting / design_handover / image / story_inputs | cmd_round、cmd_reopen、cmd_import、cmd_complete的局部业务矩阵，真实文件副作用；局部读取不走全设计链 | 原件→入料→人答→冻结→消费者；真实退出码/JSON/cwd、缺输入不补造、失败保旧、F1完整核源与F2引用保护保持 |
| blueprint_case_closure / verifier_chain_in_workspace | 明确状态的判定函数边界 | 第一条真实组合及装配专项；原生生产者能力不能只由手写状态证明 |
| 其余现有检查 | 保原确定性责任 | 预算、宿主、runtime、runner、失败/截断/历史保护等不因非热点而删除 |

不是所有带ctx的导出都属于L1：如果真实函数依赖原生readFeature/冻结身份，归L2并显式准备，不伪造ctx绕过生产。没有现成动作导出的adapt-scan保现有命令，不修改产品导出或抽代码造影子checker。

Python局部函数测试明确隔离TAMPER_NOTES等已有进程全局；原CLI main承担的reading_view、usage.after_command、输出/退出与进程隔离在入口集成中保留。直接函数的FlowError/返回值不能用新模拟CLI壳转换成假成功。

## 2. 相同产物不再重复生产

- DraftsCarryTheDeterministicWork：同一真实skeleton供不变输入的各项只读断言；恢复现稿/草稿、补pending、已有内容不覆盖各用私有样本并实际执行动作。
- 十章生成与无旧台账合在同一生产链逐步断言；统稿消费者拿该链明确生产的满篇前态私有副本，再真实改第五章。不是依赖另一个测试先运行。
- ReviewTaskReachesTheVerifier各Part和大任务：相同输入一次真实prepare，多项独立观察；变化输入另准备。源码/材料缺件、换版和接收身份不要混成纯报告格式测试。
- prepare_designed不再作为所有Story子类共同setUp；只在真正验证其生产链及无法以合法输入隔离的集成保留。被移走的上游义务由上表具名链承担。
- installed_package、legacy/business源前态只在真正消费它的fixture显式取得，配置/根绑定不成立就用更早前态，不扩根重定位框架。
- YAML五种引号/注释全部保留，通过合法已安装目标的status观察同一WITH_ADAPTERS消费者；一份引号加注释完整apply核真实adapter字节，业务来源/所有权其它链保持。status报错不能当解析成功。接受这一职责分工，不再要求五次完整apply。

## 3. failure-modes不是第二套全量业务模拟

保台账当前全部有效模式及正反判别，区分安装件静态扫描、合成内部判断、真实目标、委派/未建。只要仍是不同输入/预期，不按同名checker合并结论。

已证S01/S02/S14及R04的internal/real完全重复继续只做一次，保持实际执行来源说明。R04仍作为真实状态集成：双查不写、审查接收/登记、重复登记身份不变、reopen后拒绝交付。无需在它前后重复跑报告格式全矩阵。

本轮不新建full向failure发PASS的协议；已有两处相似链先只去各自无关准备。局部形态用例明确给最小合法输入并执行被测真实检查；若只观察规则，不再从初始取材调用prepare_designed。当前九份不同准备不能凭文件夹名强合并；保持源/知识/图身份真正不同的输入。

保真正安装目标扫描、M15目标路径与无Feature未执行边界。checker's预期由原缺陷/合同独立给出，不由其实际返回生成。

## 4. 退场与交回

完整退出清单及保留者在[参考01](参考/01-工作量收敛与达标预算.md)。每个被移走的隐式生产动作列去向；不能只写“已改直接函数”。
正常矩阵与集成不增加并行写共享根；同根改正文后读取原生缓存需新进程或真实合法入口，不改run ID、加clearCache、手写冻结状态。纯局部规则则不要引入该缓存依赖。

未来实施的必要验证和覆盖迁移一起进行，不另组织一次逐族性能巡回。原事件/语义/视觉未验证继续明确；本步不能关闭L4或性能目标。
