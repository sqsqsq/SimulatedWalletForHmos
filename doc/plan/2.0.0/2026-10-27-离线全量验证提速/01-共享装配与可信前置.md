# 01 基底、准备和装配职责

输入：总方案四层合同、499fc4e2交回、当前主分支及提效worktree差分。结果：测试收集不生产工程，L1最小输入，L2/L3真实生产边界明确。当前仅设计，以下为获准实施后的动作。

## 1. 退出导入时生产

ext_workspace的DEV_EXT=_install_dev_source，以及两个adapt模块顶层PKG_ROOT=installed_package退出。模块导入只定义函数/路径，不安装、复制整树、物化或建立业务状态。不能用一个会自动安装的Path代理或懒全局对象隐藏副作用。

读源码/合同的测试可读DEV_SOURCE；需要运行态相对路径的测试在明确fixture里取得安装路径，现有BUILD/SCAN/ENTRIES等从该fixture取得，不全局强改为开发路径。只有解析YAML需要的输入只接已有yaml依赖，不能顺手overlay整个Framework。调用原生身份/派生的测试归L2，显式接真实Framework。

handback已由verify生成一份真实template；安装消费者借同一对象的只读安装基底，原安装器写前核/物化/同源由L3承担。需改包、改版本、改宿主的测试复制自己的安装面和必要配置，再执行真实被测动作；不得写共享template。独立affected/full没有boundary时，由确需安装的fixture显式生产一次，不能在所有worker收集时生产。优先复用现有boundary及shared_tree的当轮协调能力，不新增第二份安装服务或缓存协议。

安装键或身份必须包含实际扩展文件、安装/准备函数、Framework树/补丁、完整配置及宿主。不同features_dir/project身份不混合；目录可搬与否按实际绑定核，不以路径字符串替换伪造合法身份。

## 2. 明确fixture性质

- L1：现有fixture中的最小输入或用例明确给定文本/字节，无上游生产成功声明。故意缺件的用例不得调用补齐helper；正常报告矩阵也先明确哪些文件是题设。
- L2：同一生产链的真实前态仅在该链负责的fixture生产；消费者测后置变化时可用未绑定样本。首次生产、冻结、身份变更及恢复用例仍真实执行。
- prepared报告、facts和CU冻结绑定实际根：不跨根共享最终态。候选C只共享默认且全配置一致的未冻结安装前态；候选D默认共享到审查/登记之前，各根必要prepare/登记保留，直到有明确证据证明后置用例完全不消费根绑定，才可进一步复用。
- 不新建fixture生成器、自动依赖图或语义样本工厂；现有design_fixture收缩到L2生产者链所需方法，普通规则测试不再统一调用prepare_designed。

## 3. 装配专项保持与降重复

第一份公共装配与第二次独立空目录重建保持。当前改装配，最终必须handback --assembly；以后第二次按TEST现有Framework/补丁/装配变更条件触发，不新设更多门禁。

framework_blob/framework_plus_patch的逐文件Git调用改为既有Git cat-file --batch形式一次读取一组固定blob，解析长度按字节；保持独立git apply和全文件字节比较。真实缺失与读取失败分别处理，不用git archive转换换行，不由被测装配函数制造期望。此项只退出36个重复Git启动，不算退出两次装配。

第二份boundary、原生UPDATE stdout/stderr与原始run-log在清理前保存到本轮独立证据目录；verify拥有第一份，测试拥有第二份。保demo不变、同源、宿主物化及失败已做/未做事实。不要增大故障矩阵来证明所有假想清理失败。

## 4. 过重机制的收缩

1. 撤销run_multi_case中无条件默认TS_NODE_TRANSPILE_ONLY=true，恢复装配原有执行默认；保留原调用方显式环境值并记录。当前未成立的历史类型检查等价不能作自动豁免。固定上游发布的静态保证按其证据使用，不新增另一套全Framework类型检查平台。
2. conftest与verify对所有Node子进程全局注入TS preload的行为退出；L1及L3不注入。现有轻转译代码暂仅允许在明确的L2原生驱动进程和failure确需原生的准备中使用，不覆盖其它进程。保真实ts-node CLI消费者及原生缓存语义，不扩通用loader兼容。
3. 在L1/L2迁移结束后，若现有轻转译机制没有必要消费者，同步删除ts_transpile_cache、注入入口及仅测该实现的测试；若少量原生消费者仍需要，交回列具体位置与实际成本依据，保留范围原地限定，不以“可能会用”保全局机制。未取得证据不谎称已退。
4. shared_state只承担相同输入真实前态的必要当轮共享；L1退出依赖，新的常用输入用明确fixture表达。清理不用本轮任务去遍历或删除全局历史缓存；删除无消费者的键/builder/专用测试，保有明确生产者与消费者的功能。不能为键命中率删准备代码/材料身份。
5. 计时只保总时段、必要阶段、安装/源码身份和失败证据；不新增长期性能数据库、动态调度器、worker调参器或跨通道PASS协议。

完成条件：静态查不到导入即安装；必要安装消费者与各自私有写面可指认；上述每个机制有保留消费者或完整退出。未来只做与改动直接相关的验证，不为证明准备成本启动24 worker全量收集。
