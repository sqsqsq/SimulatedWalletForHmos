# Framework 3.1：无 Feature review request 对 Markdown 问题引用产生阻断 SKIP

2026-09-30，Story Extension 维护设计者。供 Framework 开发人员核对；本仓没有修改 vendored Framework。

## 发布基线与诉求

AgentMaison 3.1.0，source_commit=074a4c3c4a0591c8ed2162e2a0d048a1fdec081f。本次使用已交付的无 Feature request-harness 审查 Story/Review Markdown，目标是让正常的文档问题和非阻断建议按真实严重性判定。

## 复现与结果

使用合法 schema_version=1.0、phase=review、baseline.head=WORKTREE、targets.files 指实际 Story/Review/任务及来源、inputs.review_report 指项目内 features_dir 外报告目录、allowed_test_writes=[] 的请求。原生 prepare 成功，request 绑定的 P1 facts 与报告齐备。报告问题表有一条 MINOR，涉及文件是实际存在的 AR/story.md，结论为“通过”。

沿 `request-phase.ts:runExplicitRequest` 正式检查，得到：

```json
{"verdict":"FAIL","check":{"id":"issue_to_file","severity":"BLOCKER","status":"SKIP","details":"问题清单中无可解析的文件路径。"}}
```

设计者独立复现证据：`output/story/2.0.0/review-step2-rework-0930/probe.json`。复现脚本 `output/scratch/review-s2-rework-0930/probe.py` 复用合法正常夹具；原始 request、facts、工作报告及 script-report/summary 保存在该证据记录的 workspace 中。本探针只验证确定性协议，不声称实际模型已经审查。

## 根因定位

`harness/scripts/check-review.ts:checkIssueToFile` 在约 652 行只收 ets/ts/tsx/js/mjs/json/json5/py/java/kt/swift 后缀。合法 .md 被全部过滤，继而返回 SKIP/BLOCKER。`generateRequestScriptReport` 对未明确 not_applicable 的阻断 SKIP 正确归为 FAIL。request 输入入口允许 Markdown 文件，错误发生在后续文件引用解析范围与合法 request 目标不一致，而非请求身份、报告目录或 Story 缺 Spec。

Extension 当前用检查 ID 豁免该 SKIP 的做法已被评审拒绝，不能把原生 FAIL 转为业务通过。

## 最小修正建议与验收

request 分支按真实请求目标和原生项目路径规则解析“涉及文件”，允许请求实际支持的文件类型；真实 Markdown 引用应核到目标或合法来源，不通过新增无关代码引用绕过。缺失或非法路径必须失败。保留 Feature 原有行为及无问题报告的不适用处理，不要求新增审查框架或 artifact API。

验证：存在 Markdown 的 MINOR 建议、BLOCKER 问题、不存在 Markdown 引用、行号定位、没有问题表的真实无问题报告；业务裁决与格式结果分别保持。原生 negative/conditional verdict 规则继续生效。

## 影响边界

这是只引用文档路径的问题表的已知局部阻塞；其他适配继续，无问题报告链可继续验证。另一项 ux-reference 与同名 blueprint 共目录冲突由 Story 方案改为显式分离需求/蓝图身份解决，本报告不要求 Framework 放宽目录判据。
