# S30 作者接续与原生收口取证

03 批，Neon 强化档。依据[联合复评 R1—R3](../评审意见/2026-11-21-035800-S08与S29及S10联合复评.md)。S31 同期，S10 读同一修后对象。

1. 在 `phases/design.md` 第六节第 5 步原处收敛三种走向：未冻结由设计 owner 修订、质询、准入、按受影响 CU 普通接续；已冻结、来源仍有效且原 Plan 义务未完，在改变权威前取得或沿用原 attended 请求，再按 S08 已核路线同一授权后继至原终点。只在成功修订后同步受影响 Story；是否派审依既有业务影响规则。已失效无转交、宿主不可用或原生空链，末动作明确为保留原件、报告缺口并结束此次接续。未获扩权的文档更新只报告施工影响。
2. 从 `/story update` 首次可能请 owner 改共同设计的动作向前核：在那一动作前，提示“若受影响 CU 已冻结且原请求仍欠 Plan，先按 design 第六节第 5 步保住原请求，再请 owner 改共同设计”；失败向该段已有出口收口。后面表格只留实际结果和责任，合并重复指路。读到已经换版的事实时，不补造事前转交。完整命令及身份只在 design 一处维护，复用原生事前、后继、恢复合同。由公开装配物化的 Story 跳板沿实际读页，分别交三类输入与一个只准改文档输入，交整段上下文、作者第一动作/最后动作和下游责任；离线语义推演与真实模型运行分记。
3. 测试端保持逐 CU 原生权威、阶段事件、同 run 的收口和 freshness。沿 900c `check-receipt.ts` 及 `phase-closure-finalizer.ts` 核当前机器提交，移除把可读 Markdown 投影作为正式 closure 开关的旧判断。原生明确报告失败或绑定错误仍应拒绝；普通无 run、适用旧形式各守原合同。用同一成功现场保留/清空/移走投影，均判同一已执行 Plan；错 run、正式收口失败或正式物证过期仍不可到达。用生产 end_target 看最终 reached/missing，不只核其中一层。
4. 中断取证须有中断前 journal 的一次 revision、无 run_end，已经终止原进程，再由新进程以同一后继恢复到唯一终局，且没有重复作者或 Feature completion。正常退出而未截到窗口时，按普通完成或未取到中断证据报告。可复用原生现场与已有可重复的中断方法，避免仅增加轮询次数；一项测试不能靠条件性略过关键断言获得中断通过结论。

批准机制 G6/X6，预计完成总量与本轮起点 19167 相当；责任为两处现有提示的替换，测试域 G0/X0。按实际计量，完整功能优先。
