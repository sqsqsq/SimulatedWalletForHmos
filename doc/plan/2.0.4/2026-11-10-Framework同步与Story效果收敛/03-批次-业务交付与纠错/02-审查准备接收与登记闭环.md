## 2. 精确接口与算法

### 2.1 同次准备只在披露改变时再次定稿

保现调用顺序：cmdReview校准备记录、准备图源、finalize一次，再进入prepareReview；prepareReview仍先receive前次回复、stageObject、判reusable。不要把原件接收提到另一个新事务或改变报告目录规则。

在story-build引入现有reviewStatusBlock导出（不是新导出），restage回调按内容比较：
```
const prior = reviewStatusBlock(ctx).join('\n');
setReader(ctx, reader);
const changed = prior !== reviewStatusBlock(ctx).join('\n');
if (changed) finalize();
return changed;
```
prepareReview的回调约定由void变boolean；只在`!reusable && restage()`时再次stageObject。可复用时仍不调用restage，保原有效对象；不是数组引用比较。其他接收、任务生成、key、prior报告、目录冲突、原子替换和结果逻辑均不动。

### 2.2 登记检查共用同一ctx，取反语义保持

`story/check.mjs`中函数改为：
```
export async function cmdCheck(ctx, { registering = Boolean(ctx.args.registering) } = {})
```
只把内部调用改成`storyCheck(ctx, {registration: !registering})`。**取反必须保留**：登记前要替旧登记，所以不核旧登记之后变化；普通check仍核当前性。ctx.args.deliver及其他CLI参数仍按原逻辑，公开命令不增加参数。

在story-build提取私有`cmdReviewCheck(ctx)`封装现action=check分支（reviewResult→原JSON输出→pass/warn/unreviewed为0，其他为1）；原cmdReview check分支和cmdRegistrationCheck都调用它，不导出新API。

登记组合顺序改为同一ctx：`cmdCheck(ctx,{registering:true})`→`cmdReviewCheck(ctx)`→`cmdBasis(ctx)`；保captured、jsonIn、失败后后项not_run、basis仅全通过时返回、退出0/1/2语义。不得通过修改ctx.args临时赋action，也不跨命令保存ctx或新建cache。

### 2.3 作者动作提示与实际消息

cmdReview现末尾已经要求“保存→prepare接收→check”，不另加同义协议；仅把“之后重跑”准确为“修改被审材料之前先重跑…接收，再check按结果处置”。phases/design的Story段保持同一顺序并明确首次/复核均原样使用当前dispatch_text，不套用A02蓝图消息或父自编修改摘要。

SKILL、design、story-write与flow/routing的正常入口去掉prepare前无条件再跑全篇check；prepare自己的结构核、章写入核、登记组合、交付前重核以及独立诊断check均保留。不得把可删重复扩成删核查能力。

具体替换位置固定：SKILL的S5流程删独立“回看→check”中间动作，成为“回看→独立审查（定稿内全篇检查、派审、核结果）”；design§五第1项从核读者并prepare开始，不再先check。story-write§六结尾的全篇check交给下一节prepare内部完成，保跨章判据说明；§七删“与check之后”。routing.py成文完成提示中同义前置一起退出，交付提示的check --deliver及诊断错误提示保持。本轮检索已核这些实际命中，不全仓删除check字样。

## 3. 预期行为表

| 输入 | 预期 |
|---|---|
| reader=task，当前无披露，不能复用 | 首次finalize后生成当前任务/派发，不为相同披露再做一次finalize |
| 从未审变有读者/未审原因实际改变 | 新披露进入Story/Review后重新取最终key，旧对象不冒用 |
| 同key已收pass/warn | 原结论复用，不改变披露或重派 |
| fail、原件被改、回复未收到或key失配 | 仍按现拒绝/补正/当前性出口，不以性能优化放行 |
| registration-check中检查失败 | 后续not_run；不返回basis，不产生登记；异常与普通不通过仍分1/2 |
| 新命令前来源/蓝图/人答变化 | 新ctx重新取源，旧报告/登记按现规则失效，不允许缓存跨命令 |
