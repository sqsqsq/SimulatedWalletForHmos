# 步骤 2 交回：原生报告接缝与失效职责退出

> 读者：维护设计者。依据：[步骤2](../02-原生接缝与职责退出.md)。基线 `3e880f17` 加步骤 1 的在途改动。改动未提交，没有运行模型或 CLI，没有修改 vendored Framework。

## 1. 报告路径回原生（R05）

**新增** `framework-access.mjs::phaseReportsDir(projectRoot, feature, phase)`：

- 经 `loadNative` 调原生 `config.ts::featurePhaseReportsDir`，返回 `{dir}` 或 `{error}`。
- 唯一消费者是 `verifier-report.mjs::reportLocation`。
- 没有登记新的 CLI action。

**`reportLocation` 改动**：不再拼 `featureDir/phase/reports`。只读原生目录下的 `summary.json`，再按 `summary.verifier_report` 找报告；不自己展开 pattern，也不复制 CU 路径算法。各情况的处理：

| 情况 | 处理 |
|---|---|
| 目录解析失败 | 报「按原生配置解析失败」，不回落默认目录 |
| summary 在却读不出、不是 JSON 对象 | 报输入故障，不当作未派审 |
| summary 不在 | 返回空，派审由原生调度 |
| 没有 `verifier_report` | 返回空，即宿主没有审查员，属于如实披露的状态 |

`notes.md` 仍按原生 Feature 阶段目录读（`featureDir`），没有搬动。`readJsonOrNull` 与其他调用点不动。

## 2. 逐判据结构合同（R06）

**合同常量**：`verifier-report.mjs` 用局部常量维护汇总表合同。

| 列 | 合同 |
|---|---|
| 前三列表头 | `id`、`status`、`severity` |
| 第四列表头 | `证据`，或原生现行的 `证据（一行：文件:行 / 引文 / 数值）` |
| status 取值 | PASS / WARN / FAIL / SKIP（`summary.schema.json`） |
| severity 取值 | BLOCKER / MAJOR / MINOR（`types.ts::Severity`） |

**读表**：复用已有的 `tableCells` 与装饰符归一化。只认表头合乎合同、且第二行是分隔行的表，从表头之后的数据行取结论；正文里提到的 ID 和其他表都不算。

**核对**：当前 overlay 每个 ID 在这些表里合计恰好一行；同表里 Framework 自有的判据不管。逐行核：

- 4 格齐；
- status 合法；
- severity 合法；
- 证据非空（SKIP 的理由写在证据里，是否成立归语义判断）。

所有问题一次报全，报告原件不改；修复出口仍是交原审查者重出。WARN/FAIL 的 notes 处置记录检查保留；PASS/SKIP 没有新增审批。

**请求侧**：新增 `summaryStructure()`，`pre_verifier.mjs` 的请求引用它，和核对用的是同一份结构。

`pre_verifier` 同步退出的内容：

- 「为 knowledge_* 在 `checks:` 各追加一条、判不出也写」的第二份 PASS 明细，以及「相应调整 summary.total」。现在 PASS 的核验方法写进报告说明，非 PASS 的照原生写进 `checks:`。
- 「裁多少行由 verifier 按需要定」的旧注释。改为说明：逐判据的结构核对与逐知识条目的语义核验是两种职责。
- 「spec 自己判」的过时注释。改为：判断由蓝图设计形成，spec 核验收承接。

`phase-closure.md` 的门禁说明同步为「格式不合、判据缺行重复或取值不合」。
