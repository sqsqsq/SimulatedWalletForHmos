## 2. E01 容量事实（只读、非秘密字段）

取证脚本是 `output/scratch/2.0.4/e01_facts.py`；触发逻辑从已安装二进制 `opencode-ai/bin/opencode.exe` 的内嵌源码读出。

| 项 | 事实 |
|---|---|
| 二进制 | opencode 1.18.32；当前 shell 里 `which opencode` 解析到 `npm\opencode.CMD` 包装，原生可执行在 `node_modules/opencode-ai/bin/opencode.exe`。TEST §1.2 要求解析到原生可执行文件：起跑前按已知做法把这个 bin 目录放到 PATH 前面，再复核一次 |
| 生效配置 | `~/.config/opencode/opencode.jsonc`：bailian、wyk、volcengine 下各模型 `limit.context` 1048576、`limit.output` 131072；没有 `limit.input`，没有 `compaction` 段 |
| 自动压缩触发 | `vl()`：`compaction.auto !== false` 且已用 token（total，或 input+output+cache.read+cache.write）≥ `vn()` |
| 可用窗口 `vn()` | 有 `limit.input` 时为 `limit.input − reserved`（reserved 默认 min(20000, 输出上限)）；没有时为 `limit.context − min(limit.output, 32000)`（32000 可被 `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX` 改） |
| 本机算出的值 | 1048576 − 32000 = **1,016,576** token |
| 服务报错 | 上一轮服务拒绝时报 `Range of input length should be [1, 1000000]`，**单位仍未知**，服务文档未取得 |

推论（未验证）：如果服务的 1,000,000 也是 token，那么累计在 1,000,000 到 1,016,576 之间的请求不会触发压缩，会直接被拒；而且压缩判断用的是上一轮回复的用量，新加的工具输出可能再推高一截。

**已固化（用户 10-12 授权，长期配置、不按单次运行设）**：

- 全局 `opencode.jsonc` 五个模型（bailian 两个、wyk 一个、volcengine 两个）都加了 `limit.input: 1000000`；改前备份在同目录 `opencode.jsonc.bak-20261012072249`。
- 可用窗口从 1,016,576 降到 **980,000**，低于服务拒收线 1,000,000。
- 新配置的非秘密字段已复读核对；原生 `opencode.exe models bailian` 能正常加载。整个过程没有调用模型。
- 规则写进 `tools/cli/README.md`「opencode：输入上限要低于服务的拒收线」。

**仍未核**：服务端 1,000,000 的单位。上面的取值假定它是 token；如果是字符，中文场景下仍可能撞线，需要再降。上一轮报错来自 `bailian/deepseek-v4-flash-0731`。
