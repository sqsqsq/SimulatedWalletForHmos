## 9. 交互组合裁定

1. 两 Case 只用 init/update 命令起手，材料和必要决定由模型主动取得。测试不泄露材料清单与修法。
2. 命令起手未表达后续目标，在交付关卡选择；真实用户已有授权则复用，不能强制重问。
3. 自动充值实际送审后才初段检查点；车钥匙选实现方案并由原生范围保证止于 Plan，不在 Coding 开始后强停。
4. 设计质询先于准入，人读审查先于相应交付；两者不能互相代替。
5. 直接 Framework 入口取得同一知识/质询资产，不创建 Story；上游 FW-01/FW-02 未接入则该项未完成。
6. update 收齐变化后先定有效输入，再判设计影响、同步人读和必要审查。表达变化不强升 revision，文档收口不授权施工。
7. 状态/回流按实际发生的结果，不凭配置、文件存在或 summary 的单个 PASS 推定完成。

以上状态不自动随测试变绿晋升；实施者交证据，设计者核语义/职责，用户确认最终行为评价。
