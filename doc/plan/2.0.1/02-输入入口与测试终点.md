# P1：输入入口与测试终点

目标：修复 F01/F02 与业务终点不一致，保留合法直接 Framework 入口。

## 1. CLI 传输

必读 `tools/cli/registry.py`、`runner.py`、`config/clis.json`、`tools/cli/tests/test_registry.py`、`test_lifecycle.py`。输入是 `CliRunRequest.prompt` 的完整 Unicode 字符串，包括换行、引号和空行；输出是 CLI 实际收到的一条用户消息，内容一致。首次与 resume 共用同一传输路径。

采用现有配置的 `executable` 指向原生可执行文件，Windows OpenCode 使用安装包中实际 `bin/opencode.exe`，以 argv + `shell=False` 启动。配置已有绝对路径支持；本机路径放本地配置或 PATH，不提交用户名路径。不增加通用批处理解释器。对仍解析到 `.cmd/.bat` 的注册项，写前返回明确的配置错误与原生入口配置办法，不在 CMD 上叠加转义；其他宿主按其已有原生入口配置。

维护环境准备说明交代如何找到已安装的原生入口以及记录实际执行文件；不修改 Case 首行来适应截断。Framework 已有的安全进程启动能力可作为行为参照，本仓工具不依赖 vendored 私有函数跨语言调用，也不复制整套进程管理。

在现有 fake CLI 加 argv 回显，覆盖中文、多行、空行、双引号、百分号、`&`，以及 resume 的 session id。断言进程收到的 prompt 与请求逐字符一致；错误执行文件在创建消费工作前失败。该验证不调用模型、不要安装另一套测试运行器。

## 2. 用途和入口选择

Extension 的 Story SKILL 描述写明“从需求材料和人工决定形成需求说明/评审交付，接受系统单和本地单；授权后交原生施工”。story-knowledge 仅供当前动作取得知识，不负责更换入口。

Framework 原生物化应保留源 Skill 的用途（U2），使用者通过宿主 Skill 描述和现有入口表就能知道何时用 Story。自然语言要求需求说明、评审与材料确认时，模型应使用这个入口；明确指定 `/spec`、既有 CU 或原生维护任务时按原生入口，不能因没有 story-flow 自动重定向。

验收分开两层：物化输出保留用途、安装路径和直接调用正确是确定性验收；自然语言未知请求是否正确选路由是 CLI 行为验收。先修传输，再评价后者；不将增加测试专名或“ISSUE 必走 Story”写入机制。

## 3. 测试终点与宿主交互

在现有 `end_at` 中明确 Story 的业务交付层次，**同一终点对象仍是唯一来源**：

- `kind: story` 增加 `delivery: local | submitted`；Story Case 均显式登记。`local` 为已登记且当前交付门成立；`submitted` 还须现有 archive 记录/对外结果对应当前 Story 与 Review。非 Story 终点不允许这个字段。
- 自动充值首段用 `submitted`，车钥匙继续 `phase: plan`；本地单不调用远端。没有授权时先等待消费模型向人询问，不由驱动器代答授权。
- `end_target.py` 读取现有 flow 的归档事实及版本；缺失/过期则未到终点，保持正常交互。不要另写“已送审”状态。已有失败报告如实展示，不轮询假定成功。
- 命令行 override 与 suite 的 requested/effective 记录按现有方式保留，新字段不得在 resume 丢失。`story` 简写只表示 local，明确写入 effective；不能暗中替 Case 选择外发。
- 初段真正到达终点后再 checkpoint、回流和投放 update。只有实际发生的更新段才用 update 后缀。后评同时保存需求、蓝图与原生独立产物审查目录及摘要，不能只复制 features。

修改位置：`test/scripts/end_target.py`、当前驱动器与回流调用点、两 Case 配置/interaction-script、TEST §4；不增加平行调度器。CLI 运行本身仍由用户授权。

宿主只回答实际被问的业务问题，允许合并问题。参会人身份和正式性不明时，模型应提出必要澄清；不为命中交互脚本强制所有术语重复确认。更新反馈按真实初稿提出“明确停用横幅直达重签”等意见，不能以不存在的缺陷强迫修改。

## 4. 验收

| 输入/动作 | 预期 |
|---|---|
| 多行初始与 resume 请求 | fake CLI 收到原文；不会出现只有首行/多余引号 |
| 解析到批处理、原生 exe 不可读 | 启动前说明配置错误，无半条业务请求送出 |
| 安装后读取宿主 Skill | 用途与源描述一致；不是只剩名字 |
| 无 story-flow 的合法直接阶段任务 | 知识照常送达，不创建 Story、不强制改道 |
| submitted 终点，只有成文登记 | 不截停，能正常回答交付选择 |
| 已授权归档成功且版本匹配 | 才形成首段检查点；重复判断不重复归档 |
| 初段失败、配置有 after_initial | 回流仍标初段，不生成伪 update 结果 |

测试在现有 `test_multi_case_cli.py`、`test_blueprint_case_closure.py`、`test_update_checkpoints.py`、`test_host_driver.py` 中覆盖所属职责；不通过改预期将“没送审”变成送审成功。预算引用总览 P1。
