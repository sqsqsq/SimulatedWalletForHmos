# P1：入口、授权与旧职责收敛

目标：完整发送请求，按用户选择到业务终点，退出已确认的重复职责。预算见[总览 §5](01-优化总览与裁定.md#5-预算与交接)。

## 1. CLI 输入

修改 tools/cli/registry.py、runner.py 和现有注册配置，复用 executable/argv。Windows OpenCode 使用安装包实际 bin/opencode.exe，直接 argv + shell=False；本机路径放本地配置或 PATH，不提交用户名路径。解析到 cmd/bat 时启动前明确原生入口配置要求，不堆叠转义、压平 prompt 或新增批处理解释器。

完整 Unicode prompt 应成为 CLI 收到的一条原文消息；初始/resume 同路。现有 fake CLI 用真实子进程回显中文、多行、空行、引号、百分号和 &，逐字符核原文，不能只核命令数组或退出 0；不调用模型。

## 3. 交付与授权

SKILL、design 页、delivery.mjs、routing.py 统一为：送审、完整设计交接、实现方案、完整实现、暂不推进；本地单不显示送审。

- 完整设计交接：原生 CU/design_refs/readiness，不启动施工。
- 实现方案：CU 准备及适用 Spec/Plan，明确止于 Plan；合法复用不强写新文档，不 Coding。
- 完整实现：在实际授权内交原生交互路径。
- 已有授权直接继续，只问新增范围/权限/业务决定。命令起手只授权 Story 段，本次在交付关卡问后续。

实现方案向原生 prepare-scope 交实际请求结果及 spec/plan 上限，沿无 run 交互路径；不创建 Goal 或扩展 next-phase 表，不以测试器在 Coding 开始后强停冒充正确上限。

## 4. 唯一终点

end_at 的 Story 增加 delivery: local | submitted；Case 显式登记，非 Story 禁用该字段。CLI story 简写归 local 并写 effective；requested/effective/Case 原值按现有方式保存。

submitted 必须同时有当前成文登记、当前交付资格和当前版本真实归档结果。读取现有发布事实，不新建“已送审”账本；缺失/过期/失败不宣称到达。驱动器不替模型上传。

自动充值 submitted，车钥匙 phase:plan。真正到达后才 checkpoint、回流和投放更新；检查点只读，**不用 --answer 绕行**。按实际发生的段落命名；同时留存 features 外的 Story 报告。修改 end_target.py 及驱动/回流消费者，不加平行调度器。

## 5. 旧职责退场

hooks/shared/verifier-report.mjs 删除 verifier.conclusions.json 写入与首份摘要锁定。身份/有效性归原生 verifier-evidence/check-receipt；扩展保留 overlay 覆盖、意见处置和不得篡改原回复的要求。同步 phase-closure.md、test_review_closure.py，真实重新派审的新报告不能因“第二份”被拒。旧账本不是新版本运行输入。

golden_design.py 的日常装配改用现行蓝图夹具中的有效知识决定，不再读取旧 spec/knowledge-use.yaml 或执行旧格式转换。历史只对照；test_golden_sample.py 不再把旧格式列为现行必需输入。保留有效金样、原始业务材料和原生指纹重算。
