## 1. 结论

T1 已修：prepare 与 check 通过同一个函数读取「这份材料在它的报告目录里的结论」。材料 A→B→A 恢复后，A 目录里已有的 pass 或 warn 由 prepare 直接复用（`reused: true`，返回原回复），check 读的是同一份。A 已有的 fail 不会被复用成通过，在原目录复审仍可以更新结论。

- 验证（`verify.py handback`）：
  - 全量 1465 通过，1 失败，232 秒，失败的仍是 `test_run_measurement`（spec 2.1.0 历史参考里的 png）；
  - 对现建的开发版模板跑失效形态，58 条 FAIL 0；
  - CLI 测试 29 条通过，compileall、validate_clis、45 个 `.mjs` 的语法检查都通过。
- 预算：本次 G +21、X −22、净增 −1；累计 G 5,213、X 5,330；总量 13,876，N = −117，R ≈ −3.8%。

## 2. 改法

位置：`extensions/skills/story/scripts/core/story/independent-review.mjs`。

- **新增 `materialConclusion(key, reportDir, reportFile)`**：当前回复位置有回复就判它；没有就从目录里其余回复中，取最新的一份有效结论（pass/warn/fail）；都没有返回空。`reviewResult` 和 `prepareReview` 都调用它。
- **prepare**：按材料键取出这份材料的报告目录（首次准备时定下），用上面的函数读结论，不再要求「上一次准备的也是这份材料」。
  - 结论是 pass 或 warn：复用那份回复，`reused: true`。
  - 其余情况：另起下一个编号的回复位置。
  - 当前回复不合合同时，按「新开位置之后 check 会读到的」那份结论判断，也就是目录里其余回复中最新的有效结论，两个入口仍然一致。
- **`earlierConclusion`** 的参数改为材料键、目录和要跳过的文件，不再依赖准备记录。回复编号的读取抽成 `replyNumbers`，prepare 与 check 共用。
- **退场**：原来那段依赖 `was.material_key === key` 的复用判断，以及「还没写回复的位置原样复用」的分支。
  - 在新规则下，下一个编号就是那个空位置，结果不变。
  - 没有新增缓存、状态或扫描，复用的仍是已有的 `report_dirs` 与目录历史。
- 模块头的说明同步改写。

## 3. 测试

测试类 `TheReportIsCheckedReadOnly`：

- 新增辅助函数 `restored(kind)`，走产品命令：A 写回复 → 改成 B 并准备 → 恢复 A 的原始字节再准备。
- `test_a_restored_material_reuses_its_passing_report`：prepare 返回 `reused: true` 和 A 的原回复；check 是 pass，`report_file` 与 prepare 相同。
- `test_a_restored_material_reuses_its_advisory_report`：warn 的情况同上。
- `test_a_restored_material_keeps_its_blocker`：fail 不复用，另起回复位置，check 仍是 fail；之后在原目录复审得到 pass，结论更新。

在旧实现上跑这三条，pass、warn 两条失败（prepare 返回 `reused: false`），fail 那条通过，与评审的反例一致；换回新实现后全部通过。原有的单元格解析、目录冲突、fail 后新回复等测试没有改。
