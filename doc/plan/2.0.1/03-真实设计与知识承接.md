# P2：真实设计与知识承接

目标：实际消费来源与知识、真实独立质询、向 CU 传递成立的义务。必读原生 component-design、app-component-blueprint-workflow、blueprint-questioning；扩展 evidence-rules、蓝图作者/质询页、knowledge-task 与 knowledge-application 合同。预算见总览。

## 1. 责任与顺序

冻结输入 → 作者取得要求/知识 → 原生候选 → 独立质询 → 设计负责方处理 → 原生准入 → Story。

主执行者派遣，作者写候选，隔离质询者判断，设计负责方维护 canonical。作者取 questioning 任务只是准备，不是执行。Extension 不建第二套设计调度/provider。

Story 交项目根、component/blueprint、冻结输入/原生 materialization、实际人签及“止于设计准入和投影”的请求。未实际读入的资产不记已消费。

## 2. 质询交接

| 项 | 合同 |
|---|---|
| 输入 | 候选、冻结原件/人签、接口转写/映射、必要完整知识、扩展要求、原生 scope/结果合同 |
| 执行者 | 宿主已有隔离子代理；读取材料，不直接改 canonical |
| 输出 | 原生逐项问题、证据、disposition、owner、verification refs、未决和处置建议 |
| 落盘 | 主执行者原样保存到蓝图质询过程目录，记录被评候选版本/内容及真实调用 |
| 消费 | 设计负责方处理真实问题，必要时问人，再记录 questioning 与准入 |
| 未完成/缺能力 | 保持未质询，不自审、不写 complete、不冒充准入 |

scope 复用原生 requiredQuestioningScopes 等能力，不复制视图/关系/根问题集合。报告绑定派审候选；不把新增 questioning 后最终 YAML 的全文摘要与派审前全文作回环比较。原件与候选是过程证据，不是第二真源；不增加防篡改账本或固定返修次数。

直接设计与 Story 转入同一路径，上游合同见[协作报告](06-Framework协作问题报告.md)。发布件前不能签直接入口完整链；本仓要求页/数据消费者/离线验证可先做，不改 vendored 或建立 Story 永久旁路。

## 3. 来源与未知

SE 明确内容忠实转写；本地映射、类型选择保持设计判断。转写是派生物，不因 source_ref 指回自己成为外部权威。

缺内容保持未知。当前设计依赖缺口时补来源、经授权调范围或留草稿；不只改 needed_by。未知响应不能以空字段/drop 冒充“不需要”。interactive 不借 headless_assumed 替代询问。脚本核路径/原始字节/结构，独立质询对原文判语义。

## 4. 知识生产与消费

| 内容 | 权威 | 下游 |
|---|---|---|
| 项目事实 | discovery.facts；知识事实用 value.knowledge，观察/用途用 observation | 设计、Story、知识任务；普通工程事实保持原生形态 |
| 规约 | knowledge_application、理由、requirement、真实 target_refs | CU 具体 must 与验证责任 |
| 模式 | 选择/拒绝/调整及真实 roles | 实体角色与落实证据 |
| 精确设计 | 原生 contracts/runtime 优先；必要且无对应字段的放 story_details | 附录、专项与施工输入 |
| 人裁定 | 实际原话、权限、对象和范围 | 模型有据判断不记人工授权 |

声明知识来源却缺 value.knowledge 要报缺口；不强迫全部工程事实套结构。应用指实际承担者，不用名称或自指证明；不适用给真实条件。

作者任务、post_check、pre_verifier、UT/Testing 读成立决定、必要原文和实际契约义务。无 Story、无新 Spec/Plan、派生/复用均保持；共享决定不在各 CU 重裁。

## 5. 验收

使用 test_requirement_source.py、test_knowledge_application.py、test_knowledge_task.py、test_cu_knowledge_chain.py 及实际设计证据：

完整接口忠实转写；业务意图接口不借邻近字段成为权威；知识事实/坏登记/合法空集合分别处理；质询有实际调用和原件，作者自填只作结构反例；义务/角色派生复用可读且不串 CU；直接设计与 Story 接线一致。

退出代填质询和为过门改变来源/范围的要求，保留原生准入、有据判断与合法未决。未运行 Coding/设备时如实未验证。
