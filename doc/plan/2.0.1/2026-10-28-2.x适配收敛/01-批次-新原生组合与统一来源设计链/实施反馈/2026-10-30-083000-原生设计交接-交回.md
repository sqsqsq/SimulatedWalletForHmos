## 1. 新的交接方式

| 项 | 现在 |
|---|---|
| 蓝图身份 | 蓝图与需求同根，标识就是需求标识：`<features_dir>/<需求>/blueprint/component-blueprint.yaml`。组件由原生设计按工程上下文认定，写在蓝图里，Extension 不存 |
| 进入设计 | 本轮范围定了（范围关卡选整体承载，或本轮切分定案），`status` 的下一步就是 `design_blueprint`：进 `/component-design <需求>`。没有交接命令，契约不写设计关联与输入 |
| 需求条目 | 语义由模型写一次（`item_id`、`kind`、`source`、`authority`），`import_sources.py --feature <需求> --scope <条目文件>` 按材料索引补工程相对路径、盘上核过的完整摘要与 provenance（人工答复 authoritative，其余 observed）。条目来自需求系统来源时另写原生物化信封 `blueprint/requirement-source-materialization.json` 并过原生检查（蓝图还没建时要 `--component`）；本地来源只输出条目，不落 provider 文件；失败不写 |
| 设计采用 | 采用 = 蓝图 `current_scope_items` 声明的来源。落在 `<需求>/sources/<版本>/` 且该版本登记在材料索引里的，按版本展开为采用文件（原件、阅读正文、图、人工答复）。`phases/design.md` 写明：设计依据的每份来源各写一条，没写进条目的材料就是没采用 |
| 设计门 | 蓝图不在 → `design_blueprint`；原生读不过 → `fix_blueprint`；条目没有一条来自本需求已导入的版本、声明来源字节/摘要不符、版本没登记、或材料文件声明高于 observed 的证据强度 → `design_blueprint`；投影无效 → `design_projection`；都成立 → 成文 |
| 流程契约 | schema 6；`status` 只有 `gathering`、`story_written`（init 与 reopen 写 gathering），旧 schema 明确拒绝。「收口」改为派生：成文已登记，或本轮范围已定且同根 canonical 蓝图已在。收口之后材料再变只登记进本轮；设计开始之前范围定了也照常开新轮重新确认 |
| 成文依据 | `story_basis` = blueprint_ref + `sources_sha256`（声明来源 [路径, 摘要] 的有序摘要，取代 input_sha256）+ knowledge_sha256 + `materials_digest`（登记时的索引摘要）+ 文件指纹。设计采用的来源换了 → 待重新登记 |
| update 收口 | `registered_input_stale` 退出；documents 收口改核「成文登记之后材料有没有再变」（`story_basis.materials_digest` 对当前索引），变了要按新材料重新登记 |

设计取舍记录：`output/evidence/2.1.0-impl/A04-handover/design.md`。

## 4. 待设计者裁定

1. **兄弟 AR 点名检查随提取稿退出**：原 `flow/check.mjs` 要求交给设计的提取稿点名同 SR 下的兄弟 AR（`positioning.sr_related_ars`）。提取稿退出后这条没有载体，本步没有迁到 Story 或蓝图。是否需要、放在哪一层，请定。
2. **「采用」= 需求条目声明的来源**：没写进条目的材料（例如只读过的系统设计）在 Story 材料表与审查里列作「没采用的阅读稿」。本步在 `phases/design.md` 要求设计依据的每份来源各写一条（系统设计约束写 invariant），夹具也按此为每份正文各写一条。请确认这个口径。
3. **人工答复不强制进条目**：设计门不要求蓝图引最新的 `sources/人工答复-v<N>/`，只在作业说明的示例里引了它。是否要作为门禁条件，请定。
4. **update documents 收口的保护强度**：现在只要求「成文登记在材料变化之后」；不再要求设计必须重新声明采用关系（库存新版本是否采用由 update 分析判断，按参考01）。请确认这一档够用。
5. **材料表按最新版**（A03 待裁定 1 延续）：采用的旧版本在审查对象里另列「设计采用的阅读稿」，材料表核对仍按各来源最新版本。
6. **物化信封落点**：`blueprint/requirement-source-materialization.json` 是本地选的名字（原生只约定 schema，不约定文件名）。
