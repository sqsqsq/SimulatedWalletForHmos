## 2. 先统一来源与采用合同（F3/F4）

### 输入与输出

输入：由本版初始化的新Story需求/原生蓝图身份、完整当前格式材料索引、实际蓝图和原生引用、人答只读投影。输出分开给真实范围义务、实际设计依据、登记库存、已引证采用版本、独立必读人答和具体问题；不落第二份采用清单。

`current_scope_items`只承载真实requirement/goal/invariant/high_risk并保原生追溯。实际依据从参考01列明的原生facts/设计对象provenance及合同真实source_ref取得；reader_guide的JSON Pointer、内部对象引用、示例和任意同名字段不当文件依据。冲突双方供核源，不自动认双方已采用。没有明确引用只能称“未见设计引用”，不能由脚本替作者判“不采用”。

### 具体动作及直接消费者

1. `materials/registry.py`从已有版本/会议生产记录派生统一`files`视图，行含真实工程内文件身份、来源/版本/角色/完整摘要，历史A05使用schema3；D05已切schema4，当前依参考01/D08切schema5，不增另一持久表。会议原件/raw/corrections/evidence和人答都可定位；不依赖旧版本目录扫描。派生阅读件核同源后取得摘要，不能任意重算坏文件来放行。
2. `materials/scope.py::_files/fill`用该完整视图补真实scope来源，保片段和实际authority/provenance；会议不因存放在story-src/meetings被误拒。scope准备不顺便把支撑资料全转成义务，也不改写原生物化协议。
3. `framework-access.mjs::adoptedSources`按参考01的字段边界收集真实依据，用原生路径/来源helper，再与完整登记文件精确匹配，退出材料索引登记的稳定版本猜身份与“只有scope才算采用”。普通原生非Story来源保持其合法性，不强建Story索引。原生`blueprintSourceRefFiles`只复用文件依赖能力，不能靠它省掉缺失文件/摘要错误。
4. 同步`knowledge-task.sourceIndex`、`story/design-source.mjs`、`sources.mjs::adoptedOf/upstreamDocs/originRows`、`story-inputs/chapter`、`review-object`、原生独立质询材料任务、`storyReviewVisual`、routing/成文登记/update等直接读者。源集合和版本选择只有一套派生规则，角色在输出中明确，不把文件在场当已读/已理解。

## 3. 闭合有效人答的生效、适用性与送达（F1）

1. `decisions.py::cmd_decide/cmd_decide_update`在保存真实答复与既有问法清理后，调用同一导出/索引刷新再给next；使用新结果，不使用答复前manifest。新答复保原问题/选项及范围语义快照，不只保一个“1”或可变选项key。
2. `answers.py`按参考01§2.2覆盖同一新需求的起手/会议、当前update及其完整早期update记录，复用既有严格记录读取。整体承载后旧split_carrier不再当前有效；不同问题版本不以自由文字item或新hash自动覆盖旧人答。update本地restore不自动撤销业务决定，保原话和适用上下文；无法机械判当前的记录明确其出处，交既有语义判断，不新建批准状态。
3. 导出失败保“答复已生效”事实、明确未完成的派生步骤和既有round恢复命令；重试不重复写答复，不在人答未改变材料时开新轮/重问。scope准备读取前确保当前人答来源可用；纯查询/独审只读，投影不同步报缺口，不默用旧答案。
4. 既有`status --materials`只读返回required_answers期待身份、实际导出/同步问题；已有flow/client在一次上下文装配中取一次，各读者共享。人答不进普通materials.digest，以免制造补料轮；但必须独立进入设计作者、原生质询核源阶段、Story作者及其独审。质询仍先人读八问再核原件，不能把原件/人答提前塞进首读隔离载体。
5. 既有来源身份摘要与审查对象绑定覆盖“实际设计来源＋当前必读人答”。即使作者完全省略人答scope，也不能把新答复排除出对象。人答变后原稿是否要改由真实影响判断；有据不变可沿必要复核/登记继续，不能只改登记时刻冒充已核新决定。

**完成结果**：正常范围答复结束后直接进入设计即可读到刚给的原话；update裁决和问题版本可追；旧承载答复不混成新授权；已有同范围授权和真实历史仍保护。不得靠测试额外refresh、预造answers文件或仅检查authoritative字段证明此链。

## 4. 保住Markdown图关系与会议阅读身份（F2/F3）

Markdown保原件字节，按导入前原位置解析本地引用，映射本次实际输入及已登记文件的最终位置；必要时生成链接正确的阅读投影，图片可留自己的来源版本。先确定真实目标再发布阅读件，缺文件给具体缺口，不静默丢图或改成假路径。重复同输入/同引用关系复用，实际内容/关系变化形成新版本；不反向扫描改写整个旧资料库。

修改importer的Markdown转换/写入及registry阅读关系派生、来源展开/图输入读者；复用已有引用/图解析能力，支持产品已有合法形态，外部URL/文内锚点保持。有效原图身份和实际引用从阅读稿及库存取得，不新增作者图表。修正后的真实产物可供下游fixture使用，但导入能力回归必须从未预改路径的原件走生产入口，不能用手改后的source字节和新SHA代替。

会议保持原件/raw与受控corrections/evidence的分工。统一来源读取覆盖其角色，scope可引用真实有效阅读依据；用已有apply_corrections/evidence_stale核同源，非法改写不能通过重登记hash洗掉。合法纠偏改变阅读身份、进入必要源/审查当前性，原话和原人答不覆盖；不为了路径统一复制一套会议或新增会议迁移流程。
