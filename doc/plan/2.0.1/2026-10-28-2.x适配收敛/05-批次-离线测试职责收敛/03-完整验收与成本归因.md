# E03 完整验收与成本归因

前置为E01/E02完成其必要定向验证与独立交回，源码/测试对象固定。目标是一次取得完整结果与可归因成本，结束“改一点→全量跑十分钟→再猜下一点”的循环。不是为测量再造一套平台。

## 1. 起跑前检查（不另跑慢基线）

读取既有d558b1d6全量与各步定向原件，确认旧对象、标准、Framework/patch及本次diff。逐项核E01的10个判据已退出总流程准备、E02同状态实际归并、原独有接线有具名承担者。仅改文档或把类名换了而调用链未变，不进入“提效完成”验证。

全量命令仍为现有verify.py handback；并发仍4/1/1，保持短临时目录/固定安装组合/相同机器条件，记录同时存在的重负载，不做workers扫描。两份配置不同的当轮template/installed_package不混用；准备和清理都在总时内。

不单独重跑1.9.9或2.x慢基线。首次完整取证就是实施完成后本来必须执行的handback；若代码仍在频繁变化，先结束定向修复，不能边跑边改被测对象。

## 2. 用现有设施收集足够证据

full使用已有 `STORY_TEST_TIMING_JSON` 输出全部类的时间/条数/子进程观察，不仅保最慢十条。其spawns是该Python进程能观察到的子进程数，不冒称覆盖所有嵌套进程；setup/call/teardown分项以原pytest结果解释。

failure沿现有run_job/ModeResult增加小范围elapsed记录：只包围实际checker调用，保持ok/infra/正反判法及输出顺序；结果随本轮证据保存，列ID、阶段、耗时。不得另造profiling服务、调度器或新验收状态。现有verify打印总时/返回码及准备/清理的真实区间保原始输出，补齐总时不能只靠手写交回数字。

这点观察性修改只在test/scripts里，不改变产品路径、性能判据或台账分母；验证确认计时不改结果。原始输出和对象指纹写现有output/verify或output/evidence，不投放模型Case输入。

## 3. 一次完整取证及判定

| 维度 | 判定 |
|---|---|
| 正确性 | 全部必需检查真实执行且成功；skip、委派、未执行分别列明；反例必须因目标判据失败，不能由准备坏掉代替 |
| 保持能力 | 每个退出项有原独有断言的去向和真实接线承担者；来源/知识/写保护/恢复/安装/usage等不缩水 |
| 实际提效 | 20次局部正反核不再造完整设计前态；相同原生状态不再跨类重复冻结；局部Node冷启动减少有具体改动依据 |
| 目标耗时 | 全部必需准备、通道、收尾及触发的第二装配计完整墙钟；120—180秒仍是目标，未达单列，不判功能失败 |
| 实跑边界 | 离线不签模型阅读/知识应用/独审语义/真实内网效果；这些继续D04 |

本批原则上不改Framework pin、patch和正式装配函数，第二次独立空目录装配沿原触发规则。若实施确实改变准备所有权/装配输入则必须重跑并计入总时，不能为目标隐藏。无变化则复用原职责证据，并公开原源码对象，不冒称新源码重建过两次。

若第一次完整运行超180秒：功能可通过、性能目标未达，不自动重跑。必须从当次所有类/失效形态及实际调用链列清剩余成本是必要原生边界、重复准备、局部规则未降层还是环境争用；有明确新原因才提出下一次修正。仅有“再加几个worker/再缓存一层”不构成继续试验依据。

如果实际保留的必要原生链本身已超过主体预算，诚实呈现其数量、原入口与实测成本，回设计者核更简单的责任安排；不能删正常保护、把离线职责推给用户或CLI凑目标，也不能把规划的80秒写成测量事实。

## 4. 交回与后续

一次集中交回应包括：三步提交/范围、标准和被测身份、每组迁移/保持/退出表、定向及完整原始结果、错误原因区分力、前态和进程工作量变化、全部成本及未覆盖。新旧条件不同的日志只作有边界对照，不宣称因果比例或稳定达标率。

用既有budget_report复核产品G0/X0边界；若extensions实际有变，就不是本测试方案的零增量，必须列真实diff及设计依据，不能移到排除域藏量。各步及总包不重置，当前产品4417/4250保持原授权和自查结论。

提交后集中评审，不逐反例交回；本批不会自动阻塞D04功能实跑准备，也不自动授予真实CLI、demo升级、晋升或发布。实现/测试方法正确、性能达标、模型效果成立分别报告。
