## 1. 定向离线

先跑本次影响的既有 test_knowledge_protocol、test_knowledge_use、test_neutral_knowledge、test_contracts_single_source 及章节/统计点相关用例。命令使用 `python -m pytest test/story/tests/<相关文件> -n auto --dist loadscope`。确定性边界用中性输入，允许构造坏格式核报错；不能靠构造错误业务稿证明模型判断力。

R09 对比最新 adapter 拆分实际 diff，核 init/fetch/archive/restore 的参数、输出、失败传播、备份 cloud/local 与目录落点。复用 test_requirement_source、test_adapt_source_kinds、test_adapt_ownership 和现有 adapter 用例，确认 core 没有 adapter 导入/命令生成，adapter 没有 core 编排。不触内网系统，不把 Demo 替身当内网验证。

R10 对受本版影响的 update 输入及文档引用回归无变化、变更前镜像、回写确认、恢复、失败与重复执行；主要用 test_story_update、test_update_checkpoints、test_update_dispatch。无实际相关变化且既有证据适用时复用并注明基线，不默认追加 update 真实第二段。

完整遗留收口运行一次必要全量离线；无新增变更不重复刷。语法/结构绿只证明这些层面。

### 具体输入、动作与预期

以下确定性用例使用现有测试文件和临时工作区；断言投影/读取结果，不让关键词断言代替语义质量。

| 测试位置 | 输入与动作 | 应观察到的结果 |

| test_indicator_reporting.py | Spec 同一点列成功/拒绝/通信失败，Plan 按三行写；取 pre_verifier 任务 | 三行全在审查输入中，原顺序保留，不只剩最后一行 |
| test_indicator_reporting.py | 两个指标引用同一统计点，Plan 一组实现行；生成审查任务 | 两个指标都能看到同组 Plan 行；不出现第二个指标虚假“Plan 缺行” |

## 2. 整版实现完成后的正常业务效果验证

沿现有两个 Case 及原材料：auto-topup 到 Spec，car-key-sharing 到 Plan，默认不开 update 第二段、不开 Coding。开跑须用户授权，宿主按 TEST 完整运行协议与原交互立场交料，不额外提示修法或注入维护文件。

R05 已核为宿主漏投；按原交互脚本将产品稿与会议记录一并送达，核实际落盘后再回复已交料。这是恢复原输入协议，不是为模型塞答案。保持未决立场，观察模型能否正确保留，不替用户补选择。

维护者独立读本轮实际输入、events 中材料读取/author 输出、Spec/Story/Review、Plan/contracts/use-cases 与最终审查对象。对业务内容逐项看：指标和业务步骤关系；本端结果可知性；身份与实际结果分离；值是否具体且有依据；决定与验收是否一致；接口和用例是否足够下游实现；图文是否解释真实业务。原始事件及 Coding 行为仍留内网。

审查不要求每项都再启一个模型；沿现有产品 verifier，维护者复核最终内容和漏判。未采纳报告、prior-review 和环境未执行分别记，不能仅凭 PASS 推断对象和语义均通过。

## 3. 时间与失败

每 Case 记录总耗时、用户等待、模型有效工作、工具与审查轮数、环境错误。比较同终点与同口径，不把等待变短称为模型提速。失败先定位模型语义、材料输入、装置或环境，不默认加测试轮次。

检查进程未启动沿现有 harness_incomplete 与诊断路径；恢复后按已有重查能力取结论，不改产品放宽内容判据。真实测试是否重跑由实际缺陷及新授权决定，保留原产物。

## 4. 收口表与 S3 入口

在本方案目录的 `实施反馈/` 中交本步结果；设计者结论写入 `评审意见/`，按 R01–R10 各给：实际根因、改动/未改理由、实际证据、结果与剩余依赖。已确认缺陷须修并验证，R05 可因证据证明无产品缺陷而关闭；R09/R10 的内网未知如实交接，Demo 能验证的部分不能借内网边界拖延。

Framework 上游依赖写出复现材料、责任文件和所需行为，用户已有只读边界保持。若该依赖阻止本轮关键效果成立，不能以已发交接称收口；在评审中明确阻塞。内网 Coding/原始事件等既定外部范围不新增为 Demo 阻塞。

S2 独立评审接受实现与离线结果后记录准确提交基线，作为 S3 输入。该基线的模型效果尚待验证，S3 后的整版实跑同时核遗留目标与迁移承接；发现 S1 问题时同时核迁移后的责任位置。
