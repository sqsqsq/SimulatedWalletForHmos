# 职责交接与预算依据

读者：实施者开工/交回、维护设计者评审。分级规则唯一来源为 test/story/AGENTS.md §5；本文只记本版对象与估算。旧的 1430/350 粗估不作为执行基线；以下区间尚未批准。

## 1. 能力交接与退出条件

| 能力 | 新/保留承担者 | 退出对象与时点 | 必须保持 |
|---|---|---|---|
| 阅读组织 | 既有 template→writing-plan→草稿→章提交 | A1 替换冲突/重复作者指引 | 章职责、合法 H3/H4、多形式、必要表、正文可扩展 |
| 图关系 | 单一来源标记和读者审查 | A1 退一律原样搬入的冲突指令 | 原型图片取舍，角色/条件/返回/责任，不按图数代判 |
| 知识与决定 | 目标知识、当前作者任务与原义核对 | B1 退含糊条件、固定会议行式及无效返修指令 | 人签、未决、规约实际落点，不按编号写特例 |
| 外部取材 | fetch 只读进入 incoming；原 init 仍负责首次输入 | C3 删除旧 review 命令与专用 adapter 模块 | 远端错误区别、本地零访问、目标 adapter 所有权 |
| 变化理解与比较 | 模型还原当前依据、解释变化和关系；普通差异与已有版本提供线索 | C1 交付模型方法；撤销未实施的语义 impact 协议、接受关卡与初始链 baseline 动作 | 不按字节变化或同词命中判业务影响，无差异不遗漏上次未完成内容 |
| 保留/恢复 | 复用备份和单需求文件操作，记录实际前后内容 | C2 只补必要恢复接线，不另造语义状态数据库 | 首次历史未知明示、完整保留、失败现场与外部变化保护 |
| 无变化快速退出 | prepare 比较已知版本、实际取材结果与未完成操作事实 | 无变化不新开语义记录；仅清理本次临时镜像和暂存 | 不漏启动前手改、不将失败/未知当无变化；普通未决不重复催问 |
| 人工意见与当前稿 | 当前 decisions、模型 update-notes、原 Review 渲染与受控重开 | C3 退 review_reflow、旧台账双写/常驻消费及当前 Story 永不刷新的规则 | 原话/语境、暂缓与未评审、自由意见、已有 Plan 同步 |
| 归档与修正 | 原 archive/restore、Framework correction/revalidate 与既有 verifier | C3 写清普通 correction 不自动重审、主动 update 审当前改动阶段；无第二审查者 | 展示后确认、当前对象报告验真；失败返修不受一次硬上限限制，发布失败不重做本地 |
| 测试续行/回流 | 原 worker/lease/reply 与 suite 回流 | T1 退 story-review 专用终点/旧台账存在即完成判定 | 同 session、两快照不覆盖、普通 Case、隔离与证据 |

C1/C2 期间公开旧 review 暂供旧入口使用；其消费者和退出点明确为 C3。新 update 的公开入口在 C3 完整切换后开放；不将半成品能力暴露给用户。旧历史原件只读保留，不持续参与双状态判断。

## 4. 工作单元预算

| B1 | 五类责任修复、原义证据/材料缺口、必要清理 | 120–200 | 50–90 | 证据装配与已有消费者的实际接线 |
| C1 | 模型的依据还原/识别/推演方法，输入送达、只读 fetch 与 prepare | 待按新职责核定 | 按替换的提示/取材消费者实核 | 不再估 scan/impact/baseline；作者方法与脚本分别计 |
| C2 | 模型关联修订/核对，复用成文/人签/人工区，最小关闭与恢复支持 | 待按复用接线核定 | 按实际被替换函数核 | 不增加语义接受状态；先核哪些恢复能力确需新增 |
| C3 | 当前结果交付、统一入口/退场、既有 verifier 当前请求派审及证据闭环、外部确认与实际发布 | 待随 C1/C2 接线核定 | 旧 review 专用消费者仍须完整退出 | 模型可继续结论不转成自动通过条件 |

| T2 | 机制版本与发布登记 | 20–40 | 0–10 | 实际完成结果 |

原机制合计与峰值不再适用：它们包含已经取消的语义协议、初始链强制基线动作与多动作接线。现在只为确定性比较保留必要的只读版本依据，不把它升级成语义审批。本次不直接按“脚本变少”打折估价，模型方法、上下文交付和场景核对本身也有成本。完成总量在 C 各项核定后按实测基线＋真实新增－真实退出重算；取消未写的方案不是代码删除量。

## 5. 开工准备与预算收敛

设计者在批准正式新增额度前取得以下有界接线事实，不启动额外真实模型、不建新工具平台：

1. 骨架父子层级＋同位置多形式＋说明进入草稿。现有七测试已证明其中层级/草稿/位置/上限/图型部分，新增组合只针对验证。
2. 已归档 Review 人工区、议题移除/变义与更新恢复的临时 fixture，确定实际复用边界和异常处理量。
3. 伪 CLI 在 initial 等待后保留 session，确认状态穿透和 snapshot 的插入点。
4. 按 C1 的场景走查核模型在每个决定前能取得哪些原文、有效决定与当前产物；先明确作者方法、入口送达和既有函数复用，分别估提示正文、确定性脚本、退场与验证成本。不得用编写更多场景状态/语义字段代替这项工作。

实施者交事实与更细的函数级工作清单，维护设计者据此签定初始新增额度、预计退出和峰值。临时验证不变成另一套正式实现；若需要新增通用平台或 Agent，按 AGENTS 先提出必要性与更简单替代。当前设计已定接口/行为，准备工作核接线和估算，不把关键产品决定留给实施者补猜。

每包对照“已完成职责预计量/实际新增/真实退出”，差异归因到漏估、重复实现、范围变化或实现膨胀；按 AGENTS §5 分级，不逐包抬数字或改分母。区间降低假精确，不能保证零超差。

## 6. 现有证据及运行成本

2026-09-20 七项 test_writing_plan 现有用例通过，46.33 秒，-n auto --dist loadscope。首次因系统临时目录权限在收集前失败，使用独立工作区临时目录后通过。用例涉及 skeleton_carries_titles、untouched_draft_is_laid_out、skeleton_does_not_cap、form_is_checked_under_its_own_parent、structure_both_required_and_listed、flowchart_does_not_stand_in、any_named_diagram_type。它们不证明新表达效果或恢复/续行能力。

运行成本不从代码行换算分钟。正常预期：先用已有理解与变更线索判断本次关联范围，再按需要回查原文；只有核对后确实无需修订才直接报告。表达改相关章，业务改真源与相关下游，冲突集中问，发布失败只重试发布。既不能每次全量重新理解，也不能因字节没变跳过已知未完成同步。主动 update 的适用阶段正常审一次，当前材料 PASS 复用；真实失败返修的额外调用单列，不按固定次数绕过错误。记录重复读源、整稿生成、审查耗时与等待及新增信息；两 Case 初始与更新分段，评测等待单列。
