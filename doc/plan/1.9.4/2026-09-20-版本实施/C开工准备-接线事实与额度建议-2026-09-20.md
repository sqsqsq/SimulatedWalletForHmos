## 1. 骨架父子层级、同位置多形式、说明进草稿（已在 A1 实证）

这一项 A1 顺带做完了，结论直接引用：

- A1 的中性需求离线链（shell → 填骨架 → 草稿 → 章提交 exit 0）实证了 `####`/`#####` 两级标题按父子关系铺进草稿、
  说明行（`- 答：`/`- 依据：`/`- 待核：`）变成草稿里的指引行、同一小节的多个 `形式：` 都送到。

**对 C 的意义**：成文链这一侧不需要为 update 新增结构能力。update 改章走的是现成的

### 2.2 确实没有现成对应物的四项（真新增，不能按「复用备份」打折）

1. **目录级镜像与整体还原**：整个 `scripts/` 树没有 `copytree` / `cpSync` / `mkdtemp`；
   `.backup/` 是**有备无还**——没有任何函数从它写回原位，它唯一的消费是当身份证据。
2. **工作区侧的 restore**：`story_flow.py` 的 mode 里没有 restore；`adapters/story.js:276-291` 的 restore
   只把需求系统上的 `design.md` 回退一版，日志明写「本地 AR/design.md 未改动」。
   `cmd_reopen` 只改契约状态，**不恢复任何文件内容**。
3. **议题被删掉时，人工表态静默丢失**：`renderReview` 只按**当前登记表里的 id** 回捞旧区
   （`review.mjs:604-633`），没有任何一处枚举「旧文里有、新表里没有」的 `<!-- decision: X -->`，
   然后 `cmdBuild` 用新文整份覆盖（`review.mjs:169`）。无报错、无归档、无告警，
   `test_review_modes.py` / `test_review_golden.py` **也没有一条删除议题的用例**。
   对照：附录投影**有**这种对账（`appendix.mjs:296-305`），review 侧没有。
4. **id 复用但问题换了，旧表态原样挂到新问题下**：匹配的唯一键是 `dec.id`，机器区内容不参与；
   `issueHandEdited` 比的是「盘上机器区 vs 标记里记的摘要」，改 `decisions.json` 时两者仍相等 →
   不触发冲突 → 换上新机器区、旧人工区照搬（`review.mjs:502-506`、`:617`）。
   **没有议题内容指纹，也没有「人是在哪一版问题下表的态」的记录。**

第 3、4 条正是 03 §8.1 要求的「同一议题意义保持才沿用 ID 和人工区；撤销或变义时旧意见及其原语境可查，
新问题不携带旧勾选」——它们今天不成立，**是 C2 的实打实工作量**，不是接线。

### 2.3 只读取材（03 §7.3 的 fetch → incoming）

现在**没有**「先落到暂存区、之后再合入当前稿」的路径：`importer.cmd_import` 是「全转到内存、全成功才写盘」，
覆盖正文前备份；唯一的只读分支 `importer.preview()`（`importer.py:468-485`）只到单份文件、不写任何东西。
会议版本目录 `meetings/<主名>/<sha8>/` 有持久暂存语义，但它本来就没有正文落点，不构成通用暂存区。
**所以 `--out <incoming>` 的暂存目录与清单是新增，但解析器可以整套复用**（`convert_sources` 与 preview 共用同一个）。

## 3. 伪 CLI 在 initial 等待后保留 session 的插入点

### 3.1 现在的行为

`run_case.py:1698-1700`：每回合 CLI run 结束后
`if target_reached(feature, end_phase): result["stop_reason"]="target_reached"; break`。
它排在取回话与续话分支（1709 起）**之前**，所以目标一到就不再取 reply、不再 `replace(request, session_id=…)`。
目标由 `--end-phase` 下发（`run_multi_case.py:1653-1654` → `run_case.py:1516`），
判据是 `target_reached()`（`:457-469`）＝三份产物齐备 + 该阶段四件凭证齐备。

### 3.2 三个要动的点，和一个意外

| 点 | 事实 | 要做什么 |
|---|---|---|
| 目标到达处 | `run_case.py:1698-1700` 的 break | 配了 `after_initial: update` 时改为进等待，而不是 break；不配仍按原路 break（普通 Case 行为不退化） |
| **session 不落盘** | `session_id` 只是 `foreground()` 的局部变量（`:1683`、`:1737`、`:1745`），**全文没有一处写进 state.json**；它只出现在 stdout JSON 与 `cli-runtime` 的 run store 里 | 这是「保留 session」最小的那笔：等待期间要把它放进 state，宿主与续跑才拿得到 |
| 续跑怎么发消息 | 与普通续话**同一条路**：`client.start(request)`（`:1636`）+ `client.poll`（`:1653`）；`tools/cli/registry.py:183` 按 `request.session_id` 有无来选 `resume_args` 还是 `args` | 不需要新写续跑通道，`resume-update` 投的就是一句正常业务请求 |
| **意外：`events.jsonl` 每次 foreground 启动被截断** | `run_case.py:1610` 用 `open("w")`，整个 turn 循环都在这个 with 块内；宿主的 `model_cursor` 是这个文件的行序号 | 只要 worker 不退出、续跑仍在同一个 foreground 里，游标连续；**一旦另起 run 就归零** —— 这正是「不能靠重启新 session 冒充续行」的机制原因，写进 T1 交回 |

### 3.3 可以原样复用的保护（不重造）

- **等待与租约**：`wait_for_human_reply()`（`:209-261`）已经是「无上限等待 + 每秒续租 + 每 300 秒发 `awaiting_reply_stale`」，
  出口只有两个（拿到回话、宿主 conclude）。`refresh_worker_lease`（`:762-791`）与
  `reconcile_worker_state`（`:794-837`，pid 不活且租约过期才收敛为 `worker_lost`）原样可用。
- **回话入队的三档拒绝**与 reply / conclude 的单槽「取走即删」（`:2133-2150`、`:175-206`）。
- **回灌冲突保护**：`promote_case_workspace` 的三方比对与 `_copy_file_with_backup`（`:2916-2943`、`:2810-2830`）。
- **快照最接近的现成物**：`run_case.py:1824-1830` 每个 run 终态时 `copytree(features/<feature> → out_dir/artifact)`，
  是一份不可变的 feature 产物副本——`checkpoint` 要的就是这个动作，只是改在**等待点**做、并按 `point` 分目录。
  （`run_multi_case.py` 侧没有整工作区快照：`snapshot_workspace_sources` 只算哈希清单不复制。）

### 3.4 两条要一并处理的既有事实

1. **两处终态集合不一致**：`concluded_by_host` / `cli_session_lost` / `harness_incomplete` 在
   `run_case.TERMINAL_STATUS`（`:117-127`）里，却**不在** `run_multi_case.TERMINAL_STATUS`（`:86-92`）里，
   而后者正是 `finalize` 的 `accepted` 判据与 `finalize_suite_status` 的来源。双检查点会让 Case 更常停在这几个态上，
   这条不处理会出现「终态了但 finalize 不回灌」。
2. **「第二段」的零件已经存在但没串起来**：`--start-phase` / `--end-phase` override、`resume_prompt()`（`:377-396`）、
   `--continue-case` / `--continue-end-phase`（`run_multi_case.py:840-858`、`2198-2303`）——
   它们**只在新建一个 run 时生效**，而 `cmd_start`（`:1928-1939`）对非终态活动指针直接拒绝并发启动。
   也就是说：要么复用它们但接受「另起 run、游标归零」，要么按 3.2 在同一 foreground 里续——
   D18 要求同会话续行，只能走后者。
