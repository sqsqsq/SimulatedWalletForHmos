# T1 交回：双检查点测试装置（2026-09-20）

方案：[04-测试与发布.md](04-测试与发布.md) §2；另按 C3 交回把两个过渡消费者一并收掉。
本步只动测试域，**机制侧一个字节未改**（预算净 0）。不启动真实 CLI——两段实跑是 T2。

## 1. 为什么要改装置

D18 要的形态是「先给初评、回流原结果且不终止，再触发同一会话的 update，第二次评测后终止、
回流为 `<需求编号>-update`」。原来的装置做不到三件事：到目标就 `break`；`finalize` 的目的地
固定成原编号；`session_id` 只是 `foreground()` 的局部变量、进程外看不见。

**为什么不能绕过去**：终止之后只能另起一个 run，而那时 `events.jsonl` 已被截断（每次
foreground 启动都是 `open("w")`）、游标归零、CLI session 要重拉——**那是重启一个新会话冒充续行**，
测不出「同一次对话里的更新」。这条写进了 TEST 的协议表。

## 2. Case 侧（`run_case.py`）

| 改了什么 | 为什么 |
|---|---|
| `after_initial` 从 case.yaml 穿透；**不配就是普通单终点**，既有用例逐字节不变 | 值域只认 `update`，别的写法当场拒绝——不要跑到一半才发现它没生效 |
| 到目标时按它分叉：普通单照旧 break，双检查点单进 `wait_for_resume` | 与等人回话同构：无上限等、每 300 秒出一次声、租约照常续，两个出口（续跑请求 / 宿主收工） |
| `state["cli_session_id"]` 每回合落盘 | 第二段续的是同一次对话，宿主得看得见它还在；断了要当场看得出来，而不是事后从「模型什么都不记得」里倒推 |
| 第一段到目标却没有 session → 终态 `cli_session_lost` | **单独一个名字**，不混进 `no_session_id`（那一条是从头就没拿到） |
| 第二段的终点读 `story-flow.json` 的 `update` 那一笔 | **看契约不看说辞**：模型说「更新完成」之后还可能继续写，而那一笔只有 `update --action close` 能关掉 |
| 新命令 `checkpoint --point` / `resume-update --text [--deliver]` | 快照要在 worker 停着时取（复制前后各取一次目录摘要，不一样就判这次作废、删掉重来）；续跑要先有快照 |
| 退掉 `story-review` 假阶段（常量、`phase_index`、`target_reached` 分支、`closure_facts` 分支、`next_phase` 三元） | 它是 PHASE_ORDER 之外的假终点，凭证是 `/story review` 的处置台账，随那条命令一起退场 |

## 3. 宿主侧（`run_multi_case.py`）

三条命令：`checkpoint`、`promote-checkpoint`、`resume-update`，各自把关一处顺序：

- **回流的是固定下来的快照**，不是还在跑第二段的工作区——拿工作区回流等于把两段混成一份；
- 目的地已有不同内容时不覆盖、两边都留着并报冲突（复用 finalize 的口径）；
- **没回流就不许续跑**：续了的话，第一段的产物就只剩快照里那一份。

`finalize` 对 `after_initial: update` 的 Case 把终态文档落到 `<需求编号>-update`——
原编号那一份是第一段回流的，两段分开才比得出「更新改了什么」。目录名换了不改里面的需求编号。

**两处终态名单对齐**（开工准备 §3.4）：`concluded_by_host` / `cli_session_lost` / `harness_incomplete`
在 Case 侧本来就是终态，宿主侧此前不认——于是 Case 已经收尾、证据齐备，`finalize` 却判它「还活着」
而拒绝回灌。双检查点会让 Case 更常停在这几个态上。

## 4. 配置、协议与度量

- 两个 Case 各加 `after_initial: update` 与 `update_inputs`（04 §3.1 的更新刺激：auto 的 PRD 改版
  200→300；car 的评审人工意见区「撤销宽限改 36 小时」）。**初始那一轮绝不能看见它们**——
  提前铺好的话，「它会不会认出变化」就永远测不到。
- `TEST.md` 新增 §5.9：八步顺序表、每一步「为什么必须在这一步」、等待窗口里只做两件事
  （固定快照、只读评测，不向被测会话发评分与修法）、续不上就说续不上。
- `measure_run.py` 按 `live.jsonl` 里的 `resume_update` 事件切两段，各自出事件数与时长。
  **按时间戳切不按序号切**：两条流各有各的序号，拿一条的序号切另一条，切在哪完全是巧合。
