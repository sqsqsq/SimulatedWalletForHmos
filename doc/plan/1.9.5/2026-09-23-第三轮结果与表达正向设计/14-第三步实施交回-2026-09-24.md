## 2. 章头渲染样例（04 业务方案，skeleton 实际输出前两行）

```
<!-- story-draft:guide 读完这一章，读者要能回答：全部参与系统及各自输入、输出、责任与失败影响；业务结果以谁为准、重要业务规则是什么；每个关键取舍：选了什么、依据是什么；有真实备选时否了什么、为什么不行；全篇的风险：触发条件、影响、已有控制——风险只在这一章成表，别的章不重复（直接回答，不写本章讲什么） -->
<!-- story-draft:guide 别的章负责：执行过程归业务流程，局部规则归功能说明；这里不重复 -->
```

boundary 删去的附言没有丢：「风险只在这一章成表」本来就在业务方案的 `questions` 里（见上）；「后文沿用同名同义」「异常在总览有去向」「必要重现关键数值」分别由术语章读者问题、审查跨章第 ② 问、章级维度「同一件事只在一处完整表述…验收独立判所必需的条件与数值重现也算必要」承接。

## 3. story-write §一留下的每条 ↔ 判据

| §一条目 | 对应的机器核点或审查维度 |
|---|---|
| 面向第一次接触需求的人、按人的理解顺序讲 | 章级维度「第一次接触的人读完能答出『为什么做 / 怎么做 / 哪里会坏 / 怎么算对』」 |
| 标题用真实业务名；编号由 `number` 统一铺 | 章级维度「标题是真实业务名、层级反映真实从属」；编号由登记时重编号与 `check` 章序核（机器） |
| 三章最详细；业务过程与特性功能分开 | 章级维度「业务过程与本特性功能分开说明」 |
| 正常受限与真正异常分开 | 章级维度「正常受限结果与真正异常分开说明」 |
| 单元格不塞成压缩袋 | 章级维度「表达贴合内容」——**这一条对应最弱**：维度没点名单元格，靠审查从「表达贴合内容」读出。它是金样批注 1 的原话，保留；设计者若认为维度该点名或这一条该删，请定 |
| 工程标识落附录；术语表不收空转定义 | 归档件自包含四条红线（`check` 机器核）；术语章读者问题 |
| 只表达已成立的需求与决定 | 读者审查 blocking「还开着的决定被写成已定的方案」 |
| 材料里的图单向 | skeleton 未用图登记（机器）；审查上游图逐张对照 |
