## 实施时一并处理的细节

1. **续行分支也要带 paths**：`cmd_update_inputs` 在有开着的更新时直接返回 `_resume(...)`，那份结果里没有路径。方案说 inputs 与 status「同一形态的 paths」，续行返回也要带上，否则 SKILL 在续行时拿不到 inbox。
2. **adapter 头注两处与日志一处一起改**：`story.js:14、25、231`。
3. **SKILL 命令模板带引号**：paths 是绝对路径，工程或需求目录可能含空格。SKILL 的 fetch 模板写成 `--project-root "<paths.project_root>" --out "<paths.inbox>"`，并注明按当前 shell 引用。
4. **「本次取材是否成功」的依据**：用这一次 adapter 调用 stdout 末行的 `success` 与四态；inputs 的 `upstream` 只用来展示回执时刻，不当作本次取材的证明。这与方案「不新增 epoch」一致，SKILL 里写明即可。
5. **范围外的现状（不在本次改）**：SKILL 里 core 与 adapter 的命令都写死了 `doc/extensions/...`，而扩展目录可以由 `paths.extension_dir` 配置。这对所有 SKILL 命令都成立，不是本次隔离引入的；paths 里也按方案不放扩展目录。方案验证表里的「不同 features_dir、路径含空格」只覆盖需求目录一侧，覆盖得到。
