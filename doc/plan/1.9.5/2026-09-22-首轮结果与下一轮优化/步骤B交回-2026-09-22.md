## 6. 按《步骤B返修评审》修终态块解析边界

改动在 `run_case.py::_report_result`，读法对齐 framework `verifier-subject.ts::parseResultBlock`：
- 用完整的开始/结束标记匹配，恰好一个块才算结果；块外文字不参与解释。
- 字段按行读 `verifier_subject_id` / `verdict` / `blocker_count`。
- subject 须为 64 位小写十六进制；verdict 只取 PASS 或 FAIL；blocker_count 须为非负整数。
- 读报告时出现 OSError 或解码错误，返回 `readable=false` 与原因，不抛异常。

诊断与采纳分开报：`report` 下保留 `present` / `readable` / `valid` 与三个字段值。`report_adopted` 另外要求 `valid=true`、subject 等于当前 subject、PASS、`blocker_count == 0`（整数比较）。块的正则与 update.py 用的是同一个协议；因为 run_case 属于测试域，这里单独写了一份，没有从扩展导入。

**测试**：正例改用合法的 64 位 subject。新增五条：
- 块判 FAIL，块外备注写着 PASS 与 0：终态仍是 FAIL；
- 缺结束标记：无效；
- 有两个块：无效；
- subject 格式不合法：无效；
- 报告读不了：`readable=false`，不抛异常。

以上都不被判为采纳。

**真实需求目录**：结果不变。ISSUE-206 spec 为 true；ISSUE-206 plan 与 AR90006 spec 为 false，三份报告都是 `valid=true`。

**全量测试**：1283 passed / 15 skipped / 0 failed。机制 0 增（`run_case.py` 不计量）。
