# 工作分册 02：引用清点与脚本适配

属于 [总览 P1](00-总览.md#2-三个实施包)，承接范围 #3/#5/#6 和 AC07。先按实际生产者/消费者分类，再修改；目录字符串本身不能决定改法。

## 1. 路径责任表

| 角色 | 目标基点 | 典型消费者 |
|---|---|---|
| 维护开发仓 | 仓根；源码在 extensions，工具在 test | 预算、源码扫描、fixture 取源、宿主装置 |
| demo 消费工程 | 仓根/demo | 发布基线、宿主依赖取用、授权的源码回灌 |
| 隔离消费工程 | 环境变量或显式传入的 workspace | run_case、产品 gate、Framework、知识及需求产物 |

执行扩展源码的单测必须在消费形态中运行：`ext_workspace.DEV_EXT` 暂存当前开发源并只接 yaml 依赖，不能在无消费配置的根 extensions 原地执行后用 fallback 掩盖失败。该帮助器不安装 bridge/入口段、不合成目标 manifest，也不能证明适配正确。P2 完整安装测试走正式安装器；DEV_EXT 的源码枚举届时复用正式规则，仍只承担单测暂存。

清点输出文件×位置×角色×现读/写对象×改法。搜索 test/story、doc/extensions、framework/config、REPO_ROOT/HOST_ROOT、parents[n]、relative_to、快照及回灌目标。业务知识相对路径和 fixture 消费目录形态保持。

## 2. 文件动作

1. run_case.py：调整维护脚本自身 HOST_ROOT 的层数；运行 REPO_ROOT 仍优先使用显式 workspace，缺省消费目标才设为 demo。harness cwd 保持运行根/framework/harness，config 保持运行根/framework.config.json。不能在隔离 workspace 下再加 demo。
2. config/test.yaml：gates.post_check 和 story_build 在 run_case 中按运行根解析，保持 doc/extensions/...；静态源码扫描或取源键才指 extensions。逐键核消费者，不批量替换。
3. run_multi_case.py：修维护根层数，区分 DEMO_ROOT 和每个 Case workspace；复制相对路径按复制源计算，不按维护仓固定根计算。FEATURES_ROOT 固定为维护仓 doc/features，供起跑前归档及产物回流使用；运行期目录仍按 workspace 消费配置解析，输出证据仍在维护仓 output/story。
4. 源码快照和 finalize 回灌：隔离端按消费相对路径记录，需求产物回灌端映射到维护仓 doc/features，源码回灌仍按原授权映射到 demo；冲突比较的前后基线使用同一对象，不把消费路径直接写回维护仓根。保护其他任务修改及已有回灌冲突处理。
5. ext_workspace.py、test_yaml_reader.py、verifier-smoke：维护端取 framework 依赖改为 demo/framework/harness；临时测试目标内仍为 framework/harness。修各自 parents[n]。
6. bootstrap_local_story.py：需求系统与临时 verify 保持；回执与 TEST §0.3 引导在 demo 的隔离副本中试用，避免重建 demo/doc/features。
7. golden_workspace.py 和 fixture builders：源改 extensions，临时目标保留 doc/extensions；不改业务答案。
8. test_mechanism_budget.py：扫描根改 extensions，计量口径保持；安装器可分项列出，合计范围按 test/AGENTS §5。
9. check_failure_modes.py：源码扫描继续接收 --extension-dir；增加明确的 --project-root 消费目标参数（默认 demo），退出无 config 即回退维护根。开发版集成检查显式给 P2 装配的 template；fixture 自检使用 fixture 自己的目标，不能悄悄读 demo。
10. adapt 检查调用：执行 --project-root 所指消费工程中已安装的 adapt-scan，传 --target；--package 与定位保持 R197。A02 包 fixture 使用已安装消费形态，M09 按登记 target 位置解析链接，详见 03。

## 3. 忽略规则

维护缓存与临时工作件统一放 output/scratch；根保留、个人设置、extensions 的适配运行态以及 test/requirement-system 等；demo/.gitignore 承接业务构建、依赖、Framework 状态/报告和需求本地运行态。相对锚定路径与例外同时迁移。根 .gitignore 增加 /doc/features/，该目录保留运行产物不入库语义；根 .gitattributes 保持，对 demo 仍有效。

不复制依赖到版本控制；迁移已有依赖或按既有 package 安装。定向测试所需依赖在测试前具备，不等 P2 才解决。

## 4. 验证

- 清点复扫逐条解释剩余命中；合法 doc/extensions 消费路径应保留，不追求字符串零命中。
- P1 跑实际存在的 yaml/harness/adapt/author-task 相关定向测试；完整 multi-case 装配测试到 P2 接线后执行。
- 覆盖带空格消费工程根、独立 fixture 根、环境指定 workspace、demo 默认目标、原生 features_dir 配置、回灌冲突及错误路径越界；扩展安装位固定 doc/extensions，不再要求自定义 extension_dir。
- checker 的源码检查与消费检查分别有证据；不能把 demo 1.9.7 的通过算作开发 1.9.8 的通过。
- 维护路径识别按路径边界及真实归属，不把 test/ 当无边界子串；合法含相同字符的目录名须通过，真正指向维护资产的路径须失败。G02 与相关测试复用这一判据，不对个别合法名称加豁免。
