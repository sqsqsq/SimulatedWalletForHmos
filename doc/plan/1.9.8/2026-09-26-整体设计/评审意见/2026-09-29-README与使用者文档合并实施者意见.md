## 2. 事实与分析

### 2.1 `test/章节合同说明.md`

- 是 `extensions/skills/story/contracts/story-chapters.json` 的逐键设计来由，78 行。1.9.3 从合同迁出为 `contracts/README.md`，1.9.7 步骤 5a（`ee091b29`）因为对消费模型没有读者而移到测试域。
- 全仓现行文件无人引用，改合同的人找不到它。
- 已与合同不一致：附录一处写「只有……五节」，`structure` 一节写「附录那四节」（合同附录实际 5 节，也没有 `structure.h3`）；首节讲的 `skeleton` 键在合同顶层不存在。
- 删前三核：
  - 唯一性：说明里的规则在交付面都有落点——缺口文件与推荐（`rules/init_analysis.md`、`rules/scope_gate.md`、SKILL）、「不涉及」写法（`phases/story-write.md`、`templates/plan-sections.md`）、编号剥离（`scripts/core/story/document.mjs` 的 `takeAuthorNumber`）、来源括注（`scripts/core/story/language.mjs`）、流程契约 `update` / `proposals` 的格式（写入侧 `scripts/core/flow/decisions.py`、`update.py` 直接构造）。剩下的是设计理由，历史在当时方案与 Git。
  - 读者可达：无人引用。
  - 保护列：不涉及人工填写区或统计口径。

### 2.2 README、使用指南、功能全景是否合并

| 文件 | 现在的内容 | 问题 |
|---|---|---|
| 根 `README.md`（30 行） | 仓定位、目录结构表、导航、新 checkout 依赖恢复 | 结构表与依赖恢复是维护内容，和 AGENTS §0 重复（两份结构表已有差异）；剩下只有导航，没有独立职责 |
| `doc/release/story使用指南.md`（183 行） | 命令、你在哪出现、定范围、评审表态、常见问题、三个保证、安装升级 | 与功能全景在命令能力、安装升级、产物三处重叠；把 `需求交付流程.md` 称为「流程全景」，与「功能全景」撞名 |
| `doc/release/story功能全景.md`（69 行） | 能力表（最近变化版本 / 本版变化）、主要产物、依赖与边界 | 同上；版本列让一份描述现状的文档也要记演进 |

实施者对「是否合并」的分析：两者读者不同——README 的读者是打开本维护仓的人，使用指南的读者是在别的工程里用 `/story` 的开发人员；但本仓维护者的入口已是 AGENTS，README 去掉维护内容后只剩导航，没有独立职责。合并的代价有三：指南里的路径指目标工程里的位置，放在本仓根容易误读；README 变长，维护者要先略过它；分发出去的文件名是 README.md，接收方可能与自己仓的 README 混淆。三者都可用开头一两句说明或分发时改名化解，所以建议合并。

### 2.3 发布说明的格式

- 1.9.0、1.9.1：开头一段产品定位 + 一段「本版重点」+ 一段 Framework 版本与文档链接（链到使用指南、需求交付流程）；然后「本版新增与优化」「功能清单」「主要产物」「依赖与发布范围」。
- 其中只有「依赖与发布范围」的**能力边界**一条是当版特有的信息（如「本版不包含会议转写的专门语义纠偏与结论提取」），与 1.9.2 起的「移交 / 未达成」同性质；产品定位、功能清单、主要产物、其余依赖项是现行说明，归 README。
- 1.9.2 起：开头引用块（收口日期、上一版）→ 本版新增与优化 → 修复 → 退出项 → 验证结果 → 移交/未达成 → 规模。
- 引用使用指南或功能全景的位置（`git grep` 核过）：根 AGENTS §0 与 §7、`doc/release/1.9.8.md` 两处、1.9.0 与 1.9.1 各一处；`需求交付流程.md` 与测试都不引用。

## 3. 方案

### 3.1 README：项目说明，只写当前状态

合并使用指南与功能全景，按当前行为写，不含版本演进信息：

1. 定位：Story Extension 是什么、基于 Framework 3.0.0；一句说明文中路径指目标工程里的位置（本仓对应 `demo/`）。
2. 命令。
3. 你在哪出现、定范围、评审表态。
4. 能力清单（能力 / 实际行为，两列）与主要产物；原指南里重复的产物说明改为引用这里。
5. 常见问题、三个保证。
6. 安装、升级与跨工程复用（原指南第七节与全景安装两行合为一节）。
7. 依赖与边界。
8. 延伸阅读：各版发布说明看变化；`doc/release/需求交付流程.md`（改称「AI 交付流程与演进方向」）；维护者读 `AGENTS.md`。

删除 `doc/release/story使用指南.md` 与 `doc/release/story功能全景.md`，不留转发文件。

### 3.2 发布说明统一只写增量

- **1.9.0、1.9.1**：删去开头的产品定位段与 Framework/文档链接段，改为与后续版本同式的开头引用块（上一版、本版在其上做增量）；保留「本版重点」一句与「本版新增与优化」；删去「功能清单」「主要产物」「依赖与发布范围」三节，其中「能力边界」一条移为「## 已知边界」小节保留原文。
- **1.9.2–1.9.7**：不改。
- **1.9.8**：开头「现行全部能力见功能全景」改为「现行全部能力见仓根 README」；维护变化里「新增功能全景」一条改为「README 承接项目说明与使用指南（只写当前状态），维护内容只在 AGENTS；1.9.0、1.9.1 发布说明整理为只写增量」。

### 3.3 维护内容回 AGENTS

- README 的结构表删掉，AGENTS §0 是唯一来源；「新 checkout 恢复依赖」原样移到 AGENTS §0 后的新小节，§0 里「依赖恢复见 README」改指该小节。
