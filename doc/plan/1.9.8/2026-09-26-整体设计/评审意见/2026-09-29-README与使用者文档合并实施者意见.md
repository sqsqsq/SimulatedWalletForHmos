# README 与使用者文档合并：实施者意见

2026-09-29，维护实施者。交维护设计者定稿，用户确认后实施。

## 1. 用户的问题与决定

用户问：`test/章节合同说明.md` 是干什么的、放得是否合理；根 `README.md`、`doc/release/story使用指南.md`、`doc/release/story功能全景.md` 三者什么关系（「不是说都是问题，而是觉得有不合理或功能重叠、不清晰」）。
听过分析后，用户的决定：

1. 章节合同说明删掉。
2. 功能全景并入使用指南。
3. 用户原话：「当前项目根的 README 跟使用指南的功能定位上，究竟有没有本质区别，是否应该合并。即项目级维护归 AGENTS.md，项目级说明归 README」。实施者判断两者没有本质区别，同意合并。
4. 使用者文档由维护者另行分发给内网使用者（`/story adapt` 不把它们装进目标工程）。

目标：仓根只有两份人读入口——`AGENTS.md` 讲怎么维护，`README.md` 讲这是什么、怎么用、有什么；同一件事只在一处写。

## 2. 事实

### 2.1 `test/章节合同说明.md`

- 是 `extensions/skills/story/contracts/story-chapters.json` 的逐键设计来由，78 行。1.9.3 从合同迁出为 `contracts/README.md`，1.9.7 步骤 5a（`ee091b29`）因为对消费模型没有读者而移到测试域。
- 全仓现行文件无人引用，改合同的人找不到它。
- 已与合同不一致：附录一处写「只有……五节」，`structure` 一节写「附录那四节」（合同附录实际 5 节，也没有 `structure.h3`）；首节讲的 `skeleton` 键在合同顶层不存在。
- 删前三核：
  - 唯一性：说明里的规则在交付面都有落点——缺口文件与推荐（`rules/init_analysis.md`、`rules/scope_gate.md`、SKILL）、「不涉及」写法（`phases/story-write.md`、`templates/plan-sections.md`）、编号剥离（`scripts/core/story/document.mjs` 的 `takeAuthorNumber`）、来源括注（`scripts/core/story/language.mjs`）、流程契约 `update` / `proposals` 的格式（写入侧 `scripts/core/flow/decisions.py`、`update.py` 直接构造）。剩下的是设计理由，历史在当时方案与 Git。
  - 读者可达：无人引用。
  - 保护列：不涉及人工填写区或统计口径。

## 3. 方案

### 3.1 删除 `test/章节合同说明.md`

依据见 2.1 的三核。退出清单记这一项；AGENTS 与 TEST 里没有指向它的条目，不需要改引用。

### 3.2 README 成为项目说明（合并使用指南与功能全景）

新 `README.md` 面向用 `/story` 做需求的开发人员，也是维护者分发的那一份：

1. 定位：Story Extension 是什么、基于 Framework 3.0.0、当前版本（1.9.8 待发布）与本版改动链接。一句说明文中路径指目标工程里的位置（本仓对应 `demo/`）。
2. 命令。
3. 你在哪出现、定范围、评审表态。
4. 能力清单（保留「最近变化版本 / 本版变化」两列）与主要产物；原指南里重复的产物说明改为引用这里。
5. 常见问题、三个保证。
6. 安装、升级与跨工程复用（原指南第七节与全景安装两行合为一节）。
7. 依赖与边界。
8. 延伸阅读：`doc/release/需求交付流程.md`（改称「AI 交付流程与演进方向」）、各版发布说明；维护者读 `AGENTS.md`。

删除 `doc/release/story使用指南.md` 与 `doc/release/story功能全景.md`，不留转发文件。

### 3.3 维护内容回 AGENTS

- README 的结构表删掉，AGENTS §0 是唯一来源；「新 checkout 恢复依赖」原样移到 AGENTS §0 后的新小节，§0 里「依赖恢复见 README」改指该小节。
- AGENTS §0 结构表：`doc/release/` 改为「按版本的发布说明、AI 交付流程说明」；加一行「根 `README.md`：项目说明与使用指南（维护者据此分发）」。
- AGENTS §7 发布步骤：发布提交带 `doc/release/<版本>.md` 与更新后的 README；核「本版增量里使用者可见的每项变化都进了 README 能力清单的最近变化版本 / 本版变化，命令与入口描述一致」。

### 3.4 引用同步

- `doc/release/1.9.8.md` 两处功能全景引用改指 README。
- 历史发布说明 1.9.0、1.9.1 链接使用指南：按 P3 迁移时只改链接、不改正文的做法，改指 `../../README.md`。
