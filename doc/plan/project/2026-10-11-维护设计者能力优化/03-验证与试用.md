## 1. 验证责任与结论层级

主维护会话组织检查和不同会话闭环，汇总证据并逐项限定结论。实际设计会话取得需求和真实工程事实写方案，评审会话据需求、当前方案和证据交意见并保留原件；用户已授权修订后，设计功能按意见修订。参与设计者的自检不称独立评审。

结构用现有文件工具，语义靠模型阅读判断，行为引用实际会话与文件。不给已知历史回放记盲测成功率，不以文本长度、字段存在、提问数或返修次数评价能力。

本轮只改维护指令和方案，不运行 Story 产品全量回归或 CLI；实际产品任务如需运行仍按[TEST](../../../../test/TEST.md)与该任务授权。主会话安排已授权的会话验证，本 Skill 不自带调度器，本步骤不新增脚本、评分框架或持久状态。

## 3. 定向检查

以下是已知风险的定向阅读或最小场景检查，不能冒充未知输入盲测。

| 场景 | 应发生的行为 | 保持的合法情形 |
|---|---|---|
| 方案引用函数，但真实调用还有版本或前置状态 | 核完整合同，补关键决定；缺事实标未知及依赖 | 局部参数组织仍可由实施者决定 |
| 单点正确，登记改变下游下一轮的当前性判断 | 沿生产、登记、再读取核变化与恢复 | 真实输入变化仍能触发必要更新 |
| 实现符合方案，方案只验名称出现而目标要求知识改变设计 | 分别报告符合性和方案、效果缺陷，责任回设计 | 纯索引需求可只验名称和链接 |
| 实现漏字段，方案失败路径又矛盾 | 同轮交可审的方案及实现意见，列受阻检查 | 无运行前置时不编造运行结果 |
| 返修改共同决定，未动消费者仍用旧含义 | 追影响范围，必要时重开原结论并说明原因 | 无关关闭项和有效证据复用 |
| 单独要求评审或后续明确要求修订 | 前者只交意见；后者按设计功能改有效方案 | 当前请求同时授权时可先审后修 |
| 局部检查通过，但完整交付缺用途所需条件或旧能力无人接替 | 核整体结果与保持项，报告缺口和复验 | 不以文风喜好或表格数量强制修改 |
| 指令装好，但实际行为证据未齐 | 结论写已安装、待验证对象及条件 | 不把必要等待归作能力失败 |

检查失败先区分未送达、动作无法执行、理解错误或判断错误，修责任源。合法场景必须保持，不按场景专名叠加例外。实际未出现的异常只能保留定向结论。

## 4. 实际不同会话闭环

本次真实任务是把当前需求与方案同步为用户已确认的新 Skill 方案。设计会话只读取当前请求、适用规则、已安装设计方法与原方案，修改授权的 spec/plan；不读取其他验证会话或评审答案，不改全史分析和产品。

另一评审会话依据需求及实际方案交意见；保持被审原件，不以作者结论当事实，不预读修订答案。已授权的修订会话使用设计方法，核有效意见与事实，将问题回写对应决定和受影响文件，交代未采纳意见及依据。评审意见没有成立问题时如实记录，不能制造缺陷或修改来凑闭环；没有发生的修订行为不写成已验证。

| 观察点 | 要取得的实际证据 |
|---|---|
| 加载与接手 | 会话实际加载哪个方法页、当前目录是否发现 Skill、按给定路径读取与自动触发的区别 |
| 设计交付 | 当前方案足以实施；退出 AGENTS 扩写和 loop 接入；保留历史限制、保护项及未验证状态 |
| 评审边界与质量 | 意见有依据、位置、影响、责任和复验；评审期间被审方案与产品保持 |
| 修订 | 明确授权后转设计；修有效决定和受影响部分，不以补充平行版本保留失效决定 |
| 整体与成本 | 闭环后的完整方案符合目标；耗时、重复阅读或用户补做关键判断仅在可可靠取得时报告 |

证据使用实际会话产物与已有工具结果。简短汇总结论由主维护会话记录在本需求的验证材料；原始运行证据放 `output/story/maintenance-designer-20261011/`，临时材料放 `output/scratch/maintenance-designer-20261011/`，有实际材料才建立。无需新报告模板或状态机制。

设计会话已实际使用主体和设计方法，并看到当前技能目录列出 maintenance-designer；它按指派路径加载，不能据此独立证明所有任务都自动触发。独立评审已按评审方法检查实际交付，无强制返修意见；另一个历史评审会话在未点名 Skill 的任务中从目录选择并使用了评审方法。本次状态更新不是缺陷返修，具体证据及未覆盖分支见实施与验证。
