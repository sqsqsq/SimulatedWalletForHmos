# 批次二：知识进入设计，并由施工实际承接

本批是2.1.0整版产品适配的设计方案，当前只获准编写维护文档，未授产品实施、测试/CLI实跑、demo接入或发布。实施须在总方案规定的启动前提成立后另行开始。

## 1. 交付结果与依据

目标是把“读取知识→理解适用性→改变设计实体→CU和后续落实”闭合，同时退出全激活知识取舍账本。依据为[主Spec](../../../../spec/2.1.0/2026-10-28-2.x适配收敛/00-需求.md) R2、R4、R6、R8—R10及AC4、5、8、11、14；全局接口、退场、预算及验证分别以本产品方案的[参考](../参考)为准。接口调查对象为main `ff111909a20ffa6fb53683f15db7ca420b2ef1f0`，Framework `source_commit=879f1e8b2b398bd6e178f1e1abcbfe2e94958042`；这不等于测试与demo已切换。

前批必须已交回可消费的同根身份、真实来源与蓝图访问，且新Framework组合已按总方案固定。本批不承担同根识别的影子实现。1.9.9有效能力是保持基线，现有2.0.0字段和门禁不是必须保留的目标。

## 3. 组合验收

先用现有隔离装配入口生成真实蓝图输入，再由设计对象产生CU投影，依次验证acceptance、contracts和获准后续消费；测试不得预填本应由生产者生成的关键上下文或投影。组合输入覆盖：相关域有适用和不适用条目、整域无关、实际候选模式、来源换版、多CU共享实体和专属实体、独立Spec/Plan，以及旧PASS与当前必修并存。换合法业务和不同实体位置仍应成立。

确定性验收核真实来源、合法地址、作用域、阶段和状态；独立语义核知识是否真改变设计、角色是否完整、验收是否能辨正误、Story是否仍可独立阅读；正常DSH仅在总方案获准里程碑取证。当前文档不启动任何真实运行，不把构造稿或ID正确当语义通过。
