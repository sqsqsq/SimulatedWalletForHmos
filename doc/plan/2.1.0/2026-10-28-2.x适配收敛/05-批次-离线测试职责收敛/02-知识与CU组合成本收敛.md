# E02 知识与CU组合成本收敛

前置E01的规则职责和接线去向已明确，产品语义/原生合同不变。目的为减少相同前态的多次冻结及每个Markdown变体的原生进程初始化，不能通过伪造原生身份求快。产品预算G0/X0。

## 1. 原生前态按责任分组

test_knowledge_task.py现有make_project、prepare和prepared_project；test_cu_knowledge_chain.py现有ChainCase。利用这些能力调整组与所有权，不增加第二缓存层。每个实际同配置、同蓝图/需求/状态组只真实准备一次，在同一绑定根内顺序执行变体；loadscope把该具体组分到同一个worker，不让相同状态拆成数个具体类各在不同worker重造。

| 必须保留的前态/组合 | 不能被什么代替 |
|---|---|
| 未冻结身份及阶段输入未知，读取不代冻结 | 不能先准备所有阶段再测“未准备” |
| 原生候选→freeze→派生阶段输入 | 不能由手写contracts/冻结回执代替 |
| materialize→候选→freeze及本地edit后的stale | 不能由无本地物化的派生分支代替 |
| 文件需求绑定和实际修改后的stale | 不能与inline绑定共用一份状态 |
| inline需求及错误正文 | 不能通过补一个真实文件掩盖inline责任 |
| 独立Spec/Plan只准备本阶段、完整run接线 | 不能用普通Plan前态证明所有入口 |
| 自定义features_dir | 不能只测默认路径字符串 |
| 真实双CU scope到公共/专属知识、作者及pre_verifier | 不能用字符串前缀假造原生归属 |

这些是现有测试责任，不按宿主×状态×材料做全组合。凡修改原生绑定、蓝图或配置，需要自己的真实状态；只改可变Spec/Plan正文的，按当前同根处理并在finally恢复字节。禁止把冻结/prepared/已登记对象复制到另一个根冒充有效，禁止跨变更复用输出结果。

## 3. 知识任务的具体调整

| 当前组 | 动作与边界 |
|---|---|
| BlueprintAndUnitIdentity | 合法身份、坏ID、缺对象等只读变体在有限Node内调用featureIdentity/readBlueprint/readFeature；保CLI参数/退出码/summary及错误输出的代表例 |
| TheKnowledgeTaskHasSixBlocks | 注册顺序、原文、audience、空/坏登记等矩阵调用真实knowledgeTask，同一有限序列逐变体恢复manifest/知识文件；不是把知识正文mock成结果 |
| RelatedStoryExpressionReachesTheUnit、AdoptedSourcesAreReadThroughOneReader | relatedStories/adoptedSources/readSourceFiles/knowledgeTask实际有限序列核来源/片段/摘要等变体；无冻结依赖就不prepare-scope/freeze |
| TheAuthorTaskBeginsThePhase及pre_verifier、错误无半份stdout | 保真实CLI/钩子接线；作者begin、preview/reviewer不begin不能用函数导入替代 |

每个逻辑动作创建新输入/ctx；native loader按root缓存、ESM按URL缓存，不能在同进程中切换Framework/配置/已导入扩展字节后宣称重新加载成立。该类测试用独立进程。声明“同进程”必须同时保证当前性：发生未被缓存键覆盖的源变化，保原入口进程或改为直接核无缓存的真实规则，不修改产品缓存来让测试方便。

本次专用Node序列只处理明确的测试输入及文件变更，执行完退出；不新增常驻服务、产品入口或通用命令调度协议。原F4六条状态序列及格式矩阵已有成果直接保留，不重复计收益。

## 4. 两种shell与其他真实能力

TheRepairLineRunsAsPrinted保PowerShell和Bash两个独立场景，各自真实apply→取得打印命令→异cwd原样执行→check；空间/中文/单引号、自定义扩展路径和无pycache保持。adapt-scan没有安全可导入接口，不为此改产品或复制私有逻辑。

两个shell用例末尾的commit+再次apply，其“已有合法记录逐字节保持”已由TheUsageRecordIsSetUpByApply.test_an_existing_record_is_kept_byte_for_byte及幂等测试承担，可以退出重复；记录承担者，不能把全部真实shell测试改成字符串断言。收益限少两次apply，不宣称解决全局瓶颈。

usage锁、原子写、真实Git历史和无需求目录统计保现有责任；不因慢就用内存字典替掉Git，不为每个数值断言重演完整业务链。没有明确重复依据的用例保持，不借本轮做任意重构。

## 5. 完成与定向证明

测试代码变更先核每个具体状态的拥有者、实际准备次数、读者和恢复边界；未改变的输出可在同组复用，写过输入后的旧_out缓存退出。合类后仍用原独立预期，不能以新实现输出生成答案。

定向覆盖知识应用、knowledge-task、cu-chain、adapt所有权及变动消费者；只有新故障或实质改动才重复相关定向。每步写独立交回/提交，表明旧类/准备/命令退出及对应真实能力承担者，随后连续E03一次完整验证。未受影响的D08来源/图片/交付修复继续保持，不另发明异常矩阵。
