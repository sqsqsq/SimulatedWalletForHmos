## 当前有效决定

| 决定 | 理由与承担位置 |
|---|---|
| 按原生职责重构，保1.9.9能力和阅读体验 | 已实现/已测不是保留旧机制的理由；产品结果见主Spec，工程合同见参考01 |
| 同根sources共享原件，CU显式消费原文/图 | root ux-reference识别冲突不是必须改Framework的证据；当前原生有辅助来源和显式图片路径，真实消费者仍须验证 |
| 导入时保存来源版本，设计直接消费原生scope | 退出complete/绑定/重复冻结账本，保原件、人答、采用版本及原子写；初次组件归属由原生设计确定 |
| facts与实际实体承担知识，真实取舍进入decision | 常规义务不套全量知识决定；相关知识不能漏，语义完整性与结构检查分责 |
| Story自主业务叙事，Review只处理真实裁决 | 保页面五要素、图文优先级、技术摘要和人工区；不变成蓝图摘要或新增批准清单 |
| 原生当前处置与真实Story审查各负其责 | 旧PASS不遮新必修，无审查员诚实未审，退出waiver；原报告/授权与必要复核保留 |
| 15个独立步骤、4个集中评审批次 | 同一接口生产消费同步切换；每步可核、批内连续，不逐文件等待评审 |
| 全版一个预算包 | G4250/X5840为待批估算，步骤只是分项；旧账/累计和正式开工S不重置 |

上述决定已体现在总方案和步骤正文。来源、知识、审查、变更、安装和计量的保持能力不能由“退场”一句话删除；代码清理必须同时有新承担者与实际验证。
