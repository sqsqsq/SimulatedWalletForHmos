# A02 Framework与DSH隔离接入

## 1. 输入与独立结果

依A01固定的S、N1或经补查的后继发布件、当前`test/config/framework-under-test.json`、`test/fixtures/framework-local/`唯一patch、维护操作§2和TEST§1.2。结果是一次性消费工程装入新原生与本地必要能力，公共接口可以被真实Extension调用；它不证明模型已正确使用。

## 2. 接入设计与操作顺序

1. 固定release_commit、framework_path/tree_oid及RELEASE-MANIFEST的version/source_commit。输入是正式发布件，不能从demo混抽新旧文件。测试配置只指一份来源，发布缓存/材料化身份按现有装配函数处理。
2. 三组定制逐职责重基：OpenCode具名审查员、受控dsh adapter/Preset、专用verifier调用文字。上游已具备同义内容的片段退掉；其余在新文件补回最小文本/声明，不整文件倒退，不改原生逻辑。patch重生成后只保当前配置指向的有效补丁，旧对象经Git/证据追溯。
3. 保本地`dsh`名、`.agents`桥与`.dsh/framework-verifier.patch.yml`显式启动/续跑装载。原生`deepseek-harness`没有等价独审声明且image_input为none，不能直接替换。Preset真实工具/能力与调用说明必须一致，不以只读文字宣称物理隔离已成立。
4. 沿现有`create_workspace_template`、原生UPDATE与Extension安装/entries物化到隔离工程；不写demo。配置去旧demo adapter残留仍按已有装配责任，不让配置名决定产品模式。
5. 适配既有`hooks/shared/framework-access.mjs`等原生桥的真实加载路径/入口变化，保一次调用的原生错误与身份。只为已变化接口改必要访问，不另建代理层。第一笔2.1.0交付源码变更将manifest升2.1.0，版本不是本轮文档先行改。
6. 从实际安装件核原生来源validator、蓝图/CU路径、typed投影、lite-schema、当前处置和扩展字段可消费性；无模型调用。声明存在但实际解析失败时修真实接入，不造占位文件或安装件临时补丁求通过。

## 3. 文件与消费者

测试来源配置、固定补丁、装配脚本必要接线、manifest、Framework访问桥和直接依赖测试同步。维护操作记录实际定制去留；TEST身份/装配入口同步。目标仓外发不携本仓补丁；demo发布版、目标知识、目标无归属文件不碰。

目录探针用1.9.9保留的inbox/RR/SR/AR/assets/.backups加blueprint/CU输入：辅助材料正常忽略、CU被原生解析，真的混入施工产物仍按原生报错。此处不加ux-reference白名单或通用目录忽略开关。

## 4. 验证与退出

复用`test_framework_drift.py`、安装/entries/实际verifier链工作区测试及原生边界定向回归。公开入口在实际新安装件读写，不仅mock返回。因来源/补丁变更，需要第二次从空目录真实原生UPDATE及安装，结果/身份可比较，成本计完整必需离线检查；不复制第一份伪装第二重建。

退旧固定构建在当前配置中的使用、上游已接替的重复补丁及访问桥失效接口；保三组尚未接替的必要能力和历史证据。装配通过不能签独立审查、视觉或DSH效果。旧pipe/沙箱故障不因adapter更新被自动关闭。

交回固定组合、补丁逐项处置、装配与接口证据、未验证能力及累计预算。拟议G120/X100（hooks100/80、prompts20/20）；测试/补丁本身不计量。直接责任通过后连续A03。
