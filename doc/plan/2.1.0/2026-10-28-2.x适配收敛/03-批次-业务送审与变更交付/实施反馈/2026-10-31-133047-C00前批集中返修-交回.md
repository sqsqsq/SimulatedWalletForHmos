## 3. 实施中的事实与判断

1. **R5 的基线判定比 C00 多看一步。** C00 让 `resolveEffectiveDiffBaseline` 的结果可见。实测在没有 `HARNESS_DIFF_BASE_REF` 时，原生返回「工作区基线可得」却不核这里是不是 git 仓库；`implementationFiles` 吞掉比较失败、静默只剩预测。所以 `implementationInputs` 在基线可得时再调一次原生 `diffChangedFilesWithStatus`，比不出来（`executed: false`）就同样记为基线不可得。这样多跑一次 git diff，不自写 Git 枚举。
2. **本机用户主目录是 git 仓库**，临时目录也在它的工作树里，测试造不出「不是 git 仓库」。所以 R5 的缺口用例改用原生的另一条真实路径：基线提交不可达。
3. **R3 的归属判断**只排除 `decision:`/`gap:` 两类地址，用的是原生稳定地址的前缀；其余地址照旧按 CU 设计责任判。
