# 2.1.1 遗留收敛与CLI效果改进需求

2026-11-03。本文根据2.1.0 D批交付、最新CLI评审、1.x真实测试对比及用户Q1 A/Q2 B决定成文。事实、原问题与纠正的定位见[证据分册](01-遗留事项与证据.md)，标准接续见[评价标准变更](../评价标准变更.md)。本Spec不把代码位置、评审建议或候选改法直接变成实施方案。

## 1. 问题、使用者与目标

2.1.0已完成主要适配与离线交回，但正常CLI暴露了合法契约引用被拒、通过迁址和注释绕过检查、独审原件被作者重写、缺核被声明为已核、建议驱动重复全审、语义与知识漏判等问题。1.x对比又显示共同设计迁移后的义务和目标表达保持不足，以及未决重试、接受方数据链、陈旧状态、草稿恢复等长期未闭合关系。当前还有E批未实施、CU真实链未走到、部分验证与记录未收口。

本版目标是让消费模型按正常入口完成两类既有需求，正确使用材料、有效人答和知识，形成可信设计及可评审产物，按真实目标交付或继续施工；维护者能够从固定证据说明哪些问题已关闭、哪些能力保持、哪些尚未验证及成本由何种工作构成。

| 使用者 | 应得到的结果 |
|---|---|
| 需求方 | 有效范围与人答持续生效，正常工程落实不转成人工批准；真正外部取舍和授权变化才交人 |
| 业务评审者 | Story可独立理解目标、页面、条件、异常和未决；Review只承载真实裁决，条件稿不冒充已实现 |
| 设计/CU作者 | 合法来源进入蓝图，知识落到实体，施工单位取得自己的设计、验收、义务和角色，不靠补登记或读checker找绕路 |
| 独立审查者 | 取得当前对象及有效原件，独立判断；本人报告原样交接，格式或覆盖缺口由本人纠正 |
| 维护者 | 实现/语义/行为/成本分层可判，原问题与证据可追，不靠finished、计数0或字段齐宣告完成 |

## 2. 范围、职责与保护

能力基线为正式1.9.9及仍有效用户决定；2.x整体设计归Framework canonical蓝图，Story负责业务表达，Review负责业务裁决，实际CU Spec/Plan分别负责本单位行为验收与实现设计。Framework通用阶段/宿主/投影归上游，Extension负责领域流程、知识消费和自身确定性辅助；知识正文归目标仓，测试域不替消费模型作业务或投放答案。

本版范围覆盖证据分册全部有效遗留：材料/契约与来源、独审交接、知识与CU、业务语义/阅读/人工点、设计证据回流、CLI度量与成本、离线测试职责、已有完整能力保持和维护资料一致性。**记录全部已知事项不等于承诺所有事项都要改产品**：已证结果错误须有处置；原因未定先查实际责任；缺证据保留未覆盖；已关闭事项核保持。

必须保持：

- 1.9.9投料和目录习惯，包括根级inbox、RR/SR/AR、assets、已有备份职责；只保原生蓝图/CU及共享UX真实必需变化，不恢复已撤回的统一sources或双根绑定。
- 原始材料、人答、人工区、稳定采用版本、图片、外部意见、已发生副作用和运行证据；同一新需求内的补料、变化、重入、更新及恢复保持。
- 有界落盘、续写、局部修改；Story必要技术摘要；原生强制蓝图质询与独立业务审查的各自职责；系统与本地权限差异、实际交付集合、读回与冲突保护。
- 合法零CU、合法条件评审稿、明确未审/未覆盖、非阻断建议有据保留、普通完成与发布资格分离。
- 安装/升级的机制、知识和对接所有权；usage真实工作记录、stats只读事实、锁/原子写/Git归属保护。

仅interactive、从当前新需求初始化；不兼容或转换旧在途现场，不增加通用来源仓、影子Framework、审查/调度/状态平台。确需改变已定接口或增加通用机制，后续Plan按项目约定说明必要性、代价、简单替代和授权。本Spec不预批。

## 3. 已定输入与评价边界

### 3.1 Q1 A：真实材料与有效人答优先

金样用于比较业务、阅读、职责和异常处理效果，不自动为当前需求新增外部接口、模拟恢复能力或实现答案。外部契约确实缺失时，可以明确来源、责任方、受影响路径、条件与解除要求，形成诚实条件稿；不编造接口或保证。内部适配错误、数据链漏设计、未读原件或作者改报告不能转称外部依赖豁免。

同一需求内有效授权保持；另一个测试需求/历史轮次的48小时、最小页面、模拟交付等人答不自动继承。具体业务仍以当轮实际送达为准。金样已认可不等于其中每项额外前提已成为本轮输入；业务前提确需变更仍由有权人决定。

### 3.2 Q2 B：继续两组既有业务验收

验收业务继续自动充值和车钥匙，不新增第三个独立需求Case。本版仍要求机制对合法未知题材成立，但实跑结论只覆盖实际输入、宿主、阶段与条件，不宣称已证明未知需求通用性或稳定成功率。定向规则和必要组合检查按真实合同进行，不借“通用性”扩成全组合矩阵。

金样、维护Spec/Plan、评审答案与checker不作为业务输入投放。正常调用业务/阶段工具与通过源码理解隐含判据再改产物分别归因；读源码次数是调查信号，不能单凭次数判作弊，也不能忽略已经发生的迎合检查。

## 4. 完整使用场景

| 场景 | 应得行为与边界 |
|---|---|
| 系统/本地新起单 | 根据真实单据和对接事实取材，材料/人答先于决定到达，系统与本地属性不由通用提示或临时目录猜测 |
| 来源进入设计 | 原件、派生契约、工程事实按真实语义和所有权引用；合法目录/指针可正常消费，坏引用报正确责任，不靠迁址或注释碰检查 |
| 设计到业务送审 | 蓝图形成完整共同设计和知识应用；Story独立表达、Review保裁决；独审原件可验证，实际归档集合与读回一致；零CU合法 |
| 设计到CU Spec/Plan | 实际需要的CU取得自身设计、义务和角色；Spec定行为/验收，Plan落实实体/方法/验证，不重新决定共同设计或用同名文件数代替承接 |
| 条件未定/结果未知 | 区分共同要求、候选方案和未获准动作；明确失败、未知和旧状态不混用；确有外部缺口时只限制受影响路径 |
| 独审与返修 | 独审有真实对象、原始回复及覆盖依据；必要缺陷修正，建议有据处置；格式返修/缺核回原审查责任，无作者重写结论 |
| 新材料/人答/评审回流 | 比较真实变化、保有效决定、修最早真源并同步下游；无变化不无条件全链重做，已有授权不因技术状态变化重问 |
| 中断/归档部分成功/恢复 | 说明已完成副作用和正确续行；原件、备份、人工区、外部意见不丢，重复执行不重发已确认成功动作 |
| 维护与评价 | 正确绑定对象、完整分层判定与成本口径；离线准备不反复为局部反例重演全链，未运行/未核不填通过 |

## 5. 需求

### R1 来源、派生契约与设计证据完整

输入材料版本、设计派生契约和工程事实各有真实身份与用途。引用校验采用该对象的真实协议语义，原生合法契约及其指针在规定需求组织中可进入设计、质询和下游；有效来源保护与坏指针拒绝同时保持。消费模型无需把设计文件搬出需求、插入迎合字符串或手工伪造材料登记来继续。

生成的共同设计和实际引用的必要配套文件在回流/保全后仍可定位、核对和阅读；不是只归档正文便称设计证据完整。必需证据缺失要报告具体对象、影响和恢复责任，不靠未来仍存在的临时workspace充当永久档案。具体保存/解析方式由Plan按现有能力设计。

### R2 独立审查与原件交接可信

派审说明、宿主实际能力和接收协议一致；独立执行体的报告正文从产生到接收、登记及交付保持可追溯原样，外层协议与正文可区分。作者可以向人概述、根据建议修被审产物，不能用概述替代原件或增删审查覆盖/结论。格式错误、漏读或覆盖声明不足由独立审查责任方补正，已有充分判断可按实际对象复用。

接收后字节未变只证明接收后保护，不代替首次原件来源真实性；examined/unreviewed须与实际阅读和能力一致。交接失败不能改成无审查员的合法未审；当前已知必修不能被旧PASS、warn或新摘要掩盖。具备与缺少审查能力的正常分支均诚实披露，不新增免责批准。

### R3 知识形成设计义务并传到实际消费者

相关项目事实、规约、模式在决定前进入正确执行体；模型按实际条件判断适用/不适用/冲突，义务和选中角色按有效蓝图/契约合同落到真正承担实体，保具体责任、来源与验证要求。facts路由、quality叙述、名称清单或target地址存在不单独证明实体义务已形成。

CU基于真实设计引用继承相关判断、共享与专属义务、角色和当前缺口。CU Spec给行为、验收与执行层，CU Plan给实体/方法/存储/调用/角色和验证落实；后续读者使用真实契约，不由作者再补一份同义账本。当前没有CU不得签已传递，也不得据缺文件判能力删除；纯业务送审零CU保持合法。

统计设计按阶段分工：蓝图完成适合业务的指标定义、分子分母/取数责任、结果与获知时机、统计点及已有覆盖/新增判断；Plan承接具体编号、登记文件、责任方法和一次结算。缺现成登记文件不自动构成需人审批的外部缺口。模式可选不同于历史金样，但有候选信号须作有据判断；不要求全激活模式逐项选用。

资源、兼容和环境判断按真正触发条件：新增字符串的体积核算义务、复用图片/图标的层级、本地内存状态的清除/恢复不能仅以“无新位图/不落盘”排除。设计期规定后续测量及承担者，不编造未执行数据。

### R4 未决、未知与生产消费关系真正闭合

业务共同要求与选项专属行为分开。某动作被有效人答要求等待时，正文/图/设计/验收不能借“待定”“不保证成功”“稍后确认”先允许该动作。各选项共同具有的功能可以形成条件评审稿，不因尚未确定验证方式就删除共同功能，也不把条件稿当已实现。

明确失败、结果未知、陈旧状态和不同对象状态分开；重试/新建/撤销等操作须有真实合同支持的前提、身份与恢复依据，不能从网络失败推定远端未完成，或从已有幂等能力推定丢失身份的新请求也能去重。只采用已有能力可支持的路径，外部不足如实列依赖，不强制照搬金样的恢复服务。

端到端关系须落实谁发起、什么身份、从哪进入、数据由谁产生/返回、谁消费、失败后去哪。不能仅因接口/页面/字段名字存在就签接受方补拉、详情数据、状态恢复完整。原材料真实冲突应显式保留取舍，不能静默选择任一边。原问题在作者与独审中重复漏判时记录可靠性差距，机制整改仍须有实际原因依据。

### R5 人读产物保持完整业务与自然表达

业务目标、关键规则、角色协作、页面五要素、正常/受限/失败/未知、验收及必要技术摘要都在适用的人读产物中有可指认表达。来源指针或机器对象不是目标内容本身；共同设计的人读图不把责任边连错，已声明的图必须实际可读，原生current不代签图文完整。

Story保持独立叙事，蓝图承担共同设计；表、图或列表可按关系选择，不能为统一形式删信息。保图＞表格＞列表＞章节＞文字，以及自制关系图的“图前短说明→图→图后补充列表”、自然标题与同节场景分组；不固定十章、图数或字数，不逐箭头复述、不凑补充项，简单清晰的图可不做SVG增强。

改善机械写作口吻、无用跨章重复、裸技术ID及阅读拼接成本；必要局部重述和精确查阅保持。原图身份/位置、图义、实际渲染和模型视觉理解分别取证，无视觉能力时保真实未核，不编造图中文字或把维护者看图当消费模型看过。

### R6 人工决定只承担真实业务与权限取舍

Review不新增无业务依据的技术批准。内部登记取号、正常新代码、原生物化/状态处理、报告格式修正和已授权工作不自动交人二选一；真正业务承诺、外部接口、范围、受保护内容或权限变化才请求决定。缺工程能力若确实改变交付承诺须说明影响；不能把所有新实现都叫承载缺口。

问法、选项与人的原话分别保留，不从模型选项标签扩大人答含义；已有有效授权持续执行。系统单与本地单按真实取材/对接身份处理，不能把通用提示当具体对象事实。建议登记、settled/open与正文之间的技术切换不能制造循环审批；真实未决允许随条件稿送审，人工区不代填。

### R7 观测、度量与结论准确

既有记录应能区分实际作者/设计委派/独立审查、工具失败、业务门禁失败、报告无效、必要返修、重复工作、等待及最终收尾。未识别、缺事件、输出截断或零计数须说明口径和缺失，不能推断“没有失败/没有返工/没有审查”。动作分类不能仅依赖旧工具名称而漏掉实际DSH子会话。

报告绑定源码、配置、标准、输入/人答、终点、原件及干预；原生独审回复、接收报告及声明覆盖可交叉核。全量适用标准逐项分层，不用组级符合掩盖子条件，条款映射正确。未到阶段、缺环境、未读全保持未覆盖；合法不适用需输入事实。真实外部系统与测试替身、普通完成与发布资格分开。

原分数、旧报告与原件保留；重判单独记录新证据和理由，建议分与用户确认分分开。沿既有三轴和90分目标，不新造评分体系或以平均分互补。

### R8 CLI工作成本与审查循环收敛

正常输入先送达，作者能够按公开合同完成工作，不以长期学习checker、改写报告或反复试格式为正常路径。真实缺陷先在责任处集中纠正；非阻断建议有据采纳/保留，改动后按受影响语义与当前对象取得必要复核，不为清空WARN逐条全链重审。

完整首读、独立性、当前性及真实变化核源保持；不设固定审查轮数、跳审白名单或硬时限来取得速度。成本分别报告必要新职责、有效修正、无效循环、读取/上下文、人工等待与外部故障。沿TEST既有期望与调查指标评价，半小时是CLI期望而非本版新增硬门，等待不能全扣给模型，子会话跨度不冒充纯推理时间。

### R9 离线验证职责与成本收敛

承接未实施E批的目标与已调查事实，不将其旧方案自动当本版Plan。局部规则、真实生产消费、装配和模型效果分别承担证据；局部反例不逐次重建完整需求/蓝图，等价前态不无依据重复准备，仍保真实接线、身份、权限、原件和恢复转折。

完整必要离线handback沿120—180秒优化目标，计入实际准备、执行、收尾及触发的独立装配；180秒不是功能门槛，不阻正常开发测试，也不能称超目标即已提效达标。收益来自实际退出的重复工作，不靠删有效断言、暖缓存藏成本、反复全量/扫并发、同对象多池重复或为测试新增产品入口。

未知skip须说明原因、责任与未验证范围；测试通过不代替独审与CLI效果。具体测试组织、预算及触发规则由Plan与现有TEST入口落实，本版不新增runner、缓存/调度框架或第三业务Case。

提效只改测试域：Framework与Extension按各自需求目标实现，不为测试速度整改、不加测试专用入口或导出；产品命令自身的单次成本是测试的既定输入，测试侧减少的是重复准备与经整条命令验证局部规则的次数。

测试可以在一轮测试期间用一个随测试起停的进程内宿主执行产品命令（用户2026-11-04同意），让Framework在每个测试进程里只加载一次；它不是常驻服务，测完即退出，执行的仍是产品自己的命令入口。保真以“同一组用例走CLI与走宿主逐次比对输出”为准，进程边界本身（参数、退出码、输出流、宿主外的环境）留一组真实CLI见证。

### R10 完整能力保持、资料与收口真实

2.1.0已关闭来源版本/图片/批内标签及其它有效修复保留；来源/知识/审查的改动同步实际消费者、状态、入口、安装与专用回归，替换旧路径时保能力和必要保护。update、归档/恢复、安装、usage/stats继续按真实契约，未覆盖不重命名为通过。
