# Framework 协作与验收

依据[目标规格](02-目标规格.md)。源码观察点为 `7753c18f`；实施先以本仓 main 的真实 3.1 同步 story，实际发布件身份与接缝核对结论唯一在[实施总览](../../plan/2.0.0/01-实施总览与协作合同.md)登记。

## 1. 已核能力与限制

上述源码观察中已存在：component-design、原生需求来源物化、蓝图评审投影/反馈、CU identity/resolver、施工输入派生/物化、component-closure、manifest 1.1 与 extension materialize、无 run 的交互阶段执行。

准入需原生蓝图结构及语义约束通过，且 review_summary.admission.status=pass；文件存在或泛化的 checker PASS 不代替这两个条件。完整设计交接另外要求 CU/readiness；Story 交付不要求 CU。

源码观察的 design lens 仅支持 hmos-app。本仓 main=025d1b6b 的 3.1.0/074a4c3c 已同步 story/demo 并通过基线评审；下一步以该接入件核实际接口和送达效果。A/B/C/D 是适配核对项，已有原生能力优先使用，确实不能满足目标的局部差异再由设计者裁定，不是 Framework 基线同步的四项前置。

## 2. 接缝

| 输入 → 消费者 | 合同与失败责任 |
|---|---|
| 确认材料 → component-design | 本地冻结文件或原生 materialization，真实 authority/provenance/原始字节摘要；坏来源回需求侧 |
| 激活知识 → 设计作者/质询者 | 按 A 核定的原生输入方式在动作前送达；直接入口与 Story 路径相同 |
| 有效蓝图 → Story | 指定 revision 的原生投影及 canonical 对象；来源失效回设计，不从 CU 拼权威 |
| 人工意见 → 设计负责方 | 原生 feedback 四类；资格校验与实际接受分开；原话在需求侧保留 |
| 设计 → 施工作者/审查 | 有效 design_refs、原生 acceptance/contracts 及扩展实体；按 C 核定载体验证文件授权和义务保留 |
| Story → 独立审查 | 按 B 核定的实际原生调用取得请求、对象绑定与验真；Extension 负责业务判据及结果消费 |
| 交付请求 → 原生交互开发 | 在已有授权内准备范围和适用阶段，不创建 Goal run，不自建调度 |
| 包 → 消费工程 | 所有权安装后原生物化；按 D 的实际所有权与物化接线在覆盖前展示冲突，保持目标人工工作 |

## 3. 验收矩阵

| 组 | 特性叶节点 | 正常与异常预期 |
|---|---|---|
| V1 来源 | A1–A8 | 系统/本地材料、会议、图及范围形成真实输入；缺料、读取故障、版本冲突分开 |
| V2 成文 | B1–B7 | 一套 Story 讲全业务及有效设计，精确信息可查；零 CU、无新 Spec/Plan 仍成立 |
| V3 人工决定 | C1–C5 | 真实原话与议题对象对应；不代填，变义/过期表态受保护并待确认 |
| V4 设计知识 | D1–D5 | 两类入口在决定前取得原文，判断有据并改变具体设计；空与坏登记分开 |
| V5 施工承接 | D6–D9 | 派生及复用保留实体、角色与验证责任；共享及组合要求不丢失 |
| V6 变化恢复 | E1–E6 | 表达/范围/设计各回责任方；文件冲突保持，原生状态和历史来源不被恢复覆盖 |
| V7 外部交付 | F1–F4 | 交付终点符合授权；失败、远端冲突及恢复准确，本地单无远端动作 |
| V8 续行质量 | G1–G5 | 从当前对象继续，审查对象稳定，未审未测如实；无需用户逐 CU 管理 |
| V9 安装 | H1–H4 | 新装/升级/重复/冲突/缺能力结果确定，目标知识、身份、对接及人工入口保持 |
| V10 组合退出 | 全部 | 上述能力在同一需求组合成立；旧入口、状态及专用测试退出，成本可说明 |

每组继续逐叶节点核，证据分为确定性、独立语义和正常 CLI 行为。字段存在、上游 fixture 或离线 PASS 不独自证明知识生效。

## 4. 实跑边界

沿用现有隔离装配与回流根 `doc/features/`。真实需求上限为 Plan，正常系统单、本地单、update 及冲突场景保留，增加直接设计、无新 Spec/Plan、多 CU 的安排；具体 Case 和启动由用户在里程碑确定。

直接阶段和输入复用应观察真实执行者取得的有效契约，不为凑阶段强制生成新 Spec/Plan。多 CU 要核共享设计和组合义务，无后段运行证据时只证明前段承接。Coding、设备、内网和整体施工单列未验证；Goal 不属于本版验证范围。

具体测试文件、输入/输出、失败副作用及命令由[步骤 4](../../plan/2.0.0/05-步骤4-验证与收口.md)维护。产品上线以前四项接缝都须有真实调用与验证证据；采用现成能力时不要求额外交付同名新增接口。基线接入、局部接线与完整版本分别验收。
