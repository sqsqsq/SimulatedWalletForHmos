# 2.0.3 Extension机制集中收敛需求

2026-11-06。输入为两轮CLI原件、本轮机制分析和用户三项决定：从case现象追机制；Framework问题独立反馈；旧2.1.0/2.1.1更正为2.0.1/2.0.2，本轮后续归2.0.3，先Plan不实施。

## 1. 目标与范围

消费模型面对合法新需求，应从有效事实形成完整共同设计，再按实际接收者产生Story/Review与获准CU阶段成果；作者、确定性辅助、独立质询、业务审查及原生消费者各自完成职责。结构合格、两稿一致、已登记缺口不替代当前义务满足。一次修正在最早责任位置集中完成，减少重复承载、无效返修及从checker反推使用合同的成本。

覆盖本轮已证内容/知识/来源、真实交付、独审交接、阶段续行、观测与目标终点问题；不以case字段、业务名、金样答案或单次错误定义通用机制。不增加新状态框架、通用语义checker、自动报告抽取CLI、调度器、差量审查平台或旧现场兼容。

保持2.0.2有效能力：材料库存与稳定版本、权限/人工区、蓝图唯一共同设计权威、知识实体义务、逐章有界写入、图表表达与同图增强、原生独立质询、独立业务首读、原样报告与严格对象绑定、可选设计参考交付、归档/读回/冲突/恢复、合法零CU、update、adapt与usage。本版仍仅interactive、新初始化需求，独立Spec/Plan设计不等同完整Feature运行；旧测试run不改写/迁移，不默认重跑update、设备、内网或编码。

## 2. 应得到的行为

| 需求 | 触发 | 结果 |
|---|---|---|
| R1 当前设计义务完整 | 原料/人答/知识提出行为或约束 | 有真实设计承担者、生产消费关系、必要条件及失败/未知去向；本端不实施外部动作不等于无需表达其影响；工程无现成封装不自动降低承诺 |
| R2 缺失与不适用分开 | 蓝图缺某类对象/明细 | 按业务与知识判断是否适用；适用未完成回设计责任，不从空投影推N/A、不将本阶段语义整包延期施工；合法不适用和真实外部未决保留 |
| R3 独立阅读与实际查阅 | 形成Story及交付集合 | 正文图表完整说明范围、旅程、条件、责任、恢复、未决和验收；既有附录承接本单必要精确查阅，不能用接收方拿不到的参考代替；非必要技术全文不重复搬运 |
| R4 审查与集中返修有效 | 首审、发现、修订、报告协议缺口 | 质询和业务审查各从有效来源判断；已登记gap或Story与蓝图一致不能掩盖共同漏项；本阶段义务遗漏按影响判断而非降为表达偏好；同根因受影响处一次同步；原报告不由作者重写 |
| R5 独立报告最终身份准确 | 子审查者完成 | 与作者隔离的只读执行体按实际宿主合同产生完整最终回复，调用方原样保存；中途完整消息不等于最终回复；缺完整最终原件诚实未完成，必要元信息或核查缺口由原审查责任方补，不以补格式强制重做全审 |
| R6 设计到CU及最终组合闭合 | 请求独立Spec/Plan，或后段需改共同设计 | 采用真实原生阶段入口，CU实际消费自身设计/义务；不预写所有未来Feature结构。共同设计修订回owner及原生质询准入，Story最终依据同步；阶段完成不冒充Feature/版本完成 |
| R7 事实与成本如实可判 | 宿主中止、未达终点、原件缺失或观测失败 | finished/host_conclude不改变原目标；未跑Spec/Plan、视觉未核、reading unknown分别保留。角色、审查轮次与业务返修按事件归因，未知不填零；保留原记录，不为报表造新观察平台 |
| R8 简单完整与成本收敛 | 修正机制和发布前评价 | 退出冲突说明/重复责任，保持必要能力与原生合同；按实际完整链说明准确性、成本和返工改善，不靠减要求/字数/跳审/删关系求绿 |

统计的指标定义、分子分母/观察窗、取数责任、结果获知与统计点属共同设计；具体编号、登记、方法和一次结算属Plan。请求身份、展示身份、失败/未知/陈旧状态的区分是职责要求，不强制Asset、恢复API或任何金样专有方案。业务/质量义务未取得真实生产者时如实限定受影响路径，不能填推断当外部合同。

### 本轮补充的职责边界

- 来源分类必须保留需要承接的正文与图，不以稿件早/粗或补图目的自动排除有效正文；已导入来源纠类不得改变历史版本的角色与依据含义。协议转写来自有效原件，本地mapping是本部件设计，不能从候选反填来源后自证。
- 蓝图审共同设计及知识/契约真实性；Story审独立业务完整、准确、可读与必要查阅。重复技术审查收缩，但业务源/人答仍独立核，发现上游缺口必须回owner，不能仅因两稿一致放过。
- 复核范围与真实变更影响相称；无可信依据则扩大核查。新对象仍要绑定当前对象的独立结论，不把旧PASS移签；原回复如实区分首次核查、集中复核、复用和未核，不要求模型重复抄录确定性材料库存或取得脚本颁发的局部复核资格。
- 蓝图审查沿Framework原生独立质询及原读者按影响收尾；Story保独立业务阅读，退出自建审查资格/历史通过搜索/重复技术报告机制。必要原件、身份、真实阻断与未审披露保持，脚本不代语义判断。
- 蓝图承担全局知识判断，CU动作取得自己的义务及必要正文；保全局可发现索引、不适用理由和回源入口，避免无差别全文广播。收缩不能隐藏漏判、坏引用、公共通则或审查动作义务。
- 初审的隔离必须在实际消息/读取中成立；前审结论不预置首读，参考区不提前喂入。格式、当前性、原样性和业务判断分别成立，不能互相代签。

## 3. 完成与验收

| 验收 | 必须取得的证据 |
|---|---|
| AC1 义务未丢、N/A有据 | 原输入→共同设计→Story/适用CU及独审核对；合法无统计与已有统计未设计两类输入有不同结果，结构核不代语义 |
| AC2 业务与查阅可独立完成 | 实际Story/Review/选入的参考，从接收方取得后按读者问题和必要精确事实核；图义、图面分别结论 |
| AC3 原样且有效审查 | 实际派审/读取边界、原生最终文本、保存字节、当前报告范围、发现与真实处置；核实际复用依据及必要未核，覆盖声明不能代语义；独审首读与技术质询分责 |
| AC4 CU/最终组合 | 固定Framework上独立阶段的真实投影、作者输入、阶段产物/原生harness及独审结果；最终共同设计与Story绑定一致；未到阶段明确未覆盖 |
| AC5 目标/观测准确 | 现有原事件对照角色/终点/原件状态及度量；宿主停止仍目标未达；CLI二进制/模型/配置身份按实际取得，缺失不猜 |
| AC6 成本与退场 | 官方预算endpoint/invested、退出消费者检查、必要离线结果、获准CLI的工作/等待/返修分项；原始完整能力保持，无新增旁路 |

真实CLI沿既有两业务：auto仍到story:submitted；car仍到phase:plan。输入使用真实材料与有效人答，不新增第三独立业务，不投放维护Spec/Plan/金样或checker答案。候选金样的模拟前提与本轮输入不同处单列，不强制相同类名、字段、CU数或图数。120—180秒仍是离线优化目标，不作功能否决门。本次无新实跑授权，实施后经批次准备与用户里程碑许可再跑。

## 4. 依赖与明确未决

F1原生gap闭包/引用种类不一致需Framework所有者修复并提供可验证发布件，影响含合法gap关联的CU闭合；独立Story改进不受此阻塞。原生设计authority的合法来源表达需设计者与Framework确认，不交执行者猜、不将canonical导入材料伪通过。人读renderer改进是上游建议，不作本仓全部工作的硬前置；最终读者效果仍须达标，达不到不得签完成。本轮已核Q2原生request范围准备、Feature冻结与阶段输入路径，不再把本地未适配归为上游缺interactive能力；真实阶段闭环、DSH组合及终点消费仍待实施验证，不以两份文档代阶段完成。详见[Framework依赖](../../../plan/2.0.3/2026-11-06-机制集中收敛/05-Framework依赖与验证.md)。已有run恢复不纳本版。

## 5. 讨论与决定依据

本轮用户要求从case表象提炼机制、Framework独立反馈；因此本Spec不逐例增规则，案例只作错误与正确结果的证据。用户要求不在极端异常上浪费设计，故只覆盖日常中断、结果未知、真实缺源/返修/消费和已触发原生契约问题，不补理论组合。2026-11-06明确版本更正并把本轮问题归2.0.3；新Spec/Plan不沿用旧G1301授权擅自开工，旧对象、预算累计和评审事实保留。
