# R1 两 Case 金样与质量基线

2026-10-07：原 2.1.0 R1 整项迁入 2.0.3，承接 T7、S1/S2；执行顺序和额度见[总览](../00-版本范围.md)。本需求先定义效果，正式替换由本版 R4 收口；2.0.2 既有装配与正确性修复不重复实施。

## 1. 问题、目标与选择

旧金样集中在早期 Story/Review，跨产物承接及新场景覆盖不足。新整理的 AR90006、ISSUE-206 含两套 Spec/Story/Review 和一份 Plan，但独立审核已发现真实语义与工程缺口。采用它们作为修订基础，可以复用历史探索和表达优点；直接升为正本会把错误变成效果标准。

选择两 Case 共同作为新基线，接替旧 AR90004 等正本的权威地位。AR90006 着重会议、材料更新、未决口径与真实人签；ISSUE-206 着重端云协作、动态权限、状态、恢复及施工承接。不是指定两套固定模板，测试 Case 的专名、数值和答案不进入产品通用规则。

目标是让维护者和评价者能判断正确性、完整性及表达质量，并能从同一依据沿设计、人读交付、必要施工契约核到底。每份示例同时注明适用阶段及完成状态，不能把待决稿宣称为可实施终稿。

## 2. 输入与决定责任

| 输入 | 取得方式与用途 | 权威边界 |
|---|---|---|
| 产品稿、系统设计、会议和评审原件 | 从现有 Case 与历史证据取得，锁采用版本；保留原话、版本和定位 | 材料冲突由真实业务权威解决，不取最新日期或多数快照自动定案 |
| 人工决定 | 核原回复及其问题、选项和当时材料；区分已被替代与当前有效 | decisions/factbase 中“用户选了”不是独立证据 |
| 目标代码、配置、知识 | 按选定工程基线核实际定义、调用、导出与接入位置 | 工程没有现成能力不等于可以缩小业务目标 |
| 新整理的七份候选与分析档案 | 从[历史参考](../../2.1.0/历史参考/README.md)定位表达与问题线索 | 模型写作物，未跑生产门禁；示范回填不是本 Case 人签 |
| 2.x 合同与生产入口 | 使用验收后的 Framework/Extension 组合 | 原生蓝图和 CU 权威保持，退出旧知识登记与固定章号依赖 |

业务事实及范围由需求权威决定；金样修订者取证、组织和同步；独立审查者核内容；用户审定金样的效果和语义变化；测试维护者负责装配及覆盖迁移。消费模型在正常工程中只取得产品输入，不取得金样、分析报告或隐藏判据。

事实基线作为来源整理索引，不把“金样写作唯一真源”解释为有权改业务。数据沿既有蓝图和产物合同传递，不再额外建立权威业务数据库。

### 2.1 本版采用基线与情景

输入锁到 `15844e09ba1bce07b2ca158adfd63df399cd90be` 的 `test/cases/auto-topup`（tree `6e613a746a2fe92c4f42343aacf5a944383aa18a`）、`test/cases/car-key-sharing`（tree `4cc39a7bac711d8e2f9c4cb43af38cb9f445ca0c`），采用各目录 case.yaml 指向的 system/workspace、supplements、update_inputs。工程取同提交 demo（tree `6d74bb0b925b45f7e57ee81fe329ea9f9df03a2c`），知识以该提交 extensions/knowledge（tree `0f329be35b34a1af3d428f38d7863a5e7a80eede`）为本版起点；有效后续修正单列真实 diff 与理由，再固定新摘要，不随工作区静默漂移。

历史七份候选是表达参考；10-03 suite 的原始会话/输入/产物用于核已发生人签与缺陷，不将最终错稿反向当需求权威。最初采纳表含原件路径/字节摘要、实际贡献及人签来源，沿已有材料/决定结构保存，不新增权威数据库。

| 情景 | 必交产物 | 正确终点与未定边界 |
|---|---|---|
| 自动充值 initial | 原始采用/人签索引、蓝图和原生投影、Story/Review/设计附件 | 系统送审，零 CU 合法；D3/D4 等未获裁定行为保留未决，不强做 Spec/Plan |
| 自动充值 update | 同一需求新冻结输入、实际反馈/裁决、修订后的三件及受影响设计 | 承接既有 update_inputs，先确认 200/300 冲突与人意见，再完成更新交付；未取得实际裁决则只交待裁定候选 |
| 车钥匙 reviewable | 原始采用索引、蓝图/投影、Story/Review/设计附件 | 需求级完整评审；撤销期限/承载策略未定时不伪称 Plan 可执行 |
| 车钥匙 plan-ready 与 update | 在真实裁决支持的 CU 中交必要 Spec/acceptance、Plan/contracts/use-cases、三件及有效引用；update 同步真实意见与影响 | 原生认可的适用 Spec/Plan 或合法复用，止于 Plan；现有 update 36 小时意见与车辆侧即时拒绝冲突须真实澄清 |

请求中尚无的真实确认不是设计者可以预设的业务答案。P1 可先完成 reviewable 候选和不受影响内容；plan-ready 缺输入单列负责人/问题/影响对象，取得原始授权后再生成。人审定金样形态不替代业务裁决，脚本预设立场也不冒充历史已发生人签。本版整体签收仍需两个 Case 的相应授权终点证据，不能以正确停等替代 Plan 完成。

## 3. 修订与 2.x 组织

先执行[审核问题与修订合同](审核问题与修订合同.md)的 G01–G09，再沿其他有效业务关系检查，不能只修列出的样例句子。相同事实和决定的所有落点一并同步。

每个 Case 建立采用材料→有效决定→蓝图事实/对象→Story/Review→实际 CU 及必要 Spec/Plan/契约的关系。整体规约判断和模式选型归蓝图，施工产物落实范围内义务。补齐真实设计与测试输入，不要求两个 Case 都硬造同样数量的 CU 或每类文档；请求包含 Plan 的场景须有可验证施工输入。

保留两种情景，明确不同预期：

- **仍有待决**：正文只陈述已知部分、建议和影响边界，图表、验收、施工不暗选方案；原生准入/交付是否受阻由该缺口实际影响决定，不为过门补确认。
- **具备定案输入**：以真实可追溯的确认输入形成有效设计和产物，按当前生产入口完成正向验证。缺确认时请求相应权威补齐；示范人签不能填这个缺口。

同一稿不能一处待决、一处已采用、一处已验收。明确的既有业务决定应正确承接，不能为展示更多 open 议题重新打开已经定案的范围。

## 4. 效果定义

| 对象 | 基线应展示什么 |
|---|---|
| 业务事实与决定 | 来源可定位、冲突有真实处置、建议与定案分开；同一事实跨产物一致 |
| 内容完整性 | 有效范围内的正常/异常/恢复、条件、责任、依赖及验收有实际落点，不靠编号齐全代替内容 |
| 结构与表达 | 同类信息组织稳定；表格能比较，图讲关系，正文解释条件与后果；推荐形态允许有理由地调整 |
| 工程可落地性 | 真实输入输出接得上；身份未因脱敏丢失；页面与依赖有接入动作；文件和验证职责完整 |
| 待决与交付状态 | 读者能判断哪些可继续、哪些等谁决定；局部模拟结果不等于真实联调通过 |

金样只定义效果，通用规则落入现有产品合同并由本版 R2/R3 消费；本分册不复制该合同的逐条正文。字节级渲染回归只验证确定性渲染，不取代语义和效果评价。

## 5. 替换合同与过渡

未来正式效果正本仍唯一放在 `test/golden/`，按 Case 组织；原始输入和知识快照由 `test/fixtures/golden/` 承担，不能保存第二份可编辑效果正文。当前 spec 内历史稿作为不可变探索证据保留，不成为另一套现行正本。

必须一并迁移：golden_workspace 的输入装配、金样文件枚举与指纹、Story 生产检查、Review 决定渲染、Story 编号/固定点回归、唯一副本检查及其他实际引用。已知消费者包括 `test_golden_sample.py`、`test_review_golden.py`、`test_review_modes.py`、`test_story_build.py`、`test_run_measurement.py`，实施时再次全仓核消费者，不能止于改文件名。

旧金样独有的有效场景逐项记承接去向：两 Case 已覆盖则引用相应场景，确有差异则保留小型专项输入与断言。失效形态、旧内容与专用断言退出，有效业务覆盖不随旧文件删除。

步骤 1 至步骤 4 之间，现有生产回归继续读旧正本，修订稿仅用于审定和新装配验证；它们的消费者不同，不将二者都称为现行基线。退出条件是用户审定修订稿、对应生产验证通过、消费者及旧覆盖完成迁移；R4 一次切换正本并撤下被替代内容。

## 6. 验收与失败处理

G01–G09 每项有来源、修订后的各处落点及复核结果；其余章节沿同一事实链审查。内容通过不能用“金样与 factbase 一致”自证，仍须回原件和工程。

两 Case 分别验证待决和定案状态、实际生产检查、机器投影与 Review 渲染；独立评价内容和表达；用相关异常及不同合法输入核通用能力，防止只服务样例。使用本版 R4 的统一证据口径。

源材料缺失、人签未核、原生能力阻塞或规则冲突时报告具体缺口，保持原始材料；由来源、业务、Framework、Extension 或测试装配的责任方处理，不删事实、不放宽要求取得通过。本轮只是规定修订和替换合同，未修改任何金样正文。
