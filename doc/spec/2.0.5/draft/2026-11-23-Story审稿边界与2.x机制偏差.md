> 历史调查记录。下文的“未定”对应当次问答时点；最新决定见[2.0.6 职责纠偏与基线承接](../../2.0.6/draft/2026-11-23-职责纠偏与2.0.5基线承接.md)。

本页保存事实、已定决定与未决。设计者据此提交的[职责纠偏方案（供人审查）](2026-11-23-Extension职责纠偏方案-供人审查.md)逐项给出建议、旧做法的退出条件与复验场景。

2026-11-23，维护设计者记录本轮 ask。审查对象为当前开发版 2.0.5，提交 `ed94a942`、Extension 树 `2fa9e13f`，发布评价口径读工作区 @33。正式 1.x 对照为 `b4fbf433`（1.9.9）。旧 2.x 同号版本单独标明。本稿记录用户裁定和已查到的问题，版本归属与施工排期另定。[历版调查及逐项来源](../../../project/2026-11-23-历版功能来源与待裁定清单.md) · [版本谱系](../../../archive/README.md)

## 本轮已定和未定

| 事项 | 用户决定及可判断的结果 |
|---|---|
| 蓝图与 Story | 用户原话：“story的审查，应该是看基于story的写作逻辑，审查它的内容跟已定事实或设计目标是否有偏差。”主 agent 完成蓝图设计和问询，再据有效设计成文。Story 审业务表达是否完整、自洽、可理解，能否忠实传递事实、授权、目标、异常与验收。有需要可回看原话。普遍寻找蓝图遗漏和重做设计问询归蓝图侧优化。偶遇实际冲突要指明依据，交设计负责方处置。 |
| 知识怎样传递（B3） | 用户选择“按本次决定给材料”。例如蓝图已确定某规约适用，Plan 收到已定义务、承担对象和可回查出处；需要解释条款、选型或判断冲突时，再给相关原文。 |
| 怎样记录不适用（B4） | 用户选择“同一理由合写”。仍能查到覆盖了哪几条，例外、冲突、待定分别写。现行相关域逐项覆盖有防漏价值；需要区分机器追踪每条去向与让作者重复写同一理由。[蓝图作者要求](../../../../extensions/hooks/blueprint/author.md) |
| 维护与交付（B6） | 用户原话：“为了防止过拟合等问题，应该是排查并清理，但不是在Extension的交付内容中，构建一个主动排除的能力。”维护时用历史误收样本与合法新输入检查规则；产品按业务对象、有效职责位置和真实契约识别本期内容。答复没有指定列名语法，也没有取消本期埋点到责任方法的检查。 |
| 怎样接报告（B1） | 用户选择“读取报告原件”。前提是有独立读者，且宿主能确认本轮读者已完成、指定文件是它写成的完整原件。宿主能否在当前链上可靠提供凭据仍待取证；文件存在或接收后的摘要相等只证明局部事实。此选择没有批准新增审查员或第二轮质询。 |
| 专项详情（B5） | 用户追问 Extension 如何与蓝图重叠。核读现行入口后，设计者撤回“是否每项再写一份”的提问。已有等价原生字段就写在那里；精确内容放不下时扩进同一蓝图。发现下游确实强索第二份时，再以实例归因。[蓝图作者入口](../../../../extensions/hooks/blueprint/author.md) |
| 未决 | 成文检查是否需要独立模型、由哪个现有入口承担；首读材料如何送（B2）、局部改稿复核范围（B9）、交付附件和中转副本各应留多少（B7、B8）仍未得到本轮裁定。冻结提示、升级指路、安装核验（B10—B12）也未表决。用户追问职责时没有选择保留或删除这些机制。 |

例如蓝图定了“失败可人工受理”，Story 写成“自动拒绝”，或正文与验收相反，作者直接改稿。若表述准确却读不出谁来受理、什么条件下可重试，仍属写作质量。若有效蓝图自身给出相互排斥的结论，记录冲突出处，回蓝图解决，随后同步受影响段落。这三个结果足以分开审稿、改稿和改设计。

## 为什么 1.x 看起来符合，而 2.x 多出一次审查

| 版本与证据 | 实际行为与决定来源 |
|---|---|
| 正式 1.9.9，`git show b4fbf433:extensions/skills/story/phases/spec.md` §二；同版本 `extensions/rules/spec-rules.overlay.yaml` | 主 agent 先定 Spec 和决定登记，再成文、登记，最后由 Spec 阶段 verifier 对同批产物审查。它既查 Story 是否忠实、好读，也可把源头错误退回 Spec、验收或决定登记。当时的成文页还允许把新形成的判断登记在决定表。因此“先设计再写、错误回源”相符；“1.x 的 verifier 只看文字”与原件不符。正式 1.9.9 的一次初段实跑中，auto 调一次 Spec verifier，car 各调一次 Spec、Plan verifier。[当时运行评审](../../../plan/1.9.9/2026-10-24-发布前问题收敛/评审意见/2026-10-25-初段CLI完整评审.md) |

## 版本与验收边界
