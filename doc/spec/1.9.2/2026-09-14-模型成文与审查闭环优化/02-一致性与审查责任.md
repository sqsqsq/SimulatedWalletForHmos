# 步骤2：按整篇设计成文，从原材料核实际结果

01通过后实施，统一修改作者、审查、恢复及直接消费者后交回。本步不重新定义template协议。恢复完整模型职责，不将写作或审查改成逐字段程序执行。

## 1. 模型真正使用整篇设计

替换story-write.md“写一章”与nextSteps：作者先读template主线/本章安排、相关原材料与已有正文，回答本章要增加什么独有解释，再写当前章。已经成立的决定沿用，不在每章重判同一业务。范围章讲责任边界，方案讲机制/选择，流程讲跨能力关系，功能讲能力内部行为；不是强制每句话唯一出现，验收独立判断所需条件及数值允许重现。

写作中发现新关系或更合适表达：不改变业务结论时直接更新相关template安排/结构与草稿，继续写，不加人签。改变业务规则或发现来源矛盾时回Spec/decisions，template只引用当前结论。未决可保留为明确边界，但依赖它的行为不能同时被肯定为已定；一个open并不自动阻断所有其它内容。

图从需要解释的关系出发：上游图可直接用、合并或改画，保留当前来源身份；总览覆盖主线与关键分支去向，复杂局部在对应节展开并接回主线。不能因为上游只有简单图就把“复制成功”当完成，也不因另画了图就省掉原义务。图讲关系、表讲属性、文字讲理由；无页面业务按对象/调用方/作业/数据生命周期表达，无需拟造UI。

## 2. 实际整稿替换旧自查路线

十章齐后，原nextSteps给当前全文、template、Spec/decisions及初筛原文位置，仍只有短行动指令，方法在story-write一处。模型完成三项工作：

1. **从来源核实际覆盖**：初筛和template所识别的真实义务是否在成品有可读解释，原材料中是否还有二者漏掉的有效内容；不能拿模板当答案或全量来源替身。
2. **推演关系及决定**：当前承诺的行为从前置、交接到结果是否成立，取消/失败/结果未知如何继续；动作需要的契约/数据是否在Spec，未决是否被写成确定承诺。只推演实际适用路径，不给所有业务套同一异常清单。
3. **核组织和表达**：主线是否仍适合，跨章是否互补，图前声明与图实际表达是否相符，条件/单位/例外/状态重组后是否保留。合并无独有用途的完整复述，必要重现保留。

修最早出错的来源和受影响产物：业务结论改Spec/decisions，解释安排改template，正文改相应草稿后chapter提交。原始材料不由作者修改来迎合成品。没有问题可以不改，不造“已核对”字段或改动配额，不重建copyedit。

删除现有“最后统稿把所有问题补回来”“逐字重复就删除”“没有被否备选就不算决策”等仍冲突的实际消费者；有真实选择才解释备选，唯一合理路径也可直接写依据。标题由当前业务关系决定，不能以金样节名/图数为标准。

## 3. 独立审查对象与责任

rules/spec-rules.overlay.yaml::story_reader_review是唯一方法真源。readerReviewTask正常fragment提供当前Story全文一次、template全文一次（先以已有安全围栏包装，保持原文）、Spec/decisions/范围与原材料路径、图片身份。独立review-task仍通过withMethod取得同一方法，不重复维护另一份正文。缺template或原件明确报缺口，不能以空串或新模板假装审了本次设计。

template是**待核查的作者判断**：verifier先根据原材料/范围/Spec独立判断完整性，再用template定位作者的解释安排与取舍，最后核实际Story；不能只问“是否照模板写”。不让模板的遗漏自动成为不在范围；不能用作者写了理由就免审理由。

严重性按读者任务定义，不以章节/图/人数配额：

| 情形 | 结论 |
|---|---|
| 已确认事实反转、未决方案冒充已定、核心动作无必要契约且未披露限制、同ID异义影响下游 | blocking，定位来源和后果，当前阶段修正 |
| 图声称覆盖关键关系但缺去向，且其它正文没有让整个过程真正成立 | blocking，不以“已提到”代替闭合 |
| 图/表/文分工不同但整体解释完整，或与template建议/金样不同 | 可通过，核依据，不机械处罚偏离模板 |
| 可读且不影响正确性/可执行性的标题或措辞偏好 | advisory，不因偏好强迫返修 |
| 真实待决清楚，相关行为未声称已实现且文档用途允许待审 | 可交人审，不把所有open一律当失败 |
| 原件/视觉能力缺席使相关判断无法进行 | 说明未验证及影响，不编造已读/已验真 |

原生报告schema、summary取reviewVerdict、receipt及交付门保持。审查后修改仍按既有新对象重验路径，不新增第二审查角色，不定固定审查次数；重复问题不收敛交维护层分析，不无限撞门。

## 4. AC一致性与知识交接

正文、template、Spec和acceptance具有不同用途：不另建业务事实源。知识要求仍先进入Spec设计，然后由现有投影和验收义务传递；模型需区分临时选择草稿与已生效状态等不同数据对象，不能仅因名字近似合并。该判断归模型，不增加业务关键词断言。

Framework外部依赖：消费仓check-spec.ts中checkFeatureToAcceptance/checkAcceptanceToFeature与utils/check-acceptance.ts各校一侧；扩展现有traceability职责校验同AC ID的功能关联一致、P0/P1在YAML有覆盖，复用acceptance-layering.ts的feature根路径。合法一对多关联按当前原生schema归一，不比较描述字符串相似度，不规定编号必须是数字。

输出沿现有harness判据，点明Spec与acceptance两个来源/ID；缺文件及坏类型归已有错误，不重复一套。测试涵盖同ID错功能、漏P0、合法一对多/顺序变化、合法无关P2、解析失败。仅语义同义与验收是否可执行仍由模型判，不交给字符串近似。

由有权限的Framework源仓实施者完成并正式发布集成；上游位置/版本未知须明确，不在本仓framework/就地改，也不在extension临时复制检查。依赖未完成时作者保持原始ID、verifier对发现漂移当前阻断，不能写notes留给plan；这是临时人工责任，不算机械要求已验收。若上游能力无法取得，需用户裁定范围，而不是隐去验收。

NFR无权威数值时不编造。当前nfr_quantified遇到DFX基线待补的适用性问题同交上游：缺真实量化义务、还是已有义务未落实，要区分处理，不让消费模型填任意秒数过门。此项不扩展为性能评测框架。

## 5. 语言与恢复的原位替换

language.mjs/clientVocabulary、story-chapters语言数据与author替词说明一起退出“回滚/回退单独出现即发布错误”的词义否决，合法订单/数据/状态恢复无需换词。仓内路径、真实标识、引用等确定边界保持；客户端是否描述不存在的服务器动作，由原语义审查看实际对象，不能叠案例豁免句。

flow/routing.py与rounds.py的reopen接续说明消费现有状态和材料事实：原范围/候选仍有效时明确先complete再story，材料变化则走原round/范围路径，不跳过人签。skeleton负责读取当前template，不在Python重做模板结构检查或起Node查询。成文登记对template使用原指纹，重开后允许同步更新；不存在template时回当前设计任务，不重写已有正确正文。

重开状态已经写入后，读取材料/计算下一步失败不再把整个reopen报成未成功；明确已重开、给材料修复与status恢复出口。save本身失败仍失败，不新增台账，也不把材料读取变成阻碍合法重开的新前置。此项0eb0aa5a已复审通过；依赖、预算及下一步以 [步骤2当前评审](步骤2评审-2026-09-14.md) 为准。

## 6. 同包退出与验证

替换旧作者“仅凭章节骨架开始写”及旧整稿方法、overlay宽松/配额说明、模糊词义机械否决和误导恢复指令。保留全部已正确的保护代码；readiness状态、逐单元台账和自评证书不增加。

两个审查入口核同源方法与当前对象；临时改template/Story，实际任务输出跟随；原材料与template矛盾时不能通过指令把模板设为真源。作者选了另一种有依据的组织应合法，不能把模板变成固定标准。

离线在隔离副本验证reopen/complete/story前提、template冻结与重开、缺原件、错误结构、合法恢复词义；不在主业务目录改产物造证据。Framework依赖证据单独交回。相关测试通过后一次交回本步，再由04真实模型观察“是否读到、理解并执行”。
