# 2.5.0 评价标准变更准备

2026-10-27。依据[版本范围](00-版本范围.md)、[lite 需求](2026-10-27-lite轻量开发/00-需求.md)和[review 需求](2026-10-27-review增强与能力吸收/00-需求.md)。当前只记录标准影响和验收准备，不启用新的产品判据或预置通过结论。

## 1. 当前标准与产品边界

[Extension 全量标准](../../../test/regression/extension-acceptance.md)当前为 extension-acceptance@19，服务 2.0.0。方法按 [TEST §6.5](../../../test/TEST.md#65-维护标准与评审)。本版涉及 Framework、Extension 和业务定制，不能将 Extension 标准的通过当作整个编码框架或所有平台的通过。

本版尚未固定实施构建、标准修订或预算。进入设计与实施前分别明确 Framework 责任的上游验收、Extension 增量/保持条目及组合行为证据；复用已有效标准，新增或改变的效果先修标准再实现。标准正文保持单一来源，本文件只登记版本采用与增量，不另复制完整标准。

## 2. 目标与证据准备

| 目标 | 已有参考及待核范围 | 所需证据 |
|---|---|---|
| lite 单任务效率与人工负担 | 本版 LA1；Extension G1/G5 仅覆盖其适用部分 | 可比输入、终点、环境、人工介入、执行/等待与返工；不以并行吞吐、文档数量或一小时阈值代判 |
| lite 必要设计和验证 | LA2—LA6；Framework 既有设计、编译、UT、testing、review 完成合同 | 最小交付足够审核合入，适用与未执行分开；真实工具与内网组合证据，不以生成代码即完成 |
| 独立 review 和修复交接 | RA1—RA4；Framework code-review 与 request 现有合同 | 无完整开发资料的真实检视、授权边界、修改后复核及 committer 可用结论；不以 checker 结构通过代语义 |
| 业务规则与三层协作 | RA5—RA6；Extension D/G/H 相关职责按实际消费者核 | 业务内容独立维护、正常入口实际消费、原有能力保持；登记、调用和效果分别证明 |
| 内网反馈诊断与 Skill 吸收 | RA7—RA8 为方向，完整终点待 review §8 定案 | 对应原发现/反馈/Skill 与真实代码依据，改进归属和适用范围；若含应用，需正常入口证明收益，原件不外传 |

不引入逐模型矩阵、固定问题数量、任意 Skill 通用接入承诺或新增评分平台。跨平台按实际具备的能力分批验证，未就绪部分如实列出。

## 3. 开工前需要完成

1. 固定采用的 Framework、Extension、平台和标准身份，核现有独立能力及上游变动，避免重复建设或复活旧 lite。
2. 对已确认目标建立可区分正确、错误和合法差异的判法；吸收入口、自动应用和多来源冲突等未决先定其影响范围。
3. 明确目标与保持集合、跨产品消费者、失效证据和验证入口。没有固定发布基线前不预签全部兼容。
4. 按本仓规则完成必要复核及预算设计后再实施；CLI、内网试用、发布和提交依实际授权，不由 Spec 自动触发。

本次结果仅为需求与标准影响记录。未修改现行标准正文，未运行产品 CLI、设备验证或对内网 Skill 作实际评价，未取得独立评审结论。
