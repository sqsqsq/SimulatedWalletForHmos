## 2. 需要收敛的共同问题

以下是由多份材料支持的分析方向，不将其视为所有问题的统一原因。最终归因必须回到2.1收工原件和实际消费者。

| 观察 | 可能积累的补丁问题 | 最终需要证明什么 |
|---|---|---|
| 蓝图已成为设计真源，旧提取/冻结/绑定仍曾承担流程前置 | 同一事实被多层表示，作者花力气满足登记而不是完成设计 | 必要版本/来源保护由明确承担者完成；无重复语义交接和独立同义状态 |
| 知识由独立决定ID桥接改为事实与实体义务 | 生产者先换，审查、后续阶段或投影仍读旧字段；形式匹配掩盖未应用 | 正确知识在设计前送达，实际实体落实，CU和后段按真实责任消费 |
| 章节身份、展示标题和顺序分离 | 首次骨架可用，已有稿修改仍依赖旧标题/物理位置 | 相同职责在改名、重排、局部修订及审查/登记后仍正确，人工内容不丢 |
| 固定三件交付改为实际集合，恢复扩到部分成功 | 写远端、回执、fetch、登记及恢复分别持有片段事实 | 实际副作用与备份关联不被刷新抹除，必需项与真实读回贯穿下游 |
| 原生准入、历史闭环、当前处置及发布条件逐步分开 | 局部PASS被读为整体可继续，或未来施工缺口阻断业务送审 | 每项结论只承担自己的范围，既有授权延续，受阻只限制真实依赖 |
| 分批返修不断修改作者要求、审查任务和错误提示 | 旧规则未退、信息顺序冲突、作者与审查者重复取证 | 维护者能从完整正常链说明每次输入和审查用途，首读隔离与核源均有效 |
| 完整离线绿测后仍发现消费者漏接，测试复用准备有顺序风险 | 局部规则和真正生产消费混淆，暖缓存或多池重复掩盖冷启动与成本 | 测试层次及前态真实可靠，适用转折有验证，成本与质量分别成立 |
| 目标稿、历史金样、当前生成稿和标准各轮演进 | 以实现为目标改金样、以金样为答案改机制、以绿测为由改标准 | 四类成果共同对应有效需求，目标与实际、合法差异与错误分别判断 |

其中“合同改变后消费者或验证未一起切换”在章组织、恢复和知识传递中有具体记录，值得跨链核查；仍不能仅凭共同外观认定同因。已确认的目录回调属于设计取舍纠正，与执行者没有照Plan实施是不同责任。

## 3. 收敛的分析顺序

1. 以有效用户目标和能力建立完整正常链，核系统/本地、纯送审/CU、首次/变化/恢复的真实差异，避免从旧目录和状态名开始拼补丁。
2. 取得2.1最终结果，按输入、送达、理解/决定、产物、下游、恢复和证据还原。将设计不足、实现偏离、宿主/装置限制、执行偏离、合法差异与未知分开；未达终点不自动证明前段失败，产物错误也不能归咎环境而不核内容。
3. 对历轮改动核最终承担者，检查源端到直接及后续消费者、入口、配置、说明、验证是否一致；已关闭且保持的事项复用，不按历史问题数重开任务。
4. 形成最终职责设计、保留/替换/退出及外部依赖，推演正常和关键转折，再核预算与验证。具体函数、数据形状、步骤批次由Plan确定。
5. 按最终目标核金样和标准，保四类成果相互一致但证据独立；不能先把生成稿定为正本，再寻找能使其通过的判据。

分析记录使用本需求/后续Plan的现有章节和引用，不新建状态系统、补丁分类引擎或通用审计工具。历史包的预算和原问题轮次保留；本版新的实施预算须按真实工作面单独确定，不由旧预算余额推定获准。

## 4. 2.1收工后必须补足的输入

| 输入 | 取得方式与责任 | 缺失影响 |
|---|---|---|
| 最终源码、在途内容、Framework/patch和标准身份 | 设计者从2.1最终交回和实际Git/文件核对，执行者提供对应原件指针 | 不能固定本版实施基线或判问题仍存在 |
| D05—D07与原问题关闭情况 | 读取最终交回、集中评审、官方预算及独立装配证据，沿原编号核保持 | 无法判断应复用还是需本版再设计，不以旧评审猜结论 |
| 正常CLI输入和完整运行 | 从获准suite取得Case/终点/宿主/模型/配置、原事件、父子会话、产物与干预 | 不能签信息送达、实际语义、跨阶段效果或真实成本 |
| 实际覆盖与未覆盖 | 系统送审、本地CU、update/恢复及独审按真实到达记录，保持2.1原运行范围 | 未跑部分列缺口，不为本版目标倒推2.1必须额外跑什么 |
| 人工阅读与金样差距 | 在同一有效材料和人答前提下，对实际产物、既有金样、候选作语义核对 | 不能确定最终金样是否应修或生成机制是否有缺陷 |
| 内网和上游依赖 | 核2.1实际取得的adapter/宿主/Framework证据；缺环境明确所需合同与取得人 | 本地替身不代签内网，缺内网证据不阻无关分析；上游问题不在本仓绕过 |

这些是分析所需事实，不是要求用户现在手填全部身份。已有确切来源由维护者自行取得；需要新运行或真实环境时按后续授权处理。
