## 1. 产品目标与依据

Story Extension帮助消费模型从系统单或本地需求起步，理解材料和工程，在Framework原生蓝图中完成共同设计，交付业务评审者可独立阅读的Story/Review，并让项目知识进入实际需要的CU及后续阶段。2.0.4的目标是在该正常使用链上恢复1.9.9已证明的有效能力，收敛2.x真实差距。

权威依据：[2.0.1整版适配需求](../2.0.1/2026-10-28-2.x适配收敛/00-需求.md)的R1—R11/AC1—AC14、[阅读与写作要求](../2.0.1/2026-10-25-Story阅读与写作质量提升/00-需求.md)的R1—R7/AC1—AC8、[TEST§6.4—6.5](../../../test/TEST.md#64-story-init-三轴评分)、项目AGENTS与用户本轮明确纠正。实现和测试结果只作证据，不反向定义需求。

当前实施设计只读[总Plan](../../plan/2.0.4/2026-11-10-Framework同步与Story效果收敛/00-实施方案.md)。全量标准及采用身份见[评价标准变更](评价标准变更.md)。原2.2最终收敛中的有效目标由本Spec承接，不按历史文档中的旧阶段名恢复旧机制。

## 3. 六项实现目标

### G01 完整准确的业务交付

业务评审者只读Story即可理解背景、范围、角色、流程、页面操作、条件、异常、责任、未决和验收。Review呈现真实需要裁决的事项、选项后果及有效答复，保人工区；不是独审报告或技术任务清单。

自然业务标题、长文分层及局部阅读成立；页面来路、操作、反馈、正常/受限/失败/未知去向不丢。保既定图＞表格＞列表＞章节＞文字的表达优先级及图前短说明—图—图后有效补充，不凑图数或项数。允许有用途的重述，去掉无信息增量的重复。必要业务和技术摘要不能只留一个外部链接，也不将完整蓝图复制进Story。

### G02 知识真实应用并传递

项目事实、规约、模式在影响决定之前到达正确执行体，经过适用判断，改变设计对象、义务、角色及可观察验收，再被实际下游取得和落实。知识名称、ID或字段存在不能代替理解与应用；有据不适用、冲突和未知分别表达。

共同设计已有的验收复用，Spec保合法局部深化；不经Spec执行也必须在实际消费入口核知识归属。两CU依赖不等于全部义务复制。统计指标、事件及资源义务有真实依据和承担，取数不足不能用编造公式补齐。

### G03 按Framework原生机制协作

1.x需求级Spec的共同设计及Story来源职责，在2.x由蓝图接替。CU按实际设计与用户交付需求形成，原生合法复用或深化分别记录；纯业务送审可以零CU，不为文件齐套制造施工产物。

Extension使用原生来源、设计、准入、认领、阶段和完成合同，保真实授权；不把测试截止转换成产品请求，不复制通用调度器或要求Framework为测试形状新增能力。真实独立Spec/Plan请求的既有权限边界保留，受限时如实报告。

### G04 有效独立纠错

蓝图质询核共同设计、来源和相应修订；Story先独立首读业务，再核原件、人答和必要设计依据，不重复整套技术论证。Story与蓝图一致不豁免两者共同遗漏，发现设计问题回设计责任位置。

真实最终回复先原样保存、接收，再处理或修改；修订按原发现和实际影响复核，非阻断建议可有据保留，不以清空WARN制造循环。无独审能力诚实披露，不能冒称独审/DSH验收通过，也不新增免责批准。

### G05 相称的性能和返工成本

优先消除已证无效规则/源码读取、重复定稿和检查、重复技术论证、错误参数重探及无效返修。保正常推理、原生必需检查、有效来源和恢复边界；不设固定篇幅、图数、审查轮数或新硬时限。

性能从正常需求开始到可交付结果评价，分列人工等待、外部故障、正常设计和返工。不能用工具调用减少直接推整链提速，也不能把某次蓝图区间当平台不可突破的下限。

### G06 既有能力和所有权保持

系统/本地取材、同名资料、会议纠偏与裁决、范围、图源与阅读形态、送审归档/读回、update与本地/远程恢复、重入、安装升级、usage/stats继续有实际承担者。2.x新需求的多轮变化支持保持，不兼容旧在途格式、不清理历史原件。

知识和对接归目标仓；本版知识修订通过既有演进主题送达适配模型，安装器不代写目标知识。升级、重复运行和局部失败不丢人工内容、使用记录或已发生的副作用。

## 4. 正常场景与保护项

| 使用场景 | 应得结果 | 保护边界 |
|---|---|---|
| 系统单/本地单起步 | 取得真实材料，发现缺口，形成有效范围和设计 | 本地零远端；不预交测试答案，建议不冒充裁决 |
| 纯业务评审 | 完整Story/Review及真实系统需要的参考，按授权送审 | 允许零CU；业务确认、设计准入和发布资格分别成立 |
| 需要施工设计 | 实际CU取得共同义务，规格/方案完成自身职责 | 依据真实请求推进；原生复用不伪称执行，不为形态复制产物 |
| 无现成实现 | 工程事实→本期承担对象/改动边界/验收 | 无封装不等于平台不可用；真外部未知如实表达 |
| 新材料/意见/直接改稿 | 比较变化，修正确真源，传播至受影响产物 | 人答、人工区、旧有效内容和外部意见保留；本轮不追加update实跑 |
| 中断/失败/重试 | 恢复到真实状态，说明已完成与缺口 | 不重复上传/计时，不以旧PASS遮住当前必修 |
| 安装升级 | 更新机制和必要主题，保目标事实与所有权 | 定向修知识，不全量重盘；不迁移旧需求现场 |

| AC02 | 单读Story形成完整业务和页面理解，标题、长文、图文与必要精确查阅成立 | G01；既有阅读AC1—AC8、金样并排及独立首读 |

| AC05 | 原生设计、阶段和复用按真实业务请求工作，测试配置不构成授权或额外交付义务 | G03；公开入口、真实请求及原生事实 |
| AC06 | 两类审查实际独立、原件真实、错漏被发现并回正确owner，复核不重复无关技术论证 | G04；主子会话、原报告和修订后结果 |
| AC07 | 已证重复消除，正常检查/写入/失效保护保持；同条件成本及返工变化可解释 | G05；确定性前后行为和真实事件 |
| AC08 | 材料、图文、归档/update/恢复、安装与usage等保持项在受影响链上不退 | G06；全量标准保持集合及适用回归 |

| AC10 | 同一职责替换覆盖生产/消费/入口/指令/配置及专用测试，不保影子机制 | 全目标；diff、真实调用和退出验证 |

| AC12 | 保持原包累计与真实成本，未实现/未审/未测/外部限制诚实列出 | 全目标；官方预算、证据身份与用户决定 |

金样是效果参照，分别核事实、关系、图表文字、逻辑、条件/异常、知识和成本，不强求同标题、字数或额外选型。目标稿、确定性、独立语义和真实行为分别结论；局部绿测或Case终态不能代签版本效果。

## 6. 测试与产品范围分开

auto系统业务送审、car本地需求到实际CU Plan是代表性取证场景。历史“auto至Spec”的内容覆盖按2.x真实承担者核，不自动建立CU或强制执行Spec-only。测试停止条件由测试域观察，不注入业务prompt，不自动转成requested_phases；具体映射在Plan验证分册唯一维护。

本轮真实验证范围不包含update、Coding、设备和真实外部联调；这些有效能力及受影响离线回归不删除。测试不足写未覆盖；无依据的极端组合不扩成实现要求。

构造的Spec-only实验结果保留为有范围的原生问题记录。只有实际业务请求在受支持入口触发并影响目标，才据事实判相应缺口；撤回其作为auto或整版默认硬前置的结论，不因此删既有真实请求权限约束。

## 7. 状态、依赖与纠正记录

本版通过已固定Framework公开能力实施；依赖合法上游发布树、现有宿主工具和正常工程事实。直接质询自动写回尚无公开入口时保现真实回复登记责任，不以可选改进阻塞正常链。当前没有由Case截止位置导出的必等上游能力；后续真实缺口按责任与影响处理，不预设全部能力已验证。
