## 2. 本版应核的评价对象

| 对象 | 判什么 | 证据与局限 |
|---|---|---|
| 最终方案 | 正常、变化和恢复链完整，职责/接口/状态/消费者唯一合理，替换与保持闭合 | 独立设计评审及真实合同；方案成立不证明代码或使用结果成立 |
| 实现与确定性能力 | 生产消费、来源与授权保护、写入/恢复、装配、入口、安装、计量及旧路径退出 | 实际输入输出、局部/集成/装配及实现评审；字段和绿测不证明业务语义 |
| 最终目标金样 | 固定有效前提下业务正确、完整可读、知识落地、图文与跨稿一致 | 独立语义核对及用户审定；目标稿不代签自动生成、送达或独审成功 |
| 正常运行结果 | 正确执行体得到输入，理解并形成产物，后续真实消费，关键失败可恢复 | 获准正常CLI原事件、产物、真实副作用及独立语义；2.1结果只签2.1实际对象 |
| 评测标准与装置 | 能辨正误和合法差异，覆盖真实使用，准备可重建，成本可解释 | 复用必要正反例、消费者及独立冷装配；装置稳定不代签产品效果 |

各对象分别给符合、偏离、未覆盖或有依据的不适用。方案、实现、金样、标准互相核对，不允许作者自查、报告格式、checker或同一金样形成循环自证。

## 4. 金样与判据共同收敛

两组既有业务按有效输入、人答、范围和真实目标阶段核对；原金样保留，候选与正本区分。需要改金样时说明原差距、当前有效依据、影响产物和独立核对，晋升按既有用户审定规则。

同一材料可以有多种合法标题、图形组织、章节和实现位置；评价业务、职责、关系、知识与恢复结果，不以逐字匹配或固定布局拒绝正常差异。反例优先用已证缺陷和直接合同，局部构造仅证明对应规则；不因本版强调完整就增加通用故障注入平台或无限组合测试。

机制与消费输入不得包含金样答案、维护判据或Case特征；目标金样和判错能力分别验证，不能以隐藏判据指导产物，再以其通过证明系统有效。
