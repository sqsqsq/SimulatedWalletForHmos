# 维护设计者能力优化

## 目标与使用者

维护 Agent 产品的会话使用 maintenance-designer 制定可直接实施的方案，或评审方案、实施改动与效果证据。设计交付应使接手者无需拼接历史或补做关键设计；评审应能区分方案错误、实现偏离和证据不足，并说明整体结果对使用者是否有效。

原始调查输入为[全史分析](../../../plan/project/2026-10-11-设计者与评审者全史分析.md)。独立全史分析保持原件；其计数与归因限制、前轮已核原件及当前决定见[总览](../../../plan/project/2026-10-11-维护设计者能力优化/00-方案总览.md)。

## 已确认范围

- 新增用户级 maintenance-designer Skill，提供“方案设计”和“评审”两个功能。角色内自动加载，入口按本次功能只读取相应方法页。
- 正文在 `C:/Users/kangz/.agents/skills/maintenance-designer/`；Claude 只设薄入口，引用同一正文及方法页。用户级 AGENTS 只增加一句入口并同步三份，不扩写通用方法。
- 任意会话可从用户当前请求、适用 AGENTS、有效方案或被审文件及证据接手；无需绑定 agent 身份或 implementation-loop。
- maintenance-agent 保留全项目维护诊断职责。普通业务开发和全项目诊断继续按各自入口处理。
- 单独评审只交意见，保留被审方案和产品原件。用户要求修订时转为方案设计；同一请求明确要求评审后修订时，先形成意见再按设计方法修订。
- 验证分为结构检查、定向检查、实际不同会话的设计—评审—修订。实际试用成功只支持本次可用，不宣称长期稳定或跨模型普适。

本需求不改变 Story Extension、Framework、知识样板和测试机制，不接管 2.0.4 在途工作，不修改 implementation-loop，不调整维护预算、角色权限、模型选择约定或用户确认权。

## 完成条件

| 对象 | 可检查结果 |
|---|---|
| 方案设计 | 关键事实有当前来源；职责、输入输出、文件动作、保持与退出、失败处理及验收足以实施；局部实现选择仍留给实施者 |
| 评审 | 依据目标与有效决定核方案、实现、证据和完整结果；实现有偏差仍审可审的方案问题；意见有位置、影响、责任及复验方法 |
| 功能边界 | 评审不改被审对象；明确修订后才进入设计；新会话能从有效文件继续工作 |
| 指令交付 | 正文、两份方法页、必要宿主元数据与 Claude 薄入口一致；AGENTS 只增加入口句且三份同步；已有有效职责保持 |
| 验证 | 三层分别报告证据与结论；实际不同会话完成设计—评审—修订并留可查产物；未执行项保持待验证 |

不以表格数量、零提问、零返修或文件长度评价能力。合理提问、发现方案错误和必要返修须保留。
