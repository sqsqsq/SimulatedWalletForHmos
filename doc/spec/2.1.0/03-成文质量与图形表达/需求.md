# R3 成文质量、SVG 指导与性能优化

承接 T8、S1–S4 的机制改进部分。效果由 R1 定义，验证口径归 R4；本分册集中维护图型指导、载体选择及性能措施，避免只有观测没有改进。

## 1. 内容质量与责任

R1 的金样错误是已知证据，不直接证明当前消费机制仍有同样缺陷。先核当前作者输入、设计决定、生成与检查职责，再做最小修正；2.0 已承担的循环、恢复和原有能力保持只做回归，不另建闭环。

| 实际缺口 | 改进位置 | 应有结果 |
|---|---|---|
| 没有依据或把建议当已定 | 来源和决定在作者行动前送达；蓝图与人读审查核权威 | open 事项不在正文、图或验收中被暗选 |
| 同一事实多处手写漂移 | 精确设计内容沿原有权威投影，叙事回源核语义 | 数值、分母、状态和异常条件一致，不另建事实数据库 |
| 同类信息组织不稳定 | 现有章节合同与作者任务给适用条件和表达指导 | 读者能比较选项、理解状态/责任/后果，允许有理由的调整 |
| 工程输入输出或接入断链 | 设计及施工审查核实际生产者、转换、接口和消费位置 | 身份脱敏不破坏业务输入，新组件有实际接入动作 |
| 报错太晚或只修局部 | 当前调用一次列已发现问题及影响面，给位置、原因和恢复动作 | 减少同一根因逐处返修，不把未执行检查伪报通过 |

规则按责任在现有合同、作者页和审查判据落一处，其余消费源内容；不按 Case 标题、表行数或业务答案增加特例。作者负责语义、信息组织和选择，脚本负责确定性的结构、来源绑定、投影和渲染辅助，独立审查负责实际完整性与一致性。

内容和表达都须稳定达到审定金样的质量：状态与动作相符；异常区分受限、失败和未知；指标说明分子分母、时间范围及来源；图文合起来讲全条件与去向；建议、人签和待决边界清楚。合法差异不自动判错，也不以表达自由免除这些结果要求。

## 2. 六类 SVG 指导

已有探索主要是一张复杂流程图的 Mermaid/SVG 对照，不能推定其他图型同样受益。复用现有[图形用途选择](../../../../extensions/skills/story/phases/story-write.md)和[历史图型盘点](../../1.9.4/2026-09-20-story人读表达增强/参考/图型全量示例.md)，按实际使用的语义分六类补指导，不重新扩成全图表平台。

| 图形用途与适用条件 | SVG 组织指导 | 中性示例题材 | 易错语义与检查要点 |
|---|---|---|---|
| 流程与分支：有实际分流/回流 | 主线清楚，复杂分支分区，多责任时可用泳道 | 资料申请、补件、批准或退回 | 条件写明，分支有去向，回流接回正确位置；不凭布局增加业务分支 |
| 时序交互：先后、等待和失败责任需分清 | 参与方横排、时间纵向；调用与返回容易辨认 | 预约请求、名额确认、通知结果 | 消息起止方、顺序、等待、响应及失败处理一致；不把不同执行方混成一条线 |
| 状态与动作：互斥状态及条件迁移 | 状态节点、带触发/条件的迁移箭头，必要时分组 | 申请草稿、待审、通过、撤回 | 初始/终止和合法迁移有据，动作不能自动变状态，不给终态增加无依据出口 |
| 对象关系：归属和数量容易读混 | 对象卡片及明确命名的关系连接 | 场馆、房间、预约记录 | 名称、方向与已知数量约束准确，不补造未提供的基数或字段 |
| 架构与责任边界：跨边界交接 | 按真实边界分区，突出跨区连接 | 前台、审批、通知服务的职责 | 所有权、依赖方向和数据交接清楚；分区美观不能掩盖真实责任 |
| 依赖与开放顺序：有前置阻塞 | 前置到后继排列，并行项并排 | 基础能力、业务接入、开放验证 | 依赖与并行关系有据，不因排版制造先后，也不虚构日期 |

每类产品指导包含适用条件、一份中性示例、易错语义与检查要点；示例展示可用形态而非固定答案。上表题材是维护验证输入范围，不含两 Case 的答案；后续实际 SVG 示例必须验证后才交付作者。

模型决定抽象层级、信息分组、重点、布局及必要图型；不得每次从零猜语义表达规则。指导不固定颜色、坐标、节点数或整图模板，不要求先后遍历全部图型，不建设通用布局引擎。超出六类的图仅按实际需求和现有能力处理，不以本次 SVG 接入自动新增支持承诺。

## 3. 选型以效果和日常总成本为准

- 已验证 SVG 更清楚且日常总成本不增加的场景，直接优先 SVG。
- 不要求先画 Mermaid 失败，不要求日常生成两版再比较。
- 效果相当时选生成、检查和维护更简单的形式；没有足够证据的图型不预设 SVG 优先。
- 不是把 Mermaid 语法换成 SVG 文件就自动改善效果，必须验证语义、布局与实际阅读。

维护阶段对六类分别记录可读性与成本，只把成立的条件交给作者；单个流程图成功不能推广到全部图型。对照实验不进入每次业务执行流程。

“日常总成本”包括模型生成 token、处理耗时、登记和检查、预览、返修、打包交付与人工操作；不能只看画图时间或只挑下降的指标。一次性接线与指导建设计入维护预算，日常不增加用户必做步骤。证据不足时只声明支持能力，不声明该场景已达到优先条件。

### 3.1 两 Case 的 SVG 验证安排

现有候选稿已有真实图形关系，以下仅是维护验证候选，不证明 SVG 已更好，也不是按 Case 名触发产品规则：

| Case 与候选 | 要比较的效果 | 比较前置 |
|---|---|---|
| AR90006 签约路径 | 正常主线、实名/验证/创建分支与取消、暂存、中断恢复是否更易理解 | 先按 R1 修正未决验证及超时处理口径，再给同一套语义输入；[当前候选图](../历史参考/原1.9.9/04-稳定性与性能分析/data/golden/AR90006/story.md) §5.1 |
| ISSUE-206 分享建立与接受交互 | 参与方、阶段、等待及失败/回滚责任是否更清楚 | 先核参与方和交互关系，不能用 SVG 美化错误设计；[当前候选图](../历史参考/原1.9.9/04-稳定性与性能分析/data/golden/ISSUE-206/story.md) §5.1 |

**维护域定向验证**可以指定 Mermaid/SVG，用相同的已修正业务语义和可比模型运行设置，比较正确性、可读性、token、耗时及返修；不把输入事实或关系不同的两张图当载体优劣对照。记录真实部署的模型版本，不预先认定某个模型更擅长 SVG。

**正式 Case 行为验证**不指定某章必须使用 SVG，只交付通用图形指导，观察模型如何选型以及实际登记、审查和交付。上述候选位置和金样成品不作为提示词答案注入，不修改业务需求来逼出 SVG。

简短状态图和依赖图保留为 Mermaid 对照，不为凑覆盖全部换格式。两 Case 未自然覆盖的图型用小型中性样例验证，不扩充业务范围。定向能力证据与正式自然选型证据分别记录；正式运行没有 SVG 时仅记录该次未覆盖 SVG 路径，不宣称端到端通过，也不自动判选型错误。

是否优先 SVG 由后续真实效果及日常总成本共同判断。当前只登记验证安排；本轮不启动模型对照、真实 CLI 或渲染验证，测试仍在后续授权里程碑执行。

## 4. 图形交付与必要检查

读者下载 Markdown 及本地图片后用编辑器阅读。SVG 使用现有图片身份、材料登记、正文引用、冻结、独立审查和归档链；作者自绘为派生表达，不能冒充原型原件。改图后的报告须绑定当前实际对象，采用已有机制，不新建 SVG 登记或状态系统。

校验职责分开：结构检查核 XML、根/视口及引用等可确定事实；实际渲染核裁切、遮挡、文字和连接的可读性；语义审查核关系、条件与责任。字符宽度近似只提示风险，不能证明渲染或语义正确。

必要接线覆盖导入器与冻结器当前后缀能力不一致、图片归档和相对引用的完整路径；不只加白名单。保持 Mermaid-only、无图及不适用图的正常行为。发现问题沿已有失败出口报告位置和修法，不新增固定返修次数或异常状态机；换表达仍不能达标时如实未完成。

## 5. 性能优化措施及落点

| 性能目标 | 本版措施与责任 | 需要观察的改善 |
|---|---|---|
| 简化发布与升级 | R2：仅发布机制，内网 adapters 独立分发；日常仅换 xxx 后调用一次原生入口，内部完成确定性步骤 | 不再内网逐版重组机制包，不重复获取 adapters，不拼接 Story 安装/检查/标记命令 |
| 减少重复知识工作 | R2：沿已有知识及有效版本增量处理，无变化不全量调查和重审 | 相同输入没有重复知识生产，首装仍保留必要准确性 |
| 提高首次成文质量 | 作者任务在动笔前交付事实、决定、表达指导与完成条件；复用确定性辅助 | 因规则晚到、漏条件或手写投影引起的首轮缺陷减少 |
| 减少局部修复循环 | 现有问题反馈说明已发现根因、受影响落点及恢复动作 | 同根因不在已知其他位置反复出现；不机械枚举每条素材造大台账 |
| 减少重复查询和输入 | 同一动作给完整结果和下一责任；规则单一来源、去除重复正文 | 无信息增量的调用和上下文减少；变化后仍核当前事实 |
| 减少无效派审 | 使用现有对象判定及有效报告复用，报告本身不使对象改变 | 未变对象不重复审，真实内容变化仍接受必要审查 |
| 减少图形试错 | 按维护阶段验证过的图型指导直接选择、复用图片链 | 不日常双版本试画，图形完整成本与人工负担不增加 |

独立审查仍取得自己的必要输入，不能复用作者上下文或结论代替独立判断；减少重复文本不等于删掉其需要知道的事实。原有检查或 2.0 已解决的机制只核保持，不重复建设。

## 6. 完成条件

六类指导逐类有验证记录，R4 分开验收维护域能力与正式 Case 自然选型；未生成 SVG 的运行如实记未覆盖。优先场景有质量和日常成本证据；相同业务关系换名称、分组或规模后仍能表达，不靠固定样例坐标过关。效果不足或成本未证实的类型如实保持非优先，不阻止其他成立类型使用 SVG。

R4 在同输入、同终点和质量合格后比较 token、有效处理耗时、人工动作及真实返修；资料缺失或自然波动导致结论不足时保持未验证。来源/业务问题回对应权威，表达回作者，通用工具缺口回 Framework。本轮只形成方案，未生成或验证六类 SVG 成品，不宣称性能已改善。
