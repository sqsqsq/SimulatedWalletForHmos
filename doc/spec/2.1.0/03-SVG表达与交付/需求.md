# R3 SVG 表达指导、选型与交付

2026-10-07 版本重整。当前只承担 SVG 能力、六类表达指导、场景选型与完整图形交付；原内容质量、跨产物一致性、首次成文与通用需求执行效率分别迁入 [2.0.3 R2](../../2.0.3/02-产物内容与独立审查/需求.md)、[R3](../../2.0.3/03-需求执行效率/需求.md)。本页保留原 T8 的 SVG 相关目标；非 SVG 的有效目标没有删除。

## 1. 进入条件与职责

采用 2.0.3 R1 审定的真实语义输入与质量基线。先解决事实/决定/关系问题，再比较不同图形表达；不能用 SVG 美观掩盖业务错误，也不在本版重复建设 2.0.2 的 dispatch、材料身份、报告消费或原生施工状态。2.1.0 R4 只验本版图形与分发效果，质量标准引用 2.0.3，不另写一份。

## 2. 六类 SVG 指导

已有探索主要是一张复杂流程图的 Mermaid/SVG 对照，不能推定其他图型同样受益。复用现有[图形用途选择](../../../../extensions/skills/story/phases/story-write.md)和[历史图型盘点](../../1.9.4/2026-09-20-story人读表达增强/参考/图型全量示例.md)，按实际使用的语义分六类补指导，不重新扩成全图表平台。

| 图形用途与适用条件 | SVG 组织指导 | 中性示例题材 | 易错语义与检查要点 |
|---|---|---|---|
| 流程与分支：有实际分流/回流 | 主线清楚，复杂分支分区，多责任时可用泳道 | 资料申请、补件、批准或退回 | 条件写明，分支有去向，回流接回正确位置；不凭布局增加业务分支 |
| 时序交互：先后、等待和失败责任需分清 | 参与方横排、时间纵向；调用与返回容易辨认 | 预约请求、名额确认、通知结果 | 消息起止方、顺序、等待、响应及失败处理一致；不把不同执行方混成一条线 |
| 状态与动作：互斥状态及条件迁移 | 状态节点、带触发/条件的迁移箭头，必要时分组 | 申请草稿、待审、通过、撤回 | 初始/终止和合法迁移有据，动作不能自动变状态，不给终态增加无依据出口 |
| 对象关系：归属和数量容易读混 | 对象卡片及明确命名的关系连接 | 场馆、房间、预约记录 | 名称、方向与已知数量约束准确，不补造未提供的基数或字段 |
| 架构与责任边界：跨边界交接 | 按真实边界分区，突出跨区连接 | 前台、审批、通知服务的职责 | 所有权、依赖方向和数据交接清楚；分区美观不能掩盖真实责任 |
| 依赖与开放顺序：有前置阻塞 | 前置到后继排列，并行项并排 | 基础能力、业务接入、开放验证 | 依赖与并行关系有据，不因排版制造先后，也不虚构日期 |

每类产品指导包含适用条件、一份中性示例、易错语义与检查要点；示例展示可用形态而非固定答案。上表题材是维护验证输入范围，不含两 Case 的答案；后续实际 SVG 示例必须验证后才交付作者。

模型决定抽象层级、信息分组、重点、布局及必要图型；不得每次从零猜语义表达规则。指导不固定颜色、坐标、节点数或整图模板，不要求先后遍历全部图型，不建设通用布局引擎。超出六类的图仅按实际需求和现有能力处理，不以本次 SVG 接入自动新增支持承诺。

## 3. 选型以效果和日常总成本为准

- 已验证 SVG 更清楚且日常总成本不增加的场景，直接优先 SVG。
- 不要求先画 Mermaid 失败，不要求日常生成两版再比较。
- 效果相当时选生成、检查和维护更简单的形式；没有足够证据的图型不预设 SVG 优先。
- 不是把 Mermaid 语法换成 SVG 文件就自动改善效果，必须验证语义、布局与实际阅读。

维护阶段对六类分别记录可读性与成本，只把成立的条件交给作者；单个流程图成功不能推广到全部图型。对照实验不进入每次业务执行流程。

“日常总成本”包括模型生成 token、处理耗时、登记和检查、预览、返修、打包交付与人工操作；不能只看画图时间或只挑下降的指标。一次性接线与指导建设计入维护预算，日常不增加用户必做步骤。证据不足时只声明支持能力，不声明该场景已达到优先条件。

**维护域定向验证**可以指定 Mermaid/SVG，用相同的已修正业务语义和可比模型运行设置，比较正确性、可读性、token、耗时及返修；不把输入事实或关系不同的两张图当载体优劣对照。记录真实部署的模型版本，不预先认定某个模型更擅长 SVG。

**正式 Case 行为验证**不指定某章必须使用 SVG，只交付通用图形指导，观察模型如何选型以及实际登记、审查和交付。上述候选位置和金样成品不作为提示词答案注入，不修改业务需求来逼出 SVG。

是否优先 SVG 由后续真实效果及日常总成本共同判断。当前只登记验证安排；本轮不启动模型对照、真实 CLI 或渲染验证，测试仍在后续授权里程碑执行。

## 4. 图形交付合同

### 4.1 一次下载的交付集合

读者取得一个 `story-package.zip`，解压后用普通 Markdown 编辑器从 `<需求标识>/AR/story.md` 阅读。包内保留工程中的需求相对布局：AR 下三件 Markdown、正文实际引用的图片/SVG，以及三件文档中相对链接指向的已采用来源文件；只收当前已登记交付版本的引用闭包，不复制整个工程或 story-src 工作目录。报告历史、运行日志、凭据和维护金样不进入包。

业务三件仍是 `story.md`、`review.md`、`design-review.md`，其字节、材料身份和权限保持；打包不改写文案或重新生成设计。图片使用原有登记和来源身份，自绘 SVG 是派生表达，不冒充原件。源图与 SVG 文件名采用已有资源名规则，不新增专属 SVG 编号/登记状态。

相对链接以包内原路径解析，保留子目录；同名不同文件不能拍平成一份。引用越出已登记交付集合或文件缺失时不生成成功包，报告具体缺项。外部 URL 保留原地址并注明需网络，不宣称离线可用。必要本地字体/嵌入图片等资源必须可在解压后解析；不能依赖维护机绝对路径。

### 4.2 本地与系统交付

本地需求交付当前三件、资源及同版本 zip；系统需求仍写正文、上传 Review/设计附件，并上传该 zip 供人一次下载资源。系统正文预览不承诺渲染 SVG，正式图文阅读以下载包为准。沿现有 archive/发布记录与材料身份记录包的摘要及实际上传/读回结果，不新建发布状态机或第二份版本号。

当前 Markdown-only adapter 不具备二进制附件交付能力：由 adapters 的实际维护方扩展上传/下载文件的能力，回执必须能核文件字节与当前包一致，不能将二进制伪作文本 putAttachment。实际传输协议、限制和返回位置属于后续 2.1.0 接入 plan 与对接合同；能力未交付则系统完整图形交付未完成，不用本地存在文件冒称已上传。Framework 不承担内网接口实现，旧对接包只在此次契约变化时升级。

### 4.3 更新、重试与恢复

任何正文、图或依赖资源变化，先按当前审查身份重验，再从同一当前版本重新打包；未变件沿用原内容。包的文件枚举、摘要及发布依据复用现有交付记录，打包时刻不独立改变审查对象。相同材料重跑应得到同一内容集合，不因压缩容器时间戳强制模型重审。

远端部分写入/上传失败保持本地与上次有效记录，不记整体成功；重试核外部修改，人工冲突按原归档所有权处理。恢复不删除人工意见、冻结来源与历史审查；旧包和新正文不可被标为同版交付。用户不需要另行拷图片、手改链接或维护包内清单。

### 4.4 三层验证

结构检查核 XML、视口和引用等确定性事实；实际渲染核文字、裁切、遮挡、连接和解压后可读性；独立语义审查核关系、条件与责任。字符宽度估算不能证明渲染或内容。保持 Mermaid-only、无图与不适用图路径；失败报告问题和原责任，不加固定返修次数或图形异常状态机。

## 5. 本版性能措施

SVG 只在已验证更清楚且日常总成本不增加的场景优先。复用现有图片身份、检查和交付链，不让业务作者常态生成两版试画；成本包含生成、登记、预览、返修、交付与人工动作，不只比较画图时间。相同输入/终点的计量方法按 TEST，R4 记录本版对照。

安装升级的效率与无变化知识增量处理统一归 R2；首次成文质量、按决定修影响面、重复查询/输入和无效派审迁入 2.0.3 R2/R3。必要知识仍完整送达，独立审查不复用作者上下文代判断。

## 6. 完成条件

| 能力 | 必须具备的证据 |
|---|---|
| 六类表达指导 | 每类至少一份已渲染和语义复核的中性例，覆盖相应关系；不靠固定坐标或 Case 专名 |
| SVG 完整交付 | 至少一条通过当前生产入口实际生成 SVG 的定向维护运行，完成登记→审查→本地/系统交付→下载解压阅读，并验证改图后的更新交付；不是手工摆文件就算通过 |
| 优先选型 | 至少一个具体适用场景证明 SVG 更清楚且日常总成本不增加，其余类型可保持非优先；不能外推全部图型 |
| 正式自然选型 | 两 Case 获授权后正常运行，只给通用指导，记录选择与结果；未自然生成 SVG 不自动判失败，也不作为 SVG 端到端证据 |
| 原能力保持 | Mermaid-only、无图、图片来源、相对链接、更新与人工保护仍成立 |

定向完整交付已证明且正式自然选型合理时，即使两个 Case 都未选 SVG，也可签本版支持能力；必须明确“自然选用 SVG 未覆盖”，不能宣称已验证自然触发。定向完整链未发生时 SVG 交付仍未完成，不能用六张静态示例或不适用替代。

成本按同语义/质量/终点的配对观察：总 token、有效处理时间与人工操作均不增加，至少一项改善或读者效果明确改善且成本持平；指标一升一降只记录权衡，不签“总成本不增加”。具体运行和用户效果审定按 R4，不预设模型优劣。本轮仅完善规格，不生成图、不运行模型或写 2.1.0 plan。
