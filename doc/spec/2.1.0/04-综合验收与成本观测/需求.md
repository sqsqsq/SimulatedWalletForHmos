# R4 综合验收与成本观测

本分册维护统一证据和成本口径；具体性能措施只在 R3，接入合同只在 R2。操作沿[TEST](../../../../test/TEST.md)，不新增评测平台或调度器。

## 1. 验收对象与证据

输入为已验证的实际 Framework/Extension 组合、产品 diff、用户审定的两 Case 修订稿及其材料/真实决定，以及本次运行证据。评价本轮目标和必须保持的原有能力；用户首次分别取得机制和内网 adapters，日常只替换机制，再使用一次原生入口。

| 证据层 | 证明内容 | 边界 |
|---|---|---|
| 确定性 | 目录所有权、登记/入口、引用/图片、完成记录及必要失败副作用 | 不证明实际语义和上下文送达 |
| 独立语义 | 来源、真实决定、知识、设计、正文及验收一致 | 不替代未运行的消费效果 |
| 表达效果 | 同类信息组织稳定、图文可读、变化有理由 | 字段、语法、字数或表格数量不能代替 |
| 成本 | 可比输入/终点的 token、耗时、人工动作及真实返修 | 不混算不同版本/范围，不由报告份数推出修复次数 |

金样和维护答案不进入消费模型工作区。脚本全绿、作者自证、格式一致或单次已知 Case 成功均不能单独签收整版。纯确定性 helper 按其输入输出和失败语义验收，不强迫每个 helper 都做真实 CLI。

## 2. 最小必要场景

| 组 | 场景 | 可检查的结果 |
|---|---|---|
| G1 金样与来源 | 两 Case 的有效材料、真实人签、示范回填及待决/定案情景 | R1 的 G01–G09 修正闭合；状态一致，无虚构确认或缩小范围 |
| G2 金样替换 | 正本、输入装配、文件指纹、渲染和真实消费者 | 旧有效覆盖有承接，新正本唯一，专用旧分支退出 |
| A1 首次接入 | 已有 Framework、分别取得 xxx 与 Wiki adapters、无 Story 入口及 knowledge | 三目录各就其位，仅用 /extension materialize 完成必要接入；不复制 Demo 知识 |
| A2 升级与保全 | 日常只替换 xxx，保留已有 adapters、knowledge、目标身份及适配信息 | 单纯文件替换不改保留内容；原生接入仅处理真实增量，契约未变不要求更新 adapters |
| A3 无变化重跑 | 相同版本与有效目标内容 | 幂等，不重复生产知识或重审，不要求用户查状态再手动标记 |
| A4 职责交接 | 原生入口消费接入要求，旧 Story adapt 登记及编排撤下 | 输入在行动前送达；旧入口退出但知识/升级方法仍有消费者，/story 业务保持 |
| A5 发布与装配 | 只从根 extensions/xxx 发布；复制 Demo 后仅替换模板 xxx | 发布包不含 adapters/knowledge；机制同源检查只覆盖 xxx，目标内容分别核来源，Demo 不被测试写入 |
| A6 独立对接与路径 | 首装、必要对接更新及新的 adapters 路径 | 真实契约适用、调用和工程根解析正确；旧内嵌副本、固定上溯及旧消费者退出，无复杂兼容矩阵 |
| Q1 成文质量 | 同一事实与待决状态贯通设计、正文、图、验收及实际工程接入 | 根因及已知影响面被发现；同类表达达到基线，合法变化不误伤 |
| V1 维护域定向能力 | R3 §3.1 两候选及六类所需中性小样，可指定 Mermaid/SVG | 修正后相同语义输入，核正确性/可读性/token/耗时/返修；不强行扩业务覆盖全部图型 |
| V2 完整交付 | 已实际生成的 SVG/Mermaid/无图产物，正文与本地资源下载阅读 | 结构、渲染、语义及交付链有相应证据；无 SVG 的运行不能证明 SVG 端到端通过 |
| V3 正式 Case 自然选型 | 仅交付通用指导，不指定某章必须 SVG | 观察选型与实际交付；未生成 SVG 记未覆盖，不自动判选型错误，不用定向成绩替代 |
| P1 性能 | 同基线、同输入、同终点、相同质量要求 | 对应 R3 措施报告 token、处理时间、人工动作和真实返修；收益与代价均披露 |

原有脏文件、人工入口、依赖和写入失败保护沿既有相关回归核保持，不在本版扩成新的异常矩阵。新增必要检查限于目录分离和接入要求确实送达/执行；损坏输入和未完成部分不能冒充成功。被撤的组合包管理、独立状态命令、人工标记和常态审查巡检不再设专用新测试。

## 3. 成本观察与判断

观测单位是一项明确请求及其实际终点，区分接入、Story、蓝图、设计交接和施工；多个 CU 不能以一个 CU 完成代替整单完成。

从现有事件和结果记录取得版本、请求范围、起止、人工介入、工具调用、输入/输出 token、等人时间、环境异常、派审对象与真实内容修改。缺数据明确未知，不以墙钟差猜纯模型耗时，不新建采集平台。首次安装合理的调查与真实决策时间不能算无效成本。

相同对象重验、对象改变、真实语义修订和基础设施重试分别观察；一份报告不等于一次成文，N 份报告不等于 N−1 次返修。历史 28/70 单报告快照只说明留存分布，不作为当前性能基线。

先核质量合格再比较：普通机制发布是否无需内网重组，日常升级是否只替换 xxx 而无需重新取得 adapters，再调用一次原生入口；无变化知识是否不再重做、无效调用和重复文本是否减少、根因修复是否完整、图形总成本是否不升。统一 AI 入口是用户选择，不把“零 AI 会话”作为接入性能指标。

SVG 日常总成本按生成、登记、检查、预览、返修和交付全过程核，人工操作不能增加。不同指标有升有降时不能只取下降项宣布成功；自然波动或证据不足时不判优先成立。维护阶段对照图不进入日常业务双版本试画，开发接线成本与日常运行成本分开登记。定向生成和自然选型分栏报告；候选场景未证明优势时保持未验证，不依据模型名称或单个演示预判。

## 4. 收口与未验证项

交回按旧职责→新承担者→消费者→保留覆盖→退出证据核对。独立 /story adapt、登记、跳板、重复安装/物化和失效指路一起退出；不能留下无人调用的旧 helper，也不能删掉仍承担发布或保护的共用能力。旧金样按 R1 的审定和验证条件切换，历史探索保留不算第二套现行正本。

未来发布枚举、知识加载、对接调用/工程根、模板装配、计量根及维护规约按 R2 §7 一并核对；冻结夹具不得变成另一个日常维护源。

Framework 和 Extension 分别报告实际新增、复用、迁移与删除；职责搬移不等于整体成本下降，额度依总览和维护契约核定。原生接入和 Markdown 审查等依赖未闭合时，对应能力如实未验收，不能靠绕过检查或伪造状态放行。

真实 CLI、内网接口、设备、Coding 及发布各按授权和实际证据报告；本轮文档验证不替代。未验证项单列，用户按现有评分协议判断消费效果，不以格式或链接通过代替产品完成。
