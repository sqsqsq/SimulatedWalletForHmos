# R4 收件箱子目录导入

2026-10-10 用户提出，归入本版。收件箱是人工补料的唯一入料口，补料常以整目录形态出现：一批会议记录、一套界面稿、一组逐日日志。当前机制只认收件箱顶层的文件，模型只好把目录里的文件复制平铺到 inbox 顶层再归类导入——一次没有信息增量的复制，还破坏「原文件留在收件箱存档」的原样。本诉求让导入链按目录原样收料：子目录里的文件按相对路径识别、归类、转换与登记。实施排在 2.0.3 知识承接包 4（材料清单生产侧改动）落地之后即可立项、不等整版收口，接线由后续 2.1.0 plan 承接；本页定现状、目标行为、边界与完成条件。

## 1. 现状：平铺假设贯穿整条导入链

| 环节 | 现状 | 位置 |
|---|---|---|
| 收件扫描 | 只扫一层，目录整体不可见；注释明说「只扫一层……递归会把子目录里的无关文件卷进来」 | [importer.py `scan_sources`](../../../extensions/skills/story/scripts/core/materials/importer.py#L119-L126) |
| 归类件 | `.classify.json` 键是平铺文件名，写不下子目录里的文件 | [inbox_import.md 归类落盘](../../../extensions/skills/story/rules/inbox_import.md#L54-L61)、importer.py `read_classify` |
| 材料门禁 | 「料到了没有」经材料清单的 pending 判定，而清单同样按顶层扫描——子目录里的新料不算「到了」，人放了料被请「再放一次」 | [decisions.py 材料关卡](../../../extensions/skills/story/scripts/core/flow/decisions.py#L137-L144)、[registry.py `collect_sources`](../../../extensions/skills/story/scripts/core/materials/registry.py#L238-L256) |
| 材料清单 | 原件按文件名登记，跨目录同名会互相顶替 | registry.py `collect_sources`（条目键为 `p.name`） |
| update | 旧原件按文件名匹配、导入前移备份；归类件校验同口径只认平铺文件名 | [update.py 归类与旧原件](../../../extensions/skills/story/scripts/core/flow/update.py#L265-L282) |
| 用户指引 | 收件箱 README 与导入规则都只说「放进本目录」；「文件名即章节标题」「按文件名排序拼接」按平铺陈述 | [inbox-readme.md](../../../extensions/skills/story/templates/inbox-readme.md)、[inbox_import.md](../../../extensions/skills/story/rules/inbox_import.md) |

结果：放进 inbox 的目录对脚本完全不可见，只有靠模型把文件复制平铺，导入链才能继续；复制产生的副本与原目录并存，清单、门禁与「原文件留档」约定失去统一基准。

## 2. 目标行为

- 用户把整目录放进 inbox（任意深度），告知后导入照常走通：子目录里的文件按**相对 inbox 的路径**出现在材料盘点、归类件与导入结果里。
- 归类仍由模型按内容判断六类之一，写进归类件；路径只是事实的定位，不参与归类判断。
- 材料门禁把子目录里的新料算作「到了」；材料清单按相对路径登记原件，跨目录同名不再互撞——同名报错并点名两条路径。
- update 的比较、旧原件替换与备份沿用既有规则，落点从文件名换成相对路径。
- 收件箱 README 与导入规则写清子目录用法；「章节标题取自文件名」在子目录下的取法由实施在 plan 定，保持「同类多份的拼接顺序确定、重跑幂等」不变。

## 3. 设计决定

- **键与身份用相对路径**：归类件、清单条目、门禁计数、update 匹配统一以 inbox 内相对路径为键；平铺文件名天然是它自己的相对路径，现有平铺用法无迁移成本。
- **枚举递归、排序确定**：递归枚举后按相对路径排序；排除规则沿用（点文件与控制件不收、README 不收、空目录不产生条目）。
- **同名冲突显式报错**：不同子目录下的同名文件、以及会影响正文分节标题的跨目录同名文件主名，都点名两条路径请人改名或整理，不静默合并、不静默丢弃。
- **会议材料不受影响**：会议版本按原件内容指纹留存（[meeting.py `version_dir`](../../../extensions/skills/story/scripts/core/materials/meeting.py#L52-L54)），与来源路径无关；子目录支持后，多目录下的会议材料自动获得同一留存能力。
- **路径口径唯一**：登记用 POSIX 风格相对路径；非法字符、超长路径等按现有失败口径报错，不做静默降级。

## 4. 边界与非目标

- 不解压压缩包：zip 等归档是否自动展开另行按真实需求立项，不在本诉求内。
- 不改 `ux-reference/`、`assets/` 的顶层平铺布局：那是材料汇入后的权威落点，Framework 对 `ux-reference/` 的扫描非递归，属 Framework 侧能力，不在本仓诉求内。
- 不按目录名自动归类、不引入目录级归类配置；归类判断仍在模型。
- 不做新旧双轨：归类件、清单与门禁只有一套相对路径口径。

## 7. 完成条件

| 能力 | 必须具备的证据 |
|---|---|
| 子目录导入 | 离线夹具：多层目录整体导入，正文拼接顺序与相对路径排序一致；重跑幂等 |
| 门禁与清单 | 子目录新料被算作「到了」；清单按相对路径登记，跨目录同名报错点名两条路径 |

| 指引一致 | 收件箱 README、导入规则与材料盘点状态表写出子目录用法，无残留「只能放顶层文件」的表述 |
| 原能力保持 | 平铺用法、六类归类、UX 图登记、会议版本留存与备份恢复全部照旧成立 |
