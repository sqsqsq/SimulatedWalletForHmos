# 2.1.0：跨仓分发、原生接入与 SVG 增强

2026-10-07，按用户确认的版本重整更新现行范围。本轮只改规格与方案，不实施产品、改 Framework、切金样、跑新 CLI 或发布。原需求未删除，迁移归属见 [版本承接表](../2.0.3/05-版本承接对照.md)。

## 1. 本版目标与有效决定

本版交付两类增强：跨仓安装升级准确、省事；在有实际效果和成本依据的场景提供 SVG 表达与完整交付。一般成文质量、跨产物语义、独立审查效果及需求执行效率已迁入 [2.0.3](../2.0.3/00-版本范围.md)，本版引用其标准并核保持，不重复建设。

原已确认的接入流程保持：维护者只发布机制包 xxx/；业务维护者首次另从内网 Wiki 取得 adapters 并放在同级目录；日常只替换 xxx/，保留 adapters、knowledge 与目标信息；随后 AI 执行一次 `/extension materialize` 完成首装或升级，不要求独立 `/story adapt`、状态查询或人工完成标记。

根 extensions/xxx 是机制唯一开发/发布源；Demo 的 knowledge 与本地替身 adapters 各保留唯一维护源，Demo 是示例工程与测试底座，不要求每次机制改动都同步。内网 adapters 独立统一维护，契约未变且无自身修复时不重复分发。R2 统一维护目录所有权和装配要求。

图形方面，用户下载 Markdown 与本地图片后用编辑器阅读。已验证更清楚且日常总成本不增加的场景可直接优先 SVG，不以 Mermaid 先失败为前提，也不要求日常双版试画。没有证据时只声明支持，不宣称 SVG 优势。

## 3. 实施顺序与依赖

资源交付已定为 [R3 §4](03-SVG表达与交付/需求.md#4-图形交付合同) 的同版本三件 Markdown 与资源 zip，系统侧需真实二进制附件能力；SVG 签收按 R3 §6 的六类指导、至少一条完整生产链、优先场景及正式自然选型分别验。正式 Case 未自然选 SVG 不自动失败，但不能用它代替定向端到端证据。

外部依赖明确保留：Framework F1/F2 的实际接口/存储合同，以及系统 adapters 二进制附件能力。未交付时阻塞各自接线/系统完整图形交付，不由实施者猜 API 或用 Markdown-only 路径冒充。具体代码接线待后续 2.1.0 plan；本轮只完善 spec，不写该版本 plan。

1. 核实际接入基线，定 R2 上游两项接缝的真实接口、所有权和存储合同；并引用 2.0.3 的已审语义输入为 SVG 候选准备。
2. 上游发布件到位后实施三目录与原生接入，迁移真实消费者及有效保护，再退出独立 adapt。缺接缝不能只删旧路由。
3. SVG 的独立维护验证可与接入工作并行；按六类指导和两 Case 候选分别核结构、渲染、语义及日常总成本，不强迫全部需求用 SVG。
4. 验本版安装/升级/图形和保持性，签收实际范围；发布与内网验证按授权。

R2 依赖 Framework 支持机制与目标内容分离读取，以及原生 extension Skill 消费接入要求。Story 专属独立审查沿 2.0.2 实际合同与 2.0.3 效果核验，不再将旧通用代码审查的 Markdown 引用问题作为本版整体前置；知识适配若有独立审查需求，先核真实对象/现有入口的适用范围，不能伪造 Feature 或新建通用审查平台。

两 Case 修订稿与效果正本切换由 2.0.3 R1/R4 负责，本版仅消费审定结果。未完成或接口未交付按对应工作声明，不从“核心链可运行”推出已全验收。维护范围仍为 interactive。

## 4. 预算、退出与历史

本次文档重整产品 G/X=0。原历史新增 1300/退出650 估算对应旧组合范围，不能当现行批准额度。产品实施前按 AGENTS §5 核实际基线与累计、分别列 Framework/Extension 本版 G/X、峰值和完成量；目录移动不算净减，分版不重置累计。

R2 的旧路由/登记/跳板/重复安装物化与失效指路一起退出，知识方法、保护及发布能力交新消费者；R3 不另建 SVG 登记或固定返修机制。正常测试与业务覆盖保留。预算和退出细则分别见 R2、R4。

当前要求只在本总览与 R2/R3/R4。原始基底数据、迁移清单与当时的事实核对集中在[历史参考](历史参考/README.md)，只用于追溯。迁出的要求在 2.0.3 维护；本目录不保留迁出需求的正文或跳转文件。
