# 2.1.0 完整规格与实施顺序

2026-10-01。维护设计者按用户确认的《落实三目录分发、Demo 职责与 SVG 测试安排》更新当前规格。本轮只交付文档，不实施产品、修改 Framework、替换金样或启动真实 CLI。

## 1. 目标与有效决定

2.1.0 交付两个结果：跨仓安装升级准确、省事；需求产物的内容与表达稳定达到好的形态。前者以用户实际操作是否减少衡量，后者同时要求事实和决定可靠、同类信息组织清楚、返修成本合理。

固定用户流程是：Extension 维护者只发布机制包 xxx/；首次接入时，业务维护者另从内网 Wiki 获取 adapters，放入同级目录；日常升级只替换 xxx/，保留 adapters、knowledge 和目标信息；随后让 AI 执行一次 `/extension materialize` 完成首装或升级。唯一交付图与所有权在 R2；不再要求用户运行独立 `/story adapt` 或 Story 安装、状态查询、完成标记命令。

用户已确认：内网真实 adapters 统一维护、独立分发，仅契约变化或自身修复时更新；评审人下载 Markdown 和本地图片后用编辑器阅读；稳定性包括内容与表达，允许有理由的变化；两 Case 新金样经独立审核和修订后接替旧效果基线。SVG 在已验证效果更好且日常总成本不增加的场景优先，不以 Mermaid 先失败为前提；一次性接线受版本预算控制。

根 extensions/xxx 是机制唯一开发与发布来源。Demo 的 knowledge 和本地替身 adapters 各留一份维护源；Demo 保留示例工程和测试底座职责，不要求每次机制修改或发布都同步。目录和装配规则由 R2 统一规定。两个 Case 的 SVG 候选及维护对照/正式自然选型分别在 R3/R4 登记，效果与成本待后续授权实测判断。

2.0.x 继续承担蓝图适配和原有能力保持。本轮开始的只读快照为 `11ea51056ad19346083c7f0012cf4a0630c3318a`，步骤 3 二次返修已提交，本轮不代其验收；实际完成状态由其维护团队判断。[2.0 版本需求](../2.0.0/00-版本需求与结论.md)及[实施总览](../../plan/2.0.0/01-实施总览与协作合同.md)保持原有权威，本轮不修改。

## 3. 实施顺序、依赖与完成条件

| 步骤 | 工作 | 完成条件 |
|---|---|---|
| 1：质量基线与接入合同 | 按 R1 修订两 Case；按 R2 明确目录所有权、责任交接和 Framework 两项最小接缝 | 金样来源、决定状态和表达基线清楚，修订稿经用户审定；上游可据接入合同实现，未把声明当执行能力 |
| 2：接入能力落地 | 接收已验证的 Framework 能力；迁移三目录与 Demo 来源、调用和装配；撤销独立 adapt 及重复物化编排 | 首装独立取得机制与 adapters 后可接入；日常只替换机制；模板只装开发机制，知识与替身来源正确 |
| 3：质量与图形优化 | 按已定位差距改进成文；修正 Case 语义后分别做 SVG 定向对照与正式自然选型验证 | 正常内容与表达保持；SVG 优先场景有真实效果和成本证据，未生成 SVG 的运行如实记未覆盖 |
| 4：综合验收 | 验证指定交付流程、两 Case、成本与覆盖；切换金样及实际消费者 | 被替代入口和重复职责退出，原有保护与业务覆盖保持，完成结论与实际证据相符 |

步骤 1 的金样和上游接入合同可独立推进；步骤 3 不依赖接入能力的部分无需等步骤 2。步骤 4 等相关工作完成。2.0 的金样装配迁移、来源绑定、恢复及阶段承接仍归原团队，本版只核保持，不重复实现。

R2 依赖 Framework 支持“机制与目标内容分离读取”和“原生 extension Skill 消费接入要求”；当前未接通，不能只删旧指令就签收。独立文档审查还须核已知 [Markdown 引用问题](../../plan/2.0.0/评审意见/2026-09-30-Framework3.1专项审查文件引用问题.md)的实际接入结果；不能豁免原生失败、修改 vendored 副本或另建 Story 旁路。所有能力仍限定 interactive。

本轮改变了实际承担者并撤销部分职责，不直接沿用上表额度或宣布总成本下降。产品实施方案须分别列 Framework 的通用能力新增/复用/退出和 Extension 的方法迁移/接线/旧实现退出；再以验收后的实际发布基线重测、估算峰值和完成量。未来计量根随机制迁到 extensions/xxx，并保持原算法和分类口径；知识及 adapters 原本属于排除范围，移出或方法移动不算净减，挪到 Framework 不算整体工作消失，原始估算与后续确认保留追踪。

退场对象是独立 `/story adapt` 路由和 Skill/跳板、重复安装/入口物化编排，以及此前拟增的 Story 专属状态和人工标记步骤。有效知识方法、演进要求、必要检查与完成记录由 R2 的新消费者承担；`/story` 需求业务、原有保护和回归保持。金样旧正本按 R1/R4 的承接条件退出。

本轮实际写入仅限获准 spec 目录，集中在 2.1.0 的有效规格和本轮交回。R1、原始探索、迁移清单、已完成记录与 2.0 文件保持不变；Extension 和 Framework 产品实现均未改动，本轮产品新增/删除均为 0。
