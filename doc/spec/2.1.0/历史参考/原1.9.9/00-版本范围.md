# 1.9.9 版本范围

2026-09-27 用户授权。本版聚焦 **story adapt 的移植能力**：adapt 的设计目的是让 extension 在不同业务代码仓之间快速移植适配，本版基于当日完成的功能盘点与设计讨论，把这一目的从隐含实现显式化为交付面规则、可验收的能力增量与可观测的移植成本。方案细化（拆步、逐文件动作、预算计量）另立 `test/story/plan/1.9.9/`，本页登记现状、诉求、范围与完成条件，不构成实施或真实 CLI 测试的启动授权。

**前置依赖**：1.9.8 仓库结构重构落地（extension 源位于根 `extensions/`、维护域位于 `test/`、bridges 登记映射化）——本版在其上实施，路径按落地后形态书写。

| 层 | 能力 | 现状 | 评 |

| L5 知识引导 | 指导目标仓模型从自己的代码识别并生成合规知识 | 方法页完整（读者决定倒推识别、取证规则、四格判定、走查标准、人定范围）；`selfCheck` 结构校验接入（kind×form） | **弱——本版主攻**：识别完备性靠走查兜底、无穷尽保证；选格正确性/证据真实性/内容质量无机制核验、无独立语义审查；`selfCheck` 只证"可加载、结构成立" |

## 2. 设计目的与推进节奏（用户 2026-09-27 确认）

- **设计目的**：adapt 让 extension 在不同业务代码仓之间**更快地移植适配**。移植工作流四阶段：到达即用（机制+入口+身份）→ 适配主体（知识+对接层）→ 演进可续 → 移植成本可见。
- **推进节奏**：**首次移植求准确**——目标知识由人定范围、模型按目标仓真实代码取证走查、画像与知识停一次经人确认后交付，不以速度换准确；**升级求快**——机制面自动完成不停等；**知识层有变更才介入知识适配**（演进条目晚于目标 `adapted_for`），介入时保持同样准确要求；知识层无变更时不问人。
- **现状判定**：该节奏已由现行实现承载（升级不停等、条目为空不问人、知识条目驱动才介入、条目定向修订而非全量盘点）。本版将其**显式化为交付面规则与验收口径**，不改脚本语义；显式化的价值是让执行模型在升级场景不过度求全（不重新全量盘点知识）。
- **设计张力（有意接受）**：移植最快的捷径是照抄 Demo 或其他业务仓的知识，被所有权规则封死（"不灌入或对照 Demo 知识"、首装知识清单为空、知识归目标维护）。知识生产无法机械化加速，合法提速路径只有方法启发式更好、错误更早发现、执行模型读码更准。
- **交互时序**：四类场景下人、执行模型、业务代码仓、extension 包的交互时序图与交互不变量见 [01-场景交互时序](01-场景交互时序.md)。

## 4. 验收边界

- **离线证明**：T1/T2/T3 的方法页与 SKILL 修订和现行实现行为一致（升级场景无重新盘点指令、首装范围含首跑集）；T5 `--status` 对 demo 或 fixture 目标输出字段与真源一致、只读（不写任何文件）；盘点表结构可核（每阶段有决定类型与形态映射）；`node --check` 全过；adapt 相关离线测试全绿。
- **T8 SVG 通道**：fixture 正反例下检查器判定可复算（well-formed/viewBox/文本溢出近似/transform 限制，FAIL 即报错不静默）；不写 SVG 的产物行为零变化（mermaid 默认回归）；SVG 走既有图片登记与归档送审链（与 PNG 同权）；写法指导落地后模型产出的样例图经检查器全过。
- **T7 金样**：按 [02-金样优化](02-金样优化.md) §4 各步验收；锚经生产入口搭工作区，门禁、story-build check 与审查前检查全部通过并有测试守住。
- **审查证明**：T4 对 demo（或 fixture 目标）的激活知识跑一次独立语义审查，输出"能否支撑对应阶段决定"的逐项结论。
- **实跑证明**：T6 的移植成本记录依赖真实移植（demo 或真实业务仓），按用户授权启动并按 TEST 协议执行；观测值如实记录，不外推。
- **预算**：extensions 侧变更限于 SKILL/方法页文字修订、`--status` 新增与 T8 的规则/检查脚本新增（T8 量级：图规则与写法指导约 40 行、检查脚本约 120 行、测试约 200 行，待 plan 登记口径）；机制面语义零变化（L1/L2/L4/L7 不重写）。
