## 已定的产品职责

- **蓝图设计与独立读稿。** 主 agent 完成蓝图写作、问询和必要调和，再基于有效设计写 Story。用户选择沿用已有独立读稿，检查最终稿是否忠实传递已定事实、授权和目标，流程能否读懂，异常与验收是否一致。设计完整性由蓝图作者与问询承担。1.9.9 在同一 Spec 阶段审整组产物；2.x 拆出业务读稿后，设计者又把“原始依据到蓝图”的整层检查留给 Story，扩大了读者职责。蓝图已定“失败可人工受理”而稿中写成“自动拒绝”，由作者纠正稿件；读稿时发现蓝图自身矛盾，则指出具体依据，回蓝图负责方处理。
- **知识与依据。** 按本阶段要作的决定给材料。承接已定规约时给义务、责任对象与可回查出处；需要解释、判断冲突或选型时给相关原文。多条规约因同一条件不适用，可列明条目并合写一次理由，例外、冲突及待定项分别说明。
- **报告接收。** 现有宿主若能确认本轮读者已完成、指定文件确是它写完的完整报告，作者可直接读取原件。当前 DSH 的实际完成依据尚待核实。文件存在或接收后的摘要相等，只能证明局部事实。
- **正常使用与维护检查。** 产品保护正常需求开发和交付中可能发生的损失。发布正文成功、附件上传失败及远端出现人工修改，都有自然发生的路径，应保住外发依据和人工原件。跨版本迁移尚未完成的需求单排除在外。只靠手工破坏目录才能触发的情形，不再据此增加功能；已有专用分支按正常使用者和真实用途核去留。防过拟合由维护者排查、清理并用不同题材复核。

## story-knowledge 是否保留

**设计者建议：保留一个很短的 Feature 阶段入口，退出重复编排。** 必需的是阶段作者在动笔前拿到本单位的已定决定、义务以及解决当前问题所需的知识。Framework 没有规定必须有名为 `story-knowledge` 的 Skill。保留现有名字与绑定的理由是原生直接进入 Spec、Plan、Coding、Review、UT、Testing 的作者都能收到同一个动作入口，包括跳过 `/story` 直接做施工的情况；用户无需手动运行这个命令。本节是设计建议，尚未实现。

| 实际入口 | Framework 已做什么 | Extension 增量与应退出的重复 |

| 施工单位阶段开始 | 正式 900c 的 `assembleKnowledge` 按阶段和受众产生知识路径、工程背景及阶段绑定；本次六个阶段均列出 13 个已激活文件，原生知识装配中这 13 项是路径，阶段前的 `skill story-knowledge` 是给模型的指令。 | 余额刷新 CU 的实际 Plan 任务指出由哪个设计对象承担 OBS-02、选中的模式角色、从原生选定契约取得的义务和共同验收，以及当前缺口。这些对照有用。任务又逐项展开 13 个知识索引、列出多项不适用判断，再给 2 份相关正文；现行指令要求先读送来的正文，也明确要求沿用已定结论。建议默认交已定义务、承担者、出处及必要解释；原生已有索引不再整表重列，无关排除理由留在蓝图，有待决、冲突或新事实时才展开。平铺 Feature 首次且尚无知识判断的情形，保留首次判断入口。[原生 Plan 输入](../../../../output/evidence/2.0.6-knowledge-and-first-entry/probe-_qpyrdlq/native-plan.txt) · [实际 Plan 任务](../../../../output/evidence/2.0.6-knowledge-and-first-entry/probe-_qpyrdlq/task-plan.txt) |

**合并对照。** 在隔离副本移除独立 Skill 的登记，将实际 Plan 的原生阶段绑定改指现有 `story`，原生成功渲染 `skill story`。这证明名称可以替换；它没有把知识命令或当前 CU 的任务自动带入。现有 Story 主入口还包括取材、成文、更新和交付。现在把六阶段都引到这个大入口，需要改造主入口分流，或让直接进入施工的模型再读整份 Story 编排。保留薄入口改动更小。没有证据需要为此新建代理、原生钩子或上游接口。[替代绑定的实际输出](../../../../output/evidence/2.0.6-knowledge-and-first-entry/probe-_qpyrdlq/existing-story-as-slot.txt)

**复验边界。** 在同一候选核原生直入 CU、平铺 Feature 初判、有已定判断的后续阶段、蓝图独立质询与预览，检查实际输入和产物，保证义务送达、真实缺口可见及计时归属正确。现有实验证实了重复投送和相互牵扯的指令；模型是否真把决定做了两遍、浪费多少时间，需从 CLI 实际读写与修订记录归因。阶段样本中实际取得了 Spec 和 Plan 正式任务，后四阶段缺少对应原生运行输入；对它们只确认阶段绑定，未移签后段运行效果。
