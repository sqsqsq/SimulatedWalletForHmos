# 2.0.6 版本范围

当前有效需求为[2.0.6 完整 Spec（修订 1）](2026-11-23-目录调整与适配.md)，本页保留版本协调与目录分工摘要。适用标准见[评价标准变更](评价标准变更.md)。两份 draft 保存调查原件与讨论过程，Spec 与本版判法供人审查并作为 Plan 输入。

## 目录与适配职责

发布与安装沿[共建方案 08 §6](../../project/2026-10-20-Maison共建讨论/08-Maison共建方案：谁做什么、东西怎么流转、怎么发版.md#6-发布物与安装)。本轮目录归属和三方交接的讨论来源见[外网发布、内网集成与业务升级](draft/2026-11-23-目录调整与就地适配.md#外网发布内网集成与业务升级)；本页摘要随正式 Spec 同步。

| 对象 | 2.0.6 要达到的结果 |
|---|---|
| 机制 | 发行包的 `extensions/base/` 与业务工程的 `doc/extensions/base/` 同构。安装后的扩展根仍为 `doc/extensions/`，Framework 从该根读取 `manifest.yaml` 并物化宿主入口。替换 base 时保留根 manifest，由就地 adapt 合并实际机制登记。 |
| 知识 | 业务知识及激活清单归工程，正式知识在 `base/` 同级的 `knowledge/`。适配模型参考随包的 `base/examples/knowledge/`，按真实工程写知识并更新登记；作者、阶段门和独审均能取得目标实际激活的知识。[随包忽略规则、清理时点与验收](draft/2026-11-23-目录调整与就地适配.md#样例随-base-分发适配成功后清理) |
| 对接层 | 外网发布物只交 base，外网项目知识样板和替身对接仅在 demo。内网发布仓的 Extensions 部分只放 base 和内网 adapters；导入外网发布物时只换 base，已有 adapters 保持原样。业务项目首装与升级均取内网发行包的 adapters。 |
| 适配 | 首装允许在根 manifest 一次配置。首装和每次升级都执行 Story adapt，更新项目知识、登记及适配版本；宿主入口应直接指向 base 内的真实 Skill。 |

**现有用户升级也在范围内。** 从当前混装布局走一次升级，核目标知识、激活项、对接实现、适配游标、目标身份、使用记录和宿主入口归属。切换前要能找到旧 manifest 和旧入口所有权。方案应明确哪一步取出业务内容、哪一步替换机制，使发行说明中的操作顺序对已有安装同样可用。1.x 在途需求沿共建方案的版本边界处理。

**目录与入口。** 根 manifest 与知识寻址保持原位，安装后没有旧的 `doc/extensions/skills/` 入口。900c 的公开物化命令在这一布局下无法通过现行 Skill 源路径校验。见[已确认的边界](draft/2026-11-23-目录调整与就地适配.md#首次取得-story-入口)。

## 使用者反馈与设计判断

08 §6.3 原定业务工程是 Git 根。用户在本轮明确 2.0.6 只保留就地适配，业务工程可以位于 Git 工作树的子目录。例如 Git 根为 `repo/`，工程配置、Framework 与扩展位于 `repo/apps/pay/`。从已安装的 adapt 定位本工程配置，按配置找到扩展；从业务仓 A 向业务仓 B 直接安装或升级的旧入口退出。涉及覆盖时，在实际写入之前保护目标改动。[本轮 ask 决定、成因与验收场景](draft/2026-11-23-目录调整与就地适配.md)

当前 2.0.5 的 `adapt-scan.mjs` 对 `--apply` 有两道不同前置：工程根须等于 Git 顶层，且包根与目标根须不同；`--mark-adapted` 也拒绝同树。脚本还从来源工程向上找配置，从包内读取适配状态。将来替换 base 后在本工程适配时，这些来源、写入对象和版本依据都变了。只修改 `paths.extension_dir` 或放松一处相等判断，均不足以完成新流程。[隔离复现](../../../output/evidence/2.0.6-design-review/adapt-roots.json)

| 验收场景 | 观察结果 |
|---|---|
| Git 根工程、仓内子工程分别首装 | 发行包可供首装；在各自工程定位配置、生成入口、调用真实路径上的对接层、读取业务知识。子工程所在 Git 根和兄弟目录不接收本工程的产物。 |
| 已安装子工程替换 base、adapters 后就地升级、再执行一次 | 两个目录均为该内网发行包的版本。适配保留项目知识与身份；同版重入不重复派发已完成项。 |
| 同一外仓中出现脏文件 | 会覆盖的目标改动写前得到保护；兄弟工程的无关改动不阻断。按同一坐标比较工作树路径与工程写面，覆盖已有和未跟踪文件。发布复制步骤与 adapt 后置检查分别承担实际能保护的时点。 |
| 安装后实际消费 | 从物化入口启动 Story、取材、执行阶段钩子及独审。清理 base 内样例后，作者实际收到根 manifest 登记的项目知识；再次替换 base 和 adapters 并适配后复验同一链路。 |

职责纠偏结合 2.0.5 基线原件确定具体替换与退场；目录部分按原扩展根核 Story 入口和升级组合。正式方案按 AGENTS §5 核峰值、包预算与评价标准变更。当前为正式 Spec 修订 1，实施预算由后续 Plan 核定。[2.0.5 专项审视与 CLI 复审入口](../../plan/2.0.6/2026-11-23-目录调整与适配/评审意见/2026-11-23-2.0.5现状审视.md)
