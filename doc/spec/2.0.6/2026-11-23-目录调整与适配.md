# Story Extension 2.0.6 完整需求规格

**修订 2 · 2026-11-24 · 供人审查、供 Plan 接手。** 本版基于 2.0.5 当前开发候选，承接目录与适配、人工授权、蓝图和 Story 的职责纠偏，以及初段 CLI 暴露的真实问题。本文件是本版当前需求正本。实施设计与步骤见[同名 Plan 修订 4](../../plan/2.0.6/2026-11-23-目录调整与适配/00-实施方案.md)。[版本入口](00-版本范围.md) · [本版评价标准变更](评价标准变更.md)

## 一、交付目标与范围

接入方从内网发行包安装或更新 Story Extension，保住本项目知识、配置和使用记录，在选定宿主中直接使用 Story。业务需求方提供材料、在确有必要时作决定；设计作者在蓝图中完成取舍，Story 作者将已定事实、目标、限制和真实待决写成业务方能独立评审的稿件。读稿、施工、验收、发布与恢复使用同一有效版本，走到用户授权的实际终点。维护方能依据真实产物和同次运行原件判断效果及成本。

范围为既有 interactive 模式、系统单与本地单、显式 Story 入口、业务送审及用户授权的原生 CU 阶段、知识应用、就地适配、发布恢复和 usage/stats。以正式 1.9.9 的有效业务效果为保持基线，沿 2.0.5 已定职责迁移。本版解决已知偏差并验证原能力；跨版本迁移在途需求、普通开发会话自动发现 AR、中央模拟 CLI 时限改造、headless 模式、2.5 的新调度和统一 review 设想均不进入本版。已有安装升级属于本版，和迁移旧需求单分开。[2.0.5 能力全集](../2.0.5/01-Extension能力集与交互对照.md) · [2.0.5 有效产品合同](../2.0.5/2026-11-12-蓝图下的人工确认与范围收敛.md)

## 三、规格层：从交付到开发的完整行为

| 编号 | 使用者、触发与应得到的结果 |
|---|---|
| R01 三方发行与所有权 | 外网发行者只交付 `extensions/base/`，正式知识样板和替身 adapters 留在 demo；包中有 `base/examples/knowledge/` 和 `base/.gitignore`。内网发布仓的 Extensions 仅有 base 与内网 adapters，导入外网机制仅替换 base；对接层独立演进。业务工程首装或升级一次取得同一内网发行包的 base 与 adapters，运行时使用本项目知识和已安装的真实对接。 |
| R02 首装、升级与可用入口 | 业务工程可位于 Git 根或仓内子目录。安装后 `doc/extensions/manifest.yaml` 固定原位，`base/`、`knowledge/`、`adapters/` 同级，唯一 Story 源为 `base/skills/story/SKILL.md`。允许首装一次最小登记。首装和更新先执行 `framework-init`，选定宿主确实有可调用的 Story 入口，再执行 `/story adapt`。adapt 就地保留目标身份、已激活知识、人工改动、适配游标和真实记录；按差异更新知识、登记和版本。同版重入复用已完成工作。外发样例只供参考，`base/.gitignore` 的 `/examples/` 保护临时副本；完成并确认正式知识可用后清理，适配中断时能续做。当前发行包与内网升级均须防止在替换时先覆盖目标人工资产。 |
| R03 选路、材料和问人 | 在已进入 Story 的普通 interactive 开发流程，AR 单必须实际生成并登记 Story；非 AR 的微型、小型已授权开发时默认免写，微型按所需改动及适用验证结束，小型用短蓝图接实现与适用验证。只看方案即止于方案，明确业务送审则成文；已有 Story 的业务承诺变化按 update 同步。系统、本地单按来源取得材料，保留原件、采用版本、图和会议纠偏。材料选择只确认收取；疑问、附言转澄清。在首次需要作业务决定之前提供范围和有效事实，已定事项按原授权继续。 |
| R04 蓝图与有权决定 | 蓝图是共同设计真源，作者先对齐原始需求、人答、材料权限和知识；原生质询负责发现矛盾、缺失、与目标不符的设计，按影响收尾。有人回答时记录原话及出处，辨明其权力、议题、期限和效力；建议、事实、临时授权与长期待定可以共存。需要某个外部人决定时留责任及解锁条件。真正阻断当前目标且用户有权回答的问题集中问。新版人答改变业务承诺时，更新蓝图、Story、责任对象与验收；未获得相应决议的部分继续待定。 |
| R05 可单独评审的 Story | Story 作者据有效设计与事实组织整稿。读者只读成品即可说明目标、范围及排除项、参与方、条件、页面动作、成功/失败/未知、恢复责任、验收和待决。必要技术细节可查，精确内容用来源或附录承接，避免同一事实在多处独立定案。图、表、文字各承担合适的信息；凡实际成文，H1 为需求编号和名称，正文一级章（Markdown H2）固定为 1. 背景、2. 术语、3. 范围、4. 业务方案、5. 业务流程、6. 功能说明、7. 异常与恢复、8. 验收、9. 交付与上线、10. 附录。确不适用在原章简述依据。二级标题按业务对象、状态、条件、责任或关系提炼。作者先明确读者的判断任务，按需复用投影或补充图、条件表、对照表和短段；图前一段简短导读，图中承担主关系，图后列表只补图外且影响判断的事项，无补充可收束。复用已有载体，避免在图两侧或列表里重讲；投影造成的冗长回投影源处理。逐章写入、整体回看及人工原稿保护保持。维护口令、测试样例、无依据的接口、来源强度或数值不得变成业务承诺。 |
| R06 独立读稿与修订 | 先独立读最终 Story，再按具体疑点对已定事实、有效设计及必要原件。作者负责修漏写、写反、叙述不清和图文矛盾。读者遇上游冲突给出处、影响和责任，由蓝图侧修设计；常规 Story 审稿退出对蓝图材料取舍的第二轮通盘问询。局部改稿只核受影响事实、表达与相邻验收；影响贯穿全稿或无法继承前次依据时扩大核查。报告与本轮材料、读者完成、实际文件绑定；父作者不代写或为新稿换键。宿主能可靠证明同次写完的完整原件时可直接收原件；能力未证前保住现有防误收效果。 |
| R07 知识识别、应用与传递 | 项目事实提供工程证据，规约的命中和争议形成义务、例外或缺口，模式选择要有承担角色。设计阶段复用来源发现的有效判断。下游在决定前得到本单位义务、承担实体、共同验收、必要原文及出处；新对象、知识变化、需选型或冲突才重判适用部分。同因排除可合写一次并列明条目，例外、冲突、待定单列。平铺 Feature 首次判断、原生直入各阶段、合法零 CU 和多 CU 均有适用路径。安全、数据和统计的字段出处、允许出口、编号及承担方法要在实际契约与验证一致。 |
| R08 正向识别和结果未知 | 脚本读确定的结构、身份和关系，作者及独审判断语义。正常业务材料按职责段、独立列和真实方法识别本期统计点；允许合法附注、列序、多结果和多表。历史表保留其原用途。识别失败应指出位置和原因。由维护者用异题材排查过拟合；目标仓的知识作者依据本工程事实写适用示例。对未知结果按真实合同采用查询、回调、同身份重送或如实待定，不将超时写成失败或默认为新请求。 |
| R09 原生施工接续与授权终点 | 用户可以只要业务审阅、设计交接、独立 Spec/Plan 或完整开发。每个实际 CU 按原生选中的需求、设计、投影、范围和当前身份履责，保留直接进入、合法复用、零 CU 和真实中断恢复。设计换版前保护原请求及未完义务；找不到合法可接身份时在写入前停住。输入过期、权威投影缺失、证据未核或需要回设计时，指明最早负责方。不得把旧门直接复制为本轮通过、批量提升证据效力、代签准入或用后段代码改动把 Plan 判绿。 |
| R10 update、交付与恢复 | 现有 Story 的人工改稿、反馈、新材料或新授权从各自来源取得。共同底稿、当前本地稿和人工版本能区分，异段修改均保留；同段冲突或缺可核共同底稿时保原件，说明须裁定之处。只有意见时按其效力处理。实质修改回最早责任处并传到受影响部分，重新绑定当前稿；纯表达修改由作者负责。系统发布按有效授权、真实收件身份和交付集合发送、读回并保恢复凭据。材料投放、实际收到、正文已覆盖而附件失败、远端已被人修改分别有可见结果；本地单按本地终点交付。 |
| R11 正常工作成本与退出 | 把时间主要用在设计、成文和有效纠错。退出无实际消费者的重复核源、重复送全文、重复登记、笼统等待和维护样例限制；保留原件、实际外发版、人工改稿与正常失败恢复所需内容。存在疑似重复的附件、冻结说明、安装前后检查时，以写入者、使用者和损失决定是否退出；无实证不扩大极端场景。维持产品真实使用开始、轮次、完成态、Git 归属和独立 stats，未知保持未知。 |
| R12 维护观测与发布裁定 | 维护侧在隔离工程取证；原件、外发、送达、同次回复、审阅对象、各方实际修改、停止原因和墙钟可追溯。相对路径和动态拼接的越界按实际访问与结果核；测试宿主按授权终点答复，不把规划外的实现指令投给模型。独审、专用 verifier、确定性门、宿主等待分别计量。效果、成本、覆盖、限制和用户裁定各有来源；实际分布包、适配和运行对象可核为同一候选。 |

## 五、保持、待取得的事实与交接边界

- 保持材料库存与采用身份、实名来源和权限、会议原件与纠偏、条件式人工介入、原生设计质询、共同验收、独立人读、逐章有界成文、图义与可选 SVG、适用时的视觉审查、增量改稿、系统交付恢复、跨 CU 合法接续及真实 usage/stats。其来源分别为 1.9.9 已交效果、Framework 原生合同、2.0.5 正式需求及用户纠正；对应全量条目见本版标准。业务 Review、独立范围签、人工免审批、旧 PASS 换键、根下旧 Skill 转发位置均保持退出。历史 1.x 数字或写法限制只在已证与职责冲突时收窄，其他既有能力按保持核。
