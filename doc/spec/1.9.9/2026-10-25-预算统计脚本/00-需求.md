# 预算多维统计固定脚本：需求

> 1.9.9 发布后维护，版本号不变，不改 `extensions/` 与 demo。实施方案见[00-实施方案](../../../plan/1.9.9/2026-10-25-预算统计脚本/00-实施方案.md)。

## 1. 原始诉求

2026-10-25 用户原话：「我发现，在历次关于预算的统计中，执行者和设计者，每次都花了很长时间，且有时口径还不一致。是否可以增加固定脚本，按照多维度统计。你觉得是否可行，已经如何设计口空」（「已经如何设计口空」按上下文理解为「以及如何设计口径」）。

## 2. 已核事实

- `output/evidence/` 下有约 20 个一次性计量脚本，每次复制或重写。它们都 import `test/tests/test_mechanism_budget.py` 的算法，有效行算法本身没有分叉。
- 口径不一致来自同一版本里并存的几种没有固定名字的指标：两端差分 G3735/X908、逐提交累计 G5880/X3053、历史实施账约 G6273、包累计、预测与峰值（[整版预算重估 §2](../../../plan/1.9.9/2026-10-24-整版预算与实现复核/01-预算重估表.md)）。
- R 的分母和整版上限只写在台账注释和方案正文里；AGENTS §5 原文写明「R 的分级计算与确认检查尚未接线」。
- 「退出的是上一正式版保留行还是本版新增行」只能推理（[预算核对 §3](../../../plan/1.9.9/2026-10-24-发布前问题收敛/05-预算核对与复算.md)）。

## 3. 需求

一个固定的只读脚本，统计 AGENTS §5 计量范围内的机制规模与变化。每个指标都有固定名字和单一口径，并按以下维度拆开，不只给总量：

| 维度 | 取值 |
|---|---|
| 类型 | `prompts_md`、`hooks_mjs`、`scripts_mjs`、`scripts_py`、`data`，与台账 categories 一一对应 |
| 模块 | extensions 下的目录，可按层级汇总 |
| 文件 | 逐文件；文件状态为新增、删除或改动 |
| 变化性质 | G 中的移动或改缩进（`relocated`）；X 的来源（退出上一正式版保留行，或退出本版新增行） |
| 提交 | 逐个 first-parent 提交，工作区作最后一段 |
| 责任项 | 可选，台账为包声明的文件分组；多组共有的文件归「共享」，不重复计数 |

| 指标 | 口径 |
|---|---|
| `identity` | 两端 SHA、未提交的计量文件、计量与交付文件数和摘要 |
| `totals` | 两端有效行 |
| `endpoint` | 基线到对象一次差分的 G/X；**整版判定用它** |
| `series` / `invested` / `churn` | 逐提交相邻差分、它们的和，以及 invested − endpoint；**包的 R 分子是包起点以来的 invested** |
| `peak` | 各点按类型和总量各自的最大值及发生点 |
| `package` | 包起点到对象的 invested 与 endpoint，X 按来源拆开 |
| `control` | 整版 G 对上限、各类型对台账、包 R 档位与缺失的具名确认、责任项对预测；**只报告，不拦** |

## 4. 用户决定（2026-10-25）

- 归 1.9.9 发布后维护。
- 包 R 用包起点以来的逐提交累计（选项原文「包起点以来逐提交累计」）。
- 只报告，不做测试门禁。
- 以批准的计划直接实施，交回后提交。
- 追加：按 1.9.8 先例把台账按 1.9.9 发布实测收口为 closed，并把设计者的发布复评报告随本次提交入库。

## 5. 讨论与修订依据

- 计划初稿只写了指标名，没有逐维度展开。用户指出「方案中似乎只有总量，没有按类型详细分类统计」；随后补上维度表和按类型的示意表，每个指标都标明按哪些维度拆开。
- 计划里把 `gx_split` 口径叫作「只换缩进」。实施时核到它按同文件删掉又原样加回的行计数，也包括移动，因此改名为 `relocated`（移动或改缩进）。

## 6. 验收

- 合成 git 仓的独立算例覆盖 endpoint、series、invested、churn、peak、未提交识别、X 来源、R 档位与确认、责任项和 control。
- 在本仓重现已审事实：2fb4c304→b4fbf433 为 14124→17042、G3866/X948 及五类数值；2fb4c304→1c541aa8 为 G3735/X908、逐提交 G5880/X3053、26 段。
- 有效行算法只有一处真源，`test_mechanism_budget` 计数不变。
