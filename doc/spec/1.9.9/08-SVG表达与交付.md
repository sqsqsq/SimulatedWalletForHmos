## 1. 进入条件与职责

先解决事实、决定与关系问题，再比较不同图形表达；不能用 SVG 美观掩盖业务错误。质量标准按 [00 口径条款](00-版本范围.md)，不另写一份。模型决定抽象层级、信息分组、重点、布局及必要图型，不得每次从零猜语义表达规则；指导不固定颜色、坐标、节点数或整图模板，不要求先后遍历全部图型，不建设通用布局引擎。超出六类的图仅按实际需求和现有能力处理，不以本次 SVG 接入自动新增支持承诺。

## 2. 派生图身份与重审（评审修正项）

1.x 现状不能按「PNG 已有完整链，SVG 同权即可」实施：[importer.py](../../../extensions/skills/story/scripts/core/materials/importer.py) 的 `IMAGE_EXTS` 不含 SVG；[images.mjs](../../../extensions/skills/story/scripts/core/story/images.mjs) 区分原材料图片与 Mermaid 图源承接；[registry.py](../../../extensions/skills/story/scripts/core/materials/registry.py) 的 `collect_materials` 枚举 `assets/` 并把其身份计入材料 digest——把作者画的 SVG 直接放进 assets，会把自有产出当上游材料变化，触发新材料轮次。

- **区分「输入原图」与「作者派生图」**：原图沿材料 digest；派生图属于成文产物，来源指向当前材料或规格，不进入上游材料 digest。
- **登记复用现有图形身份与说明入口**，扩充其来源类型与产物指纹；不新增 SVG 专属状态机。存放路径与共用登记字段在实施分册定案，不放入被 registry 全扫的目录。
- **图字节改变使现有成文/审查依据过期**，回既有重审路径：只改图不改正文时旧审查失效并重派审；上游输入未变时不重启材料范围判断，正文未变的其余产物不连带重审。
- **Mermaid 转为 SVG 后仍须保有上游关系的承接证据**，不被现有「只能围栏带图源」的承接规则拒绝；相应限制退出，Mermaid 原能力保留。

## 3. 六类 SVG 指导

复用现有图形用途选择（[story-write.md](../../../extensions/skills/story/phases/story-write.md)）与 [历史图型盘点](../1.9.4/2026-09-20-story人读表达增强/参考/图型全量示例.md)，按实际使用的语义分六类补指导，不重新扩成全图表平台：

| 图形用途与适用条件 | SVG 组织指导 | 中性示例题材 | 易错语义与检查要点 |
|---|---|---|---|
| 流程与分支：有实际分流/回流 | 主线清楚，复杂分支分区，多责任时可用泳道 | 资料申请、补件、批准或退回 | 条件写明，分支有去向，回流接回正确位置；不凭布局增加业务分支 |
| 时序交互：先后、等待和失败责任需分清 | 参与方横排、时间纵向；调用与返回容易辨认 | 预约请求、名额确认、通知结果 | 消息起止方、顺序、等待、响应及失败处理一致；不把不同执行方混成一条线 |
| 状态与动作：互斥状态及条件迁移 | 状态节点、带触发/条件的迁移箭头，必要时分组 | 申请草稿、待审、通过、撤回 | 初始/终止和合法迁移有据，动作不能自动变状态，不给终态增加无依据出口 |
| 对象关系：归属和数量容易读混 | 对象卡片及明确命名的关系连接 | 场馆、房间、预约记录 | 名称、方向与已知数量约束准确，不补造未提供的基数或字段 |
| 架构与责任边界：跨边界交接 | 按真实边界分区，突出跨区连接 | 前台、审批、通知服务的职责 | 所有权、依赖方向和数据交接清楚；分区美观不能掩盖真实责任 |
| 依赖与开放顺序：有前置阻塞 | 前置到后继排列，并行项并排 | 基础能力、业务接入、开放验证 | 依赖与并行关系有据，不因排版制造先后，也不虚构日期 |

每类产品指导包含适用条件、一份中性示例、易错语义与检查要点；示例展示可用形态而非固定答案。上表题材是维护验证输入范围，不含测试 Case 的答案；后续实际 SVG 示例必须验证后才交付作者。

## 4. 选型以效果和日常总成本为准

- 已验证 SVG 更清楚且日常总成本不增加的场景，直接优先 SVG；不要求先画 Mermaid 失败，不要求日常生成两版再比较。
- 效果相当时选生成、检查和维护更简单的形式；没有足够证据的图型不预设 SVG 优先。
- 不是把 Mermaid 语法换成 SVG 文件就自动改善效果，必须验证语义、布局与实际阅读。
- 「日常总成本」包括模型生成 token、处理耗时、登记和检查、预览、返修、打包交付与人工操作；不能只看画图时间或只挑下降的指标。一次性接线与指导建设计入维护预算，日常不增加用户必做步骤。证据不足时只声明支持能力，不声明该场景已达到优先条件。

维护阶段对六类分别记录可读性与成本，只把成立的条件交给作者；单个流程图成功不能推广到全部图型。对照实验不进入每次业务执行流程。

## 5. 图形交付合同

### 5.1 本地交付集合

读者取得一个 `story-package.zip`，解压后用普通 Markdown 编辑器从 `<需求标识>/AR/story.md` 阅读。包内保留工程中的需求相对布局：`<需求>/AR/story.md`、`<需求>/AR/review.md`、`<需求>/spec/spec.md`（现有规格在 `spec/`，不在 `AR/` 下），加正文实际引用的图片/SVG 与三件文档中相对链接指向的已采用来源文件；只收当前已登记交付版本的引用闭包，不复制整个工程或 story-src 工作目录。报告历史、运行日志、凭据和维护金样不进入包。

三件的字节、材料身份和权限保持；打包不改写文案或重新生成。图片使用原有登记和来源身份，自绘 SVG 是派生表达（§2），不冒充原件。源图与 SVG 文件名采用已有资源名规则，不新增专属 SVG 编号/登记状态。相对链接以包内原路径解析，保留子目录；同名不同路径不丢文件、不拍平。

**越界引用在打包前报告**：三件中的链接可能指向过程材料或工程源码——出现不允许的链接时报告引用位置，由作者修正文表达或明确交付边界后重验；打包器不改文案，不无限递归复制工程，不静默断链。外部 URL 保留原地址并注明网络依赖；SVG 内部依赖同样解析；必要本地字体/嵌入图片必须可在解压后解析，不依赖维护机绝对路径。Markdown 资源解析复用已有可用能力并扩展实际需要的语法，不以单个正则宣称支持全部 Markdown。

**本地打包是确定性 helper**：输入为当前通过交付检查的三件及获准引用资源，输出 zip 与同批内容摘要；消费者是本地交付入口与后续 adapter。必要性在于自动解析依赖、保路径并核缺件，避免用户逐张拷图——只交 Markdown 无法满足离线资源完整性；helper 不承担写作、版本调度或审查判断。该新增能力按项目约定确认后实施。

### 5.2 系统交付与外部依赖

1.x 归档上传事实：[archive.js](../../../extensions/skills/story/scripts/adapters/archive.js) 只上传 Markdown（story 正文与 review 附件）；[state.py](../../../extensions/skills/story/scripts/core/flow/state.py) 的 `STORY_REGISTERED` 不含独立 SVG 文件；[lifecycle.py](../../../extensions/skills/story/scripts/core/flow/lifecycle.py) 的归档记录只有时间——**不存在可假定的资源上传、包摘要或资源版本回执**。

因此系统交付分三项分别报告：系统正文归档、图片展示、zip 附件上传。zip 下载与二进制附件依赖需求系统对接实现（adapters）的能力：先核真实系统接口与回执能力，再由 adapter 维护方实现（本仓计量范围排除 `adapters/`），回执必须能核文件字节与当前包一致，不能将二进制伪作文本。无接口证据时只交本地包，**系统资源交付单列未完成**，不用本地存在文件冒称已上传。沿现有 archive/发布记录与材料身份记录包的摘要及实际上传/读回结果，不新建发布状态机或第二份版本号。

### 5.3 更新、重试与恢复

任何正文、图或依赖资源变化，先按当前审查身份重验，再从同一当前版本重新打包；未变件沿用原内容。包的文件枚举、摘要及发布依据复用现有交付记录，打包时刻不独立改变审查对象、不制造新材料轮次（§2）。相同材料重跑应得到同一内容集合，不因压缩容器时间戳强制模型重审。远端部分写入/上传失败保持本地与上次有效记录，不记整体成功；失败保留上次有效包与人工意见；恢复不删除人工意见与历史审查，旧包和新正文不可被标为同版交付。用户不需要另行拷图片、手改链接或维护包内清单。

## 6. 三层验证

结构检查核 XML、viewBox、引用解析等**确定性事实，FAIL 阻断**；字符宽度近似只能提示风险，溢出、裁切、遮挡与连线交**实际渲染确认**，不一概机械判 FAIL——字体、对齐、transform 都影响结果，合法图形不得被机械门禁误拒。读审同时取得正文与图像，独立语义审查核关系、条件与责任。保持 Mermaid-only、无图与不适用图路径；失败报告问题和原责任，不加固定返修次数或图形异常状态机。SVG 走既有图片登记与归档送审链（与 PNG 同权，按 §2 派生图身份登记）。

## 7. 完成条件

| 能力 | 必须具备的证据 |
|---|---|
| 六类表达指导 | 每类至少一份已渲染和语义复核的中性例，覆盖相应关系；不靠固定坐标或 Case 专名 |
| 检查器 | fixture 正反例下确定性判定可复算（well-formed/viewBox/引用解析），FAIL 报错不静默；近似判断不阻断合法图形；不写 SVG 的产物行为零变化 |
| 派生图身份 | 作者改图不触发上游新材料轮次；图字节改变使成文/审查依据过期并重审；登记复用现有图形入口 |
| SVG 完整交付 | 至少一条通过当前生产入口实际生成 SVG 的定向维护运行，完成登记→审查→本地打包→下载解压阅读，并验证改图后的更新交付；不是手工摆文件就算通过 |
| 打包 | 同名不同路径不丢文件；缺资源与越界链接不产成功包且报告位置；重复打包内容集合一致；失败保留上次有效包与人工意见 |
| 优先选型 | 至少一个具体适用场景证明 SVG 更清楚且日常总成本不增加（配对证据），其余类型可保持非优先；不能外推全部图型 |
| 正式自然选型 | 测试 Case 获授权后正常运行，只给通用指导，记录选择与结果；未自然生成 SVG 不自动判失败，也不作为 SVG 端到端证据 |
| 原能力保持 | Mermaid-only、无图、图片来源、相对链接、更新与人工保护仍成立 |

定向完整交付已证明且正式自然选型合理时，即使正式 Case 都未选 SVG，也可签本版支持能力，但必须明确「自然选用 SVG 未覆盖」。成本按同语义/质量/终点的配对观察：总 token、有效处理时间与人工操作均不增加，至少一项改善或读者效果明确改善且成本持平；指标一升一降只记录权衡，不签「总成本不增加」。
