# 1.9.9 SVG 图形例外通道

2026-09-29，维护设计者。用户当日看过三形态对比 demo 后裁定：图形表达增强纳入 1.9.9（T8），方向为「手写 SVG 例外通道」，**默认仍是 mermaid，不替换**。本页登记依据、机制设计、分步与边界；方案细化（拆步实施、逐文件动作、预算登记）另立 plan。验证材料：`output/scratch/2026-09-29-graph-expression-demo/`（不入库：mermaid/SVG/HTML 三形态同内容对照 + 检查器雏形）。

## 1. 目标结果

1. 交付件的图形表达在 mermaid 不足处有合法出路：模型可产出**手写 SVG** 图，评审人拿到的是动线可控、角色语义清晰、失败分支与主路径视觉分离的图，而不是自动布局叠字的长图。
2. 不增加新的失真面：SVG 与 mermaid 各管各赢的场景（§3 选型规则），结构语义图（状态机/时序/实体）不受影响；SVG 必须过确定性检查，烂图不静默。
3. 复用既有机制面：图片引用、登记、归档送审链零新增概念，SVG 与 PNG 同权。

## 2. 依据（已核实事实）

- **交付链事实**：需求系统单据只承载 md 不承载图片（`test/cases/README.md` L43）；送审归档只上传 story.md 与 review.md 加图片目录（`test_material_rounds.py` L1220），评审人直接在归档件上批注回传——HTML/页面级形态进不了评审环节，2026-09-29 验证后裁定出局（00 §5 已登记）；md 内的图片引用（PNG/SVG 同权）与 mermaid 源码是评审人能拿到的全部图形形态。
- **mermaid 弱场景证据**：历史 110+ 份产物全部图均为 mermaid 可表达（无数据图、无复杂拓扑），但大流程图的自动布局在节点多、分支多时叠字错乱——demo 中同一 16 节点带 5 失败分支的流程，mermaid 竖向长图 vs SVG 蛇形两行+角色配色+失败分离，人读差距肉眼可判（用户 09-29 确认「html体验>svg>mermaid」并接受 svg 为交付内可行上限）。
- **手写风险与兜底证据**：检查器雏形在 demo 上第一轮即抓到一处文本越界风险，修复后 PASS——证明「手写图必有烂图、必须确定性检查兜底」成立（show-me-first 的同类思路在社区已验证）。

## 3. 机制设计

### 3.1 选型规则（写进 story-write.md 图类型选择表）

1. **默认 mermaid**：结构语义需要被精确核对的图（状态机、时序、实体关系、甘特）——语法约束即防错机制，SVG 手画放弃这层保护，不做替换。
2. **SVG 例外通道**，两个触发条件（模型语义判断，不设机械阈值）：
   - mermaid 语法正确但**布局已不可读**（节点多、交叉密、自动布局叠字——大流程图为主）；
   - 需要 mermaid 给不了的**语义视觉编码**（角色配色分区、失败分支与主路径分离、关键路径高亮）。
3. **禁手画**：数据类图（饼图/坐标图/甘特——手算坐标必然易错，业务数值惯例用表格）；一两个节点的小图（有序列表即可——选择表现有规则）。
4. **退回出口**：SVG 尝试后检查器连续两轮 FAIL、或模型判断布局仍不可控时，退回 mermaid 承载并在图后以列表补足分支语义，登记「该图曾尝试 SVG，退回原因」——退回不是失败，不重复尝试。执行模型（尤其小参数级）的手写布局稳定性是本通道的主要成本风险，此出口保证风险有界。
4. 同一信息点单图承载：SVG 与 mermaid 不混画同一张图；SVG 图同样遵守「每张图三件套」（图前一段讲过程、图、图后写图上没有的分支细节）。

### 3.2 写法指导（放 story-write.md 或其模板件，量级约 40 行）

- 布局模板：蛇形两行为默认动线（编号即阅读顺序）、泳道为多参与方场景备选；主路径实线、失败分支虚线红、关键结果金——与 demo 样例一致；
- 文字纪律：中文按字号实宽预留（13px 字号 ≈ 13px/字），卡内文字手动分行不依赖自动换行；
- 角色配色规范：蓝=用户操作、绿=端侧、紫=云侧、金=关键结果、红虚线=失败分支，配图例；
- 尺寸约定：viewBox 必填，建议宽度 ≤960（需求系统与 VSCode 预览的舒适区）。

### 3.3 确定性检查器（fail-loud，量级约 120 行）

判据全部可复算（雏形已验证）：
- well-formed：XML 可解析、根为 svg；
- viewBox：存在且 4 数合法；
- 文本溢出近似：text/tspan 按 x + 实宽估算与 viewBox 比，transform 文本记人工复核；
- 越界图形：rect/circle 坐标在 viewBox 内；
- 接线位置：作为 story-build 收口或交付门的一组判据（与图片引用解析判据同层），FAIL 即报错并给修法，不静默降级。

### 3.4 登记与送审复用

- SVG 文件放归档件图片目录（`story_image_dir` 合同既有机制），md 内 `![说明](路径)` 引用；
- 登记、caption、used 状态走既有 `materials.json` / `import_sources.py` 通道，不新增第二套；
- 归档红线（图片引用必须解析得到文件，failure-modes 既有判据）对 SVG 同判。

### 3.5 载体自查

- SVG 是 md 原生图片形态，不触碰 story-write.md L137（Markdown 扩展、HTML、折叠与交互不在载体）；
- 机制层零测试特征：选型规则与写法指导不含测试 Case 业务名，示例题材中性。

## 4. 分步

| 步 | 内容 | 验收 |
|---|---|---|
| S1 | 选型规则 + 写法指导落 story-write.md；SVG 加入图类型选择表（含禁手画情形与退回出口） | 规则与现行图纪律同源无冲突；样例图须由**执行模型实测产出**（非设计者手写）并经检查器全过——实测暴露布局能力不足时收紧模板或缓上该通道，不在上线后暴露 |
| S2 | 检查器实现并接入门禁（story-build/交付门判据）；fixture 正反例（合法 SVG、坏 XML、无 viewBox、文本溢出、越界图形、未引用） | 正反例判定可复算；FAIL 报错含定位与修法；不写 SVG 的产物行为零变化（mermaid 回归全绿） |
| S3 | 登记通道核验（materials.json/import_sources 对 SVG 的登记与 used 流转）+ 金样联动：T7 锚按 §5 决定是否加 SVG 实例 | SVG 与 PNG 同权走登记送审；金样处置按 T7 原则另行裁定 |

先后：S1 → S2 → S3。每步一次提交、一份交回。

## 5. 与其他部分的衔接

- **T7 金样**：金样不演示未接线机制——S2 接线完成前，金样现有图形（全部 mermaid）不动；接线后锚内 mermaid 布局已不可读的图（若有）是否改 SVG，按金样「每份改动经用户确认」原则另行裁定，不为演示新通道而改。
- **图片机制**：`import_sources.py`/`materials.json`/`ux-reference` 现有语义不变，SVG 只是新增的文件扩展名与一份检查判据。
- **1.9.4 预览件**：`doc/spec/1.9.4/2026-09-20-story人读表达增强/参考/图型全量示例.md` 的 mermaid 16 型盘点继续有效；本通道不重复盘点，只补 mermaid 之外的一行。

## 6. 不做（本通道边界内明确排除）

- HTML/页面级叙事形态（评审链拿不到——§2 事实）；
- 数据类图形的手画与专用图表库引入（无真实场景；数值用表格）；
- Excalidraw/drawio 等外部格式与 MCP 画布（产物格式需求系统不可展示、交互形态与管线交付不匹配）；
- 把现有 mermaid 图批量改写为 SVG（替换不是本通道目的；触发条件满足一处才允许一处）。
