# R5 adapt 移植能力（T1–T6）

2026-10-12 立项，沿用原 1.9.9（2026-09-27 用户授权）的范围与节奏裁定；该版未曾实施，本版在 1.x 上交付。同日按[需求评审](../../plan/1.9.9/2026-10-12-整体设计/00-需求评审与设计建议.md) §2.5/§3.3 修正：T2/T3 服从现行知识准入规则，T5 明确只读视图的事实边界。adapt 的设计目的是让 extension 在不同业务代码仓之间**更快地移植适配**。现状盘点（L1–L7 分层评级）见[历史参考原稿](历史参考/00-版本范围-20260927.md)——关键结论不变：adapt 当前是「安装工具 + 知识方法页」，不是知识生产系统，脚本对知识内容零判断；本版所有增强遵守这条边界，**不把语义判断塞进脚本**。四类场景的交互时序与不变量见 [01-场景交互时序](01-场景交互时序.md)。金样（原 T7）归 [R6](02-金样优化.md)，SVG（原 T8）归 [R4](08-SVG表达与交付.md)，升级分发链路（原 T9）不承接、留 2.1.0。

## 1. 设计目的与推进节奏（原稿裁定，继续有效）

- 移植工作流四阶段：到达即用（机制+入口+身份）→ 适配主体（知识+对接层）→ 演进可续 → 移植成本可见。
- **首次移植求准确**：目标知识由人定范围、模型按目标仓真实代码取证走查、画像与知识停一次经人确认后交付，不以速度换准确；**升级求快**：机制面自动完成不停等；**知识层有变更才介入知识适配**（演进条目晚于目标 `adapted_for`），介入时保持同样准确要求；知识层无变更时不问人。
- 该节奏已由现行实现承载（升级不停等、条目为空不问人、知识条目驱动才介入、条目定向修订而非全量盘点）；本版将其**显式化为交付面规则与验收口径**，不改脚本语义——价值是让执行模型在升级场景不过度求全（不重新全量盘点知识）。
- 设计张力（有意接受）：移植最快的捷径是照抄 Demo 或其他业务仓的知识，被所有权规则封死；知识生产无法机械化加速，合法提速路径只有方法启发式更好、错误更早发现、执行模型读码更准。

## 2. 本版目标（T1–T6）

| 事项 | 范围 | 要点 |
|---|---|---|
| T1 推进节奏显式化 | `SKILL.md` + 方法页 | 写明首装求准确/升级求快/知识层变更才介入；**升级场景的知识修订只按演进条目定向进行，不重新全量盘点知识**；`--check` 与知识自检仍分开报告 |
| T2 首装知识范围显式化（准确性） | 方法页 | 定义**首跑必需知识集**用于发现缺口：范围从当前升级主题与目标仓决定空间取得，**服从现行准入规则**——逐主题判断、首批每份最多 3 项、编码规范不进知识、模式仅按演进主题与相同依赖准入（[knowledge-adaptation.md](../../../extensions/skills/story-adaptation/reference/knowledge-adaptation.md) 及 1.9.8 后补判据为准）；不要求填满四格，有据不适用允许；覆盖判断三态「适用且已覆盖 / 有据不适用 / 缺口」，缺口记录并写明由目标维护者处理，不自动扩充、不假报就绪。旧 [03-知识范围定义](03-知识范围定义.md) 的「完整覆盖」与「从仓内惯用结构推导模式」不采用，该册保留为方法历史 |
| T3 识别完备性盘点表 | 方法页 | 按主题列「决定类型 → 应有知识形态（四格）→ 缺口显式登记」；盘点结论写在既有交回中，**不造第二份知识台账**；盘点表是启发式不是硬约束，不新增脚本判据 |
| T4 知识适配独立语义审查 | 流程 + 审查载体 | 在知识产物完成、交回适配完成**之前**进行：输入是目标激活知识、已定范围、对应源码/规范和待验证的正常需求；核有据性、阶段决定支撑、项目级边界与不适用理由；不把作者自评当审查结论；失败回适配作者修相应知识；缺独立执行能力时明确未审，不由同上下文自检代签。宿主调用入口实施前按 codex/opencode 实际可用能力核实，不复制阶段 verifier 调度框架 |
| T5 `--status` 聚合视图 | `adapt-scan.mjs` | 只读模式：复用 `knowledgeCheck`、版本比较、manifest 读取与 followUp 的纯计算部分，退出方法页内重复的手写检查片段；**不得调用含 `writeAdaptedFor` 的 `printFollowUp`**。输出当前事实与按当前游标可推导的建议；升级后另起进程丢失升级前起点（`INSTALLED` 在进程启动时读目标 version），历史完成情况不可恢复时明确未知并引用上次交回，**不以新增状态文件补洞**。未安装、依赖缺失、坏 manifest/坏知识清单分别报告，不误报「零知识且通过」；读前读后核文件集合与内容不变 |
| T6 移植成本观测 | 观测口径 + 实跑记录 | 记实际人工决策次数与首个需求 spec 闭环成本；现有两个计划确认点是流程设计，发生额外澄清或返修时照实计入，**「2 次」不是达标阈值**；实跑按用户授权启动并按 [TEST](../../../test/TEST.md) 协议执行，观测值如实记录、不外推 |

## 3. 机制落点（实施输入）

[SKILL.md](../../../extensions/skills/story-adaptation/SKILL.md)、[knowledge-adaptation.md](../../../extensions/skills/story-adaptation/reference/knowledge-adaptation.md) 与 [upgrade-changes.md](../../../extensions/skills/story-adaptation/reference/upgrade-changes.md)（方法页，升级演进记录不计预算）、[adapt-scan.mjs](../../../extensions/skills/story-adaptation/scripts/adapt-scan.mjs)（T5 只读模式，复用现有纯计算函数）、adapt 相关离线测试（`test_adapt_ownership.py`、`test_adapt_source_kinds.py` 行为约定保持）。

## 4. 完成条件

- **离线证明**：T1/T2/T3 的方法页与 SKILL 修订和现行实现行为一致（升级场景无重新盘点指令、首装范围按现行准入规则含首跑集与三态覆盖判断）；T5 `--status` 对 demo 或 fixture 目标输出与真源一致、只读（读前读后文件集合与内容不变、不写任何文件），未安装/坏清单路径分别报告；盘点表结构可核（每主题有决定类型与形态映射）；`node --check` 全过；adapt 相关离线测试全绿。
- **审查证明**：T4 对 demo（或 fixture 目标）的激活知识跑一次独立语义审查，输出「能否支撑对应阶段决定」的逐项结论；独立执行者与适配作者不同上下文。
- **实跑证明**：T6 的移植成本记录依赖真实移植（demo 或真实业务仓），按用户授权启动；观测值如实记录，不外推。

## 5. 边界

- 不改 Framework 本体；不改知识所有权（知识归目标维护、不灌入 Demo 知识）；脚本不承担知识内容质量判断。
- 不做多仓并行的移植调度系统、知识模板化参照等通用平台化能力；不改宿主入口分发的生产者。
- 对外适配准备不在本版启动目标仓升级路径改造（原 T9 方向留 2.1.0）；本版只服务「从已装发布版 adapt 到目标工程」的既有形态。
