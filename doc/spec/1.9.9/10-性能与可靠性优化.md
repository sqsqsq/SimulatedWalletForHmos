# R7 稳定性与性能优化

2026-10-12 立项。来源：用户 2026-09-29 提出的稳定性与性能优化诉求（性能 P1–P3、稳定性 S1–S3），当日授权的全量分析已完成并留档于 [04-稳定性与性能分析](04-稳定性与性能分析/00-分析方案.md)（62 个 suite、105 个 run、60 份产物快照、842 条门禁条目、223 份审查报告；[01-分析报告](04-稳定性与性能分析/01-分析报告.md)）。分析按其方案约定只做现象与归因、优化另立——本页即该立项：把报告中「现状仍在」的问题按其 C3 处置层分类落成本版需求。分析对象是 1.x 历史运行（1.9.0–1.9.8 + Framework 3.0.0），结论对本线直接适用。

## 1. 分析结论（本项的输入事实）

详见 [01-分析报告](04-稳定性与性能分析/01-分析报告.md)，立项直接引用的四条主结论：

1. **性能**：正常路径稳定（auto-topup p50 64 分钟，主体 30–90 分钟）；时间流失大头依次为审查对象自激循环（机制层）、真实语义返修、环境异常。「模型不稳定」不是主要矛盾。
2. **一次成文率 ≈41%（spec 审查）**；极端战役中约九成派审轮次的产物与已审对象逐字节一致——「写报告→材料变→新审查对象→再派审」的自激循环是第一成本成分。
3. **产物漂移的一半是规则高频演进的投影**（c 类 6/12 组）；现行真实自由度集中在门禁盲区 3.5 处与规则模糊带 5 处；门禁 PASS ≠ 形态最优。
4. **842 条 FAIL/WARN 前 6 项占 85%**，其中 MINOR 项 387 次反复出现——告警没有收敛出口。

## 3. 边界

- **不改 Framework 本体**：审查对象按材料寻址属 Framework 机制；本版只修 extensions 自身的引用方式（O11）并把已有合法出口写明（O1），不改 Framework 寻址行为。若实施证实该出口在 Framework 3.0.0 上不成立，报设计者裁定，不造 Framework 替身。
- **不重跑历史、不追改分析**：分析结论是输入事实；优化效果由后续授权实跑按 [00 口径条款](00-版本范围.md) 的配对口径观察，不预设阈值、不宣称统计收益。
- **c 类（规则演进投影）不立项**：产物漂移的一半来自规则高频变更，其处置是本版「方案一次列全、换道重走确认」的承接纪律与预算一次列全（[00 §1/§4](00-版本范围.md)），不是机制改动。
- 环境/基础设施异常（终检崩溃、API key 失效、worker_lost）不在本版：属装置与环境维护，O13 只承担可观察性。
- 不做无人值守能力；维护范围 interactive。
