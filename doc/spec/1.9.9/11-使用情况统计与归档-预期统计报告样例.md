## 4. 统计口径

- **统计对象与时间范围：** usage 中有记录即按使用 AI 框架编码的需求计数。各标题中的时间为相应需求关联 Git 提交的最早、最晚 committer 时间，不是立项到发布周期；只有一笔提交时起止相同。
- **业务版本：** 初始化时优先取需求明确版本，没有再取工程配置，冲突以需求为准，找不到归未知版本。
- **开发人与代码量：** 通过提交的 `[TicketNo:]` 唯一 AR / DTS 编号关联需求；开发人取 Git author，以邮箱去重。版本间人员可能重叠，全版本人数重新去重，不能直接相加。行数是关联提交变更量，不是 AI 生成量；按提交 SHA 去重，merge commit 不重复累计父分支改动。
- **步骤数量与占比：** 使用数按步骤节点存在计，完成数按 completed 计，表示该步骤完成过，不表示当前轮或整项需求已完成。使用占比 = 使用需求数 ÷ 相应统计范围内的 usage 需求数；步骤完成率 = 步骤完成过的需求数 ÷ 使用需求数。没有使用需求时完成率显示 —。一个需求可使用多个步骤，各步骤的占比与完成率不相加。
- **初始化环境与平均耗时：** 环境只反映初始化信息。每个环境组、每个步骤分别取“已完成且 spent 可核实”的需求，用其 spent 合计除以需求数；未使用、未完成及耗时未知不按 0 参与。spent 含已结束轮次内的等待与中断，按需求平均，不按轮次平均，不是 AI 活动工作时间；不同步骤不求总和，组间差异不单独证明模型性能优劣。
