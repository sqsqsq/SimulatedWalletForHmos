# Story Extension 功能全景

Story Extension 面向需求开发与评审：从需求单号起，整理材料、确认范围，生成规格、需求叙事与评审记录，承接评审意见与材料变化，并把工程知识带进后续设计、编码、检视与测试各阶段。

**版本状态**：本文对应 **1.9.8（待发布）**。维护仓的 `demo/` 当前装的仍是 1.9.7，发布 1.9.8 时更新。每版改了什么见各版发布说明（最新：[1.9.8](1.9.8.md)）；命令与操作步骤见[《story 使用指南》](story使用指南.md)，整体协作方式见[《需求交付流程》](需求交付流程.md)。历史版本当时的全量能力从对应版本的 Git 提交查。

「最近变化版本」写发布说明里最后一次改动这项能力的版本；「1.9.1 或更早」表示 1.9.1 之后的发布说明没有记录改动。「本版变化」只写 1.9.8 相对 1.9.7 的变化。

## 主要产物

需求目录是消费工程里的 `doc/features/<编号>/`：

| 产物 | 职责 |
|---|---|
| `RR/prd.md`、`SR/design.md` | 上游需求与整体方案（外部输入） |
| `AR/design.md` | 经范围确认形成的本部件需求输入，spec 的输入 |
| `spec/spec.md` 与需求目录根的 `acceptance.yaml` | 后续设计、实现和验证的依据 |
| `AR/story.md` | 面向评审者讲清完整需求、方案、行为与交付安排；归档的上传正文 |
| `AR/review.md` | 需要人审核的判断与待定事项，人工区归人 |
| `AR/story-src/story-template.md` | 本需求的整篇写作设计 |
| `AR/story-src/materials.json`、`story-flow.json` | 材料身份与版本；从 init 到归档的流程契约 |
| `AR/story-src/updates/<id>/` | 每轮 update 的执行前现场（`before/`）与 `update-notes.md` |
| `.backups/` | `cloud/` 为归档前的需求系统正文，`local/` 为本地文档备份 |

需求叙事由 AI 根据材料、规格、写作设计与已确认判断编写，附录部分内容由脚本从规格与知识判断投影；整篇不是规格的确定性转换。

## 依赖与边界

- **Framework**：基于 3.0.0 的公共扩展点接入，安装本扩展不修改 Framework。
- **需求系统**：业务工程要有自己的对接实现与访问配置；Demo 的对接脚本是本地模拟。
- **知识维护**：三类知识由目标工程按真实代码核实并维护，机制按激活清单使用。
- **运行范围**：有人参与的交互式流程；不覆盖 Framework 的 headless / goal 模式。
- **效果边界**：上面写的是机制提供的行为，不等于每次运行都做到。1.9.7 收口实跑还有这些没达成：update 轮内人的拍板没有经 `decide --update` 记进契约；评审意见与系统设计的安全口径冲突时模型直接采纳、没有问人；材料里写明还没定的事项没在需求叙事与评审记录里露出来；读机制源码次数未达到目标。1.9.8 没有改业务机制，这些仍然成立。
