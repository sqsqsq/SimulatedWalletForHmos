# Story Extension 1.9.0 发布说明

> 1.9 系列首版，之后各版在它之上做增量。本版基于 Framework 3.0.0。

**1.9.0 重点优化文档展示与跨工程复用**：Story 各章按内容关系组织表达，减少固定排版限制；安装升级明确区分公共机制、业务对接与目标知识；需求过程文件保留，便于后续排障与返修。

## 本版新增与优化

### 1. Story 展示形式按内容组织

十章的阅读职责保持稳定，具体小节与展示形式由内容决定：属性与约束、条件组合适合表格；过程与分支适合流程图；多方交互适合时序或泳道；状态变化适合状态图；原因和取舍用叙述解释。

本次调整覆盖全部章节：

- 取消固定段数、固定分支标签、预设页面槽位等排版要求，支持有页面与无页面能力的说明。
- 多个独立的入口、功能或数据对象可以分别说明管控与恢复措施，避免整项需求只套一份回退描述。
- 章草稿提供读者问题、组织提示和必要表头；按实际业务生成二、三级小节，不预填整套可选目录。
- 图、表、文字可以互补，章节间按内容职责衔接；保留流程总览、源图对应、验收追溯和附录契约投影。
- 附录允许在契约投影之外补充必要的单位说明与格式样例，投影仍以原始契约为准。

### 2. 安装升级与业务仓复用简化

公共流程脚本与业务对接实现分目录管理。正常升级按明确范围更新文件并检查安装结果，不重新分析目标业务或合并知识正文。

| 复用场景 | 本版行为 |
|---|---|
| Demo 仓向业务仓提供扩展 | 更新公共机制与指定入口，保留目标已有对接实现，不复制 Demo 替身 |
| 内网业务仓之间复用扩展 | 公共机制与共用对接实现一并更新，保留目标已有知识 |
| 目标首次接入 | 创建知识说明骨架，扫描目标仓形成部件画像，不复制来源仓业务知识 |
| 目标已有知识 | 保留知识正文、说明、画像及激活清单，升级不重新扫描画像 |

目标工程身份与无关配置保留。安装检查覆盖公共文件、指定入口和清单，允许目标采用自己的需求目录忽略策略及宿主入口文件。

### 3. 交付目录与过程文件职责分离

AR 根目录集中放置 `design.md`、`story.md`、`review.md`，以及需求系统对接层的 `detail.json`。流程记录、材料分析与其他辅助文件放入 `story-src/`。

成文登记保留章草稿和其他过程文件，便于核查文档生成过程与返修。需求系统归档仍只传需求叙事与评审记录，过程文件不随这条归档路径上传。

### 4. 公共指引与检查规则收敛

删除无消费者的旧适配模板和重复规则文件；移除部分固定业务例子及失效维护说明。作者与审查者从当前需求提取关键对象、条件和依据，减少对熟悉场景的依赖。

脚本保留结构、引用、编号与投影等确定性检查，展示是否清楚、内容是否遗漏或矛盾由独立 AI 检视。能力描述同时允许有工程依据的既有能力和有需求依据的计划新增能力。

## 已知边界

本版不包含会议转写的专门语义纠偏与结论提取。结构检查和独立 AI 检视辅助质量把关，需求取舍与最终评审仍由人负责。
