## 本版新增与优化

### 1. 使用记录与 `/story stats`（R8）

- 工程根新增使用记录 `doc/usage.json`，随代码提交。每个需求目录一个节点，记做完过的步骤（story、story update 与 Framework 六阶段）、各步累计耗时、
  `story update` 的收口轮数、最后活动的 Extension 与 Framework 版本，以及 AI 自报的工具与模型。
- 每个阶段开始前记开始（`usage.py --begin`），原生闭环后收尾（`usage.py --finalize`）。Spec、Plan 取任务包时自动记开始，Story 交付门自动收尾；
  Story 从取材前或返修前的开始算到登记成功，多轮累计。漏记开始的那一轮只记做完过，不拿文件时刻或检查时刻补耗时。
- 新命令 `/story stats`：脚本只从 `doc/usage.json` 与 Git 取事实，AI 按模板写出汇总与逐需求明细（步骤耗时、身份与版本、关联提交与新增/删除行数）；报告放在系统临时目录，不写进工程。
- 1.9.9 之前的使用记录格式不支持，也不自动转换：遇到旧格式会报错，旧版进行中的需求在旧版收口，或从 init 重起。

### 2. 图文表达与增强阅读 SVG（R3、R4）

- 需求说明先问读者要判断什么，再选载体：关系优先用图，精确条件用表或列表补；图后用列表补图里没有的条件、责任与去向。
- 有人机交互的流程沿流程讲入口、经过的页面、每页的操作、正常与异常去向，可用页面流转图加页面流转表；业务已定而材料没有页面稿时，页面组织与操作反馈由 AI 补齐，不为此登记议题。
- 正式图是正文里的 Mermaid，图源在 `AR/story-src/figures/`。AI 逐张判断要不要做同一张图的增强阅读 SVG（`AR/figures/`），不追加或删减事实；
  做了的交独立审查者读 SVG 源码对照图源，过了才在本地显示，`AR/切换视图.cmd` 切换两种形态。不要求每张图都做，零张也可以成立。
- 登记、阶段检查、审查、update 比较与归档上传一律用 Mermaid 形态：各阶段开始前的钩子与正式命令自动切回 Mermaid，结束后恢复可用的 SVG；SVG 不上传。

### 3. 材料导入（R1、R2）

- 收件箱可以整个文件夹放入，按相对 `inbox/` 的路径识别每份原件；不同文件夹的同名文件各自导入，派生落点带路径摘要，不用改名。
- 新原件取代旧原件时用 `import_sources.py --retire` 把旧原件移入 `.backups/local/inbox/`，每版各留一份；不退的同类原件按路径拼接。
- Story 附录的材料清单改为一张「材料 | 来源 | 贡献」表，一份阅读稿一行，只取图的原件也算来源。

### 4. Story、审查与 update

- Story 附录去掉「改动边界」一节，技术契约、规约、埋点三节仍从规格与知识判断派生。
- 归档改为一条命令 `story-build archive`：交付门 → 上传并读回核验 → 核回执 → 登记归档态。读回不一致不登记；远端已写入而本地登记失败时只补登记，不重复上传。
- 独立审查报告落盘后由 `verifier-report.mjs` 核对：格式不合的重投同一请求，每条 WARN、FAIL 在 notes 里按判据与审查对象写处置。审查者可以在必审输入之外多读，必审覆盖与缺件仍逐项核。
- 初析的待实现功能逐条写工程现状（已有能力的位置或缺口），影响范围或验收的缺口在范围关卡交人定。
- update 先判提出变化的人或文档有没有决定权，再判内容；需要重定范围时先做完不依赖范围的部分，其余收口留作保留项。

### 5. adapt 移植（R5）

- 首次安装求准确，升级求快：升级的机制面一次做完不停等，只有出现新的知识条目或加载问题时知识层才介入，并按条目定向修订。
- 知识写完、交回之前交不共享写作上下文的执行体独立审查（`reference/knowledge-review.md`）；没有独立执行体时写明未审。`--mark-adapted` 在本次有知识演进时核独审证据对得上当前知识。
- 新增只读的 `adapt-scan --status`：报目标当前版本、待做条目与知识加载结果，不写文件。
- `--apply` 补齐使用记录工作件的忽略行，并确保 `doc/usage.json` 存在（已有的合法记录不改，坏了在写机制之前停下）；目标关闭了生命周期钩子时提示采集限制。
- 升级跟进只剩 `[知识]` 与 `[对接层]` 两块，原「在途单」块与它的完成条件退出；adapt 不扫描、不迁移旧需求。
- 演进记录新增 1.9.9 一节：知识独立审查、敏感数据按用途分面核实两条知识条目，归档读回核验与核心归档入口两条对接层条目。

### 6. Demo 知识

- 安全隐私规约 SEC-01 改为按用途处理敏感数据：业务处理、展示与观察性输出、跨重启存储、缺依据分别写义务与验证；项目事实补 `MaskUtil` 对短标识的行为与没有受保护持久化封装的事实。

### 7. 发布后补充：DSH 入口（2026-10-28，版本号不变）

- 新增 DSH（DeepSeek Harness）的宿主入口 `.dsh/skills/story/SKILL.md`，扩展的流程与产物不变。在 DSH 里用法与其它宿主相同：`/story <init|archive|restore|update|adapt|stats|help>`。
- 以 1.9.9 原号重装：已经装了 1.9.9 的目标工程，`adapt-scan` 会报入口缺失、manifest 与包不同，跑一次 `/story adapt` 补上入口并重新合成即可，不涉及知识或需求。使用记录里的 Extension 版本区分不出补充前后。

## 已知局限

完整的已接受遗留与未覆盖范围见[07 §3–§4](../plan/1.9.9/2026-10-24-发布前问题收敛/07-发布结论与遗留确认.md#3-用户已接受遗留至1100)，这里只列使用者需要知道的：

- 生成的规格、Story 与评审记录仍需人评审。最近一轮实跑里，材料写明待定的事项曾被写成已生效，用户旅程与数据来源有缺口，交付为条件评审稿。
- 独立审查是纠偏手段，不保证正确：它会漏判或低估上述缺口。没有配审查员的宿主照常交付并写明未审。
- 增强阅读 SVG 是否值得做由 AI 判断，选择效果还在优化；最近一轮实跑没有制作 SVG。本机制不依赖看图能力，图面显示问题需要人看。
- 使用记录的耗时是日历时长，含等待与中断；模型晚记开始时，开始前的工作不计入。工具与模型是 AI 自报。统计报告里的概述措辞可能不够精确，以数字和明细为准。
- 交互中仍有重复确认、上下文成本偏高等问题，留待 1.10.0。
