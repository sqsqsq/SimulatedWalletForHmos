## 本版新增与优化

### 1. 六份宿主入口，按登记分发

- `manifest.yaml` 的 `provides.bridges` 改为「目标位置 / 来源」成对登记，共六份：Claude、CAC 的命令，Codex、OpenCode、Cursor 与通用 `.agents` 的 Skill。新增的是 Cursor 与 `.agents` 两份。
- `/story adapt` 只改为按登记的目标位置分发入口，其余行为与 1.9.7 相同。

### 2. 从 Demo 升级其他工程，来源是已安装的发布版

- 从 Demo 发起 `/story adapt` 时，来源工程是维护仓 `demo/` 目录里已安装的发布版，不再从开发中的源码执行。

## 维护变化

这一节只影响维护本扩展的人，不改变使用者看到的能力。

### 1. 仓分成四部分

| 目录 | 是什么 |
|---|---|
| `extensions/` | 开发源（原 `doc/extensions`），维护者只改这里 |
| `demo/` | 完整消费工程：钱包业务、framework 发布件、消费配置与宿主物化，装着 Extension 的发布版 |
| `doc/` | 项目文档：需求 `spec/`、方案与评审 `plan/`、发布说明 `release/`（原 `test/` 下同名目录）；`features/` 收 CLI 测试回流的需求产物，不入库 |
| `test/` | 测试域（原 `test/story`）：测试协议与脚本、Case、夹具、回归台账、金样与演进记录 |

迁移用 git mv，代表文件历史可追溯。根目录的维护入口是项目级维护契约 `AGENTS.md`（原 `test/AGENTS.md` 合入）、指向它的 `CLAUDE.md` 与 `README.md`。

- 需求产物的回流根是维护仓 `doc/features/`：起跑前从这里归档，检查点与终态回流到这里；demo 不存产物，装配前发现 `demo/doc/features` 即停。
- 人手试用由 bootstrap 从 demo 复制出仓外的隔离副本，产物只落副本。
- 临时脚本、临时工作区与 pytest 缓存放 `output/scratch/`（根 `pytest.ini` 指定缓存位置），运行证据放 `output/story/`。

### 2. 一个安装函数，两种目标

`test/scripts/publish_to_demo.py` 整体替换目标的 `doc/extensions`，按 manifest 登记的入口写宿主文件，再更新 AGENTS/CLAUDE 的扩展段。

- **测试**：从 demo 复制出一次性 template，把开发源装进去，核同源后再建 Case；demo 在装配前后都核干净、提交不变。
- **发布**：命令行装进 demo，前置是 demo 在 git 里且干净；失败由维护者用 git 查看、还原。
- 退出：测试期替换再还原 demo、安装事务清单/备份/恢复、目标路径预检。

### 3. 维护工具与文档

- `check_failure_modes.py` 增加 `--project-root`：用那个消费工程里装着的扩展执行，开发版检查给装好开发源的 template。
- `check_framework_drift.py`：比较 main 与 demo 接入的 framework 版本，退出 0 相同、1 不同、2 读取失败。
- 根 `AGENTS.md` 写明 framework 接入（§6）与 Extension 安装发布（§7）两条协议；`README.md` 列新 checkout 的依赖恢复命令。
- 根 `README.md` 合并原使用指南与功能全景，只写当前状态，由维护者分发给使用者；目录结构与依赖恢复只在 AGENTS。
- 发布说明统一只写本版增量：1.9.0、1.9.1 删去全量功能、产物与通用依赖三节，当版能力边界留作「已知边界」。
- 删除 `test/章节合同说明.md`：它说明的有效规则已由章节合同数据与消费脚本、作业页承接。

### 4. main 分支退出 Story Extension

main 删除 `doc/extensions`、四份 Story 宿主入口与 wallet-sdk-onboarding 的 Cursor 入口，AGENTS/CLAUDE 去掉「实例扩展 Skill」段；
framework、业务与 Framework 钩子配置不动。该提交 `51377a49` 在本地，未推送。
