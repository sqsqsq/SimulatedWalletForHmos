## 2. 必须集中补齐的两项设计

### R1 [P2] 新Framework与DSH的隔离组合缺可提交、可自动重建的输入落点

**位置**：[03](../03-重写实施与验收.md)第34–36行；[14](../14-DSH宿主接入.md)第15–22行；[01](../01-成果保全与基线切换.md)第97行；[12](../12-测试基线迁移与验收.md)第39行。

方案明确B在一次性N template加入DSH定制，demo保持旧发布版；也提到template层可复现装配，但未指定N输入与DSH定制实际保存在哪里、哪些内容随E入库，以及现有公共构建函数如何消费它们。

**真实消费者证据**：O `test/scripts/run_multi_case.py:255–274` 的 `create_workspace_template()`每次新建临时目录，从demo复制后立即 `install_dev_source(template)`；B对应函数第291–310行仍是该方式。O `test/scripts/verify.py:80–86`的build_template直接调用它，suite创建也重新调用同一入口，不复用B前一次手工修改的template。

**影响**：执行者只按当前逐文件动作准备临时N/DSH组合，E的fresh-template handback和F的新suite仍可能复制旧demo Framework；临时改动也不进入E真实merge对象。一次局部template通过不能证明提交后其他执行者或下一次运行能得到相同组合。这不是单纯目录命名留给实施者的选择，而是生产输入→公共装配→E/F消费者尚未闭合。

**最小修订**：设计者在现有测试域明确固定N发布输入/取得与摘要规则、受版本控制的DSH定制文件或补丁，以及公共 `create_workspace_template` 的改接顺序：复制demo→置入并核N→应用/核本地定制→原生物化→安装开发源→核最终身份与demo未变。verify、failure-modes及runner共用该入口。可复用现有安装/装配机制，不新增通用构建框架；运行cache可不入库，但重建所需配方/定制与来源身份必须随交付可取得。

**定向复核**：方案先给出明确来源、落点和消费者；实施时离线从两个空目录各自重建，核N身份、DSH adapter/Preset、宿主物化及开发源同源，demo未变；丢弃第一份template后第二次仍能成立。不要求为本项先跑真实CLI。

### R2 [P2] 独立Story的视觉能力/保真裁定尚未从旧Spec生产者迁出

**位置**：[02](../02-新版合同与适配定案.md)第57、69行；关联[04](../04-旧成果与能力承接清单.md)图形/独审保持项和[12](../12-测试基线迁移与验收.md)独审测试群。

**真实生产消费证据**：

- B `extensions/hooks/shared/review-inputs.mjs:114–133` 的visualDeferral只读主需求 `spec/reports/capability-snapshot.json` 与 `fidelity-intent.json`，要求两份 `execution_identity=phase:<主需求>:spec`、一致decision_id、vision=false、semantic_layout/best_effort。
- N `framework/harness/scripts/fidelity-intent-init.ts:1–17`明确这些产物由Feature Spec Step 1生产；后续CU Spec使用CU逻辑身份，不是主需求身份。
- B `test/tests/test_verifier_report_protocol.py:874–907`保护了“合法无视觉且文本读完可WARN”，并拒绝PASS冒认视觉已审、文字未审、strict、身份不匹配和图片缺失。

**影响**：在新正常Story/零CU链里，B消费者所需主需求Spec裁定没有生产者。直接保留旧读取会让原本允许有边界WARN交付的情况变为无裁定；借某个CU的裁定又违反身份对应。保留函数名或把原测试一起复制，无法保持这项能力。

**最小修订**：设计者明确独立Story在何时通过哪个Framework现有入口取得视觉能力与保真约束，如何绑定当前Story/蓝图审查对象并进入task、材料键和basis；调查现有 `effective-vision-context.ts::resolveEffectiveVisionContext`等入口时，区分能力事实与保真决定，不能将只有能力轴的结果当作best_effort授权。若原生缺必要入口，说明上游最小所需能力及受影响范围；不造假Spec文件、不借无关CU裁定、不新增平行能力账本。

**定向复核**：12/15明确把上述回归迁到不预置主需求Spec的独立Story正常链及零CU链；有效无视觉/best_effort且文本审完可WARN，缺图、strict、身份错、文字未审仍拒绝。实际图面未审继续披露，不能改成强制看图或为了放行降低判据。该问题是生产者迁移缺口，不是要求本轮提供未来CLI效果证据。
