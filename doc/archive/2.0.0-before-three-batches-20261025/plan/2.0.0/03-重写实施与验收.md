# 六个检查单元、交回与验收

范围、权威与拆分理由见[00](00-重写准备与适配总览.md)，产品设计见02，DSH见14，测试见12，预算见13。本轮没有执行以下步骤。实施前由执行者读完整有效Plan，先核预算及实际源身份，发现与接口事实冲突交设计者，不自行补架构。

## 执行批次与评审等待点

文件编号00–15不是十几个实施步骤；00是入口，01/02/04/11–15是职责分册和索引，05–10是历史入口，实际只有A–F六个检查单元。采用**单元独立交回、批次连续实施、集中评审和返修**，不要求每单元写完就停等设计者。

本任务沿现有目录接续，明确两批而不迁已有分册：批次一为A–E，目标是形成保持能力、文档/测试/预算闭合的双亲merge对象，依赖已授权预算和实际实施许可，末尾评审E固定对象与全部增量交回；批次二为F，依赖批次一评审给出的就绪范围和真实运行授权，目标是取得送审、归档、update与CU到Plan的真实证据，末尾评效果。两个批次都引用04保持项、02上游边界与13同一预算；未解决的依赖限制对应结论，不自动忽略。没有获准的后续工作时，不另造空批次。

| 批次/节点 | 执行者动作 | 是否停等评审 |
|---|---|---|
| 批次一·A | 保全、来源/文档/标准清单，写A独立交回并提交维护资料固定T | 预算已有授权，实施授权和前提成立即可继续；不额外设A评审门 |
| 批次一·B→C→D→E | 按依赖连续完成，每个单元结束保存独立交回和定向验证；B–D保同一merge事务，E组合核对后提交双亲对象，在E交回中汇总本批索引 | B/C/D不逐个等待；E集中评审实现、保持项、文档和证据，明确后续安排 |
| 同轮集中返修 | 评审把该轮问题合成一个返修步骤，按真实依赖处理；完成后增量交回并提交 | 影响后续契约、设计或证据可信度的先修，是否先复评由reviewer说明；非阻塞项可经评审明确并入批次二，不逐问题停等 |
| 批次二·F | 按评审安排先处理并入的非阻塞返修，再在相应就绪范围和里程碑授权内执行DSH；各检查点留证，最后交本批效果/问题闭合汇总 | 业务Case检查点仍按TEST；批末同时核原问题和新增工作，F后评效果，发布另按实际授权 |

批次内必须中途报告并暂停**受影响工作**的条件：核心设计/范围或所有权冲突；真实前置失败使后续结果失去依据；需上游处理的已证阻塞；预算达到13规定须reviewer/人工确认的档位；现有授权未覆盖的写入/实跑。其余独立工作可继续。普通局部选择、已有授权内修错或单元报告写完，不构成等待理由；已知道前置失败时也不能为了“集中交回”继续堆其依赖实现。

本节规定未来获准实施后的节奏，不扩大本轮“只改方案、不替换源码、不跑CLI”的授权。A–E若被一次性授权，可连续执行到E总交回；预算已获13§5授权，产品实施/真实CLI仍按其实际授权分别判断。

投入取舍适用于执行者和维护者：先保证正常交付链、常见操作失误、已证缺陷和必须保持的能力。新增异常保护或测试前，先核实际入口是否可达、影响/可发现性和现有恢复责任，再比较新增逻辑、状态和装置成本；真实可达且后果严重或合同明确要求的情况，即使少见也保留针对性保障。仅理论组合、需破坏内部状态且影响有限或已有恢复的，不专门扩机制/测试；足以影响设计但事实未知的只做有边界取证。不按主观概率阈值判断，不因“没见过”删既有合同，不新增兼容平台、宿主×模型×版本矩阵或长驻故障注入工具。关键取舍记现有讨论依据，不逐假想场景建台账，也不为了“全面”不断加步骤或返修轮次。

## A. 固定基线、保全与迁移准备

依赖：最新Spec、整体重写确认；预算按13§5已有授权，本单元只读/维护资料准备与产品开工仍分开。

输入：O/P/B/N，01完整来源表，旧快照、源末轮suite及发布原件，12标准迁移表。

动作：核T工作区，保全Git外唯一证据并做恢复核对；生成完整包逐路径来源/去向/冲突索引；按01归档源历史和目标差异原件，修活跃引用；形成2.0标准修订与Case终点、回归迁移记录。隔离N发布树及DSH本地差异设计可装配检查；此时不更新demo或开发源、不运行真实CLI。核13§5的已有预算授权，记录确认人/范围/原分母，不重复请求同一额度；其他实施前提成立后进入B。

可检查结果：来源完整，历史可恢复，project保护，当前入口不误指旧版本，标准区分历史/新组合，预算政策与设计没有混口径。维护资料可先提交形成T；它不是实现完成，也不提前提交依赖未到位的产品/测试运行改动。

## B. 真实反合、安装与蓝图/CU基础

依赖：A完成、实施授权与预算确认；DSH采用14定案。

动作：按01启动no-commit真实merge；完整引入B能力/测试/资料并按O复用清单接入。改manifest/schema/skills/knowledge资产/phase_bindings，entries原生物化接替bridge；按01§5把N固定输入和DSH本地补丁放入测试域版本控制，改现有create_workspace_template公共入口，使每份新template自动构建N/DSH而非手改临时件，修active adapter观测。按02完成来源冻结、原生publication新签名、知识任务/knowledge_application、CU初建与原生路径。

必改文件族：manifest、story-adaptation/entries与adapt-scan、publish_to_demo、framework-access、flow/native/submission、materials/frozen、knowledge-task/application/schema、story-knowledge、蓝图author/reviewer、相关hook/overlay，以及01§5的test/config固定输入、test/fixtures本地补丁和既有run_multi_case装配函数；14列出的定制通过这些可提交输入进入隔离组合，正式demo按独立接入边界。

定向结果：空白template和已确权旧安装升级均可原生物化；来源不全/路径冲突写前失败；合法材料→设计知识→原生CU接收/readiness有真实消费者；不存在第二CU writer。原生未决草稿/零CU正例，以及FW04/FW05中性复验按02§8取证；受阻路径隔离，不篡改fixture绕过。

交回：当前diff、来源表、定向回归、阻塞条件、工作区预算。B不是整版可运行承诺，merge事务保留，C/D继续完成其消费者，不提交混合产品树。

## C. 独立Story、审查与送审归档

依赖：B的输入与装配成立。

动作：B写作设计、章提交、图片/SVG/Review行为为底，改为蓝图/冻结源输入；复用O独审对象/原件恢复，采用先Story正文后核源的阅读顺序。按02§5的story-review-visual薄桥使用原生能力与保真纯函数，裁定随已有task/material_key绑定，退出主需求Spec文件依赖。解除“准入才能成文”错误耦合，公开真实issues/未决；附录迁canonical且消除正文逐字搬运约束。保持B命令白名单、工具故障分类和归档上传/读回/补登记。

必改文件族：phases/design/story-write、core/story/{design-source,story-inputs,writing-plan,chapter,appendix,review-object,review-report-contract,independent-review,delivery,check}、hooks/shared/reader-review-task与review-inputs、flow/{routing,lifecycle,publish}、Story reader规则及原有图/Review消费者。退出Spec成文路由及其专用投影，不删材料贡献、埋点定义或正式Mermaid恢复。

定向结果：只读Story能评业务；相同事实合法表达不因字面不同拒绝；来源/身份坏不能以draft放行；报告无效→独立修格式→新原件可恢复，作者改原件不变可信PASS；未知人工附件不覆盖；归档部分成功从未完成处续，不重复上传。

交回：结构回归与作者/独审输入检查；语义效果仅作设计自查，等待F真实独立证据。merge事务继续，不提交未适配update/usage的产品包。

## D. update、CU修订、使用记录与adapt

依赖：B/C正常链成立。

动作：update权限/冻结/原件→原生设计修订→受影响CU同批修订→Story/审查→归档/close；按02§6接revise API及恢复分支。把源usage的开始副作用迁作者入口，修全部逻辑ID/物理路径消费，保持schema1、pending与stats仅usage/Git。adapt保知识/对接层/合法usage，不迁旧在途需求；更新2.0升级说明及入口所有权。

定向结果：新材料、真实人签和直接改稿有权威归属；未接受建议不变业务决定；同名换版保历史；完成CU用新工作/后继；provide变化不漏消费者；busy/旧ref/写失败可恢复。两CU共享工作不重复计，晚begin仍未知、缺closure不finalize、重复收尾幂等；无业务目录stats仍成立。

交回：update/usage/adapt消费者、源已实现能力与七组遗留对应结果、退出表、预算。此时所有交付入口均须已迁完；没有“旧版本先顶着”的正常分支。

## E. 组合检查、归档引用闭合与真实merge提交

依赖：B–D消费者闭合；任何仍影响已承诺正常能力的上游阻塞明确列出，不用排除测试伪装全绿。

动作：核12全部80模块处置和公共helpers/装配/fixtures/标准，跑相关Framework离线、一次verify handback、Case计划及文档引用检查；按当前源码和正式source身份核13的endpoint与first-parent适用边界。diff自查保持项、专名/答案泄漏、旧协议残留、旧入口和失败恢复。

若只有已明确且未触发的上游局部路径受阻，可固定一个如实标明限制的实现对象供继续调查；但用户未接受缩范围前不能签全版实现完成。若阻塞破坏首包正常链，保持merge未交付，回设计者/上游处理。不可提交一个安装都错配的树。

完成条件：首包已能按其实际范围验证，退场/能力映射/文档与标准一致；适用离线失败和skip原因完整；预算复核满足权限；git双方祖先、双亲及staged文件集合正确。此时才提交真实merge，E增量交回同时汇总批次一的步骤/提交/证据/未关闭问题，集中送审并等待评审。提交只固定对象，不是CLI、发布或评分认可。评审需给批次二可继续范围及阻塞项先修/复评要求，不能只写通过或不通过让执行者猜后续。

## F. DSH真实验收及最终接续

依赖：获准的实际代码对象、E结果、受影响上游路径条件，以及用户启动真实CLI里程碑。没有授权就交E结果，不能自行实跑。

使用12选定的系统单送审/归档/update与本地单CU到Plan；先走真实正常路径，同时取14独审身份与首读顺序、知识应用、usage起止、七组遗留和成本证据。适用补充直接入口/多CU覆盖采用自然业务请求，不向消费模型送checker/金样/维护答案。

每个检查点冻结原件并评，人工仅扮演需求方；实际未投放的update probe、未出现的SVG和缺日志均保留边界。评分由用户按有效TEST确认。没有达到计划终点/关键内容仍缺/上游阻塞仍在的范围明确未完成，不因有PASS自动结项，也不无限重跑到绿。

最终交回：当前实现/来源身份、保持能力、七组遗留处置、独立语义与原生调用证据、未覆盖/外部阻塞、实际预算与退出差额、金样审定状态。用户后续决定发布后再执行demo Framework接入与Extension §7发布；本版重写方案不自动执行发布。

## 每单元共用交回格式

使用既有实施反馈/评审意见位置，不移动原件；新文件名称带“批次一-A”等实际批次/步骤。每个单元一份增量交回，不另建同内容的整篇总结；批次最后一份交回兼作本批汇总索引。写清对象/提交、执行动作、增改删、保持/退出、验证与跳过、原件路径、G/X/净变/峰值及差额、未决、授权和下一动作。B–D特别写“未提交merge工作区”，附可还原diff；E后常规步骤/返修完成后交回并提交，再依评审明确安排继续。状态区分单元自检和批次评审，不能自行签评审通过。

跨批返修的新记录写实际执行批次并引用原问题/原报告，原件不移动或覆盖；原问题的返修轮次、基线、预算分母和累计不重置。复评同时核原问题关闭及新增工作，未受影响结论复用；第二轮及以后先归因，不继续堆补丁。接续摘要必须能看出当前批次/步骤/原问题轮次、已完成、未决、权限边界和下一动作。
