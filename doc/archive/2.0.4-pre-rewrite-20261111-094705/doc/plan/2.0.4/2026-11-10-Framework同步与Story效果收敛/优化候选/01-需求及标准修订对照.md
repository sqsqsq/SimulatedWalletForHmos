# 需求与标准修订采纳对照

本页为采纳摘要。有效需求只在doc/spec/2.0.4/2026-11-10-Framework同步与Story效果收敛.md维护；唯一标准已生效为extension-acceptance@29，采用SHA和参照校正在本版评价标准变更.md。下表随正本同步，不另设判据。原评审I1–I8与203010 R1–R3保留；优化对象仍是Extension机制，业务Case输入不改。

## 1. Spec 目标与范围

| 原项 | 修订后的要求 |
|---|---|
| A1/A2 | 在同源原件、实际人答及同等范围下，保持1.x有效能力，达成金样必要业务语义。按事实、关系、正常/失败/未知、页面交互、知识、验收和可读性核；不以字数、总写对数抵消关键错误 |
| R1 | 新原生同步；按专项请求止于原终点。原F1与新F2分别核；真实未决仍按当前依赖阻断 |
| R2 | 共享可观察验收由原生实际承担目标产生；Spec复用权威内容并保合法局部深化；原生复用跳过Spec时，Plan实际消费仍核知识归属 |
| R3 | 已有材料/工程支持的写结果与恢复在共同设计明确；未知如实表达，缺接口不编造，工程该设计的不能推给需求方 |
| R4 | 适用知识产生实际落点；QA引用真实事件/验收，事件详情只存现有event源；Story、Plan实际消费 |
| R5 | 修正样板“无封装”的含义及资源口径；新增文案的量化责任按样板条件与落法，不预设字符串KB门槛 |
| R6 | 两类独审有真实对象、首读/核源职责及原件；直接质询保持当前登记责任，公开写回只列条件性上游改进 |
| R7 | 沿已有授权推进；缺会影响动作的决定才询问。保外部登记/送审边界；本地DSH配置禁Goal工具，不新增阶段状态 |
| R8 | 按现有TEST和标准做独立效果对照，补可复算事实及原因；不先新建形态脚本、探针台账或修改公共Skill |
| R9 | auto真实到Spec、car真实到Plan；不跑update。条件答复仍按实际运行触发；没有问到/没有送达分别归因，不提前补答案 |
| R10 | 每项替换同时核旧路径/指令/测试退出，保有效能力；不按40条句子、过期净减或统一schema做删除指标 |

澄清纠正：Q3–Q5撤回，未授权改demo、业务原件、条件答复、统计口径或模拟服务。Q2仅要求核清金样来源和不可比项，不能解释为维护者直接替消费模型做业务设计。原有合法业务未决继续保持。

## 2. 验收替换

| 项 | 通过条件 | 证据层 |
|---|---|---|
| V1原生组合 | 固定Framework/pin/补丁装配成立；合法CU和真实当前阻断分清；Spec-only不越权、Plan正常到达 | 离线真实入口/组合，F2未关闭则相关部分不通过 |
| V2来源与设计 | 原件→转写→设计无无源承诺；工程缺项有本期承担或有据外部依赖；新题材同样适用 | 独立语义；机制结构测试只证局部 |
| V3知识消费 | 同源must/AC/事件及正确CU；Story自足；Spec合法补充；不经Spec也经Plan实际消费者核 | 真producer/consumer离线＋获准实跑 |
| V4关键语义 | 既有已核错误逐项处置，关键事实、授权、终态、隐私等无已知未关偏离；不允许半数抵消其余 | 维护独立语义评审 |
| V5交互/独审 | 真实条件问答、先独立首读再核源、原件保存后接收、按影响复核、无Goal吞停等 | 配置＋真实主子会话证据 |
| V6效率 | 同次等值重复退出；分离候答/模型/工具/返工，按同阶段同组合比较；不以更少内容换快 | 确定性＋原事件事实＋语义归因 |
| V7效果终点 | auto到Spec、car到Plan；原始目标、实际终点、产品质量和未验证单列；三轴建议分交用户确认 | 真实CLI，另行授权 |
| V8退出/预算 | 逐职责退出成立，必要拒绝/正常能力保留；官方G/X/R和峰值如实交回 | diff＋官方计量＋消费者回归 |

## 3. 已采用 @29 的变更摘要

保58条及三轴框架，不另设分母。正本与SHA已在本轮设计阶段更新，A/B/C开工核该固定身份，D不再首次整合；历史报告不倒签。

| 条目 | 要变的语义 |
|---|---|
| B2 | 写操作的明确结果/未知/恢复有真实依据；“每种都填一遍”不是合格；缺决定由真实owner承接 |
| B5 | 质量/统计的具体业务效果和可观察落点，空投影不能自证不适用；无源公式也判偏离 |
| D3 | 知识沿真实承担对象进入AC并被实际Spec或Plan消费者核；保Spec局部深化和两CU归属 |
| D10 | CU显式认领与原生闭包分工；当前依赖不能通过移远期求绿；没有封装不自动等于外部阻塞 |
| F1 | 有效授权在动作前成立，已有授权不重复问；不规定一律把终点问题提前到范围门 |
| G2 | 专项请求止于真实终点；不把DSH进程的headless传输名等同Framework headless/Goal能力 |
| G3 | 首读/核源/影响复核、当前最终对象与真实原件；现直接质询登记保持，不预写“已切原生自动写回” |
| G4 | 对照原件、人答、历史实际和金样；额外选型与必要能力分开，合法不同表达可达标 |
| G5 | 度量报告可观测事实，原因由审查解释；调用数、删行、没有Goal事件都不单独证明效果 |

现行A8已有转写来源责任，本次落实与校正评审判法，不为同一要求增条。其余条目保持，D01逐项写符合/偏离/未覆盖/不适用及对象证据。未跑设备/视觉/update不写“不适用”消失。

## 4. 最终收敛范围对账

移入原2.2需求继续有效：R1问题处置→本候选/I1–I8；R2正向职责→总方案四表；R3替换完整→各批退出；R4来源授权→B01/A03/C02；R5必要审查→C02；R6最终金样→D01逐语义校正、候选另存且由用户审定；R7标准→本页；R8相称验证→D01/D02。

金样应覆盖整体设计、Story、Review和适用CU Spec/Plan，具体语义按当前有效输入；旧模拟/恢复选型没有取得本轮授权时只作目标设计参照。不能删掉业务能力求金样可达，不能把先制成的理想答案投给消费模型。跨版本分列能力恢复、已改善、仍有差距、不可比与未覆盖。


本轮补充：R5经本版两条知识主题、followUp、适配模型、既有独审/mark及后续知识读取闭合，H2原标准保持；FW-F2由已公开证据升级为外部依赖，设计安排补齐不等于原生问题已修。每步预算/退出见总方案唯一表。
