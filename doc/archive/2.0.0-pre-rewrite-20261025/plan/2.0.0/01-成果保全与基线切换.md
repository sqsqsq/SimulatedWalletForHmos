# S1：成果保全与1.9.9基线切换准备

依据[总览](00-重写准备与适配总览.md)及根AGENTS §5。执行者负责文件操作，设计者核处置与预算；本文件区分今天可盘点的准备、等发布身份的参照验证及S3正式切换要求。今天不执行产品替换。

## 1. 替换之前保住什么

先重新核`git status`、分支、HEAD、worktree与其他运行任务。记录替换前完整提交SHA；当前`8807b401`只是观察，不能当未来切换点。保留story的祖先链，不reset、不rebase、不整仓checkout、不删除未跟踪项。无需新worktree时复用当前checkout。

已提交源码按固定提交精确引用；在途修改和未跟踪材料须列明归属并保留。逐项区分Git内对象与Git外唯一副本，后者包括未跟踪评审、在途差异、运行原件和必要本地配置，不能用HEAD替代。针对实际可能受本任务覆盖/清理影响的内容，在`output/story/2.0.0-rewrite/`记录来源、文件清单、摘要和恢复位置；其他任务文件保持原处，不全盘复制或纳入本任务提交。个人配置核非秘密身份，不复制密钥。本次实际保存范围及恢复证据见[07](07-旧2.x成果保全与复用盘点.md)，后续新增修改需增量补保全。未来确需提交准备成果时按明确文件清单暂存，不使用全仓暂存。

以[旧成果清单](04-旧成果与能力承接清单.md)为种子，枚举旧extensions及与固定1.9.9开发观察或正式发布源不同的测试、装置、配置、文档。S1为每个差异文件记录当前身份、保全来源、业务目的、依赖、证据成熟度与已知缺陷；新落点不明的标“已保全、复用去向待新版”，注明责任及影响。S2才定保留复用、随发布引入、由新能力接替或退出，不要求今天提前作完最终处置。依赖反查覆盖import、命令调用、manifest、overlay、宿主物化和测试装配，单搜文件名不能证明没有消费者。

有用成果优先保存“目的、合同、来源提交+文件+符号、证据、缺陷、候选新落点”。固定Git对象已经可取得的代码无需再复制全文。只有跨文件难理解或旧片段确需离线交付时才摘录，并标全依赖、旧接口适用范围及待重验，不把维护片段送入消费模型知识。

完成条件：历史引用可解析、在途成果可找回、全文件保全覆盖已核、关键证据存在或明确缺失。实际保全时，从固定提交取回代表性旧文件；受覆盖影响的Git外副本在scratch核可读与字节摘要。该检查只证明恢复能力，不重跑旧业务。唯一副本未保全不得覆盖；“复用待定”不代替“尚未盘点”。

## 2. 锁定真正的1.9.9发布源

取得正式发布提交完整SHA及用户发布决定，核`doc/release/1.9.9.md`、README、EVOLUTION、开发源与demo已装发布源的一致性及发布验收边界。没有标签不单独判失败，但不能仅凭分支名或manifest批准发布身份。若仍在开发，只做只读差异分析，源码切换等待发布；本方案不要求1.x为赶进度提前发布。

**同步对象是同一正式发布身份下的完整需求包：Extension交付主体＋配套测试＋相关资料。** 用户所说的docs包括本仓实际使用的doc目录及相关文档入口；当前story-1.0根目录为doc、extensions、test，正式发布时按实际树重新枚举。文档更新是必须同步的组成部分，不能只留在来源分支供参考。

| 同步面 | 必须纳入的来源与目标处理 |
|---|---|
| Extension交付主体 | 完整extensions树，包括机制、知识样板、adapters、manifest和安装/升级所需文件；先核发布字节，再按新版适配 |
| 配套测试 | 相关test/tests、fixtures、cases、golden、regression、scripts、config及其运行依赖；原行为覆盖与测试数据成套承接，按03/08处理新Framework配套和两线差异 |
| 需求、方案与评审资料 | 来源线更新的doc/spec/1.9.9、doc/plan/1.9.9及直接相关的决定、评审、交回、限制和引用附件；同步到本仓相应1.9.9资料位置，作为新2.0.0起点的依据 |
| 发布与使用/维护说明 | doc/release/1.9.9.md、相关流程/适配说明、README、TEST、EVOLUTION及必要配置/维护约定；将1.9.9有效增量并入相应当前入口，现行描述再按新2.0.0适配结果同步 |
| 关联资料与身份 | 金样审批/来源、图源与资源、引用清单及支持上述结果的资料，随主件闭合引用；运行日志等仍按output规则保全/引用，缺失证据登记责任和影响，不冒称已取回 |

发布锁定时为三面分别列源路径、来源提交、目标路径、字节摘要或合并依据、删除/接替项；检查新增、修改和已删除内容，不能只复制新增文件。扩展原样起点核字节；测试和资料需要适配/合并的保留原始副本及实际差异。若来源后续修改，先比较差额、核身份与影响再决定更新，不追随移动分支造成三面版本混用。

发布后若有适用于该1.9.9版本的资料修订，也纳入同步，记录补充提交及适用的发布身份；不能因不在最初发布提交里就漏掉。涉及产品或测试行为变化的后续更新重新核基线与验收，不能把不同版本的实现和合同混用。

同名资料按责任处理：1.9.9合同及历史说明以锁定来源的对应版本成套更新，被替代稿通过Git/既有保全追溯；共享README/TEST/EVOLUTION合并有效增量，保留story已成立的职责与记录。当前doc/spec/2.0.0、doc/plan/2.0.0和doc/archive/legacy-2.x受保护，不能被1.x目录或旧2.x材料覆盖、也不在当前树恢复旧2.1.0入口。其他任务资料不因目录同名被整树替换。每项冲突在逐路径清单定明采用、合并、历史保留或待核及理由。

成套同步验收同时核交付主体、测试和资料：发布行为/能力有对应实现、覆盖和说明；金样/审定/来源链接有效；目标当前说明与实际适配一致；删除的旧要求有接替或明确失效依据。任一必需配套面未同步、身份不明或必要引用缺失，都不能称完整基线已同步。

能力清单按04逐项记录源码/合同、测试、实际证据、发布成熟度与保持验收。今天可据固定开发提交建立清单，正式发布后补变化；不把开发spec所有承诺或已审金样视为已发布能力。未完成项列原责任和后续去向，不静默丢弃或自动迁入本版。

用发布快照的整套1.x环境在`output/scratch/2.0.0-rewrite/`准备一次性基线验证，Framework、安装器、测试工具、Case/金样及配置采用该发布配套，按它的TEST执行适用离线验证；命令不假定存在story线的verify.py。记录03规定的组合身份。不降级当前demo/framework，不把旧测试放在新Framework上失败解释成1.9.9退化；实际行为仍引用发布证据，缺失则列未知。今天可列依赖，未锁发布源前不签正式基线，本轮不执行测试。

## 3. S3正式切换之前的路径准备

今天准备精确路径及恢复清单；S2定案后，设计者核首包确切路径、预算、最终接替/删除及适用检查。S3实施者按该清单替换开发源：旧树中发布源不存在的受版本管理文件随责任接替退出，逐字节导入发布树后再实施最小适配。遇到未归属本任务的在途/未跟踪内容先保留并停止冲突路径，不静默覆盖；不通过递归清理解决。

先在scratch核交付主体及其测试、资料来源集合，原样导入部分与发布源逐字节一致，manifest为1.9.9，保存同源证据。S3再把获批完整起点带入story、升为2.0.0并完成最小适配、安装物化、测试装配和相关说明同步，首个改变extensions的代码包满足适用离线检查后才提交/交回。分别保留“同源起点”和“首包适配后diff”证据；首包除版本外可以有获批适配/合并差异，不能再要求最终树仍逐字节等于1.9.9。保留story祖先链，不提交纯恢复后无法验证的混合树。

当前demo仍是旧Story发布件与Framework 3.1，与scratch中的1.9.9不构成支持组合声明。S3本地切换过程中可能短时混合，消费者仅为实施者，退出条件是同包最小装配与适用检查通过；在此之前不提交、不交作可用版本，不以混合环境失败放宽业务规则。若必须单独交付纯恢复提交，须先另定可验证配套及其检查，不由实施者豁免现有门禁。

测试源和运行配置不在S1盲换。今天列03的测试依赖和原行为覆盖，S2定逐路径迁移；1.9.9有效覆盖引入，旧2.x专用覆盖按新合同迁移或退出，公共装置和CLI按身份保护。金样连同审定/来源/资源闭合核查，不能把1.x Spec正文当新版蓝图固定答案。

## 4. 保护、失败与交回

保护demo、业务代码、全部历史文档、另一任务的tools/cli同步、测试证据与个人配置。安装器与当前AGENTS有出入时由S2明确安全合同接替；本步不让恢复的旧安装器写demo。

写入失败或来源错误时，依据切换前SHA及本次文件清单恢复仅本次改动，保留其他在途文件，核字节后记录失败位置。新文件删除也只限清单内且身份相符的文件；不使用全仓clean/reset。Framework发布件失败按根AGENTS §6处理，与源码回退分开。

S1交回包括固定身份、保全覆盖与恢复办法、能力/测试依赖/相关资料清单、发布状态及待定项；取得发布源并实际做参照验证后再附其结果。未做备份或验证须明示。S3首包另交三面同步完整性、同源证明、实际适配/合并差异、引用闭合、装配及检查、实际G/X/净增和差额；准备完成不等于新适配已工作。
