## 1. 结论与180秒判断

## 2. 完整调用链与成本归属

```text
verify handback --assembly：总计时开始
  → 首次真实模板装配
      copy demo → 固定Framework Git原始字节 → 本地补丁
      → 原生init UPDATE（S1–S4）→ 安装开发Extension → 物化入口/身份边界
  → 三条通道并行，总worker预算32=24+7+1
      full：pytest主进程 → 24 worker各自收集全部模块
          → ext_workspace模块导入：暂存DEV_EXT
          → 两个adapt模块顶层调用 installed_package（每进程缓存一次）
              link_framework → publish.install_extension
              → entries plan(Node) → 拷贝扩展 → entries materialize(Node)
          → 类setup/用例/teardown
              准备前态 → Python/Node业务入口 → 原生加载/状态生产
              → Node内部spawnSync(Git/原生命令/Python usage等)
              → 产物、状态、退出码与副作用断言
      failure：同首次安装件 → 内部判别/真实组合及安装扫描
      第三通道：第二个空根独立装配和独立期望核对
          → runtime → compile → config → Node语法
  → 全部消费者结束 → 保存原始边界/原生日志 → 清理 → 总计时结束
```

原生UPDATE不是一次简单Node启动：固定发布源码的 `init-task-executor.ts::runGlobalPhases` 对 catalog/glossary/docs分别启动 `npx ts-node harness-runner.ts`，其下还有检查命令。第二次独立装配保留这条真实链；不得借首份模板、跳S2或把准备搬到总计时之外。

真实Story登记也不是Python账中的一次调用：辅助准备含两次Node review prepare，Python `flow.lifecycle.cmd_story`再启动 check --registering、review check、basis 三次Node；不含usage和视图附加动作时，这一组合已至少有6个进程。第二次review prepare仍包含project/number/build/disclose/attach/check，不能因名字相同就整次删除。

## 3. 修改位置、退出数量和覆盖保留

以下均为下一次修改候选，本次尚未实施。A/B优先处理明确重复；C/D/E仍需按条件落地。不扩展产品接口，不新增依赖。

### A. 正式安装包一次生产，worker各取私有副本

**位置**：`test/tests/ext_workspace.py:107 installed_package`；`test/tests/test_adapt_ownership.py:36`、`test/tests/test_adapt_source_kinds.py:15`的模块顶层PKG_ROOT；`test_usage_stats.py`相关消费者。

**现状**：pytest-xdist各worker收集全部模块，两处顶层调用通过进程内 `_INSTALLED` 合并，所以是24次正式安装，不是48次安装。`publish_to_demo.py::_plan/install_extension`每次调用entries plan和materialize，共48次Node入口。这是源码推导的调用次数，不是现有日志测得的用时。

**改法**：使用既有 `shared_state.shared_tree`，在本轮私有状态目录内真实生产一份正式安装包；每个worker克隆独立可写包并重接Framework。PKG初始化移入现有类级准备，消除导入期重活，不造延迟Path代理。单独运行保留可用行为。

**退出**：一次handback的正式安装24→1，退出23次安装、46次Node入口（48→2）；保留24份私有复制和链接。仅把顶层调用改为懒加载，最多变为实际消费者worker数W次，W可能仍为24，不能算上述收益。

**保留**：正式安装生产者确实执行；源枚举、写前核、目标字节、入口物化仍由原安装器承担。apply/check/status、业务所有权、拒绝脏写和真实首装用例继续执行。共享键包含全部开发源、准备及安装代码、Framework固定树/补丁、完整配置/宿主/路径等输入；本轮私有目录避免跨运行依赖漂移。不得共享可写包，不把DEV_ROOT（仅暂存、config为空）当正式包，不直接拿含dsh/业务状态的handback模板冒充。

**未证条件**：正式安装产物能否无绝对绑定地复制，需要后续小范围核查。未证明前不能带入冻结feature/run或prepared报告，也不能改写根字段来伪装有效。消费者虽主要读包或复制后改manifest，仍用私有副本保护遗漏写入。

### B. 独立补丁期望一次批量读取Git原件

**改法/退出**：当前补丁19个文件，每份独立期望读取启动19次 `git cat-file blob`；改成一次 `git cat-file --batch`读取，仍独立git apply。两份装配核对合计退出36个Git进程，原始blob读取38→2；不改变两次装配本身。

**保留**：固定发布提交、Git原始字节及换行、补丁后的全文件字节比较。期望推算保持独立，不调用被测装配函数生成答案；新增文件的missing与Git读取/ref错误分别处理，不把所有非零都当不存在。不得用git archive替代原始blob。

### C. 默认知识工程复用“尚未冻结”的正式安装前态

### D. 带TOPIC的登记前态只生产一次

**位置**：`test/tests/test_story_update.py:1832 RegisteredCase.setUp`及三个派生类（1875、1921、2016行）。

**现状/改法**：`cls=type(self)`后写 `cls._registered`，是每个派生类、每个参与worker分别缓存，不是整个基类一次。将同一TOPIC的真实登记生产移到现有shared_tree，键覆盖WALKED、TOPIC、有效before_init和准备实现；每个用例继续私有复制。

**退出**：至少三个派生类各自生产的一组相同登记前态→一次，退出至少两组生产；若类分散worker，实际重复更多但本次不量化。原类注释“约4秒”没有当前竞争下证据，不能乘次数当收益。

**保留**：真实prepare/回复/receive/登记生产者；update全过程、设计反馈归属、发布外部版本核对等后置断言原样保留。无TOPIC的通用REGISTERED不是同一状态，不能合并；已有WALKED共享不算新增收益；含时间/usage特定语义的状态不强并。已有复制也不自动证明报告根绑定可迁移，后续需核依赖，不能回放旧报告替代实际prepare。

### E. YAML字面矩阵使用既有业务观察，保留真实apply组合

**位置**：`test/tests/test_adapt_source_kinds.py:325 test_yaml_quoting_does_not_change_the_source_kind`。

**现状**：五种等价YAML写法各做完整apply，只为证明解析后stand-in身份一致和真实adapter未覆盖。

**改法/退出**：五种写法仍全部送入真实adapt-scan，但用已安装且knowledge有效的合法私有目标执行 `--status`，断言 `items`中“对接层”的有无；保留一种引号+注释写法完整apply并核adapter实际字节。五次完整apply收敛为一次，退出四次完整写入路径；仍有五次status，顶层进程数甚至可能增加一次，不能只看Popen数量。

**为什么观察有效**：`adapt-scan.mjs:497 WITH_ADAPTERS`的同一个解析结果既用于coveredFiles/write face，又在635行followUp决定是否包含对接层；status走该真实消费者。不能改用目标adapters身份字段，它不是来源kind；不能对fresh目标观察items，因为会提前返回。

**保留/边界**：全部五种YAML输入及来源kind业务判断；实际apply保护真实adapter组合、业务来源实际复制、包名不决定kind、旧桥接/脏写/不同来源切换等原真实测试。status必须正常成功，不能忽略knowledge错误仅抽items。若需要逐一证明五种写法都完成实际安装，应保留原五次apply；届时此项不能算退出收益。此项属于责任迁移候选，不冒充已验证等价。

- `extensions/.../entries.mjs:40 renderedEntries`按每个宿主入口重复buildAgentsTemplateVars。固定原生实现中entryFile主要决定AGENT_ENTRY_FILE，可能共用其他变量装配；但这需要修改Extension，超出本专题G0/X0，须设计者另核。保留所有宿主实际物化和共用目录warnings，不在测试侧缓存假结果。

- 更细缓存键可能帮助日常暖跑，但完整handback本轮状态冷建；不能声称能因此解决180秒。不要删除准备代码依赖求命中。
