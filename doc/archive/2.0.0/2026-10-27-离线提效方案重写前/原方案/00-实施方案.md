# 离线全量验证提速方案

2026-10-27。依据[需求](../../../spec/2.0.0/2026-10-27-离线全量验证提速/00-需求.md)、[定向诊断](../../../diagnosis/2026-10-27-135851-维护自检.md)、TEST§5及当前测试源码。优化已提交基线368cb18d，读取时HEAD036f5c6f；正在进行的第三批功能返修是独立在途工作，实施时取实际对象，不回退到旧HEAD覆盖它。

目标是当前改动后首次所需准备也计入的完整handback≤180秒，功能与性能双通过。已有数据支持工作量与争用需要收敛，但不支持提前承诺达标；本方案给确定修改，不用满载参数扫描找方向。

当前接续：独立worktree a4197b5c三步实施后未达标。按[完整工作量与达标预算](参考/01-工作量收敛与达标预算.md)在原步骤01/02集中返修，再进入03；该页补齐全部测试族、真实函数/入口边界、固定依赖与性能条件，接替[首次受阻答复](评审意见/2026-10-27-171328-独立工作区受阻调查与设计答复.md)中的有限收敛范围。原失败和答复保留。当前为方案可实施、性能待证；不新开批次、不先继续调worker或全量重跑。

## 1. 根因与明确动作

| 已核事实 | 工程决定 |
|---|---|
| full和failure各建一次同组合模板；装配类在一次full观测中259.9秒 | handback由verify真实装配一次，两通道借用同一对象和身份记录；独立full/assembly按原语义自己构建 |
| 局部规则矩阵重复init/人签/冻结/原生加载，round1直接Popen6799次 | 矩阵调用已有生产导出函数、同进程批量独立输入；关键生产者和CLI语义保少量真实组合 |
| S01/S02/S14、R04忽略root/ctx却在internal和real重复同一序列 | 本次同安装执行器同输入只执行一次；结果注明内部判别/组合验证身份，不冒称不同业务对象扫描 |
| mechanism真实目标默认仍读开发源，M15也硬指开发源模块 | 显式传安装扩展根；M15脚本消费显式模块路径，源与安装件同源由装配检查承担 |
| 多通道分别auto/进程池/j0开满 | 整个handback只有一个并行总预算，静态分配给既有通道，禁止乘法式扩张，不新增调度器 |
| 缓存缺准备代码依赖；冷builder读未初始化root；register回放旧输出 | 先修正确性，明确哪些用例测后置消费、哪些必须执行生产者；不把暖缓存绿测当新对象生产证据 |

## 3. 运行资源与度量定案

verify的full/affected/failure-modes/handback允许可选`--jobs N`，含义是本次离线运行的总worker预算，正整数。默认沿本机可用逻辑核数（能读process可用核则优先，否则cpu_count，至少1）；Case计划的jobs仍是Case并行含义，不借此改模型运行参数。

handback使用现有三通道；第三通道固定串行：触发时先第二次独立装配pytest -n 1，再runtime/compile/语法（pytest不再auto、compileall不再j0）。总预算B≥3时先保留第三通道1，再令H=B-1、full=min(H-1,ceil(3H/4))、failure=H-full，保证两条重通道各至少1且总和不超过B；B<3时三通道顺序执行且每通道不超过B。当前32核对应24/7/1，B=3对应1/1/1，B=4对应2/1/1。这是消除超订阅的明确初始策略，不是已测最优配额；180秒主要依靠退出重复工作，不能把这一比例当性能保证。

不为调比例先跑全量矩阵。完成方案后一次整轮结果若表明某通道结束很早而另一通道排队，才允许用该证据作一次有明确预测的配置修正，并固定其他条件。没有证据不连续试16/20/24/32。

沿现有计时JSON补源码/工作区摘要、完整命令、各通道jobs、有效状态键及命中/本次构建、阶段起止与总elapsed。总计时从verify入口开始，覆盖装配、pytest收集、所有通道及必要收尾；失败在finally记已完成时间和真实状态。原产品检查退出语义保持，功能通过与性能达标单列；代码0不自动等于180秒达标。

控制分解更新为：入口与首次装配60秒、三通道并行窗口110秒、记录和收尾10秒；第三通道的第二重建与其后轻检查合计也须装进窗口。实际首次约48秒、收尾约3秒，旧对象留给并行的实际余量约129秒，见[预算推导与工作量缺口](参考/01-工作量收敛与达标预算.md#3-时间预算和固定依赖)。这是定位约束，不是未实现的收益预测；最终按完整总墙时≤180秒且覆盖成立判定。静态接口调查能证明可实施，不能代替性能验收。若已知保留串行链超过可用窗口，先定位责任，不重复整轮确认已知超限。

## 4. 保持与验证边界

- 保留当前全部必要离线职责；变化触发的assembly第二次重建继续沿TEST，不因它慢改成可选。`handback --assembly`将ASecondEmptyDirectoryRebuildsTheSameCombination置于第三通道首项，显式单worker独立重建；full始终deselect此类，确保没有漏测或重复。该顺序接替旧方案“放入full”的安排，使用既有第三通道预算。第二份boundary及原生日志在私有目录清理前保存，原始身份不改。本专题最终验收仍按`handback --assembly`包含必要专项，总墙时≤180秒，不能扣除专项。后续无触发时按TEST复用有效专项证据，不以范围变化隐藏本次成本。
- 不把原生生产结果预写成通过；不mock本仓checker、原生派生或被测试的状态转移。边界替身仅用于已有外部系统/宿主结果和定向错误输入。
- `framework-access.readFeature`有按root/feature/phase/run缓存。批量独立样本使用独立合法projectRoot；同root改字节后重读属于缓存/恢复测试，保持新进程或其原有真实入口，不改run ID逃缓存，不加产品clearCache导出。
- F1/F2及迁移U类仍按原评审收口；降层不是退出有效能力。test/TEST.md负责最终命令和触发条件，tests/README解释写测试纪律；不生成第二套规则入口。
- 原报告、历史运行数据及其他版本资料不动；本次新的证据按TEST放output/evidence与verify既有日志目录，不复制清理旧suite。

## 5. 成本与接手

本专题设计默认不改extensions，交付机制G0/X0；原2.0.0已批准额度和累计不变。新增只限现有测试脚本的参数、借用上下文、局部驱动及记录，不安装新依赖，不建长期服务、通用测试DSL或调度/结果平台。清理的重复代码/空壳按实际diff解释，不用测试域不计预算作为无界扩建理由。

执行者先核当前未提交产品返修与同名测试文件，按原任务授权保护/提交或明确基线后接续；不得整文件恢复368cb覆盖F1/F2返修。正式计时前固定候选对象，运行中源码变化则这次只留观察，不作达标基线、不自动重跑。

若确需新增产品导出、改原生协议或越过其它明确边界，交设计者说明必要性和更简单替代，相关部分暂停；其余已定工作继续。此次方案编写不代执行者修改产品或启动新测试。

## 6. 讨论与修订依据

用户先要求从测试必要性和方案看耗时，确认handback全部必需离线2–3分钟；随后要求直接解决、先分析清楚给方案、不要乱试。第一轮优化的收益保留，否定继续仅凭猜测调worker/堆缓存或只压full数字的做法。

本轮追加源码调查确认四个failure内部/real完全重复、安装扫描回到开发源、M15硬路径、批量原生模块缓存隔离条件，以及可直接调用的生产函数。它们使本方案从诊断建议变成具体责任替换。未做新性能试验，原数据的冷暖/构建绑定不足仍如实保留，不编造节省百分比或达标承诺。

2026-10-27受阻后，用户要求补齐能否达标的设计。首次答复只覆盖缓存和少数例组，不足以解释全量；新增[工作量总账与责任迁移](参考/01-工作量收敛与达标预算.md)覆盖全部类和通道，明确已存在的优化不重复记收益。固定Framework接口已核，但没有改后实测，性能保持待证。原Plan字节与原失败报告保留，历史路径见该页§6。
