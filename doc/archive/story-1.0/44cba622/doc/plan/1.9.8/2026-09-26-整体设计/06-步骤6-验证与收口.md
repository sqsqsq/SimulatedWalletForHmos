## 1. main 的独立清理

在独立 worktree/checkout 检查当前 main，保护 story 在途修改。按实际文件清点 doc/extensions、Story 专有 bridge、AGENTS/CLAUDE 的实例扩展表和 story-ext 标记区；存在其他由 Extension 生成的专有入口时同样列清。

清单显式包含 `.agents/skills/story/SKILL.md` 和 `.agents/skills/story-adaptation/SKILL.md`：它们虽由 Framework 生成，消费目标仍是已退出的 Extension，存在则删除。2026-09-28 只读核 main 时二者均不存在，交回登记“不存在”，不为了清理创建文件或删除整个 .agents。main 的四份 Framework 钩子配置不属 Extension 删除面，保持；Codex 路径修正仅作用于本版 demo，不能顺手修改 main 的框架接线。

只删除清点确认的 Extension 安装物及入口内容；保留 framework、业务、其他命令/skills 和标记区外文本。对精确文件清单核零残留，不要求整个 .claude/commands、.codex/skills 等宿主目录为空。

提交 main 独立变更并交回 diff，未获推送授权不推 origin/main。若无 Extension 的正常 framework 操作失败，报告实际失败并回对应上游责任，不把失败直接视为预期通过，也不在本版修 framework。

## 5. 各包评审的必查维度

按用户 2026-09-28 要求，每包及最终收口均从以下三方面审：Extension/framework/demo 的功能保持与实现、补丁/过拟合；文件位置/引用/定位及本地依赖关联；各类实际使用场景的输入、动作、失败处理与交互。按本包责任判断，后续包未到期项单列，不混作本包通过或失败。

| 场景 | 完成前必须取得的证据 |
|---|---|
| 维护设计者和实施者 | 根入口的必读链指当前目录；版本、方案和评审结果可定位；只读边界与实际宿主能力一致 |
| CLI 测试 | 开发源经正式安装进入 template，真实入口/命令可执行；各 Case 的系统快照和回灌隔离，source/template/demo 三者身份清楚 |
| demo 发布 | 待发布源、demo 干净前置、四类安装面一致、失败由 Git 处理、无旧开发文件混装，R197 保持面与开发版分别核 |
| 内网升级 | 从 demo 已装发布版执行，固定 doc/extensions 操作链可用，缺宿主源按 R197 拦截，知识和对接按所有权保持 |
| 人维护/新 checkout | 依赖可从说明恢复、本地链接可达、环境变量按实际宿主可设置，启动/失败/恢复说明可以直接使用 |

保留固定安装位命令、合法名称不误判及 demo oh_modules 链接检查。退出开发源直接执行、路径别名保护、目录源预读，以及安装事务恢复/源途中变化/目标外跳专用断言；保留其适用场景下的正常安装、所有权和失败报告覆盖。P1 历史通过不代表减法已经验收。
