## 2. 必须修正

### R1（高）：目标中的 Junction 可把安装写入带到工程外

`test/scripts/publish_to_demo.py` 的 `_plan/add_op` 只验证相对路径字面，未核目标路径链的真实落点。独立 fixture 在 target/host 放指向工程外目录的 Junction，bridge.target=host/entry.md；安装返回 installed，工程外原有 `human` 被写成 `package`。

修复：扩展目录、bridge、入口标记区三类写入面共用目标路径预检，真实落点必须留在明确目标根内；检查父目录的符号链接/重解析点，发现外跳或不能确定时在任何写入前拒绝。源遍历拒绝链接不能替代目标检查。补三个写入面的越界反例与正常目录正例，失败时目标内外文件都保持。

### R2（中）：完整源快照未覆盖“本次无需重写”的文件

`install_extension:372` 只复核 ops 中对应的 source；源文件与目标原字节相同时不入 ops，安装途中改变它不会被发现。

独立 fixture：目标已等于源，将 a 改为新版本准备安装；写 a 时把源 z 改为 Z2。安装返回 installed，但目标 z 仍是 Z，源和目标不同。本次正式 template 的后置比较可以抓到一部分此类情况，独立发布 API 仍错误报告成功。

修复：成功出口必须验证完整固定源集合及其字节未变，包含未写文件、已写文件、增删文件、bridge 和扩展段来源；源变化按已有 write_failed 清单处理，不自动回滚或重选源。保留逐文件写前检查，增加没有进入 ops 的源和已写源变化反例。

### R3（中）：临时文件的路径只写进内存，进程中断时清单缺项

`_write_file:326` 先在 item 中设 temp_path 后写临时文件，但磁盘清单要到调用者返回/捕获 Exception 后才保存。

独立模拟进程在临时文件已写、os.replace 前中断：目标留下 `.a.txt.install-…`，磁盘 manifest 中没有任何 temp_path。现有测试抛 OSError，恰好仍经过 except/save，不能证明进程中断时的恢复链。

修复：临时路径和预期摘要必须先持久化到现有清单，再创建/替换文件；清单自身用原子写，保存失败不得继续后续目标写入。加入不经过 Exception 收尾的中断点检查，核磁盘清单能定位临时文件，恢复时仍按内容保护后来人工修改。复用本次清单，不新增运行状态系统。

### R4（中，含设计澄清）：demo 脏状态只记录，不影响装配准入

`run_multi_case.demo_state` 读取 git_status，`create_workspace_template:266` 只拒绝结构漂移，随后即复制。独立 fixture 的 demo 业务文件有未提交人工修改，template 仍创建并带入该修改；前后相等只证明装配没改 demo，不证明所用的是提交的发布基线。

本版已定 demo 是发布基线、开发修改来自 extensions，因此在此明确：demo 的非忽略变更须在复制前报告并拒绝装配；Git 查询失败作为错误，不能用空 stdout 表示干净。正常 ignored 依赖/运行态不因此被阻止，不 stash、不还原人改内容。补脏业务文件、脏宿主文件、Git 失败、干净基线四种场景，拒绝时不创建 template/Case。前述方案“有修改报告”没有明确停止点，设计责任在此补齐。
