### 4.1 README 的唯一职责与章节

根 README 面向使用者，只说明当前产品与用法。顺序定为：

1. 产品定位、适用对象与运行位置：目标工程路径，本仓对应 demo/已装消费副本；维护说明链接 AGENTS。
2. 快速起手与命令：系统单、本地单的正常入口及用户需给出的输入；命令来源核当前 Story SKILL。
3. 人参与的位置：补料、定范围、确认与评审、交付选择。步骤按实际流程，避免把模型机制说明塞进用户动作。
4. 能力与产物：能力/实际行为两列表，主要产物另表。去掉最近变化版本、本版变化等演进列；与命令节重复的说明合并。
5. 安装、升级与跨工程复用：前置、demo已装发布版取源、六份宿主入口、目标知识/对接/身份所有权、失败时该由谁处理。adapt不安装README；维护者另行分发，开头写清它是Story使用说明，避免覆盖目标仓自己的README。

不写待发布、本版重点、最近改动等版本叙事。开发源、demo安装版身份由对应manifest确定；不可把尚未发布的开发特性声称为当前demo已经安装。独立“需求交付流程.md”保留，链接称为“AI交付流程与演进方向”，将其未来方向与README当前能力区分。
