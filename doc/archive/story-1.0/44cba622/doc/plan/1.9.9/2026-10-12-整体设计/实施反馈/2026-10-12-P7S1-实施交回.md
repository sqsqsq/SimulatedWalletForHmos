# P7 S1 实施交回：闭环与完整失败

2026-10-12，维护实施者。对象：[P7 分册 §2、§3、§6 S1](../08-R7-性能与失败解释.md#2-所有失败的交付合同本轮用户新增重点)。已实施，按用户指示不等评审、继续下一步。未提交。

## 1. 实际改动

| 文件 | 动作 |
|---|---|
| `hooks/spec/post_check.mjs`、`hooks/plan/post_check.mjs` | 退出 `reportProblems` 调用。审前门禁不再读本阶段报告，写报告不会改变审前结论。 |
| `hooks/shared/verifier-report.mjs` | `reportProblems` 改为内部函数。<br>新增 `reportCheck`：没有 summary 判 FAIL，并给出完整跑 harness 的入口；没有报告落点判 NOT_REVIEWED（「未审」，不算 PASS）；落点上没有报告时，只有沿用有效的历史 PASS 才放行，并写明未独立重审，其余判 FAIL；有报告时依次核格式、判据、一对象一结论、处置记录；规则读不出判 ERROR。<br>新增命令出口 `--feature --phase [--project-root]`：退出 0 通过或未审，1 有问题，2 参数或前置错误。失败时先给恢复类别与入口，再给问题清单。<br>`withoutCurrentReport` 只在 spec 阶段核读者审查那一行，plan 等阶段沿用历史 PASS 时同样成立。 |
| `story/delivery.mjs` | 交付门先跑 `reportCheck`，再跑 check-receipt，两边的问题一次报全。<br>去掉 `.slice(-12).join(' / ')`：check-receipt 的 stdout 与 stderr 原样逐行缩进带出，前面先给「spec 阶段闭环未成立 + 按『闭环』表恢复」。<br>环境类失败分开说：回执脚本缺失归 Framework 安装维护；缺 ts-node 归环境依赖，入口是 `npm install`；子进程起不来归环境问题。 |
| `flow/update.py` | 收口时，对开轮已闭环、这一轮审查对象变了的阶段跑报告核对命令，原话带回，直接 close 不能绕过。`cmd_update_close` 显式接收工程根。 |
| `flow/lifecycle.py` | 新增 `_said`：子进程的 stdout 与 stderr 都带回。登记归档时去掉 `[:2000]` 截断，交付门的原始输出放进报错。 |
| `flow/client.mjs` | 状态查询失败时 stdout 与 stderr 都带回，不再二选一。 |
| `story_flow.py`、`story-build.mjs`、`hooks/shared/gate.mjs` | 顶层的意外异常都保留原始异常全文，并写明「这一步没执行完 / 判据从出错处起没跑完，不是产物问题，归扩展维护者」。story_flow 输出 JSON 并退出 2，story-build 退出 2，门禁仍按 BLOCKER。 |
| `phases/spec.md`「闭环」 | ⑥ 改为「报告核对 → check-receipt → 收口 → 交付门」。新增落报告之后的三行动作表：<br>• 首次审完、未闭环：走 sync-closure；<br>• 格式不合：同一 request 重投，作者不改报告；<br>• 已沿旧报告闭环、之后补了当前对象的审查：完整跑 harness 采纳。<br>原「报告结论怎么处置」表保持不动。 |
| `phases/update.md` 第 9 步 | 收口核对加上报告核对。作者页原本就指向「闭环」，没有另写。 |

## 4. 未决与说明

1. **Framework 原生错误未逐条核**：check-receipt 自身的报错内容现在原样透传，我没有逐条核它是否满足「不读源码即可理解」，也没有登记上游缺口。这类核对需要真实闭环失败的样本，交评审决定是否在授权实跑里收集。
2. **「未审」的退出码**：没有审查员时命令退出 0，状态行写「未审，不是 PASS」。方案只定义了 0/1/2，这里没有另设退出码，消费者要读状态行。
