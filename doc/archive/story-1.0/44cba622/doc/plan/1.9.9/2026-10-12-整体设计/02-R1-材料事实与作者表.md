# P1 / R1 材料事实、作者表与图文合同

必读：[实施总览](01-实施总览.md)、[R1 spec](../../../spec/1.9.9/05-材料清单与图文合同.md)、[返修定案](09-2026-10-13-返修合同与验证安排.md)。本包定输入身份和作者表，P2 在同一身份上开放递归。当前分额 G380/X110（初始 G310 保留，调整见总览），遵守 AGENTS §5。

## 1. 合同与职责

| 对象 | 真源 / 生产者 | 消费者 |
|---|---|---|
| inbox 原件身份 | 相对 inbox 的 POSIX 路径＋当前内容摘要；importer 枚举、registry 计算 | 归类、pending、update、作者与读审 |
| 实际采用输入集合 | registry 根据 sources、合同声明的文档落点、会议留存与转换映射派生 | 作者表覆盖检查与独立审查 |
| 转换关系 | importer 的真实归类与转换落点，registry 复用其算法 | 来源覆盖，不另写导入回执 |
| 材料采用与贡献 | Story 附录的作者三列表 | 评审人、独立审查、来源检查 |
| 图片说明与不用理由 | 既有内容身份和 captions 登记 | 正文引用、作者任务、读审；不重复抄入贡献表 |

材料表表头为 `材料 | 来源 | 贡献`。材料列写可识别名称及采用阅读稿的相对链接；来源列列出原件链接及采用版本，版本优先使用原件已有版号/会议版本，无版号时写内容摘要；贡献由作者写明当前采用信息，未采用写原因。机器只核来源身份与覆盖，不能从贡献文本关键词决定是否采用合理。

同一转换稿合并多个原件时一行列齐所有原件，不为计数再列原件行。独立原件可独立一行。会议行指向留存版本的原件/阅读件，不能只指 notes 或结论。远端直接取得的 RR/SR/AR 文档没有 inbox 原件是合法输入。图片按现有引用/不用链管理；生成的 Spec、Story、Review、写作设计不作为上游来源贡献行。

只抽图的文档仍是来源：IMAGES 原件一行，材料列与来源列可同指原始文档，来源同时写采用版本，贡献说明只采用哪些视觉信息、正文不采用或全部图不采用的理由。图片自身不逐张重复成贡献行；原件到图片的关系由机器事实提供，图片去向沿既有登记核。不得把“不列图片”解释为“不列提供图片的原件”。

“五类对象区分”不等于强制五类都出表：缺原件、转换关系、输入图、会议版本与生成件须能被区分；生成件被误列为来源时报告，不能让它替代遗漏原件。表内真实文件名允许空格、中文、括号和转义竖线；链接相对 Story 所在目录解析。

## 2. 机器集合派生

保留 `materials.json` 当前 `materials`、`sources`、`digest` 职责。在同一机器文件内增加来源关系的派生视图 `origins`，不是作者维护的第二份清单：每项为需求相对 `path`、`sha256`、`kind`、`readable_paths`。`kind` 仅表示 direct / converted-source / meeting；图片仍在 materials 的 image 集合。

R03 的确定落法：已 ingested 的 IMAGES 文档归 `converted-source`，`path/sha256` 取其原件，`readable_paths=[原件路径]`（本次只有图被采用，没有伪造的正文转换稿）；增加该项的 `image_paths`，列本次确定性抽取且落盘一致的图片路径。其它来源可无此字段。`image_paths` 只存路径关系，图片身份/取舍继续消费 materials 的现有 image 项；相同图片的多落点按既有内容身份关联，不另存一份图片身份清单。

`collect_sources` 在已有 IMAGES 转换与字节比对处取得“源键→图片路径”，把这份计算结果交 collect_origins，不再次解析 docx、不由文件名猜业务来源。未导入或抽取结果不完整仍是 pending，不能先生成有效 origins。作者/读审同源得到原件、版本及图片关系；覆盖检查允许材料列链接原件自身，漏这份文档仍报漏源。原始图片直接入 UX 的既有取舍链保持，本次不为每张图片增加贡献行。

inbox 的源键仍叫 `file`，含义统一为相对 inbox 路径。转换来源由 source→class→doc_targets 与已并入事实推导；对被当前 inbox 确定性转换完全承接的正文目标，不再把目标自己算作第二份原件。直接远端落点照合同枚举；可选来源缺席单列正常不适用，必需来源读不到明确报错。

集合只从既有权威位置取得，不递归整个需求目录猜原件，不纳入备份、updates、报告和生成件。有源在 inbox 尚未并入时先走既有 pending 处理，不能靠作者表写一行绕过导入。会议使用留存版本事实，不因重转改变已引用行号。

模型人工转写的来源只能声明“原件＋阅读稿”的关系，不能仅凭声明替 registry 证明确定性导入成功；读审必须能取得原件。原件格式超出现有导入合同仍沿当前失败出口要求可处理版本，本包不新增通用转写转换器。

`origins` 不进入 `compute_digest` 的第二轮计算，避免同一事实重复计哈希。它随材料刷新重算；materials schema 从当前 1 升为 2，缺/坏字段与旧 schema 分开报。当前 schema 的派生文件损坏可重跑 round；旧运行按升级演进要求在旧版收口或 init 重起，不编写旧表兼容分支。

## 3. 文件动作与步骤

### S1 身份和实际来源集合（当前分额 G185/X35；初始 G150）

- `materials/importer.py`：集中源相对路径取得，归类查找和转换分组使用该键；枚举仍保持顶层，递归由 P2 交付。转换返回的来源映射供 registry 消费，避免两个算法。
- `materials/registry.py`：sources 相对路径、origins 派生、schema 与完整性错误；保留 digest、pending、captions、meeting 语义。
- `flow/update.py`：同源使用相对路径的比较键、归类读取和旧原件提示；不将路径变化自动解释为业务替代。
- `core/import_sources.py` 的输出与参数说明、`rules/inbox_import.md`、`rules/init_analysis.md` 同步键含义；首个产品提交升 manifest。

验收：平铺原件在新键下行为不变；同类多份正确形成一对多来源；远端无 inbox、会议复用、缺来源与未导入分别有正确结果。相同输入多次刷新 digest 不变，改贡献文本不变，改有效输入内容则变。

### S2 作者表、检查和审查同时替换（当前分额 G195/X75；初始 G160）

- `story/sources.mjs`：材料节骨架只有表头和填写指引，内容归作者；覆盖集合读 origins，不再混合“正文＋inbox”重复要求。
- `story/language.mjs`：旧列表行语法退出，改三列表结构；复用 `document.mjs` 表格/围栏解析。空格路径和含括号链接按有界 Markdown 解析，无法解析明确报位置。
- `story/writing-plan.mjs`、`story/drafts.mjs`、`phases/story-write.md`、`contracts/story-chapters.json`：替换旧图前全文复述要求，统一图前概括、图后补未表达的条件/责任/结果；不按字数或固定列表项数判断语义。
- `hooks/spec/author.mjs`、`hooks/shared/reader-review-task.mjs`、`rules/spec-rules.overlay.yaml`：同源交付材料全集、转换关系、缺件与采用表；独立审查核贡献与来源，不信作者表自报完整。
- `reference/evidence-rules.md` 与 `rules/spec-rules.overlay.yaml` 的来源说法接 P7 的已登记材料名口径；不为一个业务域加原件名称表。

验收：漏行、重复原件行、表外来源、生成件伪作原件、缺文件各被点名；两个原件合成一稿为合法正例。表中采用错版但文件都存在，应由独立语义审查发现，不能宣称机械覆盖已证明忠实。图中文字已经讲明时不因“少一句空话”失败。

R03 补验：只取图原件能由材料表追溯；全部图标为不用时原件仍有有据去向；两份文档含同一张图时两份原件分别可回查、图仍按内容身份去重；少一张抽取图保持 pending；原件换版本时 sources/origins 与 update 的来源比较如实变化。origins 派生及贡献文字不另改材料 digest 算法，不制造写表→新轮次的循环。schema 2 尚未发布，直接补齐本版结构与消费，不再开兼容分支。

## 4. 回归与退出

扩展 `test_material_rounds.py`、`test_material_delivery.py`、`test_author_task_package.py`、`test_story_build.py` 及相关 failure-modes fixture。用不同材料类别、中文/空格路径、同内容不同文档验证，不依赖 Case 专名或固定行数。

退出：作者材料列表旧语法、旧解析断言、重复要求转换稿和其所有原件各独立贡献一行的规则，以及文件名作身份的消费者。保留：转换算法、材料摘要、原图取舍、机器投影四节、会议版本与备份恢复。

退出量按初始基线只计一次：S2 的 X75 包含共用图文规则替换，P3 不再次计同一批旧行；同文件中不同职责的改动按实际行与消费者归属划分，不能以包名不同重复登记。P2 复用本包的路径/预检能力，不再建第二套归类校验。依据为[澄清 §2](../澄清-设计者说明.md)。

失败报告按 P7：原件所在位置、哪条关系不成立、机器如何取得集合、恢复类别与真实入口，一次列出；具体来源取舍和修法由消费模型据事实推导，不要求读 registry 源码。完成交回应能沿原件→阅读稿→作者表→读审走通；只改表头不算完成。
