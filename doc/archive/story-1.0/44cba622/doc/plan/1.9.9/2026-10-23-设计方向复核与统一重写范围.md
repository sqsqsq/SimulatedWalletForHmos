# 1.9.9设计方向复核与统一重写范围

2026-10-23，维护设计者Codex。用户已明确：SVG是已有图的增强阅读形态，不是额外补图。本文件记录机制检查、必要替换和其他反复问题的方向复核，供一次统一重写确认；不作为新增产品开工包，不与G120方案并行执行。产品、当前标准正文和既有方案未在本轮改写，未启动CLI。

## 1. SVG的实际错误不是模型不愿意工作

现行 `reference/svg.md` 标题就是“写作设计选中的补充SVG”，明确正式图不需要SVG、SVG候选ID不必对应Mermaid；`writing-plan.mjs`要求模型写问题/增益/放置/依据或“不采用”；`figure-view.mjs::readingWork`把明确不采用判为已完成；`formOf/inspect`把单张正式图块里的SVG引用识别为old-svg并拒绝。

这四处共同形成执行目标：先把正文与Mermaid写好，再判断要不要加图。模型判断重复、选不采用，是按任务完成，不该归为不确定性。最近多轮增加阅读增益提示，是在强化错误问题，不能实现用户期望。

### 1.1 最小目标链

以当前Story正式图为范围，不扩展为扫描整个仓库或转换所有外部位图：

已确认的正式Mermaid → prepare登记图ID与.mmd真源 → 为该图制作同ID SVG阅读形态 → 对照同一.mmd做文本语义/结构检查 → 在该图原位置切换显示。

- 一张逻辑图一个ID，`.mmd`是唯一语义真源，SVG是其派生呈现。
- 正式/审查/归档形态仍保留Mermaid；本地增强阅读形态在同一个受管块内显示SVG，不同时插一张同义补充图。
- 任务由已有图清单确定，不再要求作者提出新的阅读问题或新增事实。已有受管图默认进入增强阅读工作；没有正式图时自然不适用，不为覆盖强造图。明确生成失败/暂未完成不能用“不必要”伪装完成，原Mermaid仍可读。
- 模型负责布局、分组、文字排布、角色区分等视觉表达；不得删边、改触发条件、合并不同业务状态或补新事实。需要改语义先改.mmd并走原业务审查。
- 沿用已有SVG结构检查和现有独立审查入口；文本审查比较该图源与SVG的文字/节点/连线/条件，以及可从源码判断的布局关系。不再审“为什么还值得补一张图”。普通模型可执行，不恢复PNG/多模态强制前置；实际显示裁切/遮挡仍按真实渲染证据另判。
- 不新增渲染服务或图形DSL。若现有工具已能满足某图的呈现，允许使用，不把所有图强制交模型重新创作；当前检查未取得一个可直接作为产品依赖的通用Mermaid→SVG渲染器，不能在方案中假定已有。

### 1.2 文件动作与旧机制退出

| 位置 | 最小动作 | 保留 |
|---|---|---|
| `writing-plan.mjs`、`story-write.md`、相关合同/模板 | 删除阅读图候选四字段、不采用理由及专用解析验证 | 正文写作设计、上游图关系承接、实际业务图选择自由 |
| `figure-view.mjs`、`document.mjs` | 正式块支持Mermaid/SVG两种当前形态；同ID原位切换；完成集合从.mmd/受管图派生 | prepare、status、toggle、指定ID恢复、源丢失/块损坏保护、正式命令前还原及后恢复 |
| `figure-reading.mjs` | 请求改绑图ID、mmd实际内容、SVG、本地资源与当前审查合同；退出候选、跨材料依据和放置节全文绑定 | 哈希防陈旧、报告对象一致性、真实独立返回、资源路径安全与XML检查 |
| `reader-review-task.mjs`与Spec相关overlay | 删除是否补充阅读图的独审作业；业务图源仍按事实/关系审 | 原业务完整性与未决约束、原图来源核对 |
| `reference/svg.md`、路由/交付恢复调用、帮助与启动器 | 统一写同图增强视图生产、完成和恢复 | 用户现有命令与单Story阅读，正式归档无本地坏链接 |
| 图与写作设计测试、失效台账、R4及标准B3/B4 | 退出补图候选/额外槽的专用测试，改测同图双形态与真实源变化 | 有效局部恢复、人工区、无关内容不误失效、原图材料功能 |

退出第二套 `story-reading` 阅读槽及其布局/重排/候选取消协议，退出“有图再证明额外价值才生产SVG”、独立候选ID与位置顺序声明，退出“同图SVG原位显示是旧格式”的禁用分支。`sources.mjs::basisFiles`若仍有其它生产消费者则保留，不按文件名整删。

历史运行/金样不自动重写；旧补充SVG没有相同语义对象，不能按同ID迁成增强图或沿用审查证据。对已退协议遵守项目不兼容规则，不新增两套入口。有效期内的同图双形态对象则必须保证纯格式变动不误失效。这两种情况不能混称“一次重审例外”。

### 1.3 空行问题随责任收敛

目前阅读绑定依赖选定Story节全文；加空行改hash本就来自绑定对象过宽。同图增强的权威输入是.mmd与SVG/资源，Story块外空行和邻接正文不应使这张图重审。切换仍核当前位置属于同一图ID，图义变动由.mmd检测。

因此不另建全文stable格式兼容、旧hash白名单或内容相似度。现有注释边界分隔、生成区摘要与人工区保护保持；已做的重复生成修正仍需回归，不能为减代码删有效保护。

### 1.4 必要验收

- 同一个正式图ID派生SVG，不要求新信息；默认工作清单与已有图一一对应，缺图源/缺SVG/未审各有准确状态。
- 同位置切换后只显示一种图；两种形态往返及重复prepare字节稳定，人工正文不改。
- SVG删分支/改变返回方向/丢异常条件应被文本审查指出；合法布局与换色不因“无新增事实”被拒。
- `.mmd`、SVG或资源真变更使对应证据失效；无关章、注释空行、编号、纯切换不误失效。
- 正式检查/归档使用Mermaid并按原机制恢复可用阅读形态；失败保留源与原件，不把不完整说成完成。
- 有限真实CLI验证作者自然完成“同图增强”任务，不以补一条人工“请画SVG”指令代替正常入口效果。范围待统一方案与运行授权固定，不本轮起跑。

## 2. 对其他反复问题采用同一反思方法

### 2.1 未决承接：目标不能同时是供人评审和已批准施工

原生轨迹已证明作者发现问题，审查者也看到open，但把“具体候选+待定披露”理解为正常评审交付。若此时只是讨论稿，这种行为未必错；若机器契约已可直接消费，就存在授权边界缺口。不能继续以更长禁止语调和两个不同目标。

收敛建议：区分“语义/结构审查完成”与“业务决定已批准”。允许候选进入评审说明，但不能将其默认为已批准验收/施工承诺；现有机器契约及下游入口须能识别这一限制。先核当前阶段/交付合同的消费者，再决定局部变更，不新增全套审批台账，不用全部open阻断。两轮没有coding实证，不能声称已发生未授权编码。

用户此次只明确了SVG，不据此替用户批准“Plan可候选通过”或“所有决定必须先问完”。统一稿将分别写清评审稿与施工输入的完成条件，若当前架构无法保持两者区别，列出真实依赖和最小选择，不能委托执行者自行发明新状态。

### 2.2 独审：目标是检查实际结果，不是把每个检查格填齐

原报告正确发现接受侧数据源/分层问题，说明能力存在。对授权的误放不是没读原件，而是沿用了候选可交的目标解释；一些时间又花在四键/条目覆盖/同subject重发。应该先使作者、独审、harness消费同一个完成含义，收敛报告输出合同和正确命令，不再给审查者增加同义审查条目。

harness能确定检查角色/对象/报告形状/已有明确阻断结论是否一致；业务意义仍由模型判。没有可靠结构映射，不新增“open关键词→FAIL”规则。正确的目标和一致输入建立后，对不改变实际承诺的表达波动接受，不继续追求零漏判。

### 2.3 usage：统计工作轮次，不是统计检查器轮次

当前pre_phase每次harness都会发生；原生summary可在后续返修前已经关闭；刷新一读到关闭就清起点，再按检查重开。测试却用set_start人工放入理想起点，因此容易证明局部算法而漏掉实际调用序列。

应先重放最近真实链：进入工作→首次检查→中间闭环→人答/改稿/独审→再检查→正常交回，按已确认“完成轮内含等待”计算边界。只在能可靠观测的原生/Extension动作处采集，缺起点明确缺口，不造整套事件账。先确认完整区间与现有触点的对应，再决定是否将结算移到finalize。**此前直接锁定finalize为唯一修法，仍是围绕现有脚本找补丁，证据不足；应从统计目标反推最小触点。** stats继续只读usage/Git，不为采集漏记补账。

agent未知是信息可得性/合同边界，不能与时间数值错误捆成同一个必修包。不猜宿主、不向用户增人工中断；是否允许Story的agent未知仍按此前待裁定项处理。

### 2.4 update测试：送达完整评审意见，不是命中固定标题

现有投放器用标题关键词代表意见对象，并用后写覆盖同题意见。这是测试对产品表达施加隐含约束。修在现有投放器：语义对象唯一可定位、同题意见完整保留、缺投可见且不称完整测试。不让模型固定标题/D号来配测试，不为投放另建状态系统。

### 2.5 性能与表达：以完成有效工作为目标

纠正缺参数示例、报告消费冲突、无变化重派审等可证明浪费；剩余真实推理/必要纠偏是模型执行成本，不把超过早期期望时长一律当机制缺陷。图数/图型/段落长度/模式选择不与金样逐项一致，不再单独阻断发布。内容变错、遗漏关键条件与授权问题仍检查。

## 3. 统一收敛的边界

重写后建议最多三个可独立验收包：

1. 同图双形态：合并SVG目标纠正、候选/槽退出与空行绑定收敛。
2. 正确完成与正确记录：明确评审/施工边界、修查实的报告/命令合同，先重放再定usage触点；不扩大语义提示集合。
3. 测试可信与集中验收：修意见投放，保持现有装置；离线先证确定性，再授权有限CLI验证组合效果。

保持R1/R2已成立能力、材料/人工区保护、固定10.4删除、V5持久文件与stats独立、纯initial交付、知识所有权和Framework只读。不因本轮改方向恢复旧状态账、强制多模态、整仓格式化或测试平台。

预算不能机械沿用G120：SVG这次是职责替换和删除，原S1“强化SVG取舍”与原S3“保留宽绑定再归一空白”的预算对象都已失效。统一重写时从当前17224有效量和真实diff基线推演新增/退出/峰值，原分母、空行实际G49及未确认G9保持，单列新预计量再按AGENTS §5确认。本轮没有新增实现量，也没有批准任何额外预算。

发布只核新目标及必要保持项：同图SVG正常产生且语义保持；统计区间真实可靠；已有授权不被候选偷换；输入投放与证据可信。已有正确能力及可接受表达差异不反复重开；未覆盖按实际范围披露，不无限扩大测试矩阵。
