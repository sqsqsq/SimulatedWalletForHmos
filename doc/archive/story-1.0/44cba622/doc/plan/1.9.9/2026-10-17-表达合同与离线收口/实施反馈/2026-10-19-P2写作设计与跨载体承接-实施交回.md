## 1. 生产者与消费者

### 1.1 写作设计是唯一解释

`skills/story/scripts/core/story/writing-plan.mjs`：

**承接登记**：
- `## 骨架` 里任一章或小节下的 `- 承接上游图：<来源> <身份>`（身份沿用 SR / spec 的节号与节内序号），解析成 `plan.carry`，每项记来源、章 ID、`at`（#### 小节）、`under`（##### 子节）。
- 这是内存派生值，不另存映射。原说明行照样进草稿指引，提交时剥掉。

**承接校验**（写入 `plan.problems`，由起手、章提交、全篇 check 共同消费）：

| 情况 | 报出 |
|---|---|
| 当前上游枚举出的图没有一处登记 | 没登记，并带图的主题 |
| 登记的身份不是当前上游里的图 | 身份不真实 |
| 同一位置重复登记同一张 | 重复 |
| 登记行没写身份 | 空值 |

一源多处、多源一节都合法。上游没有图时，不要求任何登记。

**阅读图选择**：新增必需的 `## 阅读图选择`，解析成 `plan.reading = {declared, noneReason, items:[{id, question, gain, placement, basis[]}]}`，规则如下：

| 项 | 规则 |
|---|---|
| 不采用 | 「不采用：<理由>」，理由不能为空；与候选不能同时写 |
| 候选 ID | 只认字母、数字、`-`、`_`，大小写不敏感去重 |
| 问题、增益、放置 | 各一项，必填 |
| 依据 | 至少一行 |
| 放置 | `<章 ID> > <骨架小节> [> <子节>]`，要在骨架里找得到 |
| 依据的路径 | 必须在本需求内（拒绝绝对路径与 `..`）；只认 `AR/story.md`、`plan/plan.md`、决策登记、合同 sources、材料清单登记的 origins 与图片、`AR/story-src/figures/*.mmd` |
| 不能作依据的 | SVG、审查报告与临时文件；二进制原件（docx、pdf 等）改写它的阅读稿 |
| 依据的文件 | 必须读得到 |
| 依据的标题路径 | 只给 Markdown |

**空壳**：多一个阅读图选择占位，并在写法说明里加入承接登记的写法。占位行只由占位符那条报，不另报「没有结论」。

**新增的两个导出函数**：
- `carryTargets(plan, storyText, chapterId)`：按章名与小节名逐层精确定位承接位置，给出那一节的正文，或定位问题、空正文。
- `basisTargets(ctx, plan)`：正文写成之后，按当前内容解析依据里的标题路径。

### 1.2 定位规则

`story/document.mjs`：
- `findByName` 遇到精确同名两处，报歧义，不再取第一个。新增 `exact` 模式，只认完整名，不按包含匹配猜。
- 新增 `headingPath(text, names)`：每层在上一层管辖范围里找名字完全一致、取最浅一级，同级同名即歧义。承接位置与依据都用它定位。

### 1.3 消费者

| 消费者 | 现在做什么 |
|---|---|
| `story/chapter.mjs` 章提交 | 本章登记的承接位置在候选稿里定得到、有正文，否则不落盘。其他未写的章不要求 |
| `story/chapter.mjs::nextSteps` | 写到某章时，在 RESULT 下面列出本章登记承接的上游图：原图全文、原件路径与行范围、要落的小节。同一张图在本章多处登记也只给一次；按当前原件现取 |
| `story/check.mjs` ⑫d | 全部登记位置定得到、有正文；阅读图依据的标题路径按当前 Story/Spec 能取到。登记全不全由 ⓪ 写作设计那条报 |
| `hooks/spec/author.mjs` 作者包 | 「4a/4b 系统设计、spec 里的图（在 story 里的去向）」：给每张图的身份、主题、原件位置与原图全文；写明由正文、表或图承接、在写作设计里登记，承接是关系还在、不是照抄 |
| `hooks/shared/reader-review-task.mjs` 读者审查任务 | 上游每张原图，与登记承接它的**全部小节**（正文、表、图原样）并排；没登记、定不到、空着的位置明说。新增「阅读图选择」一节：不采用的理由，或每个候选的问题、增益、放置与逐条依据，并写明审查判什么 |
| `rules/spec-rules.overlay.yaml` | 语义判据改为两部分。上游图被改画或改写成表与正文后，核调用方、被调方、条件、请求与返回、结果、失败责任与有效决定是否保全；拆段断链、只留正常分支、表里写错条件都算。新增阅读图选择不合理的判据：不采用而讲不清，或选了却没有增益、依据编造事实、把未决当已定 |
| `phases/story-write.md`、`hooks/spec/author.md`、`story/drafts.mjs` | 写作设计改为三部分，加入承接登记行、阅读图选择的写法、协议例子与依据范围。「源图到这里还得是图」改为「关系要有完整去向，可以是图、表或分段正文」。草稿图指引去掉「围栏第一行写图源标记」 |
| `story-adaptation/reference/upgrade-changes.md` 1.9.9 | 加一条在途单条目：在途单补齐两项后重跑登记。不计预算 |

## 4. 顺带发现并修的一处（记 adapt 包）

全量并行运行时，上一轮新加的 PowerShell 补建测试两次失败，单独跑却通过。原因是 PowerShell 管道在某些环境状态下给 stdin 开头加 BOM，`usage.py` 把它判成「stdin 不是 JSON」。

修法：`usage.py` 的 stdin 改为按原始字节以 `utf-8-sig` 解码，不再随控制台代码页变，BOM 一并去掉。新增 `test_usage.py::test_stdin_is_read_as_utf8_with_or_without_a_bom`。修后全量通过。

这一处计入 adapt 包：G1/X1，adapt 包逐步累计 G77/X13，批准 G80。它属于 adapt 补建命令返修那次交回的延续，请一并评审。

- 承接与阅读图选择的**语义**（关系保没保全、不采用合不合理、增益真不真）只在审查任务与判据里送达，没有独立审查实跑。
