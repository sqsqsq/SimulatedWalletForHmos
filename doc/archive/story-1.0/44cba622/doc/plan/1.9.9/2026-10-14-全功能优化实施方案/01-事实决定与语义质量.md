# S1 输入、来源与决策：在行动前取得完整依据

必读 [总览](00-实施总览.md)。初始预计 G115/X45 保留为估计起点；当前 S1 已交回但需按[复评 RV01/RV02/RV05/RV07](评审意见/2026-10-14-需求覆盖与S1-S2交回复评.md)返修，预算按总览 §6 统一核。本步让初析、作者、检查与独审依据同一批真实输入工作。事实与决定不另建账本，必做范围不由作者已经写出的条目倒推。

## 1. 输入与送达

| 动作之前 | 必须取得 | 责任与输出 |
|---|---|---|
| 范围/拆分决定 | 当前 RR/SR/补料、会议有效版、已导入与 pending、项目画像 | 作者核真实能力与缺口，人决定范围，沿初析/提取稿记录 |
| Spec/Story | 确认范围、原件/阅读稿映射、decisions、激活知识、工程依据 | 作者设计正常/异常/未知结果，脚本给可引用名与结构合同 |
| Plan 冻结 | 有效 Spec、真实 API/定义/调用、知识义务、模式候选 | 作者落实入口、数据、状态、调用、返回、清理、验证；业务缺口回 Spec |
| update 改稿 | 新请求、现行决定、原有效约束、本轮 record/before、update-notes | 先判权限与影响，冲突经有权人裁定后传播 |
| 独立审查 | 上述原始依据、作者产物、适用判项、当前新旧对照 | 从原件反查遗漏，对当前 request 出报告 |

从 materials.origins/readable_paths、manifest 知识清单及 update.open 指向的 record/mirror.path 派生实际文件集合。保持原件与阅读稿对应。任务交完整目录、用途和稳定路径，执行体按需分段读，不内联全部原文制造膨胀。缺失、不可读和未审分开；文件存在不是理解正确。

复用 author、pre_verifier、reader-review-task 的装配位置，不另造任务包框架。当前有效依据变化进入现有审查片段身份；报告、阶段目录的 notes.md 审后处置和纯时间戳不进入。update-notes.md 是本轮审前变化判断，不属于这项排除。大输入保留原路径/版本和未覆盖范围，分段后核跨段关系，不新建分批调度或持久覆盖状态。

### 1.1 预期集合、存在性和能力分别判断

reviewInputs 接收当前阶段/用途，先按现有章节合同、材料登记、当前阶段应有产物、update 记录推导预期输入，再逐项读取。每项区分 required、missing/读取错误、用途及摘要；required 不能由 exists 决定。来源缺失、合法不适用、宿主无法读取三种事实不能互换。复用既有路径/材料/知识合同，坏 shape 不继续遍历造成 TypeError。

| 输入类别 | 适用和必需条件 | 缺失处置 |
|---|---|---|
| 材料登记及已登记原件/阅读稿 | Story 正式作者/审查时必须有有效 materials；每个 origin 的全部 readable_paths 独立加入，不能因同时含 image_paths 跳过正文；别名归并到同一对象 | 缺/坏清单不返回空正常集合；已要求的文件缺失保留为 required+missing，不能签依赖它的审查通过 |
| 原材料图及其取舍 | 从登记图集合和 origin 关系派生，不限于作者已引用图片；图片独立于同原件正文枚举 | 无视觉能力记未核及具体能力缺口，不因当前模型看不了而排除；已核有据不适用可说明去向，但登记“不用”不自动替代独审判断 |
| Story 专属产物 | 正式 Spec/Story 审查要求写作设计、Story、Review、decisions、Spec、acceptance 及已确认范围；初析/范围阶段只校其阶段前置，不提前要求 Spec/Plan | 必需件缺失返回前置问题；合法未到阶段不强造文件 |
| Plan 及其依据 | Plan 审查取得有效 Spec、当前 Plan/已有强契约、激活知识与对应工程依据，沿 Framework 现有阶段合同判断强契约必需性 | 不借“没有 story_reader_review 项”跳过真实输入/覆盖检查；S2 在现有 Plan 判项消费同一派生合同 |
| 条件材料 | 合同声明 required 的来源应保留；可选文件按真实登记/当前任务适用性加入，会议发生则要求对应原文/纠偏/判断；知识依据取 manifest 实际激活项 | 不用一律 optional 吞掉已适用缺口，也不要求无会议的需求制造会议件 |

图片文件和知识路径可位于各自已授权根，统一以工程相对路径交任务、规范化后核归属；不能只允许 feature 相对路径而漏知识，也不能放开任意越界路径。任务、报告和校验用同一对象到路径映射；报告中的覆盖声明只证明形式，不证明真的理解。

### 1.2 update 的真实输入与身份

从 update.open 取得当前 record.json，核 id/status/目录归属，再使用 record.mirror.path，不拼另一个 guessed before 路径。rid、mirror.path 和材料路径均校合法相对路径及所属范围；坏记录明确拒绝，不扫其他轮次替代。

before 的预期集合由 record.files、phases_before 及该阶段已成立的必需产物合同推导；record.files 已登记的旧件必须在 before 对得上对应摘要，Spec/Plan 已闭环时应有的验收/决定等也不能因删除变可选。合法从未到达的 Plan 不强求。before 目录空、记录不可读、应有项缺失都须报“基准不足”，目录存在不算完整。复用现有 record，不增加第二份快照台账；原始材料从 before 的材料登记和原件关系回查。

当前 AR/review.md 的人工原话、新输入与已定决定、本轮 update-notes 全部在审前送达 Spec 和 Plan 审查；update-notes 给变化依据、影响、决定和不变项，并入身份。作者在正式审查前写好它，审后采纳/报告处置写阶段 notes 或原有操作记录；实质修改变化说明必须按真实依据变化重审，不能为省重审把整份说明排除。

story-flow.json 不整份 hash，以免时间戳/成文登记自激；读取其中当前有效 split.scope_text、split.parts、范围选项与相关 gate 的选择/原话/依据，作稳定投影送达并摘要。会议裁定沿现有同源投影，不重复并列同段全文。真正范围变化必须改变输入身份；单纯时间、closed 标记和报告落盘不能改变。决定集合仍来自 decisions，不能由范围投影维护第二份决定。

## 2. 来源解析只有一个实现

现有 core/story/sources.mjs 输出内存中的可引用名、唯一事实对象、人读名和证据路径，供 Spec 作者、post_check、Story 附录生成及核对共同消费，不增加手工 alias 台账。

| 对象 | 权威身份 | 名称与失败 |
|---|---|---|
| 原件 | origins.path/sha256 | 登记相对路径、完整文件名；去扩展名仅唯一时成立 |
| 阅读稿 | readable_path 与承接原件组 | 仅真实登记且存在的对象；静态 label 不创建事实 |
| 会议 | original.docx 及 source.json 原名/完整 sha | 恢复原名并核与 origins 对应，同名多版本用现有版本标识消歧 |
| 人工决定 | 当前 decisions 的 id/status/clarification/decider | 已确认决定：ID；机械核唯一、settled 与依据字段，独审核人签真实性和权限 |

中文、空格、括号、逗号按登记完整名称匹配，名称后用公开的分隔/行尾；不短前缀蒙中。歧义列候选及唯一写法；缺件/坏元数据/身份不符直接报，不从目录名猜。保持 schema2/digest，不重解析 docx 来恢复名字，不增加历史格式兼容。

正式 Story 的来源检查/投影遇到无材料清单，返回明确前置错误及 round 入口，不能零 problems 静默跳过。一般尚未进入 Story 的早期草稿可返回“尚未适用/未核”，但调用方不得记作校验通过；出现上游标签就必须取得可核来源。catalog 的致命 shape/身份缺口独立进入诊断，不能只有标签解析另报错时才附带显示。决定 ID 在建 Map 前核唯一，重复 open/settled 不能后者覆盖前者；复用现有决定登记验证和错误说明。

数值依据统一为“上游约束：可定位材料名”“已确认决定：ID”“本工程设定，无上游依据”“平台基线”。动笔前给实际可用名/ID及意义；量、单位、条件和真实依据仍由模型判断。新工程值走已有决定流程，后续复用，不随机重选。脚本不把标签当真实，也不用 Case 数字判正确。

appendix.mjs 用同一解析把已识别标签的内部路径转成人读来源名，决定显示标题及必要 ID；保留量、条件、原文和材料链接。无法唯一定位阻断该投影并报真源位置。zone 核对复用同一投影结果；不全局删路径/数字、不让作者改机器区、不改 Framework hash。

## 3. 模型的决定职责

已有能力必须核真实定义/调用。通用页面、文件或方法签名不证明有具体业务对象、状态和数据通路。计划能力与工程事实分开；影响范围或验收的假设先给需求方决定。

涉及外部状态的操作分别设计明确成功、明确拒绝、结果未知，说明状态权威、确认、重试与重复副作用。协议缺查询/幂等依据时记具体缺口与责任人，不编造 API。纯本地计算不强填三态。

未决允许写所有备选共有的要求；选项专属行为以条件表达并关联接口/验收。“占位、待定、模拟”不是选边授权。范围内明确未定、来源冲突、关键能力缺口进入现有 decisions/Review；已有决定复用 ID，新决定才新增。人作决定，模型不代填批准。

update 不因材料更新就自动撤销旧约束。先比较变化权限与影响，有冲突按 open 议题问人，无冲突按授权推进。缺 before 是基准不足，不是无变化；不扫其它轮次凑基准。

知识原文义务必须落实为具名行为/实体/AC，核边界输入、保护/隔离/清理能力和验证。Plan 冻结 must/verify，后段沿已有合同执行；合理不适用和有依据的模式调整保留，不为覆盖率强用。

这些动作合并替换原有相关指引，删除平行解释。遗漏由 S2 门禁或独审发现，是否能发现由 S4 证明，不能每次失败再加一句 Case 特例。

## 4. 文件动作与保持

路径相对 extensions，任务按安装到消费工程后的路径生成。

| 位置 | 动作 |
|---|---|
| skills/story/scripts/core/story/sources.mjs | 共用来源/决定解析与显示，退出分散枚举 |
| hooks/spec/author.mjs、author.md、post_check.mjs | 同源可用依据和检查，动笔前送达 |
| core/story/appendix.mjs 及 zone 核对 | 精确投影与同源验证 |
| hooks/shared/reader-review-task.mjs、pre_verifier.mjs | 必审输入集合、当前 before、稳定身份与缺失事实 |
| hooks/plan/author.mjs、author.md | 真实业务通路落实，不止能力名称 |
| skills/story/rules/init_analysis.md、ar_design_init.md | 范围决定前核事实，保持提取/拆分/会议 |
| skills/story/phases/spec.md、story-write.md、update.md、reference/evidence-rules.md | 替换冲突写法与失效顺序，引用同一合同 |

表中 core/story 简写指 skills/story/scripts/core/story。保持原材料留存、导入恢复、会议纠偏、人工原话、Review 人工区、知识所有权和六阶段出口。知识错误回真源，机制不复制目标仓事实或测试答案。

## 5. 验收

入口链核“原会议名→留存版本→作者写法→Spec→Story 人读投影→独审核源”，覆盖同名多版、标点、合稿、settled/open/重复决定、坏元数据/缺件。合法输入不被迫改成 Case 名称或句式。

验证 before 在改稿和独审前送达，相关依据变化使对象失效，报告落盘不使对象变化。大输入不静默截断并明确未覆盖范围。复用现有 author-task、material、meeting、story-build、review-closure、update 测试，不能只测字段存在。

返修必须有与生产派生函数独立的预期：用中性输入明确登记一个图文混合补料、一份缺失必需原件、一个合法可选来源、一次只有 Spec 的 update 和一次已有 Plan 的 update，核集合不会因缺件/含图而缩小。再核坏 origins、空/不完整 before、目录越界、重复决定、缺清单标签、原话/范围/update-notes 改动与纯簿记改动。可以用生产函数生成普通正例报告，但不能只用它的输出当集合完整性的测试答案。

离线只签输入/来源/身份机制成立。外部未知结果、未决选边、漏决定、业务能力误判和跨段冲突的效果必须由 S4 真实模型证据签，文案改完不算行为完成。
