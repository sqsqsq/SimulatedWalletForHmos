## 1c. 复审第三轮：围栏关闭条件补全

`_plain_lines` 在围栏内只判「同字符、长度够」，没核标记之后是不是只有空白。
`​```text` 里写一行 `​```python` 是合法的代码内容，却被当成关闭——评审给的那一例复核过：
上一版把围栏里的示例标题当成正文、真正的正文标题反而被跳过。

修法是把关闭条件写全：**同字符、不短于开启、标记之后只有空白**；开启行照常允许带语言标记，
两者不再共用一个只看前缀的判断。新增反例「围栏里还有一行带语言标记」与它的空白关闭对照，
其余围栏与空格文件名的回归原样保留。没有为这一处新建解析器或状态。

## 2. 会议：中间协议退场，结果由模型写

**退出**：两份话题清单（`topics.json` + notes）、C/O 编号、`effect`/`apply_changes`/`add_changes`/
`keep_open`/`resolves`、`overturns`/`supersedes` 替代图，以及把它们编译成 `doc-refresh.md` 的
`effective_meeting_results` + `render` + `_citer` + `write_refresh`。

**现在的链路**（没有新增停等、Agent 或状态机）：

```
导入原件 → 脚本转换 raw.md → 模型交纠偏差异 → 脚本出 evidence.md
        → 模型写 meeting-notes.json（一个话题一条：归属、原话行范围、finding，
          要问人的写 question + options）
        → status 机械枚举全部话题 → 人在第一级那一轮逐条 decide（记 key 与原话）
        → **模型**按原话与裁决写 doc-refresh.md（当前会议结果，下游唯一入口）
        → 原初筛 / 提取 / Spec / Story / Review 链
```

脚本这一段只剩确定的事：转换与版本、差异应用、话题清单的结构与引用校验、摆给人的枚举、
人选记录，以及当前结果的**输入绑定**（`meeting_basis`）与四项核对（文件在不在、声明的输入是不是
当前这版、每个话题有没有去向、引用指不指得到真实行）。`finding` 是模型写的自然语言，
**脚本不读它判业务**（有测试锁住）。多场会的先后与冲突由模型判断，脚本不按文件名或时间替谁覆盖谁。
