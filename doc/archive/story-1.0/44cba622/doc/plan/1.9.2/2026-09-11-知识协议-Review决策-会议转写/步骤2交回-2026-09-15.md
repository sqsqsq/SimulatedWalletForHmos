## 4. 与 03 不一致处（按事实处理）

1. **自检放在载入，不进 `selfCheck`**：§4.3 写「`selfCheck` 加四条」，同时写强制力、执行体「载入失败」、模式缺篇「派生失败」。各道门都要用 `force / executors`，值域不合时下游无法执行，所以四条都在 `activeKnowledge` 里核，收齐一次抛出（知识所有者升级后逐条改，不改一条撞一条）；`selfCheck` 不重复这几条。
2. **「人工只配评审动作，反之亦然」的读法**：按字面，DLV-01（处置非评审动作、验证列「模型…。人工：回稿跟踪与合入」）会被拒，与判据 15「样板零报」冲突。实现为：评审动作条目的验证列必须含「人工」；只由「人工」验的条目必须是评审动作。模型 + 人工的普通条目合法。
3. **协议版本只核声明了的**：index 件写了 `protocol` 且不等于 1 才报；没写不报。`knowledge/README.md`（总索引）与既有夹具的 index 件没有这个键，缺省按「未声明」处理。三份类目 README 已写 `protocol: 1`。
4. **「探针无落点」的呈现**：gate 没有告警通道，记为「未执行判据」（`skipped`），不阻断 plan、在回话里可见。
5. **coding 的「记未落实 / 证据缺口」**：写进 `knowledge_landing_in_code` 检查的告警明细（进 trace），verifier 经 coding overlay 一句提示逐处核；没有新增状态文件。review 门禁对基线「未落实」要依据，但不机械核「coding 记过未落实的落点在复核表里必须写未落实」——那是语义，归 verifier。
6. **注释里的编号是 problem（阻断）**：§5 P5 写「报到行号」；按门禁一条处理，确定性、修起来成本低。
7. **plan 作者页 60 行上限**（`check_failure_modes` 的作者页形态）：加入执行体对照表与借挂句后，删去页内两句与模板重复的话：「判据一句话：义务要挂在下游真的会读的那个实体上」「spec 全部单元都写无候选时不应凭空选出一个模式」。两句在 `plan-sections.md` 原样保留。spec 作者页同样按行数合并了几处换行，内容不删。
