## 1. 这一步新增的是一条链，不是一个判据

会议转写是**第三种输入**，性质不同：讨论态的证据，不是定论（D1）。

```
会议 docx ──解析（脚本）──→ meetings/<主名>/<sha8>/transcript.json ──纠偏（模型）──→ evidence.json
                                                                                    │
                                                            切话题（模型，只做索引）→ topics.json
                                                                                    │
                       整体通读 → 每个话题一份判断：变化 / 闭环结论 / 遗留问题 → meeting-notes.json（按版本分节）
                                                                                    │
                                              自检（脚本）：留痕对得上、登记的话题都有去向、结构合法
                                                                                    │
                          材料关卡那一轮：摘要 + 值得问的（D7），每项带明确的可选结果 ── 人一次答完
                                                                                    │
                                有效结果（一处派生，人签的 + 整体确认的）→ doc-refresh.md（提取作者与人共读）→ AR/design.md 输入（D8）
```

**范围到 design.md 的输入为止**（D10）：S4 收口时按已定范围生成的 `AR/design.md`（`rules/ar_design_init.md`）。不改 RR / SR 正文（D1），不直接改 spec。

## 2. 材料怎么进来、产物落哪、版本怎么存

会议 docx 走**收件箱**。归类档加 **`MEETING`**（`materials/importer.py::CLASSES`）：它像 `IMAGES` 一样没有正文落点（`DOC_SOURCE` 不加项，`doc_targets()` 不含它），产物落 `AR/story-src/meetings/<docx 主名>/<sha8>/`——**一个源版本一个目录**（N7）：同名 docx 换了内容，是新目录，旧目录里的原文与纠偏证据原样留着，旧结论引的 `S15` 永远查得回。`rules/inbox_import.md` 的归类表加 `MEETING` 一行（什么时候选它、落哪）。

| 产物 | 谁写 | 落哪 | 谁读 |
|---|---|---|---|
| 原始 docx | 人 | `inbox/` | 解析脚本；材料清单登记它（`registry.collect_sources`，`kind: doc`，`class: MEETING`） |
| `transcript.json` | 解析脚本（公共，`materials/meeting.py`） | `meetings/<主名>/<sha8>/` | 纠偏、留痕自检 |
| `evidence.json` | 模型（纠偏） | 同上 | 索引、结论的原话依据、读者审查、人 |
| `topics.json` | 模型（话题索引） | 同上 | 自检、会议结论 |
| `meeting-notes.json` | 模型，一份文件，**按 `<主名>@<sha8>` 分节** | `AR/story-src/` | `status` 摆关卡、有效结果派生、读者审查、人 |
| `doc-refresh.md` | 脚本由有效结果派生 | `AR/story-src/` | 提取作者（design.md 输入）与人（文档刷新清单）——**同一份** |

`meetings/`、`meeting-notes.json`、`doc-refresh.md` 进 `state.py` 的 story-src 保留集（AR 根清扫不动它们），**不进 `STORY_SRC_FROZEN`**：留、不冻结。

**导入判定**（`registry.collect_sources` 的 `ingested`）：`MEETING` 档 = 收件箱那份 docx 的指纹对应的 `meetings/<主名>/<sha8>/transcript.json` 存在。换了内容 → 新指纹 → 未导入 → 重导到新目录。

**新版本到来不撤销旧决定**（N7）：新目录只表示「新材料的分析待生成」；旧版本那一节的结论与人已签的裁决继续有效，直到新版本里针对它的条目（`overturns`）经人裁决通过（§5）。指纹只负责定位，被定位的原文随目录保留。

## 3. 解析与纠偏

### 解析（D4）

公共脚本 `scripts/core/materials/meeting.py`，在 `importer.docx_to_markdown` 之上识别 D3 的形态：

```json
{
  "source": {"file": "xxx.docx", "sha256": "…"},
  "meeting": {"title": "…", "date": "…", "attendees": ["张三", "李四"]},
  "sections": [{"title": "议题一 …", "speeches": [{"id": "S1", "speaker": "张三", "time": "10:02", "text": "…"}]}]
}
```

发言逐条编号，全场唯一；原话依据都指编号。识别不出形态的段落原样落进最近一条发言，不丢字。

### 纠偏（D5）

只改字面（人名、术语、拼音、错别字），依据只来自四处已知事实；源外拿不准的不改；不删、不合并、不摘要、不消解矛盾、不调顺序；不单独停等。

`evidence.json` 与 `transcript.json` 同结构，发言文本换成纠偏后的，另加 `attendees[].role`（模型提出，标 `proposed`，关卡那一轮人确认）与 `corrections[]`（发言编号 / 原文片段 / 改成 / 依据哪一条）。

**脚本自检**：编号集合与顺序守恒；**每条发言的文本差异必须全部由 `corrections` 解释**——按 corrections 替换原文后与证据文本逐字比，剩下的差异是未声明的编辑，报出来。纠偏有没有改了意思归语义审查。

提示词落 `phases/meeting-read.md` 的纠偏一节。

## 4. 执行者的任务：会议结论怎么产生

阶段页 `phases/meeting-read.md`：判议题归属（D11）；整体判断先于逐条对照；三个尺度（真源 §2）——收口靠转写里那句话、没有就记开放、改口按后说的、文档与会议冲突以会议为准但属修正类要人过目。

**话题索引 `topics.json` 只做索引**（F10）：每个话题记「id + 议题 + 哪几条发言（编号）」。发言原文一字不改。判断只在一处：`meeting-notes.json`。

**`meeting-notes.json`**：按 `<主名>@<sha8>` 分节，一条一个话题，**一份判断、三个角度**（用户 2026-09-08：变化、闭环结论、遗留问题，可并存）：

```json
{
  "meetings": [{
    "source": "xxx.docx", "source_sha": "…",
    "attendee_roles": [{"name": "张三", "role": "产品"}],
    "topics": [{
      "id": "T3",
      "ownership": "ours | not_ours | unclear",
      "changes": [{"id": "C1", "kind": "add | remove | modify", "doc": "SR/design.md", "section": "§3.2",
                   "before": "…", "after": "…", "impact": "…", "evidence": ["S12", "S15"]}],
      "conclusion": {"text": "会上定了什么", "scope": "适用到哪", "evidence": ["S15"]},
      "open_points": [{"id": "O1", "what": "还缺什么决定或事实", "impact": "…", "needs": "谁来定 / 要什么事实",
                       "suggestion": "（模型建议，标明）"}],
      "transcript_doubt": false,
      "ask": true,
      "ask_reason": "unclear_ownership | unresolved | transcript_doubt | high_impact | overturns",
      "overturns": "xxx.docx@a1b2c3d4/T1",
      "recommend": "opt_a",
      "options": [
        {"key": "opt_a", "label": "按会上定的改 SR §3.2，阈值取 5",
         "effect": {"ownership": "ours", "apply_changes": ["C1"],
                    "add_changes": [{"kind": "modify", "doc": "SR/design.md", "section": "§3.2",
                                     "before": "阈值未定", "after": "阈值 5", "impact": "验收 AC-3 的数值", "resolves": "O1"}],
                    "supersedes": ["xxx.docx@a1b2c3d4/T1"]}},
        {"key": "opt_b", "label": "维持文档口径，阈值仍待产品定",
         "effect": {"ownership": "ours", "apply_changes": [], "add_changes": [], "supersedes": [], "keep_open": ["O1"]}}
      ]
    }]
  }]
}
```

- 一个话题可以同时有 `changes` 与 `open_points`；可以有 `conclusion` 而 `changes` 为空（**讨论收敛、原文不变**，F9）——合法去向，不进变更输入与刷新清单。
- `conclusion` 与每条 `changes` 必须有 `evidence`（在本版本的 `evidence.json` 里）。
- **选项自带完整结果**（N6、R3）：`options[].effect` 由模型在摆选项时写清四件事——`ownership` 归属定成什么；`apply_changes` 会上已定的哪几条变化生效；`add_changes` **人补定的决定落到需求哪里**（与 `changes` 同一结构，多一个 `resolves` 指向它解决的遗留问题，没有 `evidence`——它的依据是人的原话，记在契约的 `basis` 里）；`supersedes` 本选项替代哪些既有决定（`<主名>@<sha8>/<话题>`，可以为空——接受一个「不改原文」的决定也可以替代旧决定，替代关系只看这一项，不从 `apply_changes` 空不空推）；`keep_open` 明确保留未决的遗留问题。脚本不理解 label 与 key，只按人选的 `key` 取 `effect`、核引用、投影。
- `ask` 为真的必有 `recommend`、`options`（≥ 2）、每个选项的 `effect`；带 `overturns` 的话题每个选项都要写 `supersedes`（可以为空）；`ownership: unclear` 的 `ask` 必为真且各选项的 `effect.ownership` 明确；`add_changes[].resolves` 必须指向本话题的 `open_points`。
- **会议明确达成的与人后续定的分开**：`meeting-notes.json` 的 `changes` 记前者；`add_changes` 进入有效结果时标 `decided_by: human` 并带契约里的 `basis`，不写成会上已定。

**自检**（脚本 `materials/meeting.py`，`status` 摆关卡前跑）：结构与 `source_sha`；`topics.json` 登记的话题 ⊆ 有判断的话题（只声称「登记的都有去向」；漏没漏转写里的话题由独立审查对照 `evidence.json` 判）。

## 5. 人怎么介入：并进材料关卡那一轮（D7）

**不新增停等点。** 摆的是：每个话题一行（变化 / 结论 / 遗留各一句）+ `ask` 为真的逐条（推荐与理由、可选结果）+ 参会人角色。人一轮答完。

```
story_flow.py decide --feature <AR> --gate meeting --meeting <主名>@<sha8> --item T3 --chosen opt_a --basis "<原话>"
```

`state.py::GATES` 加 `meeting`；`decisions.py::cmd_decide` 对这一关取选项集自 `meeting-notes.json` 该话题的 `options[].key`（其余三关的来源不变），记录进契约当轮的 `gates`，形状与现有关卡相同，多 `meeting` 与 `item` 两键，`by` 沿步骤 0 之后的写法固定记 `human`（`--by` 已退出）；`chosen` 必须在该条 `options` 里（现有校验）。裁决绑定 `<主名>@<sha8>` 这一版。`rules/init_analysis.md` 的命令表加这一行。

**「这一轮答完了」**：这一版 `ask` 为真的条目与契约当轮 `gate = meeting` 且 `meeting` 相同的记录做差，为空即逐条裁决完成。

**未逐条问的条目的生效前提**（N6 第 3 点）：不是「差集为空」，而是**这场会所在轮次的第一级材料关卡已 accepted**——会议的摘要与问题是在那一轮停等里摆给人的，人回答第一级（`supplied` / `confirm_scope`）就是对摆出的整体的确认。`ask` 全为假的会议同样走这一条，不会在没人看过之前生效。

**有效结果只有一个派生函数** `flow/meetings.py::effective_meeting_results(notes, contract)`，`status`、`doc-refresh.md` 渲染两处都调它（design.md 输入与刷新清单读的是同一份渲染件，§6）：

| 条目 | 有效结果 |
|---|---|
| `ask` 为真且已签 | 取 `chosen` 选项的 `effect`：归属按 `ownership`；`apply_changes` 里的变化生效；`add_changes` 作为人补定的变化生效（`decided_by: human`，`basis` 取契约记录），它 `resolves` 的遗留问题落定；`supersedes` 指到的既有决定失效；`keep_open` 与未提及的遗留问题保持未决 |
| `ask` 为真未签 | 不生效 |
| `ask` 为假 | 所在轮次第一级关卡 accepted 之后生效；之前不生效 |
| 归属最终 ≠ `ours` | 不生效（只记不消费） |
| 生效的变化为空（`changes` 为空且选项无 `add_changes`） | 无变更进 design，结论与依据保留 |
| 旧版本或前一场的条目 | 只有被某个**已签选项**的 `supersedes` 指到才失效；否则继续有效（D9）。新版本到达、`overturns` 未签、签了一个 `supersedes` 为空的选项——三种情况旧决定都继续有效 |

design 输入与刷新清单消费的是同一组「生效的变化」= `apply_changes` ∪ `add_changes`，每条带来源：会上定的带 `evidence`，人补定的带 `decided_by: human` 与 `basis`。

`meeting-notes.json` 是模型的判断，人的裁决在契约里，两边合起来才是「人最终接受的」。

**`status.next` 的顺序**（`flow/routing.py::next_step`，在现有「收件箱未导入 → 导入」之后插入）：有 `transcript.json` 而本版本三份派生物缺 → `read_meeting`（会议阅读，动作指向 `phases/meeting-read.md`）；自检不过 → 报出来、不摆关卡；本版本有未裁决的 `ask` 条目 → `await_gate:meeting`（与第一级同一轮停等里摆）；第一级未定 → 现有 `await_gate:material_scope`；都定了 → 下一步照旧。`decide --gate meeting` 的前置按同一处 `next_step` 判，不另写。

**会议在 `story_written` 之后到**：走 `reopen` 开新一轮（`rounds.py::cmd_reopen` 的下一步提示已点名收件箱里的原件），一场会一轮（D9）。

**与步骤 1 的关系**：这一轮要问的东西用的是步骤 1 的撞法（`story-write.md` 四节的两问与四种「不合适」，R3、R5）。后续 Review 沿用会议已确认的决定，不因换产物再问同一件事；只有新证据或新冲突才产生新的待确认事项，并说明为什么要重新审核。

## 6. 确认之后：消费者

有效结果只经一份渲染件送达：**`AR/story-src/doc-refresh.md`** 由派生函数写出，每条生效的变化一节——哪份文档哪一段过期、改前改后、影响、来源（会上定的写原话编号带版本，人补定的写「人工补定」与原话）；`changes` 为空的结论单列一节「原文已确认」。它同时是给人的文档刷新清单（D8）与给提取作者的会议输入；送回需求系统不在本轮范围。

四处消费者，按 1.9.1 之后的实际入口：

| 消费者 | 改什么 |
|---|---|
| 提取（`rules/ar_design_init.md` 输入表） | 加「`AR/story-src/doc-refresh.md`：会议有效结果」一行，优先级最高（更晚且经人确认）；「原文已确认」节作为该段沿用原文的依据 |
| 初析（`rules/init_analysis.md`） | 材料盘点列入会议 docx（状态：待导入 / 已转写、结论 N 条）；**⑥ 来源初筛按话题登记会议**：来源位置写 `meetings/<主名>@<sha8>/T<n>`，作用写生效的变化或已确认的原文，「还要核实」写仍未决的 `open_points`——它们由此进步骤 1 的回看清单（`recheck.mjs` 读 ⑥ 第三列，不改脚本） |
| 写作设计骨架（`story-write.md` 二节） | 说明行的「依据」可以指向 `doc-refresh.md` 的节名或 `evidence.json` 的发言编号；四节撞法「更晚的输入」已含会议有效结果，不改 |
| 读者审查（`hooks/shared/reader-review-task.mjs`） | 存在时给 `meeting-notes.json`、各版本 `evidence.json` 与 `doc-refresh.md` 的位置（只给位置，不复制）；`spec-rules.overlay.yaml::story_reader_review` 加一问（§7） |

`story-chapters.json` 不加目录，不加来源项（会议不是 `sources` 里的正文来源，它经 `doc-refresh.md` 进提取稿）。

**多场会议 / 多个版本**（D9、N7、R3）：后一场或新版本推翻前面已确认的条目时，模型写 `overturns`，自检强制它 `ask`，每个选项写清 `supersedes`；人选了哪个，旧决定就按那个选项的 `supersedes` 失效或保留。旧结论、旧原话随版本目录与分节保留可查。

## 7. 判据怎么跟

| 层 | 判什么 | 谁判、什么时候 |
|---|---|---|
