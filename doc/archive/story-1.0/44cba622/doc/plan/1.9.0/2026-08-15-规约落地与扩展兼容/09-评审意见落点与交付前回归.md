## 一、计划外意见:人的意见会丢(**已修**)

### 现象与根因

Human 追问「`review.md` 里如何表达人工额外的检视意见」,查下来是**两处缺口**:

**缺口 A:没有位置。** `review.md` 的结构是

```
如何填写 → 请逐项留下你的结论(每题一张表单) → 已定决策(逐条过目)
→ 下一步(两个勾选) → 附录 → 状态行
```

每个输入槽都绑在已登记的 `DEC-00X` 上。评审人发现一件起草方**压根没登记过**的事
——缺的分支、该复用的既有能力、遗漏的埋点——没有任何一处是给他写的。

**缺口 B:写在别处会被静默冲掉。** `renderReview` 每次按登记表重建,人工区靠
`extractHumanZone(existing, DEC-id)` **按议题 id 抠取**保留。写在议题块之外的自由文本
不在任何 id 的抠取范围内,下一次 `build` 就没了。

**最刺眼的是:回流侧早就接得住。** `review_reflow.md` §1 已规定怎么处置
「模板外的自由意见」(判需求类/叙述类、落台账带 `freeform#<序>` + 原话摘录)——
**规则假设了一个模板里不存在的东西**。产出侧与回流侧是同一件事的两半,只做了一半。

### 修法

`story-build.mjs` 加一个与议题人工区同等待遇的**计划外意见区**:

- 常量 `FREEFORM_OPEN` / `FREEFORM_CLOSE` 一对标记;
- `extractFreeformZone(reviewText)` 取出标记之间的内容;
- `renderFreeformSection(inner)` 渲染整节:标题与写法说明是机器区(每次重渲染),
  标记之间是人工区(逐字节保留);
- 排在议题之后、「下一步」之前——逐项表态完了才谈得上「还有什么没被问到」;
- **不给表单**:套不进表单正是它存在的理由;
- 填写说明里加一句告诉评审人有这个位置,否则等于没有。

`review_reflow.md` §1 同步:把「模板外的自由意见」改称「计划外意见」并指明落点;
补一句「人写在别处时照样处置,但落台账要注明写在哪」。

### 验证

- 实产物验:往 AR90006 的 review.md 写两条意见 → 重建 → **原文完整存活**;
  `story-build check` 与 `merge-story --check` 都过;
- 回归三条(`test_story_build.py`):有位置 / 扛得过重建 / 不打破门禁;
- 反例:去掉保留逻辑 → 红;整节删掉 → 红。
