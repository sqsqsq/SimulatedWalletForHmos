# W10 成文任务形态重设计与 review 回流首测方案

> 状态:**待 Human 确认,未实施**。

## 一、背景:两件事,一轮观测

1. **内网(GLM5.2)再报 story.md 大幅精简**——W7 已给判据式定义,内网照样精简;
2. **`/story review`(评审回流)从未端到端测过**——Human 要求评审意见由测试者
   读真实产出后**当场写**(不可预置 mock/fixture),且须含议题外的计划外意见。

## 二、精简的根因:源块的物理形态

现状成文流程:scaffold 把源材料**复制进章节文件**(source-material 区块)→
模型在区块之下写正文 → build 剔除区块、装配正文。

**「一段材料 + 在下面写字」是 LLM 摘要行为的最强任务先验。** 这个物理形态
本身在告诉模型"处理(压缩)这个区块"——判据写得再清楚也是在对抗形态诱导。
精简不是模型没读懂规则,是形态压过了规则。此前的尝试(判据式定义、章头注提示)
都是在这个错误形态上修补,所以无效。

而「注入源块」当初的两个设计理由,逐一查实都站不住:

| 理由 | 查实结论 |
|---|---|
| 保证模型确实看到源材料 | 可用**取材路标**替代——源文档就在工作区,S2b 阶段模型本来就通读过全部材料 |
| 作为 build 的对照基准 | **不成立**:build 的形态守恒由 `loadSourceDocs + extractSection` 从源文档**现场提取**计算,从不读源块;源块只是给模型看的复制品 |

## 三、重设计:注入任务书,不注入材料

**处理器框架 → 作者框架**:作者要内容才能成文,自然去源里取事实;
处理器面对眼前材料,只会把长的变短。让"去源里拿"取代"把眼前的变短"。

### 3.1 scaffold:章文件 = 写作任务书(实现反而简化)

每章不再含 source-material 区块,只含:

```
<!-- chapter: 08-flow | title: 业务流程与状态变化 | form: mermaid≥1 -->
<!-- 取材：spec/spec.md §5 业务流程；SR/design.md §3 端到端时序 -->
<!-- 必答（写到足以支撑这些判断为止，不设篇幅上限）：…（现有 must_answer 保留） -->
<!-- 写完的判据：打开上面每份取材源，其中的每个事实点（数据、条件、分支、约束、
     名词、表格行）都要写进本章；可换措辞、可改顺序，不可少一条。
     一次只写一章：写完本章，再开下一章。 -->
```

- 「取材」行由 `contracts/story-chapters.json` 的 `inputs` 生成(契约不改,
  它本来就是取材路标的数据源);
- 判据从 rules 层进入执行位置,且与写作动作同框(不再隔几十步);
- 「一次只写一章」吸收进任务书(指导,不造机制);
- 附带收益:14 章不再各带全量源块副本,写作时上下文体积大减。

### 3.2 build:校对闭环——生成即合格的保障

- **形态守恒照旧**(sourceText 本来就从源文档提取,零改动);
- **新增三条结构守恒(FAIL 级)**,逐章从取材源提取比对:
  1. **表格行数**:正文表行总数 ≥ 取材源表行总数(允许合并表,总量不减);
  2. **数值 token**:带单位(`300ms`/`5 元`/`3 次`/`30%`)、≥2 位数、小数——
     正文必须都在。提取从保守:**宁可漏检,不误伤**(误伤会逼模型灌水);
  3. **code-span**:取材源反引号 token(接口名/字段名/存储键)正文必须都在。
- 失败信息给**精确靶子**,模型按门禁自修惯例补齐,产物出门时已达标:

  ```
  08-flow：表行 42→30（-12）；缺数值 300ms、3 次；缺 `getAutoTopupStatus`
  ```

- 正文判定简化:没有区块了,章文件除头注外即正文;`authorBody`、
  「区块外无正文」判定、「源材料只读保留」不变量随之简化/退役。

**反馈的消费者是执行中的模型**,不是事后看报表的人——这是 Human 明确的要求:
要生成即符合期望的输出件,不是输出件不满足后由人发现原因。

### 3.3 规则同步

- `rules.md` 红线 1 重写:成文 = 按任务书从取材源写作;判据与头注**同句**(防漂移);
  红线 2(表达形态与数量不降级)保持;**「转写」一词随旧框架消亡**——
  它本来就是"源块→正文"框架的词,新框架里没有它的位置;
- `hooks/spec/story_on_context_load.md`、SKILL 相关句、`transcribe_note` 文本同步
  (契约键名不改);
- 计划外意见区、决策/编号登记等既有机制**全部不动**。

### 3.4 看护与迁移

- 新断言:章文件无 source-material 区块;头注含取材行与判据句;
  rules 与头注判据同句;
- 三守恒正反例:砍表行 → FAIL;丢数值 → FAIL;丢 code-span → FAIL;
  等量改写(换措辞、改顺序)→ PASS;
- **迁移量主要在测试**:`test_story_build.py` 现有 fixture 均构造 source-material
  区块,全部迁到任务书形态;`test_merge_story_check.py` 等相关同步;
- 全链 grep 无「转写」「source-material」残留(mock-data 除外)。

### 3.5 风险(如实)

模型不读源**就编**——比精简更糟的失败模式。三重缓解:取材路标点名到节;
必答问题需要源内容才能作答;三守恒缺事实即退回。首轮实测把「编造」列为
与「精简」并列的观察方向。

## 四、harness:story 侧终点 `end_phase: story-review`

归档与回流发生在 spec 闭环之后,现有 `end_phase` 到 spec 即停,续不到那里。
`run_case.py` 增加 story 侧终点(~15 行):

- `story-review`:三产物齐备 **且** `AR/review-disposition.json` 存在 → 达标;
- 轮次上限:spec 档 +3(归档、回流、修订各一轮);
- `test_harness.py` 补断言:该终点判据含 disposition;非法 end_phase 仍报错。

## 五、用例 `review-reflow`

```yaml
id: review-reflow
ar: AR90006
interactive: true          # 关卡与评审意见都由测试者当场给
end_phase: story-review
prompt: |
  （基础 prompt,不提拆分;spec 闭环后执行 /story archive AR90006 归档送审）
```

- `workspace/` 复用交通卡 docx(carry_all 全量单——正好是宽范围成文的考验);
- **不放** `mock-data/AR90006-review-feedback.md`:review 替身无回稿文件时
  保持本地 review.md 原样——正是 SKILL 认可的「本地修改」路径,
  测试者的意见不会被覆盖。

## 六、执行规程(测试者在回路)

1. 关卡 reply 推进(整体承载);
2. spec 闭环 → **首测新形态成文**:三守恒零触发或触发后自修收敛;
   抽读事实密集章(契约/异常/验收)对照源文档,查**精简与编造**两个方向;
3. 读真实产出(spec.md 技术契约/异常/验收 + review.md 议题),
   **当场写评审意见**进本地 `AR/review.md`,五类齐:
   - 同意 ≥1(验证不动路径);
   - 修改 ≥2(指向真实存在的 spec 编号,给具体改法——验证定向修订与 correction 闭环);
   - 暂缓 1(含责任人与是否阻塞——验证记台账不动产物);
   - **计划外意见 ≥2**(写在末尾专区:一条需求类=spec 真实缺的东西,
     一条叙述类=组织性意见——验证判类分流与原话摘录);
4. reply:「评审意见已回,跑 /story review AR90006 并按意见处置」;
5. 按观察表记录,结论写入本目录 11-首轮观测结论。

意见内容**跑起来之后才定**——必须针对被测模型的实际产出,不可事先编。

## 七、观察表

| # | 观察 | 达标 |
|---|---|---|
| 0 | 新形态成文 | 事实密集章对照源:无精简、**无编造**;守恒零触发或自修收敛 |
| 1 | review 命令 | 先备份 `.review-backup/`;不覆盖本地意见;回执 success |
| 2 | 同意项 | 不动产物 |
| 3 | 修改项 | spec 对应编号确有修订、改在意见所指处;correction 走 framework 既有机制 |
| 4 | 暂缓项 | 记台账、标挂起、不改产物 |
| 5 | 计划外意见 | 判类处置(需求→改 spec;叙述→记台账);**原话摘录**入台账 |
| 6 | `review-disposition.json` | 逐条 from/verdict/disposition;自由意见带 kind+text |
| 7 | 边界 | `AR/story.md` 与归档件不被重建(story 定稿于评审时点) |
