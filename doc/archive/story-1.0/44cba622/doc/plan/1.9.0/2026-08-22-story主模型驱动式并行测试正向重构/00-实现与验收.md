# Story 主模型驱动式并行测试正向重构

## 目标

测试驱动只有一条正向主链：`plan → start → 主模型连续 poll → Goal heartbeat → finalize`。
主模型理解被测输出并决定自适应回复；脚本不模拟主模型，也不在后台接管测试生命周期。

## 职责边界

- 主模型：Case 选择确认、15 秒连续驱动、语义判断、自适应回复、恢复、状态变化汇报和最终汇总。
- 多 Case 脚本：顺序启动、并行单轮读取、预置回复、状态持久化、稳定计算、隔离、清理和回灌。
- 单 Case runner：被测 CLI 进程、事件、交互通道、阶段 gate 与执行证据。

正式接口为 `plan`、`start`、`poll`、`status`、`reply`、`stop`、`finalize`。不存在 `watch` 或后台
monitor。`status` 只读，`poll` 是唯一推进观测、预置交互和稳定确认的接口。`stop` 只由用户明确触发。

## 控制协议

`start` 和 `poll` 统一返回动态 Case 快照、交互、待自适应回复、稳定状态与 `next_action`。
`next_action` 封闭为 `poll_after_15s`、`reply_then_poll`、`create_goal_heartbeat`、`finalize`。
预置回复后的零等待确认不累加稳定次数；所有实际 Case 的两轮有效 15 秒确认才允许 Goal 交接。

## Workspace

模板只从显式运行依赖白名单复制；递归排除测试、工具、输出、Git、历史 features 和其他 Case 输入。
每个 Case 的输入单独 seed。`workspace-boundary.json` 记录 copied、excluded、case_seeded 和递归检查。
启动前出现软链接、越界或受限目录即拒绝起跑，不创建运行期“污染”状态。

## 验收

- 单选、部分多选、全选均只使用 suite 实际 Case 集合。
- start 返回 `poll_after_15s`；status 不改变游标、交互或稳定状态。
- poll 自动处理预置回复，未匹配问题返回 `reply_then_poll`。
- 连续两轮有效 15 秒 poll 后才返回 `create_goal_heartbeat`。
- 代码与当前入口文档没有 watch、monitor、pollution 或自动 stop 路径。
- workspace 递归没有 `test`、`tools`、`output`、`.git` 和其他 Case 输入。
- finalize 保留本轮 workspace/output；下一轮安全清理仍支持 Windows 短暂删除失败重试。
- Story 单测、Tools CLI 单测、Python 编译、CLI 校验及只读 plan 通过；不启动真实被测 CLI。
