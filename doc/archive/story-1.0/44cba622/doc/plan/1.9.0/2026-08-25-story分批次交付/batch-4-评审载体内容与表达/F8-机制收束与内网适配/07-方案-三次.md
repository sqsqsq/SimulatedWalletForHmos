## §3 方案

十项。**S1 是主项，其余九项各自独立。**

### S1 · 形态判据从「每章一个布尔」改成「每章每类，画出数 ≥ 分配数」

对 P1 / P1b / B1 / B2 / B3 的统一修法，**替代 `04` 的三处收回**。
全部落在 `doc/extensions/skills/story/scripts/story-build.mjs`。

**S1a · `chapterForms` 从判有无改成数个数**

```js
function chapterForms(sections) {
  return new Map(sections.map(s => [s.title, {
    diagram: (s.text.match(DIAGRAM_FENCE) ?? []).length,
    image: (s.text.match(/!\[[^\]]*\]\(/g) ?? []).length,
    table: /^\s*\|/m.test(s.text),   // 表仍是布尔：表行不是一行一张表
    text: s.text,
  }]));
}
```

**S1b · 新增图形围栏白名单，不再把任何带语言标签的围栏当图**

```js
/**
 * 什么算一张图：只有画图语言的围栏块。
 * json / yaml / text 围栏是数据与摘抄，把它们算成图会让「这一章画了几张」凭空多出来——
 * 仓里就有实例（S06-appendix-dump 那份产物里有一个 text 围栏）。
 */
const DIAGRAM_FENCE = /^[ \t]*(?:```|~~~)[ \t]*(?:mermaid|plantuml|puml|dot|graphviz)\b/gmi;
```

**S1c · `formShortfall` 比数量，不比有无**

```js
for (const [key, list] of bucket) {
  const [at, kind] = key.split(' ');
  const drawn = forms.get(at)?.[kind] ?? 0;
  if (list.length > drawn) out.push({ at, kind, units: list, drawn });
}
```

单元只在有 `at` 时进 bucket（沿用现有逻辑），所以 `covered_by` / `machine_facing` /
`material_only` 三态天然不计入分配数。

**S1d · 报错措辞给出两个数**

- `drawn === 0`：沿用现文案「落在「X」，但那一章没有图」——它已经准确；
- `drawn > 0`：新文案「材料里分到「X」的图有 4 张，那一章只画了 1 张——把流程图压成
  箭头文字算降级，读者要的是一眼看出的结构」。

**S1e · 把越界的两处收回**

`IMAGE_KINDS` 收回 `new Set(['image'])`；diagram 落点判恢复 `!rec?.at && !rec?.covered_by`。
理由是范围纪律——内网 7 只讲图片，`material_only` 是为「30 张界面图不必都进 story」开的通道，
流程图没有这个诉求。

**S1f · 不恢复任何全篇总数判据**

`storyDiagrams` / `imgs.length` 两条都不回来——每章每类已经覆盖它们能抓的一切，
而且不带它们的三个毛病（不看 `covered_by`、数错对象、分母不受作者支配）。

#### 为什么每章每类不会退回硬塞

**分母换人了。** 全篇总数判据的分母是**材料里有几张**，作者无法降低，只能塞。
每章每类的分母是**作者自己给了几个 `at`**：不该进 story 的图标 `material_only`（图片）
或 `covered_by`（流程图），分配数当场归零。

30 张界面图的场景：作者给 2 张 `at`、28 张 `material_only` → 该章分配数 2、画出 2 → 零报错。
**这正是内网问题 7 要的行为**，而它不需要为图片和流程图写两套规则。

#### 它同时修掉的

| 原毛病 | 每章每类怎么覆盖 |
|---|---|
| 4 张分到一章只画 1 张不报（P1） | 分配 4 > 画出 1 → 报 |
| 全篇总数不看 `covered_by`（P1b-1） | 只数 `at`，`covered_by` 不进分母 |
| 把 json / text 围栏当图（P1b-2） | S1b 白名单 |
| 图片与流程图要两套规则 | 同一套粒度，不需要分治论证 |

### S3 · CLI 实跑判定线改准（对 P5）

判定脚本是执行会话自己的临时件，落 `<scratch>`，**不入库**。改两处：

| 现在（会误报） | 改成 |
|---|---|
| 图片或流程图 < 上一轮 | **直接跑 `story-build.mjs check`，读它报不报形态欠账** |
| 判定时机：`story.md` 文件出现 | **十章齐才判**（逐章追加，半成品判必误报） |

**关键设计：判定线不自己实现一套逐章比对。** S1 之后 `check` 本身就报「分了 N 张画了 M 张」，
判定脚本重实现一遍等于第二个真源，两边认得不一样时人就在中间打转。
判定脚本只做三件事：等章齐 → 跑 check → 按判据类挑出严重项。

另一个 case 的 `review.md` 正本被评审人的整文批注版覆盖。

**核过的事实**：`rules/review_reflow.md:36` 已定义 `AR/review-disposition.json` 为处置台账，
`:62` 已定义「`review.md` 归人所有，build 只备份不重建」。**冻结判据本来就拦对了**——
缺的是没有一处告诉作者该写哪儿。所以这一项零机制改动。

1. 开头补：`decisions.json` 随 story 登记冻结，登记之后只读；评审引起的状态变化只记进
   `AR/review-disposition.json`，不回写冻结件——门禁会拦，那是拦对了。
2. §4 补「回传意见写到哪」小表：针对议题的表态落该议题的「审核结果：」行；没有对应议题的
   落「其他意见」章；**整文批注版不得整份覆盖 `review.md`**，逐条摘回上面两处，原批注件由
   既有备份机制留在 `.review-backup`。同时把「归人所有」的范围从整个文件精确到**人工区**
   （`审核结果：` 之后与 `freeform-zone` 之内），结构归渲染器。

**不引入第二输入文件**——`SKILL.md:98` 写明「模型的输入唯一就是 `AR/review.md`」，保持一致。

### S5 · review 禁用词按结构分区豁免（放宽项，账见 §4）

**问题**：F7 实跑两处禁用词命中全在 `review.md`，且全是决策语言
（「没有运营灰度诉求」「不同意时改什么：文案回退为」）。

**为什么会误伤**：`story-build.mjs:1821` 把 `reviewText` 整份丢进 `scanBannedTerms`，
豁免参数 `exemptChapters` 传的是 **story 的章标题**，review.md 里根本没有那些标题，
等于零豁免。

**改法三条规则**（`story-build.mjs` 该调用点，必要时 `lint-rules.mjs` 加一个作用域参数）：

**规则一 · 人工区不判。** 归档件红线管的是**这份文档对产品的承诺**；评审人写在
`审核结果：` 之后、以及 `<!-- freeform-zone -->` 之内的话，是**人的表态**不是产品承诺。
两个标记 `review-render.mjs` 已经有（`HUMAN_ZONE_MARK` 与 freeform 注释对），直接复用。

**规则二 · 机器区里，必答内容本身就是上线动作或开关管控的议题类别豁免。**
判据与 story 的章级豁免（合同 `banned_terms_exempt`，「交付与上线」章，理由是
「上线路径、开关与兼容、回退设计是本章的必答内容」）**逐字同一条**。

按这条判据过一遍合同 `decision_categories` 的全部十一类，**从判据正推、不从样本反推**：

| 类别 | 必答内容是不是上线动作 / 开关管控 | 豁免 |
|---|---|---|
| 入口与管控 | 是——开关放量与入口收敛就是它的题目 | ✅ |
| 交付顺序与协同 | 是——上线顺序与联调节奏就是它的题目 | ✅ |
| 范围与拆分 · 流程顺序与准入 · 规则与数值 · 数据与缓存 · 界面与还原度 · 异常与受限体验 · 依赖与可用性 · 安全隐私与合规落地 · 验收口径 | 否——讲发布术语是跑题，不是必答 | ❌ |

豁免由合同数据驱动（给这两类加 `banned_terms_exempt: true`），**脚本不写死类别名**。

**规则三 · 其余机器区照拦。** 反例 N6（review 正文写「本方案采用灰度发布」且不属上述两类）
必须仍然报。这是本项的硬门。

### S6 · 术语判据剥掉括注（`story-build.mjs` 的 `missingGlossaryTerms`）

**根因**：判据拿**整个术语单元格**去 story 做子串匹配，而单元格普遍带括注。
本轮 `car-key` 一次报 12 个词，逐个验过全是这个成因：

| 术语单元格 | 整串在 story | 去掉括注后 |
|---|---|---|
| 数字车钥匙（车钥匙） | ❌ | ✅ |
| 车钥匙分享（分享） | ❌ | ✅ |
| 钥匙卡片（卡片详情） | ❌ | ✅ |
| 配额（剩余可分享数） | ❌ | ✅ |
| 权限档（全功能/仅解闭锁） | ❌ | ✅ |

**改法**：匹配前把括注剥掉，用主名去核（中英文括号都认）。括注是给读者的同义提示，
不是要求 story 逐字复述的内容。

**剥空的情形**（单元格形如「（仅括注）」）：不静默跳过——按原串判或报格式问题，二选一并写清。

**不加任何豁免标记。** 「本需求不做、只为对照而列」的词若剥括注后仍报缺，本轮如实记入遗留，
等有真实样本再谈。

### S7 · 沉积清理（`source-units.mjs`、`story-build.mjs`）

**问题**：轮次 / 批次指涉对内网读者无意义（他们没有本仓维护史）。

已知残留两处「批次 1」。**基数由执行会话自己 grep**，模式至少覆盖
「批次\d」「F\d 实测」「上一轮 / 那一轮」，逐条判「保留（纯事实相对说法）/ 改写（含本仓轮次编号）」，
清单进交付报告。改写只去轮次编号，**「为什么」原样留着**。

不扩大到「作者面去重」——那一项已识别的那处（「缺什么 / 写到哪 / 怎么写」从六份 author.md
收敛到两处）已在 `0e35623c` 做掉。

### S8 · 报错按判据类分组（放宽项，账见 §4）

**问题**：内网 8 的伴生——错误洪水本身构成删台账的动力。当前 `check` 逐条平铺，
`auto-topup` 一次 86 条，翻不到头也看不出错在哪一类。

**改法（无阈值、无新产物）**：

1. `problems` 换成带判据类标记的登记本；各判项**照旧 push 一句话**，只在每个判据类开头
   加一次分类戳（如 `problems.at('② 落点守恒')`）。**判定逻辑一个字节不改。**
2. 输出时**按类分组**，每类先给一行计数再列该类明细。**全量列出，不封顶、不截断、
   不写第二个文件。**

**为什么不封顶、不写 `check-detail.md`**：封顶就要定阈值（凭什么是 40 条？），
写第二个文件就要求模型多走一步去读它——**模型只修它看得见的那些**，多一步就多一次可能不做。
洪水难读的成因是「平铺、看不出错在哪一类」，分组加计数正面解决它；
截断解决的是另一个问题（终端行数），那个问题没人提过。

## §4 放宽账（凡放宽必填）

只有两项是放宽，其余八项要么收紧、要么零判定变化、要么纯文字。

| 项 | 它原本防什么 | 放宽后的误伤面 | 谁来接 |
|---|---|---|---|
| **S5** review 禁用词分区豁免 | 归档件里出现服务端发布术语，让评审人以为这是产品要交付的东西 | 人工区与两类议题里**真·产品承诺**将不再被这条拦住 | 规则三：其余机器区照拦，反例 N6 是硬门；story 侧一字未动，仍全篇照拦 |
| **S8** 报错按类分组 | （不防什么——它不是判据，是输出形态） | 分组后若模型只修头几类 | 全量列出、零截断、无第二文件；判定逻辑逐条字符串相等（单测锁）；实跑测修复率 |

**S1 不是放宽。** 它把每章一个布尔换成每章每类计数——同样的输入下，
原来报的现在都报（`drawn === 0` 分支保持原语义），原来不报的现在可能报。**只收紧不放宽。**
唯一的方向性变化是 S1b 的白名单让 `drawn` 变小（json 围栏不再算图），那也是收紧。

## §5 为什么这十项都不是补丁

**判据**：补丁 = 已定位根因却不修它，在症状处加一层。逐项对照：

| 项 | 根因 | 修的是不是根因 |
|---|---|---|
| S1 | 形态判是每章一个布尔 | ✅ 直接把粒度改对。**`04` 的修法（恢复全篇总数代理）在此被否决，理由见 §2 P1b** |
| S2 | 加第四态时改表没改正文 | ✅ 改那句话本身 |
| S3 | 判定线拿跨轮总数当粒度 | ✅ 换成读 check 的逐章逐类结论，且不重建第二个真源 |
| S4 | 没有一处告诉作者写哪儿 | ✅ 补那一处。机制零改动——冻结判据本来就拦对了 |
| S5 | 豁免参数传的是 story 章标题，对 review 恒等于零豁免 | ✅ 按 review 自己的结构分区，不是加词表、不是降级 |
| S6 | 判据把括注一起拿去匹配 | ✅ 剥括注。**不加豁免标记**（那才是补丁形态） |
| S7 | 机制层写进了本仓维护史 | ✅ 去掉编号、留下事实 |
| S8 | 洪水平铺、看不出错在哪一类 | ✅ 分组加计数。**不封顶、不写第二文件**——那两样解决的是别的问题 |
| S9 | 前两轮都中途停 | ✅ 跑到终点 |
| S10 | 只做过夹具级 | ✅ 端到端走一遍 |

**净变化不承诺方向。** S1 / S5 / S6 / S8 都会让 `story-build.mjs` 变长，这是正常的——
判据变准需要代码。上一版方案承诺「代码净减」并据此立判据，那条判据必然失败，是自设的陷阱。
本文件不设这类判据；范围纪律由「只动点名的文件 + 未动清单」保证，不由行数保证。
