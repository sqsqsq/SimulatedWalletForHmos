# Story 自动观测与驱动测试实现

## 1. 目标

新会话阅读 `test/story/TEST.md` 后，可以在用户输入“开始测试”时完成 Case 多选、确认、外层非沙箱
启动、交互驱动、Goal/heartbeat 续跑、回灌、清理和逐 Case 报告。非沙箱授权只属于宿主模型执行的
外层协调器，不进入被测模型 prompt。

## 2. 本轮改动

- `TEST.md` 增加新会话操作协议、多选与确认、宿主/被测模型边界和 Goal/heartbeat 生命周期。
- 首次启动严格串行；每个 Case 确认有效 run 后再启动下一个，失败最多恢复并重试三次。
- Story 与交互期每 15 秒观测，进入 Spec 后每 120 秒观测；事件、终态和回复立即处理。
- 未匹配交互不再自动发送固定话术，而是输出 `adaptive_reply_required`，由宿主根据公开场景回复并留痕。
- 每个 Case 保存无截断的 `observations.jsonl` 和最终 `observation-report.md`。
- 历史 `doc/features` 只迁移不恢复；所有终态 Case 回灌文档及无冲突的受控源码差异，并保留质量标签。

## 3. 验收

1. 单 Case、任意组合和四 Case 均能通过统一协调器运行。
2. 首次启动调用顺序可由测试证明，确认后的 worker 保持并行。
3. 三次启动失败、响应丢失但 run 已建立、脚本外交互和双观测节奏都有回归测试。
4. 失败 Case 的产物可以回灌且不会伪装成通过，临时工作区在证据固化后删除。
5. Goal 和 heartbeat 由宿主会话创建和关闭，Python runner 不伪造应用层定时任务。
