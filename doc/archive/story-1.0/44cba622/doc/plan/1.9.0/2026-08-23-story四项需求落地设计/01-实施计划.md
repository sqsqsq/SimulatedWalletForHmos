## §2 验证轨道

- **机制轨（demo 可执行）**：证明适配流程正确——Framework 缺失=零写入 / 首装 / 升级 / 重适配 / 失败恢复，用临时 demo 结构目标程跑通。
- **内容轨（内网执行）**：真实 SDK/API/案例取证 + ADAPTATION 绑定表"已确认"——列为**内网事项**，demo 仓不伪造"真实适配已完成"证据。
- demo 仓验收终点 = **机制链路 + 知识层本仓可证事实**；不把机制通过表述为内容已核实。

## §3 范围与禁改清单

- allowed：`doc/extensions/**`、四宿主 story 桥、`test/story/scripts|tests`（直接验证）。
- immutable：`framework/**`、产品 ArkTS、`test/story/cases/**`、冻结需求基线目录、本 design 目录。
- forbidden：不新增 Story CLI 阶段/状态机/平行 verifier；不修改 case 输入迁就实现；不把测试答案/维护历史写进生产规则。
- **机制层依赖禁令（唯一权威在本节）**：非 `knowledge/` 部分不出现仓模块名 / SDK API / 业务名 / 绝对路径。

## §4 完成定义与状态管理

- 完成判据 ≠ 文件存在：每项具备「生产落点 + 正向证据 + 负向故障证据 + 真实 Case 位置」。
- Story 完成须通过 00 §3.1 统稿检查清单（五条）+ 九问首读 + 全量事实复核。
- 行为验证结论**单独文件记录**（通过/未通过/阻塞），绝不写进 00 或本文件状态。
- EVOLUTION 只回填真实完成与验证边界。
- 全部通过后 `releases/2.0.json` 定指纹，此时才允许文档状态=验证中→已验证。
