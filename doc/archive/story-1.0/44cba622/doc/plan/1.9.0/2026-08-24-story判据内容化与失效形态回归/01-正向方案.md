## 0. 用户裁定与本轮纪律

**裁定（2026-08-24）**：基于 1.0 正向实现全部优化诉求，彻底解决，不打补丁；
本轮 CLI 实跑由用户手动执行（进行中：DTS90006），维护者交付到离线验证全绿为止。

**纪律**：

1. **判据先行**：验收判据表（02）先于实现、从冻结条款独立重推；实现对判据负责。
2. **三责任分离**：机械门禁只证明结构、引用、实体和证据**真实存在**；
   独立 verifier 判断内容**是否真的解决本需求**；历史回归 + holdout 分别证明
   旧问题不回来和机制没有过拟合。**不让任何单一代理判据同时承担三种责任。**
3. **结构判据配对内容检查**：凡「必须有 X 节 / 非空 / 逐条覆盖」的结构判据，
   配一条内容检查（机械筛 + verifier 必裁）；只有结构判据的门禁一定被形式满足（已实测四次换皮）。
4. **派生不枚举**：域、条目、专名、角色、层清单运行期从知识与产物派生；派生为空必须出声。
5. **失效形态永久留档**：每轮全量回归，每条形态带正反夹具。
6. **计数口径自声明**：计什么、不计什么，随结果一起输出。
7. 不设形式配额（冻结 02-C2 红线）；不改 `framework/`；机制层零强依赖、零测试特征。

## 7. 验证（详表见 `02-行为验证计划.md`）

三种证明各归其位，不互相冒充；汇总只按 02 的**总判定规则**，不允许选择性解释：

1. **历史回归（校准）**：AR90006 / AR90004 现有产物上，新判据必须抓住已知失效，
   **E1/E2/E3/E4 逐分支冻结预期命中行**（实施时先逐分支重数，禁止合并计数——
   合并会掩盖某一分支完全失效），且不误伤 ENV-02 / UX-01 / SEC-01 等真设计——抓不住即判据无效；
2. **泛化证明**：冻结后揭盲 holdout（首个 = DTS90006 实跑产物，见 §1 基线决策）+
   五类对抗夹具（L4-6），均不参与调参；揭盲失败即泛化失败；
3. **行为证明**：用户手动实跑，终点以实际到达为准；
   未真实到达的阶段只写「构造验证通过、行为未验证」，报告分项七字段（L7-1）；
   adapt/SHA 类结果只报基线完整性与守恒，不计入 Story 质量结论。

## 9. 错误方案留档（只记错误与教训）

| 错误做法 | 教训 |
|---|---|
| 每轮在上一轮实现上打补丁 | 判据层反应式生长，指令与门禁不同批，同族问题换皮复现；重大结构问题须回基座正向重写 |
| 用形态判据管语义目标 | 形态判据必然被最省力的形式满足；四轮四次换皮 |
| 让单一代理判据（相似度/专名）同时承担结构、语义、泛化三责任 | 代理判据可被「复述+自造专名+同义改写」形式满足并自证；责任必须拆给机械/verifier/回归+holdout 三方 |
| 整文件 SHA 绑死需要扩展元数据的原件 | 「字节一致」与「承载新元数据」互斥；守正文、白名单管 frontmatter |
| 回退范围声明与回退门禁覆盖不一致 | 只查 `doc/extensions` 看不见四宿主入口与 untracked 残留 |
| 用「到达阶段」概括产物/执行/门禁/闭环四种状态 | runner hint 与真实闭环脱节（highest_phase_reached=review 而 plan not_reached 已实证）；报告必须分项 |
| 校准与最终证明用同一批样本 | 只能证明抓住已知问题，不能证明对新需求有效；holdout 与对抗夹具必须独立 |
| 每轮只验新增判据 | 修好的东西换个形态回来，结构上不可能被发现 |
| 实现完再拟验收判据 | 判据天然对着自己做过的事；漏的那批就是下一轮的新问题 |
| 内容自检标准只写给维护者 | 模型写作时没有判断工具，只能事后被拦 |
| 计数指标不声明口径 | 「长段 7/10」把列表块算成段落，直接导致错误结论 |
| 只数覆盖率就宣布达成 | 「命中条目 100% 到达 spec」掩盖了 73%–80% 是规约复述 |
| 决策引用去掉截断而不约束复述 | 修一个形态制造另一个形态 |
| 装配器降级标题却不告诉作者 | 作者只写一级；H4 恒为 0 |
| 附录逐域覆盖按前缀判 | 编号列只写 `SEC` 也放行，粒度退化没人发现 |
| 用「每章至少一行裁决」冒充「每项事实逐项核对」 | 一章十项事实写一行摘要即形式通过——覆盖闭环必须落到机械可枚举的来源单元 ID 集合 |
| 为修「不切小节」引入数字触发的写作命令 | 数字触发就是形式配额换皮（冻结 02-C2 明禁）；计数只能作诊断喂给 verifier |
| 用参与过多轮设计的已知 Case 冒充 holdout | 只能证明抓住已知问题；holdout 必须冻结后揭盲、用过即换 |
| 校准时多分支合并计数 | 某一分支完全失效也能靠其它分支凑数通过——预期命中必须逐分支冻结 |
| 义务 schema 漏掉冻结点名的阶段（coding） | 文案提到 ≠ 结构可验证；冻结点名的每个阶段必须出现在 schema 键中 |
