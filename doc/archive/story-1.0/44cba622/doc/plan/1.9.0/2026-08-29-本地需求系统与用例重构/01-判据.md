# 本地需求系统与用例重构 · 判据（先于实现）

| id | 判据 | checker |
|---|---|---|
| KM-1 | `story.js init` 对系统快照：三套 md 落盘、AR 预填、不产生任何图片；查无此单 → `success:false` JSON、退出 1 | 单测（临时系统目录） |
| KM-2 | `archive`：系统正文被 story 覆盖、history 有备份、review 进 attachments；只有 md 进系统；工作区字节不变 | 单测 |
| KM-3 | `restore` 回到上一版；`review` 有回稿则写入并备份、无则 unchanged | 单测 |
| KM-4 | 全仓零 `mock-data` 引用（排除 .bak/scratch/output） | grep |
| KM-5 | 投放：起跑时 inbox 只有 README；脚本条目 `deliver` 触发后文件出现在 inbox；`reply --deliver` 同样 | 单测（run_case 状态机）+ 实跑事件 |
| KM-6 | 两 Case 各经 docx 补料抽出 ≥2 张图，story 本地引用可解析（check ⑨ 断链）且图片全篇唯一有 alt；`RR/assets` 路径约定与 case 内 svg 删除，图片目录只剩 `assets/<stem>/` 与 `ux-reference/` | 实跑 + 单测 |
| KM-7 | prompt 零机械化：两份 prompt 不含命令名 / 文件名 / 关卡名 / 观测点词（图片、兄弟、冲突、拆分） | 单测（词表） |
| KM-8 | 单测 / 台账 / `--phase extensions` 全绿；旧 Case 名零引用 | 离线 |
| KM-9 | 行为：两 Case 各跑一轮到 review，四路能力点（系统拉取、按需补料、图片全链、评审回流）在 events 与 system-after 里有证据 | CLI 实跑 |
