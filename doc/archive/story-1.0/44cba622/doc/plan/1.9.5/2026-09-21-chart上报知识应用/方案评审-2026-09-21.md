## 3. 阻断项：S3 的两个前提没核

### 3.1 真实 Case 要跑到 UT，装置与环境从没走过

S3 §1 定「一项真实模型 Case，终点 UT」，§4.1 要在模型写完代码后按业务入口做七种刺激并捕获 hiAppEvent 原始事件。这要求三件此前从未发生的事同时成立：story 装置驱动 framework 的 coding、review、ut 三个阶段（现有 Case 止于 plan）；宿主环境能编译 HarmonyOS 工程并在设备或模拟器上跑 Hypium（TEST 里没有任何设备协议）；`hiAppEvent.addWatcher` 在该设备上真能收到自己 `write` 的事件（设计 §2 自己写「须本工程实测」）。设计把它们列为「S3 验证」，但它们是 S3 能不能开始的前提，不是 S3 的产出。

要求：S3 前加一个**有界预检**，不用模型、不用业务 Case：用现有 Phone 工程写 S3 §3 那份 SDK 样例测试并在真机或模拟器上跑通一次，同时用装置的伪运行走一次 spec→ut 的阶段推进。预检失败就改 S3 的验收形态（例如 UT 改为宿主原生测试捕获，模型 Case 终点降到 plan 或 coding），不能等模型跑了两小时再发现设备收不到事件。预检的成本单列。

### 3.2 夹具源码没有注入通道

S3 §4 要给 Case 工作区放一个「小型既有刷新服务」作为旧业务夹具，「在 WalletMain 现有层级内放置、不进入 Demo 生产模块」。Case 工作区是整仓复制，现有覆盖层只覆盖需求目录；没有任何机制把 `.ets` 源码注入到工作区的产品目录。两条路都有代价：进主仓生产模块，则「不进入 Demo 生产模块」不成立，且 catalog/architecture 守门要过；给装置加源码覆盖层，则是 T 类装置新增，要进预算与 TEST 协议。设计要选一条并写清，不能留给实施者猜。

## 4. 要先定的三件事

1. **facts 里放完整可编译代码块（S1 §4.3）。** 与既定的知识写作尺度相悖：知识给模型消费，只给关键信息或规则与定位，不含大段实现。完整用法应当作为仓内可编译的样例代码存在（例如与 S3 那份原生测试同源的一个 sample 文件），facts 只写「完整用法在 `<路径>`，读它」。这样样例随编译保真，facts 不会与代码漂移。
2. **样例码枚举放进生产模块 CommFunc（S1 §4.2）。** 六个 `90` 段的样例值进了 05-SystemBase 的公共出口，等于 Demo 生产代码带着一组只为样例存在的常量。可接受但要写明理由与退出条件；更干净的是放在 ohosTest 样例模块，facts 指向「登记规则在 constraints、真实登记位置由目标仓定」。二选一，设计者定。
3. **1.9.4 的移交项不在 1.9.5 范围里。** 1.9.4 收口会留下：装置 post-run 门禁的环境错误、无变化退出与回写确认未实证、advisory 返修循环的观察、revalidate 与 sync-closure 文案的上游交接。1.9.5 目前只有 Chart 一项候选，spec 00 也说「不代表 1.9.5 全部范围」。建议 1.9.5 spec 目录先立一份版本总览，把 1.9.4 移交项和 Chart 需求并列，再排步骤；否则 Chart 的 S1–S3 会把版本占满。

## 5. 细节

- **基线数字过期**：设计 00 §6 用 12297 与 HEAD `4e044270`；C5 之后实测 12349、在途 12360，且 1.9.4 收口时 target 会重签。开工时按 00 §6 自己的话重测即可，但预算表要以 1.9.4 的 closed target 为起点，不以在途值为起点。
- **`setReportParam` 可见性改动的边界**：S1 §4.1 只改 protected→public。设计已说明它不是校验器；再补一句：标准字段名（FuncID、SubFuncID、WalletFuncResult 等）经通用入口写入时不做拦截，由 Review 与原始事件核，这条要进 OBS-04 的验法而不是靠读者记得。
- **S2 §2 的 Story 位置**：「功能说明章的独立 H3」与 1.9.4 A1 定的分节规则一致；但 D03 说三份文档「各有独立可定位的小节」，Story 侧还要能在附录投影里定位精确码表。设计已交给既有附录投影，可行；实施时核 `appendix.mjs` 对 §9.4 的投影不会因专项解释搬到业务章而丢行。
- **OBS-02 与 D12 的表述**：S1 §2 把「已选统计节点的终态不再报 VOC」写进 OBS-02，又保留「VOC 方法存在性探针为非阻断线索」。探针只认方法出现，判不了「同一终态位置是否双报」；这条要么明说探针不负责这一句，要么退掉探针。避免 1.9.3 那种「探针在、判断不在」的形态残留。
