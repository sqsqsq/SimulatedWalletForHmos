# 写作心智：为什么 Story 反复优化仍不像给人写的（2026-09-24）

维护设计者的反思，起因是用户指出金样里「这张图从…开始，到…为止」这类句子只在考虑怎么写文档，不考虑读者。本文先给证据，再给根因，再给替换方向；不是实施方案，实施动作在 §5。

## 1. 证据

| 来源 | 指着文档说话的句子 | 数量 |
|---|---|---|
| 第三轮 car Story（ISSUE-206） | 九章开头「本章讲清…」「本章讲整体机制…」「本章按能力分组讲…」「本章把…分开说明」；附录四节「这一节给评审者看…」 | 13 |
| 第三轮 auto Story（AR90006） | 无 | 0 |
| 金样 AR90006 | 「本节统一定义全局规则；后文说明…」；附录两节「本表帮助评审者…」「本表说明规约如何…」 | 3 |
| 金样 AR90004 | 「责任边界如下：」一类过渡句 | 1 |
| 设计者本轮补写的图前段 | 「这张图从…开始，到…为止；参与方是…；先看…」 | 4（已改回业务语言） |

同一个模型、同一套机制，auto 零句、car 十三句：这不是模型做不到，是输入把它推向了哪一边。附录那四句尤其说明问题——章节合同要求「每节开头一句『这一节给评审者看什么』」，机制自己规定了指着文档说话。

## 2. 执行模型现在被放在什么位置

把作者动笔前后拿到的全部输入摆在一起看：

| 输入 | 它对作者说的话 | 诱导出的写法 |
|---|---|---|
| 草稿每章开头两行指引 | 「读者问题：…」「主要职责：…」 | 作者把它改写成第一句「本章讲…」 |
| 章节合同附录节 | 「每节开头一句这一节给评审者看什么」 | 「这一节给评审者看…」 |
| 图三件套（第二步刚落地） | 「图前一段：这张图的范围、起止、参与方，先看哪条线」 | 「这张图从…开始…先看…」——设计者自己照着写出来的 |
| 写作设计协议 | 「形式：表格 / 描述 / 依据 / 待核」 | 先定结构与形式，再想内容 |
| story-write.md 约 360 行 | 表前一句引导、单元格不塞、图前一句、恢复类用「时机 / 方案 / 走向」…… | 满足规则；读者只在开头一段出现过 |
| 审查维度 | 表达贴合内容、标题真实、不重复、图有引入与要点 | 全是形态维度，没有一条问「这句话在对读者讲业务，还是在讲文档」 |
| 范例 | 骨架写法与决策议题各一个中性片段；正文声音的范例：零 | 学到的是遵守，不是写法 |

结论：机制把执行模型放在**文档操作员**的位置——填结构、过门禁、按规则；它从来没有被放在**向一个没参与的同事解释这件业务**的位置。读者是谁、读完要做什么、什么让他信任这份文档，在 story-write 开头有一段，但没有变成作者的任何一个动作。

## 3. 设计者的责任

1.9.4 A1、1.9.5 三轮、本轮两步，每一次都在加规则、加形态、加审查维度。金样批注的十二条是形态口径（表前一句、单元格不塞、H3 带号、附录小节 A–E），我把它当成效果定义；效果定义应该是「读者读完能做什么」。规则越多，作者越像操作员；这条关系我一直没有正面处理。

## 4. 替换方向：先设计心智，再留必要的规则

这一节是方向，不是逐条规则；每一条都说明它替换什么。

**读者与用途先于结构。** 写作设计的「阅读主线」现在只问「最容易误解的关系」；改为三问：读者是谁（评审人：产品、开发负责人、测试，都没参与开发）、读完要做什么决定、哪几件事最容易误解。这是作者动笔前的第一个动作，替换「先定小节与形式」。

**声音：向同事解释业务。** 全篇每一句的主语是业务里的人、系统、对象、规则；不是「本章 / 这一节 / 这张图 / 下表 / 如下」。章不写开场白，第一句就是业务；图前讲过程（谁在什么条件下做什么、结果怎样，不看图也懂），图后讲判断（这条分支里读者要知道的条件、责任、后果）；表前那一句说的是业务事实（「一次挂失涉及五个参与方」），不是「下表列出」。这一条替换 story-write 里所有「表前一句引导」「图前一句承接」「图前一段讲范围」的表述。

**附录是查阅区，允许一句定位。** 附录读者是来查名字的，节首一句定位（「接口、数据、配置与统计点的精确名称在这里」）可以保留；正文十章之内不允许。这一条把合同的「每节一句目的」限定在附录，并把它改写成业务定位句而非「给评审者看什么」。

**范例替代规则。** story-write 放一段中性题材的小节范例：一章的开头、一张图及其前后文、一张表及其引导句、一个恢复类短段，用范例承载声音；再把 360 行里重复讲形态的句子删到只剩机器不核、审查要判的那几个判断点。范例一段、规则减半，模型才有东西可模仿。这是本方向的核心动作，替换「再加一条规则」。

**指引行说内容，不说文档。** 草稿的「读者问题 / 主要职责」改成「读完这一章，读者要能回答：…」并注明直接回答、不写本章讲什么；图三件套三行改成内容句：「先把这段过程讲一遍：谁在什么条件下做什么、结果怎样」「图」「逐条：这条分支里读者要知道的条件、责任、后果」。替换第二步刚落地的三行措辞。

**审查从读者位置判。** story_reader_review 加一条判据：正文里指着文档说话的句子是表达缺陷（advisory），章开场白是读者要跳过的一段；不设机器词表，由审查判。替换现有「图与文的配合」那条的措辞方向。

**金样的效果定义升级。** 在金样 README 的十二条形态批注之前加一段「读者心智」（读者、用途、声音），批注保留为形态；两份金样正文按声音再过一遍（设计者做），首先是 AR90006 第 76 行「本节统一定义全局规则」与附录三句。

**验证。** 离线只能验范例在、指引改了、审查判据在；效果只能由单阶段定向实跑看：成品里有没有「本章讲」「这张图」类句子，图前后是不是在讲业务。

## 5. 与当前步骤的关系

- 第二步提交前先做两处最小修正，避免刚落地的三件套把「这张图从」教给模型：`drafts.mjs` 三行图指引与 `story-write.md` §三、spec overlay 图三问的措辞改为 §4 的内容句；章节合同附录「一句目的」改为业务定位句并限定附录。这两处不增加规则数。
- 其余作为第三步之前的一个新步骤「写作心智」：设计者先写范例段与读者心智段、过一遍金样；实施者再改写作设计三问、指引行、story-write 删减与审查判据；预算另估，走 AGENTS §5。
- 第三步的单阶段定向实跑等这一步完成后再起，否则测的是旧心智。
