## 3. 正向设计

### 3.1 版本号开工即升（5a）

上一版发布后，新版本的第一次提交就把 manifest `version` 升到新版本号，升级演进记录同时出现这一版的节；发布提交带发布说明与使用指南。`test_story_build.py::test_the_manifest_version_covers_this_round` 锁版本号与演进记录那一节。

### 3.2 按版本升级（5a，U30）

- **升级演进记录** `skills/story-adaptation/reference/upgrade-changes.md`：按扩展版本分节，每条以块开头——`[知识]`、`[对接层]`、`[在途单]`，写变了什么、目标要做什么、怎样验证。对接层条目只写扩展调用或读取的命令、参数、stdout、写盘落点与失败语义。
- **目标状态键** `adapted_for`（归目标）：三块都交回后由模型写成包的版本；缺这个键从头列。
- **脚本**：启动时逐条读演进记录（没标块的一条即报包坏了、不写目标）；升级后按块列出条目——知识与对接层列晚于 `adapted_for` 的，在途单列晚于目标升级前所装 `version` 的（在途单只跟从哪一版升上来有关），包带对接实现时不列对接层块；知识只读检查照旧。
- **SKILL**：「按版本跟进」一节给出三块各怎样做、交回什么；升级后按块摆给人问一次，可只选几块；替身包首装时对接层列为未适配，从已实现的业务仓复刻。
- 内网指南退场；使用指南指向演进记录。

### 3.3 README 定位与内外网隔离（5a，U31）

- `scripts/README.md` 删除；⑤ 改为 `scripts/` 根下没有文件。
- 替身文件头只写替身自己做什么；`story.js` 的 docstring 写本替身实现的命令接口。extension 里不出现「内网」。
- `contracts/README.md` 移到 `test/story/章节合同说明.md`，同步 `id_shapes.function`、流程契约 schema 与 `update.decisions` 的现行形状。
- `templates/inbox-readme.md` 按导入规则写人要做的事：四类材料与去向、读不了的格式由 AI 转写。

### 3.4 埋点描述字段（5b，U33）

依据 `05-SystemBase/CommFunc/src/main/ets/shared/ha/`：

| 渠道 | 事件内容 | 回答的问题 |
|---|---|---|
| VOC | 事件名固定、类型 BEHAVIOR；带调用方给的事件编号、可读文本 `WalletEventDesc`、`FuncID=VOC` | 这里发生了什么、为什么 |
| Chart | 类型 STATISTIC；带模板、流程、步骤身份，结果分类，内码，外码 | 哪一步、哪种结果、外部错误码 |

- 三个 `log*AndReport` 门面先写本地日志再发一条 VOC；Chart 的 `report()` 不写本地日志，基类的 `setWalletEventDesc` 让它也能带可读文本。
- 同一统计点只走一个渠道：进统计的结果走 Chart，描述写编码表达不了的原因、场景与定位用的关键状态；VOC 只用于不进统计的过程定位点。Chart 点位要本地日志时直接调 `Logger`，用门面会同一点位再报一条 VOC。
- 描述写成每种结果一句固定说法加本次关键值，关键值写来源；不写个人数据与凭据，编码字段已有的值不重抄。
- 知识下篇逐结果要给的值由三项变四项（加描述）；上篇「选渠道」让 spec 能直接定渠道；可观测规约 OBS-02 写明统计点位的定位信息随统计事件的描述带。
- 替代 1.9.5「描述按项目规范要求带」的口径。

### 3.5 维护规约与实跑宿主（5c，U32）

- AGENTS §3.2 只改两条：「正向实现，不打补丁」写成 extension 不兼容历史功能或数据格式，旧格式直接报错并指明在旧版本收口或从 init 重起，升级要做的事只写在演进记录；「正向表达」覆盖方案、知识与交付面，退出项进退出表。其余候选是单次诉求，不进规约。
