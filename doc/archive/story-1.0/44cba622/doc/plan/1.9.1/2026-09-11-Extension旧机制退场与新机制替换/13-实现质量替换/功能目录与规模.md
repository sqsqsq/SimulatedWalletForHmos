# 功能目录与单脚本规模

用户新增要求：同一块功能放在子目录，不把子脚本全部平铺到core根；最终单脚本不超过500有效代码行，不含注释和空行。本文件规定Q线路终态布局与规模；每包接口、退出与验收在Q1–Q11分册。只修改维护方案，不实施搬迁。

## 1. 口径与基线

沿现有test_mechanism_budget.code_lines计算MJS/Python有效行；JS也按脚本去注释及空行，不把整行合写、删必要说明或迁到预算外当缩减。单文件500与需求总量是两项不同指标。

ebdd317f实测：story-build.mjs 1696、story_flow.py 1072、knowledge-use.mjs 499、import_sources.py 461。前两个必须拆；后两个虽未超限，也需保持职责与目录清晰。200–350行是规划参照，不强求小模块凑到200。

500是本轮最终默认上限。新建/完成迁移的模块在当包验收；尚未迁完的旧入口允许阶段性超过，但须在下表规定步骤退出。不能用“临时入口”无限延期。确有不可合理分割的职责先具名评审，不以机械切块或删功能凑数。

## 2. 终态目录

对外命令路径保留；旧入口只留下参数解析、命令分派、顶层错误/结果输出，属于正式入口，不保留导出旧内部函数的兼容层。子模块不各建CLI，不要求业务模型多记命令。

```text
skills/story/scripts/
  adapters/                        # 业务仓对接，所有权不变
  core/
    story-build.mjs                 # 成文CLI入口
    story_flow.py                   # 需求流程CLI入口
    import_sources.py               # 导入CLI入口
    story/
      context.mjs                  # 成文当前输入、路径与冻结守卫
      document.mjs                 # 原章节/机器区定位与编号
      drafts.mjs                   # 草稿渲染与缺稿恢复
      chapter-contract.mjs         # 必要结构、种子及局部结构核对
      chapter.mjs                  # 单章提交与接续
      appendix.mjs                 # 附录投影、手改保护、只读比较
      sources.mjs                  # 正文来源与材料贡献清单
      images.mjs                   # 图片身份、源图对应与引用检查
      review.mjs                   # 决策读取、Review渲染及人工区保护
      check.mjs                    # 全篇检查调度、问题归组
      delivery.mjs                 # 回执、真实审查结论与交付
      language.mjs                 # 原lint-rules语言/路径作用域
    flow/
      __init__.py                  # 空包标识，不做导出转发
      state.py                     # flow持久化、常量及基础状态查询
      inputs.py                    # 定位/选项侧车读取、初始化AR骨架
      routing.py                   # scope_step/next_step与阶段恢复定位
      decisions.py                 # 人签、份表与范围决定
      rounds.py                    # round与reopen
      submission.py                # C00候选、原输入身份与complete
      lifecycle.py                 # status/story/archived命令
      check.mjs                    # 原flow-check，JS侧读取/校验flow
      client.mjs                   # Q1共用的Python status查询，两个JS消费者
    materials/
      __init__.py                  # 空包标识
      importer.py                  # 导入实现，原import_sources主体
      registry.py                  # 原materials.py材料身份、登记、摘要
hooks/
  shared/
    knowledge-use.mjs              # 原知识命令入口
    knowledge-use/
      document.mjs                 # knowledge-use读取与合法形态
      validation.mjs               # 覆盖/落点检查
      projection.mjs               # Spec生成区渲染与只读保护
```

这不是立即创建全部文件的清单：每个模块到所属步骤有实际消费者时才创建。若两项小职责实际紧密且合并后低于500，可在对应步骤方案具名合并，但不能改成utils/common杂物文件。知识激活、实体契约、探针等现有独立功能保留原模块，本轮不为目录整齐强拆它们。adaptation已有独立功能目录，不混进上述运行核心；业务adapters不搬。

## 4. Python拆分的准确归属与依赖

state.py：FlowError、流程路径/状态/关卡常量、log/now、load/save/require、ledger_digest、after_complete、round_gates、last_gate。数据定义仍复用原合同，不为拆包增加配置文件。

inputs.py：read_sidecar/consume_sidecar、read_positioning/read_scope_options、chosen_dimension/split_carrier_options、sidecar_gate/read_gate_options/read_split_parts、material_options、read_ids/ar_design_skeleton/cmd_init。初始化骨架在这里唯一维护，submission使用同一生成函数识别空骨架。

routing.py：material_state/frozen_inbox_note/frozen_tail、material_gate_state、settled_this_round、scope_step、spec_stage_step、sidecar_shape、next_step。它只依赖state、inputs和materials.registry；不导入decisions、rounds或lifecycle。

decisions.py：cmd_decide；依赖routing.next_step检查当前可操作关卡，依赖inputs读侧车，不自己复制路由。rounds.py：cmd_round/cmd_reopen；依赖routing查询材料/冻结状态，不通过lifecycle间接调用。

submission.py：resolve_candidate/section_numbers/is_ar_skeleton/candidate_problems/ar_input_identities/prior_ar/cmd_complete；依赖state、inputs骨架、routing.scope_step/material_state、materials.registry。三种身份和全部恢复测试保持，不能以搬迁为由回退到第一次未修复版本。

lifecycle.py：cmd_status/cmd_story/cmd_archived；调用routing并沿原命令路径调用story-build，不导入入口story_flow.py。根入口只import各命令，不反向被功能模块import。该方向专门避开“cmd_decide需要next_step，next_step又需要范围判断”导致的循环。

Python入口以现有core为模块搜索根，使用明确包导入如 `from flow.submission import cmd_complete`、`from materials import registry`；不在每个子文件追加sys.path。CLI任意cwd均须通过 `--project-root` 及原默认根定位用例；默认工程根在入口计算一次后传递，不能继续照抄迁移前的 `parents[6]`。

## 5. JS调用与全篇check拆法

入口创建一次ctx，传给显式命令函数；模块只读所需字段，不注册到新调度器。context可以依赖已有hooks/shared路径与知识读取，但不导入check/command。document只处理文字定位/编号，不读业务状态；其它功能模块可共同使用。

check.mjs调用chapter-contract、sources、images、appendix、review、language、delivery的明确问题函数。已有不同职责的检查不能因为都返回string[]就合成一套新规则DSL。全局章序/H1/完成态归check；各领域判据回所属模块；同一错误不由入口再查一遍。

为避免Q5需要投影而Q6模块尚未建立的反向依赖，Q5可先将已有投影职责机械迁到appendix模块，保持算法、接好两个当前消费者；Q6再在同一个模块完成原定算法收敛。迁移仅一次，Q5不在入口保留影子版本、不传入口函数回调。这一提前移位不等于提前完成Q6功能。

类似地，全篇check中尚待后续优化的来源/图片/Review职责若要迁出以避免循环，在Q5只做语义等价归位，记录明确后继；各后续步骤在所属文件直接替换旧算法。不能创建“legacy-check.mjs”把整块大函数藏起来。

## 6. 消费者与退出

变更import要覆盖Extension内部、六阶段hooks、作者包、测试直接import、失效形态脚本及适配资产核对。对外story-build/story_flow/import_sources命令路径不变，子模块不是新增业务操作步骤。

Python测试不再从story_flow入口取内部常量/函数，而从实际所属模块导入；CLI测试继续调用原入口。JS直接import的导出同样改到所属模块。禁止为了让旧测试不动而在根入口批量re-export；兼容内部import不是用户功能。

移动headings、lint-rules、review-render、materials和flow-check的步骤，同包删除旧文件并切换全部消费者。knowledge-use根文件保留真实CLI，读取/投影API消费者改import子模块，不保留双份实现。安装器已有递归复制固定目录能力继续使用，验证新子目录实际能被安装、旧固定文件实际被清除；不恢复历史迁移协议。

提示词指向正式命令和作者材料，不把内部模块清单灌给执行模型。维护FEATURE映射到实际模块，业务作者不需要读源代码才能知道要求。

## 7. 验收与约束

1. 每包列旧函数/判据→新唯一文件→全部消费者→旧位置删除；不能仅报告原文件变小。
2. 对新/已完成模块测有效行和完整字符；Q11扫描全部交付脚本（含安装器与adapters），报告超过500者，不把它们排出单文件审视。测试脚本单列，不混入Extension限额。
3. 导入图无循环、模块导入不自动执行CLI、不写文件；实际命令验证原参数/退出码/输出和工作目录支持。仅import成功不算调用链成立。
4. 原正常、失败、恢复测试迁到新路径后仍验证同一行为；C00三身份×保存失败、章外字节、投影人工区、源图、知识一对多等不能因模块拆分丢失。
5. 不加新状态、功能字段或额外模型轮次；不压行/删注释凑500；移动不冒充净删除。合理的import/错误传播成本如实计入总预算，必要超限按04具名处理。
6. 逐包评审后再继续，不趁下一包修前包遗留；最终完整功能树和模块映射共同复核，确认被替换的旧机制确实退出。
