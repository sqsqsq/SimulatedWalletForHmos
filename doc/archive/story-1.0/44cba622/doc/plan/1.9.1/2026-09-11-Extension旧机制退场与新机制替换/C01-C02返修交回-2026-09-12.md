## 2. R2 必要结构：位置、条件与最低凭据

数据合同（`structure`）改成：`h3[] = {title, when?}`；`tables[] = {header, anchors, at?, seed?}`，`anchors` 是锚列组，第一组认表的主语、其余组是**同一张表**必须有的列，每组内任一同义说法命中即可。同一份解释供打底与核对两处用（`chapter-contract.mjs`）。

| 评审复现 | 现在 |
|---|---|
| 有兄弟、有交接叙述、无表 → 报缺「约定」表 | 「约定\|内容」表退场，改为 `{title: 交接约定, when: siblings}` 说明节；有叙述即通过 |
| `siblings=null` 仍强制 | `when: siblings` 只在**确为 true** 时必需；null（离线仲裁锚）不判缺席、也不打底 |
| 流程章图挂在局部小节，章首无总览 → 零问题 | 章首范围＝第一个正文 H3 之前，图不在那里就报，并说清「挂在局部小节下面答不了整条业务怎么走」 |
| 验收只有「编号」一列 → 零问题 | 锚列组 `编号` + `通过条件/通过判据/算通过/算完成`，缺列点名；`原始编号/场景与前置/怎么算通过/主责` 这种改措辞加列的写法照过 |
| 交付物表在章内任何位置都算 | `at: 交付物`，只在那一节里认；那一节缺席由必要 H3 那条报，不重复 |
| 围栏里的示例标题/表冒充正文结构 | 结构判定走「去围栏视图」，围栏内容只参与章首图判定 |
| 必要 H3 不进草稿种子 | 种子按同一解释生成必要 H3 标题，附属表打在它下面（`### 交付物` + 交付物表） |

**一处按金样纠正设计**：10 §7 要求交付物保留「用途/接收方/时间」凭据，而判据锚金样 AR90004 的那张表是 `交付物 | 给谁、做什么用` 两列、没有时间列。按「拦金样即判据错」，机器只核身份、接收方、用途；「什么时候要」留在表头种子与逐章方法里，完整性归语义审查。已同步写回 08 §3 与 10 §7。

## 3. R3 起手预检：问材料链，不比两份旧摘要

`cmdSkeleton` 重排成「读完、判完、算完，才写盘」，五道预检依次是：

1. **流程**：契约在、`flowProblems` 通过、本轮 `complete`；
2. **材料**：清单在、与本轮基准一致，再加**磁盘现状**——由 `story_flow.py status` 回答（`staleMaterials`），不另算 JS 摘要、不另立版本台账；问不出来（解释器起不来／非零退出／输出不是 JSON）当场报原因，不当成「材料齐备」；
3. **来源必需性**：`sourceStatus` 一处判定，远程单由既有 `AR/detail.json` 认，本地单的 PRD/系统设计降为可选并记一笔，必备缺失阻断；
4. **Spec**：可读、非空，并核本步要消费的那几节（术语映射表、§9.1–9.5）定位得到——定位不到**记一笔并说清后果**，不拦（那一节确实不涉及是合法状态）；
5. **决策登记**：严格读取，坏 JSON／坏形状当场报错；**这一步只读**，空骨架与草稿、Story 一起在预检全过之后才写。

Python 侧同包补上「收口之后材料又变了」这一支（`next_step` 的 complete 分支）：此前收口后材料再变没有任何人问，两份落盘记录彼此照样相等。处置是 `round`（它不开新轮，要重新决策才 `reopen`）。没有登记过基准不算「变了」——那是轮次缺材料指纹，由流程契约判据报。

**同判**：交付前的 check ⓪a 改用同一个 `sourceStatus`，必备缺失进 problems、可选缺失进 notes，与注释「必备缺了拦」一致。夹具补齐相应必备来源（见 §6）。
