## R1 · P1 · 引号与行尾注释组合仍会覆盖真实 adapters

位置：`doc/extensions/hooks/shared/yaml-lite.mjs` 的 scalar；`adapt-scan.mjs` 的 manifestValue 与 WITH_ADAPTERS。

改为调用 parseYaml 的方向正确，但该读取器先判断整串是否由引号包裹，再剥行尾注释；剥完后不再处理引号。`name: "wallet-sdk-demo" # source` 因而返回包含双引号的字符串，WITH_ADAPTERS 仍为 true。

本次用临时包和带真实 adapters 的目标复现：只改变上述 YAML 写法，apply=0、真实适配文件被替身覆盖、check=0。它仍属于上一轮 N1，不另起来源类型问题。

修正应在标量读取的词法处理上完成：注释只在引号外生效，引号内的 # 是内容；合法引号和注释组合须得到同一字段值。不要在 adapt 再加一个字符串替换或 Demo 特例。补充组合测试，同时保留引号内 # 的正确行为；不要求扩展到本次用不到的全部 YAML 特性。

## R2 · P2 · 步骤 3 不应从探针操作符推导它是不是强制要求

位置：步骤 3 §4.3“探针分两类，由形态决定”、§5 P4。

新方案将 absent_regex/count_eq 一律视为“约束本身”，present_in_method/referenced_outside_definition 一律视为“辅助取证”。操作符只说明怎样匹配，不能说明匹配与业务要求之间的关系。存在性检查也可能对应明确的强制形态；计数检查也可能只是观察线索，例如源码出现次数不能自动代表运行时事件次数。

这个分法解决了当前 Chart 的误拦，却把该例的处置泛化成所有知识的共同语义。知识维护者仍需迁就机制对操作符的预设，不符合本轮要求的维护解耦。

建议先统一探针的职责：若本轮只将探针定位为辅助证据，就统一按这一定位交给既有验证者判断要求是否落实；若要支持强制形态，则必须由知识明确声明该形态就是要求，不能由脚本根据操作符猜。选定后替换当前二分表，避免保留两套互相矛盾的说法。不要求为了当前样板再扩正则、加新探针类型或新增调度。

验收围绕声明与证据的关系：相同操作符可服务不同要求时，处理不能被机械类型错误决定；规约强制力和实际未落实的后果仍按既有合同执行。

## R3 · P1 · 步骤 5 的人工结果还缺“落到需求哪里”与“是否替代旧决定”的明确表达

位置：步骤 5 §4 options.effect、§5 有效结果表、§6 消费说明。

第一处：effect.resolve 只有 open_point 与 value。正常情形是会上没有决定阈值，因此 changes 为空，仅留下 O1；人在材料关卡选定阈值 5。此时人已经作出了需要进入需求的决定，但有效结果表仍写“changes 为空，无变更进 design”，没有定义 O1 的值落到哪个需求或方案位置，也没有明确它如何进入刷新清单。当前验收只检查“值落定并标人定”，没检查下游真正采用它。

第二处：overturns 放在话题级，表里仍用“已签为采纳/不采纳”决定旧条目失效；选项 key 已是任意值，effect 又只有 ownership/apply_changes/resolve，没有表明本选项是否替代旧决定。不能用 apply_changes 非空推断：接受一个“不修改原文”的新决定也可能替代旧决定；反之选项可能只解决另一遗留问题而保留旧决定。

修正方向：让选项的实际结果完整表达其对需求及既有决定的影响。模型在摆选项时写清，脚本只选择、核引用并投影。可以沿用现有变化与结果结构，明确人工补定的落点及来源，并把替代关系绑定到被选结果；不让脚本理解“采纳”文字，也不从空列表猜意图。

补两条直接验收：

- 会议仅有遗留问题、changes 为空；人补定后，design 使用该值，必要的刷新清单包含对应变更，来源标为人工补定。
- 同一话题的两个选项分别替代/保留旧决定，选任何一个后，有效结果只按对应选择处理；无须 key 名称含 adopt/keep。

这两处属于 N6 的剩余输入输出缺口，不需要再次扩展会议状态或增加平行结论文件。
