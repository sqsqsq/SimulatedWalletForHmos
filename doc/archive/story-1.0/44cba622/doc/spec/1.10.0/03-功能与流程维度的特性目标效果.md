## 2. 开发流程主干（逐阶段）

### S1 起手与取材

| 特性 | 目标 | 目标效果 |
|---|---|---|
| 系统单取材 | 从需求单号可靠取得全部上游材料（1.9.0 基线能力，1.9.5 完整化，→02§2） | 「AR 单逐级取回 AR、SR、RR 三份正文；取不到的写成占位件，按缺料处理」（全景表） |
| 本地单起手 | 没有系统单也能开工（问题单/工单） | 非 AR 编号不碰需求系统，材料由人提供；「本地单没有归档环节——交付终点是仓内的 spec/story/review 三件」（SKILL:129-130） |
| token 配置 | 接入需求系统一次配好 | 按三级顺序取（脚本→用户配置→向用户要并写入），「配一次以后都不用再配」（SKILL:208-219） |
| 工作区骨架 | 需求目录结构确定、重跑安全 | init 建 `RR/SR/AR/inbox` 四目录与骨架文件，「唯一写入者，重跑安全」（SKILL:120） |
| 异常分流 | 来源异常不静默 | 「缺权限、查无此单、无关联材料分别报告」（树:13） |

→01§A1（缺口：F05 真实鉴权未测；非 OpenCode 宿主未测）。

### S2 材料补充与导入

| 特性 | 目标 | 目标效果 |
|---|---|---|
| 收件与六类归类 | 人工补料有唯一入口、归类有据 | 「收件箱是人工补料的唯一入料口」；归类由模型按内容判六类，「路径只是事实的定位，不参与归类判断」（06:21） |
| 递归收料（R2，1.9.9） | 整目录补料不再靠模型复制平铺 | 「用户把整目录放进 inbox（任意深度）……子目录里的文件按相对 inbox 的路径出现在材料盘点、归类件与导入结果里」；「保留输入子目录、冲突显式处理」（06:20,25） |
| 冲突显式处理 | 不静默合并/丢弃 | 「同名与落点冲突在写入前显式报告……不静默合并、不静默丢弃、不带病写入」（06:31） |
| 材料清单三列表（R1，1.9.9） | 采用关系有唯一语义正文、机器事实不退 | 「作者维护的一张『材料｜来源｜贡献』三列表，是采用哪些材料、来源与贡献的唯一语义正文」；「materials.json 保持唯一机器事实索引……漏写一行不能把原件排除在审查外」（05:17,19） |
| 检查分工（R1） | 语义与机械各归其位 | 「表结构、来源覆盖、重复、缺文件与禁止纳入的过程件由脚本核；来源采用是否合理、贡献是否真实、遗漏业务内容由独立审查核」（05:27） |
| 图片身份与取舍 | 一张图有确定身份，能被引用、能解释为什么不用 | 「图片按内容身份登记，引用或说明不用；不漏原图」（CLI F11 预期）；F 树 F1.3 |
| 格式转换与原件留存 | 补料格式多样且原件可回查 | docx/文本转正文、图片抽出保留引用；「原件都留档」（README:93）；「不能读取时明确缺口，不丢内容报成功」（树:14） |
| 版本替代与备份 | 新版到来旧件可回查、不混拼 | 「未导入料阻断，真实材料变更可见」；「替代由内容决定，旧原件保留可恢复，多版本不混拼」（CLI F14/F15 预期） |
| 材料门禁 | 「料到了没有」由事实判定 | 「材料门禁把子目录里的新料算作『到了』」（06:22）；「模型先盘点实际缺口，人决定本轮补料；不把未取得的材料当成已理解」（树:17） |

→01§A2/A3（缺口：F07 PDF/损坏格式、F13 来源名不贯通、F15 替代链未证明）。

| SVG 自然选型（R4） | 按证据选载体，不凑覆盖 | 「已验证 SVG 更清楚且日常总成本不增加的场景，直接优先 SVG；不要求先画 Mermaid 失败」；「证据不足时只声明支持能力，不声明该场景已达到优先条件」（08:35,38） |
| 本地交付打包（R4） | 读者离线可读、资源完整 | 「读者取得一个 story-package.zip……只收当前已登记交付版本的引用闭包」；「越界引用在打包前报告……不静默断链」；「相同材料重跑应得到同一内容集合，不因压缩容器时间戳强制模型重审」（08:57,61,73） |
| 系统交付三报告（R4） | 远端能力不冒称 | 「系统交付分三项分别报告：系统正文归档、图片展示、zip 附件上传……无接口证据时只交本地包，系统资源交付单列未完成，不用本地存在文件冒称已上传」（08:69） |

### S6 独立审查与交付门

| 特性 | 目标 | 目标效果 |
|---|---|---|
| 必审集合派生 | 审查范围由输入事实决定、缺件不缩小集合 | 「reviewInputs 按用途推导……文件在不在只影响 missing 标记，不再决定是否必审」；「审查者看不了图时，按未核处理，不从集合里删掉」（→02§2 S1/S2 返修 RV01） |
| 报告协议 | 结论可机读、状态五值自洽 | 「结论只认 PASS、WARN、FAIL、UNKNOWN、SKIP……PASS 与 WARN 都要求覆盖完整、没有必审未核、没有阻断项；FAIL 必须带阻断项」（RV03，→02§2）；「汇总 FAIL 与终态 PASS 矛盾拒收」（1.9.9 S2 提交说明） |
| 交付门 | 按实际审查结论放行 | 「reviewVerdict !== 'PASS' 时拒绝交付并说明判的是什么；NOT_APPLICABLE 时记一笔『未经读者语义审查即交付』」（F 树 F5.6）；「宿主没有配审查员时如实披露」（树:97 G4） |
| 闭环判定 | 表面闭环、实际没审被拦 | 「update 收口与交付门用同一条闭环判定：开轮以来审查对象变了的阶段，要有当前对象的 PASS」（1.9.7）；本轮实证：C update 首次 close 拦下未采纳报告（CLI F52） |
| 阻断分级与 WARN 处置 | 必修不降级、告警有收敛 | 「阻断类缺陷被拦在本阶段」（1.9.7 J5）；1.9.9 O9「已报且未修的告警由『每轮重报』改为『修了清零、不修写明处置』」（→02§3.7） |
| 失败解释 | 一次给全、不逼读源码 | 「首次输出都一次列全，并带上位置、机制与恢复入口」；环境缺失与产物问题、门禁自身异常分开说（→02§2 RV06 诊断矩阵） |

→01§G1/G3（缺口：审查区分力未证明——资格门未跑且样本不全；checker 读取 30/66 次）。

### S7 归档与恢复

| 特性 | 目标 | 目标效果 |
|---|---|---|
| 核心归档（archive 一条命令） | 上传前门禁必过、回执必核、不重复上传 | 「一条命令走完：交付门 → 对接层上传并读回核验 → 核回执 → 登记归档态」；「交付门没过不调用需求系统；回执不全不登记」（SKILL:138-143）；「归档前交付门不过就不上传」（F 树 F3.3） |
| 云端备份与 restore | 覆盖可回退 | 「归档把需求叙事与评审记录上传需求系统，覆盖前的系统正文存进 .backups/cloud/；恢复用它回退上一次归档」（全景表） |
| 归档态与视图分离 | 远端成功≠本地登记成功≠阅读完成 | 「远端成功而本地登记失败时，说清副作用并给出只补登记的入口，不重传」（→02§2 S3 交回）；「系统资源交付单列未完成，不用本地存在文件冒称已上传」（08:69） |

→01§F 组（缺口：F56–F58 全部未覆盖——检查点吞归档回复，装置已改未跑）。

### S8 变化承接（update）

| 特性 | 目标 | 目标效果 |
