# 步骤4：按完整恢复目标验收，而非按文件清单验收

01–03适用的离线验证完成后，沿TEST安排真实行为验收。没有Framework正式集成证据可以经用户授权先做写作探索，但不能宣称整个需求的AC机械一致性已完成。

## 1. 离线验证

复用现有story_build、writing_flow、author_task_package、chapter_view、image_registration、verifier_report_protocol、verifier_chain、S4/材料和知识测试。实施各职责后跑相关用例，整项收口跑一次必要全量、形态与适配检查；按TEST并行，无新变化不重复全量。

正常路径与缺失/坏输入、可选来源缺席、已写草稿恢复、template修改/冻结/重开、旧机器区/人工区保留都要有出口。所有模型选择后的结构校验复用现有解析/判据，不新增第二套开闭/表头算法。

退出核覆盖代码、提示、协议、模板、测试旧期望和入口：本轮新链只有一条，旧2.3索引系统未恢复，旧Q“没有整篇设计”的路线不再与新路线并存。静态测试不能只验证新关键词出现，应核旧消费者退出及真实数据输出。

## 2. 真实测试顺序

每次由用户按TEST启动并确认Case/配置，不因本文件自动发起CLI。建议先与20260913的auto-topup在相同材料/范围及实际模型版本下比较，成功关闭关键问题后做同条件独立重复，再选择已有car-key-sharing或traffic-card-loss观察不同关系。配置名相同不能代替版本相同，用户干预与等待单列。

当前Case均不能自动代表完整无页面数据管理需求。先以中性无UI材料离线核方法开放性；如需正式无UI Case，说明其需求与输入范围后取得用户授权，不用改Case名称或加入金样答案冒充泛化测试。

## 3. 首稿、过程件、最终稿分别检查

| 对象 | 期望看到 | 不能替代的证据 |
|---|---|---|
| 初筛 | 已有理解、资料用途/疑点在后续实际复用，原始义务没有被Spec省略消掉 | 材料索引存在、每行打勾 |
| template | 当前需求的主线/依据/待解释关系/跨章分工，形式有理由，真实未决有出处 | 固定十章标题、泛泛“讲清楚”、照最终稿倒写 |
| 设计开放性 | 合理深化可以修改安排；未列的新有效内容仍进入正文 | 所有正文标题都与模板完全一致 |
| 首次正文 | 模型使用相关原图/表/关系，未决不被肯定；主要解释位置一致 | 最终靠门禁补齐图片和标记 |
| 整稿 | 从原始来源及已定判断核实际覆盖，比较独有信息、关系与后果；必要重现保留 | “已通读”一句、固定改动数或自评记录 |
| 中间契约 | 各数据对象/动作有依据或明确待决，同ID关联一致，知识改变设计并可传递 | 只有机器投影与原表一样 |
| 独立审查 | 按原材料独立发现作者及模板遗漏，合法表达差异不误拦 | 报告结构PASS、模板结构齐全、源码引用路径齐 |
| 恢复 | 既有判断和正文可继续使用，模板不是每次重新生成，状态/材料变化走正确路径 | 文件恢复但模型从头再决定同一业务 |

从既有events/runlog/artifact还原初稿和修改，不要求消费模型另写审计日志。工具输入/输出与分页截断一起看，文件存在不代表读到；没有内层轨迹的verifier行为标未知。保持初始证据，不修改旧稿或金样补证。

每个H2/H3/H4最小正文都评估，父节自有正文也算：事实、关系、形式、重复、遗漏、责任与可验收性。图不按数打分，表不按列数打分；金样用于效果比较，不把其未批准业务结论或小节清单放入消费上下文。

## 4. 达成标准与否决信号

按TEST三轴分别建议评分，经用户确认三轴达标才宣告达到效果目标。性能比较整体耗时、人工等待、外部故障、重复源码读取、上下文与模型调用，不用“多一个template”或“少几行代码”直接换分。

以下说明恢复能力未成立：template只是形式壳、写作不消费它、原材料义务在初筛/Spec/template任何一层丢后不再查、一个未决在不同章被重新定、为遵模板删除有效深化、统稿只补标记、verifier按模板打勾放过真实缺口。回真正职责修，不追加模板字段或审查轮次作为默认答案。

相反，没有问题无需制造修改；两方简单交互无需大图；无图片材料无需找图；合理未知按边界呈现，不因“模板必须填完”强行定案。保留范围人签、原件、已有图、原始AC和知识传递等保护项，不能优化主线却退化验收或数据义务。

## 5. 交付与维护映射

更新FEATURE候选：恢复“初筛判断延续”“运行时整篇写作设计”“按设计表达与确定性结构落实”“模型从来源核实际全文”的真实职责，不再以骨架派生/脚本check冒充。功能粒度按独立职责决定，不以“本轮没有新叶子”的叙事固定ID。代码/数据/提示反向映射含template生产者、作者/脚本/verifier消费者、失败与恢复位置。

分别报告功能新增/替换/退出、必要结构成本、完整字符和实际模型输入成本，保留310初始估算及用户后续确认额度，不按步骤重置。预计增长不能自动提高旧目标，净减也不能豁免行为缺失。

在本需求实际实现后按用户既定1.9.x策略准备版本和使用指南差异，不现在改manifest、不宣称已经发布。Framework依赖、未验证宿主/场景、真实评价与旧轮G2关系明确交用户裁定。最终交付同时证明新行为成立和被替代旧路径退出，不借另开轮次隐藏本需求未完成项。
