## R1 YAML 读取与 framework 同一读法

**现状**：`hooks/shared/yaml-lite.mjs`（217 行）自述不支持流式映射；6 个直接消费者（`contracts.mjs:9`、`knowledge-use/document.mjs:16`、`knowledge.mjs:23`、`verifier-report.mjs:26`、`spec/post_check.mjs:22`、`skills/story-adaptation/scripts/adapt-scan.mjs:25`；成文侧 `core/story/{appendix,context,delivery,language}.mjs` 经前四者间接读）。framework 的 `spec-loader.ts:15`、`check-plan.ts:21` 用 `yaml` 包（`framework/harness/node_modules/yaml`，`package.json:46`），流式写法对 framework 合法。car 实跑：plan 门禁一次列出 27 处流式写法，作者逐条改写 `contracts.yaml`；步骤 0 评审 §3 第 2 条与步骤 2 用 `flowStyleProblems` 补偿而非解决。

**演进史**：yaml-lite 2026-08-25（0d09f597）作为「只覆盖实际用到子集」的最小读取器进来，同一文件头记着两条实测事故纪律（CRLF 分行、缩进不假设两空格、解析失败必须响亮）；09-07 两次补合法形态（bedb4d4b 块标量、ae4a3f9a `- |`），提交正文自己写「读取器的局限于是变成了作者的限制」。两周内三次为合法 YAML 打补丁，第四次就是本轮的流式映射。换成 framework 同一解析器后 CRLF 与缩进两条纪律由 `yaml` 包承担，「解析失败响亮、不吞成空对象」这条纪律保留在新封装里。

**替换**：新建 `hooks/shared/yaml.mjs`，导出 `parseYaml(text)`，签名与现在的 yaml-lite 一致，六个调用者不改调用方式。依赖解析在模块加载时做一次：从 `yaml.mjs` 自身的 `import.meta.url` 向上找到含 `framework.config.json` 的目录作为工程根（扩展目录可配置，但一定在工程根之下；不用 cwd、不用全局变量、不要求调用者传根），再以 `createRequire(<根>/framework/harness/package.json)` 取 `yaml`。找不到根或找不到包时在**第一次 `parseYaml` 调用**处抛错，文案给出可复制的命令 `cd framework/harness && npm install`，不退回旧读法，不在运行期下载，不做「有就用、没有就下」的双路径。解析失败抛出 `yaml` 包的原始错误（带行列）。

**耦合条件与失效行为**（用户 2026-09-16 定）：本封装依赖的是 framework 在 `framework/harness/package.json:46` 声明的 `yaml` 依赖（当前装的是 2.9.0），不是 harness 内部实现；framework 升级换掉或大版本升级该包时，扩展只用 `parse` 一个入口，2.x 内不受影响，换包时由 framework 升级说明触发本封装同步。「确保有包」放在安装期：`story-adaptation` 装扩展时检查 `framework/harness/node_modules/yaml`，缺则明确提示先装 harness 或由安装器代跑一次安装（安装器改动不计入机制预算）。离线夹具在测试域解决（见 03 §6）：至少六个套件把扩展拷进临时根再起 node（`test_knowledge_use.py:71`、`test_empty_knowledge_repo.py:47`、`test_author_task_package.py:124`、`test_image_registration.py:93`、`test_author_context_entry.py:88`、`test_adapt_ownership.py:58`），临时根没有 `framework/harness`，按上述规则必抛错，所以要有公共 helper 在临时根建 `framework/harness` 指向真实目录的 junction。开工前复核：把扩展 `copytree` 进临时根的套件共 18 个（`grep -l copytree test/story/tests/test_*.py`），不止六个；其中起 node 走到 `knowledge.mjs`/`contracts.mjs`/`verifier-report.mjs`/`knowledge-use/document.mjs` 任一条路径的都会抛错，以 R1 落地后离线全量的实际失败为准逐个接 helper，不预先猜名单。安装期检查的落点是 `adapt-scan.mjs --apply`（它就是安装器，SKILL 第 56 行）与 `--check`：核 `<目标根>/framework/harness/node_modules/yaml` 存在，缺则提示先在目标里装 harness。

**退出**：`yaml-lite.mjs` 整文件；`contracts.mjs::flowStyleProblems` 及 `plan/post_check.mjs:237` 的调用；`hooks/plan/author.md:52`「扩展只读块式」一句；`test_knowledge_protocol.py` 中针对流式拒收的用例；`1.9.2.md` 里对应说明改为「与 framework 同一解析器」。**保留并迁到接替者**：`test_yaml_lite_scalars.py` 锁的是「同一个值的几种合法写法读出来一样」（adapt 靠 `name` 相等判来源），改为指向 `yaml.mjs` 后原样保留，并成为四类样本深相等比对用例的落点。

**验收**：framework `contracts-template.yaml`、1.9.1 car 的 `contracts.yaml`（含 `- { name: … }` 写法）、当前 `knowledge-use.yaml` 骨架、任一 verifier 报告里的 YAML 围栏，四类样本用新读取器与 framework 侧 `YAML.parse` 得到深相等对象（写一条离线用例直接调 framework 的解析器比对）。中文键、锚点、流式映射不再产生扩展侧报错。

## R2 `resource_keys` 按公共合同消费

**现状**：`framework/harness/scripts/utils/types.ts:313` 定义 `resource_keys?: Record<string, Record<string, ResourceEntry[]>>`；扩展 `contracts.mjs:100-111` 把它与 `files` 同样当平铺数组，用 `n.includes(target)` 匹配；`obligations.mjs` 的 `push()` 同样按数组遍历。car 实跑作者先满足一边再修另一边，最终把 RES/DLV 义务挪到 `files[]` 才闭环。

**替换**：`contracts.mjs` 新增 `resourceEntries(contracts)` 返回 `[{module, category, key, node, ref}]`，`ref = resource_keys.<module>.<category>.<key>`；模块与分类来自实际键，不硬编码名字。`obligationsFromContracts` 遍历它读 `node.must`；`misplacedMust` 对挂在模块层或分类层的 must 点名；`resolveEntityRef` 对 `resource_keys.*` 用完整 ref 精确匹配，key 含点也按整串比。缺 `resource_keys` 返回空；形状不是两层对象时报具体模块/分类。

**退出**：`contracts.mjs:106-111` 的模糊分支对 `resource_keys` 的适用；`templates/plan-sections.md` 与 `hooks/plan/author.md` 里 resource_keys 的示例改为块式两层结构。

**验收**：夹具含两个模块、各两个分类、其中一个 key 带点；每条 must 都被派生且 ref 唯一；挂在分类层的 must 被点名；参考截图不因 visual-parity 告警被列成运行资源的规则写进 plan 作者页一句（语义归 verifier）。

## R8 写作单位与改章边界

**现状**：`story-write.md:206`「已经写好的章不要重写」无限定；`:8/:321/:330` 又要求回看后改草稿重提；`drafts.mjs:87` 头注只给本章。C16 首次骨架成为事实上的成文边界，核心内容下沉附录。

**替换**：story-write 写章节改为：先从当前来源与决定里认出一条完整业务关系（条件、行为、责任、结果、例外、未决），把它讲完整的那一章和需要重现的章一起写或改，再逐章 `chapter` 提交；**登记前**任何章可重提（`chapter` 原子替换已支持），**登记后**只经 `reopen`（`refuseIfFrozen` 已在）。drafts 头注加一句「写本章前先读已写章与本章共用的关系」，不加字段。

**退出**：:206 绝对句；「十章各自重建理解」的表述。

**验收**：提示层里改章路径只有两条且与 `context.mjs::refuseIfFrozen`、`rounds.py::cmd_reopen` 一致；真实产物副本上重提已写章成功、登记后重提被拒并指向 reopen。
