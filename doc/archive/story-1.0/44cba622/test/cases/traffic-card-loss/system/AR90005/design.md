# AR90005 挂失后的补卡申请（钱包端）

> 本单与 AR90004 同属 SR90004，由另一位开发承接，本文件只作交接对照。

补卡在旧卡冻结成功之后开始：收集补卡地址、确认费用、创建补卡订单，随后跟踪制卡进度、
处理支付中断与领取通知。它读 AR90004 交出的 `freezeTicketId` 与最终冻结状态，
不复制冻结实现、也不改写冻结结果。

- 没有有效 `freezeTicketId` 时不能创建补卡订单；
- 订单确认前不扣费，取消填写不产生费用；
- 订单创建成功后清理共享挂失上下文，旧卡继续保持冻结；
- 支付中断从既有订单继续，不重复建单；通知失败不撤销冻结或制卡结果。

联调与正式开放被 AR90004 的接口与共享上下文清理能力阻塞。
