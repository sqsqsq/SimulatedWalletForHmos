# A04 来源直接进入原生设计，退出旧交接仪式

## 1. 输入与结果

依A03来源库存/人答、实际业务范围、原生组件上下文、参考01§3和component-design Skill。结果是新需求/续行以实际来源直接进入原生设计；不用bind-design、五段提交稿、design-input或重复冻结包，来源可信性与原权限不退。

## 2. 首次设计和续行

1. routing从真实材料/会议/范围关卡派生设计可开始；缺影响本次工作的资料或人答按原权限处理，可选未来缺件不一律阻断。来源库存可直接读取，不先生成complete状态。
2. 调用原生component-design，给本次目标/终点、已确认范围、来源版本及人答。组件身份由原生设计从工程上下文确定，blueprint_id取需求根身份；无完整canonical仍可按原生草稿路径开始，不造空canonical/默认组件过门。
3. 外部系统按原生source materialization规范化，本地/直接人工按原生直接输入。模型只形成一次必要scope item语义，工具据索引填真实路径/摘要/来源权威；不另写采用集合、人答标识和五段稿再相互对账。原生信封如需落盘放blueprint内，内含引用而非第二套原件复制。
4. 原生校验来源并建立current_scope_items/traceability，走设计、独立质询、调和；已存在canonical沿原生查看/继续，不能重复创建。完整交接是否准备CU由本次请求决定，纯业务零CU可用；本步不授权施工。
5. status从当前来源/蓝图/本地Story登记派生next。设计实际消费的是current_scope_items绑定的字节和版本，不拿“已调用工具”或源清单数量证明设计采用。原生设计变更由原生版本承担，不另写Extension revision。

## 3. 接口、状态和文件动作

flow schema5→6按参考01：业务轮次/人答/授权和Story登记保，退status=complete、input.snapshot_*、design_binding、DESIGN_DRAFT强制输入及after_complete语义。`cmd_story`不再要求complete字段，而按当前来源/业务范围/真实设计参考及审查条件判是否可登记；真实完成时刻与usage保持，不因去字段放宽实际完成。

删除`flow/submission.py`的bind-design/候选五段/complete分派；其中必要原生来源校验并入设计前现有来源读取职责，不换一个强制新提交命令重造仪式。`materials/frozen.py`在没有活动消费者后退出，保原子存储能力由A03版本管理承担。`story_flow.py`命令/帮助/参数，state/routing/check与flow/rounds.py的cmd_round/cmd_reopen、decisions/asks关卡适用性，phases/design/ar_design_init/SKILL的旧next与作业说明同改；初析作为必要分析可以保，不再作为强制冻结产物。

所有直接消费者一起改：`design-source.mjs`、`sources.mjs`、`chapter.mjs::designInput`、`story-build.mjs`的skeleton/登记前置、`flow/check.mjs`、`review-object.mjs`、`reader-review-task.mjs`、`knowledge-task.mjs`/framework-access的blueprintSources/readFrozenInputs、storyReviewVisual、update的registered_input_stale、生命周期成文登记及状态查询。来源读原生声明＋材料索引；图面入口继续用真实原文/原图及原生能力，不读已删snapshot_ref。保原生consumption/当前引用与实际已读对象；只清属于旧交接的数据，真实业务decision/报告绑定不可误删。

旧input_sha依赖改为从实际采用来源集计算的source identity，蓝图ref仍精确；库存新版本是否影响本轮由update分析，不自动把全体未采用材料塞入设计。新增/修改人答按其语义适用性处理，原人答不重复批准。工作流状态本身的时刻变化不让已审业务稿无故过期。设计后新增材料不自动重开范围轮；reopen按真实范围变化处理并保历史人答。usage等任何读取complete/input的直接消费者在本步同改事件来源，D02只做完整保持核对，不能留失效读取到D批。固定设计附件登记集合在C01撤常驻副本时同步切换，A04不提前删掉仍有消费者的交付附件。

## 4. 验证与完成

一条真实系统来源交接和一条本地直接来源路径核：无旧命令仍创建/继续原生蓝图，当前scope绑定真实来源和有效人答；本地无多余provider文件要求；图与正文在sources原位；同请求不重绑/重复造版本。来源缺失/摘要错误由原生反馈，不自动改哈希放行。

核旧在途schema明确拒绝当前格式消费、正常新任务不要求迁移；已成文后材料/人答变化保原记录并进入正确update，不能去掉complete后把保护全部删掉。独审源对象、视觉裁定、知识上下文来源和CU未来交接都不引用旧冻结包。fixture移除bind/complete预填，L2走真实新生产者，L1只验证独有局部合同。

保`test_requirement_source.py`、`test_flow_status_client.py`、材料/来源/视觉/闭环相关回归的能力断言，替换仅证明旧命令或字段存在的断言；同根真正混入施工产物仍按原生拒绝。真实语义/DSH结果留后续获准Case，不通过临时造PASS关闭本批。

交回给实际新建/续行来源链、状态前后、全部退场消费者与保护结果；批末合并A01—04证据做组合验收并送审。G650/X1150，旧原件/来源包/历史报告不删除、不计X；删除只核本版交付机制行。
