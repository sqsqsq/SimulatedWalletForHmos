## 2. 目标职责与正常路径

```text
取得原件/图片/会议 → 导入可复用来源版本 → 原权限下的材料/会议/范围决定
  → component-design直接取得来源与知识 → 设计/独立质询/调和
  ├─ Story自主写作 → Story业务独审或诚实未审 → 原权限下送审/交付
  └─ 请求需要施工交接：原生CU接受/readiness → Spec → Plan → 获准后Coding等
变化 → 取得与比较 → 回原件/人答/蓝图/表达的正确责任 → 同步相关CU与业务稿 → 必要复核/交付
```

纯业务请求可零CU；有CU不自动编码。普通设计草稿、业务送审、原生施工准入、普通完成、发布资格分别判断；不能用任一PASS代替另一种结果。范围内既有授权继续有效，只有真实业务/权限变化或原生确需条件才问人。

### 2.1 同根材料与设计

```text
doc/features/<需求标识>/
  sources/README.md             当前来源导航，不是另一份需求正文
  sources/inbox/                待导入原件
  sources/<材料名称与版本>/     原件、转换正文、images等
  sources/backups/              恢复责任材料
  AR/story.md、review.md
  AR/story-src/                 必要流程、人答、写作和来源索引
  blueprint/                   原生蓝图、评审投影与原生临时件
  <change_unit_id>/             原生CU及阶段产物
```

共享材料归sources，命名可读、来源索引直接可达。Framework原生Feature级`ux-reference`继续适用于CU自身视觉产物；根级旧位置不再固定。根和sources直接层不塞施工标志，用户原件按来源版本封装，原文件名不改；这同时解决inbox原件名为spec.md等误识别，不增加目录忽略补丁。

新原生支持显式工程内图片来源与引用。CU调用输入必须实际带当前原文和共享图路径，Spec视觉引用指向原图，不能把blueprint source_ref自动当作已进入requirement_source_files。不复制图给每个CU，不调用原生读取失败后悄悄改别的路径。该合同已有静态依据，撤回“必须先等Framework修复同根”的定论；实际装配/消费结果由A02—A04及B02取证。

### 2.2 来源权威与状态

导入负责原件/转换/图版本，流程只记录业务关卡与实际人答，原生current_scope_items记录设计采用，原生蓝图/CU记录设计版本。退出complete、bind-design、design-input与重复冻结包的流程地位；不保新旧并行格式，不迁旧在途。保必要原子写与旧字节，保有效人答，不能删快照模块便丢掉来源保护。

新接口字段、来源库存/采用分责、首次组件身份时序、CU原文/图片实际交接均在[目标接口§2—4](参考/01-目标接口与状态.md)。这些是实施决定，执行者可局部组织函数，不可另建来源/状态/兼容平台。

### 2.3 知识与五稿

知识原文在设计前送达；事实与适用性进入原生facts，真实取舍/豁免/未知进入decision/gap；义务在实际接口/模型/组件/资源和验收，角色在真实承担实体。CU继承设计目标，Spec说明行为和验收，Plan说明方法/协作/验证，Coding等消费实际义务。旧通用knowledge_application账本、全激活条目decision与强制decision-ID桥接退出，不以scope:file补丁继续旧模型。

Blueprint按原生组织设计与投影；Story自主完整叙事、页面五要素、技术摘要与可查事实；Review只承载真实裁决和人工区。共同设计不在CU重判，业务正文不全量抄知识。真实决策可使用原生conclusion，常规义务不包装为取舍。原生显示仍有差距时按真实结果归因，不能手改签名投影或另造renderer。

阅读要求全部保持：图＞表格＞列表＞章节＞文字；同节分场景；图前导读、图后补充；标题概括主题；不逐箭头复述、不任意重编号。案例十章/§9恢复不是通用固定章数门。两组初段目标继续需要，update按现Case；本轮不重新改已确认业务、人答和模拟前提。

### 2.4 审查、更新和交付

蓝图独立质询负责设计，Story独立业务审查负责完整可读和设计一致，必要回查原件。没有Story审查员时派生诚实未审，所有登记/update/交付读同一结果；删除waiver及重新批准，已知FAIL/坏对象不可被未审覆盖。建议由作者采纳或有据保留，真缺陷修、变化后做必要复核。

当前处置沿原生读者，历史closed/回执不遮当前必修，软债务的普通完成与发布限制分别保留。update回正确真源；本地恢复只处理本轮确权派生件，原生完成成果不顺带回滚。系统归档保持授权、上传读回、外部冲突及失败续行；设计参考按真实合同交付，主业务读者不被要求再审技术副本。安装和usage/stats保持所有权与真实工作记录，不重开已技术关闭问题。

完整58项、R/AC及阅读要求分配在[验证映射](参考/04-验证与标准映射.md)，每步骤给实际预期。目标文稿、确定性、独立语义、正常DSH分别结论。离线沿L1/L2/L3，实际模型效果归L4；不建立全组合矩阵、关键词质量门或新runner。

只改接口的直接消费者在该步验证，批末一次组合handback；TEST节奏先按A01明确生效，不静默减少现行必需检查。Framework/补丁装配有变化必须有第二次真实空目录装配；全部必需离线准备、执行和记录计入≤180秒。既有提效专题的已接受成果按实际diff接入，未达标保功能/性能两个结论，不假签。
