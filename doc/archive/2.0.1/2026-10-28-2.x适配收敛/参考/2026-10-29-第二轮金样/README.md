## 三条链路看 Extension 怎样生效

| 知识输入 | 蓝图形成什么设计 | CU Spec 必须验什么 | CU Plan 怎样实现 | 后续 Coding 应做什么 |
|---|---|---|---|---|
| 安全与环境规约：身份分用途、保护持久数据、按环境变化恢复 | 业务账号与展示值分离；草稿按账号车辆保护；原请求先保存再发送，未知不能重建 | §9.1–9.2：不泄漏账号、换号不串稿、结果未知不重复创建，落到具体 AC | §5.1、§9.2、§10.2：ShareDraftStore 的保存／恢复／清理与仓储串行责任，及其验证 | 实际实现受保护存储和清理，控制旧会话回调；验证真正承担责任的代码，不写“已遵守”自证文档 |
| page-interaction 模式：等待用户或服务结果后继续的页内协作 | 设置页选用该模式；发起主链不选 decision-tree，管理页不强套 | §9.3：换对象重查权限，旧权限失效时重选，未知原请求只读 | §9.3：动作表、动作枚举、交互封装、上下文、页面组件五个角色及实际调用 | 按模式下篇落结构，页面经 doOperator 调用；角色实际参与运行，不能只建同名文件 |
| 上报项目事实与观察性规约 | §8：创建、接受、撤销各自成功口径；被接受比例归车云 | §9.5：未知与明确失败分开，同次重复回调不重计，查询不混入三流程 | §9.4：WalletHAManager 复用、逐点取值、三个结算方法与编号登记 | 接入真实结算调用、安全字段取值与去重；按适用测试和审查验证 |

“看到”由阶段知识入口送达原文；“理解”体现为蓝图中的适用原因和设计选择；“应用”体现在实际接口、状态、存储与角色；“传递”体现为 Spec 验收、Plan 实体责任和 Coding 的真实实现。这张表解释链路，不是新增产品表单或门禁。

## 情景与目录说明

- 继承既有整单钱包端范围：卡包卡片与入口、分享、接受、管理、续办及三流程统计。撤销由车云受理后车辆立即拒绝，48 小时只管设备卡片收回；点击失败或结果未知不等于受理。
- 模拟前提保持：API 12、设备 Asset 能力、完整草稿 UTF-8 不超过 1024 字节；稳定模拟身份及独立于钱包进程的模拟创建恢复。真实六接口没有等价恢复能力，正式接入仍有依赖。这些不是新增加的业务承诺或已验证事实。
- D2 再转第三人、D5 极端断网强制下线、D8 待接受撤回保持未决，原有效人答不改。四张参考线框与撤销关系图沿用原件，不代表新做了视觉验收。
- 所有展示产物位于 `doc/features/ISSUE-206/`，`blueprint/` 与 CU 同级。`wallet-key-sharing` 是本例选用的 CU 名称，一个 CU 承担钱包端完整工作；Framework 按候选的 `change_unit_id` 定目录，不固定这个名称。此布局说明目标，不声称已通过原生枚举。
- 当前 `blueprint/` 只有一份人读目标稿。`blueprint.target.md` 是维护展示名称，不是新增产品正式文件；真实产品仍用 Framework 原生人读投影。本包不放 `design-review.md` 副本，不要求另审第二份蓝图。

## 当前实现与目标的差距

| 状态 | 具体结论 |
|---|---|
| 已有接入代码与指令 | Extension 已登记蓝图知识入口及 Spec／Plan／Coding 等阶段的 story-knowledge、作者要求、检查与 verifier 规则；Spec／Plan 的宿主扩展仍在。代码存在不证明本次真实送达和效果已验 |
| 职责调整需明确 | 1.9.9 的共同知识判断主要在 Spec，模式由 Spec 提候选、Plan 选型；当前 2.x 将这些共同判断与选型前移蓝图，CU 承接。整体设计先于 CU 是原生分工；具体知识登记、选型路由与人读表达是 Extension 的适配选择，不是原生要求逐条造空取舍 |
| Extension 待收敛 | 无关知识展开、重复作者登记与人工批准等沿 2.0.1 Spec 处置；人读解释与下游承接一起修。首次金样淡化 Spec 扩展、重复 Plan 责任表属于制作错误，本轮已纠正，不据此要求产品追随错误样稿 |
| 需核 Framework 支持 | 固定 N 的需求根辅助目录识别与目标布局有已知冲突；原生渲染对 Extension 知识字段的展示仍有差距。目标稿不证明现版本可正常生成，需通过公共契约解决，不手改带签名输出、不新增影子渲染器 |
| 旧附件安排 | design-review.md 是旧 2.x Extension 为需求系统归档复制的设计参考，不是 Framework 的另一种设计真源。本次仅从金样阅读区撤下，正式归档如何交付设计参考仍须核实际系统需要，不默认删除能力 |
