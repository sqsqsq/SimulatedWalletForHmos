# 是否提前进入 2.1.0

结论：**建议提前开展 2.1.0 的质量基线、成文/审查效果与成本这条工作线；不建议把整个 2.1.0 提前施工，也不以版本迁移替代 2.0.2 正确性收口。** 本稿为维护设计者建议，未改 2.1.0 规格、未授权其产品实施或真实 CLI。

## 1. 依据不只是题目相近

2.1.0 现行 R1《两 Case 金样与质量基线》要求先修金样真实语义再替换；《审核问题与修订合同》G04 已指出展示脱敏值不能承担接口身份，G05 已指出草稿/模拟承载跨产物决定不一致。这与 2.0.1 实跑的 SEC-01 和 D3 问题是同一条因果链。

R3《成文质量与图形表达》已要求来源在动作前送达、同一事实跨产物一致、根因及影响面一起修、减少重复查询/无效派审，并提出六类 SVG 的有据选型。R4 要求按实际终点、相同质量、独立语义与成本证据判断，不以结构通过代替效果。这些目标恰是 2.0.2 机械改造完成后仍缺的评价和优化。

R2 则是另一个交付目标：机制/knowledge/adapters 三目录、Demo 唯一维护源、统一 `/extension materialize`、退出独立 adapt；它还有原生扩展接入依赖。它不能解决当前正文决策矛盾或审查质量，把它同时搬进来会扩大装配和发布变量。

## 2. 对 2.0.x 的反思

蓝图适配本来应保证原能力正确承接。2.0.1/2.0.2 已延伸到产物粒度、完整派审、来源展示与成本，这些有必要，因为原链实际不成立；但若继续把所有“更好读、更少 token、更稳定”的优化都留在适配收口中，2.0.x 会变成无终点的质量重构。

相反，尚有原报告恢复死路、错误格式门、失效运行消费者，就直接进入新版本，会将确定性缺陷混入质量对照，无法判断新方案有效。版本边界应依性质划分，不依“还有多少文件未改”。

复制原生设计投影为附件解决完整设计可取得，不自动解决整体文档人读体验。近期讨论已明确两者不能混同；该效果差距应纳入提前的 R1/R3，而不是在 2.0.2 再追加一个大型叙事生成系统。

## 3. 建议的责任分界

| 工作 | 归属/时机 | 原因 |
|---|---|---|
| 本次评审 R1–R3、正常 Spec→Plan 机械承接、已授权的来源/恢复/发布正确性 | 2.0.2 收口 | 原流程正确性，不能转成未来优化逃避 |
| FW-01/02/04/05 实际接入及其未验范围 | 延续原责任单独记录 | 外部等待不阻止独立质量设计，但不能标适配全完成 |
| 两 Case 的正确内容与人读产物基线，含整体设计、需求叙事、CU 局部方案 | 提前做 2.1.0 R1 | 先有共同可审的期望，再判断模型是否达到，避免按当前错误产物立标准 |
| 作者任务/独立审查输入、按决定修影响面、重复送达和表达组织 | 提前做 R3 的相关部分 | 以现有 2.0.2 实现为基线修真实差距，不重复建 dispatch/材料键/状态 |
| 质量合格前提下的时间、token、人工动作与返修成本 | 与上述共用 R4 | 统一评价，避免一次测试按两个版本重复解释 |
| 六类 SVG 指导及优先场景实证 | 在正确内容基线上依 R3 推进 | 不先靠换图形掩盖关系错误，不预设 SVG 必然节省成本；不要求和所有适配项同日完成 |
| 三目录迁移、统一安装入口和 adapt 退出 | 保持 R2 独立依赖与实施批次 | 与当前交付质量目标可解耦，不为提前版本一次全部开工 |

## 4. 前移前必须更新的事实

2.1.0 总览仍以 `11ea5105` 及 2.0.0 方案为当前进展参照，并引用 2026-09-30 的通用 Markdown 审查问题作为独立文档审查依赖。2.0.1 已退出该选型，2.0.2 已实现 Story 专属 dispatch/报告合同；不能重新申请代码审查变通或重复实施已有能力。

若用户采纳前移，先形成一份当前差异与交接：继承有效 R1/R3/R4 目标，标明 2.0.2 已有承担者与消费者；用当前证据替换失效技术前提，保留历史结果不回写。金样从真实来源修订，不能把 2.0.1 错误原件直接升格；也不能因 2.x 增加了附件就要求每份金样全文复制蓝图。

这一步是新工作线的开工合同，不自动重写 2.1.0 已多次调整的整套规格。需要实质性重写时按用户级 AGENTS 单独说明范围并取得确认；不能把用户本轮“反思是否前移”当实施授权。

## 5. 建议推进顺序

1. 2.0.2 执行者收敛本次局部缺陷并补正常阶段机械验证，保持现有工作区。
2. 可同时由设计者准备 R1 的期望产物与语义差异，优先让用户能判断 Story/Review、整体设计表达及 CU Spec/Plan；不先引入新产品机制。
3. 差异审定后，为 R3 的必要调整给出当前源码落点、退出内容和正预算；不挪版本重置 G/X/B/A。
4. 必要依赖及装置条件成立、用户授权后，用一轮正常需求实跑同时核适配保持与 R1/R3 改善；每项结果按实际范围归属。不能用“合并验证”省掉必要输入/独立审查/未验证披露。

这允许提前进入真正解决输出与执行成本的工作，同时避免要求先发布一个效果尚未成立的 2.0.2，或一次打开分发、图形、语义、原生接入全部变更面。
