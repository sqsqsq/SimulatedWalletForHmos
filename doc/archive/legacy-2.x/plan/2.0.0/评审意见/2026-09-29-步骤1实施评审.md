## 2. 必须修正

### R1 / P1：CU 输入绕过当前阶段的原生解析

位置：extensions/hooks/shared/framework-access.mjs 的 readFeature（89–142，特别是 121–124）；knowledge-task.mjs:featureTask。

readFeature 没有 phase 参数，CU 总是 deriveBlueprintSkillInput，平铺直接 SpecLoader。它没有消费阶段已解析输入及其 binding，也没有执行当前原生输入选择。“不冻结范围”不能推导成“跳过只读 resolver”；resolveCapabilityInputs 的读取和 ensureFeatureExecutionScopeFrozen 的写入是不同职责。

复现：在真实夹具中原生物化 CU 契约，再改变该本地契约字节。调用原生 coding resolver 得到 state=invalid、detail="blueprint projection stale; return to design owner"；同对象的 Extension readFeature 却得到 contracts.state=resolved，并交出重新从蓝图派生的旧内容。原生明确拒绝的本地输入被绕过。

修正：恢复总览合同的当前 phase 输入。hook 已有 resolvedInputs 时消费同一份；命令行通过对应原生只读入口取得实际输入、来源 binding 和错误。artifact 优先级、复用、过期与 invalid 由原生决定，Extension 不自行用 derive 回退覆盖。缺 scope 返回真实准备责任，不替原生冻结。

验收：有效本地契约、合法蓝图派生、过期本地契约、缺必要输入和自定义 features_dir 均与原生结果一致；坏当前输入不能借另一来源变绿；读取前后不新增 scope、报告或回执。

### R2 / P1：必要输入缺失或损坏仍成功输出任务

位置：framework-access.mjs:readFeature 的 status/shape_issues；knowledge-task.mjs:featureTask（102–135）及 knowledgeTask/CLI 输出。

独立复现两例：

- 不存在的普通 Feature 请求 action=coding，退出 0，输出约 23KB 任务，直到末尾才提示契约 absent。
- 已存在 Feature 的 contracts.yaml 写 `files: wrong-shape`，仍退出 0，输出“契约里没有知识义务”及完整作业任务。

第三例是 CU 的 contracts.state=invalid，任务仍退出 0。原生 missing/invalid/shape 错误被当成普通说明，违反“所需来源缺失退出 1、stdout 不给半份”的合同；还会让错误输入看起来等同合法空义务。

修正：根据本动作原生必需输入与其实际错误分类失败；TaskError 退出 1 且 stdout 为空，stderr 交对象、缺口与责任。蓝图 discovery 允许尚无蓝图、Spec/Plan 可补其负责的内容等已约定正常路径继续保留；不把所有动作硬要求完整后继契约。必要输入坏/失效不能仅列在成功任务末尾。

验收：上述三反例失败；合法空知识/空义务、前蓝图 discovery、无后继契约但当前设计动作合法的用例成功。pre_verifier 中相同读取失败也须如实留下不可据此完成依赖判断的结果，不被展示成当前有效知识。

### R3 / P1：安装预检没有校验待安装 manifest 的引用

位置：test/scripts/publish_to_demo.py:_plan（103–138），entries.mjs:entryPlan；对外 adapt 的合成 manifest 预检同步审计。

复现：复制当前源包，只把 provides.knowledge 改为不存在的 knowledge/not-present.md。dry-run 返回 planned；实际安装先替换目标扩展、完成 118 项写入，之后 native materialize 才报 knowledge_missing，返回 write_failed。目标原来的可用包已经被替换。

修正：源/合成目标 manifest 的合法性和实际交付引用在替换之前核对，使用原生 schema/现有解析能力；至少覆盖已声明 skill、hook、overlay、asset、维护全包知识路径及绑定。只有目标可写性等写入期错误才走部分失败。对外 adapt 按合成后的目标知识登记和目标文件验证，不能拿 Demo 知识覆盖或替代目标，也不读取知识正文作适用性判断。

验收：缺引用、非法字段/绑定的源包在 dry-run/apply 都 preflight_failed，安装面字节不变；未提交的合法源文件仍进入安装面；目标知识保留。无需增加备份、安装事务或新的恢复系统。

### R4 / P2：原生物化中途失败丢失已完成宿主写入

位置：entries.mjs:entryMaterialize（156 行调用后才计算 written）和 CLI catch；publish_to_demo.py:install_extension（166–172）。

复现：源包新增合法 extra Skill，目标 CLAUDE.md 设只读。安装返回 write_failed，`.claude/commands/extra.md` 已存在，但 completed 中没有任何宿主写入项。原生抛错跳过了前后字节比较，CLI 仅 stderr；调用者无法知道已改了哪些入口。

现有 test_a_write_failure_reports_what_was_actually_done 只核 completed 中的路径存在，没有核实际写过的入口都被列出，因此漏测。

修正：在共享物化责任处捕获异常后仍核本次覆盖面的前后字节，返回真实 written/removed、失败项和原始错误；维护安装和 adapt 同样消费。保持明确非零，不回滚、不留持久安装日志。

验收：后段根入口失败时，先前新建/改写/删除的宿主入口均在结果中；未变字节不计写入；原始 I/O 错误保留；错误未发生时幂等结果不变。

- 同名 CU 测试只测“另一蓝图不存在”，不足以证明两个合法蓝图都有同名单元时不混用；返修补两个真实存在对象的正例。
