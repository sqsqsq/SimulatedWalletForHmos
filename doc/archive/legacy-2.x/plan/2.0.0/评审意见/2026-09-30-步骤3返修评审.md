## 2. 剩余问题

### F1（P1）：coding 探针去重仍按裸编号，吞掉另一来源的阻断

位置：extensions/hooks/coding/post_check.mjs 的 reported 集合，键仍为 `${ob.rule}|${r.ok}|${r.detail}`。

独立反例：两个已激活知识文件各有 NEU-01，各自有真实来源摘要与不同 decision_id；第一条强制力为基线，第二条为红线，均要求同一方法满足相同阻断探针。实现不满足两条。当前返回 ok=true，只留下第一条基线告警，红线因“同编号/同结果/同文字”被去重。不是知识无效，也不是 Framework 问题，是旧的裸编号身份假设没有迁完。

修正：去重键包含决定身份或来源文件+单元，保证不同决定、不同强制力的处置都执行；同一决定重复扫描才可合并。相关按 rule 分组/回查的消费者同步核身份，不以显示编号代替决定身份。最小回归保留同一输入，交换两条义务的顺序结果仍须阻断；不同来源不能互相遮盖，同一决定重复结果仍可去重。不新增通用去重层。

### F2（P1）：部分提前返回丢掉原生输入错误

位置：coding/post_check.mjs、review/post_check.mjs 的无契约、无义务、无实现/报告等提前返回。正常末尾带 inputs.problems，部分提前出口只有 skipped。

独立探针：对不存在的 Feature 调 coding，phaseArtifacts 已报 feature_missing，门禁却返回 ok=true，只在 promptFragments 说该判据没执行。原生错误不能在同一消费者里被降成非阻断提示。

修正：所有出口都保留当前输入的原生 problems；无义务等合法不适用仅在原生输入成立时成立。直接在现有 gate 参数/共同出口处理，保留已有一次报告完整问题的方式；不用增加重试、fallback 或错误状态系统。补缺对象/失效输入不能被提前返回吞掉的反例，同时保持合法无义务输入不阻断。外层 Framework 可能另报失败不代表这个 hook 可自报通过。

### F3（P1）：无 plan.md 的埋点送达仍丢正文

位置：hooks/shared/stat-points.mjs:statDelivery。它把蓝图明细转成 title/id 和统计点名称，丢掉 body 的其他列与正文；验收也只取 description/expected/scenario 中一个值。作者和 plan 审查共用这份不完整材料。

独立输入的 event body 包含“失败原因必须保留”以及“成功、拒绝”两类结果；输出只剩“保存结果”这个统计点名，条件和结果均不在返回里。审查任务随后要求对照适用结果逐点判断，实际却没送到这些依据。

修正：statDelivery 并列原生设计已形成的完整 event body、实际方法说明与相关验收完整条目（含可用验证字段）；保留可回查的设计身份/地址，不让读取器自行摘要业务内容。表格一致性在无 plan.md 时可不适用，原始义务不能随之缺席。直接复用现有对象和 Markdown 原文输出即可，不加新文件、状态或语义匹配器。用上述含附加条件及多结果的合法明细核作者/审查实际任务，而不只断言标题存在。
