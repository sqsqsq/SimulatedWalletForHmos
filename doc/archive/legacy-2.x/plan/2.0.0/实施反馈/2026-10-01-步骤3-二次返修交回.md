> 读者：2.0.0 方案设计者。时机：复核[步骤 3 返修评审](../评审意见/2026-09-30-步骤3返修评审.md)的 F1–F3 之前。
> 起点：返修评审入库 `5a5c6c7e`。已接受的 R1–R4 部分没有重做。

## 1. 逐项处置

### F1 coding 探针按决定身份去重

- `hooks/coding/post_check.mjs`：探针结果的去重键从「规约编号 + 结果」改为「义务出自的判断（`decision_id`）+ 结果」。
  同一判断挂几处、扫到同一结果仍只报一次；不同来源的同编号规约是不同判断，各按自己的强制力处置。报文里加上「出自判断 <id>」，
  两条同编号的结果能分清是哪一条。
- 其他按编号认义务的消费者核过：plan、ut、testing、审查任务的义务表已经按 `decision_id` 认；review 门禁的强制力按每条义务
  自己的判断取，同一行「未落实」对红线那条照样阻断，不存在遮盖。复核表的行仍按「rule + 落点」认（`review/author.md` 定的表形），
  没有改表形。

### F2 每个出口都带原生输入问题

- coding、review、ut、testing 四个门禁在取到本阶段输入后立一个共同出口 `done`，把 `inputs.problems` 并进每一次返回：
  没有契约、没有义务、实现文件未建、报告未生成、激活知识读不出等提前出口都经它。原生输入有问题时这些出口都阻断；
  原生输入成立、只是没有义务时照常不阻断。spec、plan 用分组出口，原本就单列「原生对本阶段输入报的问题」，没有提前出口，未改。

### F3 没有 plan.md 时埋点原文送达

- `hooks/shared/stat-points.mjs`：`designStatPoints` 的明细带上完整正文 `body` 与依据 `evidence_refs`；`statDelivery` 改为并列三份原文：
  1. 落在本单位的每条埋点明细：标题、`id`、依据地址，正文照录（含附加条件与统计点表）。
  2. 契约里有说明的每个方法：`interfaces.<接口>.<方法>` 地址与 `description` 原文。
  3. 验收 `criteria`、`boundaries`、`performance` 的每个条目：`id` 与其余全部字段照录，包括 `verification_steps`、`expected_result`、
     `ut_layer`、`device_focus` 等验证字段。
  哪些条目相关由作者与审查判断，读取器不挑、不摘要。作者（知识任务）与 plan 审查任务都用这一份。
- `hooks/plan/author.md` 的精确明细一行补上：这一次没有 plan.md 时，统计点、适用结果与验证方式写进承担方法的 `description` 与相关验收条目。
  作者在动手前就能看到，不用等审查任务提示。

## 5. 请设计者裁定的发现

原生契约里接口的身份字段是 `class`：`demo/framework/harness/scripts/utils/blueprint-skill-projection.ts:114` 要求接口有 `class/file/methods`。
测试夹具蓝图派生出的契约也只有 `class`，没有 `name`。扩展里有几处只读 `name`，拿到的就是空名：

- `hooks/shared/obligations.mjs` 的 `name()`：义务落点成了 `interfaces..refreshBalance`，review 复核表按它认行，coding 按它取末段。
- `hooks/plan/post_check.mjs:83` 的已声明方法集合 `${i?.name}.${m?.name}`：plan.md 逐点表的责任方法写 `HomeRepository.refreshBalance` 会被报找不到。

实跑证据：在 `test_cu_knowledge_chain` 的冻结工程上取 plan 审查任务，义务落点显示为 `interfaces..refreshBalance`，
同一份任务里 `statDelivery` 给出的是 `interfaces.HomeRepository.refreshBalance`。第二处按代码读出，没有单独跑。

`hooks/shared/contracts.mjs` 的 `entityName` 已经按 `name → class → …` 取。本次只在 `statDelivery` 用了同样的回退，
上面两处不在 F1–F3 范围内，没有改。建议统一改成与 `entityName` 相同的取法，并补一个派生契约上的逐点表与复核表用例。
