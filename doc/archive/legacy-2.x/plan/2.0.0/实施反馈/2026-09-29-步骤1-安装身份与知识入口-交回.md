## 5. 需要设计者复核的实施选择

1. **demo 遗留跳板**：`.agents/skills/story-adaptation/SKILL.md` 由 3.0 生成、没有归属标记，也不在 1.9.8 的登记中。按「只认可证明的旧发布源」的规则，安装在写前停在它上面，模板因此装配不起来。用户裁定在 demo 删除，安装规则不变。
2. **写后核对容忍 F5**：chrys 与 generic 共用 `.agents/skills`，原生总会把其中一方判为 stale。核对规则定为：同一路径至少有一个宿主判为 present，且没有 missing、unowned、drifted、orphan，就算通过。已按规定不改 vendored 标记。
3. **name 规范化**：manifest 1.1 要求小写 slug。首装时把 project_name 转成 slug（例如 BizA → biz-a）；升级时 name 归目标所有，若不合规就在写前停，不替目标改名。
4. **framework-access 的 feature 动作**：CU 用原生派生，平铺 Feature 用 SpecLoader；只报告范围是否已冻结，不调 resolveCapabilityInputs 启动阶段解析（按总览 §4「缺 scope 返回待原生入口准备」）。
5. **knowledge-task 的受众语义**：Feature 阶段按 manifest 语义发送：字符串登记给所有 Feature 阶段，对象登记给 global 或列出的阶段。蓝图的设计动作发送全部登记，相关与否由模型按「何时读」判断。
6. **pre_verifier 的材料量**：审查者任务包含完整知识原文，按 demo 当前 13 份知识约 750 行，verifier 的审前材料因此明显变长。步骤 3 会重写各阶段审查的真源，是否在那时收窄，请设计者定。
7. **A02 夹具**：已改为 2.0 形态，夹具目标的入口由被查工程的 Framework 当场物化。因此对 demo（仍是 1.9.8）跑失效形态时，A02 会失败，直到 2.0 发布。开发期按步骤 4 对装了开发版的隔离 template 跑，结果为 62 条、FAIL 0。
8. **A03**：hooks 下允许 author.md 与 reviewer.md 两种要求页，行数与段落上限不变。
9. **预算类别拆分**：由实施者按总览 §5 的组成拆分，见 §6；类别完成上限暂时等于峰值，待复核。
10. **根 AGENTS**：§0、§2 的开发源说明与 §7 的维护安装协议已按实现修改；§6 第 5 步描述 demo（1.9.8）的接入处理，保留到发布时再改。
