# 步骤2：原生报告接缝与失效职责退出

承担 R05–R07。必读[架构调查](调查/01-架构与原生协作调查.md)、`extensions/hooks/shared/framework-access.mjs`、`verifier-report.mjs`、`pre_verifier.mjs`、Framework `harness/config.ts::featurePhaseReportsDir` 及原生报告协议。原生只读。

## 1. 报告路径回原生

`verifier-report.mjs::reportLocation` 不再拼 featureDir/phase/reports。在 `framework-access.mjs` 提供薄的内部报告目录函数，输入 projectRoot、原生 Feature 身份、phase，通过已有 loadNative 读取 `config.ts` 的 `featurePhaseReportsDir(projectRoot, feature, phase, frameworkRoot)`，输出原生绝对目录，消费者为reportLocation以及下述update只读观察，二者复用同一原生目录事实。函数名字及局部拆分由实施者定，不另登记 CLI action。

该目录下读取 summary.json，再按 summary.verifier_report 找实际回复；不自己展开 reports_dir_pattern，不复制 CU base64/path 算法。notes.md 仍属 Feature 阶段工作件，沿实际原生阶段目录规则，不因报告目录改变而搬它。

原生路径解析失败明确返回既有 gate 的问题结果，不回默认目录假装未派审。确实尚无 summary/尚未产生报告，继续由原生调度控制，不增加第二派审门；已存在却不可读或 JSON 损坏的 summary 是输入故障，不当“尚未运行”。只在该消费者区分缺席和坏输入，不批量重写 readJsonOrNull 工具和所有调用点。

### update同源读取

`flow/update.py::_unit_facts/_phase_facts`一并退出硬拼目录。既有`--action blueprint`增加可选`--report-phases <逗号分隔阶段列表>`，仅这个action接受；update把当前PHASES作为本次观察集合传入，并使用已有--summary。去空白、去重，空列表报参数错误；不在JS再维护一份阶段清单。

同次readBlueprint输出的每个活动单位增加`phase_reports`数组，每项为`{phase, dir}`（原生绝对报告目录）或`{phase, error}`（解析失败）。目录由已有phaseReportsDir调用原生生成，不解析pattern、不缓存阶段状态。没有此参数的普通蓝图读取不增加该字段；现有blueprint身份、准入和原生units结果保持。

Python改为消费该数组，每目录读取summary.json并保持原phase/readable/closure/verdict/subject输出。确实没有summary不列既有报告事实；路径解析失败或summary存在却不可读/不是JSON对象，给该phase的readable=false及原因，不降级空集。update仍只报告施工真实状态，不因进展阻塞文档收口，也不宣告施工完成。

实现只扩现有调用参数与返回的只读投影，不新增CLI action或通用调度，不为每个阶段启动Node。一个需求的update观察仍沿原有一次蓝图读取返回所有单位的路径。

## 2. 逐判据结构合同闭合

沿用现有汇总表四格 `id | status | severity | 证据`。在 `verifier-report.mjs` 复用已有 tableCells，定位含当前 overlay 判据的汇总表；无关表不计，当前判据每个恰好一行。核四格齐、status 为原生现行结果集合 PASS/WARN/FAIL/SKIP（见 summary.schema.json）、severity 是现行严重性取值 BLOCKER/MAJOR/MINOR（`harness/scripts/utils/types.ts::Severity`；INFO仅属于Story独立报告，不用于阶段协议）、证据非空。SKIP 的适用理由放证据栏，由语义审查判断，不以出现 SKIP 自动豁免义务。

表头取上述共享四列合同，使用已有Markdown单元格解析与装饰归一化；第四列明确接受`证据`和原生现行`证据（一行：文件:行 / 引文 / 数值）`两种标题（见verify-spec/verify-plan原生模板），不能以只认短标题拒绝合法原生报告。其余列仍按现行原生合同，不靠业务关键词猜列；只从合同表头之后的数据行取判据，不把正文提及ID或其它表的引用列算作结论。当前overlay每个ID跨这些汇总表合计必须恰好一行；允许同行表包含Framework自己的其它判据，其业务结果归原生校验。没有合同表、目标ID缺失或重复均报结构问题，不能任选一个表忽略冲突。WARN/FAIL仍要求notes中有该ID的既有处置记录；PASS/SKIP不新增notes审批，SKIP证据栏必须非空，理由是否成立由语义判断。

结构定义在现有 verifier-report 模块以局部常量/函数维护，pre_verifier 的请求引用同一结构说明；不建通用报告schema层。原生 subject、终态块内容、blocker计数及receipt仍由 Framework 校验，本仓不重新解释其完成结论。报告结构不合一次给全可确定问题，原文件不写；修复出口仍是交原独立审查者重新出报告。

notes 中出现判据ID只证明留了记录，不能宣称语义上处置完成；本步骤不另加处置状态机。证据内容是否充分不靠长度/关键词校验。

`pre_verifier.mjs` 收敛实际请求：全部 overlay 判据在四格汇总里给结论；非PASS按原生报告要求写明细，PASS知识核验方法写报告说明，不再要求第二份PASS checks。删除“裁多少行任意/不核判据全量”的旧注释，说明逐判据结构核对与逐知识条目语义核验是不同职责。现行 spec 不重新决定知识适用性，过时的“spec自己判”等职责注释同步退出。
