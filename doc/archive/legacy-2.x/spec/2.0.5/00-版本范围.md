# 2.0.5：人读蓝图交付后的 2.x 适配重新设计

2026-10-13建立；2026-10-18按用户新目标补齐范围。**2.0.5 是 2.x 重写的临时版本：以 story-1.0 的 1.9.9 正式发布源码重新起步，依据最新 Framework 3.1 蓝图能力重新分析适配。** 保留 story 分支全部历史、文档和有效成果。本轮只制定初步操作方案，新版 Framework 预计于2026-10-19推送，实际交付身份待核。

## 1. 目标与已确认决定

本版要在 Framework 补齐人可读的需求级蓝图后，重新确定 Framework 与 Story Extension 的职责、产物权威、成文协作和生命周期交接，使人能够完整理解和评审需求，使消费模型能够依据同一有效设计完成 CU 施工。

用户已确认：

- 将本次讨论记录在 2.0.5 spec。
- 在 2.0.5 取得 Framework 的 `blueprint.md` 版本，作为重新设计 2.x 适配的实际输入。
- Story 是否与蓝图合并、哪些职责迁移、哪些能力保持独立，进入本版设计讨论；本次记录不将建议自动批准为最终架构。
- 以1.9.9正式发布版本作为产品重写起点；将story分支的开发源重新同步到该基线，再按新版Framework合同实现适配。
- 保留story分支记录，将旧2.x有效内容按方案、源码引用或必要代码片段保存，选择性复用；不对旧提交作整批合并。
- 2026-10-18先整理准备、切换、设计和验收步骤，不执行产品替换。新版到位后再补齐接线决定和实现预算。

需求详情与讨论依据见 [蓝图与 Story 职责讨论](01-蓝图与Story职责讨论.md)。本版当前工作入口是[重写准备与适配总览](../../plan/2.0.5/00-重写准备与适配总览.md)；它替代“沿旧2.x继续补适配”的推进方式，不改写旧版本结论，不等于产品设计已定案。

## 2. 本版范围与版本关系

| 对象 | 本版工作 |
|---|---|
| Framework 新版蓝图 | 核实际发布身份、`blueprint.md` 与结构化蓝图的权威关系、作者及审查输入、扩展能力、修订与下游消费合同 |
| Story Extension | 重新设计其需求级叙事、知识应用、Review、图片资源、送审及 update 等能力与新版蓝图的协作 |
| 既有 2.x 能力 | 核已实现职责与实际消费者，明确保留、接替、退出及未解决问题，不根据文档名称推定能力已接替 |
| 验收 | 分别检查设计完整、人读效果、机器消费、独立审查、更新恢复、既有能力保持及成本 |

本版不把2.0.4的未完成验证或缺陷自动标为关闭。1.9.9正式发布中已成立的能力是必须保护的新起点，包括与2.1.0同诉求的已实现部分及1.x新增能力；不因它们原先登记在未来版本就丢弃或重复实现。2.1.0中未被发布基线覆盖的需求仍留原版，按能力逐项核归属后再同步受影响入口。

旧[2.0.4执行基线](../../plan/2.0.4/2026-10-11-职责收敛与最小实现/00-实施总览.md)保留为成果与问题来源，不作为此次重写的产品实施入口；[2.1.0现行范围](../2.1.0/00-版本范围.md)作为后续范围核对来源。今天本地story-1.0开发源为1.9.9，但demo仍装1.9.8，未找到1.9.9发布说明或标签；不能把分支最新提交自动当作正式发布。

## 3. 下一次设计的输入与交付

输入包括1.9.9正式发布身份及源码、新版Framework发布件及正式设计材料、替换前story的固定提交和工作区成果。维护设计者从发布清单、源码、合同和实际消费者核实，不仅根据开发者口头描述确定接口。

设计交付须明确：各类读者及其阅读任务；需求级设计与人读表达的责任；YAML/Markdown的编辑与权威关系；Extension在设计前、成文中和交付后的实际作用；变更、意见与授权裁决如何回到真源；下游CU如何取得有效设计；1.9.9能力保持、旧2.x成果复用和被替换机制退出。初步步骤已在plan给出，产品接口与逐文件实现待真实输入齐备后定案。

新版未交付或关键合同不明时，列明未知及影响，不猜 API、不修改 vendored Framework、不用局部文本插入冒充完整能力接替。合并或保留独立产物由用户依据方案取舍确认，实施者按有效方案实现。

## 4. 预算与完成边界

本轮准备工作产品G/X=0，不修改产品版本、demo、金样或旧版本方案，不启动CLI、模型评价、发布或推送。今天可做的盘点/保全准备和等待条件以[plan总览§3](../../plan/2.0.5/00-重写准备与适配总览.md#3-四步与推进条件)为准；用户后续已授权并完成[能力盘点、指定成果副本保全与测试迁移清单](../../plan/2.0.5/05-准备盘点与保全交回.md)。尚未取得正式1.9.9发布身份或新Framework，未执行装配及产品测试。

1.9.9同源起点先在scratch核字节，正式源码切换与最小适配、安装物化、测试装配形成可验证首包；首个修改extensions的重写提交按项目AGENTS §7升为2.0.5，满足适用检查后再交回，不单独提交错配混合树，不发布名为1.9.9的蓝图改造版。

实施方案制定前按 AGENTS §5 核实际基线与历史累计，估算新增、退场、净增、峰值及完成量。本版不批准新的增长额度，也不通过开版重置累计。

当前方案准备的完成条件是能力保持、成果可恢复、测试配套与首包边界明确，今天可做和待输入动作可区分；现状盘点和实际验证未完成的仍标未完成。后续适配不能只以blueprint.md出现或门禁通过判断；须按[讨论§6](01-蓝图与Story职责讨论.md#6-后续设计与验收要求)核实际使用结果、职责接替和旧路径退出。
