# 批次二：CU交接与更新交付

依据[产品总方案](../01-产品实施方案.md)§3/5/6。前提为批次一关键契约评审通过，保持其来源、知识和审查真源。结果是共同设计被CU真实消费，更新回真源后可交付和恢复。01→02连续，每步独立交回/提交，批末集中评审；不重置预算。

## 01 原生CU阶段与当前资格

**输入**：批次一设计、原生CU身份/design_refs、N1或后继已核构建的prepare/SpecLoader/disposition/attended run接口。

**动作**：

1. Spec-only/Plan-only按原生phase准备，已有runtime准备不重做；保冲突owner和合法增量。`framework-access`、`contracts`、knowledge任务及Spec/Plan gates消费同一解析结果，支持合法calls序列。保宿主扩展章节的原职责、必要编号和附录，不另加固定尾章。
2. 蓝图真实设计对象里的acceptance/must/pattern_roles经design_refs进入本CU；Spec说行为和验收，Plan说责任实体/方法/协作/verify，Coding及后续任务继续消费。规则/角色只写声明而无实体、或只有ID相同而业务条件不一致都不算传递完成。
3. 修预测文件白名单假设：普通实现位置调整保原义务，真实边界变化回原owner。保接口/数据/状态/资源的真实责任检查，不把所有文件都视作任意可改。
4. 既有原生访问桥加只读当前处置出口。阶段事实/update/usage用原生当前集合，不复制判定规则；历史closed、当前必修/待核、普通完成、发布资格分别展示。
5. 完整交付指令接原生attended run的prepare/next/report，复用已授权范围及active run；独立阶段不建完整run、不启动Coding。当前请求的run身份从原生上下文传递，不另存Extension进度或需求快照。

**保持/退出**：保蓝图权威、合法CU增量、知识verify责任、后续调用链与原报告。退出跨阶段私写投影、私有旧结论字段消费者、预测等于授权的规则及旧PASS/closed即当前完成捷径；旧未运行阶段不被补造。

**检查**：真实蓝图→原生Spec投影和Plan投影→扩展任务/gates至少一条L2；独立局部判据用L1。核Spec不写Plan件、原生冲突回正确owner、calls有序重复不丢、普通路径变化与真实越界区分。原生处置以真实绑定summary/缺口输入核旧PASS＋当前必修、缺必需检查、软债务发布阻断；不拿构造PASS冒充独立语义。Coding任务消费及实体/角色下游用既有定向回归，不启动模型编码。

**完成**：CU阶段与正常完整交付的入口分流清楚，原生事实读者在真实消费者处生效；三条知识链每层有实际要求和验法。G520/X650。

## 02 变化同步、系统交付与恢复

**输入**：01实际身份与当前性、现有update Case/回归、来源版本、系统adapter合同与原始人答。

**动作**：

1. update沿既有取得→比较→修订→同步→收口链。`registered_input_stale`按采用集/有效scope/人答/原字节核当前性，退提取稿依赖。新材料不替代未变人答；缺基准或读取失败不能当无变化。
2. 已有同范围授权续行，变化影响设计回canonical并原生更新/投影，表达变化在Story改。原生CU列表与当前处置决定已有受影响阶段的后续，未授权阶段不新建。清routing/update文案中的无条件再问和旧双根定位。
3. 本地update restore只回本轮确权派生文件，保后来人工内容/未知归属；已提交设计与完成CU保持原生事实，不能正文恢复顺带撤销。既有前后字节/ownership机制复用，不新增恢复协议。
4. 系统沿现有prepublish冲突检查、上传、读回和登记；远端已成功部分不重复，外部新意见保护。本地交付零远端。设计参考附件按真实系统合同携带原生投影，仍为参考，未审状态和必要阻断在所有消费者一致。

**保持/退出**：保来源/人答版本、差异说明、恢复与原备份、有效授权、上传失败副作用证据；退旧绑定状态读取、重复范围/材料确认、旧closed遮当前待核，以及提取稿过期专用判据。

**检查**：现有update Case四种比较结果和已有材料变化/外部反馈，关键一条真实生产消费链证明设计回源/CU刷新；既有恢复、人工区、远端已成功后登记失败重试、外部冲突回归继续。状态错误分别归数据/原生/外部，不扩成全异常组合矩阵。

**完成**：变更者知道改了什么与为何保持，后续读取当前义务，交付/恢复不丢人答或重复远端副作用。G470/X600。

## 批末交回

组合handback按当前协议一次完成；受影响测试迁移见参考，保退场证据及预算累计。真实DSH仍未运行时，交回明确“确定性组合成立/语义待实跑”，不宣称业务效果完整通过。

集中评审核CU正常路径和update链，阻塞身份/授权/证据/恢复错误先修；可独立处理的安装/usage保持进入批次三时说明依赖和已通过范围。原问题、原报告保留，不以新一轮名义清累计。
