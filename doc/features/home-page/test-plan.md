## 一、测试范围

### 测试模块

| 模块名 | 所属层 | 格式 | 说明 |

| WalletMain | 02-Feature | HAR | 首页 Tab 页 `HomeTabPage`、数据 `HomeRepository` 及子组件；宿主壳、底 Tab 为 Phone，本测试以「在壳内切到首页」为假设 |

### 测试功能点

## 四、测试策略

### 测试方法

- **功能测试**: 按上表对 PRD/acceptance 逐条在真机或模拟器上走查。  
- **异常与边界**: BD-1/2/3 在可行性下执行，否则在报告中注明**阻塞/基于评审**。  
- **UI/交互**: 对照 `design.md` 组件树，核对导航名与现实现。  
- **性能**: 首屏 2s、轮播 55 FPS 为 PRD NFR，本计划可**抽样计秒或目视**，不强制与自动化压测等效。

### 执行顺序

1. 先执行 P0 用例 TC-001…TC-006、TC-011、TC-012、TC-013、TC-014。  
2. 再执行 P1 用例 TC-007…TC-010、TC-015。  
3. 回归：缺陷修复后重跑「关联用例」及**关联公共路径**的 P0。

### 回归策略

- 与首页相关的缺陷修复后，至少重跑**对应 TC 及** TC-001、TC-002。  
- 若改动 `CommUI` Toast 或 `Phone` 导航，需与负责人确认**是否扩大回归范围**（本 feature scope 不扩模块修改）。

## 六、风险与依赖

### 已知风险

- 模拟钱包与生产 API/账号行为不一致，E1/E2 部分场景**需 Mock 或手工构造**。  
- BD-2（空数据）在仅 Mock 的构建上可能**不触发真实空列表 API**。  
- NFR-2（FPS）真机与模拟器差异大，**仅作目标参**。

### 测试依赖

- 可安装** Debug** 包；`navPathStack` 由 `Phone` 根页面提供，**禁止**在不知会团队下只跑孤立页面导致 BD-3 假阳性。  
- 依赖 **Skill 3/4** 已合入的 WalletMain 实现与**当前导航名** `CardPackPage` / `AddCardEntryPage`。

### 环境限制

- 无华为应用市场发布审查；不替代**合规/安全**专项测。
