# 运行模式适配

管新功能在钱包各受限运行模式下的可用性策略；每个需求都必须回答「本功能在这些模式下是什么表现」。

> 「出处」列指向上游 story 模板规约（HarmonyOS）的章节号；标「工程增补」者规约中无对应原文。「等级」与「判定方法」两列规约未定义，整列均为工程增补。

## 模式定义

四种模式取自规约 §3.4.1（原文：「是否支持游客模式、基础模式、未成年人模式，儿童账号」）；**「定义」与「判定入口」两列规约未展开**，定义为工程理解，判定入口待内网 API 录入。

| 模式 | 定义（工程理解，待内网确认） | 判定入口 |
|---|---|---|
| 游客模式 | 未登录华为账号使用钱包 | <待补充：账号状态 API/状态位> |
| 基础功能模式 | 用户未同意完整用户协议，仅基本功能（§2.1.1 要求功能点明确「全量功能模式 or 基本功能模式」） | <待补充：协议同意状态位> |
| 未成年人模式 | 系统未成年人保护开启 | <待补充：系统 API> |
| 儿童账号 | 账号本身为儿童账号 | <待补充：账号属性 API> |

## 条目

| ID | 条目 | 出处 | 等级 | 判定方法 | 例外条件 |
|---|---|---|---|---|---|
| MODE-01 | 游客模式策略已声明：功能入口在未登录态的表现（隐藏/引导登录/可用） | §3.4.1 | 红线 | spec 异常场景表或功能清单含未登录分支 | — |
| MODE-02 | 基础功能模式策略已声明：功能是否属「基本功能」，非基本功能须在该模式下不可见/不可用 | §3.4.1 + §2.1.1 | 红线 | spec 场景章节含基础模式声明 | <待补充：基本功能清单> |
| MODE-03 | 未成年人模式/儿童账号策略已声明：支付类、开卡类功能默认受限，例外须产品确认 | §3.4.1 | 红线 | spec 场景章节含未成年人声明 | 纯展示类且无支付触达 |
| MODE-04 | 模式切换时序：运行中模式发生切换（如协议撤回）的功能行为有兜底 | 工程增补（规约只列四种模式，未提运行中切换，待与内网核对） | 基线 | spec 异常场景表含模式切换场景 | 无跨模式状态残留 |

## 回显指引

应用域约束符合性表的「运行模式适配」行几乎不可能为「否」——至少 MODE-01～03 须逐条给出策略结论（可以是「全模式可用，因为纯展示且不采集数据」），证据写 `run-modes:MODE-01` 等并指回 spec 对应章节。
