# UX 一致性

管新增/改版界面在多形态设备与系统显示设置下的一致性；不管交互方案本身的合理性（那是 spec 界面描述的职责）。

> 「出处」列指向上游 story 模板规约（HarmonyOS）的章节号；标「工程增补」者规约中无对应原文。「等级」与「判定方法」两列规约未定义，整列均为工程增补。
>
> 规约 §3.2 的完整列举为：「产品有设计则需考虑的内容：**折叠屏、pad 等机型、智慧多窗**，同步考虑 UX 一致性要求 / **深色主题** / **显示大小** / **大字体**（含适老化特大字体）/ **维语镜像** / **多语言** / **无障碍页面播报**，适老化因系统暂无此能力暂不要求」——下表逐项展开，**「产品有设计」是这些项的共同前提**。

## 条目

| ID | 条目 | 出处 | 等级 | 判定方法 | 例外条件 |
|---|---|---|---|---|---|
| UX-01 | 深色主题：新增页面所有元素在深色模式下可读、色值走资源引用（`resources/dark/` 或 `$r('app.color.*')`），无硬编码亮色 | §3.2 | 红线 | 深色模式截图走查 + 检索硬编码色值（`#[0-9A-Fa-f]{6}` 出现在 .ets 布局中） | 无 UI 变更 |
| UX-02 | 折叠屏/pad 等机型/智慧多窗：布局用相对/栅格单位，展开态与悬停态不破版 | §3.2 | 基线 | 折叠屏与 pad 模拟器走查关键页面 | 产品无对应形态设计；或需求明确 phone-only 且产品确认 |
| UX-03 | 显示大小与大字体：文本容器可伸缩、不截断关键信息 | §3.2 | 基线 | 系统字体最大档走查；检索固定高度文本容器 | 无文本 UI 变更；适老化特大字体暂不要求（规约原文：系统暂无此能力，<待补充：复核是否已具备>） |
| UX-04 | 维语镜像（RTL）：布局方向性属性使用 start/end 而非 left/right | §3.2 | 基线 | RTL 语言切换走查；检索 `.left(`/`.right(` 布局调用 | 无 UI 变更 |
| UX-05 | 多语言：新增文案全部走 string 资源，无硬编码中文 | §3.2 | 红线 | 检索 .ets 中的硬编码中文字符串字面量 | 无新增文案 |
| UX-06 | 无障碍页面播报：交互元素有可播报语义（accessibilityText/Description），自定义控件可聚焦 | §3.2 | 基线 | 屏幕朗读走查关键路径 | <待补充：豁免审批流程> |
| UX-07 | 交互动效：涉及动效的功能点在 spec 功能点与实现方案中有对应设计说明 | §2.1.1 | 建议 | spec 功能清单/界面描述含动效说明 | 无动效 |

## 回显指引

应用域约束符合性表的「UX 一致性」行：需求无任何 UI 变更 → 「否 + 证据：spec Scope/界面描述无 UI 项」；有 UI 变更 → 「是」，处置结论逐条覆盖 UX-01～07 中适用项（如「UX-01 深色已适配、UX-04 不涉及方向性布局、UX-07 无动效」），证据写 `ux-consistency:UX-01` 等。
