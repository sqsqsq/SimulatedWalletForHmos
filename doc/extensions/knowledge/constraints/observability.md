# 可观测性

管日志、VOC 与 Chart 上报的覆盖与数据正确。

## 条目

| 编号 | 约束 | 强制力 | 命中条件 | 处置 | 验证（执行体） | 探针 |
|---|---|---|---|---|---|---|
| OBS-01 | 新增或改动的日志经统一日志封装，带定位问题所需的上下文；同一件事不在门面已记过之后再单独记一遍 | 基线 | 新增或改动日志 | 说明新增日志点各自用来定位什么 | 模型：核日志经封装、上下文够定位、无重复记录 | 无 |
| OBS-02 | VOC 记过程关键点：关键步骤的进入与完成、重要状态变更、用户中止与失败；已选为统计节点的终态只发 Chart，不同时发 VOC | 红线 | 新增或改动业务流程 | 列出关键路径 VOC 事件 | 模型：核关键步骤都有事件、统计终态处没有同时发 VOC。实机：只看 VOC 能定位用户卡在哪一步 | present_in_method:WalletHAManager\.(log\w*AndReport\|vocBuilder) |
| OBS-03 | 按业务目标选出要统计的业务节点，每个节点的全部适用结果都发 Chart；同一节点同一次执行只发一条终态 | 红线 | 需求涉及统计指标，或改动已有上报 | 列出统计节点、选择依据与各节点的适用结果 | 模型：对着业务流程核节点选择有依据、结果不漏不重。实机：按场景刺激捕获原始事件，一次执行一个节点一条 | present_in_method:WalletHAManager\.chartBuilder |
| OBS-04 | Chart 的内码是十位数字字符串，五段各两位，依次为业务模块、业务流程、节点/事件、子节点/子事件、具体结果，保留前导零；结果分类与内码末段是两个维度，取中间成功、全程成功、普通失败、主动取消之一，只有用户主动取消归主动取消，拒绝授权等归普通失败 | 红线 | 需求涉及统计指标，或改动已有上报 | 逐节点逐结果给出内码与结果分类 | 模型：核五段语义与分类。实机：核捕获事件的内码与分类 | 无 |
| OBS-05 | 外码取该步骤实际外部返回的错误码，没有就不填；事件描述与所需维度写明含义、类型、单位、来源与何时必需，耗时写明起止点 | 红线 | 需求涉及统计指标，或改动已有上报 | 逐字段说明取值来源；敏感内容按安全隐私域处理 | 模型：核字段来源与单位；标准字段要经专用设置入口，通用入口写同名字段会静默覆盖，要看实际调用。实机：核捕获事件的字段值 | 无 |
| OBS-06 | 新增或改变上报前先查已有节点与编码：相同节点、相同具体结果复用已有内码；只有需要区分的新含义才分配新码，在唯一登记位置登记，不与已有值冲突、不改变旧码含义 | 红线 | 新增 Chart 编码，或改动已有上报 | 列出复用与新增的编码及依据 | 模型：对照已有定义核复用、冲突与旧含义。实机：旧路径回归，旧事件含义不变 | 无 |

## 落法附注

- 流程类命中看有没有新的业务过程，与有没有界面无关；「步骤」「关键路径」按用户视角切：用户会说「我卡在哪一步」的那些。
- 统计节点按业务目标选：需要知道「这件事成没成、没成是因为什么」的那些。不按函数或分支数量铺点，也不为少报而少选必要节点；业务上没执行到的节点不发事件。
- 成功率等计算属于数据使用层；客户端只保证原始事件完整正确，不为某个统计公式删减取消或失败事件。
- VOC 用于问题定位、Chart 用于运维统计、BI 用于运营打点；「二选一」只约束 VOC 与 Chart，终态处仍可按排障需要记本地日志。
- 探针只证明调用形态出现过；覆盖、双报与字段正确由模型审查和原始事件判断。
- 用什么封装、字段怎么设见项目知识；敏感字段见安全隐私域。
