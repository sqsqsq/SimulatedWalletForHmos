# 安全隐私

管个人数据、权限、对外暴露面的红线；权威版本以安全团队发布为准。

> 「出处」列指向上游 story 模板规约（HarmonyOS）的章节号；标「工程增补」者规约中无对应原文。「等级」与「判定方法」两列规约未定义，整列均为工程增补。

## 条目

规约 §4 引导语原文列举的六类为：用户个人数据传递和采集、用户协议同意和更新、对外暴露接口和页面、敏感权限申请、敏感数据打印；并特别指出「新增权限获取/采集新的个人数据，新增特性/业务出海场景需要重点评估」。下表逐类展开。

| ID | 条目 | 出处 | 等级 | 判定方法 | 例外条件 |
|---|---|---|---|---|---|
| SEC-01 | 新采集/传递个人数据须声明数据项、用途、存储位置、留存期，并评估是否触发协议更新 | §4 | 红线 | spec 数据流描述 + spec §9.2 数据存储；对照 <待补充：个人数据分类分级表> | 无新增个人数据 |
| SEC-02 | 用户协议：新功能涉及协议范围变化时，协议同意与更新流程已设计 | §4 | 红线 | spec 场景含协议分支 | 不涉及协议范围 |
| SEC-03 | 对外开放页面：涉及用户隐私等敏感信息或受控访问的页面，须对调用方身份做合法性校验 | §4.1 + §8.1.4 | 红线 | spec §7.3 安全性要求中 exported 页面逐条有校验方案 | 无对外页面 |
| SEC-04 | 对外开放接口：涉及用户隐私等敏感信息或受控访问的接口，须对调用方身份做合法性校验 | §4.2 + §8.2.4 | 红线 | spec §7.3 安全性要求中对外接口逐条有校验方案 | 无对外接口 |
| SEC-05 | 敏感权限：新增权限须最小化申请、使用处申请（禁止启动时一次性全量），并说明必要性 | §4（另见 §11.1 系统权限行） | 红线 | `module.json5` requestPermissions diff + spec 权限说明 | 无新增权限 |
| SEC-06 | 敏感数据打印：日志不得输出明文敏感数据（账号/卡号/手机号/身份证），须脱敏 | §4 | 红线 | 代码检索日志调用点 + 脱敏工具使用（本工程参考 `CommFunc` 的 `FormatUtil` 模式） | — |
| SEC-07 | 出海评估：新特性/业务涉及出海场景须走安全隐私评估 | §4 | 基线 | <待补充：出海评估流程入口> | 仅国内 |

## 回显指引

应用域约束符合性表的「安全隐私」行：即使结论是「否」，也须给证据（如「不采集新个人数据、无新增权限、无对外暴露面——spec Scope + module.json5 现状扫描」）；「是」则逐命中 ID 声明处置，证据 `security-privacy:SEC-xx`。SEC 红线在评审①由安全角色主判，漏判属评审驳回项。
