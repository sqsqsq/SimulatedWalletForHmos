# 工程惯例与取证导航

**这个工程有哪些能力、各自长什么样、怎么找到它们。** 工程级知识，不属于任何单个流程阶段。
取证公式「事实 = 变更意图 × **代码库现状**」的现状那一半，第一落点就是本文件。

## 总则：先找已有实现，再谈新增

任何一类能力——打日志、上报、脱敏、存数据、读配置、跳页面、写界面——这个仓里大概率已经有做法了。
**先去找它，照它写。** 自己引平台 API 或另起一套，会让同一件事在仓里出现两种写法，
之后谁也说不清该照哪个。

**本文件写特征，不列实例**：写这类能力长什么样、从哪认出来，不写调用点清单——
判据是「这条写下来，一次重构会不会让它变成假话」。方法名会随重构改，改了就更新这里；
调用点每次改代码都过期，那种不写。

## 这个工程有什么

### 可观测性：日志 / VOC / Chart 三条渠道齐备

都在公共能力模块的 `shared/` 下，从模块公开出口导出。

| 渠道 | 形态 | 认出它 |
|---|---|---|
| 日志 | 静态类，封装平台 `hilog`，统一 DOMAIN，分 `debug` / `info` / `error` 三档，签名 `(tag, format, ...args)` | `shared/log/` |
| VOC | 链式 Builder + `report()`，底层写平台 `hiAppEvent` 的 **`BEHAVIOR`（行为）事件**，带事件 ID 与描述 | `shared/ha/` |
| Chart | 同上，写 **`STATISTIC`（统计）事件**，带功能 ID、子功能 ID 与业务终态 | `shared/ha/` |

- **共用一套字段**：两类 Builder 继承同一基类，业务字段由预定义的链式 setter 设置——
  功能 / 子功能 / 业务终态 / 渠道 / 时长 / 订单号 / 交易号 / 发生时间 / 内外部错误码 / 问题标识。
  字段是受控的，不能随手加。
- **统一门面**：`shared/ha/` 下的静态门面把「记一条日志 + 发一条 VOC」合成一次调用，
  分 info / error / debug 三档——**三档都发 VOC**，业务侧通常调门面而不是直接用 Builder。
- **业务终态是受控枚举**：成功 / 步骤成功 / 用户中止 / 异常失败。设计终态集合时从这个枚举取，不自造字符串。
- **上报非阻塞、失败不外传**：`report()` 内层 Promise 与外层 try/catch 双重兜住，
  失败只记一条本地错误日志，不抛、不改返回值。这就是「观测失败不改业务」在本工程的既有实现。

### 敏感数据处理

通用脱敏工具在公共能力模块的 `shared/utils/` 并从公开出口导出；
业务专属脱敏（按业务规则留头尾这类）在对应业务模块的 `shared/utils/` 内，**不上提公共层**——
业务规则会随业务变，公共层只放与业务无关的通用遮蔽。

### 数据存储

关系型持久化封装在业务模块 data 层的 `*RdbHelper` 形态里（持有单例 Store，配置带安全等级）；
内存态用平台的应用级存储，出现在 domain / service 层。
**已核实未使用**：平台的轻量偏好存储与分布式键值存储——选新方案时不要选它们。

### 配置项

常量开关在各模块存放常量的目录下，形态是 `static readonly <NAME>: boolean`（现存的均默认关闭）；
同目录另有非布尔的业务常量类，按类型区分，别一并当开关。
**无远程配置封装**（已核实）：没有管理台或云侧下发开关。

### 对外暴露面

三处认：应用清单里 ability 的对外可达声明、页面路由注册表、跨模块跳转的统一入口
（导航栈由公共能力模块持有）。

### 端云接口

**无端云封装**（已核实）：平台网络 API 与常见 HTTP 客户端源码内零命中，数据来自本地仓储层。

## 找到之后

- **照调用形态用**，不绕过封装直接引平台 API——绕过去就等于在仓里加了第二种写法；
- **照命名与目录惯例**放新文件：同类的东西放在同类的地方，名字用同样的构成方式；
- 既有实现与本需求确实不匹配时，**先说明哪里不匹配再新增**。不说明就新增，
  事后没人分得清这是「有意的第二种做法」还是「没找到就自己写了」。

## 找不到的时候

**「没有」必须是核对过的结论，不是没查到。** 写明查了什么、在哪查的、零命中。
本文件的前身就栽在这上面：凭平台常识写了本仓根本不用的埋点 API，又漏了实际存在的上报封装。

定位线索：用模块画像与模块目录缩范围，再在范围内检索。
画像只登记关键导出，**「画像里没有」不构成「工程里没有」**——「无」只能由检索零命中得出。

## 换工程复用

「总则 / 找到之后 / 找不到的时候」跨工程通用，直接带走。
「这个工程有什么」那几节须由模型实扫目标仓重写，再由人确认——它是唯一与具体工程绑定的部分。
