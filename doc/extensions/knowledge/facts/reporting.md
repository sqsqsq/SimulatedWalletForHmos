# 上报

**业务统计语义**两面——[1. 业务统计语义](#1-业务统计语义--confirmed-已确认)、[2. 渠道与已有能力](#2-渠道与已有能力--confirmed-已确认)——回答要观察哪些业务过程、会有哪些结果、本端何时可知、哪些已有采集覆盖。**协议与实现映射**四面——[3. 身份与 SDK 映射](#3-身份与-sdk-映射--confirmed-已确认)、[4. 结果与字段映射](#4-结果与字段映射--confirmed-已确认)、[5. 业务扩展字段](#5-业务扩展字段--confirmed-未确认)、[6. 登记与复用](#6-登记与复用--confirmed-已确认)——回答一个结果用什么身份、取值与调用报出去、新值怎样分配。[7. 使用参考](#7-使用参考--confirmed-已确认)各给一段例子。

## 1. 业务统计语义 — `confirmed: 已确认`

三类上报目的不同：VOC 定位过程问题；Chart 统计流程质量（运维指标）；BI 只做需求明确要求的独立运营采集。同一业务事实同时服务运维与运营时，两边共用同一个业务步骤身份，不各起一套。

指标与流程不一一对应：一个指标可以观察一条流程，也可以汇总几条相关流程的同类结果；一条流程也可以支撑几个指标，同一事件事实只采集一次、共用于这些指标。观察范围按需求与统计语义确定。流程由步骤组成，步骤下可以有子点；一次尝试从发起到得到这一点的终态结果。同一步骤的不同结果属于同一个统计对象，结果不同不改身份；失败后重新输入是新的一次尝试，父步骤仍可最终成功。步骤成功与流程整体成功是两件事，各自有结果。

结果在远端产生时，本端只统计实际观察到的那一刻（响应、回调或状态查询），写明时机；本端观察不到的，由谁统计或待决要写清。页面进入与点击这类交互记录不表达校验通过、受理成功等业务结论，业务结论由业务调用的结果产生。

## 2. 渠道与已有能力 — `confirmed: 已确认`

| 渠道 | 用途 | 仓内现状 |
|---|---|---|
| VOC | 过程问题定位 | 已实现：`WalletHAManager.vocBuilder(eventID, desc)`；`logAndReport` / `logErrorAndReport` / `logDebugAndReport` |
| Chart | 运维统计 | 已实现：`WalletHAManager.chartBuilder(eventID, funcID, subFuncID)` |
| BI | 明确需求的独立运营采集 | 已定规范，仓内尚无 BI 封装；需求要 BI 时属于建设差距 |
| 自动运维上报 | 页面进入、点击等交互记录 | 已定规范，仓内尚无自动采集实现：现在不构成已有覆盖；需求要用到这些交互数据时，数据要求与这项建设差距都要写明 |

VOC 与 Chart 在同一统计终态处二选一，过程关键点用 VOC。

VOC 与 Chart 的封装位于 `CommFunc/src/main/ets/shared/ha/`，经 `CommFunc/src/main/ets/index.ets` 导出；发送非阻塞，失败记本地日志。SDK 不负责业务去重。

## 3. 身份与 SDK 映射 — `confirmed: 已确认`

Chart 与 BI 共用业务步骤身份：模板 `eventID`、流程 `funcID`、步骤 `subFuncID`。例如 `BankCard_001_002` 表示银行卡模板下某流程的一步，同一步骤的不同结果共用身份；同语义运营和运维点位引用同组常量。

Chart 中模板作为 hiAppEvent 的事件名，流程/步骤写入 `FuncID` / `SubFuncID`；Builder 生成的 `WalletEventID` 是 `FuncID_SubFuncID`，与事件名共同定位完整身份。平台类型为 STATISTIC。BI 的业务身份相同，具体传参采用项目 BI 接口，不从 Chart 封装推定其传输格式。

VOC 使用自己的标识：类型 BEHAVIOR，`WalletEventID` 为调用方事件标识，`FuncID` 固定为 `VOC`。三个日志门面先记相应级别的本地日志再发一条 VOC；仅上报使用 `vocBuilder(...).report()`。

## 4. 结果与字段映射 — `confirmed: 已确认`

运维内码是十位数字字符串，五段各两位：业务模块、业务流程、节点/事件、子节点/子事件、具体结果，前导零保留。内码定位具体结果，分类表达结果类别，两者独立；事件身份表达步骤，不随成功/失败改名。

| 数据 | 项目语义与用法 |
|---|---|
| 结果分类 | `setWalletFuncResult`：`SUCCESS` 全流程成功；`STEP_SUCCESS` 步骤成功；`STEP_ERROR_BY_ERROR` 普通失败；`STEP_ERROR_BY_USER` 主动取消。拒绝授权归普通失败 |
| 内码 | `setWalletEventInCode(string)`；Chart 结果采用已登记编码，子点可由子节点段区分 |
| 外码 | `setWalletEventExtCode(string)`；仅带该结果实际取得的外部错误码，无则不设置 |
| 耗时 | `setDuration(number)`，毫秒；有统计需要、明确起止且实际测量时带 |
| 描述 | `setWalletEventDesc(string)`，点位可读描述；按项目协议及场景填写 |

BI 按明确运营需求选择参数，不默认携带运维内码、外码或结果分类。项目约定借用内外码表达相近业务含义时，采用对应的运营定义和取值来源。自定义维度经 `setReportParam(name, value)`，值为 string / number / boolean；已有标准字段使用其专用入口。

## 5. 业务扩展字段 — `confirmed: 未确认`

`WalletHAReportBaseCBuilder.ets` 提供 `setChannel`、`setSource`、`setIssueID`、`setIssueName`、`setOperationType`、`setSrcPassType`、`setOrderNumber`、`setTransactionId`（string）及 `setHappenedTime`（string | number）。以上名称和类型已核；业务含义按项目参数规范核实。

需要核实的具体内容：Channel/Source 的区分与取值；IssueID/IssueName 所指主体；OperationType/SrcPassType 取值集合；OrderNumber/TransactionId 的区别；HappenedTime 格式，以及本需求实际使用字段的必需条件、来源和隐私处理。只核本需求需要的字段，不要求填满全部参数。

## 6. 登记与复用 — `confirmed: 已确认`

现有定义：模板枚举位于 `CommFunc/src/main/ets/shared/ha/WalletHAEventID.ets`，当前只有 `Wallet_COMMON`；仓内尚无业务流程、步骤与内码的登记，也没有 Chart 调用。

两套编号各有命名空间：身份按「模板 → 流程 → 步骤」分配，流程号、步骤号三位；内码按「业务模块 → 模块内流程 → 节点 → 子节点 → 具体结果」分配，每段两位。两处的流程段长度不同，不互相截取。

本仓采用下面的分配规范；具体编号仍按规范提出并确认，不是现有代码里已有的分配：

- 先扫全仓的模板、常量定义与调用，同语义的已有值直接复用；同一模板跨特性使用时先核全部已有定义。
- 新值在对应父范围里取未用号，给出具体候选：首次按升序从 `001` / `01` 起，节点与子节点段的 `00` 留给未细分；结果段 `00` 成功、`10` 主动取消，失败取其余未用号。
- 父范围首次使用（例如业务模块段还没有登记）时，父范围与子项的候选及依据一起提出，经项目设计评审确认；候选不称作已有分配。项目有外部统一分配的用其结果，拿不到时列出待决的那一项，不自行占号。
- 登记文件放在特性自己的 shared 层，文件名以 `ChartCodes` 结尾，首次使用时新建；候选在设计里标「待登记：<登记文件>」，写入登记文件前重核冲突，有冲突回到设计调整，不自动换号。

身份定义不是一次执行的流水号。已有定义按语义复用，新的具体结果扩展内码，不为同一步骤的不同结果复制身份常量。

## 7. 使用参考 — `confirmed: 已确认`

**业务语义**：一项「开通服务」的运维指标开通成功率，观察一条开通流程。可重试的短信验证下有两个子点，属于同一步骤。步骤划分与粒度随具体业务，下表只是关系示例。

| 统计点 | 实际业务结果 | 本端从哪得知 |
|---|---|---|
| 开通/身份校验 | 通过；不通过 | 校验请求的返回 |
| 开通/短信验证 | 验证通过；用户终止验证；无法继续 | 子点结果与用户操作 |
| 开通/短信验证/发送验证码 | 发送成功；发送失败 | 发送请求的返回 |
| 开通/短信验证/校验验证码 | 校验通过；未通过 | 校验请求的返回 |
| 开通/整体 | 开通成功；开通失败 | 开通结果的回调或查询；结果在远端产生时写明本端取得的时机 |

终止验证不撤回已经发出的发送请求，各对象记录自身结果；同一尝试的重复回调只算一次。

**实现映射**：「校验验证码」的两种结果各自落到调用上。身份是开通流程下短信验证步骤的一组 `funcID`/`subFuncID`；内码在该步骤的节点段下用子节点段 `02`，结果段通过取 `00`、未通过取未用的失败号；分类为步骤成功或普通失败；外码取校验接口返回的错误码，没有则不带。由执行校验的方法在校验请求返回时报告；同一次校验的重复回调按请求标识只报一次，耗时取请求发出到返回。子点也可以按项目粒度采用独立步骤身份，不能只按共用事件名去重。

```ts
WalletHAManager.chartBuilder(WalletHAEventID.Wallet_COMMON, funcID, subFuncID)
  .setWalletEventInCode(inCode)
  .setWalletFuncResult(result)
  .report();
```
