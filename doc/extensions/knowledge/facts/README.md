# 项目知识

一节一面（一类能力）：有没有、叫什么、在哪。照它写。

- `confirmed: 已确认` = 已对仓核实；`未确认` = 用前先核。
- 已确认「无 X」的能力不可当作已有能力复用；本轮确需新建的，作为有需求/设计依据的方案项明确登记。
- 这里没登记的能力去仓里实扫（`build/`、`.bak/` 不是源码，排除）；与这里不符时以仓为准，并在产物里登记矛盾。

## 这一类里固定的一份：部件画像

`component-profile.md` —— 这个仓是什么部件、有哪些交互方、职责边界到哪。装扩展时第一份写的就是它，
之后每次需求的作者都从它起步。写的时候每条事实后面带仓内路径或架构 DSL 的键名，查不到的写「未确认」，
不写推断。

其余项目事实按面另起文件，名字随内容——**只有进了激活清单的才读得到**，目录里躺着的没人看。
