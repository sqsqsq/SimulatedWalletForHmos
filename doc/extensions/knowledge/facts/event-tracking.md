# 埋点上报

把业务结果变成可算的指标，按项目协议上报。**当前实现**以 `05-SystemBase/CommFunc/src/main/ets/shared/ha/` 为准；**已定规范**是本仓采用、尚未实现的要求。

# 上篇 · 适用与统计设计（读者：spec）

## 1. 解决什么问题

- **指标**：由事件结果算出的比率，如成功率；失败原因这类分析信息是随每次上报带上的事件字段。
- **流程**：有起止的业务过程，由步骤与子点组成；一个指标可以跨几条流程。
- **事件分类**与**业务目标**都不是指标：材料里的业务目标翻成要算的率，并写出它与指标的关系；终态分布（各结果各占多少）不写成指标。

## 2. 什么时候不该用

- 需求不新增、不改变任何业务结果（纯文案、样式或资源）。
- 要观察的结果已由现有采集完整覆盖。
- 材料明确不做运维观察，且无运营诉求。

## 3. 应用步骤

1. **定指标**：一个指标一个小节，标题写指标名；定义段写衡量什么、怎么算（分子分母是本端哪些结果；以后台数据为分母的，写需要什么数据、由谁统计）、每次上报带什么、在哪些流程哪些步骤打点。
2. **列统计点**：步骤、子点、步骤整体、流程整体各是一个点。不同流程里的同名步骤，把流程写进统计点名（「开票流程 / 校验抬头」），下游按统计点名对齐。统计点表的列：统计点、业务动作、实际适用结果、本端获知时机、已有覆盖或新增（已有覆盖的写现有采集，只是规范、仓内未实现的不算覆盖）、代码现状。
3. **写结果与获知时机**：只写实际会发生的结果和本端在哪个响应、回调或查询里得知；本端看不到的写由谁统计或列待决。
4. **定边界**：重新发起是新尝试；前一步失败而没进入的步骤不记；同一业务事实只在一处采集；远端状态按首次得知计一次；页面进入与点击不进统计设计。
5. **选渠道**：一个统计点只走一个渠道。进统计的结果走 Chart（按身份与编码计数），原因、场景与关键状态写进它的描述；VOC（给人读的定位记录）只用于不进统计的过程点，如中间状态切换、进入降级分支。BI（运营采集，需求明确要求才加）与交互自动记录（页面进入、点击）是已定规范，仓内无实现，写成建设差距。

示例（假设开票结果由服务端异步通知）：

```markdown
##### 电子发票开具成功率

衡量提交开票后最终开出发票的比例：开出的申请 / 全部开票申请；每次上报带失败原因（通知里的错误码）；打点在开票流程的校验抬头与开票全流程。

| 统计点 | 业务动作 | 实际适用结果 | 本端获知时机 | 已有覆盖或新增 | 代码现状 |
|---|---|---|---|---|---|
| 开票流程 / 校验抬头 | 提交抬头信息 | 通过 / 未通过 / 请求失败 | 校验响应或通信失败 | 新增 | 检索零命中 |
```

# 下篇 · 结构与落地（读者：plan、coding、review）

## 4. SDK 行为事实

- **Chart**：`WalletHAManager.chartBuilder(eventID, funcID, subFuncID)` 链式设字段后 `.report()`；`WalletEventID` = `FuncID_SubFuncID`（如 `Wallet_COMMON_001_002`），平台类型 STATISTIC。按身份、分类、内码、外码计数；可读描述经基类的 `setWalletEventDesc` 设，构造时不设。`report()` 不写本地日志。
- **VOC**：`vocBuilder(walletEventID, walletEventDesc).report()`：事件名固定 `Wallet_COMMON`、类型 BEHAVIOR，`WalletEventID` 由调用方给，`FuncID` 固定 `VOC`，内容就是那段描述。`logAndReport` / `logErrorAndReport` / `logDebugAndReport` 用同一段描述先写本地日志、再发一条 VOC。
- **发送**：经 `CommFunc/src/main/ets/index.ets` 导出；不阻塞业务，失败只记本地日志，不做业务去重。
- **现有定义**：模板枚举 `WalletHAEventID.ets` 只有 `Wallet_COMMON`；仓内没有流程、步骤、内码登记，业务代码里也没有 Chart 或 VOC 调用。
- **字段**：setter 与类型见 `WalletHAReportBaseCBuilder`；业务扩展字段（`setChannel`、`setSource` 等）的含义本仓无依据。

## 5. 每种结果要给的值

成功率类运维上报，每个统计点、每种结果都要给出四项具体值：

| 项 | 写什么 |
|---|---|
| 事件 ID | 模板、流程号、步骤号，如 `Wallet_COMMON` / `003` / `001` |
| 内码 | 十位，按 §7 第 2 条取号 |
| 结果分类 | `SUCCESS` / `STEP_SUCCESS` / `STEP_ERROR_BY_ERROR` / `STEP_ERROR_BY_USER` 之一 |
| 描述 | 一句固定说法加本次关键值：写编码表达不了的原因、场景与关键状态（如第几次重试、走了哪条分支、远端返回的状态），写明关键值取自哪里；不写个人数据与凭据 |

耗时只在时延类指标里带。

## 6. 角色与结构骨架

| 角色 | 职责 | 命名惯例（拟定） |
|---|---|---|
| 尝试持有者 | 决定业务结果的业务方法，持有本次尝试标识，重新发起时新建 | 业务流程类的提交或查询方法 |
| 结算方法 | 一次尝试只结算一个结果；正常响应、失败、请求异常与重复回调都调它；写进契约 | `settle<结果>` |
| 登记文件 | 流程、步骤、内码常量 | 特性 shared 层 `<特性>ChartCodes` |

接上篇示例（`InvoiceFlow` 为示意名，编号只示范取号形态）：

| 统计点 | 结果 | 责任方法 | 事件 ID | 内码 | 结果分类 | 描述 | 外码来源 | 去重与验证 |
|---|---|---|---|---|---|---|---|---|
| 开票流程 / 校验抬头 | 未通过 | InvoiceFlow.settleTitleCheck | `Wallet_COMMON` / `003` / `001` | `0203010001`（候选，待登记：InvoiceChartCodes） | STEP_ERROR_BY_ERROR | 「校验抬头未通过」，拼校验响应里的原因说明与抬头类型（个人 / 企业，取自提交参数） | 校验响应的错误码 | 每次提交一次尝试，重复回调不再报 |

结算方法先看本次尝试是否已结算，已结算即返回；否则置位，`chartBuilder(模板, 流程, 步骤)` 设内码、分类、描述与拿到的外码后 `report()`。

## 7. 使用约定 — 人为纪律，SDK 不强制，review 逐条核查

1. **候选就是具体值**：§5 的事件 ID、内码、结果分类写出实际的号，新取的标「候选，待登记：<登记文件>」，「xx」「待定」不是值。
2. **编号按分配规则**（Demo 拟定，目标仓以自己的登记为准）：身份「模板 → 流程 → 步骤」，流程、步骤号三位；内码十位「业务模块 → 模块内流程 → 节点 → 子节点 → 结果」，每段两位、保留前导零。同语义已有值直接复用，同一步骤的新结果扩展内码；新值在父范围升序取未用号，从 `001` / `01` 起；步骤 `000`、节点 `00` 表示流程整体，子节点 `00` 表示未细分；结果 `00` 成功、`10` 主动取消、其余为失败。有外部统一分配的用其结果，拿不到列待决；编码前写入登记文件并核冲突。
3. **结算一次**：结果在决定它的业务方法里报，一次尝试一条；尝试标识与业务幂等键分开；已发出的请求按它自己的最终结果记。
4. **分类按语义**：`SUCCESS` 只给流程整体成功，步骤成功 `STEP_SUCCESS`，普通失败（含拒绝授权）`STEP_ERROR_BY_ERROR`，用户主动取消 `STEP_ERROR_BY_USER`；内码定位具体结果，与分类独立。
5. **只带拿到的**：外码只带实际拿到的外部错误码；plan 写它来自哪个响应或回调，没有写「无」。
6. **一个点位一个渠道**：进统计的结果只报 Chart，定位信息写进描述；Chart 点位要本地日志时直接调 `Logger`，`log*AndReport` 会再发一条 VOC。
7. **BI 与扩展字段**：BI 按运营需求选参、走项目 BI 接口，同语义的运维与运营点位引用同组常量；借内码、外码表达业务含义时写明含义、取值来源与消费约定。业务扩展字段先向项目参数规范或负责人取得含义、取值集合、必填条件与隐私处理；`setReportParam` 只放标准字段之外的维度。

## 8. 设计之外的完成判断

§4、§5、§7 是实现与审查的判据；此外：

| 对象 | 完成判断 |
|---|---|
| plan 埋点小节 | 每个统计点、每种结果一行，按统计点名对齐 spec；责任方法是契约里的「接口.方法」；§5 各项与外码来源都已写出 |
| 单元测试 | 每种结果预期的原始事件与次数，含重复回调与重新发起；统计点上不出现 VOC 事件 |
| 真机验证 | 只核需要真机的回调时序与远端结果 |
