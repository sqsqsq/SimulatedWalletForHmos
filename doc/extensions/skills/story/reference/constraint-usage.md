# 应用域约束在 spec/story 阶段的用法

`knowledge/constraints/` 是**工程级**约束知识，只答「约束是什么、怎么判断命中」。
消费方不止一个——coding 要落实、code-review 要检查、testing 要走查，各自的用法各自维护。

**本文只管 spec/story 这一段**：怎么判定、结论回显到哪里。
约束文件本身只答「约束是什么」，本阶段的回显指引一律在本文。

## 判定的三个出口

判定在 **spec 阶段**做（那时 SR / PRD 都在手上，取证成本最低）。判定的推演过程是工作底稿，
三份产物都不写；它只输出三样：

| 判定产出 | 落点 | 为什么在这 |
|---|---|---|
| 命中 / 不涉及的**结论** | 叙事件的「影响面与合规」章两张表（兼容性自检 + 应用域约束符合性） | 零条代码要求，纯粹是给评审者的完备性回显 |
| 判定中冒出来的**代码要求** | 规格件 §7 非功能性需求（UX 适配 / 触发频次 / 存储兼容 / 个人数据采集） | 这类要求只在合规判定时才冒出来，别处没有，漏了就到不了编码 |
| 判定中得出的**待某方确认** | 决策件的开放决策项 | 需要人表态的事项必须有表态位 |

## 两张回显表的写法

**应用域约束符合性表**——七个约束域全覆盖，逐域一行：

1. 每行给「是/否 + 一句话结论 + 规约编号」；判「否」也须给依据
   （如「不采集新个人数据、无新增权限、无对外暴露面」）；
2. **「是否命中」只能填 `是` 或 `否`**——填「按需」「命中」是把判断推给下游，
   而这里的全部价值就是此刻给出判断；
3. 编号**逐个列出**（`XXX-01`、`XXX-04`），禁止用波浪号连写首尾编号那样的区间记法；
4. 详情写**中文规约名 + 编号 + 含义括注**（「<中文规约名> XXX-01（<该条要求什么>）」）
   ——不用「英文文件名 + 冒号 + 编号」的仓内标识形式：归档件随需求上传，
   评审者打不开仓内文件，那种写法对他们没有意义。
   **这是 story 侧的形态**；spec 侧只写裸编号（它是仓内工作件，读者手上有规约文件）
   ——两侧形态见 [`evidence-rules.md`](evidence-rules.md) §3.2 证据表；
5. 小结数字须与实际判「是」的条数一致（说「涉及五项」就必须恰好五项为「是」）。

**兼容性自检表**——`compatibility-checklist.md` 是它的逐项过表数据源：

- **逐 ID 判定命中与否，无豁免行**——表里的每条都面向本部件，未命中的在末尾汇总行
  一并说明即可，不必逐条单列「不涉及」；
- 命中判定必须能指回**具体变更的名字**；自检表的首列写 COMPAT-xx 编号；
  一条含多问的（如缓存、端云配套），命中时逐问给结论，不一票带过；
- 本域在应用域约束符合性表**无独立行**——兼容性自检表即它的回显。

## 各域的特殊承载

| 域 | 承载方式 |
|---|---|
| UX | 无 UI 变更 → 「否 + 证据」；有变更 → 「是」，逐条覆盖该域适用条目 |
| MODE | 几乎不可能为「否」——该域每条都须给策略结论（可以是「全模式可用，因为纯展示且不采集数据」） |
| SEC | 红线在评审①由安全角色主判，漏判属评审驳回项 |
| APP | 涉及配置项的条目，其配置本体写进规格件的配置项表，回显处只写管控结论与必要性评估结论 |
| DFX | 量化性能指标条目由规格件非功能章节承载，回显只确认「已声明」；该域其余条目由符合性表的「DFX 扩展」行管 |
| TEL | **无独立行**：由规格件埋点表（按该域中定义埋点内容的条目生成）+ 符合性表「资料交付」行（承载该域的归档动作条目）共同承载；该域的通知动作条目落决策件的跨团队协同并留承接方 |
| ENV | 判定新功能是否引入受环境场景影响的状态/流程；「是」→ 对命中 ID 声明兜底并确认已列入异常场景；「否」→ 说明为何无状态可受影响 |
| DLV | 逐 ID 判定；命中项的执行动作（翻译跟踪 / TA 联调 / 通知）落决策件的跨团队协同与上线时序 |

## 判定纪律

- 生成前**逐个读取** `knowledge/constraints/` 下全部约束文件（README 有清单与 applies_when）；
- 判定结论由 verifier 的 `spec_constraint_echo` 语义判据检查——这是判断，脚本判不了，
  所以不在机械门禁里；
- 条目一律平权，逐条判定；`<待补充：…>` 处写「基准待补充，按条目语义定性评估」，
  **不得臆造数值**。
