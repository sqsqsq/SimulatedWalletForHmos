# {{SR}} 交通卡快捷充值 — 系统设计（SE）

> 关联：AR {{AR}} / PRD {{RR}}。本设计覆盖钱包 app、账号能力、钱包云侧和支付部件。

## 1. 方案与边界

首页交通卡卡片新增两个触发方式：长按快捷菜单中的“充值”，以及余额不足角标。两者共用同一条前置链路：
确定被操作的 `cardNo`、检查账号身份、进入既有充值页、由用户选择金额后创建订单，再拉起既有收银台。

被否方案是在卡详情页新增浮层入口。该方案没有减少“首页 → 卡详情 → 充值页”的路径，且会造成首页低余额提示
和卡详情入口含义重复，因此不采用。

本需求不改变云侧余额计算、交通卡充值金额、订单风控策略和收银台支付流程；这些能力由已有系统继续负责。

## 2. 参与方与职责

| 参与方 | 输入 | 输出 | 责任 | 失败影响 |
|---|---|---|---|---|
| 钱包 app 首页 | 卡片、开关、余额结果、用户操作 | 跳转参数、下单请求、用户提示 | 展示入口、保存原卡意图、处理端侧异常 | 用户无法从首页快捷进入，但旧路径仍可使用 |
| 账号能力 | 游客的登录请求与回跳参数 | 已登录身份或登录失败结果 | 完成既有登录并恢复原卡充值意图 | 不创建订单，用户留在既有登录结果页 |
| 钱包云侧 | `cardNo`、金额、来源 | 余额与阈值、订单、错误码 | 提供余额、配置、订单有效期和风控判定 | 首页不展示基于余额的提示或无法继续下单 |
| 支付部件 | `orderNo`、`payParams`、来源 | 支付结果回调 | 拉起收银台并记录 `home_quick` 来源 | 订单可按既有机制继续支付或重新下单 |
| 运营管理台 | 开关值、报表需求 | 开关配置、报表口径 | 管控入口可见性和使用分析 | 不改变既有充值能力 |

## 3. 端到端时序

```text
用户
  │ 长按交通卡 / 点击低余额角标
  ▼
钱包 app 首页 ── queryTrafficCardBalance(cardNo) ──▶ 钱包云侧
钱包 app 首页 ◀─ balance + lowBalanceThreshold + 开关 ── 钱包云侧
  │ 判断入口可见；保存被选 cardNo
  ├─ 游客 ──▶ 账号能力登录 ──成功──▶ 回到同一张卡充值页
  └─ 已登录 ───────────────────────▶ 充值页
充值页 ── 用户选择金额后 createTopupOrder(cardNo, amount, home_quick) ──▶ 钱包云侧
充值页 ◀─ orderNo + payParams / ORDER_RISK_REJECT ───────────────────── 钱包云侧
钱包 app ── 拉起既有收银台(orderNo, payParams, home_quick) ───────────▶ 支付部件
钱包 app ◀─ 支付结果回调 ─────────────────────────────────────────── 支付部件
```

关键边界：首页不根据角标自动下单；账号能力不理解交通卡业务，只接收并回传跳转意图；支付部件不决定入口
是否显示；来源统计改造由支付部件独立排期，不阻塞钱包 app 发布。

## 4. 接口约定

### 4.1 `queryTrafficCardBalance`（复用，无接口变更）

| 项目 | 约定 |
|---|---|
| 服务 | `wallet-card-service` |
| 请求 | `cardNo` |
| 响应 | `balance`（分）、`lowBalanceThreshold`（分）、`homeQuickTopupEnabled` |
| 调用时机 | 首页可见且存在交通卡时，随首页刷新（下拉或回到前台）触发；无定时任务。 |
| 展示规则 | `balance < lowBalanceThreshold` 才显示角标；阈值由云侧配置，客户端不写死 10 元。 |
| 失败处理 | 保留已有卡片展示；不依据过期结果新增角标；用户仍可从既有路径充值。 |

### 4.2 `createTopupOrder`（新增）

| 项目 | 约定 |
|---|---|
| 服务 | `wallet-order-service` |
| 请求 | `cardNo`、`amount`（分）、`source`（固定为 `home_quick`） |
| 响应 | `orderNo`、`payParams`、`expiresAt` |
| 触发时机 | 用户在充值页选择金额后单次调用；首页入口不调用。 |
| 错误码 | 新增 `ORDER_RISK_REJECT`：风控拒绝，端侧展示可理解说明并允许用户返回修改金额或结束。 |
| 重试 | 不自动重试；用户主动再次提交才创建新的请求。 |

## 5. 端侧数据与恢复

### 5.1 最近订单缓存

| 项目 | 约定 |
|---|---|
| 键名 | `wallet_last_topup_order` |
| 介质 | Preferences |
| 值结构 | `{ orderNo, cardNo, accountScope, createdAt, expiresAt }` |
| 用途 | 支付中断后回首页时提示“继续支付”，不作为余额或支付结果真源。 |
| 有效期 | 至云侧订单过期，最长 30 分钟（上游约束：本 SE）。 |
| 隔离 | `accountScope` 与当前登录账号匹配才可读取，切换账号后不得展示前一账号订单。 |
| 加密与日志 | 缓存不保存金额和支付参数；不加密。日志与埋点不得记录完整 `cardNo`、`orderNo` 或 `payParams`。 |
| 清理与备份 | 订单过期、支付完成、账号切换或用户清理应用数据后删除；不随备份恢复。清理后允许用户重新下单。 |

### 5.2 跳转意图

游客跳转登录时只保存“目标为充值页”和被选 `cardNo`；登录成功后校验该卡仍属于当前账号，再进入充值页。
登录取消、失败或卡片不再可用时丢弃意图，不创建订单，也不展示上一次用户的卡号。

## 6. 配置与兼容

### 6.1 `home_quick_topup_enabled`（新增管理台开关）

| 项目 | 约定 |
|---|---|
| 默认值 | `false` |
| 开启态 | 首页可展示长按菜单中的充值项；余额不足时允许展示角标。 |
| 关闭态 | 隐藏上述新增入口和角标，首页按既有方式展示。 |
| 旧版本 | 不读取该配置，无行为变化。 |
| 配置不可用 | 按关闭处理，避免意外显示新入口。 |

### 6.2 兼容性

- 新增 Preferences 键，不读取或迁移旧数据；
- 旧版本不解析 `home_quick` 来源；
- 支付部件尚未完成来源统计时，钱包 app 仍可按既有收银台协议拉起支付；
- 首页不支持长按的设备或卡片类型继续保留既有点击行为，不新增不可操作的入口。

## 7. 异常与用户表现

| 场景 | 钱包 app 行为 | 用户可见结果 | 恢复方式 |
|---|---|---|---|
| 余额查询失败 | 不展示基于新结果的低余额角标 | 卡片仍可浏览 | 用户可下拉刷新或走旧充值路径 |
| 开关关闭或读取失败 | 隐藏新入口 | 首页与旧版本一致 | 运营开启后随下次刷新生效 |
| 游客登录取消/失败 | 丢弃跳转意图 | 停留在既有登录结果页 | 用户可稍后重新选择充值 |
| 下单风控拒绝 | 不拉起收银台 | 展示风险拒绝说明 | 用户返回充值页修改金额或结束 |
| 下单网络失败 | 不自动重试 | 展示网络失败说明 | 用户主动再次提交 |
| 支付中断 | 若订单未过期保存最近订单 | 首页可看到继续支付提示 | 按既有收银台恢复能力继续，过期后重新下单 |

## 8. 质量、安全与运营要求

| 维度 | 结论 |
|---|---|
| 性能 | 余额查询随首页刷新触发，不增加定时任务或并发轮询。 |
| 可用性 | 新入口不可用时不影响既有卡详情充值路径。 |
| 隐私 | 不新增个人信息采集；对日志、埋点和错误提示做卡号、订单号、支付参数脱敏。 |
| 无障碍与适配 | 新增角标、菜单和充值文案使用主题资源和字符串资源；文本容器可随显示大小伸缩。 |
| 埋点 | 只上报入口曝光、点击、下单结果及结果类型，不上报完整卡号或订单号。 |
| 协同 | 运营更新报表；支付部件登记来源统计维度；钱包 app 负责端到端联调。 |

## 9. 埋点

| 事件 | 触发节点 | 字段 | 归属 |
|---|---|---|---|
| `home_topup_entry_expose` | 快捷菜单项或低余额角标展示 | `entryType` | 运营 |
| `home_topup_entry_click` | 用户选择入口 | `entryType` | 运营 |
| `home_topup_order_result` | 下单成功、网络失败或风控拒绝 | `resultType`、`entryType` | 运营与运维 |

任何事件都不得携带完整 `cardNo`、`orderNo`、`payParams` 或账号标识。
