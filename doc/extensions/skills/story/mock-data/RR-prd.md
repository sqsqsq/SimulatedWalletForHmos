# {{AR}} 交通卡快捷充值入口 — 产品需求（PRD）

> 需求单号：{{RR}}（关联 AR：{{AR}} / SR：{{SR}}）

## 1. 要解决的问题

交通卡用户发现余额不足后，当前必须从钱包首页进入卡详情，再进入充值页才能完成付款准备。路径包含三个页面
动作，用户容易在卡详情页离开；低余额时首页又没有足够明确的行动入口。本需求把“发现余额不足”和“开始充值”
连接起来，让用户从首页交通卡卡片一步进入充值页。

本需求服务已经绑定交通卡的登录用户，也覆盖尚未登录但能浏览首页卡片的游客。它不改变交通卡的充值金额规则、
支付能力或卡片管理能力，而是前移已有充值能力的入口。

## 2. 目标与成功口径

| 目标 | 说明 | 成功口径 |
|---|---|---|
| 缩短路径 | 从首页直接开始充值 | 用户从首页进入充值页只需 1 步（上游约束：本 PRD） |
| 让低余额可见 | 在需要时提示用户处理余额 | 余额低于阈值时显示入口角标；阈值由云侧返回（上游约束：本 PRD） |
| 不干扰旧用户 | 能按运营策略关闭新入口 | 关闭开关后首页与现有版本一致（上游约束：本 PRD） |
| 不丢失登录前意图 | 游客先完成登录再继续原任务 | 登录成功后回到同一张交通卡的充值页（上游约束：本 PRD） |

## 3. 用户与使用前提

| 用户 | 当前处境 | 需要完成的事 | 不在本需求内 |
|---|---|---|---|
| 已登录交通卡用户 | 首页可见一张或多张交通卡 | 选择某张卡并快速发起充值 | 改变充值金额、支付方式或卡片绑定规则 |
| 游客 | 可以浏览首页，未取得账号身份 | 进入登录并保留所选卡片 | 修改登录产品或注册流程 |
| 运营人员 | 需要按业务状态控制入口 | 通过管理台控制新入口是否可见 | 手工配置单张卡余额 |
| 支付部件团队 | 需要识别入口来源用于统计 | 接收 `home_quick` 来源 | 改造钱包首页界面 |

前提：首页已经能够展示交通卡卡片；卡片有可供云侧查询的卡号；既有充值页和收银台可正常使用。

## 4. 用户旅程

### 4.1 已登录主路径

1. 用户在钱包首页看到交通卡卡片；
2. 用户长按该卡片，快捷菜单出现“充值”；或在低余额角标出现时点击角标；
3. 应用带着该卡片的卡号进入充值页，展示常用面额；
4. 用户选择金额并继续支付；支付结果由既有收银台流程反馈；
5. 用户返回首页后，按照既有余额刷新逻辑查看更新后的余额。

### 4.2 游客路径

1. 游客从长按菜单或低余额角标选择充值；
2. 应用先展示既有登录流程；
3. 登录成功后，应用回到同一张交通卡的充值页并保留进入充值的意图；
4. 用户取消登录或登录失败时，停留在登录流程的既有结果页，不创建充值订单。

### 4.3 低余额提示路径

1. 首页刷新时查询交通卡余额及低余额阈值；
2. 余额低于阈值时，卡片显示“余额不足”角标；余额等于或高于阈值时不显示；
3. 角标不是独立营销入口，点击后走与长按菜单相同的充值前置校验和页面跳转。

## 5. 产品范围

### 5.1 本次提供

| 编号 | 能力 | 说明 |
|---|---|---|
| F1 | 卡片长按入口 | 首页交通卡卡片长按后出现快捷菜单，其中包含“充值”。 |
| F2 | 低余额角标 | 余额低于云侧返回的阈值时显示“余额不足”角标。 |
| F3 | 充值页直达 | 从任一快捷入口进入充值页时携带卡号并预填常用面额。 |
| F4 | 登录后续接 | 游客先登录，成功后回到原交通卡的充值页。 |
| F5 | 入口管控 | 管理台开关关闭时不显示长按菜单中的充值项和低余额角标。 |

### 5.2 明确不做

- 不新增充值金额档位、优惠、支付方式或退款能力；
- 不改变交通卡详情页、卡片绑定、解绑、挂失和迁移能力；
- 不在首页自动创建充值订单；用户必须在充值页选择金额后才下单；
- 不修改支付收银台交互，只将快捷入口来源提供给既有收银台统计；
- 不因为余额低而强制用户充值，也不在阈值外展示角标。

## 6. 产品规则

| 规则 | 结论 |
|---|---|
| 入口显示 | 仅在首页交通卡卡片可见且 `home_quick_topup_enabled` 开启时显示。 |
| 低余额阈值 | 由云侧随余额查询返回；默认示例为 10 元，但客户端不写死。 |
| 卡片归属 | 跳转、下单和缓存始终使用用户触发的那张卡，不能误用首页第一张卡。 |
| 常用面额 | 由已有充值页的面额选择规则决定，本需求只负责带入卡号。 |
| 开关关闭 | 不展示新增入口或角标；原有从卡详情充值的路径保持可用。 |
| 重复操作 | 用户可从充值页手动再次尝试；首页不做自动重复下单。 |

## 7. 验收意图

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 登录用户长按交通卡 | 出现含“充值”的快捷菜单；选择后进入该卡充值页。 |
| AC-02 | 余额低于阈值 | 卡片出现“余额不足”角标；点击后进入该卡充值页。 |
| AC-03 | 余额等于或高于阈值 | 不显示低余额角标。 |
| AC-04 | 游客选择充值 | 先进入登录；登录成功后回到原卡充值页。 |
| AC-05 | 管理台开关关闭 | 首页没有新增菜单项与角标，旧充值路径不受影响。 |
| AC-06 | 下单被拒绝或支付中断 | 用户获得可理解的结果并可按既有流程重新尝试，不产生自动重复订单。 |

## 8. 需要协同的边界

- 钱包 app 负责首页入口、登录续接、充值页跳转、端侧状态和用户可见异常；
- 钱包云侧负责余额、阈值、订单创建、订单有效期和风控判定；
- 支付部件负责既有收银台与支付结果回传，并独立记录入口来源；
- 运营负责开关和报表口径；支付部件来源统计的上线不阻塞钱包 app 展示入口。
