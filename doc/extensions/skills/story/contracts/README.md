# 章节合同 `story-chapters.json` 的说明

> 读者：维护章节合同的人与想知道某个键为什么这样定的作者。时机：改合同之前。
> 合同本身只放数据；每个键的来由写在这里，按键在合同里的位置排列。

## 合同整体

章节合同：十章骨架 + 每章读者要回答的问题，外加编号形态与语言红线两份数据。不含取材路标——那是 1.0 逐章生产线的核心，同一个事实被多个章节合同各指一次，于是被强制写多遍。story 由作者读完全部材料后按章写、按章落盘，事实只需出现一次，在哪一章由「它主要帮读者回答哪个问题」决定。questions 是给作者与语义审查的题目，不是给机器的匹配词：机器不拿它去检索材料。

## skeleton

十章顺序即阅读顺序：先说为什么做（背景），再统一词（术语），再划清谁做什么（范围），然后是怎么解决（业务方案）、怎么推进（业务流程）、本特性承担哪段（功能说明）、哪里会坏（异常与恢复）、怎么算做对（验收）、怎么交出去（交付与上线），工程细节留在最后（附录）。

## sources

每份材料给出路径。`derived: true` 声明「这一份是本轮流程自己生成的中间产物」——它只守业务编号（id_shapes.keep 那类评审人认得的号），标识名、带单位的工程数值、包名不再背落点义务：那些东西的家是那份产物自己，逼它们在归档叙事件里找地方，长出来的只有附录表后的散文尾巴和材料清单里的倾倒。真业务事实必在上游材料里另有出处，照旧守恒。 界面图不在这张表里：图片的身份、落点与说明都在 AR/story-src/materials.json，由 import_sources.py --register-ux 登记（复制起名 + 一句「这张图是什么」+ 刷新清单）。ux-reference/ 下的文件（含说明文件 README.md）按目录逐个登记为材料，不在这张表里第二次登记。　`label` 是这份来源在归档件里的中文类别，附录·材料清单的每一行由它打头——类别是读者判断「这一行该不该看」的第一个信息，而它在这里已经有答案，不必让作者再判一次。

## chapters / 「09-rollout」 / banned_terms

整章豁免客户端语境禁用词：上线路径、开关与兼容、恢复设计是本章的必答内容，把它们判成违规等于要求作者删掉评审者最要看的那一节。

## chapters / 「10-appendix」 / subsections

附录只有这五节，多出的小节即违规——工程细节各有落点表，叙述归正文。每节开头一句目的；确实不涉及的节写「不涉及：<依据>」一行，不删标题。小节序号 A.–E. 必带（模板给形态），序号本身不进合同——标题比较一律过规范化通道，把序号剥掉再比。

## chapters / 「10-appendix」 / subsection_tables

附录里由脚本投影的那几张表，表头在这里登记，投影照它渲染——脚本里不留表头字面。列只留有信息的：每一格都要回答读者打开这一节要问的事，回答不了的列（比如逐行重复同一个来源）只是让他多读一遍。

## id_shapes

keep 的编号是读者要对照的（验收编号）；drop 的是仓内工作标识，出现在归档件里读者对不上。

## language_redline

语言红线四类，逐类带作用域：写字符串 = 默认作用域（附录之外的主叙事），写 {kind, scope:"all"} = 全篇。工程标识与规约编号的落点是附录，主叙事写中文业务名与中文规约名；文档坐标（指向不随归档的文件、会随重编号漂移的章节号）放在哪里读者都打不开，全篇判。来源括注的词登记在 source_tags。形态（行内代码、驼峰、下划线、文档坐标）写在 scripts/core/story/language.mjs。附录里由真源投影的机器区不就地报，check 报到真源。

## language_redline / source_tags

来源括注：括号里以这些词起头的那种，是起草时标「这个数是谁定的」，读者不需要，它属于附录的材料清单。表格格子里的不判。

## language_redline / client_vocabulary

客户端语境禁用词：服务器侧词汇，单独使用也算。词与改法都在这里——作者动笔前从任务包读到它，门禁按同一份判。豁免不在这里：整章豁免看 chapters[].banned_terms_exempt、决策类别豁免看 decision_categories[].banned_terms_exempt，不设按行语境的豁免。只收单独出现就只可能指服务器侧动作的词；订单、数据、状态的撤销与恢复是正常业务语言，客户端文案有没有描述端侧不存在的服务器动作由语义审查看实际对象。

## verdicts

逐章维度：语义审查读完全篇之后按这几维判「这一章读起来对不对」。不设逐单元、逐问两张表，也不核引文长度——逐条对齐「材料这件事讲了没有」是机器数不出来的事，数出来的只会是凑数的段落与抄回原文的引文。

## decision_categories / 「入口与管控」 / banned_terms

开关放量与入口收敛就是这一类议题的必答内容——在这里讲它们不是跑题，是本职。

## decision_categories / 「交付顺序与协同」 / banned_terms

上线顺序与联调节奏就是这一类议题的必答内容。

## decision_categories

决策内容的类型词表，两个形态并存：`key` 是找议题时的扫描指引原名（作业书里带触发特征与典型问句），`section` 是它在评审记录里成章的自然名。**它是指引与词表，不是配额**：机器只判「登记的类别在不在这张表里」，不判每类有没有条目、不判数量、不判空类要不要解释——逼填只会逼出凑数与逃生口。十一类来自三源正推：材料内容块、实现方案面、产物章节反查。

## gates

第一级关卡的选项集，**两项固定**。人陈述的是事实——料放进去了，或者现有材料就是全部；够不够由作者盘点、由人定，机器不判。带 request 的那一项是「我还要料」，第 2 轮起它要写清剩余缺口。label 由脚本按 key 填进契约，作者不写：可改写的话，摆给人的那句话是合同给的还是作者当场编的，事后分不出来——而那正是「他问了什么」的全部内容。本轮缺什么写进选项的 missing / why 与停等正文，不进标签；标签固定，人每次看到的才是同一个问题。流程脚本与流程校验都从这里读，两边不各存一份字面：只改一处，写进契约的选择会在阶段门禁上被判非法。

## flow

流程契约（AR/story-src/story-flow.json）的常量：schema 版本、关卡名、第二级里固定的「整体承载」键。写入侧 `scripts/core/flow/state.py` 与门禁 `flow/check.mjs` 都从这里读，两边不各存一份字面。

**`story-flow.json` 里的 `update` 键不在这份合同里，也不加判据。** 它是可选键，由 `flow/update.py`
一处写入、`flow/routing.py` 一处读：`{"open": <轮次 id 或 null>, "opened_at"/"last_closed"/"last_restored",
"decisions": [{"item","basis","by","at"}]}`。形状由写入侧保证——这与门禁「写入侧已保证的形状不在这里重判」
的口径一致（`flow/check.mjs` 只认 schema、rounds、positioning、gates，不拒绝未知的顶层键）。
**`flow.schema` 不因它升版**：旧读者忽略这个键就行，升了会让在途的单立刻报 schema 不符，而它们的流程并没有变。

## pending_mark

骨架给每章留的待写记号。JS 与 Python 两侧都要认它——各写一份字面的话，改一处忘一处，story 的进度在两条路上会说成两样。

## heading_counters

小节标题开头的数字后面跟着这些字，那个数字就是内容不是序号（`3 类异常处置`）。**它是第二道**：主判据是位置——数字接不接得上作者的编号序列（见 scripts/core/story/document.mjs 的 takeAuthorNumber）。收字的尺子是宁可误留不可误剥：误留是标题上多个数字（看得见），误剥是业务名丢了第一个字，而那一节之后还要被十几处标题匹配用到。所以会做词首的不收——收了「成」，`3 成功怎么衡量` 的序号就剥不掉。

## structure

每章只登记机器核得到的**最小必要结构**，而且只登记机器**确实要定位**的那几样。`structure.h3` 是必须存在的 H3——只留下要给表定范围的那种（`tables[].at` 指向它）与附录那五节；内容目标不靠标题名判定：分工讲没讲清、回退措施有没有依据，由 `questions`、`verdicts.chapter_dimensions` 与独立语义审查读内容判，作者按业务给小节起名。`structure.tables` 是必须出现的表：`header` 全列供草稿打底；`anchors` 是最低锚列，第一组认这张表的主语、其余组是它必须有的列，每组内任一说法命中即可（列名换措辞不算缺）；作用域内**任意一张**表满足全部锚列即通过，加列、改措辞都合法，把几件事散在几张表里不算。`at` 写这张表所属的必要 H3（不写 = 章内合理位置皆可）。`seed: "terms"/"table"` 表示草稿按同一位置打底。`structure.diagram: true` 表示这一章要有一张真正的图（画图语言的围栏）；**位置不判**——总览在章首那段或一个总览小节里都行，它讲没讲清整条业务归语义审查。围栏里的标题与表是被引用的样例，不参加结构判定。其余形式——叙述、列表、图种、小节怎么切——由作者按内容的关系定，方法在 story-write.md，机器不核。

## review_form_banned_lines

评审记录里不该出现的行——每一样都被裁掉过，每一样都以「更规范」的名义长回来。判的是**行首形态**而不是词：
`确认人：` 是签署字段，而评审人在自己的意见里写「这条要找确认人」是正常的话，只判机器渲染出来的那种独立字段行。
模型写的澄清正文会被渲进评审记录，所以这组判据在运行时核，不只是渲染器的事。
