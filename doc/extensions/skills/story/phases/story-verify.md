# story 裁决（verifier 子 agent 的作业书）

**你只做一件事：逐条判「这个单元讲了没有」。**

writer 已经写完并跑过 `story-build check`，机器能核的落点它都核过了；
剩下机器定不了的那些，只有模型能判——框架给 spec / plan / coding 每个阶段都配了
verifier，story 这一份此前没有，这是缺口，不是给作者加的围栏。

**不要对整篇下结论**——通篇读感、方案理由充不充分，这些由 writer 自己交回前自检，
不在你这里。一份任务里掺进整篇印象题，逐条那件事就被稀释掉了：实测 43 条裁决全是
「讲清」、一条「未讲清」都没有，引文里有 15 条与被裁的单元根本无关。

## 输入

| 文件 | 拿什么 |
|---|---|
| `AR/story-src/audit.json` | **你的任务清单**：`by: author` 的每一条。其余三态是机器判的，不归你 |
| `AR/story-src/source-units.json` | 每条任务的**单元正文**——那件事是什么 |
| `AR/story.md` | 被裁的产物。引文只能从这里抄 |

## 每一条怎么裁

给你的是一对：**单元正文 → 它落点的那一章**。

1. 读单元正文，把它说的那件事**用自己的话说一遍**——说不出来，说明这条单元本身没内容，
   照实裁「未讲清」并写「单元无可讲事实」；
2. 打开 story 里 `at` 指向的那一章，找**陈述这件事**的句子；
3. 找到了 → 裁「讲清」，把那一句抄下来；找不到 → 裁「未讲清」，写清**缺什么**。

### 「陈述这件事」是什么意思

引文必须是**讲这件事**的那一句，不是同一章里的任意一句。

- 单元说「用户点了提交但未收到回执时处于待提交态」，
  story 那一章写「提交后回执未到之前停在待提交，收到回执才转已回执」——**这一句讲了它**，抄它；
- 同一章里另有一句「界面支持深色主题」——它在这一章，但它讲的是别的事，**不算**；
- 那一章只写「有多种状态」——没有讲清哪个状态由什么触发，裁「未讲清」，
  缺什么写「未说明待提交态由『已提交但回执未到』触发」。

**找不到就裁「未讲清」，这是你存在的理由。** 通篇「讲清」等于没审——
一条「未讲清」都没有时，先回头确认你是不是在拿同章任意一句凑引文。

### 引文的机械要求（`check ⑥` 会核）

- 是那一章的**逐字子串**，连续 12 字以上；
- **不是单元原文的子串**——把材料原话抄回来是回声，证明的是「材料这么说」，
  不是「story 讲清了它」。

## 产物

写 `AR/story-src/story-verdicts.md`，固定表头，一条一行，**不附整篇结论**：

```
| 单元键 | 裁决 | 引文 |
|---|---|---|
| PRD:31:ab12cd34 | 讲清 | <从 story 那一章抄的、讲这件事的原文，≥12 字> |
| SE:88:9f0e1d2c | 未讲清 | 缺：未说明回执超时后由谁重试 |
```

裁「未讲清」时，引文列写「缺：<缺什么>」——它不必满足 12 字与子串要求，
`check` 会因为存在「未讲清」而 FAIL 并点名那一条，交回 writer 补写。

**没有 `by: author` 记录时不必产出这份文件**——机器全核完了，没有你要裁的东西。
