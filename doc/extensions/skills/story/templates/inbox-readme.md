# 上游材料收件箱

需求系统里 PRD / SE 设计还没归档时，把手上的材料放进**本目录**，
然后在对话里说一句「材料放好了」即可——AI 会自动识别、分类、转换并接进流程。

## 放什么

| 类型 | 格式 | 会发生什么 |
|---|---|---|
| 产品需求、系统设计、本部件补充说明 | `.docx` | 转成 md（含表格），**图片自动抽出并保留引用**，覆盖对应的上游正文 |
| 同上 | 文本文件（`.md` `.txt` `.log`、无后缀均可） | 原样接进对应的上游正文 |
| 界面设计图 | `.png` `.jpg` `.jpeg` `.webp` `.bmp` | 分发到界面参考目录，进入视觉链路 |

判断标准是**文件本身读不读得开**，不是扩展名。二进制格式（`.pdf` / `.doc` 等）
读不开，请先另存为 `.docx` 或转成 `.md`。
放错格式不会被静默忽略，会明确报错告诉你该怎么办。

## 几条约定

- **文件名即章节标题**：转换后每份材料成为正文里的一节，标题就是文件名（不含扩展名）；
- **同类多份按文件名排序拼接**：想控制先后就加数字前缀（`1-总体.docx`、`2-补充.docx`）；
- **原文件留在这里存档**，不会被移走或删除；
- **改了重放即可**：更新文件内容后再导一次，对应内容整体重转；
- **拿掉某类的全部文件**，该类的目标正文就不再被本流程改写（保持现状，不会被清空）；
- 本 `README.md` 不会被当成材料。

> 导入会**整体覆盖**对应的上游正文（人工放的材料视为权威版本）；被覆盖的旧内容
> 自动存入 `../.backup/`，需要时可取回。
