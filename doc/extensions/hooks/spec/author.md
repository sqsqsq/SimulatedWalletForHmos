# spec 阶段 · 扩展要求（写之前读这一页）

本工程的实例扩展在 spec 阶段要求三样东西。下面四段就是全部：读什么、写成什么、跑什么、门禁拦什么。
判据推理不在这里，示例长文也不在这里——这一页只做索引。

## 一、读哪几个文件

| 文件 | 拿什么 |
|---|---|
| `doc/extensions/skills/story/templates/spec-sections.md` | §9 / §10 / §11 三节的表结构与写法；每节顶部的 HTML 注释就是该节的结构判据 |
| `doc/extensions/manifest.yaml` 的 `provides.knowledge` 所列文件 | 本阶段生效的规约条目表与项目知识。**只读清单里的文件**，不扫描 `knowledge/` 目录——没登记的读不到 |
| `doc/extensions/skills/story/reference/evidence-rules.md` | §9 各节怎么取证、结论怎么写才能按名回查 |

走 `/story` 链时另读 [`skills/story/phases/spec.md`](../../skills/story/phases/spec.md)：本轮材料从哪来、
要出几份产物、§9 怎么取证。

规约条目表的「处置」列和该域的落法附注是要求的正文，此处不复述——规约改了这一页不用改。

## 二、产出形态

spec 正文里扩展要求的只有三节，全部按 `spec-sections.md` 的表写：

- **§9 技术契约**——本需求**有什么**。守恒与专名的数据源。
- **§10 规约约束要求**——必须**满足什么**。判「命中」且处置未标（评审动作）的条目**逐条一行**，
  每行给出「这条在本需求里具体要求做什么」和「落点契约名」；落点名必须是 §9 里已登记的名字。
  **不为任何域预留固定小节**——哪些条目命中由本次需求决定。
  **有命中条件的域先判域**：整域不适用时不必逐条登记，但要有一句可回查的依据
  （「本需求无新增对外开放页面或接口」是依据，「不涉及」不是）。逐条判定的完整回显在归档件的
  「影响面与合规」章成表，那是叙事件的产物，不进 spec。
- **§11 设计模式候选登记**——可以**选什么**。逐个适用单元一行，只登记不选型（选型缺方案上下文，是 plan 的事）。
  零候选是正常结论，但要写出单元与「为什么都不需要」。

判定的推演过程是工作底稿，**不进 spec**；决策论证（为什么这么配、谁先上线）也不进 spec。
spec 是交给代码的要求说明书——与最终代码无关的内容不进来。

## 三、跑哪条命令

```
cd framework/harness && npx ts-node harness-runner.ts --phase spec --feature <需求名>
```

走 `/story` 链时，S1–S4 的命令由 `story_flow.py status` 逐步打印，照它给的敲即可，不必读脚本。

## 四、门禁会拦什么

- §9 / §10 / §11 缺章，或章里只剩模板占位符没填。
- §10 的「落点契约名」在 §9 里找不到——落点必须是已登记的实体名。
- §10 的要求是规约原文的**复制或子串**。（同义改写机械拦不住，会进评审的必答清单逐行裁。）
- 正文出现文档坐标（`spec §x`、`SR §x`、`见 A5` 这类章节互指）——改写**事物的名字**：
  写「见管理台功能开关 `feature_entry_enabled`」，不写「见 A5」。坐标换个文档就失效，且可以伪造。
- 引用约束规约时写了 `<域文件名>:<编号>` 这种仓内 slug——改写中文规约名 + 编号。
- 阈值 / 时长 / 次数没标来源类型。三选一：`（上游约束：<文档名>）` / `（本工程设定，无上游依据）` / `（平台基线）`。
  标「上游约束」时门禁会**读 SR/RR 原文验证该数值真实存在**，查无此数即判伪造出处并阻断。
- 结论不具体到可按名回查——写全接口名、存储键、事件名、配置项名、错误码，不写「新增了一个开关」。
- `/story` 三级关卡没走完就进本阶段（材料够不够 → 范围怎么定 → 承载哪份）。

报错会**一次列全**，每条都写「缺什么 / 写到哪 / 怎么写」。不需要去读 `post_check.mjs` 反推判据。
